# SD-304 — Keys page through the last N turns (shared conversation model with the desktop modal)

**Complexity:** 3
**Phase hint:** 4
**Area:** area:ui
**Depends on:** SD-303 (extends its chat controller and `ConversationSource` ref with `page/3`)
**Serializes with:** SD-303, SD-105 (removes the Logs mode this replaces), SD-201 (dial 1 scroll binding)

## Outcome

On the ticket page the keys show the last N conversation turns, newest at the LIVE end. Pressing
a turn key puts that turn on the strip; dial 1 scrolls; paging past the oldest key loads older
turns. The deck shows the same entries, in the same order, as the desktop modal.

## Context and evidence

See `evidence/C-findings.md` §1–§3. Deck Logs mode builds its event keys from
`StreamdeckLogs` (`AgentEventFeed` + `Conversation.Anchors`), a different and shorter source than
the modal. The modal pages with `ConversationSource.page(ref, before)` and an opaque cursor
(`build/conversation.ex:127-140`). #5181's acceptance (seeded transcript is listed; fails on
main) moves here.

## Scope

- Group `Entries` into turns server-side: a turn = one `say` plus the `tool`/`sys` entries
  before it back to the previous `say` or `op`; an `op` is its own turn. N = 7 keys + LIVE
  (`EVENTS_PER_PAGE`).
- Channel: `chat_page` request with the opaque `before` cursor → `ConversationSource.page/3`;
  reply with turns and `more`. Cursor stays opaque to the device (pattern: `commands_page`).
- Sidecar: reuse the 8-key event window and `chatLog.ts` selection rules; feed them turns
  instead of `StreamdeckLogs` events.
- Delete the `logs` push from the focus path once this lands (SD-105 deletes the module).

## Non-goals

- Bus events (PR opened, CI passed) as keys. Default is conversation turns only; see Open points.
- Search, filters, composer.

## Existing owner and reuse target

- `AiurWeb.Build.ConversationSource.page/3` + `Wave0b` cursor rules (`:invalid_cursor`, `:reset`).
- `ConversationSource.Entries` entry shape.
- Sidecar: `touchStrip/chatLog.ts` (`selectedKeyAtOffset`, `ensureEventVisible`), `logs.ts`, `dial.ts` (`EVENTS_PER_PAGE`).

## Contract and invariants

- Same entries and order as the modal for the same ticket and cursor.
- `:reset` / `:invalid_cursor` → device drops its pages and reloads the tail; never shows a gap silently.
- Bounded: at most 500 retained entries on the device (modal cap).

```json
{"v":1,"kind":"chat-page","id":"5181","before":"c:1:18000","more":true,
 "turns":[{"id":"t:l:17990","at":1761229000000,"k":"say","text":"Tests pass; opening PR.","tools":2},
          {"id":"t:l:18010","at":1761229500000,"k":"op","text":"Rebase on main first."}]}
```

## Acceptance criteria

1. A ticket with a seeded 30-turn `agent.ndjson` shows 7 turn keys + LIVE; the newest seeded turn is next to LIVE.
2. Pressing a turn key shows that turn on the strip; LIVE returns to the newest entry.
3. Paging past the oldest key loads the previous page via `chat_page`; the first page's turns are not repeated.
4. The deck turn list for a ticket matches the entry ids the desktop modal shows for the same cursor.
5. (#5181) A browser emulator test seeds transcript lines and asserts they are listed; it fails on main.

## Test that fails without the change

- Unit: grouping of `[sys, tool, say, op, tool, say]` yields three turns with tool counts 1, 0, 1.
- Browser (`src/browser/tests/streamdeck-emulator-surface.browser.spec.mjs`): seeded transcript
  lines appear as turn keys. On main Logs shows only "Ticket opened" (#5181), so it fails.
