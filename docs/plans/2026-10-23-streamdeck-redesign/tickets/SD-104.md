# SD-104 — Browser /streamdeck emulator shows server-rendered images; retire the parity contract

**Complexity:** 3
**Phase hint:** 3
**Area:** area:ui
**Depends on:** SD-102 (images); SD-201 (one view state shared by the emulator and the channel)
**Serializes with:** SD-201 and the group B/C view tickets that edit `live/streamdeck_live.ex` and `live/streamdeck_live/components.ex`

## Outcome
`/streamdeck` shows the same SVG images that the physical deck shows, produced by the same
`Render.frame/1` call. The HEEx key faces, the strip markup and the CSS that drew them are removed.
The key-face parity contract and its mirrors are deleted, because only one renderer is left.

## Context and evidence
See `evidence/A-findings.md` §5. The emulator faces are in `live/streamdeck_live/components.ex:72-115` and
`screen_components.ex`, plus 1,470 lines of CSS in `priv/static/css/52-58-streamdeck-*.css`. The parity
contract consists of these files:
- `src/priv/streamdeck/key-face-contract.json` and `key-face-parity-vectors.json`
- `AiurWeb.StreamdeckKeyFaceContract`
- `packages/streamdeck/src/key-face-contract.{json,ts}` and `key-face-parity-vectors.json`
- tests `streamdeck_key_face_contract_test.exs`, `key-face-contract.test.ts`, `protocol-mirror.test.ts`

## Scope
- The emulator LiveView builds the frame with the same adapter and renderer the channel uses, from
  its own SD-201 view state.
- Each key stays a `<button>` with its `data-streamdeck-*` attributes and
  `aria-label={image.label}`. The button content is the inline SVG.
- The strip renders its regions as absolutely positioned inline SVGs at `left: x`.
- Dial and knob controls stay HTML (`streamdeck-emulator-knob.js`, `streamdeck-emulator-hook.js`).
  They send the same `input` events as the sidecar.
- Delete the face and strip markup in `components.ex` and `screen_components.ex`, the CSS rules
  that only style them, and the parity contract with all its tests and mirrors.
- Move the remaining colour tokens into `AiurWeb.Streamdeck.Render`, if SD-102 did not do it.
- Update the browser specs that query the deleted DOM classes:
  `src/browser/tests/streamdeck-emulator-*.browser.spec.mjs`, `streamdeck-operator-flow.browser.spec.mjs`
  and `support/streamdeck-emulator.mjs`. They should assert on `aria-label` and `data-*`.

## Non-goals
- No new views or strip layout. No change to the sidecar (SD-103).
- `StreamdeckLogs` and the meters deletion belong to SD-105.

## Existing owner and reuse target
- `AiurWeb.Streamdeck.Render.frame/1` (SD-102) and the SD-201 view reducer.
- The `<button>` wrapper and its `data-streamdeck-key` and `data-control-action` attributes stay,
  because the hook JS binds to them.

## Contract and invariants
- The emulator and the channel call the same function for the same view state. No emulator-only
  drawing code remains.
- Inline SVG is safe only because SD-102 escapes all text. A test keeps that rule.
- Every key button has a non-empty `aria-label` when it is not empty.
- Empty slots are `disabled` and have `aria-hidden="true"`, as today.

Worked shape (rendered DOM):

```html
<button type="button" class="sd-key" data-streamdeck-key="0" data-streamdeck-identifier="5181"
        aria-label="#5181 Running 40% Fix strip squeeze">
  <svg xmlns="http://www.w3.org/2000/svg" width="120" height="120" viewBox="0 0 120 120">…</svg>
</button>
```

## Acceptance criteria
1. `/streamdeck` renders 8 key buttons. Each non-empty button contains exactly one `<svg` whose bytes
   equal the `Render.key/1` output for that slot.
2. With `Render` stubbed through an injection seam to return a marker SVG, the page shows the marker.
   This proves that the emulator draws nothing itself.
3. Every non-empty key button has an `aria-label` equal to `image.label`.
4. A key title `<img src=x onerror=alert(1)>` appears only in escaped form in the page HTML.
5. `src/priv/streamdeck/` and `AiurWeb.StreamdeckKeyFaceContract` no longer exist. `mix compile`,
   `npm test` and the browser specs pass.
6. A screenshot of `/streamdeck` and a photo of the deck for the same fixture fleet look the same.

## Test that fails without the change
`src/test/aiur_web/live/streamdeck_live_test.exs`: criteria 1 to 4. Criteria 1 and 2 fail today
because the page renders HEEx faces. Mutation guard: render the title through `raw/1` without
escaping in the renderer, and criterion 4 must fail.

## Open points
- Inline SVG versus `<img src="data:image/svg+xml…">`. Default: inline, so the page fonts apply.
  An `<img>` SVG cannot load page fonts and would fall back to system monospace.
