# SD-206 — Dial 2 priority up/down on the selected ticket (BuildQueue)

**Complexity:** 2
**Phase hint:** 3
**Area:** area:daemon
**Depends on:** SD-201 — the `{:priority, id, dir}` effect and the selected ticket come from the nav reducer. SD-102 — the result is visible only on server-rendered keys (the server action itself does not need it).
**Serializes with:** SD-302 (ticket page priority action must call this module, not a second path); SD-403/SD-404 (dial 2 is today's provider-panel scroll, `PROVIDER_SCROLL_ENCODER = 1`)

## Outcome

Turning dial 2 moves the selected ticket one place up or down in its build queue, through
the same `Aiur.BuildQueue.reorder/2` the CLI uses. A ticket that cannot move says why on
the deck.

## Context and evidence

- `Aiur.BuildQueue.reorder(id, at)` (`src/lib/aiur/build_queue.ex:66-67`) sets an absolute position; the CLI calls it (`build_queue/mutation_cli.ex:129`). The Build page has no reorder control (`live/build_live.ex:129-176`).
- Refusals: `:not_queued` (`build_queue/list_mutations.ex:104-108`), `{:unavailable, :not_list}` for build-order queues (`build_queue/sources/executor_list.ex:6-13`), `:invalid_position`, `:disabled`, `:outcome_unknown` (`build_queue.ex:72-77`).
- Not `Aiur.AgentChat.prioritize/1` (`agent_chat.ex:123`), which is the orchestrator flag; decision 3 says build queue. `evidence/B-findings.md` §6.
- Dial 2 currently scrolls the provider panel (`packages/streamdeck/src/controller.ts:204-216`); decision 6 moves per-account detail to a meter press, so the binding is free once SD-403/404 land.

## Scope

- Module `AiurWeb.Streamdeck.Deck.Priority` (`src/lib/aiur_web/streamdeck/deck/priority.ex`): `step(id, :up | :down, opts)`:
  read the current position from `Aiur.BuildQueue.show/0` (the ticket's queue and index), compute `max(0, i-1)` / `min(last, i+1)`, call `Aiur.BuildQueue.reorder(id, at)`; a no-op at the edges returns `{:ok, :at_edge}` without a write.
- Channel: handle the SD-201 effect in `AiurWeb.StreamdeckChannel` (write requires `streamdeck_authenticated`); reply `{ok, position}` or `{error, reason}` with the reason words above.
- Coalesce a fast turn: N detents in one input frame = one reorder to `i ∓ N` (one write, not N).
- Key/strip feedback: the selected ticket's key shows its new queue position (`Queued #k`) on the next render; a refusal shows a short strip toast ("not in a queue", "plan order is fixed", "queue disabled", "outcome unknown").
- Remove dial-2 provider scroll from the TS controller only when SD-103 moves input to the server (note in SD-103); do not touch `controller.ts` here.

## Non-goals

- Orchestrator prioritize flag. Moving tickets between queues. Reordering build-order (plan) queues.
- A Build page reorder control.

## Existing owner and reuse target

- `Aiur.BuildQueue.reorder/2` and `show/0`. Test seam pattern: `EndpointConfig.get(:streamdeck_implement_fun)` in `streamdeck_channel.ex:380-385` — add `:streamdeck_reorder_fun` the same way so tests never start the queue server.

## Contract and invariants

- One deck turn produces at most one `reorder` call.
- `{:error, :outcome_unknown}` is never retried (write outcome unknown).
- The deck never shows a position it did not read back from the queue.

Worked shape:

```elixir
# input: dial 2 turn -1 while ticket "5998" is selected and at index 3 of list queue "ops"
Nav.reduce(nav, %{"kind" => "dial_turn", "index" => 1, "ticks" => -1}, sizes)
#=> {nav, [{:priority, "5998", :up, 1}]}
Priority.step("5998", :up, 1)   #=> BuildQueue.reorder("5998", 2) #=> {:ok, %{queue: "ops", position: 2}}
Priority.step("5181", :up, 1)   #=> {:error, :not_queued}
Priority.step("6010", :up, 1)   #=> {:error, :not_list}      # build-order queue
```

## Acceptance criteria

1. Ticket at index 3 of a list queue, dial 2 turn -1: `reorder(id, 2)` is called once; reply position 2.
2. Turn -3 in one frame calls `reorder(id, 0)` once.
3. Ticket at index 0, turn -1: no write, `{:ok, :at_edge}`.
4. Ticket not queued: reply `not_queued`; ticket in a build-order queue: reply `not_list`; no write in either case.
5. Unauthenticated socket: `unauthorized`, no write.
6. `outcome_unknown` is shown and not retried.
7. On the real deck, a turn moves the ticket in `aiur build-queue` output.
