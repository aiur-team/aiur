# SD-204 — Epic view with remaining work and drill-in (#5999 data)

**Complexity:** 2
**Phase hint:** 4
**Area:** area:ui
**Depends on:** #5999 — its server block `epic_progress` (multi-label counting) is the data; not on main. SD-102 — renderer. SD-201 — paging and drill. SD-202 — drill-in uses `Tickets.keys(rows, {:epic, key})`.
**Serializes with:** SD-202, SD-203, SD-205 (Deck shell (`AiurWeb.Streamdeck.Deck`) section list)

## Outcome

The Epic view shows one key per general epic with its remaining (open) ticket count,
sorted like the Build home Epics view: remaining desc, then label. A key press lists the
tickets that match that epic; dial 4 long press goes back.

## Context and evidence

- #5999 (OPEN, `agent:todo`, blocked by #5996) defines `epic_progress` keyed by general-epic key: `{closed, open, total}` + `observed_at`, counted by label match against every general epic's matchers (a ticket can count under several epics). Empty state when `build_order.general_epics` is `[]`.
- Not on main. The existing `counts` (`src/lib/aiur/build_order/index.ex:123`) counts by the single resolved epic, which hides feature-owned area tickets (#5999 § Code today). Do not use it.
- `evidence/B-findings.md` §5.

## Scope

- Section `AiurWeb.Streamdeck.Deck.Epics` (`src/lib/aiur_web/streamdeck/deck/epics.ex`).
- Key model: epic label, remaining = `open`, "open/total", percentage closed. Sort: remaining desc, label asc; unknown rows last.
- Empty state: one key/strip text "No epics configured" naming `build_order.general_epics`; never "0 remaining".
- Drill-in: tickets whose labels match the epic's matchers. Reuse the matcher function #5999 adds (same normalization as `Aiur.Config.Schema.GeneralEpic`, `src/lib/aiur/config/schema/general_epic.ex:54-70`); do not write a second matcher.

## Non-goals

- `epic_progress` itself and the browser view (#5999). Adding `area:*` epics to this repo's config (operator follow-up named in #5999).

## Existing owner and reuse target

- `epic_progress` block (from #5999) via the SD-101 adapter; matcher from #5999.

## Contract and invariants

- Order and counts equal the Build Epics view for the same snapshot.
- Unknown counts render "—" and sort last, never as 0.

Worked shape:

```elixir
%{"ui" => %{closed: 30, open: 12, total: 42}, "docs" => %{closed: 3, open: 12, total: 15}, "ci" => %{closed: nil, open: nil, total: nil}}
# keys, in order
[%{key: "docs", label: "Docs", remaining: 12, of: "12/15", pct: 20},
 %{key: "ui", label: "UI", remaining: 12, of: "12/42", pct: 71},
 %{key: "ci", label: "CI", remaining: :unknown, reason: "history incomplete"}]
```

5. On the real deck the order equals `/?view=list&list=epics`.
