# SD-303 — Live chat on the strip at full width from the shared conversation source

**Complexity:** 3
**Phase hint:** 3
**Area:** area:daemon
**Depends on:** SD-101 (chat is a section module of the deck adapter); SD-301 (the chat strip is part of the ticket page); #5181 parked by the Executor first (its PR #5284 edits the same deck transcript path)
**Serializes with:** SD-105 (deletes `StreamdeckLogs` / `StreamdeckTranscriptRelay` callers this ticket replaces), SD-304 (same chat controller), SD-201, SD-301, SD-302

## Outcome

On the ticket page the touch strip shows the latest agent message, tool call or operator reply
across the full 800 px, live, from the same conversation source as the desktop modal. It also
works after a daemon restart.

## Context and evidence

See `evidence/C-findings.md` §1–§3. The deck reads `AgentEventFeed` (in memory, limit 50) through
`StreamdeckLogs.load/1` (`streamdeck_logs.ex:489-497`); the modal reads the workspace
`agent.ndjson` through `ConversationSource.Wave0b` + `Conversation.History` page reads. This is
#5181 item 1. The cmd strip spends its left 200 px on a summary column
(`art/segmentPanels.ts:51, 69`), and the logs strip indents rows behind a glyph and a 72 px badge
(`art/chat-readout.ts:135-141`).

## Scope

- Add a deck chat controller (suggested `AiurWeb.Streamdeck.Deck.Chat`) that runs in the
  channel process: `ConversationSource.call(source, :prepare|:tail|:subscribe|:unsubscribe, ...)`;
  on `{:live_conversation_changed, _}` and a bounded poll, read `tail(ref, last_cursor)` and push
  `chat` with the newest entry.
- On focus change / unfocus / channel terminate: unsubscribe and cancel the timer.
- Sidecar: ticket-page strip shows one full-width row block for the newest entry (role glyph
  inline, no left column, wrap to the strip's rows). Reuse the `chatLog` painter with zero
  summary column.
- Remove the `transcript` push and `StreamdeckTranscriptRelay` start from the focus path (SD-105
  deletes the modules).

## Non-goals

- Paging through older turns (SD-304).
- Composer or dictation changes (SD-407).
- Server-side image rendering (SD-102 ports this painter later).

## Existing owner and reuse target

- `AiurWeb.Build.ConversationSource` (behaviour + `source/0` + `call/3`) and `ConversationSource.Wave0b`.
- `AiurWeb.Build.ConversationSource.Entries` (entry wire shape).
- `Aiur.Conversation.History.live_subscribe/1`.
- Pattern: `AiurWeb.Build.Conversation` `open/2`, `info/2`, `schedule/1` (do not reuse the module; it is LiveView-bound).

## Contract and invariants

- One source of transcript truth: the deck never reads `AgentEventFeed` or `agent.ndjson` itself.
- Subscribe/unsubscribe run in the channel process (plan risk in `2026-10-21-conversation-read-seam.md`).
- Non-live states are named on the strip (`not_retained`, `unavailable`, `stale` with age); never an empty strip that looks live.
- Push rate stays bounded (≤ 4/s, as today's 250 ms relay flush).
- No prompt bodies, raw JSON, paths or tool output beyond the `Entries` allowlist reach the device.


## Acceptance criteria

1. With a seeded `logs/agent.ndjson` and no `AgentEventFeed` entries (fresh daemon), focusing the ticket pushes `chat` with the newest seeded entry.
2. Appending a line to `agent.ndjson` reaches the deck within 2 s.
3. The strip draws text from x ≤ 8 px to the right edge; no summary column on the chat strip.
4. A ticket with no retained log shows "Conversation not retained", not a blank strip.
5. Unfocus leaves no subscription or timer behind (channel test checks `LiveConversation` subscribers).

## Test that fails without the change

Channel test with a temp workspace whose `agent.ndjson` holds one assistant line and an empty
event feed: `focus` → `assert_push "chat", %{"latest" => %{"k" => "say"}}`. On main the deck
pushes `logs` with an empty transcript and no `chat` event, so it fails.
