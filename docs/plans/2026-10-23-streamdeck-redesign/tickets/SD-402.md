# SD-402 — Strip redesign: category counts and a separate queued backlog

**Complexity:** 3
**Phase hint:** 3
**Area:** area:ui
**Depends on:** SD-401 — supplies `counts`; SD-102 — the server renderer draws the strip image.
**Serializes with:** SD-205 (fleet summary strip shares the strip layout module), SD-403 (meter segments share the strip image)

## Outcome
The bottom strip shows one count per agent category (live, awaiting CI, usage limited,
command, error, retrying, parked, paused, blocked, ...) with the queued backlog and the not-queued count
set apart at the right. The operator reads the fleet state at a glance, the same way as the Build page.

## Context and evidence
`evidence/D-findings.md` §1 and §2. Today segment 1 is "logo + N live + build bar", and the pager
segment prints one total (`art/segments.ts:56-89`, `surface.ts:447-468`). Decision 5 of the brief
asks for every NowRows category, with the non-agent tickets shown apart.

## Scope
- Strip layout in the SD-102 renderer for the grid/ticket views, 800x100:
  - segment 1 (200 px): build progress (SD-101 data, unchanged);
  - segments 2-3 (400 px): category chips. Each chip is a state glyph + count. The order is fixed:
    `error`, `command`, `retrying`, `active`, `ci_wait`, `usage_limited`, `parked`, `paused`, then
    the pass-through states, then `unknown`. Only non-zero known counts are drawn;
  - segment 4 (200 px): "Queued M" and "Not queued K" on their own band, and the pager dots under them.
- The state glyph and colour come from the SD-202 state table (one table for keys and strip).
- When more chips are present than fit (more than 8), the last chip is "+N more", and dial 1 scrolls the chip row.
- When `counts.status` is `"stale"`, the chips are dimmed and "stale" is printed. When it is `"unavailable"`, the band reads
  "Counts unavailable".

## Non-goals
- Provider meters (SD-403/404). Fleet page API bars (SD-405).
- Tapping a chip to filter (a later ticket, if wanted).

## Existing owner and reuse target
- `AiurWeb.Streamdeck.Deck.Counts` (SD-401) and the SD-202 state-to-face table. Do not count again.

## Contract and invariants
- A count of `nil` is never drawn as `0`. A zero count is not drawn at all.
- The chip order does not change between renders when the data does not change.
- The sum of the chips equals `counts.agents` when `status` is `"ok"`.

```elixir
%{chips: [%{state: "command", glyph: "!", count: 1}, %{state: "active", glyph: "▶", count: 9},
          %{state: "ci_wait", glyph: "◷", count: 2}],
  backlog: %{queued: 512, not_queued: 17}, status: "ok"}
```

## Acceptance criteria
1. With `by_state = %{"active" => 9, "ci_wait" => 2, "command" => 1}`, the strip model lists the chips
   in the order command, active, ci_wait.
2. A state with count 0 has no chip. A `nil` count gives no chip, and the status reads "unavailable".
3. The backlog band shows "Queued 512" and "Not queued 17" from `counts`.
4. With 11 non-zero states, 7 chips and "+4 more" are shown, and one dial 1 tick moves the window.
5. The rendered strip PNG for a fixture matches a golden image (SD-102 snapshot harness).
