# SD-302 — Ticket page actions: priority, pause/resume, answer Commands, open PR / desktop modal

**Complexity:** 3
**Phase hint:** 4
**Area:** area:ui
**Depends on:** SD-301 (actions sit on the ticket page and read its DTO: `control`, `qpos`, `pr`); SD-206 (priority up/down uses SD-206's channel handler over `BuildQueue.reorder/2`)
**Serializes with:** SD-201, SD-301, SD-303, SD-304 (`mode.ts`, `controller.ts`, `keys.ts`, `streamdeck_channel.ex`)

## Outcome

From a ticket page the operator can move the ticket up or down the build queue, pause or resume
its agent, answer its open Commands, and open the PR or the desktop modal on the PC.

## Context and evidence

See `evidence/C-findings.md` §4. Pause/resume (`control` event, `streamdeck_channel.ex:84-96`)
and Command answers (`answer_command`, `:157-174`, `CommandAnswers.record_command_answer/2`)
already exist on the channel and use the same APIs as the desktop. Priority has no deck caller;
`Aiur.BuildQueue.reorder/2` is the API. Nothing on the deck opens a URL today.

## Scope

- Keys on the ticket page: Pause/Resume (existing `control`), Commands (existing commands mode),
  Priority up / Priority down (call SD-206's `priority` handler), Open PR, Open in dashboard.
- Open PR / Open in dashboard: the ticket DTO (SD-301) adds `links: %{modal, pr}` built on the
  server (`<dashboard base>/build?ticket=<n>`; `repo.url <> "pull/<num>"`). The sidecar opens
  the URL with `xdg-open` through its injected `spawn`; the emulator renders a link with
  `target="_blank"`.
- Disable keys the DTO marks unavailable (read-only dashboard, no PR, not in queue).

## Non-goals

- New mutation APIs. Each action uses an existing function.
- Opening a URL on a machine other than the sidecar host.

## Existing owner and reuse target

- Pause/resume: `Aiur.AgentChat.pause/1`, `resume/1` via existing channel `control`.
- Commands: `AiurWeb.StreamdeckCommands` + `StreamdeckChannel.CommandAnswers` (unchanged).
- Priority: `Aiur.BuildQueue.reorder/2` via SD-206.
- URLs: `Build.URLState` `ticket` param; `routes/dashboard_pages.ex:47`; `header.js:33-41`.

## Contract and invariants

- Every action replies with the existing channel reply shape; failures name the reason.
- Answer stays focused-ticket enforced and versioned; actor stays `streamdeck`.
- URLs are built server-side from configured values only; the sidecar never builds a URL from
  free text and only opens `http(s)` URLs.

```json
{"links":{"modal":"http://127.0.0.1:4000/build?ticket=5181","pr":"https://github.com/aiur-team/aiur/pull/5284"},
 "actions":{"pause":"enabled","priority_up":"enabled","priority_down":"disabled","commands":1}}
```

## Refreshable implementation notes

- `src/lib/aiur_web/streamdeck_channel.ex` — no new pause/answer code; add `links` in SD-301's
  DTO builder; `priority` handler comes from SD-206.
- Dashboard base URL: reuse what `StreamdeckProjection` / endpoint config uses for the public URL
  (`AiurWeb.Endpoint.url/0`).
- `packages/streamdeck/src/keys.ts` (cmd key set), `mode.ts:130-180` (cmd transitions),
  `runtime.ts:42` / `line-source.ts` (injected spawn pattern) for `xdg-open`.
- Emulator: `src/lib/aiur_web/live/streamdeck_live.ex` key handler.

## Acceptance criteria

1. Priority up on a queued ticket at `qpos` 3 moves it to 2 (`BuildQueue.show/0` confirms).
2. Pause then Resume on a running ticket changes its Build status to `paused` and back.
3. Answering an open Command from the page records an answer with actor `streamdeck`.
4. Open PR runs `xdg-open <pr url>` on the sidecar host; Open in dashboard opens `/build?ticket=<n>` with the modal open.
5. Keys show disabled for a read-only dashboard, a ticket with no PR, and a ticket not in the queue.

## Test that fails without the change

- Sidecar unit test: Open PR key press with a DTO carrying `links.pr` calls the injected spawn
  with `["xdg-open", url]`; a DTO with `links.pr: null` does not. Fails on main (no key).
- Channel test: the `ticket` DTO for a ticket with an open PR includes `links.pr`. Fails on main.
