# SD-205 — Fleet summary view

**Complexity:** 2
**Phase hint:** 4
**Area:** area:ui
**Depends on:** SD-401 — the per-category counts from NowRows (one counting module, reused, not recounted); SD-102 — renderer; SD-201 — view cycle and drill; SD-202 — drill-in uses `Tickets.keys(rows, {:state, s})`.
**Serializes with:** SD-202, SD-203, SD-204 (Deck shell (`AiurWeb.Streamdeck.Deck`) section list); SD-405 (adds API bars to this view's strip)

## Outcome

The Fleet view gives one-glance fleet health: one key per agent/ticket category with its
count (live, needs command, error/retrying, waiting for CI, usage limited, parked/paused,
queued backlog, capacity), and a strip with daemon state, capacity and global pause. A
category key press lists those tickets.

## Context and evidence

- Categories come from `AiurWeb.Build.NowRows` states (`build/now_rows.ex:8-20`) plus the `plan` backlog (`build/planned_rows.ex`); `evidence/B-findings.md` §4.
- Capacity and daemon liveness are already Build payload blocks: `capacity {max, observed_at, stale}` and `daemon {state, heartbeat_at, observed_at}` (`src/lib/aiur_web/build/payload_schema.ex:59-80`).
- SD-401 builds the same counts for the bottom strip; this view must read that module.

## Scope

- Section `AiurWeb.Streamdeck.Deck.Fleet` (`src/lib/aiur_web/streamdeck/deck/fleet.ex`).
- 8 keys: `active`, `command`, `error`+`retrying`, `ci_wait`, `usage_limited`, `parked`+`paused`, queued backlog, capacity (`live / max`). Unknown-state rows add to a visible "unknown" sub-count on the active key ("12 · 1?"), never dropped.
- Strip: daemon state with heartbeat age, `capacity.max` (stale flag shown), global pause state (`AiurWeb.DashboardShell` pause source the dashboard uses).
- Drill-in on a category key: push `{:state, states}`; list = `Tickets.keys(rows, {:state, states})`.

## Non-goals

- GitHub core/GraphQL and ElevenLabs bars (SD-405 mounts them here).
- Toggling global pause from the deck (not in decision 3).

## Existing owner and reuse target

- Counts: SD-401's module. Capacity/daemon: Build payload blocks through the SD-101 adapter.

## Contract and invariants

- Key counts sum to the Ticket view's key count (same rows, same filter).
- A nil `capacity.max` renders "—", not 0; a stale daemon renders "stale <age>", never "live".

Worked shape:

```elixir
%{keys: [
   %{cat: :active, count: 11, unknown: 1}, %{cat: :command, count: 2}, %{cat: :error, count: 1},
   %{cat: :ci_wait, count: 4}, %{cat: :usage_limited, count: 0}, %{cat: :paused, count: 3},
   %{cat: :queued, count: 37}, %{cat: :capacity, live: 21, max: 24}],
  strip: %{daemon: "live", heartbeat_age_s: 4, capacity_stale: false, global_pause: false}}
```

## Acceptance criteria

1. With a fixture of NowRows rows in every state plus 3 backlog rows, each key count matches the fixture and the total equals the Ticket view key count.
2. A row with an unknown state appears in the unknown sub-count.
3. `capacity.max: nil` renders "—"; `daemon.state: "stale"` renders stale with its age.
4. Pressing the CI key drills into exactly the `ci_wait` tickets.
5. On the real deck, the counts match `/build` Now band counts at the same moment.
