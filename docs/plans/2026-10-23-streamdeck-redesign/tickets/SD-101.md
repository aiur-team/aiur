# SD-101 — Deck adapter shell over shared read models, with build order from BuildQueue/BuildProgress (fixes "No build order")

**Complexity:** 3
**Phase hint:** 1
**Area:** area:daemon
**Depends on:** none
**Serializes with:** SD-401 (`surface.ts` strip data block, `live/streamdeck_live/surface.ex` summary descriptor), SD-403 (`streamdeck_channel.ex` join subscriptions, `streamdeck_projection.ex`)

## Outcome
The deck shows the real build progress on both surfaces, using the current TS renderer and the
current emulator markup. The summary strip segment shows "Build 30%" for the focus lane, with a bar. It
shows "No build order" only when no lane exists, and "Build unavailable" when the build queue cannot be read.
A new deck adapter module is the single place where the deck reads shared models. Later tickets add
one section file each, and do not edit the projection.

## Context and evidence
See `evidence/A-findings.md` §1 and §4. `surface.ts:451-455` reads `grid.build`, but
`StreamDeckGrid.project/2` (`stream_deck_grid.ex:56-64`) never sends it. The emulator
hard-codes the bar as unobserved (`screen_components.ex:133-139`). The deck reads no Build
model.

## Scope
- Add the shell `AiurWeb.Streamdeck.Deck` (`src/lib/aiur_web/streamdeck/deck.ex`). It has one
  function, `read(opts \\ [])`, which returns a map of section results. Each section is one module
  under `src/lib/aiur_web/streamdeck/deck/`. Each section read is guarded, so one failing section
  gives `nil` plus a status and never breaks the payload.
- Add the first section, `AiurWeb.Streamdeck.Deck.BuildOrder.read/1`, over `Aiur.BuildQueue.show/0`.
- Merge `build` and `build_status` into the grid map in `AiurWeb.StreamdeckFleet.grid/1`. This
  covers the snapshot and every `fleet` push. Merge them also in
  `AiurWeb.StreamdeckLive.Grid.load_grid/0` for the emulator.
- Channel: in `join`, subscribe to `"build_queue:changed"` and `"build_progress"`. Map both
  messages to `StreamdeckFleetUpdates.schedule/1`, to reuse the 250 ms coalescing.
- Emulator: subscribe to the same topics in `StreamdeckLive` mount and call `refresh_grid/1`.
  `Surface.screen_descriptors/4` carries `build`. `screen_components.ex` renders the percent,
  the bar and the observed state from it.
- TS (phase 1, current renderer): in `summarySegment.ts`, prefer `percent` over
  `completed/total`. Accept `eta_seconds`. In `art/segments.ts` `drawSummary`, draw
  "Build unavailable" when `build_status === "unavailable"`. Add `build?` and `build_status?`
  to `StreamDeckGrid` in `channel-types.ts`.

## Non-goals
- No ETA computation. Send `eta_seconds: nil` (see Open points).
- No change to grid buckets, counts or meters (SD-202, SD-401, SD-403).
- No server rendering (SD-102).

## Existing owner and reuse target
- `Aiur.BuildQueue.show/0`: the queue read model, never raises.
- `Aiur.BuildQueue.ReadModel.focus_starvation/1` ordering: `{set_rank, queue_id}`.
- `AiurWeb.BuildQueue.Runtime`: the topic pair it subscribes to.
- `AiurWeb.BuildQueue.Copy.progress/1`: wording, if a label is needed.
- `StreamdeckFleetUpdates.schedule/1`: coalescing.

## Contract and invariants
- `build` is `nil` or a map. `build_status` is always one of `"ok" | "none" | "unavailable"`:
  - `"none"` means the model was read and no lane has `progress.total > 0`.
  - `"unavailable"` means `status` is not `:running`, or the read raised or exited.
  - Never collapse `"unavailable"` into `"none"`.
- Lane choice: the queue with the lowest `{set_rank, queue_id}` whose `progress.total` is a
  positive integer.
- `percent` is passed through unchanged (`nil` stays `nil`). `completed` stays `nil` when the
  source has `nil`. Never derive it from `percent`.
- The read is a `GenServer.call` with a 1 s cap. It runs in the channel process inside the
  already-coalesced flush, and is never called per event.

Worked shape (string keys on the wire after `external_value`):

```json
"grid": {
  "agents": [...], "total": 12, "windows": 2, "max_column_offset": 2,
  "build": {"queue_id": "q-7", "name": "Stream Deck redesign", "kind": "build_order",
            "completed": null, "resolved": 9, "total": 22, "percent": 41,
            "resolution": "partial", "eta_seconds": null},
  "build_status": "ok"
}
```

## Acceptance criteria
1. With an injected build-queue read that returns two lanes (set_rank 2 with total 5, and set_rank 1
   "X" with total 22 and percent 41), `StreamdeckProjection.snapshot()["grid"]["build"]["name"] == "X"`
   and `["percent"] == 41`.
2. An injected read that raises or returns `status: :disabled` gives `build: nil` and
   `build_status: "unavailable"`. An empty `queues` list gives `build_status: "none"`.
3. A `{:build_progress_changed, fact}` message to a joined channel produces one `fleet` push within
   about 300 ms, carrying the new `build`. Five messages in 100 ms still produce one push.
4. TS: `summaryModel(1, 2, {percent: 41, total: 22, completed: null})` gives `build.fraction` ≈ 0.41.
5. TS: the summary segment draws "Build unavailable" for `build_status: "unavailable"` and "No build
   order" for `"none"`.
6. Emulator `/streamdeck`: the build mini element has `data-observed="true"` and an aria-label with the
   percent when `build` is present.
