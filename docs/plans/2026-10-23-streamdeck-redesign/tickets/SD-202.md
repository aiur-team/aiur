# SD-202 — Ticket view on the NowRows 9-state taxonomy

**Complexity:** 3
**Phase hint:** 3
**Area:** area:ui
**Depends on:** SD-101 — reads NowRows and PlannedRows through the adapter; SD-102 — the server renderer draws the 9-state faces; SD-201 — paging, selection and drill-in.
**Serializes with:** SD-203, SD-204, SD-205 (each adds one section line to the Deck shell (`AiurWeb.Streamdeck.Deck`)); SD-105 (deletes the grid bucket this replaces)

## Outcome

The Ticket view (the default view) shows one key per ticket with the same agent state
the Build page shows: the 8 named NowRows states plus "unknown", then the queued backlog
(no agent) after them. A key press opens that ticket's deck page.

## Context and evidence

- Today the grid uses 5 deck-only buckets: `Aiur.AgentEvents.streamdeck_bucket/1` (`src/lib/aiur/agent_events.ex:298`) via `AiurWeb.StreamDeckGrid.project/2` (`src/lib/aiur_web/stream_deck_grid.ex:39-60`), enforced by `AiurWeb.StreamdeckKeyFaceContract` (`streamdeck_key_face_contract.ex:12`).
- The Build page uses `AiurWeb.Build.NowRows` (`build/now_rows.ex:8-20,115-157`) and maps state to label/class in `src/priv/static/build-home/now-state.js:2-12`. Taxonomy and the wider pass-through enum: `evidence/B-findings.md` §4.
- Backlog without an agent: Build `plan` rows from `AiurWeb.Build.PlannedRows` (`build/planned_rows.ex:20,44`, field `qpos`).

## Scope

- New section `AiurWeb.Streamdeck.Deck.Tickets` (`src/lib/aiur_web/streamdeck/deck/tickets.ex`): builds the ordered key list from the adapter's NowRows rows + plan rows.
- Order: `error`, `command`, `retrying`, `active`, `ci_wait`, `usage_limited`, `parked`, `paused`, pass-through reason states, unknown; ties by ticket number; then the queued backlog in `qpos` order.
- Key model per ticket: number, short title, state, state label (same text as `now-state.js` `AST`), `pct` or unknown, model label. Unknown state renders "State unknown"; unknown `pct` renders no bar, never 0%.
- State -> face tokens for the 9 states plus `queued` in the SD-102 renderer's palette (reuse the 5 existing token sets where the class matches: `now-state.js` `cls` `stuck|queued|idle|active`).
- Drill-in source for SD-203/204/205: `Tickets.keys(rows, filter)` where filter is `{:feature, key}`, `{:epic, key}` or `{:state, state}`.
- Key press -> `{:open_ticket, id}` (SD-201 effect).

## Non-goals

- The ticket page itself (SD-301). Strip counts (SD-401/402). Sort setting (SD-406).
- Deleting `streamdeck_bucket` and `StreamDeckGrid` (SD-105).

## Existing owner and reuse target

- `AiurWeb.Build.NowRows.build/2` and `AiurWeb.Build.IndexReader.read_now/2` (`build/index_reader.ex:38-62`) — read through the SD-101 adapter, never re-derive state.
- Labels: port the `AST` table from `now-state.js:2-12` into one Elixir map in this module; a test pins every value of `PayloadSchema` line 33 to a label.

## Contract and invariants

- Every value of the `agent.state` enum in `AiurWeb.Build.PayloadSchema` (`payload_schema.ex:33`) and `nil` maps to a label and a face; a value outside the enum maps to unknown, not to `active`.
- The view never shows a ticket twice (a NowRows ticket that is also queued shows once, as its NowRows state).

## Acceptance criteria

1. With fixture rows in each of the 9 states plus two queued backlog rows, the key order equals the order in Scope.
2. Each key's label equals the Build page label for the same state.
3. A row with `agent.state` `"merge-queued"` shows label `agent:merge-queued`; a row with `"mystery"` shows "State unknown".
4. A row with `pct: nil` renders no progress bar (no 0%).
5. A ticket present in NowRows and in the plan section appears once.
6. Key press emits `{:open_ticket, id}`.
7. On the real deck, a ticket waiting for CI shows "Waiting for CI" on its key and on the Build page at the same time.
