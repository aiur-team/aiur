# SD-401 — Strip counts from NowRows replace the "543 agents" total

**Complexity:** 2
**Phase hint:** 1
**Area:** area:ui

## Outcome
The current touch strip (TS renderer) and the emulator no longer show "543 Agents". The
summary segment shows the live agent count from NowRows, and the pager label shows
"N agents · M queued". Both numbers match the Build page Live and Planned headers.

## Context and evidence
`evidence/D-findings.md` §1 and §2. `grid.total` counts running + retrying + every idle
backlog ticket (`stream_deck_grid.ex:47-54,67-77`; `snapshot_payload.ex:39`). The strip prints
it (`surface.ts:451-467`), and so does the emulator (`live/streamdeck_live/surface.ex:72-77`).

## Scope
- New section `AiurWeb.Streamdeck.Deck.Counts.read/1` (`src/lib/aiur_web/streamdeck/deck/counts.ex`).
  It reads the Build index window (`AiurWeb.Build.Index.window/3`). It counts `sections.now`
  by `agent.state`, and it takes `length(sections.plan)` and `length(sections.nq)`.
- The shell merges it into the grid map as `counts` (one read per coalesced flush, next to SD-101's `build`).
- TS (current renderer): `surface.ts` summary uses `counts.live` and `counts.queued`.
  `pagerLabel` becomes `"${agents} agents · ${queued} queued"` and falls back to `"— agents"`
  when `counts` is absent or unknown. Paging still uses `grid.total`. Add `counts?` to
  `StreamDeckGrid` in `channel-types.ts`.
- Emulator: `Surface.screen_descriptors/4` reads `grid.counts` for `live` / `remaining`.

## Non-goals
- No change to `grid.agents`, `grid.total` or paging (SD-202 replaces the key list).
- No per-category strip layout (SD-402).

## Existing owner and reuse target
- `AiurWeb.Build.NowRows` (state per row), `AiurWeb.Build.Index.window/3`, and `PlannedRows`
  (`plan` section). Counting rules mirror `src/priv/static/build-home/list.js:86-96`.

## Contract and invariants
- `by_state` keys are the exact `agent.state` strings. `nil` is counted under `"unknown"`. A pass-through
  reason state (`merge-queued`, `blocked`, ...) keeps its own key.
- `live` = `by_state["active"]`. `agents` = number of `now` rows.
- When the index read fails or the agents source is `unavailable`, every number is `nil` and
  `status` is `"unavailable"`. Never send `0` for an unknown count.
- `status` is `"stale"` when the agents source is stale. The numbers still show, and are dimmed.

```json
"counts": {"status": "ok", "observed_at": 1761234567000,
  "agents": 14, "live": 9, "queued": 512, "not_queued": 17,
  "by_state": {"active": 9, "ci_wait": 2, "usage_limited": 1, "command": 1, "parked": 1}}
```

## Acceptance criteria
1. Given an index window with 3 `now` rows (`active`, `active`, `ci_wait`), 5 `plan` rows and 2 `nq`
   rows, `Deck.Counts.read/1` returns `agents: 3, live: 2, queued: 5, not_queued: 2,
   by_state: %{"active" => 2, "ci_wait" => 1}`.
2. A `now` row with `agent.state: nil` is counted as `"unknown"`, not as `active`.
3. An index read that returns `{:error, _}` gives `status: "unavailable"` and `nil` for every number.
4. The TS strip with `counts.agents = 3, counts.queued = 5` and `grid.total = 543` paints the
   pager label "3 agents · 5 queued", and the summary shows 2 live.
5. The TS strip with no `counts` paints "— agents", not "0 agents" and not "543 Agents".
6. The emulator `/streamdeck` summary shows the same live count as criterion 4.
