# SD-405 — Fleet page API bars: GitHub core/GraphQL and ElevenLabs

**Complexity:** 2
**Phase hint:** 5
**Area:** area:ui
**Depends on:** SD-403 — `Deck.Meters` already calls `Build.Usage.block/3`, which returns `apis`; SD-205 — the Fleet summary view that shows the bars; SD-102 — server renderer.
**Serializes with:** SD-403 and SD-404 (`deck/meters.ex`), SD-205 (Fleet page layout)

## Outcome
The Fleet page shows three API bars beside the provider meters: GitHub core, GitHub GraphQL and
ElevenLabs credits. Each bar shows remaining, as the Build page APIs card does, with a hold marker
when GitHub budget holds dispatch.

## Context and evidence
`evidence/D-findings.md` §6. The deck has no API data today (`streamdeck_projection.ex:88-96` maps
provider families only). `AiurWeb.Build.UsageAPIs.rows/4` (`build/usage_apis.ex:9-66`) already builds
the rows from `Aiur.GitHub.Quota` and `Aiur.ElevenLabs.Quota`.

## Scope
- `Deck.Meters.read/1` also returns `apis`: the `Build.Usage.block/3` `apis` list, mapped to
  `%{name, lines: [%{tag, remaining_percent, reset_at, hold_until, tip}], stale, observed_at}`.
- The Fleet page (SD-205) draws one bar per line: `core`, `gql`, `credits`. The ElevenLabs row is absent
  when the quota is unconfigured. It is not drawn as empty.
- A refresh tick: reuse the Build page usage tick periods (`build/usage_updates.ex`), or re-read on each
  fleet flush. Use whichever is less often.

## Non-goals
- No new GitHub calls. `Build.Usage` reads the cached quota snapshot (60 s max age).
- No change to the strip in grid or ticket view.

## Existing owner and reuse target
- `AiurWeb.Build.UsageAPIs`, `Aiur.GitHub.Quota.cached_snapshot_at/3`, and `Aiur.ElevenLabs.Quota.snapshot/1`.

## Contract and invariants
- `remaining_percent` is `acc[0]` after #5589. `nil` (not observed yet, or unavailable) is drawn as "—"
  with the tip text, and never as 0 or 100.
- `hold_until` in the future draws a hold marker and "held until HH:MM".
- `stale: true` (the reset has passed) dims the bar.

```elixir
apis: [
  %{name: "GitHub", lines: [%{tag: "core", remaining_percent: 79, reset_at: 1761240000000, hold_until: nil, tip: "3,950 of 5,000 · 79% left"},
                            %{tag: "gql", remaining_percent: 8, reset_at: 1761240000000, hold_until: 1761240000000, tip: "400 of 5,000 · 8% left"}], stale: false},
  %{name: "ElevenLabs", lines: [%{tag: "credits", remaining_percent: nil, reset_at: nil, hold_until: nil, tip: "not observed yet"}], stale: false}]
```

## Acceptance criteria
1. With a GitHub quota fixture (core 21% used, GraphQL 92% used), the Fleet page model has `core` 79 and
   `gql` 8 remaining, and `gql` has `hold_until` set.
2. With ElevenLabs `:unconfigured`, there is no ElevenLabs bar.
3. With GitHub `{:error, :unavailable}`, both lines show "—" and the tip "GitHub budget meter unavailable".
4. Building the bars adds no new caller to `aiur github-cost` after one hour.
