# SD-103 — Node sidecar shows server-rendered images (physical deck)

**Complexity:** 4
**Phase hint:** 3
**Area:** area:ui
**Depends on:** SD-102 (images to show); SD-201 (server-side view state and input model, so the server knows which view to render)
**Serializes with:** SD-201 (`streamdeck_channel.ex`, `packages/streamdeck/src/main.ts`), SD-407 and SD-408 (voice handlers in `streamdeck_channel.ex` and `main.ts`)

## Outcome
The physical deck draws only what the daemon sends. The sidecar sends raw input (key down and up,
dial turn, press, long press, touch) and receives `frame` pushes. It rasterises each changed SVG
to JPEG and writes it with the existing HID writers. The sidecar keeps only transport, layout
(slot to report) and input.

## Context and evidence
See `evidence/A-findings.md` §5 and §7. Today `surface.ts` `createPhysicalSurface().repaint`
builds descriptors from the grid, usage and controller state, then rasterises them with
`rasterizer.ts`. The mode state lives in `controller/state.ts`. The transport layer stays:
`keys/keyImage.ts`, `keys/writeQueue.ts`, `imageWriter/headerGenerator.ts`,
`touchStrip/panelCache.ts` and `keys/keyCache.ts`.

## Scope
- Channel (daemon):
  - Add an `input` event, routed to the SD-201 reducer for this socket.
  - After any input or data change, push `frame` (`Render.frame/1` output) within the existing
    250 ms fleet coalescing window.
  - Send a full frame on join.
- Sidecar:
  - In `channel.ts`, handle `frame`.
  - Add `src/frame.ts`: for each key or region whose `hash` changed, `loadImage(svg)`, then
    `drawImage` on a canvas of that size, then encode JPEG at quality 90. Then call
    `KeyRenderer` and `StripRenderer` (or the writers directly), so the existing write queue
    and byte-diff caches still apply.
  - Keep a hash-to-JPEG LRU, as `rasterizer.ts` does today.
  - Send `input` from `input.ts` / `controller.ts` instead of mutating local mode state.
- Register JetBrains Mono at startup (`GlobalFonts.registerFromPath`). Ship the font in the
  archive `assets/` next to the vendor marks.
- Offline behaviour: when the channel is down, show one local "Aiur offline" full-strip image and
  blank keys. Draw it with the same `loadImage` path from a bundled SVG.

## Non-goals
- Deleting the old TS draw code (SD-105). It becomes unreferenced here.
- New views (group B). Voice changes (SD-407).

## Existing owner and reuse target
- `packages/streamdeck/src/keys/keyRenderer.ts` and `keyWriter.ts`, `touchStrip/stripRenderer.ts`
  (it already takes an injected encoder), `imageWriter/headerGenerator.ts` (any region) and
  `art/vendorMark.ts` (the `loadImage` pattern).

## Contract and invariants
- Device to Aiur `input`:
  `{"kind": "key"|"dial"|"touch", "index": 0..7|0..3, "action": "down"|"up"|"turn"|"press"|"long_press"|"tap", "delta"?: int, "x"?: 0..799}`.
  SD-201 owns the semantics. This ticket only carries the event.
- Aiur to device `frame`: `{"keys": [ {svg, hash, label} | null ] × 8, "strip": [ {x, width, svg, hash} ] }`.
- A frame replaces the whole device state. The sidecar never merges two frames.
- An unchanged `hash` causes no HID write.
- A `null` key uses the existing black feature-report fill (`keys/keyFill.ts`).
- A region is written as one `0x0C` write at `(x, 0, width, 100)`.
- The sidecar never interprets fleet data. A `grep` for `bucket`, `usage` or `build` in the new
  sidecar code finds nothing.

Worked shape:

```json
["3","12","streamdeck:fleet","frame",{"keys":[{"svg":"<svg …/>","hash":"9f1c2a7be0d4c311","label":"#5181 Running 40%"},null,null,null,null,null,null,null],
  "strip":[{"x":0,"width":800,"svg":"<svg … width=\"800\" height=\"100\">…</svg>","hash":"c03b…"}]}]
```

## Acceptance criteria
1. TS: applying a frame with one key SVG writes `0x07` reports for that key index only. The payload
   starts with JPEG SOI `FF D8`.
2. TS: applying the same frame again causes zero backend writes. Changing one region hash writes exactly
   one `0x0C` region.
3. TS: a `null` key writes the black fill feature report.
4. TS: a key press on the HID report stream sends one `input` `{kind:"key", index, action:"down"}`
   on the channel and does not repaint locally.
5. Elixir: `input` on a joined channel results in one `frame` push whose `keys` has length 8.
6. On the real deck after restart, the keys and strip match the emulator for the same fleet (manual
   check, with a photo in the PR).

## Test that fails without the change
- `packages/streamdeck/test/frame.test.ts`: criteria 1 to 3, with a fake `HidBackend` that
  records writes. Mutation guard: remove the hash check, and criterion 2 must fail.
- `src/test/aiur_web/streamdeck_channel_frame_test.exs`: criterion 5.
