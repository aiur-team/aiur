# SD-406 — Settings page redesign; remove the test-mic key

**Complexity:** 4
**Phase hint:** 4
**Area:** area:ui
**Depends on:** SD-201 — view state and input model; SD-102 and SD-103 — the server renders the page and the sidecar shows it; SD-207 — the instance list for the "which instance" setting.
**Serializes with:** SD-201 (reducer), SD-207 (instance selection state), SD-407 (mic and speaker device use)

## Outcome
The settings page lets the operator choose the microphone and speaker, the default view and sort,
the brightness and the dim-when-idle timeout, the instance the deck follows, and which alerts flash or chime.
The standalone TestMic key is removed.

## Context and evidence
`evidence/D-findings.md` §7. Today the settings page is 6 mic keys, TestMic on key 2 and paging on key 7
(`packages/streamdeck/src/settings.ts:27-44`, `surface.ts:302-332`). Brightness is a fixed env value
(`main.ts:65`). Devices are known only on the PC (`audio/devices.ts`).

## Scope
- Sidecar reports devices: on join and on a device change, send `devices` with `{mics: [...], speakers: [...]}`
  (from `listMicrophones` and a new `listSpeakers` over the same `pactl`/`pw-dump` port).
- Daemon owns the deck settings: `AiurWeb.Streamdeck.Deck.Settings` reads and writes
  `~/.aiur/instances/<key>/streamdeck-settings.json` (mode 0600, atomic write). Fields: `mic_id`,
  `speaker_id`, `default_view`, `default_sort`, `brightness`, `dim_after_seconds`, `instance`, `alerts`.
- The daemon pushes `settings` to the sidecar. The sidecar applies brightness (`setBrightness`), dims after
  `dim_after_seconds` with no input, and wakes on any input. It opens the chosen mic and speaker.
- Settings page: one key per section (Mic, Speaker, View, Sort, Brightness, Sleep, Instance, Alerts).
  Press drills into the choices, dial 1 scrolls them, press selects, and long press on dial 4 goes back.
- Remove TestMic: `SETTINGS_TEST_MIC_KEY`, its face in `descriptorSettings`, the release at `controller.ts:277`,
  and the TestMic strip panel (`touchStrip/stripLayout.ts:76,234`). Remove the same from the emulator (`streamdeck_live/modes.ex`).
- `STREAMDECK_BRIGHTNESS` stays the default until a value is saved.

## Non-goals
- No voice conversation (SD-407). No alert routing changes in the daemon. Only the deck's flash and chime choice.
- No settings sync across several decks.

## Existing owner and reuse target
- `audio/devices.ts`, `audio/preferences.ts` (the current mic memory, migrated once into the daemon file),
  `report.ts` `setBrightness`, `runtime.ts:205`, and the SD-207 instance list.

## Contract and invariants
- An unknown device id (unplugged) shows "missing" and falls back to the first device. The saved choice is kept.
- A write failure keeps the old file and shows "not saved". Never write a partial file.
- `brightness` is clamped to 0..100. `dim_after_seconds` = 0 means never dim.

```json
{"mic_id": "alsa_input.usb-Blue_Yeti", "speaker_id": "alsa_output.pci-0000_00_1f.3", "default_view": "ticket",
 "default_sort": "state", "brightness": 70, "dim_after_seconds": 300, "instance": "pc",
 "alerts": {"command": {"flash": true, "chime": true}, "ci_red": {"flash": true, "chime": false}}}
```

- The instance key path: copy the `~/.aiur/instances/` pattern used for the dashboard signing key.

## Acceptance criteria
1. No key on the settings page is TestMic. The `SETTINGS_TEST_MIC_KEY` export is gone.
2. Choosing a mic on the deck persists across a sidecar restart (it is read back from the daemon file).
3. Setting brightness 30 changes the device brightness within 1 s.
4. With `dim_after_seconds: 5`, the deck dims after 5 s with no input, and any key press restores it.
5. An unplugged saved mic shows "missing", and capture uses the first device.
6. A failed write leaves the previous file unchanged.

## Test that fails without the change
- `packages/streamdeck/test/settings.test.ts`: criterion 1 (it fails today because key 2 is TestMic).
- `src/test/aiur_web/streamdeck/deck/settings_test.exs`: criteria 2 and 6 with a temp HOME path. Do not read the real `~/.aiur`.
- A sidecar runtime test with a fake clock: criterion 4.
