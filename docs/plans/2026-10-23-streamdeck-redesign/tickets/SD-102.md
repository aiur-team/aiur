# SD-102 — Server-side key and strip image renderer (daemon)

**Complexity:** 4
**Phase hint:** 2
**Area:** area:daemon
**Depends on:** SD-101 (the adapter shell is the model input the renderer draws)
**Serializes with:** none (new files only)

## Outcome
The daemon draws every deck image once, as an SVG string: 8 keys at 120×120 and the strip as
one or more regions of an 800×100 canvas. One pure Elixir module produces them from a render model.
Each image carries a content hash and an accessible label. No new dependency is added.

## Context and evidence
See `evidence/A-findings.md` §5 to §7. Today two renderers are kept equal by a JSON contract. The
sidecar draws on canvas with `@napi-rs/canvas`. The emulator draws with HEEx and CSS. The sidecar
already rasterises SVG (`art/vendorMark.ts` uses `loadImage` on SVG files). `mix.exs` has no image
library.

## Scope
- `AiurWeb.Streamdeck.Render` (`src/lib/aiur_web/streamdeck/render.ex`) has the public API:
  - `key(face) :: image` and `strip(regions) :: [region_image]`, where `image = %{svg, hash, label}`.
  - `frame(model) :: %{keys: [image | nil] (length 8), strip: [%{x, width, svg, hash}]}`.
- Primitives under `src/lib/aiur_web/streamdeck/render/`:
  - Key face: epic icon, provider mark, ticket number, priority star, title wrapped to at most 3
    lines, status label, progress bar (fresh, stale or unknown), and an accent from a state style map.
  - Strip parts: a title and bar segment, a meter row, a count row, a text line, and a pager.
  - Groups B, C and D compose these parts. They do not add a second drawing path.
- First consumer: render today's grid view (ticket keys plus a summary, meters and pager strip)
  from the SD-101 adapter output. This proves the result is the same as the TS renderer on the
  real deck.
- Text: JetBrains Mono only. The fixed advance is 0.6 em, so wrapping and truncation use a char
  budget computed from the font size. Every interpolated string is escaped with
  `Phoenix.HTML.html_escape/1`.
- Icons:
  - Epic icons reuse the Heroicons inlining in
    `AiurWeb.OperatorControlCenter.BuildOrderEpicIcon`. Expose its path data and do not copy it.
  - Provider marks are read at compile time from `priv/static` (the same SVG files that
    `packages/streamdeck/assets/vendor/` copies). They are inlined as nested `<svg>`. The
    DeepSeek PNG is inlined as a base64 `<image href="data:image/png;...">`.
- State colours: the renderer owns them as an Elixir map, taken from today's contract tokens.
  SD-202 replaces the bucket keys with the 9 NowRows states.

## Non-goals

- No new views (group B) and no new strip layout (SD-402).
- No raster output in Elixir.

## Contract and invariants
- Every SVG has `width`, `height` and `viewBox` equal to its pixel size: 120×120 for a key, and
  `width`×100 for a region with `x + width <= 800`.
- An SVG is self-contained: no external `href` and no `<script>`. It is valid XML.
- `hash` is `:crypto.hash(:sha256, svg)`, base16-encoded and truncated to 16 characters. Equal SVG gives an equal hash.
- `label` is a plain-text accessible name, for example "#5181 Running 40% — Fix strip squeeze".
- Rendering is pure. The same model gives the same bytes, with no clock read (relative times
  arrive already formatted in the model).
- Unknown progress draws the flat grey track and never a 0% bar. This keeps the documented rule
  in guide § Progress bars.

Worked shape:

```elixir
%{
  keys: [%{svg: "<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"120\" height=\"120\" viewBox=\"0 0 120 120\">…</svg>",
           hash: "9f1c2a7be0d4c311", label: "#5181 Running 40% Fix strip squeeze"}, nil, …],
  strip: [%{x: 0, width: 200, svg: "<svg … width=\"200\" height=\"100\" …>…</svg>", hash: "…"}, …]
}
```

## Refreshable implementation notes
- Build SVG as iodata with `~s` and `Phoenix.HTML.html_escape/1 |> Phoenix.HTML.safe_to_string/1`
  for text. `phoenix_html` is already a dependency.
- Read logos with `@external_resource` plus `File.read!` at compile time. Copy the pattern of
  `streamdeck_key_face_contract.ex:10-12`. Keep the file under `src/priv`, because
  `scripts/test-check-components.sh:193-195` refuses Elixir resources read from `packages/`.
- Text metrics: `chars_per_line = floor((box_width - 2*pad) / (0.6 * font_px))`.
- Font family attribute: `font-family="JetBrains Mono, monospace"`.
- Size target: about 4 KB or less per key and about 6 KB or less per 200-wide region. Assert it in a test, so the
  frame push stays small.

## Acceptance criteria
1. `Render.key/1` with the title `"<script>&\"x"` returns an SVG that `:xmerl_scan.string/1` parses.
   The SVG contains `&lt;script&gt;&amp;` and no `<script`.
2. A 60-character title wraps to at most 3 lines, and no line is longer than the computed char
   budget. The third line ends with "…" when the title is truncated.
3. Unknown progress (`nil`) renders the grey track element and no fill rect. 0 renders a fill rect
   with a non-zero minimum width. 100 uses the complete fill colour.
4. `frame/1` for the SD-101 adapter fixture returns 8 key entries (empty slots are `nil`) and strip
   regions that tile 0..800 without overlap.
5. Each key SVG is at most 4 KB for the fixture. The output contains no `href="http` or `href="/`.
6. Calling the renderer twice with the same model gives byte-identical output and the same hash.

## Test that fails without the change
`src/test/aiur_web/streamdeck/render_test.exs` with criteria 1 to 6. Mutation guards:
- Replace the escape call with plain interpolation. Criterion 1 must fail.
- Replace the unknown-progress branch with `0`. Criterion 3 must fail.
