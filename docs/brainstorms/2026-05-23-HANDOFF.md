From adversarial review F11 (real, not theoretical):

> `slot.ex:872-876` and `drain_pending_select` both call `broadcast_attach_added` from inside the slot. If you delete `:slot_attach_added`, you must ensure the new `:slot_state_changed` (or whatever replaces it) triggers re-reads of the attach side, AND PaneManager's `attach_to_focused_pane` path (`pane_manager.ex:1240-1249`) still correctly updates `pane_to_slot` before the next user action.

Background fill or post-boot agent activation will hit this. The plan explicitly DEFERS dynamic `known_identifiers` updates to a follow-up ticket — don't try to solve it in step 4.
