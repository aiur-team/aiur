# MPG-407 — Publish full gateway workload in heartbeats: research

Plan: `docs/plans/2026-11-06-multi-project-gateways.md` (PR #7579). Contract: MPG-407 in
`docs/plans/2026-11-06-multi-project-gateways/tickets-m4-m7.md`. Code read at `origin/main` 26ec6e00d.

## Outcome

A gateway's shared-store heartbeat carries `gateway_id`, `agent_count`, `agent_capacity`, `held_tickets`, `projects`,
`public_url` and `executor_present`. `/instances` and the `aiur status` roster show each as a value when the gateway
published it, and as `unknown` / `unavailable` only when it did not. A field the gateway cannot supply is **omitted**
from the payload, never zero-filled. The whole payload stays inside a fixed byte budget.

## Corrections to the plan (read first)

The plan's code evidence (§1 row 6) and the MPG-407 contract say the heartbeat publishes only `owns`, `pool`,
`dispatching`. That describes `Aiur.Instance.heartbeat_metadata/0` (`src/lib/aiur/instance.ex:222-240`), which is only the
**fallback** in `Aiur.Instance.Heartbeat` (`heartbeat.ex:23-27`). The daemon does not use it: `children.ex:372` starts
`{Heartbeat, metadata_fun: &InstanceHeartbeatMetadata.metadata/0}`, and
`src/lib/aiur/orchestrator/instance_heartbeat_metadata.ex` already publishes `host_kind`, `public_url`, `agent_count`,
`agent_capacity`, `held_tickets`, `agents` plus the ownership keys (PR #6310).

| `gateway_id` | not published | add |

Latent defects in the existing module that this ticket must fix because it adds more calls of the same shape:

1. Failed reads publish `nil`, not "omitted": `count_agents(nil)`, `agent_capacity/0` and `held_tickets/0` return `nil`
   and the key is still written as JSON `null`. The roster treats `null` as unknown, which works, but the contract
   asks for omission and the size budget needs it.
2. `statuses/0` calls `Aiur.Orchestrator.status()`, which can return `:timeout` or `:unavailable`
   (`orchestrator/status_report.ex:85-89`); both fall to `nil`, fine. But `agent_capacity/0` and `held_tickets/0` use
   `rescue`, which does not catch the `exit` a `GenServer.call` raises on timeout. A busy orchestrator can crash
   the `Heartbeat` GenServer inside `metadata_fun.()`. Use `catch :exit, _`.
3. `Heartbeat.handle_info/2` calls `metadata_fun.()` inline, so a slow metadata build delays the publish and can
   let the 30 s TTL lapse. Calls use short timeouts (below).

## Design

All changes are in the metadata builder. The store, schema and roster transport do not change.

### Payload

`InstanceHeartbeatMetadata.metadata/1` keeps the envelope `%{"version" => 1, "data" => map}`. **No version bump:**
old readers (`Roster.metadata_data/1`, `Instance.ownership_metadata/1`) read only the keys they know and ignore the
rest, and new readers treat each new key as optional. `data` gains:

| Key | Type | Source | Omitted when |
|---|---|---|---|
| `gateway_id` | string, 26 base32 | `Aiur.Identity.machine/0` → `machine_id` (the value MPG-001 puts on control results) | `{:degraded, _}` |
| `projects` | list of `%{"repo" => string, "running" => int, "owned_tickets" => int}` | grouped from the orchestrator status rows by the repo part of `identifier` (`owner/repo#N`) | statuses unavailable |
| `executor_present` | boolean | `Aiur.Executor.Roster.build(record?: false).executors` has an entry whose `state` is `:active` or `:idle` | roster read raises or exits |
| `agent_count`, `agent_capacity`, `held_tickets`, `public_url` | as today | as today | their read returns nil/error (new: omit instead of `null`) |
| `agents` | as today | as today | statuses unavailable, **or trimmed by the size budget** |

Decisions and reasons:

- **`executor_present` uses `record?: false`.** `Roster.build/1` default records an observation
  (`roster.ex:61-63`), which would let a heartbeat timer move stall evidence. The heartbeat must not write.
- **`active` or `idle` count as present; `stalled`, `expired`, `unknown` do not.** A wedged consumer is not an
  Executor who will answer a Decision (the roster moduledoc's own point).
- **Project rows carry counts only.** `ready`, `paused`, `focus_features`, `pending_decisions` in S6 need the
  scheduler (M3/M4) and are served live by MPG-602's endpoint from the daemon; the heartbeat is the cached,
  cross-gateway fallback and publishes the three fields it can derive today. Field names equal the S6 project keys
  (`repo`, `running`, `owned_tickets`) so MPG-602 reuses them verbatim.
- **Single-project today.** With one orchestrator, `projects` has one row (or none when idle: zero rows is a valid
  list). When M3 multi-project orchestrators exist, the same grouping works because the identifier already carries the repo.
- **`owned_tickets` per project** is the count of `held_tickets` ("owner/repo#N") whose repo matches. When
  `held_tickets` is unavailable, the project row omits `owned_tickets` rather than using 0.
- **Omit, don't zero.** Build the map from `{key, value}` pairs and drop `nil`. `false` and `0` survive (a real
  `executor_present: false` and `agent_count: 0` are facts).

### Size limit

The column is `metadata_json text NOT NULL` (`lease_store/postgres.ex:39`). PostgreSQL itself allows far more than we
need (a hard cap exists; exact figure pending evidence, and irrelevant because we set our own). The binding
constraints are ours: the heartbeat runs every 10 s per gateway (`heartbeat.ex:8`), `list_live`/`list_roster`
returns every row to every reader, and a 5 s query timeout (`lease_store.ex:399`).

Budget: **`@max_bytes 8_192`** for `Jason.encode!(metadata)`. Estimated shape (not yet measured on a live store; the implementer records the real size in the PR): a row in `agents` is about
150 bytes (identifier + title + state) so 8 agents is about 1.2 KB; a project row is about 70 bytes; the fixed keys
about 400 bytes. Normal payloads are under 2 KB, so the budget is a guard, not a daily event.

Trim order when over budget, re-measuring after each step, and record what was cut:

1. Truncate each `agents[].title` to 80 bytes.
2. Drop `agents` entirely.
3. Truncate `held_tickets` to the first 50 and set `"held_tickets_truncated" => true`.
4. Truncate `projects` to the first 25 and set `"projects_truncated" => true`.

`agent_count`, `agent_capacity`, `gateway_id`, `executor_present` and the ownership keys are never trimmed; they total
under 500 bytes, so the budget is always reachable. Every trim sets `"trimmed" => ["agents", ...]` so a reader can
tell "omitted for size" from "unknown". Alternative rejected: a hard error on overflow, because a failed heartbeat
removes the gateway from the roster and the dispatch eligibility check
(`self_missing_from_roster`) halts dispatch.

### Timeouts

`statuses/0` already passes `Aiur.Orchestrator.status()` the 5 s default. Change the builder to read the status
once with `status_api(Aiur.Orchestrator, 1_000)` (the `poll_status_api` bound) and derive `agents`, `projects`,
`agent_count` from that one list. Wrap capacity, held tickets and executor roster in `catch :exit, _`. Worst
case the builder spends about 3 s, inside the 10 s interval and the 30 s TTL.

### Roster side

`Roster.present/5` (`src/lib/aiur/instance/roster.ex:80-104`) adds `gateway_id: metadata["gateway_id"]`,
`projects: metadata["projects"]`, `executor_present: metadata["executor_present"]`, `trimmed: metadata["trimmed"]`.
`Roster.Presentation` gains `executor(true) → "present"`, `executor(false) → "absent"`, `executor(_) → "unknown"`.
Rendering: `instance_roster_live.ex:58-60` and `status_cli.ex:167` add `executor=...` and a `projects=repo:running,...`
segment, `unknown` when nil. Per AGENTS.md "Computed ages": the age is already rendered (`age_ms`); do not
add a new one.

## Test scenarios

| Scenario | Input | Expected |
|---|---|---|
| Full payload | statuses: 3 running rows (2 `acme/widgets`, 1 `acme/api`); capacity 4; held `["acme/widgets#1","acme/widgets#2","acme/api#9"]`; gateway id `"01HZ..."` (26 chars, fixture); executor roster `[%{state: :active}]` | `agent_count 3`, `agent_capacity 4`, `executor_present true`, `projects` = `[%{"repo"=>"acme/widgets","running"=>2,"owned_tickets"=>2}, %{"repo"=>"acme/api","running"=>1,"owned_tickets"=>1}]`, `gateway_id` equals the fixture |
| Statuses unavailable | `statuses_fun` returns `nil` | no `agent_count`, `agents` or `projects` keys (`refute Map.has_key?`); key `agent_capacity` still present |
| **Omitted, not zero** (fails without) | capacity read exits; statuses nil | data lacks `agent_capacity` and `agent_count`; fed through `Roster.list` the row has `agent_count == nil` and `Presentation.count/1` gives `"unknown"`. Mutation: make the builder default them to `0` and this test fails |
| Zero is a fact | statuses `[]`, held `[]`, executor roster `[]` | `agent_count 0`, `held_tickets []`, `executor_present false`, `projects []` |
| Identity degraded | `Identity.machine` returns `{:degraded, :not_loaded}` | no `gateway_id` key; never a made-up id |
| Stalled executor | roster `[%{state: :stalled}, %{state: :expired}]` | `executor_present false` |
| Roster read does not record | executor fun is the real `Roster.build` with a temp claims `path:` | calling `metadata/1` leaves the claims file's observations unchanged (bytes equal before and after) |
| Exit is contained | `held_tickets_fun` and `executor_fun` call `exit(:timeout)` | `metadata/1` returns; keys omitted; process alive |
| Size trim step 1 | 20 agents, titles 300 bytes, `max_bytes: 4_096` | encoded size <= 4096; `trimmed == ["agent_titles"]`; every title <= 80 bytes |
| Size trim to floor | 200 held tickets, 100 projects, `max_bytes: 1_500` | size <= 1500; `agent_count`, `gateway_id`, `executor_present`, `owns`, `pool`, `dispatching` all present; `trimmed` lists every cut |
| Old reader compatibility | new payload into `Instance.eligible?/3` and `Roster.list/1` | same eligibility result as the payload without the new keys; no crash |
| Roster passes new keys | record metadata with `gateway_id`, `projects`, `executor_present: true` | row fields equal the input; with the keys absent, row fields are `nil` and `Presentation.executor(nil) == "unknown"` |
| Unknown branch not defaulted | render a roster row with `executor_present` nil | output contains `executor=unknown`; replacing the nil branch with `"absent"` fails the test |

## Data and assets

Heartbeat JSON example (about 600 bytes):

```json
{"version":1,"data":{"gateway_id":"01HZXAMPLEMACHINEID00000A","host_kind":"home","public_url":"https://aiur.example",
"agent_count":3,"agent_capacity":4,"held_tickets":["acme/widgets#1"],"executor_present":true,
"projects":[{"repo":"acme/widgets","running":2,"owned_tickets":1}],"agents":[],
"owns":[],"pool":true,"dispatching":true}}
```

Known gaps and fallback: pre-MPG-407 gateways keep publishing the old shape and the roster shows `unknown` for the
new fields; that is the intended mixed-version behaviour. `focus_features`, `ready`, `paused`, `pending_decisions`
wait for the scheduler; MPG-602 serves them live.

## Risks

- **Heartbeat latency.** More reads in the publish path. Detect: log `heartbeat build_ms`; fallback: build in a Task
  with a 3 s deadline and publish the previous payload.
- **Executor roster contention.** `Claims` reads a file; `record?: false` keeps it read-only. Detect: the "does not record" test.
- **Mixed-version fleets** read `null`/missing as unknown; covered by the compatibility test.
- **Title content** in `agents` may include sensitive ticket titles in a shared store; unchanged from today, but the
  trim in step 1 reduces it. Raise with the operator if the store is shared across trust boundaries.

## Open questions

| Question | Recommended default | What changes if answered differently |
|---|---|---|
| Publish `ready`, `paused` per project now? | No; wait for the scheduler (M4) | If yes, MPG-407 depends on MPG-401 and gains a scheduler read |
| Byte budget | 8 KiB | A smaller budget trims `agents` more often; a larger one grows each 10 s write for every gateway |
| Does `executor_present` include `stalled`? | No (only `active`, `idle`) | If yes, the dashboard shows a wedged Executor as present, the failure the roster module exists to avoid |
| Bump envelope `version` to 2? | No; keys are additive | If yes, every reader (`Roster.metadata_data/1`, `Instance.ownership_metadata/1`) must accept 2 first, a separate ticket |
| Should MPG-001's `gateway_id` live in a shared helper both use? | Yes: call `Aiur.Identity.machine/0` in both | If MPG-001 names a different helper, switch the one `gateway_id/0` function |
| Should this ticket also fix the `exit` handling of the existing capacity/held reads? | Yes, in scope (same file, same failure) | If no, the new reads wrap `catch` but the old ones can still crash `Heartbeat` |
