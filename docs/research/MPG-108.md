# MPG-108 — Make the Postgres lease an optimisation under durable ownership: research

Research ticket MPG-108R (#7611). Plan: `docs/plans/2026-11-06-multi-project-gateways.md` (KTD-2, KTD-3, "Ownership
protocol"). Contract: MPG-108 in `docs/plans/2026-11-06-multi-project-gateways/tickets-m0-m1.md`. Code read at
`a39605edc` (origin/main, 2026-11-06). Line numbers refer to that commit. No code changed.

## Outcome

With `instance.ownership: github` (key added by MPG-103), no decision about *who owns a ticket* reads Postgres. Dispatch,
the 11 per-ticket observers and the repository-wide services decide from the durable ownership ref (S1) plus a local
read-only view of it. With the store configured, the store still does two jobs and only two: the per-run lease
(`LeaseStore.claim/1`, refuses a second concurrent run of one owned ticket) and liveness (heartbeats, roster, leader
election for repository services). With `instance.ownership: off`, nothing changes.

dashboard or sweep will show fewer rows on the non-owner.

## Design

Decisions use the labels **decided** (in the plan), **proposed default**, or **open** (section "Open questions").

**D1 (decided by KTD-3).** Postgres never grants or revokes ownership. Ownership comes from the ref only.

**D2 (proposed default). A read-only ownership view, `Aiur.Ownership.View`, answers observers.**
New file `src/lib/aiur/ownership/view.ex`. ETS table `:aiur_ownership_view`, owned by one GenServer, read with
`:ets.lookup` from any process (observers run in many processes and must not call GitHub).

```elixir
@spec lookup(ticket_key :: String.t()) ::
        {:owner, %{gateway_id: String.t(), daemon_key: String.t(), epoch: pos_integer()}}
        | :unowned
        | :released
        | :unknown
@spec put(ticket_key :: String.t(), record :: map(), observed_at :: DateTime.t()) :: :ok   # from MPG-103 claim and read results
@spec replace_all([{ticket_key :: String.t(), record :: map()}], observed_at :: DateTime.t()) :: :ok  # from the refresh
@spec ready?() :: boolean()
```

Fed by two writers: (a) `Aiur.Ownership.ensure_owned/2` (MPG-103) calls `put/3` after every `:won`, and after every
`{:lost, current}`; (b) a refresh, `Aiur.Ownership.View.Refresh`, once per orchestrator poll lists all refs under
`refs/aiur/owners/` in one paginated GraphQL `refs(refPrefix:)` call (MPG-101 step 8 confirmed list-by-prefix works) and
calls `replace_all/2`. The refresh must bypass `Aiur.GitHub.ReadCache`, as MPG-102 requires for ownership reads.
Whether the single call can also return `owner.json` inline (`target { ... on Commit { tree { entries { object { ... on
Blob { text } } } } } }`) is **pending evidence**: MPG-102R must confirm. Fallback: store each ref's commit oid in the
view; fetch the blob only for oids that changed since the last poll.

`lookup/1` returns `:unknown` when the view has never loaded (`ready?() == false`) or its newest observation is older
than `ownership.view_max_age_ms` (see Config). It returns `:unowned` only when the view is fresh and has no ref for the
key.

**D3 (proposed default). `foreign?` under ownership.**
In `Aiur.Instance`, `foreign_by_shared_lease?/1` becomes `foreign_by_owner?/1`, chosen by the ownership mode:

| Mode | `lookup/1` | Result |
|---|---|---|
| `off` | n/a | today's `LeaseStore.holder/1` logic, unchanged |
| `github` | `{:owner, self}` | not foreign |
| `github` | `{:owner, other}` | foreign |
| `github` | `:unowned` or `:released` | not foreign (matches `:unheld` today: nobody owns it, observers may act) |
| `github` | `:unknown` | foreign (fail closed, same as today's `_unknown_or_error -> true`) |

"Self" is `gateway_id` **and** `daemon_key` (S1), so two daemons on one machine do not both count as owner. The existing
`foreign_by_rules?/3` (`instance.ignore`) is untouched and still ORed in: it is a manual operator override, not
ownership. The existing `foreign_by_shared_lease?/2` tests (4 references in `instance_test.exs`) keep working in `off` mode.

**D4 (proposed default). Dispatch eligibility under ownership.** `Instance.eligible?/3` gets a new first clause, per the
contract: a ticket whose ownership record names this gateway returns `:eligible` before any roster check. Signature
change: `eligible?(ticket, self, live_instances, owner \\ :unknown)`; the owner is the view's answer, passed in by the
caller so the function stays pure. Behaviour:

- `owner = {:owner, self}` -> `:eligible` (roster not consulted; works with `live_instances == []`).
- `owner = {:owner, other}` -> `{:ineligible, :peer_owns_ticket}`.
- otherwise today's roster logic, but see D5.

**D5 (proposed default). Roster failure is advisory under ownership.** In
`shared_lease_dispatch.ex:89-107` (`ownership_eligibility/2`):

| Roster result | `off` (today) | `github` |
|---|---|---|
| `{:ok, list}` | `Instance.eligible?/3` | same, with D4 owner argument |
| `{:error, :store_not_configured}` | `{:unavailable, :store_not_configured}` if `owns` set, else `:eligible` | `:eligible` (ownership claim decides) |
| anything else (store down) | `{:unavailable, :live_roster_unknown}` hold | `:eligible` (the claim on GitHub decides; no `ownership_unknown` hold) |

The `{:unavailable, :self_missing_from_roster}` result (`instance.ex:134`) also becomes `:eligible` under `github`
when the owner is self, which D4 already returns first. The `instance.owns`/`pool` reservation policy is therefore
enforced only while the roster is readable; see open question Q1.

**D6 (proposed default). The run lease stays, as an optimisation.** `dispatch_with_shared_lease/5` and
`DispatchClaim.call/3` keep their shape. Changes:

1. `DispatchClaim.call/3` stays as is for `off`. Under `github`, `{:error, {:shared_lease_unavailable, _}}` (store down)
   no longer holds dispatch: it proceeds with `{:ok, :degraded, dispatch_fun.()}` and logs once per outage. The ownership
   ref already prevents two *gateways*; the lease only adds protection against two runs by *one* owner (restart
   overlap), which a store outage cannot add to. `:held` still refuses (a second live run).
2. `AgentRunner.run/3` lease watch (`agent_runner.ex:25-30`): the `pr_head_ref` bypass is MPG-103's. MPG-108 only
   changes the failure arm: `LeaseStore.watch/1` errors under `github` log and continue rather than stop the run.
   (`lease_watch` result values besides `:ok`/`:disabled` are not read in this research; MPG-108 implementer reads
   `agent_runner.ex:25-60` first and keeps stop-on-`:lost` semantics: a *lost* lease still stops the run.)
3. The `Aiur.Instance.LeaseStore` outage alert text (`lease_store.ex:462`, "dispatch is held and observers fail
   closed") is wrong under `github`; make it mode-aware (below).

**D7 (proposed default). Repository services without a store.** `RepositoryLeader` (`repository_leader.ex:69-80`)
without a store starts services for every `primary`; `secondary` already stops them first (line 69,
`elect(%{role: "secondary"})`). So acceptance bullet 4 of the contract, as written, **already passes today** and is not
"fails without". Evidence: `elect/1` pattern-matches `role: "secondary"` before the `store_configured_fun` branch.
`LeaderFence.allowed?/1` (`leader_fence.ex:12-14`) also returns false for secondary. Recommendation: keep the bullet
as a guard test (name it `..._guard_secondary_without_store`, mark "passes on main, guards regression") and do not
count it toward covering the change. With ownership on and no store, two `primary` gateways on one repository both run
landing watch, main watch and the quarantine lifter; this is the real remaining gap. Proposed default: leave it, and
document that a shared repository without a store needs exactly one `primary` and the rest `secondary` (the
`instance.role` key already says "Without a shared store, primary retains single-instance behavior"). Leader election
without a store is a separate piece of work (Q2).

**D8 (proposed default). Alerts.** `system.instance.ownership_unknown` (`lease_store.ex:462`) keeps firing for a store
outage, but under `github` with `ownership_unknown` severity lowered: `needs_attention: false`, message "Shared lease
store unavailable; ownership continues on GitHub, run leases are off." The held-dispatch wording stays for `off`. The
`ownership_unknown` *decline* reason in MPG-103 (GitHub ref unreadable) is a different condition and keeps
`needs_attention: true`.

## Risks

| Risk | Detect | Fallback |
|---|---|---|
| View stale or never loaded makes every observer skip (fail closed) and the board go quiet | `aiur status` shows `ignored_since_boot` rising fast; view `observed_at` age | Set `ownership: off`; refs are inert. Add `view age` to `aiur status` (consumer MPG-104). |
| Cold boot: reconciler runs before the first refresh | Scenario 15 | Start `View` before the orchestrator and block the first reconciler pass on `ready?/0` for up to one poll |
| An idle ticket stops being visible to the non-owner | Compare `aiur agents` / sweep rows before and after on a two-gateway repo | Intended; mention in PR and docs |
| Owner gateway offline: its tickets stay reserved and unobserved | MPG-701 A5 | Explicit `aiur ticket assign` (MPG-106) |
| Roster reservation policy skipped while the store is down | Q1 | Keep `pool: false` on the gateway that must not take unreserved work |
| `agent_runner.ex` lease-watch semantics misread | Review `agent_runner.ex:25-60` before D6.2 | Skip D6.2 and ship D6.1 only |
