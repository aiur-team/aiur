Research ticket MPG-604R (#7631). Inputs: `docs/plans/2026-11-06-multi-project-gateways.md` (PR #7579), the MPG-604 contract in
`docs/plans/2026-11-06-multi-project-gateways/tickets-m4-m7.md`, `state-schemas.md` (S2, S4, S6), `code-evidence.md`,
`docs/research/MPG-601.md` (the design this builds to), `MPG-209.md` (shared `Workload.derive/1`), `MPG-408.md`

## Outcome
`/gateways` lists every gateway the home gateway knows (itself plus S2 registry peers). `/gateways?gateway=nook` shows one:
connectivity and workload as **two separate fields**, capacity, projects, agents, local queue, health, owned tickets, and
a `[Pause Nook]` button. The home screen gains a gateway filter that links here. A **Pause all** button opens a delivery
report with one line per gateway. With one gateway offline and the shared store up, that line reads
`will pause on reconnect`. An online, idle gateway reads connectivity `online` and workload `idle`.

## Design
Decisions D1-D7 of MPG-601 are fixed and not reopened. What MPG-604 adds:

1. **Thin LiveView, browser fetches the rest.** `AiurWeb.GatewayLive` renders the shell, the local gateway's own data
   server-side, and mounts one JS hook that fetches each *peer* summary cross-origin with `credentials: "include"` (MPG-601 D2).
   The server cannot render peer data: it holds no peer session. So peer fields are filled by the hook, local fields by
   LiveView. Both go through the same presenter shape so one test fixture covers both.
2. **Pure JS state module.** `connectivity` and the delivery report are computed in `gateway-state.js`, a plain ES
   module with no DOM, so it is unit-testable with `node --test` and mutation-testable. The LiveView and hook only render
   its output. This is where the `[fails without]` guarantees live.
3. **Connectivity is the MPG-601 table verbatim** (`connecting|online|error|unknown|offline`). The hook never maps "no
   answer" to `offline` or `idle`. `offline` needs the server-side liveness flag (MPG-408) delivered by the home gateway
   in the shell's `data-offline-peers` attribute. Workload comes from the S6 `workload` field, computed by the gateway
   with `Aiur.Gateway.Workload.derive/1` (MPG-209). The browser does not recompute it.
4. **Stale values.** Not-`online` gateways show the last cached summary (`localStorage` key `aiur.gateway.summary.<gateway_id>`,
   with `observed_at`), prefixed `last known` and an age. No cache: `unknown · never seen on this device`. Never `0`, never `idle`.
5. **Pause writes.** Browser writes need the D5 rules: preflighted, `X-Aiur-Request: 1`, `Origin` in `server.dashboard_origins`
   or registry URLs. Add two session-authenticated endpoints on every gateway (existing `agent_writes` scope in
   `routes/api.ex`, so `observability.dashboard_writable: false` still blocks them):
   - `POST /api/v1/gateway/pause` and `POST /api/v1/gateway/resume`, body `{"request_id": "<uuid>"}`; response
     `{"ok": true, "globally_paused": true|false, "request_id": "..."}`. They call `Aiur.Orchestrator.Client.set_global_pause/2`
     (`client.ex:151`, today used by `ControlCli.pause_global/0`), with source `"dashboard gateway pause"`. Replay of the same
     `request_id` returns the stored response (MPG-204's `ReplayStore`); no new idempotency code here.
   - The existing `POST /api/v1/:issue_identifier/pause` is per-agent and stays untouched. The new literal route is declared
     **before** it, or `gateway` is captured as an issue identifier.
6. **Pause all** is browser-orchestrated, in this order:
   1. `POST` the *home* gateway `/api/v1/fleet/pause` (new, same scope; calls MPG-406's `fleet.pause` writer, slot `human`).
      Result: `intent_written` true or false (store unreachable within 5 s).
   2. In parallel (`Promise.allSettled`, 3 s timeout each): `POST /api/v1/gateway/pause` to every gateway with a known URL.
   3. Feed both into `deliveryReport/2` (below). Resume mirrors with `/fleet/resume`; per reconciliation rule 5 a human
      resume clears every slot.
   Writing intent first matters: if a direct call fails after the write, the gateway still applies the pause on reconnect.
7. **Scope cut.** The ticket names gateway pause and pause-all. The per-project `[⏸]` of MPG-601 needs MPG-308, which is
   not a dependency of MPG-604. It is out of scope here (Open question 1).

Rejected: server-side proxy of peers (MPG-601 D2); polling LiveView for peers (no peer session); a browser percentage
threshold for `saturated` (the gateway computes it); writing pause only to shared intent (a reachable gateway must pause
immediately; MPG-406 acceptance says the direct call still works with the store down).

### Delivery report rules (`deliveryReport({intentWritten, results, gateways})`)
| Per-gateway outcome | Line text |
|---|---|
| Direct call 2xx and `globally_paused: true` | `paused ✓` |
| Direct call 2xx but `globally_paused: false` | `error: pause not applied` |
| 401/403 | `not paused: signed out` plus `[Sign in]` |
| No answer (timeout, `TypeError`) and `intentWritten` | `will pause on reconnect   (unreachable; fleet pause is in shared intent)` |
| No answer and not `intentWritten` | `not paused: unreachable and no shared store` |
| No URL (off tailnet card) | `not paused: off tailnet, pause it from its own dashboard ↗` |
| 5xx / other | `error: <status>` |
Header: `Pause all — N gateways`. A "no answer" is never reported as paused and never as `offline`.

## Prior art
None needed beyond MPG-601 and the three `docs/research/multi-gateway/` reports (priority-reconciliation covers the
`fleet.pause` pause-wins tie). The only external behaviours relied on are `fetch` rejecting with `TypeError` on any network,
TLS, CORS or mixed-content failure (so causes cannot be told apart, per MPG-601 D6) and `Promise.allSettled`. *Pending
evidence* for cross-origin cookie behaviour: MPG-601 E1/E2; this ticket's browser test stubs the peers and cannot prove it.

## Risks
- **Dependency drift:** MPG-602/603/406 contracts are assumed. Detect early: unit 1 starts with a grep for the real names; if S6 lacks the agent list, stop and raise it, do not invent a second summary.
- **Route capture:** `:issue_identifier` swallows `gateway`. Covered by the route-order test.
- **Cross-origin cookies** unproven (MPG-601 E1/E2): the real-browser check cannot run in the workspace. Add to the PR body: `Post-deploy check: from the PC dashboard, press Pause all with Nook stopped and confirm Nook reads "will pause on reconnect" (operator: PC and Nook).`
- **CORS widening:** four write paths join the allowlist. A mistake lets a listed origin write; test the unlisted case.
- **Duplicate pause:** retried POST without request_id; mitigated by always sending one.
- **File size:** `gateway_live.ex` plus presenter must stay under 500 lines each.
