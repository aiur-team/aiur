# MPG-001 — Expose the gateway identity on every daemon response: research

Research deep dive MPG-001R (#7581). Plan: `docs/plans/2026-11-06-multi-project-gateways.md` (PR #7579), contract
MPG-001 in `docs/plans/2026-11-06-multi-project-gateways/tickets-m0-m1.md`. No code changed by this document.

## Outcome

Every control-call result, every instance heartbeat and the instance status summary carry `gateway_id` (the durable
machine id from `identity.json`) and `gateway_label` (the machine label). When `identity.json` is unreadable or not
loaded the three keys read `gateway_id: null`, `gateway_label: null`, `gateway_identity: "unavailable"`; an id is
never invented. `instance_id` is untouched everywhere.

## Design

### The two existing identity schemes (confirmed in code)

| | `Aiur.Identity.instance_id/0` | `Aiur.Instance.Identity.current/0` |
|---|---|---|
| File | `src/lib/aiur/identity.ex:23-29` | `src/lib/aiur/instance/identity.ex` |
| Value | `<machine_id>/<AIUR_INSTANCE_KEY>` (26-char base32 id, 10-hex key), or `nil` when either half is missing | `instance.id` config, else `<hostname>:<base64url(sha256(state_dir)[0,8])>`; never nil |
| Source of truth | `identity.json` via `Aiur.Identity.Machine.current/0` (`:persistent_term`), launcher env key | `Aiur.Config.settings/0`, pinned in `Application.put_env(:aiur, :booted_instance_id)` by `Instance.Identity.configure/0` (`src/lib/aiur.ex:81`) |
| Meaning | "which daemon, on which machine", for the dashboard, capabilities, events, voice | Row key of the shared PostgreSQL coordination store |

They are different keys for different purposes and cannot be unified by MPG-001. The gateway identity is a third,
coarser value: the machine id alone (`Aiur.Identity.machine/0`), shared by every daemon on that machine.

### Callers that must keep `instance_id`

Keep as is (store keys, wire contracts, per-daemon addressing):

- `Aiur.Instance.Identity` users: `src/lib/aiur/instance.ex:153,190`, `instance/roster.ex:88`,
  `instance/lease_store.ex:8`, `instance/lease_store/repository_lease.ex`, `instance/lease_store/shared_state.ex`,
  `orchestrator/dispatcher/shared_lease_dispatch.ex:95` — PostgreSQL row keys and ownership; changing them orphans
  live leases.
- `Aiur.Identity.instance_id/0` users: `instance_summary.ex:25,61`, `capabilities.ex:35`, `capabilities_cli.ex:14`,
  `capabilities/collector.ex:15`, `events/instance_id.ex` (event feed epoch: a changed value starts a new export
  epoch), `aiur_web/voice_targets.ex:84-89` (same-instance check), `aiur_web/conversation/composer.ex:41`,
  `experiments/auto/deploy_ledger.ex:74`, and the control result `instance_id` key
  (`control_controller.ex:141`).
- `gateway_id` must not be compared with either: a roster row's `instance_id` is the second scheme, a control
  response's is the first. Consumers pin `gateway_id` only (plan `state-schemas.md`, peer entry: `gateway_id` is pinned and a response with another id is refused).

Not callers of either scheme (no change): everything reading `Aiur.Identity.machine/0` already.

### Module

New `Aiur.Gateway.Identity` with one function:

```elixir
@spec current() :: %{gateway_id: String.t() | nil, gateway_label: String.t() | nil, gateway_identity: String.t()}
def current do
  case Aiur.Identity.machine() do
    {:ok, %{machine_id: id, label: label}} -> %{gateway_id: id, gateway_label: label, gateway_identity: "available"}
    {:degraded, _reason} -> %{gateway_id: nil, gateway_label: nil, gateway_identity: "unavailable"}
  end
end
```

Reason for a third key on the available path too: consumers `Map.merge/2` one map and the JSON shape is identical in
both states. Reason for reusing `Aiur.Identity.machine/0` rather than reading `Machine.current/0`: it already folds
`:not_loaded` and unreadable into `{:degraded, _}`. The degraded reason is deliberately collapsed to
`"unavailable"` at this single point (the AGENTS.md "collapsed cause" rule: cause-neutral, not a specific cause).

Alternative rejected: add `gateway_id` into `Aiur.Identity.instance_section/0`. That function feeds capabilities
and its output is guarded by `InstanceSummary.Guard` keys; widening it changes more than the ticket names.

### Wiring

1. **Control result** — `src/lib/aiur_web/controllers/control_controller.ex`, `result/3` (line ~138): add
   `|> Map.merge(Aiur.Gateway.Identity.current())` beside `instance_id:`. Error bodies (`error/5`) are left alone:
   the acceptance names results; refusals carry no daemon facts today.
2. **Heartbeat** — `src/lib/aiur/orchestrator/instance_heartbeat_metadata.ex`, `metadata/1`: put
   `"gateway_id"`, `"gateway_label"` (string keys, stored JSON) into the `"data"` map next to `"host_kind"`; new
   option `:gateway_identity_fun` (default `&Aiur.Gateway.Identity.current/0`) so tests inject without global state,
   following the existing `*_fun` options. Keep `"version" => 1`: additive keys, readers ignore unknown keys
   (`ownership_data/1`, roster reads by name). `"gateway_identity"` is also written so a roster row can show
   "unavailable".
3. **Status summary** — `src/lib/aiur/instance_summary.ex` `v1/1`: add the three keys beside `instance_id`;
   `src/lib/aiur/instance_summary/guard.ex` `@keys`: add `gateway_id gateway_label gateway_identity` (the guard
   walks every key and rejects unlisted ones in test). The plan lists "status report" in the Outcome without a file in
   the Files line; this is the only report with an identity header, so it is included. Value is injected with
   `opts[:gateway_identity]` like `:instance_id`. The 4,096-byte budget is not at risk (about 100 bytes added).

Out of scope: renaming `instance_id`, the registry (MPG-201), `aiur capabilities`/`status_cli` rendering of the new
fields (a later ticket may print them), the dashboard.

## Test scenarios

Fixture: `Aiur.Identity.Machine.ensure(dir: tmp, hostname_fun: fn -> {:ok, ~c"workstation.example"} end)` as in
`src/test/aiur/identity_test.exs:22-36`, restoring the `{Machine, :boot_result}` and `{Machine, :boot_context}`
persistent terms in `on_exit`. Use `Aiur.TestCleanup.rm_rf!/1` for the temp dir.

| Scenario | Input | Expected |
|---|---|---|
| Available | fixture above | `current() == %{gateway_id: machine.machine_id, gateway_label: "workstation", gateway_identity: "available"}` |
| Unavailable, not loaded | erase `{Machine, :boot_result}` | `%{gateway_id: nil, gateway_label: nil, gateway_identity: "unavailable"}` |
| Unavailable, unreadable | `:persistent_term.put({Machine, :boot_result}, {:degraded, :identity_unreadable, :x})` | same map as above |
| Control result, available | read-token `POST` with `Aiur.AgentControlCLI.status()` (existing test shape, `control_controller_test.exs:~55`) | body `"gateway_id" == machine.machine_id`, `"gateway_label" == "workstation"`, `"instance_id"` still present and unchanged |
| Control result, unavailable | identity erased | body `"gateway_id" == nil`, `"gateway_identity" == "unavailable"`, `Map.has_key?(body, "gateway_id")` true |
| Heartbeat | `metadata(gateway_identity_fun: fn -> %{gateway_id: "abc", gateway_label: "l", gateway_identity: "available"} end, ...)` | `get_in(metadata, ["data", "gateway_id"]) == "abc"`, `"version" == 1` |
| Heartbeat unavailable | fun returns the nil map | `"gateway_id" == nil` and `"gateway_identity" == "unavailable"` (not `""`, not the last known id) |
| Summary | `InstanceSummary.v1(gateway_identity: ...)` | top-level keys equal the injected values; `Guard.check!/1` does not raise |
| Instance id unchanged | existing `identity_test.exs` | still passes untouched |

**Reverting checks (AGENTS.md):** the controller "available" and "unavailable" tests fail with the `Map.merge` removed;
the "unavailable" test fails if the degraded branch returned a placeholder id such as `"unknown"` or `""`. The summary
test fails if the three keys are left out of `Guard` `@keys` (strict in test).

## Risks

- **`persistent_term` leakage across tests**: the identity cache is global. Detect by running the controller test
  alone and after `identity_test.exs`; fallback is to inject via a function option on the controller (not preferred).
- **Strict summary guard**: an unlisted key raises only in `Mix.env() == :test`; production silently logs. Mitigated
  by the summary test.
- **Roster readers**: any code that pattern-matches heartbeat `data` exactly would break on new keys. `roster.ex:89` reads `metadata["host_kind"]` by key and is the only other
  `"host_kind"` reader in `src/lib`.
- **Merge order with MPG-204**: both edit `control_controller.ex`; MPG-001 is a one-line merge in `result/3`.

## Open questions

| Question | Recommended default | What changes if answered differently |
|---|---|---|
| Does `current/0` always return `gateway_identity`, or only when unavailable? | Always (`"available"`/`"unavailable"`) | Contract says the key appears only when unavailable; consumers would branch on a missing key instead of a value |
| Include the status summary and heartbeat `gateway_identity`? | Yes (Outcome says "status report"; Files line omits it) | Drop units 3-4 and the summary files; the Outcome shrinks to the control result and heartbeat |
| Add gateway keys to refusal/error bodies? | No | One more `Map.merge` in `error/5` and tests; pinning clients would then learn the id from a refusal |
| Does `instance_id` in the control result stay the first scheme? | Yes, unchanged | Changing it breaks event epoch and voice targeting |
| Bump heartbeat `"version"`? | No (additive) | Roster readers would need a version branch |
