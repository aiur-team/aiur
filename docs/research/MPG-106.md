# MPG-106 — Show and transfer ticket ownership from the CLI: research

Research ticket MPG-106R (#7609). Inputs: `docs/plans/2026-11-06-multi-project-gateways.md` (KTD-2, S1, Ownership
protocol), `tickets-m0-m1.md` (MPG-106), `state-schemas.md`, the MPG-001/002/101/205/207/209/407/408 research docs, and the
code read below. No code change. Brainstorm questions are recorded under Open questions, each with a default.

## Outcome
`aiur ticket owner <n>` prints the owner (gateway label and id, daemon key), `epoch`, `actor`, `reason`, the record's age,
and whether the owner is `online`, `offline` or `unknown`, with the source of that verdict. `aiur ticket assign <n> --to
<gateway> --reason <text>` advances the ownership ref to the new gateway with compare-and-set (`epoch + 1`) and then
disables auto-merge on the old owner's open PR. It refuses a live owner without `--force`, and `--force` works only
locally and only for a human. An owner that cannot be shown to be offline counts as live. Nothing is ever printed as
owned, live or zero when the read failed: it prints `unknown`.

## Design
**Where it runs.** Both verbs run on the gateway the CLI targets (local, or `--gateway <g>` through the existing control
call). The daemon does the work; the shell only parses and encodes, exactly like `cmd_ticket estimate`
(`packaging/npm/aiur-cli/libexec/engine/ticket.sh`: `run_control_rpc "Aiur.AgentControlCLI.ticket_estimate([...])"`,
strings crossing as base64 via `encode_control_value`). `cmd_ticket` today rejects every subcommand but `estimate` (line
3); it becomes a `case` over `estimate|owner|assign`.

**Read path (`owner`).** `Aiur.Ownership.GitHubRef.read/2` (MPG-102; uncached by MPG-102's own acceptance) returns the S1
record, "no ref" or `unknown`. Output states: `owned`, `released` (record kept, no owner), `unowned` (no ref), `unknown`
(read failed; exit 75, no owner fields). The ref is the only source of truth; the `gateway:<label>` label is MPG-104's
projection and is not read here.

**Liveness (the point of this research).** A pure function `Aiur.Ownership.Liveness.classify/2` takes the owner record,
the evidence gathered, and `offline_after_ms`, and returns `{status, source, observed_at, age_ms}`. Evidence, in order:

| # | Source | What it proves | Used for |
|---|---|---|---|
| 1 | `owner.gateway_id` equals this gateway's id and `daemon_key` equals this daemon's key | self | `online`, source `self` |
| 2 | Store heartbeat: a live-roster row whose metadata `gateway_id` (MPG-001 adds it to `InstanceHeartbeatMetadata`) matches and whose `instance_id` equals `owner.daemon_key` | the owner daemon published within the window | `online`, source `heartbeat` |
| 3 | Hello: `GET /api/v1/gateway/hello` (MPG-207) on the registry entry whose pinned `gateway_id` equals the owner's | the gateway's daemon answers now | `online`, source `hello` |
| 4 | Store row present but `age_ms > offline_after_ms`, and hello did not answer (or no registry entry) | silent beyond the threshold | `offline`, source `heartbeat` |
| 5 | Anything else (store down, store up but no row, hello unreachable and no row, hello `gateway_id` differs from the owner's) | no source | `unknown` |

Rules that follow from the plan:
- **Only `offline` allows a transfer without `--force`.** `unknown` is treated as live (plan, failure table: "With no
  liveness source (store down, hello unreachable) the owner counts as live"). Rows 1-3 are live.
- **The threshold is `coordination.offline_after_seconds`** (MPG-002; integer 30..86400, default 180, the same value
  MPG-408 uses for its offline alert), read through `Aiur.Machine.Settings.get/0`. It is not `Roster`'s 30 s
  `stale_after_ms`: a row 31 s old is `stale` on the roster but not offline here. `Roster.list/1` returns `age_ms` already
  (`roster.ex` `present/5`), so the function compares `age_ms` itself and ignores the roster's `state`.
- **A fresh heartbeat beats a failed hello.** Heartbeat age <= threshold is `online` even when hello fails (the store is
  the closer witness). A stale heartbeat plus an answering hello is `online` (the daemon is up; the store link is the
  broken part), because transferring from a running owner would split a live agent from its record.
- **A removed roster row (older than `stale_retention_ms`, default 300 s) is no evidence.** Absent row with no hello
  answer is `unknown`, not `offline`: an owner that never had a store configured is indistinguishable from a dead one.
  Declared in the Test scenarios so a refactor cannot turn this into `offline`.
- **Two daemons on one machine.** Matching on `daemon_key` as well as `gateway_id` keeps a live second daemon from
  making a dead owner look alive; hello cannot tell daemons apart, so hello is accepted only as a gateway-level
  witness (row 3 stays "live" for the gateway). Accepted: it errs toward refusing, which is the safe side.
- A hello that answers with another `gateway_id` than the registry pin is `error` for MPG-209 and contributes nothing here.

**Transfer path (`assign`).**
1. Parse and validate: `<n>` positive integer or `pr-<N>`; `--to` required; `--reason` 1..500 chars, no control
   characters (the `ticket estimate` rule); `--json`, `--force` optional.
2. Resolve `--to` against the registry and this gateway (names, labels, ids all resolve, KTD-6) to a `gateway_id` and
   label. An unknown or ambiguous target exits 64. A target that is not this gateway needs its registry entry's
   `gateway_id`; the new record's `daemon_key` is unknown to the sender, so the transfer record sets `daemon_key: null`
   and the target daemon fills it with its own key on first read (open question 2).
3. Read the record (uncached) and remember its `beforeOid`. `unknown` read: exit 75, nothing written.
4. Owner is already the target: print the record, exit 0, no write (idempotent retry after a lost reply).
5. Classify liveness. `online` or `unknown` and no `--force`: exit 64 with `owner is online; ask it to release` or
   `owner liveness unknown; treat as online`. These exact strings are the acceptance texts.
6. `Aiur.Ownership.GitHubRef.transfer/4` with the observed `beforeOid`, new owner, `reason: "transfer"` in the record, the
   free-text `--reason` stored in `note` (see Interfaces), `actor`, `epoch = previous + 1`. Results: `:won` continues;
   `:lost` exits 64 `ownership changed to <label> at epoch <n>; re-read with aiur ticket owner`; `:unknown` exits 75 with the
   safe retry command (same arguments), per KTD-12.
7. After `:won`, disable auto-merge on the old owner's open PR: `Aiur.Orchestrator.ReworkGate.open_pr/2` finds the PR
   (`{:ok, pr}`, `{:skip, :no_open_pr}`, `{:error, _}`), then `Aiur.GitHub.LandingWithdrawal.disable_auto_merge/2`
   (existing: `disablePullRequestAutoMerge` mutation, `landing_withdrawal.ex:59,120`). `:no_open_pr` is success. A failure
   here does not undo the transfer (the epoch already fences the old owner's pushes, MPG-105); it is reported as
   `auto_merge: "failed: <reason>"`, exit 75, with the retry `aiur ticket assign <n> --to <g>` safe because step 4 skips
   the write but still runs step 7. Order matters: transfer first, so a failed mutation never leaves auto-merge off on a ticket the old owner still holds.

**Actor and `--force`.** The daemon derives `actor`, never the caller: local CLI with no `--as` is
`{kind: "human", id: "cli:$USER"}`; a call arriving with a client token is `{kind: "executor", id: <token name>}`
(code-evidence line 88: remote arguments may not carry `who`, `actor`, `set_by`, `owner`). `--force` is accepted only by
the local path: the shell refuses it when `AIUR_REMOTE_INSTANCE` is set (`--gateway`/`--instance`) or `--as` is present
(exit 64 `--force is local and human only`), and the allowlist row for `assign` does not list a `force` option, so a
remote call carrying it fails option validation. A forced transfer records `reason: "transfer"` and `note` prefixed
`forced: `, so the audit shows it.

**Allowlist.** MPG-205 turns scopes into categories. New rows in `src/lib/aiur/control_call/allowlist.ex` (the
`@rows` list, in the `{{[:Aiur, :ListenModeCli], :run, 2}, ...}` style): `{{[:Aiur, :Ownership, :CLI], :owner, 1}}`
category `read` options `json: :boolean`; `{{[:Aiur, :Ownership, :CLI], :assign, 1}}` category `tickets` options `ticket`,
`to`, `reason`, `json`. MPG-205's research deliberately left `ticket_assign` to this ticket (its open question table).
If MPG-205 has not merged when MPG-106 starts, use the scope form (`:read`, `:write`) and let MPG-205 convert; both
depend-chains already list MPG-205 first, so assume merged.

**JSON shape** (`--json`, envelope like `aiur.agents` v1). Computed ages are rendered by the text view too (AGENTS.md
"Computed ages" rule):
```json
{"schema": "aiur.ticket-owner/v1", "ticket": "12", "repo": "owner/name", "observed_at": "2026-11-06T12:00:05Z",
 "freshness": "fresh", "state": "owned",
 "owner": {"gateway_id": "<26 base32>", "gateway_label": "PC", "daemon_key": "pc"},
 "epoch": 4, "previous_epoch": 3, "reason": "dispatch",
 "actor": {"kind": "daemon", "id": "pc"}, "at": "2026-11-06T11:58:00Z", "age_ms": 125000,
 "liveness": {"status": "online", "source": "heartbeat", "observed_at": "2026-11-06T12:00:01Z", "age_ms": 4000}}
```
`state` is `owned|released|unowned|unknown`; `owner`, `epoch`, `actor` are `null` unless `owned` (a released record keeps
`epoch`); `liveness` is `null` when there is no owner. `assign --json` returns the new record plus `previous_epoch`,
`auto_merge: "disabled|none|failed: <reason>"` and `forced: true|false`. A cause the code cannot name collapses to
`unknown` at the source (AGENTS.md "collapsed causes"): `liveness.status` and `source` are never defaulted to
`offline`/`heartbeat`.

**Alternatives rejected.**
- *Treat an owner with a stale heartbeat as offline without trying hello.* The two-source rule exists because the store
  link can fail while the daemon runs; the plan names both sources.
- *Add a new `/api/v1/ownership` endpoint.* The control-call path already carries auth, categories, request ids and audit.
- *Let `assign` write `owner.json` from the shell.* Compare-and-set and the `:unknown` classification live in
  `GitHubRef`; the shell would duplicate them.
- *`--gateway` to name the target.* It selects where the command runs (KTD-6); hence `--to`.

## Test scenarios
Dates are relative to an injected `now`. "Threshold" is 180 s.

| Scenario | Input | Expected |
|---|---|---|
| **[fails without]** Stale owner, transfer | PC owns #12 at epoch 3; roster row for PC aged 600 s; hello stub unreachable; `assign 12 --to nook --reason x` | writes epoch 4, `owner.gateway_label = Nook`, `actor.kind = "human"`; exit 0 |
| **[fails without]** Liveness unknown | Store call returns `{:error, _}`; hello unreachable; same command | exit 64, stderr `owner liveness unknown; treat as online`; no `transfer/4` call |
| **[fails without]** Live owner | Roster row aged 20 s | exit 64 `owner is online; ask it to release`; no write |
| **[fails without]** Auto-merge | After `:won`, `open_pr` returns PR 9 | `disable_auto_merge(9)` called once, after `transfer`; JSON `auto_merge: "disabled"` |
| **[fails without]** Forced remote | `aiur --gateway nook ticket assign 12 --to pc --reason x --force` | exit 64 `--force is local and human only`; no RPC; and a raw control call with `force: true` fails option validation |
| `--force` with `--as` | `aiur --as e1 ticket assign ... --force` | exit 64, same text |
| Local force over live owner | Roster row aged 20 s, `--force` | writes epoch+1; `note` starts `forced: `; exit 0 |
| Boundary | Row aged exactly 180 s, then 181 s (hello unreachable) | 180 s: `online`; 181 s: `offline` (the comparison is `>`) |
| Absent row is not offline | Store up, no row for owner, hello unreachable | `unknown`, exit 64 as above |
| Stale row, hello answers | Row aged 600 s, hello 200 with owner's id | `online`, source `hello`; exit 64 |
| Hello with another id | Hello answers a different `gateway_id` | contributes nothing; stale row -> `offline` |
| Two daemons, one machine | Row for the same `gateway_id` but other `instance_id` is fresh; owner's own row is 600 s old | `offline` (matches `daemon_key`) |
| Lost CAS | `transfer/4` stub returns `:lost` | exit 64 `ownership changed to`; no auto-merge call |
| Unknown CAS | stub returns `{:unknown, :timeout}` | exit 75, retry command printed; no auto-merge call |
| Idempotent retry | Owner is already the target | exit 0, no `transfer/4`, `open_pr` still checked |
| No open PR | `{:skip, :no_open_pr}` | exit 0, `auto_merge: "none"` |
| Mutation fails | `disable_auto_merge` returns `{:error, ...}` | exit 75, record transferred, `auto_merge: "failed: ..."` |
| Owner read | Record epoch 4, `at` 125 s before `now` | JSON `age_ms: 125000`, `freshness: "fresh"`; text prints `125s ago` (not just the timestamp) |
| Unknown render | `read/2` returns `unknown` | JSON `state: "unknown"`, `owner: null`, `epoch: null`; text has no `0` or `-`; replacing that branch with `unowned` must fail the test |
| Unowned / released | no ref; `state: released` | `state` `unowned` / `released`; `liveness: null` |
| Bad input | `assign abc`, no `--to`, empty `--reason`, 501-char reason, `--to nobody` | each exit 64 with a distinct message |
| Remote allow | Token with `read` only calls `assign` | refused by category; `owner` allowed |

## Risks
- **Hello cannot name a daemon** (two daemons, one machine). Errs toward refusing; detect via the two-daemon test.
- **Clock skew** between roster `heartbeat_at` (DB time) and the CLI host: use `age_ms` computed by the same code that builds the roster, not a local wall-clock subtraction. Fallback: `--force`.
- **MPG-001 not merged**: no `gateway_id` in heartbeats, so row 2 never matches and liveness falls to hello or `unknown` — safe, noisy. Detect: `owner` shows `unknown` for a healthy peer.
- **Auto-merge mutation needs PR scope**; the existing mutation path already runs under the GitHub guard.
- **Note field**: if MPG-102 ships without `note`, the free-text reason has nowhere to live.
