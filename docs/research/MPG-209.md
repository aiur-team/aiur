# MPG-209 — Show gateway status from the CLI: research

Research ticket MPG-209R (#7592). Inputs: `docs/plans/2026-11-06-multi-project-gateways.md` and `tickets-m2.md`,
`code-evidence.md`, `state-schemas.md` (all from PR #7579, not yet on `main`), plus the code read below. No code change.

## Outcome
`aiur gateway list` prints one row per registry entry: name, `registered`, connectivity (`online|offline|unknown|error`),
workload (`idle|active|saturated|paused|unknown`), last-seen age, gateway id, projects, running agents, owned tickets,
Executor presence and grants both ways where known. `aiur gateway status <g>` prints one gateway in detail. An offline
gateway shows cached values with their age and workload `unknown`; it is never `idle` and never `0`.

## Design
**Source of truth.** Each online gateway answers `GET /api/v1/gateway/summary` (state-schemas S6, built by MPG-202/207).
The receiver derives workload once so the CLI, dashboard (MPG-603) and JSON agree. The CLI calls the same function only
as a fallback when the summary lacks the field (older peer).

**Workload derivation** (pure function `Aiur.Gateway.Workload.derive/1`, over S6 `capacity`, `projects`, gateway pause):

| Order | Condition | Result |
|---|---|---|
| 1 | connectivity is not `online`, or `capacity` missing | `unknown` |
| 2 | gateway-level pause set, or `projects` non-empty and every project `paused` | `paused` |
| 3 | `capacity.max > 0` and `capacity.running >= capacity.max` | `saturated` |
| 4 | `capacity.running > 0` | `active` |
| 5 | otherwise | `idle` |

Reasons: pause outranks load because a paused gateway with leftover running agents is draining and the operator needs to
see "not taking work". Saturated outranks active because it is the actionable state (plan A4: lower-priority work uses
idle slots, so saturation means no slack). `idle` means "reachable, unpaused, zero running" and says nothing about ready
work. `max = 0` is never saturated. Rejected: a percentage threshold (a made-up number; `running >= max` is the cap the
orchestrator already enforces in `src/lib/aiur/orchestrator/slots.ex`); an `offline` workload value (connectivity
already carries it).

**Connectivity.** `online`: hello and summary both answered. `offline`: transport failure or timeout. `error`: answered
but refused or invalid (401/403, bad JSON, gateway id differs from the registry pin). `unknown`: never reached (no cache).

**Cache.** After each successful summary, write `~/.aiur/remote-state/<name>.json` (temp file + rename, mode 0600) with
the S6 body plus `observed_at`. On failure read it: `age_ms = now - observed_at`; `freshness` is `fresh` (answered now),
`stale` (from cache) or `none` (never reached). Row text: `agents: 3 (12m ago)`. Totals sum only known numbers; any
`none` entry renders the total as `12 + unknown`.

**Fan-out.** Reuse `packaging/npm/aiur-cli/libexec/engine/remote_all.sh`: it already runs read commands in parallel with
per-instance result files (`run_remote_all_instance`) and forces `max_scope=read`. Add the summary read to its read-command
allow-list (the `case` near line 37) rather than a new fan-out. Per-entry timeout default 5 s so one dead peer cannot
stall the table.

**JSON.** One object per row: `{gateway, connectivity, workload, last_seen_at, age_ms, freshness}` (the acceptance
shape) plus `last_workload`, the cached value when offline. The text table must render the age too (AGENTS.md "Computed
ages" rule).

## Test scenarios
| Scenario | Input | Expected |
|---|---|---|
| Offline uses cache | stubs: A answers, B times out; B cache has 3 agents observed 12 min ago | B row `offline`, `agents: 3 (12m ago)`, workload `unknown`, freshness `stale` |
| Never reached | no cache, unreachable | `unknown`, freshness `none`; totals `12 + unknown` |
| Idle | online, running 0, max 4, unpaused | `idle` |
| Active | running 2, max 4 | `active` |
| Saturated | running 4, max 4 | `saturated` |
| Max zero | running 0, max 0 | `idle` |
| Paused beats saturated | running 4, max 4, gateway pause | `paused` |
| All projects paused | running 0, every project paused | `paused` |
| Error | peer returns 403 | connectivity `error`, workload `unknown` |
| JSON shape | `--json` | each row has the six keys plus `last_workload` |
| Corrupt cache | truncated file | treated as never reached, no crash |
| Unknown-branch mutation | replace the offline `unknown` with `idle` | the offline test fails |

## Data and assets
Cache path `~/.aiur/remote-state/<name>.json`. Tests point the state root at a temp dir (AGENTS.md: never read real
`~/.aiur`). Known gap: heartbeat `agent_count`/`agent_capacity`
(`src/lib/aiur/orchestrator/instance_heartbeat_metadata.ex`) is display-only and carries no pause or project data, so S6
must be built from orchestrator state, not the roster.

## Evidence to produce
`mix test` on the new gateway test files, the launcher test, the CLI-reference and config-docs checks, and the AGENTS.md
revert check for each new test. A live two-gateway capture belongs to MPG-210.

## Risks
- S6 field names may move in MPG-202/207. Detect: tests use the S6 literal from `state-schemas.md`.
- One slow peer stalls output. Fallback: per-entry timeout and parallel fan-out.
- Stale cache read as live. Fallback: always print age; JSON carries `freshness`.

## Open questions
| Question | Recommended default | What changes if answered differently |
|---|---|---|
| Paused with running agents: `paused` or `draining`? | `paused` | A fifth state touches the enum in the plan and MPG-603 |
| Offline: show last-known workload as the workload? | No: `unknown`, last value in `last_workload` | Plan item 16 forbids offline reading as idle; a cached `active` risks the same lie |
| Per-entry timeout | 5 s, `--timeout` flag | Longer slows `list` when a peer is down |
| `idle` when ready work exists but gateway is unpaused? | Yes; ready count is a separate column | A `starved` state needs a ready-vs-slots rule |
| Derive in the CLI when the peer lacks `workload`? | Yes, same function | Older peers would show `unknown` |
