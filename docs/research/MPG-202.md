# MPG-202 — Add the --gateway selector to every remote-capable command: research

Plan: `docs/plans/2026-11-06-multi-project-gateways.md` (PR #7579; KTD-6, decision 30). Contract:
`docs/plans/2026-11-06-multi-project-gateways/tickets-m2.md` § MPG-202. Research ticket: MPG-202R (#7585).
Focus of this doc: **ambiguity rules when a label matches two registry entries.**

Paths below are relative to `packaging/npm/aiur-cli/` (`libexec/`, `test/`) unless they start with `scripts/`,
`website/` or `docs/`. Line numbers are from `main` at 26ec6e00d; re-check them after MPG-201 merges.

## Outcome

`aiur --gateway <name|label|id|all|local> <cmd>` does what `aiur --instance <name|all> <cmd>` does today, after
resolving the selector against `~/.aiur/remote-instances.yaml`. `--instance` is unchanged. Giving both exits 64.
A selector that matches more than one registry entry exits 64, lists every match, and makes no HTTP call.
`aiurdev` accepts the same flag. No server change.

## Design

**Where it hooks.** `aiur_engine_main` (`libexec/aiur-engine.sh:208-234`) already treats a first-argument
`--instance` as the only way to select a remote target, after `unset AIUR_REMOTE_INSTANCE`. `--gateway` is parsed in
the same `case`, resolved to a registry **name** (or `all`, or "local"), and then everything downstream runs on
`AIUR_REMOTE_INSTANCE=<name>` exactly as today: `validate_remote_instance_name`, `ensure_remote_all_read_command`,
`ensure_remote_command_allowed`, `load_remote_instance`, `run_remote_rpc_with_timeout`, `run_remote_all_*`, the
executor-wait cursor files (keyed by name, so renaming a label never orphans a cursor). No new transport.

**Selector grammar.** `--gateway X` and `--gateway=X`; `X` is non-empty. Empty or missing: `aiur: --gateway requires a
name`, exit 64. Selector is not checked against the `^[A-Za-z0-9._-]+$` name regex (a label may contain spaces);
the resolved *name* is, as today.

**Resolution order (decided by the ticket, defaulted here).**

1. `local` → run locally. Clear `AIUR_REMOTE_INSTANCE`, shift, continue as if no selector. The registry is not read,
   so it works with no registry file. No HTTP.
2. `all` → `AIUR_REMOTE_INSTANCE=all` (read-only fan-out, same gate as `--instance all`).
3. Otherwise collect **every registry entry** that matches by any of:
   - `name` equals `X` (exact, case-sensitive; names are case-sensitive keys today),
   - `label` equals `X` case-insensitively (ASCII only, `LC_ALL=C`),
   - `gateway_id` equals `X` case-insensitively (full id only; no prefix matching).
   One entry matching by two fields counts once.
4. Exactly one entry → `AIUR_REMOTE_INSTANCE=<its name>`. Zero → `aiur: unknown gateway 'X' in
   ~/.aiur/remote-instances.yaml`, exit 64. Two or more → ambiguity error, exit 64.

`local` and `all` are keywords and win over any registry entry or label spelled the same way. `all` is already a
rejected entry name; `local` is **not** (today a registry may name an entry `local`). Do not make that a parse error
(it would turn a working registry into exit 65). A `local` entry stays reachable with `--instance local`; `--gateway
local` always means this machine. Say so in the docs.

**Ambiguity output (exact).** Matches in registry file order, one per line, then the remedy. stderr, exit 64:

```text
aiur: gateway 'nook' is ambiguous in ~/.aiur/remote-instances.yaml; it matches:
  nook  (name)
  lab2  (label "Nook")
use the registry name with --instance, or the gateway id
```

`(how)` is `name`, `label "<label>"` or `id <id>` (the field that matched; if one entry matched twice, join with
`, `). Why exit 64 and not "first wins": every command here may be a write (`pause`, `set`, `message`). A silent
pick sends it to the wrong machine; a refusal costs one retry. Why name does not outrank label: adding a peer labelled
`PC` must not silently retarget `--gateway pc` scripts either way, so both fail closed. `--instance pc` stays an exact
name lookup and is the escape hatch, which is why `--instance` must not change.

**Two selectors.** `--gateway` and `--instance` together, in either order and either form (`--gateway=x`,
`--instance=y`), exit 64 with `aiur: use one of --gateway or --instance`. The check runs right after the first
selector is consumed: if `$1` is then `--gateway`, `--gateway=*`, `--instance` or `--instance=*`, fail. Two of the
same flag fail with the same message. Today the second flag would fall through to "`--instance` is unavailable with
--instance", which is misleading.

**Local-only commands.** The existing gate stays. For `--gateway`, `stop` and `restart` print
`aiur: stop is local to the gateway's host; run it there` (command name substituted), exit 64. Mechanism: export
`AIUR_REMOTE_SELECTOR_FLAG` (`--gateway` or `--instance`; unset with `AIUR_REMOTE_INSTANCE` at the top of
`aiur_engine_main`) and derive the noun (`gateway`/`instance`) and flag in the messages of `ensure_remote_command_allowed`,
`validate_remote_instance_name` and `ensure_remote_all_read_command`; the default stays `--instance`/`instance`, so
every existing assertion on the old text stays green. Only the `stop|restart` message gains the `; run it there`
suffix, and only under `--gateway` (existing tests assert the old `--instance` text).

**Inherited env.** Unchanged: `unset AIUR_REMOTE_INSTANCE` first, plus `unset AIUR_REMOTE_SELECTOR_FLAG`. Neither
variable is an input.

**Registry read.** `resolve_gateway` runs the registry awk in a new mode that prints, for every entry matching the
selector, `name<TAB>how`. The selector is passed in the **environment** (`AIUR_GATEWAY_SELECTOR`, read with
`ENVIRON[...]` in awk), never `awk -v`, because `-v` interprets backslash escapes and a label may contain any
character. It reuses the existing validation, so a malformed registry still exits 65 with its line. MPG-201 adds
`label` and `gateway_id` to `finish_instance` (variables `current_label`, `current_gateway_id`); this ticket reads
those. If MPG-201 named them differently, follow its names.

**Module placement.** `libexec/engine/remote.sh` is 497 lines; the file-size gate fails over 500 and the rule is to
add new code in a new small module. Put `resolve_gateway` and `parse_gateway_selector` in a new
`libexec/engine/gateway.sh` and add `gateway` to `AIUR_ENGINE_MODULES` (`libexec/aiur-engine.sh:67`, after
`remote_all`). The ticket names `engine/remote.sh (resolve_gateway)`; this is the same function in a new file. The
awk mode itself must live in `remote.sh`'s parser (one awk program) and adds roughly 8 lines there (a sibling of the `if (target == "*")` branch), so with
MPG-201's additions `remote.sh` will pass 500. MPG-201 merges first and extracts the awk
program to `libexec/engine/registry.awk` with no behavior change (open question 4); this ticket adds its mode there.

**Alternatives rejected.** (a) Rewriting `--gateway` to `--instance` textually before the existing code: loses the
two-selector check and the noun in messages. (b) Resolving in the Elixir daemon: the registry is a client-side file;
the server never sees labels. (c) Prefix matching on ids: a prefix that is unique today turns ambiguous after the next
enrolment.

## Prior art

None needed. The question is local: how this registry's names, labels and ids collide. The plan's prior-art reports in
`docs/research/multi-gateway/` cover enrolment and permissions, not CLI selector resolution. (Rule of thumb from
existing tools — `kubectl --context`, `ssh` host aliases — is exact-name lookup with no fuzzy match; not cited as
evidence for anything here.)

## Interfaces

  `gateway_id` check happens after resolution and is independent of it.

- Provides to docs: the selector grammar and ambiguity message above.

```yaml

  nook:   {url: S1, token_env: AIUR_TOKEN_T, gateway_id: aaaaaaaaaaaaaaaaaaaaaaaaaa, label: Nook}
  pc:     {url: S2, token_env: AIUR_TOKEN_T, gateway_id: bbbbbbbbbbbbbbbbbbbbbbbbbb, label: PC}
  lab:    {url: S3, token_env: AIUR_TOKEN_T, gateway_id: cccccccccccccccccccccccccc, label: nook}
```

## Risks

- **`aiur-engine.sh` is exactly 500 lines.** Any growth trips the size gate. Mitigated by putting the case bodies in
  `gateway.sh`; verify with `wc -l` before pushing.
- **`remote.sh` is 497 lines** and MPG-201 also edits its awk. Order of merge matters; see open question 4.
- **MPG-201 field names.** If `label`/`gateway_id` are stored differently, unit 1 changes; detect by reading the
  merged MPG-201 diff before starting.
- **Ambiguity from a harmless registry edit.** A script using `--gateway pc` breaks when someone labels another entry
  `PC`. It fails closed with both entries listed; the fix is `--instance pc`. Accepted.
- **Case folding is ASCII-only.** A label `Zürich` vs `ZÜRICH` is two labels. Documented, not fixed.

## Open questions

| Question | Recommended default | What changes if answered differently |
|---|---|---|
| 1. Should a name match outrank label/id matches (kubectl-style) instead of failing on collision? | No: exit 64 and list both (the ticket's default). | Name-first removes scenario 6/7 and makes `--gateway nook` silently pick the name entry; ids remain safe. Cheaper for users, riskier for writes. |
| 2. Does the unknown-gateway error list the known names? | No; print the single line. | Listing helps typos but adds registry contents to stderr/logs; adds one test and a sort order. |
| 3. Reject an entry named `local` at parse time? | No; keyword wins in `--gateway`, `--instance local` still works. | Rejecting gives a clean namespace but a working registry starts failing with exit 65 on upgrade. |
| 4. Where does the awk live once both MPG-201 and MPG-202 grow it past 500 lines? | MPG-201 (merges first) extracts the awk program to `libexec/engine/registry.awk` with no behavior change; MPG-202 extends it. | If left inline the file-size gate blocks the second PR. |
| 5. Do duplicate labels get warned about when the registry is read (e.g. by `aiur gateway status`, MPG-209)? | No; resolve-time failure only, MPG-209 may show a `label shared with <name>` note. | A parse-time rejection would make registries invalid for commands that never use labels. |
| 6. Should `--gateway` be accepted after the command (`aiur status --gateway nook`)? | No: first argument only, same as `--instance`. | Position-independent parsing collides with per-command flags and the executor `--as` handling. |
