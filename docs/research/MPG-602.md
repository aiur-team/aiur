# MPG-602 — Serve a gateway summary API the dashboard can read cross-origin: research

Plan: `docs/plans/2026-11-06-multi-project-gateways.md` (PR #7579). Contract: MPG-602 in
`docs/plans/2026-11-06-multi-project-gateways/tickets-m4-m7.md`. Schema S6 in `.../state-schemas.md`. Auth and CORS
decisions D2-D6 and evidence items E1, E2, E5 come from `docs/research/MPG-601.md`. Code read at `origin/main`
153173280. No external deep-research run: the one external question (E1) is answered by the Public Suffix List file
itself, and E2 and E5 cannot be verified from a workspace (see Prior art).

## Outcome

`GET /api/v1/gateway/summary` returns S6 for this gateway. A browser page served from another gateway on the same
tailnet can read it with `fetch(url, {credentials: "include"})` when its origin is listed in
`server.dashboard_origins` or in a registry peer `url`. Three results are distinct to that page:

- 200 with the payload (signed in, origin listed).
- 401 `{"error":"signed_out"}` **with CORS headers**, so the page can show `error: signed out` and not `unreachable`.
- No CORS headers at all (origin not listed). The browser sees a network error, which MPG-601 D6 renders as `unknown`.

Google sign-in accepts `return_to=<listed origin>`, so one Google login can chain across gateways.

## Design

### Decisions

| # | Decision | Why |
|---|---|---|
| R1 | The route sits in its own pipeline `:gateway_summary` = `[DashboardCors, :fetch_session, GatewaySummaryAuth]`, `GET` only | CORS headers must exist on 401 and 403 answers |
| R2 | Auth accepts (a) a valid dashboard session cookie, or (b) `Authorization: Bearer <client token>` with any scope. Nothing else: no Basic, no Tailscale identity headers (MPG-601 D4) | Session is the browser path (D3). A bearer token is the CLI and peer path (S2 `credentials`) |
| R3 | Unauthenticated: `401 {"error":"signed_out"}`, no `WWW-Authenticate`, `Cache-Control: no-store`, CORS headers present if the origin is listed. Bearer present but invalid: `401 {"error":"unauthorized"}`. Token insufficient: not applicable (read scope is enough) | The page tells "signed out" from "unreachable" (D6) |
| R4 | CORS answers an exact-match origin only. Listed origin: `Access-Control-Allow-Origin: <origin>`, `Access-Control-Allow-Credentials: true`, `Vary: Origin`. Unlisted or absent `Origin`: no CORS headers, and `Vary: Origin` is still set | Never `*` (credentials). The request is not blocked server-side: a non-browser caller with a token still works |
| R5 | `OPTIONS /api/v1/gateway/summary` answers `204` for a listed origin with `Access-Control-Allow-Methods: GET`, `Access-Control-Allow-Headers: content-type, x-aiur-request-id, authorization`, `Access-Control-Max-Age: 600`. Unlisted origin: `204` with no CORS headers (browser fails the preflight) | Contract acceptance. `GET` with a simple header set needs no preflight, but a bearer `Authorization` header triggers one |
| R6 | The listed set = `server.dashboard_origins` ∪ origins of registry peer `url` values (S2) ∪ this gateway's own `server.public_url` origin. Computed per request from two cheap sources (config in `EndpointConfig`, registry via `Aiur.Gateway.Registry` once MPG-201 lands; until then the loader that today reads `~/.aiur/remote-instances.yaml`). Each entry is normalised to `scheme://host[:port]`, lowercase, default port elided, no path, `http`/`https` only. `null`, `*` and `file://` never match | D5. Reusing the same normaliser for `return_to` (below) keeps one definition of "listed" |
| R7 | Write routes stay same-origin. The existing `:api_write` pipeline is not touched, no CORS plug is added to any other route | Contract acceptance 3 |
| R8 | A refused credentialed origin is logged once per origin per boot at `Logger.info("gateway summary: origin not listed: ...")` (no cookie or header values) | MPG-601 risk: operator can see why a peer reads `unknown` |
| R9 | The payload is built from injected readers and is always fast: each reader has a 1 s budget, a failure yields `null` for its fields and never fails the request | Summary must answer when the orchestrator is busy. A timeout is `null`, not `0` |

### Payload (S6, with the exact null rules)

```json
{
  "gateway_id": "01J...26chars",
  "gateway_label": "PC",
  "observed_at": "2026-11-06T16:00:00Z",
  "age_ms": 0,
  "connectivity": "online",
  "workload": "active",
  "capacity": {"max": 8, "running": 5},
  "projects": [
    {"repo": "aiur-team/aiur", "observed_at": "2026-11-06T16:00:00Z", "age_ms": 0,
     "focus_features": null, "running": 5, "ready": null, "owned_tickets": 5,
     "paused": null, "pending_decisions": null}
  ],
  "executor_present": true
}
```

- `observed_at` (ISO 8601 UTC, second precision) is the time the gateway took its own snapshot; `age_ms` is
  `now - observed_at` computed at serialisation time. For the gateway block it is the orchestrator status read. For each
  project it is the time of that project's reader result; a project whose reader failed carries the last cached value
  with its older `observed_at` (see Cache) or `observed_at: null, age_ms: null`.
- `connectivity` is what the **gateway** knows of itself: always `"online"`. The browser overrides it with its own view
  (MPG-601 D6); the field exists so the CLI and tests have the S6 shape. It is never `"offline"`.
- `workload` per MPG-601 "States": `paused` if the gateway is paused, else `saturated` if `running >= max`, else
  `active` if `running > 0`, else `idle`. If `capacity.max` or `capacity.running` is `null`, `workload` is `null`
  (never `idle`).
- `capacity.max` is `Aiur.Orchestrator.max_concurrent_agents().effective`; `capacity.running` is the count of `:running`
  and `:paused` status rows (the same rule as `InstanceHeartbeatMetadata.active_agent?/1`).
- `gateway_id` and `gateway_label` come from `Aiur.Gateway.Identity.current/0` (MPG-001). When identity is
  unavailable: `gateway_id: null, gateway_label: null, gateway_identity: "unavailable"` (MPG-001's rule). The client must
  refuse a payload whose `gateway_id` does not match the pinned id (MPG-601); a `null` id is `error`, not `online`.
- `projects[].running` and `owned_tickets` reuse the MPG-407 heartbeat reader (`projects/2` in
  `instance_heartbeat_metadata.ex`), exposed as a public function so there is one grouping implementation.
- `ready`, `focus_features`, `paused`, `pending_decisions`: injected readers, `null` until their producers land
  (`ready` ← MPG-401 demands, `paused` ← MPG-308, `focus_features` ← Build Order focus feature ids,
  `pending_decisions` ← the Decision store pending count). The summary ships with these `null` and the home screen
  renders `unknown` for them. This is a stated limit, not a stub: the field is part of S6 and a later ticket fills it
  without a schema change.
- Unknown keys are never added. A test walks the keys and rejects unlisted ones (the MPG-001 pattern).

### Cache

An `Agent`-less, ETS-free design: `Aiur.Gateway.Summary.build/1` is a pure function of injected readers; the controller
calls it per request. One extra rule: the controller keeps the previous successful project rows in `:persistent_term`
keyed `{Aiur.Gateway.Summary, :last_projects}` so a failed reader yields the last value with its **old** `observed_at`
and a growing `age_ms` (never a fresh `observed_at` on stale data). Default: no cache beyond that.

### Auth plug

`AiurWeb.GatewaySummaryAuth` (new, `src/lib/aiur_web/gateway_summary_auth.ex`):

1. `Authorization` bearer present → `Aiur.ClientTokens.authenticate/1`; `{:ok, name, scope}` → assign `:token_name`;
   `:error` → 401 `unauthorized`. More than one `Authorization` header → 401 `ambiguous authorization header` (matches
   `ClientTokenAuth`).
2. Otherwise `FinancialDataAccess.context_from_session(get_session(conn))` is `{:ok, _}` → pass.
3. Otherwise 401 `signed_out`. It does **not** call `FinancialDataAccess.authenticate_request/2` (that sends Basic
   challenges and stages session writes).

### Google `return_to` (in this ticket, per MPG-601)

- `GET /auth/google?return_to=<url>`: normalise `return_to` to an origin with the R6 function and require it in the
  listed set. If it fails, ignore it (sign in as today), do not error. If it passes, store `google_return_to` (the origin
  only, never a path) in the session next to `google_session_params`.
- `google_config/0` drops `prompt: "select_account"` and adds `login_hint` when `return_to` is stored **and** a
  `login_hint` query param is present (the page passes the email shown in its own session). Without the hint, keep the
  chooser. `login_hint` is passed through `URI.encode_www_form`; length-capped at 254.
- `complete_google_sign_in/2`: after a successful sign-in, if `google_return_to` is in the session, delete it and
  `redirect(external: origin <> "/")`, skipping the passkey hop. The session cookie is set on **this** gateway before
  the redirect, which is what makes the peer's later fetch authenticated.
- The redirect target is rebuilt from the stored origin (`scheme://host[:port]` + `/`), never from the raw parameter, so
  it cannot carry a path, query or userinfo. That is the open-redirect defence.
- The allowed-email check (`allowed_google_user?`) is unchanged: a chained sign-in does not widen who may sign in.

### Config

`server.dashboard_origins`: array of strings, default `[]`. Validation in `Aiur.Config.Schema.Server.changeset/2`:
each entry must parse to scheme `https` or `http`, a host, no path other than empty or `/`, no userinfo, query or
fragment; `*` rejected; trailing `/` stripped; duplicates dropped. A bad entry fails config load with
`server.dashboard_origins: must contain http(s) origins`. `http://` is allowed for loopback hosts only (dev); a
non-loopback `http://` origin is rejected (cookies are `Secure`).

`http_server.ex` `configure_endpoint/5` adds `dashboard_origins: normalised_list` to the endpoint opts. The startup check
(Q4) logs a warning when Google sign-in is configured and `server.public_url`'s origin is not in the effective list.

## Risks

- **E2 fails in a browser.** Every peer reads `error: signed out`. Detect with the post-deploy check; fallback is Kevin's
  decision on MPG-601 Q6 (proxy through the page's gateway).
- **`*.c.ts.net` hosts** are not same-site with each other (PSL). Document that gateways must use ordinary
  `host.tailnet.ts.net` names.
- **Cookie `Secure` flag.** `AiurWeb.Session` sets it when `conn.scheme == :https` or config says so; behind
  `tailscale serve` the daemon sees plain HTTP unless `public_url` is `https` (then `secure: true`). A cookie without
  `Secure` is still sent over HTTPS, so it works; the risk is only cosmetic. The startup warning already requires an
  `https` `public_url` for Google.
- **Origin-list drift.** A gateway whose peer URL changes silently drops out of CORS. R8's log line is the signal.
- **Heartbeat coupling.** If MPG-407 renames `projects/2`, unit 5 breaks at compile time, which is the intended alarm.
- **Reader latency.** Mitigated by R9 (1 s per reader, `null` on failure).
- **Open redirect.** Mitigated by rebuilding the redirect from a stored, normalised, listed origin (see tests).
