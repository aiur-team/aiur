# `agent-backends-oc-01`: bridge authorization gap

Snapshot: `3339b887196d5e9aefb273117a14bf33391ee41f`.

The reproduction claim holds. `Aiur.Opencode.Bridge` has no outer authorization plug and calls `ChatCompletions.handle/2` directly for `POST /v1/chat/completions` (`bridge.ex:5-19`). The ordinary text branch calls `Caller.authorize/1` through `OperatorDispatch.dispatch_user_text/4`, but the turn-marker branch dispatches coalesced user text through `OperatorDispatch.send_operator/3` and then opens `TurnStream.stream/3` without calling `Caller.authorize/1` (`chat_completions.ex:61-77,138-158`). The replay and nudge branches also lack a route-level check. Existing `chat_completions_test.exs:31-68` calls `ChatCompletions.handle/2` with no authorization header and asserts a 200 response, including the late-close content `boom`; this is a positive control for the unauthenticated marker path. The `Caller` unit tests prove only that `Caller.authorize/1` rejects a missing header when that function is invoked.

The default bridge host is loopback (`opencode/config.ex:11,29-38`), limiting default remote reachability but not authenticating other local processes. `opencode.bridge_host` is operator configurable, so a nonloopback bind widens exposure. The missing guard can expose transcript data and route coalesced operator text to an agent; P0 is plausible pending an independent severity check of reachable deployment configurations and agent authority. This is a source/test chain, not a live exploit against a running user instance. Do not count it as either required independent skeptic verdict.

Post-snapshot consequence: the native Muse branch inherited this shared bridge gap. A focused real Plug regression produced 200 for unauthenticated turn and replay/nudge requests before the repair; the branch now gates all parsed issue requests through `Caller.authorize/1`, and the focused bridge/stream suite passes. This implementation action does not substitute for the frozen research's independent severity verdict or a packaged-release acceptance check.
