# Merged-main refactor validation checklist

Run after the discussed release PRs land, from a clean detached worktree at the exact merged `origin/main` SHA. Record that SHA, the release version, and command outputs beside any finding disposition. The frozen evidence and v3 candidate are comparison inputs; neither substitutes for this step.

1. **Source delta.** Compare all 986 canonical findings' cited paths and full cited flows with merged main. Start with the 294 v3 path-affected findings, including the four newly affected by PRs #2845/#2846, then trace indirect callers and absent-path replacements. Retain all 1,033 source-ID mappings. For each P0/P1 finding, mark current reachability, exact behavior contract, test, and observed or unknown runtime incidence separately.
2. **Two P0 repairs.** Verify merged `CommandRunner` does not pass daemon `GITHUB_TOKEN` or `GH_TOKEN` through bubblewrap `--setenv`, while governed `gh` reads its token file; run the focused test and its clean-worktree production-hunk mutation check. Verify `aiur stop` selects only its instance's pidfile for current and legacy records; run the signal-free sibling regression and mutation check. Keep recycled-PID identity risk #2844 open until separately repaired.
3. **P2/P3 dispositions.** Run `tooling/audit_p2p3_triage.py` and `tooling/audit_p2p3_reconciled.py` in the pinned research checkout. Revisit all 244 provisional fixes and 645 deferrals against merged main, starting with the 17 overlay IDs and the [b4bc cited-path exposure](p2p3-b4bc-path-impact.md), then tracing changed callers and replacements for unchanged citations. Attach a behavior test or an executable missing-evidence gate before a ticket becomes worker-ready; do not infer incidence from path overlap or source support.
4. **Universal file census.** Recount every tracked UTF-8 text path using physical lines, including docs, tests, skills, vendor and generated text; classify binary and symlinks. Reconcile all 359 frozen owner-map rows with current paths and counts, assign an owner, action and caller/release check to each surviving oversized path, and enumerate any new path above 500. Treat the four cache-dashboard deletions as release changes, not refactor savings.
5. **Contract gates.** Reproduce degraded CODEOWNERS trust, DecisionStore journal/projection failure and replay, and the first in-process GitHub access seam with failure-path tests on current source. Keep the plan `requirements-only` until the responsible owners resolve those contracts and the owner map is reviewable.
6. **Measured progress.** Preserve the historical gap-attribution limit. For new progress and LOC claims, state the observed baseline, counted reachable population, before/after units and actual deleted versus moved lines. Test user-visible behavior through the real foreground Aiur CLI, multiple agents, TUI chat panes and rendered output under the repository manual-testing rule.

Before publishing a refreshed research artifact, repeat contextual private-source review and `tooling/privacy_check.py`. Promote only the short index, requirements and plan to main after their links and merged-main statements have been revalidated; retain raw evidence on a public pinned research ref outside the universal 500-line gate.
