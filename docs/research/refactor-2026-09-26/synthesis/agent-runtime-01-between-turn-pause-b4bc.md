# `agent-runtime-01`: between-turn pause containment at `main@b4bc11f`

This is a static trace of `b4bc11ffcb6abf693bb3c8570aca3e12d82cb24f`, not an observed production incident or a runtime test. It narrows the earlier queue-drain finding to two between-turn receives. The queued-turn `{:paused, payload}` branch already calls `PauseContainment.confirm/1` (`src/lib/aiur/agent_runner/queue_drain.ex:716-718`), as does the primary turn loop (`turn_loop.ex:172-174`). The two registered-handle tests at `src/test/aiur/agent_runner/queue_drain_test.exs:796-854` cover the queued-turn branch only.

## Observable mismatch and consequence

The operator's correlated pause request is sent to the worker before `PauseResume.accept_admitted_control_request/4` calls `arm_pause_containment/2` (`src/lib/aiur/orchestrator/pause_resume.ex:1791-1797,1810-1823`; `operator_messages.ex:1131-1141`). When the worker is between turns, either `QueueDrain.drain_operator_messages/6` or `wait_for_operator_message/6` receives `{:pause_agent, request_id, generation}`, sends a correlated `:paused` control-state report, and waits (`queue_drain.ex:40-57,130-146`). Neither branch confirms the session's containment handle. The Orchestrator accepts the matching report into the control lifecycle and running status without confirming that handle (`orchestrator.ex:168-170`; `pause_resume.ex:960-978,1005-1039,1061-1106`). Thus the user-visible/control-lifecycle pause can be applied while the registered containment entry is still `:armed`.

For a **registered, armed** Codex or Muse process group, `PauseContainment` schedules a five-second deadline on arm; only a generation-matched confirm changes `:armed` to `:paused` and cancels that deadline (`pause_containment.ex:11,182-192,361-369`). An entry still `:armed` at the deadline starts a group reap and emits `fallback_started` (`pause_containment.ex:245-253,288-309`). This is a concrete state-transition and event contract: a worker that acknowledged pause between turns can still take the fallback path. Actual timer execution, group termination, frequency, and user impact have **not** been reproduced here.

A different case is **no registered handle**. Codex and Muse registration can return `nil` (`src/lib/aiur/codex/session_lifecycle.ex:36-49`; `src/lib/aiur/muse/session.ex:147-157`); `arm_pause_containment/2` discards `:not_registered` or `:ignored` (`pause_resume.ex:1810-1823`). With no armed entry, this specific five-second fallback cannot follow. The caller currently does not expose that absence as a distinct pause outcome; investigate it separately from the armed-but-unconfirmed path.

## Minimal regression contract

1. Register a containment handle for a unique issue identifier, arm it, and pass that exact handle in `app_session`. Exercise **each** between-turn receive separately: send `{:pause_agent, request_id, generation}` before entering `drain_operator_messages/6`, and send it while already blocked in `wait_for_operator_message/6`. Assert the correlated `{:worker_control_state, issue.id, :paused, payload}` report and that the same generation's entry becomes `mode: :paused` **before any resume**. On `b4bc11f`, the report arrives but the entry remains `:armed`; these assertions should fail. Existing `queue_drain_test.exs:277-319` checks pause/resume delivery without a handle, so it cannot catch this.
2. Check the send/arm/ack order at the Orchestrator boundary. Because the worker message is sent before arm, a worker-side confirm alone can run while the entry is still `:active`; `PauseContainment.confirm/1` silently leaves that mode unchanged (`pause_containment.ex:182-192`). The Orchestrator cannot process the worker's acknowledgement until its current control call finishes, so a generation-fenced confirmation upon **accepted** `:paused` evidence is a candidate seam. Test acknowledgement produced before arm completes and after it completes. Confirm the handle captured by the accepted arm, rather than looking up a current identifier that may now belong to a replacement worker. A stale request or old handle must never confirm the successor generation (`pause_resume.ex:1061-1120`; `pause_containment.ex:182-192`).
3. With a controlled containment server/reaper, establish that a confirmed between-turn pause does not emit `fallback_started` or invoke the reaper after the grace deadline, while an unconfirmed armed entry still does. Preserve the independent fallback behavior for genuinely uncontained processes (`src/test/aiur/pause_containment_test.exs:22-52`).

The first contract is the smallest failing regression. The second is needed before choosing a production fix, since a worker-only confirm can lose the send-before-arm race. No Mix or live TUI verification was possible in this sandbox; this note records source reachability and the proposed test, not passing tests.
