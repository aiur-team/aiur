# Preparatory finding delta: frozen main to release candidate

The companion [per-finding ledger](release-candidate-finding-delta.jsonl) covers **all 986 canonical findings** by exact ID. Each row records its source IDs, cited-path count, every cited location whose path changed or disappeared, candidate path presence, and whether its old line range intersects a diff hunk. The comparison is from frozen public main `3339b887196d5e9aefb273117a14bf33391ee41f` to clean pre-release integration candidate `7bce08f36aede1f9747d24bb3a5c08145abd081e`, which combines nine code PRs and excludes the version PR. This is a static Git/source audit, not a run, a runtime-incidence measurement, or final merged-main validation.

| Candidate fix visible, validation pending | 1 | The named P0 unauthenticated agent-dispatch path is statically blocked, with a narrower auth boundary than the original recommendation. |

**Affected set:** 290 findings, including two P0, 31 P1, 214 P2 and 43 P3. Their 640 affected citations touch 97 changed paths: 80 remain at the same path and 17 are deleted. For 535 citations the old range falls outside candidate diff hunks (possibly shifted), 51 ranges intersect changed hunks, 52 cite deleted files, and two symbolic references have no parseable line range. The ledger names all affected IDs and paths; the summary deliberately does not duplicate its 290-row index. A candidate source file remaining at the same path is not proof that its behavior is unchanged.

## Direct source outcomes

- **P0 `agent-backends-oc-01`: named bypass blocked statically, full contract open.** Candidate `src/lib/aiur/opencode/chat_completions.ex:56-65` calls `Caller.authorize` before identified turn, replay, nudge or operator-text routing. Candidate `src/test/aiur/opencode/bridge_test.exs:35-69` asserts 401 on unauthenticated marker requests. `Aiur.Opencode.Bridge` still has no router auth plug; `ChatCompletions.handle/2` returns unauthenticated empty SSE for a placeholder model and 400 for invalid/no model before auth (`chat_completions.ex:43-58`, bridge tests 111-137). Those branches do not appear to dispatch an operator message, so the **named exploit mechanism is blocked**; the original recommendation that *every* completion request require bearer authorization is **partially unmet**. Verify with a focused pre/post mutation test and after merge.
- **Nine exact subjects removed:** `github-a-03`, `github-a-20`, `github-a-21`, `github-a-22`, `github-a-34`, `nonelixir-shell-29`, `web-occ-11`, `web-rest-23`, `web-rest-24`. The candidate deletes the local deletion guard, the GitHub cache page and its BudgetMap/CacheInspector stack; a candidate search found no same-name production modules or guard command remaining. This is source-level removal, not measured LOC saving or proof that adjacent quota, chart, test or web concerns vanished. The user-directed deletions belong to the release, not later refactor savings.
- **Other affected P0/P1 findings:** retain `needs_source_recheck` even if their cited line range did not change. For example, `nonelixir-shell-01` cites a launcher modified only to remove the guard command, while the cross-instance stop behavior is still untested; `agent-runtime-04` has a checkpoint-delivery diff but its restore/failure contract needs a targeted test. Prioritize these 31 P1 and the remaining P0 before promoting them to implementation-ready.

For deleted `.ex` sources, a candidate `defmodule` scan found no same-name module relocated to another production path. That scan does **not** establish that all behavior disappeared: new modules, indirect callers and replacement code need separate review. For modified files, line mapping in the ledger is a navigation hint derived from zero-context diff hunks; source meaning must be reread. After the nine PRs merge, rerun this ledger against the actual merged `main`, inspect changed callers/tests, and update each canonical finding's disposition without rewriting the frozen source claim.
