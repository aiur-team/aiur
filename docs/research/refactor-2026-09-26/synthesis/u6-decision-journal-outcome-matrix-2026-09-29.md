## Contract gates before U6 implementation

1. Choose one acknowledgement model for every write path: accepted after journal fsync with stable event ID; failed only when absence is known; uncertain complete write holds the caller/retry until journal reconciliation. Reserve ID and logical request identity must not be conflated.
2. Decide whether projection failure with an accepted event returns `accepted` plus degraded health or a distinct accepted-degraded result. Every reader must expose journal authority, projection freshness/age, and held side effects without treating stale JSON as current.
3. Specify which notifications and dispatches are withheld, recorded and replayed by event ID after projection repair. Include request, enrichment and lifecycle paths; replay must be idempotent across process restarts.
4. Add failure-path characterization tests for foreground append error, complete-write/uncertain-sync, accepted append plus projection failure and restart, complete corruption, and torn-tail repair. Each test must fail when its production repair is reverted; use isolated temp state and avoid live daemon files.
5. Recheck this matrix against the actual merged `main` before promoting the plan beyond `requirements-only`. No runtime frequency or saving is inferred from this static audit.
