# U5 trust boundary recheck at merged main

Read-only source audit at `17f82aae243cb1428e3b56b468ef9ed79ecb51e9`. This narrows the [earlier trust audit](u5-trust-boundary-behavior.md); it does not establish runtime incidence or authorize implementation.

- [`GitHub.CodeOwners.do_refresh`](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/github/code_owners.ex#L181-L237) retains a previous allowlist if CODEOWNERS is absent or unusable and no configured account or repo owner resolves. A formerly trusted team member can therefore remain authorized despite the degraded log message.
- [`Teams.fetch_member_logins`](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/github/teams.ex#L25-L41) fails the entire paginated lookup after a later-page error, but [`resolve_team`](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/github/code_owners.ex#L273-L300) collapses that error to an empty list. The resulting snapshot can still claim `source: :file` and no degradation when direct accounts remain.
- The separate [`Aiur.Codeowners`](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/codeowners.ex#L409-L494) path treats lookup errors as unknown, but does not consume later team-member or changed-file pages. A successful first page can be mistaken for a complete result. The shared [`PullRequests.fetch_pull_request_changed_paths/2`](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/github/pull_requests.ex#L13-L29) also reads only one page, so routing the separate path through it alone would retain the changed-file gap. [`Config.allowed_users`](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/github/config.ex#L479-L490) remains a distinct dispatch gate.
- Newly added formal reviews pass through [`CommentContext`'s authoritative trust gate](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/agent_runner/comment_context.ex#L252-L265); they need one bootstrap regression case. Sanitized untrusted content can remain in the Executor view while [`EventsDigest`](https://github.com/aiur-team/aiur/blob/17f82aae/src/lib/aiur/agent_runner/events_digest.ex#L35-L77) omits it from agent instructions.

The smallest safe U5 contract keeps configured daemon, bot and explicitly trusted accounts plus a verified repo owner in degraded mode; stale or partially fetched team members authorize nothing new. Preserve the difference between unknown/incomplete and proven empty, with cause and observed age. Use one authoritative result across event and per-path consumers before extracting files.

Behavior gates: healthy to team page-two failure; missing CODEOWNERS after a healthy snapshot with no repo owner; explicit and origin-derived owner fallback; later pages beyond 100 team members or PR paths; trust process crash; and an untrusted `/aiur` comment that stays Executor-visible but cannot enter the agent digest, command path or rework. Each case must assert the trust decision, degraded cause and age, and the affected consumer. The [existing team tests](https://github.com/aiur-team/aiur/blob/17f82aae/src/test/aiur/github/teams_test.exs#L44-L66) and [CODEOWNERS tests](https://github.com/aiur-team/aiur/blob/17f82aae/src/test/aiur/github/code_owners_test.exs#L228-L239) do not cover those transitions.
