# MPG-502 — Route Executor wakes by gateway and let one Executor claim a Decision: research

Plan: `docs/plans/2026-11-06-multi-project-gateways.md` (PR #7579; decision row 27). Contract: MPG-502 in
`docs/plans/2026-11-06-multi-project-gateways/tickets-m4-m7.md`. Code checked at `origin/main` 26ec6e00d (2026-11-06).
Paths below are relative to the repository root; `S/` = `src/lib/aiur/`, `T/` = `src/test/aiur/`,
`E/` = `packaging/npm/aiur-cli/libexec/`.

## Outcome

1. Every Executor wake record written by a daemon carries `gateway_id` and `gateway_label` (the machine identity from
   MPG-001). `aiur --gateway all executor-wait --as <id> --json` therefore prints PC's records with `gateway_id` = PC's
   id, and the Executor can tell which machine a wake belongs to without parsing the registry name.
2. Every Decision wake (`ticket.N.agent.attention.operator-decision` and `executor.decision.answered`) names its
   `decision_id` and its `gateway_id`, so an Executor holding two gateways' wakes can address the right store.
3. `aiur executor-claim-decision <decision-id> --as <executor>` makes one Executor the owner of one open Decision.
   A second Executor's `executor-answer` (or escalate, reclassify, moot) on it is refused with the claimant's id.
   `aiur executor-release-decision` hands it back; the claim also expires on its own.

## Design

### D1. Stamp the gateway at one choke point

All three wake paths already funnel through `enqueue_wake/2` (`S/executor_listener.ex:310`): projected PR/CI events
(`deliver_projection/2`), the blocking-Decision wake (`wake_blocking_decision/2`, line ~321), and the escalation ladder
(`escalation_opts/2` defaults `wake_fun` to `&enqueue_wake(&1, inbox)`). The contract's "line 311, where records are
built" is slightly off: records are *built* in `Aiur.ExecutorWakeProjection.project/1` and
`Aiur.ExecutorAttention.DecisionEscalation.wake_record/5`, but they are *all enqueued* at line 310. Stamping at
enqueue covers every path with one edit and cannot be missed by a future projection clause.

`enqueue_wake/2` merges `Aiur.Gateway.Identity.current/0` (MPG-001) into the record as
`"gateway_id"` and `"gateway_label"` before `ExecutorWakeInbox.enqueue/2`. When MPG-001 reports the identity
unavailable, both are `nil`; nothing is invented. The inbox stores records as opaque maps (no key whitelist in
`S/executor_wake_inbox/storage.ex`; dedup key is `{topic_class, ticket}`, unaffected), but the journal round trip is
tested, not assumed (scenario T3).

The stamped value is always *this daemon's* gateway: a wake is written by the daemon that observed the event, and each
daemon has its own journal. It does not mean "owner of the ticket".

### D2. "PR review wakes go to the gateway that ran the agent" — no new routing in this ticket

Today a foreign ticket's wake is already dropped by `Aiur.Instance.skip?(ticket, nil, :executor_wake)`
(`S/instance.ex:93`, applied in `enqueue_wake/2`), based on the shared lease. With D1 each retained wake names its
gateway. The ownership ref (MPG-101..106) is not a dependency of MPG-502 (it depends only on MPG-001), and
`Aiur.Ownership` does not exist on `main`. So MPG-502 keeps `Instance.skip?` as the only gate and leaves one named
seam: the `skip?` call in `enqueue_wake/2`. When M1 lands, replacing that predicate with an ownership read is a
one-line change in a later ticket. Doing it here would invent an API the ownership tickets define.
(Open question Q1.)

### D3. Decision ids are not gateway-unique; the claim lives with the Decision's home gateway

`decision_id` is `dec_` + 16 hex of `sha256("<ticket identifier>::<source id>")`
(`S/decision_validation.ex:444`). The ticket identifier is the bare issue number, so the same number in two repos, or on
two gateways, can produce the same id. It is stable and durable on one store, but not unique across stores.

Decision (row 27 "durable ids"): **do not change the id format.** It is validated by regex in
`S/executor_command_ack.ex` and used in journals. Instead the claim is arbitrated by the store that holds the
Decision, and a remote call reaches that store through `--gateway <name>` (MPG-202) exactly as `executor-answer` does.
Cross-gateway display uses the pair `gateway_id` + `decision_id`. Because one GenServer (`Aiur.DecisionStore`)
serializes writes on its home gateway, two Executors racing to claim cannot both win; no distributed lock is needed.

### D4. The claim is a journaled fact on the Decision

Alternatives: a separate claims JSON file with a lock (as `S/executor/claims.ex` does for the wake stream) or a new
`DecisionEvent` type. Chosen: reuse the existing **routing-fact path**, which already models "an Executor did something
to this Decision" (`:executor_acknowledged`). A claim is replayed from the journal, survives restart, shows in Decision
history, and needs no second file lock.

- Fact types `:executor_claimed` and `:executor_claim_released`, added to
  `Aiur.Commands.Routing.FactData` (`@types`, `fields/2`; `S/commands/routing/fact_data.ex`).
  Data: `executor_id` (1–256 bytes), `at`, and for claimed `expires_at`; for released `reason`
  (`released | expired | answered | operator`).
- Decision struct gains `executor_claim: nil | %{executor_id, claimed_at, expires_at}` (`S/decision.ex` defstruct and
  `@type`), carried through `Routing.Facts.@fields` so `inherit/2` and `public/1` keep it
  (`S/commands/routing/facts.ex`).
- `Facts.transition/2` clauses: claim is valid while `decision_status in [:open, :deferred]` and `answer == nil`
  (else `{:error, :command_not_open}`, same as `:routed`); a second claim by a *different* executor while the claim is
  live is `{:error, {:claimed, executor_id, expires_at}}`; the same executor re-claiming renews `expires_at`.
  Release by the claimant, or after expiry, clears it.
- **Content hash:** `request_json/1` in `S/decision_event/codec.ex:254` drops routing fields so routing facts never
  change the frozen request hash. `executor_claim` must be added to that drop list. Omitting it would make a claim
  change `content_hash` and break replay of every claimed Decision (scenario T8 guards this).
- `lifecycle_slug/1` (`S/decision_store/requests.ex:353`) and `S/decision_history/event_projection.ex:86` get matching
  clauses so history renders "claimed by" and "claim released"; the UI label in
  `src/lib/aiur_web/components/operator_control_center/decision_timeline.ex:11` gets two entries.

The contract names `decision_store/claims.ex` with `claim/2` and `release/2`. Keep that module as the home of the pure
rules (live-claim test, expiry, conflict, the answer-path check), and have `CommandFacts.record/5` do the persisting.
`Aiur.DecisionStore.Claims`:

```elixir
@spec claim(Decision.t(), %{executor_id: String.t(), now: DateTime.t(), ttl_ms: pos_integer()}) ::
        {:ok, claim_map} | {:error, {:claimed, String.t(), DateTime.t()} | :command_not_open}
@spec release(Decision.t(), %{executor_id: String.t(), now: DateTime.t()}) ::
        {:ok, :released} | {:error, {:claimed, String.t(), DateTime.t()} | :not_claimed}
@spec check_actor(Decision.t(), actor :: map(), now :: DateTime.t()) ::
        :ok | {:error, {:claimed, String.t(), DateTime.t()}}
```

Public API on `Aiur.Commands` (`S/commands.ex`, next to `record_command_fact/4`): `claim_decision/3`,
`release_decision/3`, both thin calls into the store.

### D5. What a claim blocks

`Claims.check_actor/3` returns an error only when the actor is `kind: :executor`, a live claim exists, and
`actor.id != claim.executor_id`. It is called from `Aiur.DecisionStore.Answers.handle_answer/4`
(`S/decision_store/answers.ex:21`) right after `fetch_actor/1`, and from the other Executor mutations
(`executor-escalate`, `executor-reclassify`, `executor-moot`, and `--supersede`). The implementer greps
`actor: %{kind: :executor` in `S/` to list the exact call sites (`withdrawals.ex`, `revisions.ex`, `override_*`); each
must go through `check_actor/3` and each gets a refusal test.

Not blocked: operator and operator-relayed answers, supervisors, system actors. Human precedence (plan Decision row on
human authority) means a human may always answer; an operator answer clears the claim (fact
`:executor_claim_released`, reason `operator`). Answering by the claimant, or any terminal status, clears it with reason
`answered`.

### D6. Expiry, not a heartbeat

The claim has a TTL, default **30 minutes** (config below). It is renewed by the claimant's own `executor-claim-decision`,
`executor-ack`, or a refused-nothing mutation. It needs no daemon timer: `check_actor/3` and `claim/2` compare
`expires_at` to `now` at call time, and an expired claim is treated as absent. This keeps the lazy design of
`Aiur.Executor.Claims.live?/2` (`S/executor/claims.ex:193`) and avoids a sweeper. A crashed Executor therefore blocks a
Decision for at most the TTL.

### D7. Executor identity must be explicit

`executor-answer` and `executor-ack` default `--executor-id` to `aiur-cli`
(`E/engine/executor_commands.sh:29`, `S/executor_command_cli.ex:6`). Two Executors that omit it are the *same actor*
and the claim would not separate them. So the new command requires `--as <id>` (same pattern and regex as
`executor-claim`: `[A-Za-z0-9._-]+`, exit 64 if absent), and **a claim by `aiur-cli` is refused** with a usage error.
Existing answers without a claim keep working with the default.

### D8. CLI surface

- `aiur executor-claim-decision <decision-id> --as <executor> [--ttl <seconds>]` and
  `aiur executor-release-decision <decision-id> --as <executor>`.
- `decision-id` validated by `^dec_[0-9a-f]{16}$` (same as `executor-ack`).
- Exit codes: 0 claimed/renewed/released; 1 refused (`aiur: Command dec_… is claimed by <id> until <iso8601>`);
  64 usage; the usual 69/75 transport codes when remote.
- Remote: add both names to the `executor-…` list at `E/engine/remote.sh:35` and make them `--gateway`/`--instance`
  capable the same way `executor-answer` is. Category is `executor` (S2), write scope.

### Alternatives rejected

- *Claim by Postgres lease row.* Decisions live in the local store; the lease store is optional
  (`AIUR_LEASE_DATABASE_URL` unset on most gateways) and its failure mode is "skip", wrong for a refusal.
- *Claim as a GitHub label.* Public, rate-limited, and the Decision may have no ticket comment yet.
- *Gateway-prefixed ids (`pc:dec_…`).* Breaks the id regex, journals and every stored reference for no gain: the home
  gateway already arbitrates.
- *Route PR review wakes by ownership now.* Depends on M1 (D2).

## Prior art

None needed beyond the existing reports. `docs/research/multi-gateway/github-claim-protocols.md` and
`notes/github-claims/lease-theory.md` cover leases and fencing for *ticket* ownership; the lesson that applies here is
the same: a lease with expiry plus a single arbiter beats a heartbeat, and an unknown outcome means "do not act".
The Decision claim has a single arbiter (the home store), so none of the distributed-claim machinery applies. No
external question remains open.

## Risks

- **Journal compatibility.** Adding fact types changes what an older daemon reads. An old binary replaying a journal
  with `executor_claimed` may reject it. Detect: replay test against a journal fixture; fallback: write the new types
  only when the daemon's schema version supports them, or accept that a rollback after claims were written needs the
  claim events skipped. The rollout order (all gateways upgrade before anyone claims) belongs in the docs.
- **Hash drift** (D4). Covered by T8.
- **Missed mutation path.** A path that does not call `check_actor/3` silently ignores claims. The grep in D5 plus a
  test per path is the guard.
- **Identity not ready.** MPG-001 unmerged means wakes stamp `nil`; harmless but the acceptance test needs the seam.
- **TTL too short or long.** An Executor idling past 30 minutes loses the claim and a second Executor can take it; the
  first then gets the D5 refusal naming the new claimant. Acceptable; adjustable via config.

## Open questions

| Question | Recommended default | What changes if answered differently |
|---|---|---|
| Q1. Should PR review wakes be dropped on non-owning gateways by reading the ownership ref? | No: keep `Instance.skip?`; add the ownership read when M1 merges | Adds a dependency on MPG-10x and an `Aiur.Ownership` read in `enqueue_wake/2` |
| Q2. Is the stamped `gateway_id` the writing daemon or the ticket owner? | The writing daemon (always self) | Owner stamping needs ownership reads and can name a gateway that never wrote the wake |
| Q3. Do operator answers beat a claim? | Yes, always; they clear it | A hard claim would let a stuck Executor block a human, against the human-precedence rule |
| Q4. Claim TTL: config key or constant? | Config key `executor.decision_claim_ttl_seconds`, default 1800 | A constant drops one config key and its docs |
| Q5. Ship `executor-release-decision`? | Yes (small; avoids waiting out the TTL) | Without it a wrong claim blocks others until expiry |
| Q6. Keep `dec_` ids unchanged? | Yes (D3) | A gateway-scoped id format touches the validator regex, journals and every stored reference |
| Q7. May `aiur-cli` hold a claim? | No: require an explicit `--as` | Allowing it makes two default-id Executors indistinguishable |
