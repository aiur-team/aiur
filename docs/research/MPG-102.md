## Outcome

`Aiur.Ownership.GitHubRef` reads, claims, transfers and releases one ownership record per ticket at
`refs/aiur/owners/<ticket>` in a repository, through the existing GitHub transport. Every write is a GraphQL
`updateRefs` with `beforeOid`. Every call returns `:won`, `:lost` or `:unknown`; anything not proven is `:unknown`.
`Aiur.Ownership.Record` encodes and decodes `owner.json` (S1). All requests declare a `caller`, so the budget broker,
quota ledger and `aiur github-cost` attribute them. Nothing calls this module yet (MPG-103 does); no config key, CLI
command or env var changes.

## Design

### The one hard fact that shapes everything

MPG-101 found that **a losing `updateRefs` has no loser signature**. Every losing create returned HTTP 200 with
`errors[0].message = "Something went wrong while executing your query on <ts>. Please include `<id>` ..."` and no
`type`. It looks like a server fault. So `:lost` is never inferred from a write response's text. The contract bullet
"a 422 whose message is not the MPG-101 'lost' signature returns unknown" is satisfied trivially: there is no
signature, so a bare 422 is `{:unknown, {:http, 422, msg}}` unless the re-read below proves otherwise.

The one documented loser shape is on advance: stale `beforeOid` gave `errors[0].type = "UNPROCESSABLE"`,
`rejecting non-fast forward update`. Treat it as a *hint to re-read*, not as proof.

### Classification rule (the whole decision table)

After the write request, with `new` = the commit oid this call created and `before` = the `beforeOid` sent:

| Write result | Action | Outcome |
|---|---|---|
| HTTP 200, no `errors` | none | `{:won, record}` |
| HTTP 200 with `errors`, or HTTP 422 | one uncached re-read (`read/3`) | by re-read, below |
| `{:error, {:github, :timeout, _}}` (timeout, closed, reset), 5xx, 401/403, rate limit, broker error | one uncached re-read (`read/3`) | by re-read; unchanged ref returns the original reason (`{:unknown, :timeout}` / `{:unknown, reason}`), no retry |
| `:local_hold` and any error where the request was provably never sent | none | `{:unknown, reason}` |
| response not decodable | none | `{:unknown, :invalid_response}` |

Re-read after an error (MPG-101: "on any error, re-read the ref"; one GraphQL point per error):

| Ref now | Outcome |
|---|---|
| points at `new` | `{:won, record}` (the write applied before the error) |
| points at another oid, record decodes | `{:lost, current_record}` |
| points at another oid, record does not decode | `{:unknown, {:undecodable, reason}}` |
| still at `before` (absent for a create) | for `errors`/422: retry the same `updateRefs` (same commit) up to `max_attempts` (default 3, delays 0/250/1000 ms via `opts[:sleep_fun]`); then `{:unknown, {:graphql, message}}`; for transport/5xx/auth/rate errors: no retry, the original unknown |
| re-read itself fails | `{:unknown, {:reread, reason}}` |

A timeout or 5xx may arrive after the write applied, so it is re-read like any error (MPG-101 rule). The ticket
acceptance bullet is amended to "a timeout returns `:unknown` unless the re-read finds our commit"; the Executor owns
that plan-text amendment. `:won` is returned only when GitHub said ok, or a re-read found *our own commit oid* at the ref (the oid is unique: the commit carries the timestamp
and the claimant, and is built fresh per attempt).

### Wire sequence

Claim of an absent ticket, the longest path, in order. Calls 1-4 are free of ownership risk: unreachable objects are
garbage GitHub collects, so a crash between 2 and 5 leaves nothing to clean up.

1. `read/3`: GraphQL, caller `:ownership_ref_read` (below). Learns `before` and the current record.
2. `POST /repos/{o}/{r}/git/blobs` `{"content": <owner.json>, "encoding": "utf-8"}`, caller `:ownership_ref_write`.
3. `POST /repos/{o}/{r}/git/trees` `{"tree": [{"path":"owner.json","mode":"100644","type":"blob","sha":<blob>}]}`
   (no `base_tree`: the tree holds exactly one file).
4. `POST /repos/{o}/{r}/git/commits` `{"message": "aiur ownership <ticket> epoch <n>", "tree": <tree>, "parents": <[] | [before]>}`.
   Transfer, release and claim-of-released use `parents: [before]`, so the ref's history is the audit log and every
   advance is a fast-forward. A first claim is a root commit. No `author` field (GitHub uses the token's identity).
5. `POST /graphql` `updateRefs(input: {repositoryId, refUpdates: [{name: "refs/aiur/owners/<ticket>", beforeOid, afterOid}]})`,
   caller `:ownership_ref_write`. `beforeOid` is `before`, or forty zeros for a create.

Same shape as `landing_watch/quarantine_pr.ex:241-269` (blob, tree, commit) with the final REST ref write replaced by
`updateRefs`. **Never** use REST `POST /git/refs` or `PATCH /git/refs` for ownership: MPG-101 step 5 showed `PATCH
force=false` accepts an unrelated commit, and the two-writer design needs one code path.

`repositoryId` is the repository's GraphQL node id, fetched once per repo (`query($owner:String!,$name:String!){repository(owner:$owner,name:$name){id}}`,
caller `:ownership_repository_id`) and kept in `:persistent_term` under `{Aiur.Ownership.GitHubRef.Wire, :repository_id, "owner/name"}`.
It is cleared when any ownership call returns a `NOT_FOUND` error, so a deleted-and-recreated repo re-resolves.

### Read

One GraphQL document, one point, returns the head oid and the record together (REST would need three core reads: ref,
commit, blob):

```graphql
query($owner:String!,$name:String!,$qualified:String!,$expr:String!){
  repository(owner:$owner,name:$name){
    ref(qualifiedName:$qualified){ target{ oid } }
    object(expression:$expr){ ... on Blob { text } }
  }
}
```

with `$qualified = "refs/aiur/owners/<ticket>"` and `$expr = "refs/aiur/owners/<ticket>:owner.json"`.
Result: `ref == null` -> `{:ok, %{oid: nil, record: nil}}` (absent). Otherwise decode `text` with `Record.decode/1`.
A ref that exists with a missing or undecodable blob, or an unsupported `schema`, is `{:unknown, {:undecodable, reason}}`,
**never** absent: treating a corrupt record as unowned would let a second gateway claim over it.
`oid` is `target.oid` (the commit), which is the next write's `beforeOid`.

Read-after-write freshness of GraphQL `object()` is not covered by MPG-101 (pending evidence, Q3). The protocol does
not depend on it: a stale "absent" makes the claim's create fail (re-read, retry, then unknown); a stale "owned by
other" is a skip that the next poll corrects.

### Uncached by construction

Ownership reads must not be served from `Aiur.GitHub.ReadCache`. Verified in the code, no new refusal rule is needed:
`ReadCache.Policy.classify/1` caches only request kinds `Shapes.classify_kind/1` names. A GraphQL read whose document
matches no known shape returns `{:no_cache, {:unclassified, shape}}` and `ReadCache.through/2` calls `fetch` directly.
The new document matches no shape. The test (below) asserts `Policy.classify(request)` is `{:no_cache, _}` for the exact
request the read sends, and that `ReadCache.snapshot().totals` is unchanged after a read, so a future shape added for
refs would fail it.

Write side effect to know about: `StoreEntries.write_through/3` retires cached reads after any write. The three REST
writes name the repo (retire `{:repo, o, r}`); the `updateRefs` mutation names only a node id, so
`write_identities/1` retires **`:root`** (the entire read cache) on every claim. Cost: one cold cache per claim.
Mitigation to try first (Q4): send `"owner"`/`"name"` as extra variables on the mutation request so
`Identity.repository_from_variables/1` names the repo; GraphQL ignores undeclared variable values per spec, but this is
unverified against GitHub, so the live probe in `scripts/spikes/github_ownership_cas.sh` should be extended once.

### Budget attribution

Nothing new to build: every request goes through `Aiur.GitHub.Access.default_request_fun/1` ->
`Transport.quota_request` -> `Budget.acquire`/`observe` (the broker), and is billed to its `:caller`. Declared callers:

| Caller (atom, passed as `caller:`) | Request | Resource |
|---|---|---|
| `:ownership_repository_id` | GraphQL repository id | graphql |
| `:ownership_ref_read` | GraphQL ref + blob read | graphql |
| `:ownership_ref_write` | blobs, trees, commits (REST) and `updateRefs` (GraphQL) | core x3, graphql x1 |

REST requests take `caller:` as a key on the request map (`Transport.put_caller/2` shape, as `quarantine_pr.ex:395,405`
does with string callers); GraphQL takes `caller:` in opts (`GraphQLCost`/`send_graphql`). Cost per successful claim of
an absent ticket, steady state: **3 core + 2 graphql** points (read, `updateRefs`), plus 1 graphql for the one-time
repository id; a lost or errored claim adds 1 graphql for the re-read. Cost per `read/3`: 1 graphql. These are
estimates from the request count, not measurements; MPG-102 claims no saving, and `aiur github-cost` shows the real
figures once MPG-103 calls it.

Caller names must **not** start with `landing_watch`, `quarantine_`, `main_watch` or `main_fixer`:
`LeaderFence.repo_global_write?/1` would otherwise refuse ownership writes on every non-leader and secondary gateway,
which must claim their own tickets. A test pins this (below).

### Return shapes (public API)

```elixir
@type observed :: %{oid: String.t() | nil, record: Record.t() | nil}      # oid nil = no ref
@type outcome :: {:won, Record.t()} | {:lost, Record.t() | nil} | {:unknown, term()}

read(repo :: "owner/name", ticket :: String.t(), opts) :: {:ok, observed} | {:unknown, term()}
claim(repo, ticket, claimant, opts)       :: outcome   # claimant: map with the S1 identity fields, below
transfer(repo, ticket, observed, new_owner, opts) :: outcome
release(repo, ticket, observed, opts)     :: outcome
```

`opts` is `[request_fun: fun, token: String, sleep_fun: fun, max_attempts: pos_integer, now: DateTime.t()]`, all
optional (production defaults: `Access.default_request_fun/1`, `Access.require_token/1`, `Process.sleep/1`, 3,
`DateTime.utc_now/0`). The contract lists arities 2, 3, 4, 3; the trailing `opts \\ []` keeps those arities valid.
`ticket` is a string: `"123"` or `"pr-45"`; the module validates `~r/\A(pr-)?[1-9][0-9]{0,9}\z/` and returns
`{:unknown, {:invalid_ticket, t}}` otherwise (it ends up in a ref name, so it is a trust boundary).

Semantics:

- `claim/4`: `read` first. Absent -> create (epoch 1, `previous_epoch` 0). `state: "released"` -> advance (epoch =
  released epoch + 1). `state: "owned"` by the same `gateway_id` **and** `daemon_key` -> `{:won, record}` with **no write**
  (idempotent). `state: "owned"` by anyone else -> `{:lost, record}` with no write.
- `transfer/5`: caller passes the `observed` it already read. Requires `observed.record.state == "owned"`, else
  `{:lost, observed.record}`. Writes `epoch = observed.record.epoch + 1`, `previous_epoch = observed.record.epoch`,
  new owner fields, `reason: "transfer"`, `beforeOid = observed.oid`. A stale `observed` is exactly the lost-race case.
- `release/4`: same, `state: "released"`, owner fields kept, `reason: "release"`, epoch bumped (Q2).
- Every write goes through one private `write(repo, ticket, record, before_oid, parents, opts)` implementing the wire
  sequence and the classification table. No other function builds an `updateRefs` request.

### `Aiur.Ownership.Record` (the `owner.json` encoder)

Struct fields = S1 exactly: `schema` (always `"aiur.ownership/v1"`), `repo`, `ticket`, `state` (`"owned"|"released"`),
`gateway_id`, `gateway_label`, `daemon_key`, `epoch`, `previous_epoch`, `actor` (`%{kind, id}`), `reason`, `at`.

- `new(attrs)`: validates and returns `{:ok, t} | {:error, {:invalid, field}}`. Rules: `gateway_id` 26 chars of
  `[a-z2-7]` (base32 machine id); `daemon_key` matches `Aiur.Config.InstanceKey` (`~r/\A[A-Za-z0-9_-]{1,64}\z/`), required
  and non-empty; `epoch` integer >= 1; `previous_epoch == epoch - 1`; `actor.kind` in `daemon|human|executor`;
  `reason` in `dispatch|transfer|release|migration`; `at` an ISO-8601 UTC string with `Z`.
- `encode(record) :: binary`: deterministic bytes. Build `Jason.OrderedObject` in the S1 field order
  (`schema, repo, ticket, state, gateway_id, gateway_label, daemon_key, epoch, previous_epoch, actor{kind,id}, reason, at`)
  and `Jason.encode!/1` it (Jason 1.4.5 in `mix.lock` has `OrderedObject`). No trailing newline. Same record -> same bytes,
  so tests can compare strings and a human diff of two commits is minimal.
- `decode(binary) :: {:ok, t} | {:error, reason}`: `Jason.decode/1`, then the same validation as `new/1`. Unknown
  extra keys are ignored (forward compatibility); an unknown `schema` value returns `{:error, {:unsupported_schema, s}}`.
- `claimant` for `claim/4` is a map `%{gateway_id, gateway_label, daemon_key, actor: %{kind, id}, reason}`; the module
  fills `repo`, `ticket`, `state: "owned"`, epochs, `at` (from `opts[:now]`). Callers (MPG-103) obtain `gateway_id` from the
  machine identity (`Aiur.Machine.Store`, `machine_id`) and `daemon_key` from `Aiur.Config.InstanceKey.current/0`; this
  module takes them as arguments and reads no global state, so tests need no machine file.

## Risks

- **Whole-cache flush per claim** (`:root` identity from the node-id mutation). Detect with `ReadCache` invalidation
  metrics after MPG-103; mitigate with Q4.
- **Poll-time read cost.** MPG-103 will want to read every candidate ticket each poll; at ~1 graphql point each, ~130
  tickets is ~130 points per poll. `read/3` is shaped so a batched read can reuse `Wire.parse_read/1`: GraphQL
  `refs(refPrefix:"refs/aiur/owners/", first:100)` listing was verified in MPG-101 (27 of 27). Not in this ticket; MPG-103R
  should decide (Q5).
- **Corrupt or hostile record.** A hand-written ref with bad JSON would otherwise read as unowned. Mitigated: undecodable
  is `:unknown`, never absent.
- **Ticket string in a ref name.** Validated by regex before use.
- **A stub that cannot reach the bug.** The stub must return the *real* loser shape (no `type`, no "already exists"); a stub
  that returns a friendly "already exists" would let text-matching code pass. The "Lost via re-read" test guards this.
- **Garbage objects** from failed attempts (blob/tree/commit with no ref) are unreachable and collected by GitHub; no cleanup.
- **Rate-limit hold during a claim** surfaces as `{:unknown, {:github, :local_hold, _}}`; MPG-103 treats it as skip.

## Open questions

| Question | Recommended default | What changes if answered differently |
|---|---|---|
| Q1. Re-read once after a timeout or 5xx, so a write that applied is reported `:won` immediately? | Yes (MPG-101 rule, adopted per review): one bounded re-read after every error except `:local_hold`; costs 1 graphql point per error. | No: `{:unknown, :timeout}` with no re-read; the next poll resolves it, but this departs from MPG-101. |
| Q2. Does `release` bump `epoch`? | Yes: every ref write bumps, so an epoch names exactly one ref position and a release-then-reclaim is strictly increasing. | No: release keeps the epoch and the next claim is released epoch + 1; the bump-on-claim contract bullet still holds, one fewer increment per cycle. The fence (MPG-105) is unaffected either way. |
| Q3. Use GraphQL `object()` for the read, or REST ref + commit + blob? | GraphQL (1 point vs 3 core reads). Add a freshness probe (write then immediate read, 25 rounds) to the MPG-101 script when convenient; the protocol is safe without it. | REST: `Wire.read_request/3` changes and the cost table becomes 3 core per read; the classification tables do not change. |
| Q4. Add `owner`/`name` as extra variables on the `updateRefs` request to avoid the `:root` cache flush? | Try it behind a test asserting the retired identity; if GitHub rejects undeclared variables on the live probe, drop it and accept the flush (claims are once per ticket dispatch). | Without it every claim empties the read cache once. |
| Q5. Provide `read_many/3` (prefix listing) now? | No. Out of the MPG-102 contract; MPG-103R decides after counting reads per poll. `Wire.parse_read/1` stays reusable. | Adding it here grows the ticket past complexity 3. |
| Q6. Should `claim/4` read internally or take an `observed`? | Read internally (the contract says claim sends "the observed head, or zeros"; one call site per caller is simpler and a stale input is impossible). `transfer`/`release` take `observed` because their callers already hold it (CLI shows it before asking). | Taking `observed` in `claim` saves one graphql read when MPG-103 has just read for its own-or-other check; revisit in MPG-103. |
| Q7. REST `POST /git/refs` for the create step, since it has a documented `Reference already exists` loser signature? | No: one code path (`updateRefs`) for create and advance, as MPG-101 decided; the re-read rule already classifies it. | Create gets a text-based loser signature, but two classification paths, and a claim of a released ticket still needs `updateRefs`. |
