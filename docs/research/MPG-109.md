`tickets-m0-m1.md` (MPG-103..108, MPG-109), `code-evidence.md` §2, `docs/research/MPG-101.md`,

## Outcome
`docs/research/MPG-109-evidence.md` records three live runs on PC and Nook (still one daemon per repository, both on
the Aiur repo with `instance.ownership: github`): **A1** a 30-minute simultaneous dispatch soak, **A5a** the shared
Postgres stopped, **A6** Nook's daemon stopped. Each section holds the exact commands, raw outputs and the numbers
below. Pass means: duplicates **0** by all three counts, and a non-vacuous workload (at least 6 tickets dispatched, at
least 2 per gateway, at least 1 contested ticket).

## Design
**What a duplicate is.** Same definition as `MPG-701.md` (it reuses this runbook): a ticket on which two *different*
gateways each ran an agent with overlapping lifetimes, or two PRs from different gateways opened for one ticket in the
window. A rework on the *same* gateway is not a duplicate; a transfer followed by a run on the new owner is not one
if the old run ended before the transfer's `at` or the fence stopped it. Expected count in every test: **0**.

**Three independent counts**, because each sees a different failure and a disagreement between them is a finding:

| Count | Sees | Source (file or API) |
|---|---|---|
| S-ref | two claims at one epoch, or an epoch that skipped | ownership refs `refs/aiur/owners/<n>` (KTD-2, S1) via `git ls-remote` and `git show <commit>:owner.json` |
| S-run | two overlapping agent lifetimes on different gateways | per machine: `<workspace.root>/<repo>/<n>/logs/agent.ndjson` (`session_started` events) |
| S-pr | two PRs or two `gateway:` labels for one ticket | `gh pr list`, issue events API |

The analytics per-ticket record (`~/.aiur/repo/<owner>/<name>/analytics/tickets/<n>.json`, field `attempts[]` with
`attempt_id`, `boot_id`, `dispatched_at`, `retry_attempt`, `start_mode`) is a **cross-check on S-run**, not its source:
an attempt has no end time, and the record refreshes on the daemon's cadence (`ledger-cursor.json` was last written
15:00 while a workspace log was current at 15:07 on the day this was written). Use it to confirm *dispatch counts*:
for each ticket, `jq '.attempts|length'` on PC plus on Nook must equal the number of `session_started` generations
S-run found, give or take the retry/rework attempts that did not reach `session_started` (record any difference).

**Why `agent.ndjson` for S-run.** AGENTS.md says it "must persist" and the attentions feed reads it. It carries
`session_started` with `timestamp`, `session_id`, `thread_id`, `generation`. Run window: from a `session_started`
to the next `session_started` in the same file, or to the file's last `timestamp` for the final session. This
over-estimates a session's end (a quiet tail after the agent stopped), which can only create a false positive, never
hide a real overlap. A false positive is investigated, not waved through (T4).

**Machine attribution.** Each machine reads only its own workspaces, so the gateway column is the label the operator
gives when exporting (`pc`, `nook`). Cross-check the label with `identity.json` `machine_label`.

**Non-vacuity gate (do not skip).** A soak in which nothing was contested proves nothing. Before reading the
duplicate counts, compute `dispatched` (rows in S-run, per gateway), and `contested` = tickets for which both
gateways attempted a claim. Contested has no direct source until MPG-103 lands; use, in order: (1) the ownership
commit chain: a ref whose first commit's `gateway_id` is X but whose ticket was `agent:todo` at the same time on
both pollers is not observable from the ref, so (2) the daemon's own claim outcome log. The name of that log line is
decided by MPG-103 (open question 1). Until then, force contention: apply the label to **N=6 probe tickets at once**
(one `gh issue edit` loop) so both 5-30 s pollers see them in the same cycle, and report `contested = 6`
as "forced", not "observed".

**Environment preconditions (check, record in the evidence file).**
1. MPG-103..108 merged and the *same build* running on both gateways (`aiur status` build commit equal).
2. `instance.ownership: github` in `.aiur/config` on both (key from MPG-103, `src/lib/aiur/config/schema/instance.ex`).
3. `AIUR_LEASE_DATABASE_URL` set on both and pointing at the same store (for A1 and A6; A5a stops it).
4. Distinct `gateway_id` per machine; distinct `github.label_prefix` is **not** relied on (leave the legacy `agent:` /
   `nuc:` prefixes as deployed; ownership, not the prefix, must be what separates them).
5. At least 6 `agent:todo` tickets eligible to both, complexity 1-2 so agents finish quickly. Probe tickets are the
   Executor's decision (open question 2).
6. Clocks: `chronyc tracking` (or `timedatectl`) on both; offset must be under 1 s. S-run overlap is a clock comparison
   across machines.

### The queries

All run from a scratch directory outside any Git tree, with `T0`/`T1` as UTC ISO timestamps for the window.

**S-run, step 1, on each machine** (`ROOT` = `workspace.root`/`<repo>`, e.g. the `.../aiur-team/aiur` directory;
`GW` = `pc` or `nook`). Emits one row per session:
```bash
for d in "$ROOT"/*/; do t=$(basename "$d"); f="$d/logs/agent.ndjson"; [ -f "$f" ] || continue
  jq -s -r --arg t "$t" --arg g "$GW" '
    [.[]|select(.event=="session_started").timestamp] as $s | (.[-1].timestamp) as $L
    | range(0;$s|length) as $i | [$t,$g,$s[$i],($s[$i+1]//$L)] | @tsv' "$f"
done | awk -F'\t' -v a="$T0" -v b="$T1" '$4>=a && $3<=b' > "rows-$GW.tsv"
```
Copy `rows-pc.tsv` and `rows-nook.tsv` into one directory (the join is the only cross-machine step).

**S-run, step 2, cross-gateway overlaps** (expected: `[]`):
```bash
cat rows-pc.tsv rows-nook.tsv | jq -R -s -c '
  split("\n")|map(select(length>0)|split("\t")|{t:.[0],g:.[1],s:.[2],e:.[3]})|group_by(.t)
  |map(. as $r|[range(0;length) as $i|range($i+1;length) as $j
    |select($r[$i].g!=$r[$j].g and $r[$i].s<$r[$j].e and $r[$j].s<$r[$i].e)|$r[$i].t]|unique)|add//[]'
```
Adjacent windows (one ends at the instant the next starts) are not an overlap (T3).

**S-run, same-gateway overlap** (expected: also `[]`; this is the lease's job, KTD-3): the same filter with
`$r[$i].g==$r[$j].g`. A rework session starts after the previous one ended, so a non-empty result is a real
double-run on one daemon.

**Workload (non-vacuity), expected `>= 6` total, `>= 2` each:**
```bash
cut -f1,2 rows-pc.tsv rows-nook.tsv | sort -u | awk -F'\t' '{n[$2]++} END{for(g in n)print g,n[g]}'
```

**S-ref** (from any clone with network; refs are not branches so `git ls-remote` is cheap):
```bash
git ls-remote origin 'refs/aiur/owners/*' | while read sha ref; do n=${ref##*/}
  git fetch -q origin "$ref:refs/aiur-check/$n" 2>/dev/null
  git log --format=%H "refs/aiur-check/$n" -- owner.json | while read c; do
    git show "$c:owner.json" | jq -c '{ticket,epoch,previous_epoch,gateway_id,reason,at}'; done
done > owners.ndjson
jq -s -c 'group_by(.ticket)|map({t:.[0].ticket, dup:([group_by(.epoch)[]|select(length>1 and ([.[].gateway_id]|unique|length)>1)]|length),
  skip:([.[]|select(.previous_epoch!=null and .previous_epoch+1!=.epoch)]|length)})|map(select(.dup>0 or .skip>0))' owners.ndjson
```
Expected `[]`. `previous_epoch` is `null` on a first claim (verify against MPG-103's writer, open question 3). If
fetching custom refs is refused by the remote, read through the API instead
(`gh api repos/O/R/git/matching-refs/aiur/owners/` and `.../git/commits/<sha>`), as MPG-101 did.

**S-pr** (expected `0` lines):
```bash
gh pr list -R "$REPO" --state all --search "created:$T0..$T1" --limit 200 --json number,headRefName,body,createdAt \
  | jq -r '.[]|[(.body|capture("Closes #(?<n>[0-9]+)").n // "none"),.number,.headRefName]|@tsv' \
  | sort | awk -F'\t' '$1!="none"{c[$1]++; l[$1]=l[$1]" #"$2} END{for(k in c) if(c[k]>1) print k, l[k]}'
```
A ticket with two PRs from the *same* gateway (a closed-and-reopened PR) is listed too; classify by the head
branch's pushing gateway (`git log` author or the `owner.json` at that time) before calling it a duplicate.
Also per ticket, `gh api repos/$REPO/issues/$N/events --paginate | jq '[.[]|select(.event=="labeled" and (.label.name|startswith("gateway:")))|.label.name]|unique|length'`
must be `<= 1`.

## Risks
| Risk | Detect early | Fallback |
|---|---|---|
| Vacuous pass (nothing contested) | workload gate fails | add probes, rerun; do not report a pass |
| Clock skew between PC and Nook makes a real overlap look adjacent | `chronyc tracking` offset > 1 s | fix NTP and rerun; a 1 s skew can hide only overlaps under 1 s |
| Custom ref fetch refused or webhook noise from `refs/aiur/owners` | `git fetch` error; unexpected `branch.push` events | use the API reads; fallback namespace is KTD-2's `refs/heads/aiur-owner/` |
| An old build on one gateway | build commits differ | R0 blocks the run |
| Ownership off on one gateway by mistake | `grep ownership .aiur/config` on both | R0 blocks the run |
| GitHub budget starvation by 6+ probes plus soak | `aiur github-cost` per-caller points during the window | fewer probes, wider spacing |
| Stopping the store takes a gateway's own heartbeat down and hides it from `/instances` | expected | not a failure; note it |
| A late stale read lets a gateway act once more (bounded by the 30 s fence refresh, plan "What it cannot promise") | S-run shows an overlap under 30 s | record as a finding against MPG-105, not as a runbook error |
