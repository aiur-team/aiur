# MP-N2-C10-T03 — T-A: publicly trusted certificate path

## Identity and outcome

- **Bucket / feature / chunk:** 3 / MP-N2 / MP-N2-C10.
- **User value:** an operator who already runs Tailscale (or any ACME client) gets HTTPS for the
  phone in two commands, knows what the choice discloses (machine name in Certificate
  Transparency logs), and is warned before the certificate expires. Tailscale stays optional:
  the same settings accept any CA-issued certificate.
- **Deliverable:**
  - `aiur mobile tls status [--json]`: the `TlsHealth` block from MP-N2-C10-T02 plus the
    setting values (paths, not contents), `days_left`, and the next action.
  - `aiur mobile tls tailscale [--host <name>]`: a **guided** helper. It prints, and with
    `--apply` runs, `tailscale cert --cert-file <state>/tls/cert.pem --key-file <state>/tls/key.pem <name>`
    (state dir `~/.config/aiur/machine/tls/`, 0700), then writes the four `transport.tls.*` keys into
    `~/.aiur/machine`. Before running it prints the CT disclosure and asks for confirmation
    (`--yes` to skip in scripts).
  - A renewal warning in `aiur mobile status` and at instance launch when `days_left < 14`.
  - Docs: a "Phone access over HTTPS" section on the pairing guide page.
- **Non-goals:** automatic renewal (a systemd/launchd timer is documented, not installed);
  bundling an ACME client; making Tailscale required.

## Verified starting point (base `45a290e3`)

- No `aiur mobile` verb exists; the engine's main dispatch is a `case` near `status`
  (`packaging/npm/aiur-cli/libexec/aiur-engine.sh:4110`, MP-N2 chunks C3-T02).
- No code in `src/lib` or `packaging` calls `tailscale` for certificates (`git grep -n "tailscale cert" 45a290e3`
  returns only docs); MP-R3 confirms that Tailscale is docs-only today.
- External facts (accessed 2026-10-06, page undated): `tailscale cert` requests Let's Encrypt
  certificates using a DNS-01 challenge; "Your certificate's private key … [is] generated and
  stored locally on your machine and Tailscale never sees them"; certificates expire after 90 days
  and "when using `tailscale cert`, you are responsible for renewing the certificate"; "machine
  names are still published in the public ledger" — <https://tailscale.com/kb/1153/enabling-https>.
  HTTPS must be enabled for the tailnet in the admin console first (same page).

## Chosen design

- The helper never stores secrets in `~/.aiur/machine`; it stores **paths**. The key file is
  written by `tailscale` itself into the 0700 state dir; the helper then `chmod 0600`s it and
  verifies ownership.
- `--host` defaults to the output of `tailscale status --json` → `Self.DNSName` (trailing dot
  stripped). If `tailscale` is not on `PATH`, the helper exits 3 with "Tailscale is optional —
  point transport.tls at any certificate (see docs)"; this is not an error state for aiur.
- The helper sets `bind_host` to the first `Self.TailscaleIPs` IPv4 address and
  `advertise_host` to the DNS name, unless the operator passes `--bind`.
- Renewal guidance: re-running `aiur mobile tls tailscale --apply --yes` is idempotent; the
  MP-N2-C10-T01 watcher picks up the new files without a restart.
- Exit codes: 0 ok; 2 bad arguments; 3 tailscale unavailable; 4 tailscale cert failed (its stderr
  is shown); 5 settings write failed.

## Implementation steps

1. Engine dispatch: `mobile tls status|tailscale` → release RPC-free paths (pure file work plus
   a release eval for `TlsHealth`), following the pattern of the other `aiur mobile` verbs (C3-T02).
2. `src/lib/aiur/machine/tls_cli.ex` (PROPOSED): `status/1`, `tailscale/1` (shells out with
   `System.cmd/3`, argument list, no shell string).
3. Launch-time warning: one line from the engine when `days_left < 14` (reads `status --json`).
4. Docs.

About 150 production lines.

## Non-happy paths

| Case | Behaviour |
|---|---|
| HTTPS not enabled in the tailnet admin console | `tailscale cert` fails; exit 4 with its message and a docs link. |
| Machine name contains sensitive text | The CT disclosure prompt names the exact host that will be published; the operator can abort. |
| Operator uses their own CA cert | `tls status` works without Tailscale; `tls tailscale` is never needed. |
| Cert renewed but key permissions widened by another tool | `TlsHealth`/T01 refuse a world-readable key; status says so. |
| Running as a different user than the daemon | Ownership check fails; exit 5 naming the file. |

## Compatibility and rollout

New CLI verbs only; nothing changes for operators who never run them. Removing the settings
returns to HTTP-only.
