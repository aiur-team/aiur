## Chosen design

### One server module decides the target

PROPOSED `src/lib/aiur/build_order/conversation_link.ex`:

```elixir
defmodule Aiur.BuildOrder.ConversationLink do
  @type target :: %{conversation_id: String.t(), pos: pos_integer() | nil}
  @type reason :: :unjoinable | :not_found | :ambiguous | :unavailable | :repository_unavailable | :invalid_id

  # Which conversation belongs to this ticket. No anchor read.
  @spec conversation_id(id :: String.t(), unit_row :: {:ok, map()} | {:error, term()}, opts :: keyword()) ::
          {:ok, String.t()} | {:error, reason}

  # conversation_id/3, then the latest anchored pos (read at click time).
  @spec target(String.t(), {:ok, map()} | {:error, term()}, keyword()) :: {:ok, target} | {:error, reason}

  @spec path(target) :: String.t()   # "/conversations/conv_…" or "/conversations/conv_…?pos=40"
end
```

`opts` is the keyword list `DataSource.call/3` passes through; it carries test
seams only: `:history` (module, default
`Aiur.Conversation.History`) and `:configured_repo` (fun, default
`&Aiur.GitHub.Config.configured_repo/0`), the injection pattern C12-T01 uses.

**Which conversation (`conversation_id/3`).**

| Input | Result |
| --- | --- |
| `id` fails C3-T02's row-id rule, or starts with `pack:` | `{:error, :invalid_id}` |
| `{:ok, row}` with `%TrackerIdentity{}` and `Ref.worker/1` → `{:ok, ref}` | `{:ok, Ref.conversation_id(ref)}` — the live path, no I/O, same id the journal tee writes |
| `{:ok, row}` with no `%TrackerIdentity{}`, or one that is not joinable (`Ref.worker/1` → `:unjoinable`) | `{:error, :unjoinable}`. No fallback: contract §3 says an unjoinable identity has no conversation |
| `{:error, _}` (past ticket, or Index has no row), `configured_repo` → `{:ok, {o, r}}` | `History.resolve_worker(o, r, id)`: `{:ok, cid}` → `{:ok, cid}`; `:not_found` → `:not_found`; `{:ambiguous, _}` → `:ambiguous`; `:unavailable` → `:unavailable` |
| `{:error, _}` and `configured_repo` → `{:error, _}` | `{:error, :repository_unavailable}` |

**Which position (`target/3`).** After `conversation_id/3` succeeds:

| `History.list_anchors(cid, [])` | `pos` |
| --- | --- |
| `{:ok, anchors}` with at least one non-nil `pos` | `pos` of the **last** anchor in C5-T03's order (`event.observed_at`, then `event.event_id`) among anchors whose `pos` is an integer |
| `{:ok, []}`, or only `unanchored` anchors | `nil` → the page opens at its tail |
| `{:error, :unavailable}` | `nil` → the page opens at its tail and shows its own unavailable state |
| `{:error, :not_found}` | `{:error, :not_found}` (the conversation is gone or never existed) |

"Latest" means the newest event, in the same order the C5-T03 event list
shows, so the highlighted entry is the bottom item of that list.

### BuildLive and the payload (changes to C11-T07's code)

- **`chat` field** (in `build-ticket-control` and in C11-T01's `open-ticket`
  reply): `ConversationLink.path(%{conversation_id: cid, pos: nil})` when
  `conversation_id/3` is `{:ok, cid}`, else `null`. It no longer depends on
  `control`: a past ticket has `control: null` and may have a non-null
  `chat`. `TicketControl.encode/3` becomes
  `encode(row_or_error, control, writable?, chat)`: it takes the `chat` value
  as an argument instead of deriving it from the row; `chat_path/1` is
  deleted.
- **`open-conversation {id}`** keeps C11-T07's contract and changes only the
  target:

```elixir
def handle_event("open-conversation", %{"id" => id}, socket) when is_binary(id)
#   row = DataSource.call(source, :unit_row, [id])            # C11-T07; {:error, _} is fine here
#   case DataSource.call(source, :conversation_target, [id, row]) do
#     {:ok, target} -> {:noreply, push_navigate(socket, to: ConversationLink.path(target))}
#     {:error, _}   -> {:reply, %{v: 1, kind: "error", reason: "unavailable"}, socket}
#   end
def handle_event("open-conversation", _params, socket)       # C11-T07's fallback, unchanged
#   → {:reply, %{v: 1, kind: "error", reason: "invalid_params"}, socket}
```

  - Any other key in the params (for example `"path"`) is ignored. The path is
    built only on the server.
  - It is a read: no writable check, as today's `/chat` route.
  - The anchor is read at click time, not when the modal opened, so a ticket
    left open for an hour still opens at its newest event.
- **DataSource seam.** PROPOSED callback on `AiurWeb.Build.DataSource`
  (C3-T01), so BuildLive keeps C3-T01's seam rule:

```elixir
# trailing opts: the one DataSource.call/3 appends (C3-T01), as for unit_row/2
@callback conversation_target(id :: String.t(), unit_row :: {:ok, map()} | {:error, term()}, opts :: keyword()) ::
            {:ok, ConversationLink.target()} | {:error, ConversationLink.reason() | :not_wired}
@callback conversation_id(id :: String.t(), unit_row :: {:ok, map()} | {:error, term()}, opts :: keyword()) ::
            {:ok, String.t()} | {:error, ConversationLink.reason() | :not_wired}
```

  Default bodies: `{:error, :not_wired}` (so the button stays hidden, never a
  guessed link). `IndexSource` delegates to `ConversationLink`. The fixture
  source also delegates to `ConversationLink`, pointed at the fixture journal
  (see Verification), so the browser test runs the real resolution.
- **Seam (C3-T01 `seam_test.exs` rule 1).** Rule 1 scans
  `build_live.ex` **and** `lib/aiur_web/build/**/*.ex` and allows only
  `AiurWeb.Build.*`, `Aiur.BuildOrder.*`, `Aiur.BuildQueue`, `Aiur.AgentChat`

  `Aiur.Conversation.History`, `Aiur.TrackerIdentity` and
  `Aiur.GitHub.Config`, none of which is on it. So it lives at

### Invariants

1. The link target comes only from the server, from the journal's own
   identity (`Ref`) or index (`resolve_worker`). A display number alone never
   makes a conversation id.
2. No link is shown for a past ticket the journal index does not know. A
   hidden button is the honest state; a link to an empty or wrong page is
   not. A live row shows the button from its `Ref` (no I/O) before the tee
   has written; if the journal still does not exist at click time, the click
   gets the `unavailable` reply, never a page change (non-happy path "live
   row, no journal yet").
3. An unknown position is "no `pos`" (tail), never `pos=0`, `pos=1` or a
   remembered value.
4. No modal-side state changes on click; the page change is a
   `push_navigate`.

| Case | Input | Behaviour | Test |

| Transferred issue: two conversations claim the number | `resolve_worker` → ambiguous | `chat: null`, no button; never pick one | K6 |
| Unjoinable live row | `Ref.worker/1` → `:unjoinable` | `chat: null`; no `resolve_worker` call | K7 |
| Configured repository unreadable | `configured_repo` → `{:error, _}`, no row | `chat: null` | K8 |
| Conversation vanished between modal open and click | `chat` was set; at click `list_anchors` → `:not_found` | reply `unavailable`; title "Chat is unavailable for this ticket."; modal stays open | K9 |
| Live row, no journal yet | joinable row, the tee has not written; `chat` set from `Ref`; at click `list_anchors` → `:not_found` | as the row above; the next click after the tee writes navigates | K9, B4 |
| Journal index unreadable | `resolve_worker` → `{:error, :unavailable}` | `chat: null`; no guess | K8b |
| Cold index on the first past-ticket open | C2-T02's ETS cache is filled on the first `resolve_worker` call, inside the LiveView process | one slow `?ticket=` change after boot; later calls hit the cache. No timeout is added here (Interface note 7) | — (C2-T02) |
| Tampered event | `open-conversation` with `"path" => "/evil"` | ignored; navigates to the server path | K10 |
| Bad id | `pack:x`, `abc`, `../x` (strings failing C3-T02's `^[1-9][0-9]*$` rule) | reply `unavailable`; History not called | K11 |
| Bad params | `id: 5` (integer), no `id` | C11-T07's fallback clause: reply `invalid_params`; History not called | K11 |
| Read-only dashboard | `dashboard_writable: false` | still navigates (a read) | K12 |
| Anchor added while the modal is open | newer anchor `pos` 55 arrives after `open-ticket` | click goes to `?pos=55` | K13 |
| `pos` beyond head (writer behind) | anchor `pos` > `head_pos` | the page shows "Position not found" and the tail (MP-E4-C5-T03); nothing here | — (C5-T03) |
| Not authenticated | no credentials | `/conversations` is in the `:dashboard_auth` scope (C5-T01) | — (C5-T01) |
| Disconnect before the click lands | socket drops | LiveView rejoins; the click is lost; no partial navigation | — (LiveView) |

**Privacy.** `chat` and the reply carry only the conversation id path. No
entry body, anchor label, provider id or workspace path reaches the client.
The conversation page applies MP-E4's masking (C2-T01) itself.

## Decisions made without the owner

1. **"Latest anchor" is the newest anchored event** in C5-T03's order
   (`event.observed_at`, then `event_id`), skipping `unanchored` events,
   because only an anchored event has a position to jump to.
2. **No anchor, or anchors unreadable → open at the tail** with no `pos`. The
   page shows its own state; the link never carries an invented position.
3. **The target is computed on click**, not when the modal opens; the
   visibility (`chat`) is computed with the modal. A stale modal still lands on
   the newest event.
4. **Show the button on past tickets that have a journal.** This matches the
   design (J:1377, J:1392) and removes C11-T07's only allowlist entry. Past
   tickets without a journal keep no button; that is reported as a
   product-only difference, not added to the allowlist.
5. **Hide, do not guess, on ambiguity, unjoinable identity or an unreadable
   repository.** A wrong conversation is worse than none.
6. **Live tickets use `Ref`, past tickets use `resolve_worker`.** The live
   path needs no I/O and gives the id the tee writes; the index covers tickets
   that left the run. One module holds both rules (ponytail: one resolver).
7. **Complexity 2, not the row's 1,** because past-ticket support, the
   DataSource seam and the fixture journals are needed to match the design and
   to test without live data.
8. **`ConversationLink` lives in `lib/aiur/build_order/`.** C3-T01's seam rule
   1 forbids `Aiur.Conversation.*`, `Aiur.TrackerIdentity` and
   `Aiur.GitHub.Config` in `lib/aiur_web/build/`. Following C8-T04's
   `Aiur.BuildOrder.Index` precedent needs no allowlist change; four allowlist
   entries would weaken the scan for every later file.
9. **The "no journal at click" browser case uses a live row that never had a
   journal**, not a journal deleted during the test. It is the real case
   (the tee has not written yet), and the fixture server has no file-delete
   control.
