# MP-N2-C10-T01 — Instance HTTPS listener (RQ-TRANSPORT)

## Identity and outcome

- **Bucket / feature / chunk:** 3 mobile-watch / MP-N2 / MP-N2-C10 "Transport security (RQ-TRANSPORT, RC-15)".
- **User value:** a paired phone can load an instance dashboard in a WebView. iOS ATS and
  Android cleartext rules accept the origin, and the origin is a secure context, so the
  in-WebView microphone can work. Every N1, N3, N6 ticket that loads a dashboard depends on this.
- **Deliverable:** when `~/.aiur/machine` sets `transport.tls.{cert_file, key_file, bind_host,
  advertise_host}`, each instance daemon starts a **second listener** with `scheme: :https`
  on `bind_host`, port 0 (OS-assigned). It reports the bound HTTPS URL through a new
  `Aiur.HttpServer.device_url/0`. It reloads the certificate when the files change. The
  existing HTTP listener, `server.*` config and `base_url/0` are unchanged.
- **Non-goals:** obtaining a certificate (T03 or T04); the gateway listener (T02); writing the
  URL into the advert (MP-N2-C2-T01 reads `device_url/0`); device-token auth (MP-N2-C6).
  The ticket does not change `server.host` semantics or the Basic Auth rules.

  **both** options, because both produce a cert and key file. It is blocked only until the owner

- **Can run concurrently with:** MP-N2-C1, MP-N2-C2-T03/T04, MP-N2-C5, MP-N2-C10-T03/T04

## Chosen design

**Dual listener.** One endpoint, two Bandit listeners:

```elixir
# configure_endpoint/5 (proposed addition)
endpoint_opts =
  base_opts ++
    case Aiur.Machine.Transport.tls_listener(opts) do   # PROPOSED module, reads MP-N2-C3-T01 settings
      {:ok, %{ip: ip, certfile: c, keyfile: k}} ->
        [https: [ip: ip, port: 0, certfile: c, keyfile: k, cipher_suite: :strong]]
      :disabled -> []
      {:error, reason} -> log_tls_disabled(reason); []
    end
```

- `Aiur.Machine.Transport` (PROPOSED, `src/lib/aiur/machine/transport.ex`):
  `tls_listener/1 :: {:ok, map} | :disabled | {:error, reason}`, where `reason ∈
  {:cert_unreadable, :key_unreadable, :key_mode_too_open, :bind_host_invalid,
  :advertise_host_missing}`. `:disabled` when any of the four keys is null, or
  `mobile.enabled` is false.
- `Aiur.HttpServer.device_url/0` (PROPOSED): `"https://#{advertise_host}:#{port}"` when
  `Bandit.PhoenixAdapter.server_info(Endpoint, :https)` returns a port, else nil. `base_url/0`
  is unchanged.
- **Credential guard on the HTTPS listener.** Same rule as `guard_dashboard_credentials/3`, with
  one addition: on a non-loopback `bind_host` the HTTPS listener starts if Basic Auth is
  configured **or** `mobile.enabled` is true (the device-token plug, MP-N2-C6, then authenticates;
  the dashboard plug still fails closed without a credential). If neither, the HTTPS listener is
  not configured; the HTTP listener behaves exactly as today.
- **Failure isolation.** Any TLS problem drops only the HTTPS key and logs one error naming the
  reason. It never prevents the HTTP listener or the daemon from starting.
- **Origin allowlist.** `allowed_origins/1` adds `{"https", advertise_host, https_port}` when
  `device_url/0` is non-nil. Nothing else changes in `verify_same_origin/2`.
- **Certificate reload.** `Aiur.Machine.TransportWatcher` (PROPOSED GenServer, started only when
  the HTTPS listener is configured) polls the cert and key mtimes every 60 s. On change it
  validates that both files parse (`:public_key.pem_decode/1`) and that the key matches the cert,
  then calls `:ssl.clear_pem_cache()`. New TLS handshakes use the new files; existing connections
  keep theirs. A failed validation keeps serving the old cert and logs `tls_reload_rejected`.
- **Invariants.** `base_url/0` output is byte-identical to today for every config. The HTTPS
  listener never binds when `mobile.enabled` is false. No secret (key content, path of the key is
  fine) appears in logs.

## Non-happy paths

| Case | Behaviour |
|---|---|
| Cert or key missing or unreadable | HTTPS off, one error log with the reason; `device_url/0` nil; advert shows `reachable_for_devices: false, reason: tls_unavailable` (MP-N2-C2). |
| Key file mode too open | HTTPS off, reason `key_mode_too_open` (never serve a world-readable key). |
| `advertise_host` not in the cert SAN | The listener starts (the server cannot know every name a client uses); `aiur mobile status` reports `tls_name_mismatch` (T02). Phones fail with `tls_name_mismatch` (MP-N1-C5). |
| Cert expired | The listener starts; status reports `tls_expired`; phones fail closed. |
| HTTPS port conflict | Cannot happen with port 0; a bind error on `bind_host` (address not on this host) logs `bind_host_unavailable` and drops HTTPS only. |
| Renewal writes key before cert | The watcher's key/cert match check fails, keeps the old pair, retries next tick. |
| Daemon restart | New OS port; the advert and registry carry the new URL; the phone re-resolves by `instance_id`. |
| Mobile disabled later | Takes effect at next instance start; documented. |

## Compatibility and rollout

- Off by default: `transport.tls.*` are null in a fresh `~/.aiur/machine`, and `mobile.enabled` is false.
- No `.aiur/config` key is added, so `scripts/check-config-docs.py` is unaffected; the
  `~/.aiur/machine` keys are documented under MP-N2-C3-T05's checker.
- Rollback: delete the `transport.tls` values; the next restart has HTTP only.
- Plan refresh: after MP-R1-C6 (web-shell split) the HTTP server and router move into the
  web-shell package; the change moves with them.

   *Fails without:* guards against a change of `base_url/0` (would fail if the implementer switched the existing listener).
4. `"non-loopback bind_host without basic auth and mobile disabled: no https listener"`.
   *Fails without:* the extended credential guard.
5. `"unreadable key: http listener still binds, https dropped with reason"` (`capture_log` asserts
   `key_unreadable`). *Fails without:* the failure-isolation branch (an exception would kill start).
6. `"world-readable key is refused"` (`File.chmod(key, 0o644)`). *Fails without:* the mode check.
7. `"device origin is allowed for api_write"` in `src/test/aiur_web/router_device_origin_test.exs`

   watcher `:tick`, a new handshake presents the new serial. *Fails without:* the
