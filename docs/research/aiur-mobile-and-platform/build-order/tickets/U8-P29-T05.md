## Implementation steps

1. PR 1 (tests only): the three test splits. Add each support module with
   `Code.require_file` in `test_helper.exs`.
2. PR 2: move `Staleness`, `Reload`, `Checkpoint`. In moved code, replace every
   `__MODULE__` that means the parent (for example a log prefix or a struct) with the
   parent's literal module. Parent functions call the new modules directly; no public
   API change.

## Non-happy paths

- **Key identity:** `@cache_key __MODULE__` and `@global_pause_key` must stay in
  `SnapshotStore`. Code moved to a sub-module must not evaluate `__MODULE__` for a
  key, or readers would see a cache miss and report stale/unavailable. `Staleness`
  takes no key.
- **Corrupt checkpoint:** `Checkpoint` keeps `quarantine_corrupt` and the checksum
  check (`:352-396`); a corrupt file is quarantined, not deleted, and the health
  value stays degraded. Tests in `progress_retention` suites guard this.
- **Fsync on first write:** `sync_filesystem_when_first_write` (`:252`) moves with
  the writer. Do not drop it.
- **Membership store test is synchronous** (`async: false`); both halves keep it,
  because they share a temp directory pattern.
