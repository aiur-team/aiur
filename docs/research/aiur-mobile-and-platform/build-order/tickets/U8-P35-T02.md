## Implementation steps

1. Create the support files; add them to `test_helper.exs` (`Code.require_file`) and
   to `mix.exs` `test_ignore_filters`.
2. Move each topic block with its `alias` lines and `setup` into its file. Keep
   `use Aiur.TestSupport` (and `async` as the base file had it).
3. Delete the two old files in the same PR.
4. Count tests: `grep -c '^\s*test "'` over the new files equals 72 and 25.
5. `git grep -n "core_test.exs\|extensions_test.exs"` in docs and CI; update any
   reference (for example a CI shard list or `mix aiur.affected_tests` mapping).

## Non-happy paths

- **Module name clash:** fakes defined inside the old test modules become top-level
  support modules; give them unique names (`Aiur.CoreTestSupport.RetryPollFailingGitHubClient`).
- **Setup order:** `extensions_test.exs` has two `setup` blocks; each topic file
  gets both, in order, unless the topic does not use the endpoint (then keep only
  the first and say so in the PR).
- **Hidden coupling:** a test that passed only after an earlier test in the same
  file ran will fail alone. Run each new file alone once (`mix test <file>`).
- **Shared ports:** the HTTP and dashboard tests bind an endpoint; keep
  `async: false` where the base was not async.
