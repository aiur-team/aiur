## Chosen design

### Server: one shared helper, two LiveViews

PROPOSED `AiurWeb.OperatorControlCenter.OperatorSend` (moved code, same
validation and error handling):

```elixir
@type composer :: %{tracker_identity: TrackerIdentity.t() | nil, target_key: String.t(),
                    issue_identifier: term(), writable_target?: boolean()}
@type pending :: %{optional(String.t()) => {String.t(), String.t()}}   # key => {message_id, text}

def target(composer)               # was agent_log_target/1
def key(composer)                  # was agent_log_key/1
def message_id(pending, key, text) # was message_id_for_send/3, unchanged rule

@spec send(composer, String.t(), pending) ::
        {:ok, request_id :: integer(), message_id :: String.t(), pending}
        | {:error, reason :: term(), message_id :: String.t(), pending}
def send(composer, text, pending)
# text is already trimmed by the caller; "" -> {:error, :empty_message, nil, pending}
# {:ok, id}                -> pending without key
# {:error, {:outcome_unknown, _}} -> pending with key => {message_id, text}
# {:error, other}          -> pending without key

@spec delivery_status(integer(), timeout()) :: {:ok, atom()} | {:error, term()}
def delivery_status(request_id, timeout)   # Endpoint.config(:agent_chat_delivery_status_fun) or AgentChat.delivery_status/2

@spec transcript_id(integer()) :: String.t()
def transcript_id(request_id), do: Aiur.LiveConversation.Source.opaque_id("message:", "operator:#{request_id}")
```

`send/3` keeps the `:agent_chat_send_fun` arity-3/arity-2 seam exactly. The
caller decides what to do with the result; the helper owns the #2717 rule.
`DashboardLive.send_operator_message/4` becomes: call `OperatorSend.send/3`,
assign the returned `pending`, then `clear_chat_state` on `:ok` or keep the draft
and `put_chat_error` on `:error` (keeping the draft only for `outcome_unknown`,
as today). The empty-text clause at `:2712` stays in `DashboardLive` so the
drawer still ignores an empty submit silently.

### Server: the `send` event in BuildLive

Event `send` with params `%{"id" => id, "text" => text}` (C3-T02 "Client →
server events" lists `send` under C11-T06; the request id is the server's
answer, not a client input).

1. Validate: `id` passes C11-T01's `ticket_id/1` (`^[0-9]{1,10}$`, value > 0)
   and `text` is a binary, else reply `Payload.error(:invalid_params)`
   (`%{v: 1, kind: "error", reason: "invalid_params"}`). A fallback clause
   `handle_event("send", _params, socket)` after the guarded one replies the
   same (C3-T02 shared rule).
2. Re-check `socket.assigns.writable and dashboard_writable?()` inside the event
   (C3-T02 shared rule; `dashboard_live.ex:2683` pattern). Fail → reply
   `Payload.error(:read_only)` and assign `writable: false`.
3. Resolve the composer from C11-T03's `conversation_composer` assign. It must be
   for this `id` and non-nil, else reply `kind: "send", ok: false, reason:
   "no_running_agent", message: "Agent is no longer running."`. A composer with
   `writable_target?: false` → `reason: "ambiguous_identifier"` with the
   `format_error` copy. The client never names the target.
4. `OperatorSend.send(composer, String.trim(text), socket.assigns.send_pending)`.
   Assign the new `pending`. The call is synchronous, as in the drawer today
   (`AgentChat.send/3` is bounded by the 5 s call timeout plus one lookup).
5. Reply:
   - accepted: `%{v: 1, kind: "send", ok: true, id, request_id, entry_id:
     transcript_id(request_id), text: trimmed, at: now_ms}` and start the poll;
   - error: `%{v: 1, kind: "send", ok: false, id, reason: reason_tag,
     unknown: boolean, message: copy}`, where `reason_tag` is a fixed string
     for known reasons (`outcome_unknown`, `not_queued`, `no_running_agent`,
     `empty_message`, `message_too_long`, `max_concurrent_agents_reached`,
     `globally_paused`, `unavailable`, `timeout`, `ambiguous_identifier`) and
     `"error"` for anything else (including `{:message_id_conflict, _}`).
     `copy` is `AgentLogModal.format_error(reason)` for a known tag and the
     fixed string "Send failed. Check the log before you send again." for
     `"error"`, because `format_error/1`'s catch-all returns `inspect(reason)`
     (`agent_log_modal.ex:145`). `unknown` is true only for `outcome_unknown`.
     The raw term never reaches the client (EC-30). `globally_paused` is kept as
     a defensive mapping only (the send path does not return it today).
   - Both reply shapes and the `send-status` push are new message kinds, so
     their `Payload` validator clauses and fixture mapping land in this PR
     (C3-T02 "Extension rule").

### Server: bounded delivery poll

Assign `:send_tracking`, `%{id => request_id}` (only the latest send per ticket
is tracked). After an accepted send:

- Schedule `{:send_status_poll, id, request_id, 0}` with
  `Process.send_after/3` at the first delay of `@send_status_delays_ms
  [500, 1_000, 2_000, 4_000, 8_000, 15_000, 30_000]` (about 60 s in total;
  overridable through `Application.get_env(:aiur, :build_send_status_delays_ms)`
  for tests; app env is global, so those tests run `async: false` and restore
  the value in `on_exit`).
- On the message, if `send_tracking[id] == request_id`, `start_async({:send_status,
  id, request_id, n}, fn -> OperatorSend.delivery_status(request_id, 1_000) end)`.
  Otherwise drop it (a newer send replaced it, or the modal closed).
- `handle_async` maps the result like `agent_control_cli.ex:1446–1466`:
  - `{:ok, s}` with `s in [:delivered, :consumed]` → push `send-status`
    `%{id, request_id, status: "delivered"}`, stop;
  - `{:ok, s}` with `s in [:failed, :superseded]` → push `status: "failed" |
    "superseded"`, stop;
  - `{:ok, :pending}` → push `status: "queued"` once (first time only), schedule
    the next delay;
  - `{:error, _}` or an `{:exit, _}` async result → schedule the next delay with
    no push (an unreadable status proves nothing);
  - no delay left → push `status: "unconfirmed"`, stop.
- C11-T03's `conversation-close {id}` or an `open-ticket` for another id drops
  `send_tracking[id]` (the modal close itself sends nothing; C11-T01).

The poll never claims delivery from a timeout, an error or the transcript echo.

  `ctx.push("send", { id: t.id, text: ta.value })`.
  - `ok: true` → if `ta.value` still equals the sent value, clear it and reset
    the height; scroll the log to the bottom (J:1494); `fx.appendItem({ id:
    reply.entry_id, k: "op", text: reply.text, at: reply.at })` (C11-T03 entry
    shape: `id` becomes `data-eid`); mark the new row `data-op-local` and push
    `{ el, text: reply.text }` onto the module's `localOps` list for this ticket;
    show `cv-in-st` "Queued" only when the first `send-status` says `queued`.
  - `ok: false` → keep the draft; show `reply.message` in the line, `bad` for a
    known failure, muted for `unknown: true`.
  - Promise rejected or no reply in 15 s (disconnect during the send) → keep the
    draft; muted line: "No answer from the dashboard, so the message may still be
    queued. Check the log before you send again."
  - Always re-enable the button afterwards.
- **`send-status`** (only for the open ticket and the last `request_id`):
  `queued` → muted "Queued · waiting for the agent"; `delivered` → hide the line;
  `failed`/`superseded` → bad "Not delivered (failed)" / "Not delivered
  (superseded)"; for `failed` only, put the sent text back into the textarea if
  it is empty (a superseded item was replaced by a newer queue item,
  `agent_queue_store.ex:279–300`, so restoring it invites a duplicate);
  `unconfirmed` → muted "Queued · delivery unconfirmed".
- **No optimism.** No local op row before `ok: true`; no state flip to active;
  no typing indicator; no mock reply. The paused → active change and the typing
  indicator come from server diffs (C11-T05, C11-T07).
- **Echo de-duplication.** The transcript later delivers the same message.
  - Remote worker (projection entry): its `id === reply.entry_id`, so C11-T03's
    `appendEntries` replaces the local row in place.
  - Local worker (`agent.ndjson` entry, id `gen:offset`): composer.js sets
    `fx.claimLocalOp(entry)`. For an incoming `k: "op"` entry it returns the
    oldest `localOps` element whose text equals `entry.text`, or whose text
    starts with `entry.text` minus a trailing `"\n..."` (the 1 600-character
    cut), removes it from the list, and returns `null` when none match.
    `appendEntries` replaces that element with the transcript row. The list is
    cleared through `onModalClose`. See Interface notes 3.
- **Drafts.** A per-ticket draft map in module state (`onReset` clears it on
  mount, C9-T01 rule 3), so closing and reopening the modal keeps an unsent
  draft for the life of the page. The server keeps only the pending message id.
- **Disabled states (EC-12, EC-06).** Read-only dashboard (`writable: false`) or
  past ticket → no form (the `.cv-end` footer from C11-T03 stays). Writable but
  `writable_target?: false` → the form is replaced by a `.cv-end` row with the
  drawer's copy "Agent actions are unavailable because this display identifier
  is not a unique writable target." (`agent_log_modal.ex:60–62`,
  `conversation_drawer.ex:248–250`). Socket offline
  (`ctx.offline.isLive()` false, C8-T03) → textarea stays editable, send button `disabled`,
  muted line "Offline · reconnect to send". The agent ends while the modal is
  open (C11-T03 state `:ended`) → the send button is disabled and the line says
  "Agent is no longer running."; the draft stays so it can be copied; the next
  open shows `.cv-end`.
