# U5-T02 - One trust snapshot

> Answers the "U5 (KTD9 single CODEOWNERS trust snapshot)" pseudo-predecessor
> of MP-R2-C2-T02 (RC-21: U5 first). The snapshot becomes the default
> `TrustClassifier` implementation there.

## Identity and outcome

- Bucket 1, prior unit U5 (KTD9).
- **User value:** when GitHub team lookup fails, a person who cannot be
  verified gets no command authority and no place in the agent's digest; the
  Executor still sees their sanitized comment and an attention with cause and
  age so they can fix access.
- **Deliverable:** `Aiur.GitHub.CodeOwners` is the only trust authority. One
  CODEOWNERS parser, one team resolver (`Aiur.GitHub.Teams`), a snapshot with
  `degradation: %{cause, observed_at}`; `Aiur.Codeowners` keeps per-path
  ownership but calls the shared parser and reader and returns unknown on
  incomplete context.
- **Non-goals:** no new process or service; no change to who is configured
  as trusted; no dashboard page.

## Dependencies and blockers

- U0-T01; U5-T01 (paginated PR-files reader).
- Read `website/docs-app/apis/github.md` first.

## Verified starting point (`58854d4c8`)

- `github/code_owners.ex:473-485` `resolve_team` turns **any error into `[]`**;
  `do_refresh` (:181-238) then reports `trust_source: :file, degradation: nil`
  (:202); when neither configured accounts nor the owner resolve it keeps the
  previous allowlist (:224-235).
- Two grammars: `code_owners.ex:399-453` (every token after the pattern must
  contain `@`, :439-440; a trailing `# comment` makes the file `:unparseable`)
  vs `codeowners.ex:340-375` (drops trailing comments, :360; rejects `!` and `[`
  patterns, :373-374). `code_owners.ex:395-396` already calls
  `Aiur.Codeowners.file_path/standard_paths`.
- Two team readers: `codeowners.ex:409-456` caches in the **process
  dictionary** (:412-416) and reads one unpaginated page (:436);
  `github/teams.ex:25-41` paginates but fails the whole lookup on any page error.
- Snapshot `trust_snapshot_map` (:322-330) has no cause or age.
- Path authority returns nil/unknown on error (`codeowners.ex:113`); on a missing
  file delegates to the server, falling back to `false` (:279).
- Consumers: `events/sanitizer.ex:192-208` sets `author_trusted?` from
  `CodeOwners.allowed?` (false if the process is absent);
  `events/pr_command_scanner.ex:122-123`, `agent_runner/events_digest.ex:66-80`
  read that flag. `run_telemetry/github_enricher.ex:291-309` has a **separate
  fallback allowlist** when the trust server is absent.
- Repository owner fallback: `Aiur.GitHub.Config.repo/0` (explicit
  `tracker.github.repo` or checkout origin).

## Chosen design

- **Parser:** keep `codeowners.ex:340-375` (handles comments) as the one
  grammar; `code_owners.ex` calls it. Delete `code_owners.ex:399-453`.
- **Teams:** `Aiur.GitHub.Teams` is the one reader. Delete
  `codeowners.ex:409-456` (and its process-dictionary cache). A failed team
  lookup returns `{:error, cause}`; `CodeOwners` records it as
  `degradation: %{cause: {:team_lookup_failed, team, reason}, observed_at}`
  and adds **no** members from that team (neither positive nor negative fact).
- **Fail-closed (KTD9):** trusted = configured trusted/daemon accounts ∪ repo
  owner (from `Config.repo/0`) ∪ members of teams that resolved in *this*
  refresh. Stale membership from a previous refresh is not kept for new
  comments. Unknown authors → `author_trusted?: false`.
- **Visibility:** on degradation, one `Aiur.Alerts` alert
  `codeowners_trust_degraded` with cause and age; the snapshot exposes both for
  `aiur status`/dashboard. Sanitized bodies stay in Executor logs/dashboard
  (unchanged); the digest keeps excluding untrusted bodies (unchanged).
- **Enricher:** `github_enricher.ex:291-309` uses the same configured set
  (configured ∪ owner) when the server is absent - no extra bot/daemon list
  unless those accounts are already configured; check and record.
- **Path authority:** incomplete PR-files or team context → `:unknown`
  (`nil`), never a smaller authoritative set.

## Non-happy paths

- **Absent or empty CODEOWNERS:** today's fallback (configured set + owner,
  `:fallback`, alert) stays; test it.
- **Origin unavailable and no explicit repo:** owner fallback contributes
  nothing; degradation cause says so.
- **Trust process absent:** sanitizer gives false (unchanged); enricher uses
  the configured set.
- **Previously trusted member now unresolved:** denied, visible cause.

## Compatibility and rollout

Behaviour change: during a team-lookup failure, team-only members lose
command authority until the next successful refresh. This is KTD9's intent;
docs say it. No config change. Rollback: revert.
