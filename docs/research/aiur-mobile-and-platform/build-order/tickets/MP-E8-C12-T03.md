## Chosen design

**Delete by a mechanical rule, in two steps, with nothing redesigned.**

1. **A symbol is dead when no route renders it and no client can emit its event.**
   Proof is a grep, written into the PR body: for a component, no `lib/` caller;
   for an event, `grep -rn '"<event>"' src/lib src/priv/static` finds only the
   `handle_event` clause itself. This one grep covers `phx-*` attributes, the
   literal `pushEvent` names in `priv/static/*.js` **and** in the inline hooks of
   `layouts.ex`, and `close_event="<event>"` attributes that the drawer and
   ticket-context hooks push as `this.closeEvent`. A grep of `priv/static/*.js`
   alone misses the inline hooks.
2. **Part A deletes only code that is dead today** (proved above at
   `58854d4c8`). It has no rollout risk: no user page renders it.
3. **Part B deletes the Units board only after one release has carried the
   rollback route and the owner has accepted the GUI features that go with it
   (D10).** Once `/units` and `/chat` no longer mount `DashboardLive, :index`,
   the whole `:index` board is dead and goes by rule 1 (B5). Then `/units` becomes a `301` redirect to `/` (plus its
   query string, so a bookmarked `/units?v=1&scope=…` reaches BuildLive's legacy
   preset mapping from C3-T03). It reuses the `CommandsRedirectController`
   pattern (`controllers/commands_redirect_controller.ex:8-18`).
4. **Tests that guard live code move; tests that guard dead code go.** After
   Part B no product route renders the Units drawer, so its browser tests guard
   dead code. They go, except where the same live code (the voice controller)
   has no other browser test; then they move (B6).
5. **The drawer notice states what is true.** New `@participation_notice`:
   `"You can read this conversation here. Sending is not available."` The
   footer lines that already exist (`conversation_drawer.ex:247-250`) give the
   reason. The moduledoc says the drawer shows the conversation and carries the
   composer when the dashboard is writable and the target is unique.

Invariants:

- No live route changes its rendered output in Part A, except the one drawer
  notice string.
- No `Units*` module named in the non-goals loses a public function.
- An unknown nav count still renders no badge (never `0`).
- Every event handler that is deleted has no emitter (rule 1).

## Non-happy paths

- **A stale browser tab on the old page.** Part A: no page ever rendered the
  fleet markup, so no tab can send `toggle-fleet-filter`. Part B: a tab still
  open on `/units` reconnects after deploy, the route is now a controller, and
  LiveView does a full reload, which follows the `301` to `/`. Nothing is
  written, so nothing is lost. The draft in an open Units composer is lost; the
  same is true of any deploy today. Test B-R2 below covers the redirect.
- **A client sends a deleted event to a live DashboardLive** (`/commands`).
  `DashboardLive` has no catch-all `handle_event/3`, so an unknown event raises
  `FunctionClauseError` and the LiveView process restarts and remounts. Before
  deleting a handler, rule 1 proves no markup or hook sends it. In Part A the
  malformed-events test keeps `filter-decisions` and `show-agent-log`, which
  still exist. If B5 deletes `show-agent-log`, Part B drops that line too and
  keeps the test with `filter-decisions`.
- **Bookmarks with Units query strings.** `/units?v=1&scope=…&conditions=…`
  redirects with its query to `/`, where C3-T03's `URLState.legacy_preset/1`
  maps it. Unknown or invalid params fall to the home default (EC-26, owned by
  C3-T03 and C12-T01).
- **Read-only dashboard.** The redirect does not need write access; it is in the
  `:dashboard_auth, :browser` scope like `/decisions`. Auth is unchanged.
- **Unknown counts.** Part B must not route the nav badge through a new default.
  `put_nav_count/3` already drops a non-integer; test B-N1 guards it, and also
  guards B3's change to the Units selection (if B3 stops projecting
  `units_view`, the badge disappears and B-N1 fails).
- **Unauthenticated `/units`.** The redirect sits behind `:dashboard_auth`, so
  an unauthenticated request gets `401`, not a `301` that reveals nothing but
  still skips auth. Test B-R3.
- **Concurrency, retries, idempotency, privacy.** Not relevant: the ticket adds
  no state, no I/O and no new data path. The drawer still shows only the
  sanitized snapshot (`presenter.ex:4-9`).
