## 4. Chosen design

### 4.1 Command

```text
aiur history export [--unsorted] [--after <n>] [--limit <k>] [--json]
```

- `export` is the only subcommand. Any other word, or none, is exit 64 with
  `aiur: history: unknown subcommand '<x>'; expected 'export'`.
- `--unsorted`: only tickets whose resolved epic is `unsorted` with source
  `default` (no feature, no override, no matching label). A ticket that
  C13-T04 has already classified (`backfill-agent` override, or a feature
  membership) has another source, so it drops out. Re-running the export is
  how the agent run resumes.
- `--after <n>`: only tickets with number greater than `n`. Default 0.
  A non-negative integer; else exit 64.
- `--limit <k>`: at most `k` tickets, 1..500. Default 200. Else exit 64.
- `--json`: one envelope (§4.2). Without it: human text (§4.4).
- Tickets are in ascending number order. `data.next_after` is the last number
  in this page when more match, else `null`.

Engine (PROPOSED `cmd_history` in `aiur-engine.sh`):

```bash
cmd_history() {
  local sub="${1:-}" json=0 unsorted=0 after=0 limit=200 arg
  [ "$sub" = "export" ] || { echo "aiur: history: unknown subcommand '${sub}'; expected 'export'" >&2; exit 64; }
  shift
  while [ "$#" -gt 0 ]; do
    arg="$1"
    case "$arg" in
      --json) json=1 ;;
      --unsorted) unsorted=1 ;;
      # Guard before shift: the engine runs under `set -e` (`:24`), and a bare
      # shift past the last argument would exit 1 instead of the usage exit 64.
      --after) [ "$#" -gt 1 ] || { echo "aiur: history export --after requires a value" >&2; exit 64; }; shift; after="$1" ;;
      --after=*) after="${arg#--after=}" ;;
      --limit) [ "$#" -gt 1 ] || { echo "aiur: history export --limit requires a value" >&2; exit 64; }; shift; limit="$1" ;;
      --limit=*) limit="${arg#--limit=}" ;;
      *) echo "aiur: history export received an unknown option: $arg" >&2; exit 64 ;;
    esac
    shift
  done
  case "$after" in '' | *[!0-9]*) echo "aiur: history export --after needs a non-negative integer" >&2; exit 64 ;; esac
  case "$limit" in '' | *[!0-9]*) echo "aiur: history export --limit needs an integer from 1 to 500" >&2; exit 64 ;; esac
  # Compare as numbers only after the digit check, so "08" or a 30-digit value cannot reach arithmetic.
  if [ "${#limit}" -gt 3 ] || [ "$((10#$limit))" -lt 1 ] || [ "$((10#$limit))" -gt 500 ]; then
    echo "aiur: history export --limit needs an integer from 1 to 500" >&2; exit 64
  fi
  [ "${#after}" -le 10 ] || { echo "aiur: history export --after needs a non-negative integer" >&2; exit 64; }
  run_control_rpc "Aiur.AgentControlCLI.history([action: :export, json: $( [ $json -eq 1 ] && echo true || echo false ), unsorted: $( [ $unsorted -eq 1 ] && echo true || echo false ), after: $((10#$after)), limit: $((10#$limit))])"
}
```

No user string reaches the RPC expression: every value is a checked integer or
a literal boolean, so no base64 encoding is needed.

Dev shim (`scripts/aiurdev:115`): add `history` to the read-only list, next to
`build-orders`:

```bash
    ask | asks | usage | commands | units | build-orders | history | analytics | github-cost | github-usage) return 1 ;;
```

It is not added to `pure_control_command` (`:504`), the same as
`build-orders`: in its own checkout a stale release is rebuilt first, so the
export runs the code that matches the sources.

### 4.2 JSON envelope

```json
{"schema_version": 1, "page": "history-export",
 "snapshot": {"captured_at": "2026-11-02T10:00:05Z"},
 "request": {"unsorted": true, "after": 0, "limit": 200},
 "sources": {
   "history":        {"state": "available", "observed_at": "...", "age_ms": 5000, "freshness": "current", "partial": false, "reasons": []},
   "epic_overrides": {"state": "available", "observed_at": "...", "age_ms": 0, "freshness": "current", "partial": false, "reasons": []},
   "features":       {"state": "available", "observed_at": "...", "age_ms": 0, "freshness": "current", "partial": false, "reasons": []},
   "issue_bodies":   {"state": "partial", "held": 37, "of": 200, "retention_hours": 72}
 },
 "data": {
   "tickets": [ { …record… } ],
   "next_after": 412,
   "matching_total": 1207,
   "unresolved_total": 0
 },
 "auxiliary": {
   "untrusted_fields": ["title", "labels", "body.excerpt"],
   "not_held": {"pr_files": "no Aiur store keeps pull-request file lists"}
 }}
```

- `matching_total`: every History row that passes the filter, over all pages.
  It does not change between pages of one run unless the stores change.
- `unresolved_total`: rows whose resolver source is `"unknown"` (an input was
  `:unknown`, C5-T02 §4.2 `gaps`). With `--unsorted` they are not in
  `tickets`, because the export cannot say whether they are unsorted. They are
  counted so they are never lost silently. Without `--unsorted` they are in
  `tickets` with `epic.source: "unknown"`.
- `issue_bodies.state`: `"available"` when every exported record has a body,
  `"partial"` when some do, `"none_held"` when none do. `held` and `of` count
  this page only.
- `sources.*` entries for the three stores use the `BuildOrdersCLI` shape
  (`build_orders_cli.ex:232-255`), so `observed_at`, `age_ms` and `freshness`
  come from each store's `ProviderHealth`.

### 4.3 Ticket record

```json
{"number": 412, "state": "closed", "state_reason": "completed",
 "title": "Fix the stale badge on reconnect",
 "labels": ["bug", "complexity:2"],
 "labels_complete": true,
 "epic": {"key": "unsorted", "source": "default"},
 "feature": null,
 "pr_number": 415,
 "body": {"excerpt": "…", "truncated": true, "observed_at": "2026-11-01T09:00:00Z", "age_ms": 90005000},
 "observed_at": "2026-11-02T09:59:00Z",
 "unknown": []}
```

The rule for missing facts (AGENTS.md "unknown is never zero"):

| History value | JSON |
| --- | --- |
| a value | the value |
| `:none` (known absent), for `pr_number` and `state_reason` | `null` |
| `:unknown` (never observed), for `title`, `labels`, `labels_complete`, `pr_number`, `state`, `state_reason` (C4-T01 `Lifecycle` reasons include `:unknown`) | key **absent**, and the field name is in `unknown` |
| held REST map with `"body" => nil` (GitHub's empty description) | `body: {"excerpt": "", "truncated": false, observed_at, age_ms}`; counts as held. Known empty is not unknown |
| body not held by ResourceStore, held map without a `"body"` key, a non-binary body, or sanitiser `:error` | key `body` absent, `"body"` in `unknown` |

The special cases run **before** `JSONSafe.normalize/1`: it turns the atom
`:unknown` into the string `"unknown"` and `:none` into `"none"`
(`json_safe.ex:16`), which would reach the agent as a real title or reason.

- `feature` is the owning feature slug, or `null` when `Features.snapshot/1`
  answered `{:ok, …}` and the ticket has no owner. It is never unknown in a
  record, because an unavailable feature store fails the whole command (§6).
- `state` is `lifecycle.state` (`open`, `closed`); `state_reason` is the
  lifecycle reason (`completed`, `not_planned`, `duplicate`, `reopened`; `:none`
  is `null`) (C4-T01 §3 "Lifecycle facts", `Lifecycle` reasons).
- `labels_complete` is the C4-T01 row field (false when the issue has more than
  100 labels). The resolver already treats `false` with no match as source
  `unknown` (C5-T02 V-16); the record carries it so the agent knows the label
  list is cut.
- `title`: `sanitize_projection(title, 256, redact_urls: true,
  redact_environment: true)` (GitHub titles are at most 256 characters).
- `labels`: each label through `sanitize_projection(label, 100, …)`, then
  sorted. A label that sanitises to `""` is dropped.
- `body.excerpt`: `sanitize_projection(body, 1_600, input_byte_limit: 262_144,
  redact_urls: true, redact_environment: true)`. `truncated` is the returned
  flag. `observed_at` and `age_ms` come from `fetched_at_ms` and the injected
  clock.

### 4.4 Human output

```text
history export: 200 of 1207 matching (unsorted), next --after 412
sources: history current (age 5s) · overrides current · features current · bodies held 37/200 (72 h retention)
unresolved (an input unknown): 0
#401  closed  unsorted/default  body: held   pr #403  Fix the stale badge on reconnect
#402  closed  unsorted/default  body: unknown pr none  Tidy docs
#405  open    unsorted/default  body: unknown pr unknown  (title unknown)
```

- Each source prints its age from `observed_at` (`history current (age 2h
  3m)`), so an old observation never reads as fresh (AGENTS.md "If a surface
  computes an age, it renders the age"). C4-T01 §4.4 has no `:stale` History
  state today; the shared `freshness/1` mapping still prints `stale` if one is
  added.
- Every printed title is the sanitised title, so it holds no ESC or other
  control character (EC-30). The sanitiser keeps `\t` and `\n` (§3.4), so the
  human row also replaces each run of whitespace with one space; one ticket is
  always one line. JSON keeps the sanitised text as is.
- `pr none` is `:none`; `pr unknown` is `:unknown`. They never print the same.

cannot render one differently. Both modules are read only. They own no state
and no process.

## 10. Decisions made without the owner

1. **Bodies come only from ResourceStore's held `:issue` bodies.** The row
   says "body excerpt and PR files per ticket from the History store", but
   C4-T01's History row has neither field (C4-T01 §4.1). Adding a body to
   History would grow its file (1,600 chars × 10k rows ≈ 16 MB against C4-T01's
   size cap) and change C4-T02's census, which already ran. The row's other
   rule, "no new GitHub reads", wins. A missing body is reported, not hidden.
   If C13-T00 shows the agent needs bodies for accuracy, C13-T04 reads them
   on the agent budget.
2. **No PR file lists.** No store holds them (§3.3). The envelope says so once
   in `auxiliary.not_held`, not as an always-unknown field in every record.
   `pr_number` is exported so the agent can read files itself if C13-T00
   accepts the cost.
3. **Pages of at most 500 (default 200) with an `--after` cursor.** The RPC
   timeout is 10 s and the engine holds the whole output in one shell variable
   (§3.1). A single 10k-ticket export would be about 20 MB. Pages also give
   C13-T04 a natural per-run budget unit.
4. **`--unsorted` means resolver key `unsorted` and source `default`.** Rows
   with source `unknown` are counted, not exported, under `--unsorted`, so a
   store gap never makes a classified ticket look unsorted.
5. **Fail closed when any of the three stores is unavailable, or History is
   incomplete.** The export feeds a write job. A partial list would make the
   agent skip tickets or reclassify ones it cannot see as overridden. Bodies
   are optional input, so a missing ResourceStore only marks bodies unknown.
6. **Sanitise with `TicketDetail.Sanitizer.sanitize_projection/3`, 1,600-char
   excerpt, URLs and `ENV=value` redacted** — the same settings as
   `LiveConversation.Normalizer` (§3.4). URL redaction loses some
   classification signal; security is not cut (ponytail).
7. **The page logic is a function, `Export.page/1`; the tool is C13-T04's.**
   An agent workspace cannot reach the daemon through the CLI (§3.5), and
   C13-T04 (§3.1, §10 decision 2, §11 interface note) adds the
   `aiur_history_export` dynamic tool, which needs a function to call. This
   ticket gives that function and no tool: the tool's cap and cursor are
   C13-T04's design. C13-T04 suggested `{:ok, rows, health}`; this ticket
   returns one map with `tickets`, `next_after`, the two totals and `sources`,
   because the tool needs the totals and the per-source health too, and one
   shape for both callers keeps them from drifting. C13-T04 adapts to it.
8. **Copy `BuildOrdersCLI`'s private `source/3` shape (about 20 lines) instead
   of making it public.** Making it shared would change `build_orders_cli.ex`
   and its boundary test (`Aiur.Regression.ProgressRendererBoundaryTest` lists
   its call sites). `ponytail:` if a third CLI needs it, extract
   `Aiur.CLISource.entry/3`.
9. **Open tickets are included.** History indexes every issue (C4-T01). An open
   ticket in Unsorted needs a column too; each record carries `state`, so the
   agent can skip open ones if the runbook says so.
10. **The command is `aiur history export`, with one subcommand.** It matches
    the row. A bare `aiur history` is a usage error, not a default action.
11. **The export reuses C8-T04's `Index.resolver_context/2`** rather than
    building its own, so the export and the board cannot disagree on a
    ticket's epic. It checks store health itself before calling it, because
    the board degrades a failed part to `:unknown` and the export must not.
12. **A held `"body": null` is a known empty body.** GitHub sends `null` for
    an empty description. Calling it unknown would make the agent ask GitHub
    for a body that does not exist; calling an unheld body `""` would hide a
    gap. So `null` gives `excerpt: ""` and counts as held; a missing key or
    entry is unknown.
13. **`history` joins the shim's read-only command list.** Without it,
    `aiurdev history export` is refused from any checkout but the shim's own
    (`scripts/aiurdev:115`, fallthrough `return 0`). It goes beside
    `build-orders`, not in `pure_control_command`, so a stale release is
    rebuilt first in the shim's own checkout.
14. **`labels_complete` and `state_reason` are exported with the unknown
    rule.** C4-T01 keeps both with an `:unknown` form; dropping them would
    hide that a label list is cut at 100.
