# U5-T01 - Complete paginated readers

## Identity and outcome

- Bucket 1, prior unit U5. Acceptance example AE4.
- **User value:** an agent working an issue with more than 100 comments gets
  all of them, or an explicit "incomplete" error - never the oldest 100
  presented as the whole thread.
- **Deliverable:** `fetch_classified_issue_comments` reads every page;
  `Transport.fetch_json_list` returns an error when a `rel="next"` link exists
  (so no caller can silently truncate); PR changed-file reads paginate.
- **Non-goals:** no cache policy change; no quota saving claimed.

## Dependencies and blockers

- U0-T01. U5-T02 depends on the PR-files reader.
- Read `website/docs-app/apis/github.md` before changing (AGENTS.md).

## Verified starting point (`58854d4c8`)

- `github/comments.ex:126-141` `fetch_classified_issue_comments`: one
  `per_page=100` request via `Transport.fetch_json_list` (`transport.ex:678-691`),
  which **ignores `rel="next"` and returns `{:ok, page1}`**.
- Sibling `fetch_issue_comments_conditional` (:91-122) reads every page;
  `fetch_json_list_conditional` (:708-736) refuses a next link with
  `:pagination_unexpected`.
- Caller: `agent_runner/comment_context.ex:96` (through `Tracker`).
- PR files: `github/pull_requests.ex:13-27` one page (`per_page=100`);
  `codeowners.ex:473-481` has its own one-page fetcher (removed in U5-T02).
- Tests: `comments_test.exs:72` covers only the conditional reader.

## Chosen design

- `fetch_classified_issue_comments`: reuse the page loop that
  `fetch_issue_comments_conditional` already uses (extract the loop if it is
  private; do not write a third).
- `fetch_json_list`: if the response has `rel="next"`, return
  `{:error, :pagination_unexpected}` - same atom as the conditional reader.
  Grep its callers; any caller that legitimately expects more than one page
  switches to the page loop in this ticket.
- `pull_requests.ex` changed files: use the page loop; a failed later page
  returns `{:error, _}` (no partial list).
- `comment_context.ex`: on `{:error, :pagination_unexpected}` or a page error,
  give the agent the explicit "comment context incomplete: <reason>" text that
  the existing error path uses (check its current wording).

## Implementation steps

1. Page loop reuse; classified reader; PR files reader.
2. `fetch_json_list` refusal; fix any caller that breaks.
3. Tests; read `apis/github.md` and update one line if it lists comment reads
   as single-page (no growth: replace the line).

## Non-happy paths

- **Rate hold on page 2:** propagate the existing hold error (`{:error, {:aiur, :locally_held, hold}}`); never return page 1.
- **Huge threads:** bounded by GitHub's own pagination; no new cap.
- **Conditional (ETag) reads:** unchanged.

## Compatibility and rollout

More API calls for issues with > 100 comments (counted: run `aiur github-cost`
before/after for one day and note it; this is a correctness change, not a
saving). Rollback: revert.
