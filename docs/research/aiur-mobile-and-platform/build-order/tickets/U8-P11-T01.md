## Chosen design

- **Move inline scripts to files.** Each `run: |` block over 15 lines becomes
  `scripts/ci/<job>-<step>.sh` (PROPOSED), called as `run: bash scripts/ci/<name>.sh`, with
  inputs passed as `env:` (never `${{ }}` interpolated into the script body, which is the
  safer pattern for untrusted values).
- **Composite actions for the repeated prologue.** PROPOSED
  `./.github/actions/job-prologue/action.yml`: checkout is not allowed inside a local
  composite before checkout, so the prologue covers the steps after checkout (rerun
  disclosure, `mise` setup where repeated). Use it only where the steps are identical.
- **No workflow file split.** `needs:` cannot cross workflow files, and the `changes` output
  gates most jobs. Keeping one `ci.yml` keeps the contexts and `needs` graph unchanged.
- Expected sizes: `ci.yml` about 480, `release-npm.yml` about 380. If `ci.yml` stays above
  500, move `workflow-security` and `merge-ruleset-drift` (no `needs`) into
  `ci-guards.yml` with identical triggers; their contexts are job names, so the ruleset still
  matches.

## Non-happy paths

- A renamed job or matrix label silently removes a required check. Compare the job
  `name:` set before and after with a `yq` command in the PR body.
- `verify-workflow-security.sh` must pass on the new files and the new composite action
  (it already scans composite actions; fixture `scripts/test-fixtures/workflow-security/composite-actions/`).
- Scripts must be executable in CI (`bash file.sh` avoids the mode bit); `set -euo pipefail`
  in each.
- Release workflow cannot be fully run from a PR; use `workflow_dispatch` on a branch with
  the dry-run channel if the workflow supports it, else verify the `smoke` job only.
