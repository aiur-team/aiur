## Identity and outcome

- Bucket 2, feature MP-E8 (continuous build history), chunk C11 (ticket modal and
  agent chat).

## Chosen design

### Port, then change only these things

The module is the design's code with these changes and no others:

1. **No mock stream.** `startLive`, `stopLive`'s timers, `MS.clock`, `MS.timer`,
   `MS.rt` and every `Math.random` go. `o.at` comes from the entry.
2. **Live rows arrive from the server** in batches (`conversation-append`).
   `appendLive(entries)` measures `stick` once, calls C11-T03's
   `appendEntries`, then scrolls or shows the pill once, and schedules one
   `buildMap`. One entry behaves exactly like the design's `appendItem`.
3. **Duplicates and the cap are C11-T03's.** Its `appendEntries` replaces an
   element whose `data-eid` already exists and returns only the new elements;
   only those get `.in` and can show the pill. Its top trim over `MAX_DOM` is
   wrapped here with a scroll anchor (EC-10). While its `trimmedBottom` is true,
   appends are dropped and the pill asks for the tail.
4. **The design's `MS.log/map/mm/vw/s` become module state** of `live.js`
   (`V`), because C11-T01's `MS` is `{ t, req, origin, state }` only.
5. **Listeners and frames go through a per-render `life`** (`createLife()`,
   C9-T01). C11-T03 re-renders the `.cv` DOM after a `reset` and after a
   reconnect, so `wireLive` first disposes the previous render's `life`.
6. **Resize uses `life.observe` (a `ResizeObserver`) on `#cv-log` and
   `#cv-map`**, not the window `resize` event. It covers the window resize the
   design handles, and also the composer growing to 140 px (C11-T06), which
   changes the log height. The rebuild is coalesced to one per frame.
7. **The typing rule reads real state** (below).
8. **Keyboard additions without pixel change** (Decisions 4 and 5).

### The live tail

```js
// modal/live.js (sketch; names from C9-T01, C11-T01 and C11-T03)
const STICK = 60                                    // J:1460, J:1469
let V = null, life = null, cv = { live: false }     // V = { log, map, mm, vw, tip, s }
onReset(disposeLive); onModalClose(disposeLive)

export function appendLive(entries) {
  if (!V || !MS.t) return
  const log = V.log
  const stick = log.scrollHeight - log.scrollTop - log.clientHeight < STICK
  const anchor = stick ? null : firstVisible(log)   // EC-10
  const d = anchor ? anchor.offsetTop - log.scrollTop : 0
  const fresh = appendEntries(entries)              // C11-T03: replace by data-eid, cap, trim top
  if (!fresh.length) { if (trimmedBottom) $("#cv-new").hidden = false; return }
  for (const el of fresh) el.classList.add("in")
  if (stick) log.scrollTop = log.scrollHeight
  else { if (anchor?.isConnected) log.scrollTop = anchor.offsetTop - d; $("#cv-new").hidden = false }
  scheduleMap()
}
```

- `firstVisible(log)` is the first child with `offsetTop + offsetHeight >
  scrollTop`. Restoring its offset keeps the row under the reader still when
  C11-T03 trims rows above it. Without a trim, the restore is a no-op.
- Rows of the first page do **not** get `.in`, as in the design (J:1414 appends
  them without the class). They come through `renderConversation`, not
  `appendLive`.
- On a `conversation` message, `wireLive` runs after `renderConversation`. Its
  `scheduleMap()` frame is requested after C11-T03's bottom-pin frame, so the
  first `buildMap` measures the pinned log (J:1468 order: pin, then build).
- `appendLive` for an entry of another ticket cannot happen: C11-T03 drops
  messages whose `id` is not the open modal's. `!MS.t` (closed modal) returns.

### The `#cv-new` pill

- Log `scroll` (passive, `life.on`): `syncView()`; when `scrollHeight −
  scrollTop − clientHeight < 60`, `#cv-new.hidden = true` (J:1469). The
  comparison is strict `<`, as in the design.
- Click: if C11-T03's `trimmedBottom` is true, `requestTail()` (the reply
  re-renders and pins to the bottom); else `log.scrollTo({ top:
  log.scrollHeight, behavior: rmOn() ? "auto" : "smooth" })` (J:1470). The
  scroll handler hides the pill on arrival.

with three changes:

1. It iterates `log.children` and **skips a child without `dataset.k`** (the
   S-15 row and the `.cv-end` state rows of C11-T03, Interface note 4 there). The
   index `i` used for `data-i` and for the width formula stays the child index,
   as in the design, so a log without those rows gives the design's widths
   exactly.
2. `data-i` is resolved back with `log.children[+data-i]` as in the design. A
   rebuild runs after every change of `log.children`, so the index is current.
   If the child no longer exists, or has no `data-k`, the pointer handler does
   nothing.
3. The `.mm-e` buttons get `tabindex="-1"` (Decision 4). The `aria-label` stays.

Pointer wiring is J:1471–1484 through `life.on`. `toY` clamps nothing, as in the
design (the browser clamps `scrollTop`). The tooltip time is `src.dataset.at ||
"—"` (C11-T04 already writes `"—"`; C11-T03 writes `""` for non-`ev` rows,
which have no tick).

### The typing indicator

```js
export function typingVisible(t, live, linkLive) {
  return t?.sec === "now" && t.agent?.state === "active" && live === true && linkLive === true
}
export function updateTyping() {
  const el = $("#cv-typing"); if (!el || !MS.t) return
  const t = ctx.D?.byId?.[MS.t.id] ?? MS.t            // the row after the latest diff
  el.hidden = !typingVisible(t, cv.live, ctx.offline?.isLive() === true)
}
// conversationApplied sets cv.live = msg.live === true for `conversation` and `conversation-state`
```

| Input | Visible |
| --- | --- |
| now row, `agent.state "active"`, message `live: true`, `isLive()` true | yes |
| same, conversation state `known_empty` (C11-T03 sends `live: true` for it) | yes — the agent runs and has written nothing yet |
| `agent.state` any other `AST` key (`paused`, `command`, `parked`, `error`, `retries`, `idle`, `stuck`…) | no |
| `agent.state null` (unknown, C8-T01) | no — an unknown state never claims "is working" |
| message `live: false` (`ended`, `stale`, `unavailable`, `restart_unknown`, or not running), or no message yet | no |
| `isLive()` false (socket down, link down, or daemon `offline`/`stale`/`unknown`) | no — the design hides it for `offline` (J:1411) |
| `ctx.offline` missing | no (cause-neutral: an unknown link is not live) |
| `not_retained` | no `.cv` DOM, so no `#cv-typing` |

The text is the design's `m.name + " is working"`, from `t.agent.name`
(C8-T01). When that name is `null`, the text is "Agent is working"
(Decision 6). The text is set with `textContent` once in `wireLive` and on each
`updateTyping`.

`updateTyping` runs on: every `conversation` and `conversation-state` message,
and at the end of every `renderOffline` call. `renderOffline` already runs on
every applied snapshot or diff, on socket down/up, and on the debounced
`linkDown` timer (C8-T03), so an agent-state diff, a daemon change and a link
change all reach it. It never runs from a click.

### Invariants

1. No client timer creates a row. Every row in `#cv-log` came from the server
   (C11-T03's render, pages and appends) or from an accepted write (C11-T06,
   C11-T08).
2. After any change to `#cv-log` children, one `buildMap` runs before the next
   paint. The number of `.mm-b` plus `.mm-e` equals the number of children with
   `data-k`.
3. `#cv-typing` is visible only when `typingVisible` is true.
4. Closing the modal, a re-render, and a LiveView navigation each dispose every
   listener, observer and frame this module added for the previous DOM.

## Non-happy paths

- **Transcript absent or empty (EC-16).** C11-T03 renders the state and footer.
  This module: an empty `#cv-log` gives `H0 = 0`, `s = min(0.14, rh / 1) =
  0.14`, no blocks, `mm.height = 0`, `.mm-vw` height `max(8, clientHeight ·
  0.14)`. The design has the same formula, so nothing special is drawn. A
  `known_empty` log holds only C11-T03's "No messages yet" `.cv-end` row, which
  has no `data-k` and draws no block. Typing follows the table (visible for an
  active, running agent with a live link).
- **Not retained (S-6).** There is no `.cv` DOM (C11-T03 shows the issue view),
  so `conversationApplied` does not wire anything (`#cv-log` is absent, `V`
  stays null) and `appendLive` returns.
- **Huge transcript (EC-16).** The minimap covers loaded rows only (≤ 500, C11-T03).
  A `buildMap` reads `offsetTop`/`offsetHeight` of each child once (one layout).
  Bursts are coalesced to one build per frame. C12-T06 measures the cost.
- **Ticket changes while the reader scrolls (EC-10).** A ticket diff changes the
  header (C11-T01) and the typing state only. It never touches `#cv-log`, so the
  scroll position is kept. When an append makes C11-T03 trim the top, the
  anchor restore keeps the row under the reader still.
- **Bottom trimmed after paging up** (C11-T03 `trimmedBottom`): appends are
  dropped by C11-T03; this module shows `#cv-new`; its click calls
  `requestTail()` instead of scrolling to a bottom that is not the real end.
- **Duplicate entries** (an `id` sent twice): C11-T03 replaces the element in
  place and does not return it, so it gets no `.in`, does not move the scroll
  and does not show the pill. A local row without `id` (C11-T06 before its
  entry id is known) is appended normally.
- **`reset` or reconnect** (C11-T03 sends a fresh `conversation` and
  re-renders): `wireLive` disposes the old render's listeners and observer and
  wires the new DOM once. No second scroll handler remains.
- **Modal closed or another ticket opened:** `onModalClose(disposeLive)` clears
  `V`; late appends return at `!V || !MS.t`. C11-T03 drops messages for a
  different id.
- **Unknown time (`at: null`).** `itemEl` (C11-T03/T04) renders the unknown
  time. The tooltip shows `data-at` as given; when it is absent or empty it
  shows `—`, never `00:00` or the epoch.
- **Untrusted text (EC-30).** The tick `aria-label` and the tooltip label go
  through `esc` (J:1478, J:1535). The typing text uses `textContent`.
- **Agent ends, is superseded or restarts** (`:ended`, `:restart_unknown`):
  C11-T03 pushes `conversation-state` with `live: false`; typing hides. No new
  rows arrive.
- **Socket down / daemon offline (EC-06).** `isLive()` false → typing hidden at
  the next `renderOffline` (it runs in `disconnected` and on each applied
  message). The log keeps what it has. Catch-up after reconnect is C11-T03's
  fresh `conversation`.
- **Read-only dashboard (EC-12).** The live tail is read access. It is shown on
  a read-only dashboard exactly as on a writable one.
- **Reduced motion (EC-19).** `scrollTo` uses `behavior: "auto"` (instant) when
  `rmOn()`; the stylesheet removes `cvIn`, `cvFlash` and the dots' animation
  (C:610). The dots stay at their resting style (no animation), as in the design.
- **Keyboard and screen readers (EC-19).** See Decisions 4 and 5: `#cv-log` is a
  focusable region, so arrow keys and Page Up/Down scroll it; the minimap ticks
  are not tab stops; `#cv-new` is a real button in the tab order when shown.
- **Pointer capture lost** (`lostpointercapture`, a touch cancel): `drag` is set
  to false on `pointerup`, `pointercancel` and `lostpointercapture`. The design
  handles only `pointerup` (J:1483); the two extra events stop a stuck drag on
  touch devices and change no pixels.
- **Navigate away (LiveView):** `onReset(disposeLive)` clears `V`, `cv` and every
  listener, so the next mount starts clean.

## Decisions made without the owner

1. **The design's 60 px stick threshold**, not the Units drawer's 24 px. The
   design is the specification.
2. **Batch append.** A server push may carry several entries. They are appended
   in one step with one stick decision, so the reader is not pulled down by the
   first entry of a batch.
3. **`ResizeObserver` (`life.observe`) on the log and map** instead of the
   window `resize` event. It is a superset of the design's trigger and also
   catches the composer growth. No pixel changes.
4. **The minimap ticks are not tab stops** (`tabindex="-1"`). With up to 500 rows,
   the ticks could be about a hundred tab stops between the header and the
   composer. Keyboard and screen-reader users scroll the log itself, which shows
   the same events as text. The ticks keep their `aria-label`. C12-T05 may
   revisit this; it is listed for Kevin's sign-off in C12-T08.
5. **`#cv-log` gets `tabindex="0"` and `aria-label="Conversation"`**, so it can
   be scrolled from the keyboard. No pixel changes unless focused; the focus
   ring is S-12's.
6. **Unknown model name → "Agent is working".** The design always has a name.
   The sentence states only what is known (the agent is active), not a model.
7. **No conversation export here.** C11-T03 step 5 already extends C1-T01's
   exporter with `convoFor`; this ticket reuses its fixtures.
8. **No gap repair.** C11-T03's appends come from a byte cursor over
   `agent.ndjson`, and a `reset` or reconnect re-renders from a fresh tail. A
   client-side merge would duplicate that logic.
9. **`pointercancel` and `lostpointercapture` end a drag.** The design handles
   only `pointerup`. The extra handlers prevent a stuck drag on touch devices and
   change nothing visible.
10. **Typing is refreshed from `renderOffline`.** It already runs on every
   applied message, link change and the debounced `linkDown` timer, so one line
   there covers agent-state diffs, daemon changes and socket changes. The row is
   read from `ctx.D.byId` so the check sees the diff even if `MS.t` is updated
   later in the same tick.
11. **Scroll anchor for the top trim (EC-10).** C11-T03 owns the trim; this
