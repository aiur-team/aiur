# MP-E7-C6-T02 — The deliver hook command

## Identity and outcome

- **Bucket / feature / chunk:** Bucket 2 · MP-E7 · C6.
- **User value:** the Executor session receives due messages with nothing to
  install beyond a hook entry; a slow or stopped daemon never disturbs the
  session.
- **Deliverable:** a generated shell command string for Claude and Codex
  hooks that posts the hook's stdin to the C6-T01 endpoint and prints the
  response body only on `200`; always exits 0. Generated by a new pure
  function `Aiur.Executor.DeliverHookCommand.command(harness, url, token_path)`
  (PROPOSED), consumed by C6-T03's installer.
- **Non-goals:** a Node hook binary in `aiur-cli`.

## Plan change (recorded for the parent)

MP-E7 chunks C6 proposed "Node, in `aiur-cli`, using the shared codecs".
**Replaced** by daemon-side rendering (C6-T01 + C6-T04) and a `curl`
command, because:

- `aiur-cli` declares `"engines": {"node": ">=18"}`
  (`packaging/npm/aiur-cli/package.json:25-27`) while Khala's published
  packages need Node `^22.18.0 || >=24.11.0` (MP-E7 plan E7-F5). Importing the
  shared TS codec would raise aiur's Node floor (RQ-E7-5). Daemon-side
  rendering makes RQ-E7-5 moot for this chunk.
- aiur already ships exactly this hook shape: a `curl` one-liner that is
  silent unless designed otherwise and always exits 0
  (`claude/hook_settings.ex:26-45`).
- One renderer (Elixir) is checked against the shared goldens (C6-T04);
  a second (TS) copy in `aiur-cli` would need the same goldens anyway.

## Dependencies and blockers

- **DESIGN-E7**; **MP-E7-C6-T01** (endpoint + response contract);

## Verified starting point (at `45a290e3`)

- `HookSettings.hook_command/2` builds
  `curl -sS -m 2 -o /dev/null -H 'Content-Type: application/json' -H 'Origin:
  http://127.0.0.1' -H 'X-Aiur-Request: 1' --data-binary @- '<url>'
  >/dev/null 2>&1; exit 0` (`claude/hook_settings.ex:36-45`) with a
  single-quote escaper (`:76`). Tests: `src/test/aiur/claude/hook_settings_test.exs`.
- `aiur-cli` supports `linux` and `darwin` only (`package.json` `"os"`), so a
  POSIX shell and `curl` are assumed, as today.

## Chosen design

Command (Claude; Codex identical with `harness=codex`):

```sh
curl -sS -f -m 3 -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $(cat '<token_path>' 2>/dev/null)" \
  --data-binary @- '<base>/api/v1/executor/hook/deliver?harness=claude' \
  2>/dev/null; exit 0
```

- `-f`: any non-2xx prints nothing. `204` has an empty body, so prints
  nothing. `200` body goes to stdout = the hook output.
- `-m 3`: total budget above the endpoint's 1.5 s, below both harness hook
  timeouts (Khala installs Codex hooks with `"timeout": 10`,
  `packages/agent/hooks/hooks.codex.json` at `99e72a43`).
- Token read at run time from the 0600 file, never embedded in settings.
- Base URL from `HookSettings.dashboard_url/0` (`hook_settings.ex:66-72`) at
  install time; documented that a port change needs reinstall (C6-T03
  `--check` reports it, MP-E3-C7-T01).

## Implementation steps

1. New module with `command/3` (pure) and the shared `single_quote/1`
   (extract from `hook_settings.ex:76` into a tiny helper to avoid copying).
2. Tests.

## Non-happy paths

- **Token file missing:** header is `Bearer ` → `401` → nothing printed.
- **Daemon down / port changed:** curl error → nothing printed, exit 0.
- **Partial body on timeout:** `-m` aborts before printing? curl streams the
  body as it arrives; the endpoint sends the whole body in one write after
  rendering, and bodies ≤ 64 KiB + envelope, so a timeout during transfer is
  unlikely but possible — the harness would receive truncated JSON and ignore
  it (Claude/Codex treat unparsable hook stdout as plain text). Documented
  risk; the item is already marked delivered (C6-T01 invariant).
- **Shell injection:** URL and path are single-quoted via the existing
  escaper; no message text ever appears in the command.

## Compatibility and rollout

Pure function; no effect until C6-T03 installs it.
