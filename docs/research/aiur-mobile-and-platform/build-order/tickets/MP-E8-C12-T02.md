## 4. Chosen design

### 4.1 Redirect controller

PROPOSED `src/lib/aiur_web/controllers/build_order_redirect_controller.ex`,
mirroring `CommandsRedirectController`:

```elixir
defmodule AiurWeb.BuildOrderRedirectController do
  @moduledoc false
  use Phoenix.Controller, formats: []
  alias Aiur.BuildOrder.Bounded
  alias Aiur.BuildOrder.Features.RootImport

  # The old pages read no query parameters, so none are carried.
  def catalog(conn, _params), do: moved(conn, "/")

  def root(conn, %{"root_number" => raw}) do
    case Bounded.github_issue_identifier(raw) do
      {:ok, id} ->
        # Safe: Bounded accepted only 1–19 digits with no leading zero.
        slug = id |> String.to_integer() |> RootImport.slug()
        moved(conn, "/?" <> URI.encode_query(%{"feature" => slug}))

      :error ->
        moved(conn, "/")
    end
  end

  defp moved(conn, to), do: conn |> put_status(:moved_permanently) |> redirect(to: to)
end
```

Router (`router.ex:144-145`), moved out of the `live_session` to sit beside the
`/decisions` lines in the same `[:dashboard_auth, :browser]` scope:

```elixir
get("/build-orders", BuildOrderRedirectController, :catalog)
get("/build-orders/:root_number", BuildOrderRedirectController, :root)
```

- **Invariant:** the only redirect targets are `/` and `/?feature=bo-<digits>`.
  User input never reaches `Location` unvalidated (no open redirect, no header
  injection).
- Interfaces exposed: none new. Interfaces consumed: `RootImport.slug/1`
  (C6-T03), `Bounded.github_issue_identifier/1` (base), the `feature` URL key
  (C3-T03).

## 7. Compatibility and rollout

- **No config, no migration, no flag.**
- **Gated by OQ-E8-9**, not by a runtime flag (ponytail: the answer is a
  one-time human decision; a flag would outlive it).
- **301 is cached by browsers.** A revert leaves cached redirects to
  `/?feature=bo-<n>`, which still works. That is acceptable, and it is why the
  target must stay valid for as long as C6-T03 imports roots.
- **Rollback:** revert the commit. The deleted modules come back with it. The
  data layer was never touched.
- **Packaging:** none. The npm `aiur` and `aiurdev` serve the same router.

## 10. Decisions made without the owner

1. **The whole ticket is gated on OQ-E8-9.** The README row asks for
   redirects, but plan §10 item 17 and OQ-E8-9's default keep `/build-orders`
   reachable until Kevin confirms. One URL cannot do both, so the redirect waits
   for the answer. The "reachable without nav" half is C12-T01's hidden route.
2. **No local route map in `BuildOrderLive`.** C12-T01 already keeps
   `:build_order` in `@hidden_routes`; a second mechanism would duplicate it.
3. **The redirect does not look up the feature.** `bo-<n>` is derived, as C6-T03
   intended. A CLI feature that took `bo-<n>` (C6-T03 conflict `:slug_taken`)
   would receive the redirect. This is rare, visible in the import conflicts,
   and cheaper than a store read on every old link.
4. **An invalid root redirects to `/`, not to a 404.** EC-26 says "invalid
   parameters dropped". A dead link landing on the home page is more useful than
   an error, and nothing is guessed.
5. **The query string is dropped.** The old page read none (§3). Carrying it
   would put stale old keys into the C3-T03 canonicalizer. This differs from
   `CommandsRedirectController`, whose target reads the same keys.
6. **301, as the Commands redirects use.** It ships only after a final human
   decision, and the target stays valid after a revert (§7).
7. **The funnel probe path stays `/build-orders/1`.** A 301 is already
   "healthy" (`build_order_funnel_health.ex:16`), so moving the probe would be
   an unasked behaviour and docs change.
8. **Deletion is decided by `mix xref`, not by file name.** The CLI,
   `/analytics` and MP-E8 reuse many `build_order_*` modules (§3). A module that
   survives xref but has no reader is listed in the PR body as a follow-up
   ticket, not deleted by guess and not pushed onto C12-T03 (which owns only
   Units code).
9. **The `aiur-meta` and docs-screenshot capture entries are removed.** If they
   stayed, every meta-check would report a false failure, and the docs capture
   would write the home page under the Build Order name.
10. **Complexity 2:** one controller of about 20 lines, a router swap, one
    registry line, mechanical deletion and doc edits. If the xref list grows past
    the expected set, it is still deletion, not design.
11. **No replacement for the catalog subscription.** The deleted page was the
    only dashboard demand on the catalog cadence. Headless runs, the normal
    case, already have none (`configuration.md:772-774`). The explicit
    `refresh_catalog/1` stays for the Executor. Adding a new trigger on the home
    page would be new GitHub cost and is not asked.
12. **This ticket follows the C12-T08 sign-off, not the reverse.** C12-T02 is
    not a predecessor of C12-T08. The sign-off package asks OQ-E8-9, and the
    answer is recorded in `questions.md` beside OQ-E8-9. On "retire" this
    ticket starts; on "keep the panes" it is closed as not needed. The Build
    Order pages are outside the nav, so the package needs nothing from this
    ticket.
