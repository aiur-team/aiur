# U0-T03 - Transitional 500-line gate

## Identity and outcome

- Bucket 1, prior unit U0 (KTD1, KTD7, AE5).
- **User value:** the oversized-file debt stops growing while U8 retires it.
  A PR that adds a new file over 500 lines, or grows an existing oversized file,
  fails a required check with the path and count.
- **Deliverable:** `scripts/check-file-size.py`, its test
  `scripts/test-check-file-size.sh`, two steps in the `workflow security` job,
  and a `CONTRIBUTING.md` edit.
- **Non-goals:** no universal (zero-debt) mode switch - that is U8's last step;
  no 201-line enforcement (review prompt only); no tracked ledger as authority.

## Dependencies and blockers

- No predecessors. It is part of U0 itself and does not wait for the U0-T01
  sign-off. It does not gate MP-R tickets.
- U8 tickets must expect this gate: a U8 split shrinks a file, which passes.

## Chosen design

- **Authority is Git, not a file the PR can edit.** Baseline = the blobs at the
  PR's merge base with the protected branch (`git merge-base HEAD origin/main`,
  CI fetches main). An oversized path at the base may stay oversized but may
  not grow. KTD-note: the design doc froze one baseline commit; using the merge
  base gives the same shrink-only result and needs no pinned SHA to maintain.
- **Counting (KTD7):** count `\n` bytes; add 1 if the blob is non-empty and the
  last byte is not `\n`. Empty = 0. A blob with a NUL byte or invalid UTF-8 is
  binary. Mode `120000` (symlink) is reported, never followed. Read blobs with
  `git cat-file --batch`; list with `git ls-tree -r -z`.
- **Rules at HEAD vs base:**
  1. text path > 500 at HEAD that is absent or ≤ 500 at base → fail;
  2. base path > 500 and HEAD count > base count → fail;
  3. a rename or copy of an oversized blob to a new path → fail (rule 1 covers it);
  4. a path that is text at base and binary at HEAD → fail (no approval list in
     this ticket; if a real case appears, add an approval record later);
  5. anything ≤ 500 → pass. Files 201..500 that are new or grew: print a
     notice line asking for a cohesion reason; exit 0.
- Output: one line per failure `path: base N -> head M (limit 500)`; exit 1.

## Implementation steps

1. `scripts/check-file-size.py` with `--base <rev>` (default merge base with
   `origin/main`) and `--head <rev>` (default `HEAD`). Standard library only.
2. `scripts/test-check-file-size.sh`: builds a temp git repo and asserts exit
   codes for each case in Verification.
3. ci.yml `workflow security` job: `fetch-depth: 0` on its checkout if not
   already full; add steps `Test file size gate` and `File size gate`.
4. `CONTRIBUTING.md`: replace :51-52 with the rule (new or grown file over 500
   fails; aim for 200; give a reason above 200).

## Non-happy paths

- **Shallow checkout:** the script fails with a clear message "base not
  available; fetch origin/main" - never passes silently.
- **Merge group / push to main:** base = `HEAD^1` on main pushes; merge queue
  uses the queue base. Test both.
- **Huge repos:** one `cat-file --batch` stream; no per-file subprocess.
- **CRLF files:** counted by LF only (the rule); documented.

## Compatibility and rollout

No config. Takes effect on merge. Every open PR that grows an oversized file
will fail; U8 and MP tickets already require no growth. Rollback: revert the
two ci.yml steps.

## Verification

`bash scripts/test-check-file-size.sh` asserts:

| Case | Expected |
| --- | --- |
| new file with 500 lines | exit 0 |
| new file with 501 lines | exit 1, names path and 501 |
| new file 500 lines, no final newline (last line non-empty) | 500 → exit 0 |
| base file 700 → head 700 | exit 0 |
| base 480 → head 520 | exit 1 (crossed the limit) |
| base 700 → head 699 | exit 0 |
| base 700 → head 701 | exit 1 |
| `git mv` of a 700-line file | exit 1 (new path over 500) |
| text file becomes binary (NUL added) | exit 1 |
| symlink to a 900-line file | exit 0, reported as symlink |
| new 250-line file | exit 0 with notice line |
| empty file | count 0 |

Mutation check: change the limit compare from `>` to `>=` - the 500 case must
fail; remove the growth rule - the 701 case must pass and the test must fail.
Run the gate once on a website-only PR to show the step runs.
