# U5-T05 - Ambiguous reply mutation

## Identity and outcome

- Bucket 1, prior unit U5 (KTD6: reconcile external mutation outcomes before retrying).
- **User value:** an agent's reply to a review thread is never posted twice
  when GitHub applied it but the response was lost.
- **Deliverable:** before a retry, `reply.ex` reads the thread and skips the
  re-post if a reply with the same body by the same author already exists after
  the attempt start; test for applied-but-lost.
- **Non-goals:** no general mutation journal.

## Dependencies and blockers

- U0-T01; U5-T04 (`:unknown` outcome classification).

## Verified starting point (`58854d4c8`)

- `github/review_threads/reply.ex:80` retries whenever
  `retryable_github_error?` is true, **deadlines included**.
- No test covers an applied mutation with a lost response (`reply_test.exs`).
- `website/docs-app/apis/github.md` is 779 lines (over 500; U8 DOCS owner).

## Chosen design

- On an outcome of `:unknown` (U5-T04) only: read the thread's comments
  (existing reader), match `author == self && body == sent_body && created_at >=
  attempt_started_at`; found → `:ok` (already applied); not found → retry once
  as today. Other retryable errors (definite failure, e.g. 502 before send) keep
  today's retry.

## Implementation steps

1. Reconcile-before-retry branch in `reply.ex`.
2. Test.
3. Docs: one sentence in `apis/github.md` mutation section, replacing an
   existing sentence (no net growth; U0-T03 gate).

## Non-happy paths

- **Reconcile read fails:** return the unknown error to the caller (do not
  post again blindly); the agent sees "reply status unknown".
- **Same body posted on purpose twice:** the `created_at >= attempt_started_at`
  window limits matches to this attempt.

## Compatibility and rollout

One extra read only on unknown outcomes. Rollback: revert.
