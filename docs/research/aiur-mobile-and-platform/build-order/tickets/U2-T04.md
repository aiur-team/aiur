# U2-T04 - Waiting reason with owner, cause and since

## Identity and outcome

- Bucket 1, prior unit U2 (R2: distinct states with observed age; U2 exit
  "every stuck state has one owner, cause, age").
- **User value:** `aiur agents` and the status board say *why* a ticket waits,
  *which part* owns the wait, and *for how long* - not just a reason atom.
- **Deliverable:** `WaitingReason.describe/2` returning
  `%{reason, owner, cause, since}` for each of the 21 reasons, used by
  `StatusReport` rows; CLI renders `since` as an age.
- **Non-goals:** no new reasons except as U2-T05 adds; no web layout change
  (U6-T04 carries fields to the web); no persistence.

## Dependencies and blockers

- U0-T01. U2-T05 and U6-T04 depend on this.

## Verified starting point (`58854d4c8`)

- `orchestrator/waiting_reason.ex:13-33`: `WaitingReason.t()` is a bare atom,
  21 reasons; classifiers `for_running/1` (:47), `for_retry/0`.
- `StatusReason` (`status_reason.ex:29`) adds `{:claim_released, cause, retry_in_ms}`.
- Ages exist but scattered: row `runtime_seconds`, `stale_for_seconds`,
  `pause_reason`, `started_at` (`status_report.ex:476-530`); retries
  `due_in_ms`, `last_failure_at`; capacity holds `held_for_seconds` (:443);
  snapshot `age_seconds` (:65).
- `:workspace_ownership_waiting` exists (#2810, `waiting_reason.ex:171-177`).

## Chosen design

- Keep the atom as the reason (callers and JSON keep working). Add
  `describe(reason, row_facts) :: %{reason, owner, cause, since}`:
  - `owner`: the module that can clear it (a fixed table, one row per reason).
  - `cause`: the existing detail already on the row (retry error, hold cause,
    pause reason); `:unknown` when absent (AGENTS.md: collapse to a neutral atom).
  - `since`: the existing timestamp for that reason (`last_failure_at`,
    hold start, `started_at`); `nil` when not known - render "age unknown",
    never 0.
- JSON (`aiur agents --json` / status payload) gains `waiting: %{owner, cause,
  since, age_ms}`; text output appends `· <owner short> · <age>`.

## Implementation steps

1. Table + `describe/2` in `waiting_reason.ex`.
2. `StatusReport` row builder calls it; move the scattered age picks into it.
3. CLI renderer prints owner/age; `website/docs-app/reference/cli.md` updates the
   `agents` output sample (documented behaviour changes).
4. Tests.

## Non-happy paths

- **Unknown since:** "age unknown" in text, `since: null, age_ms: null` in JSON.
- **Clock skew:** ages from monotonic-derived values where the source is
  monotonic; never negative (clamp and log).

## Compatibility and rollout

Additive JSON field; text line gets longer. Docs: `reference/cli.md`.
