# U2-T05 - Retained workspace lease is visible

## Identity and outcome

- Bucket 1, prior unit U2.
- **User value:** a ticket blocked because its workspace lease is held with no
  provider no longer waits silently for ever; the Executor sees
  "workspace retained" with age and one alert, and a timed-out release is not
  reported as success.
- **Deliverable:** `ownership.ex` timeout returns `{:error, :release_timeout}`;
  a separate reason `:workspace_retained`; one alert when a lease enters the
  indefinite `:reaping` latch.
- **Non-goals:** no change to when the guardian reaps (the latch is deliberate
  safety); no new operator release command (existing `aiur` reset/stop paths
  stay the recovery; record which one in docs).

## Dependencies and blockers

- U0-T01. U2-T04 (reason table gains the new row).

## Verified starting point (`58854d4c8`)

- `workspace/ownership/guardian.ex:425-434`: provider nil and expected → lease
  enters `:reaping` unless `local_provider_exited_after_reboot?` (#2879,
  `220b8f253`). `:446-447`: remote provider without release request →
  `:reaping`. `:440` releases on request.
- `workspace/ownership.ex:241` `timeout_result(_message) -> :ok` - a timed-out
  release reports `:ok`.
- No `needs_attention` alert in `guardian.ex`.
- `WaitingReason` has `:workspace_ownership_waiting` (#2810, :171-177,
  "not always self-clearing"), rendered "awaiting safe release" (`status_reason.ex:42`).
- `test/aiur/workspace/ownership_test.exs:26-54, :115-118` assert the latch as intended.

## Chosen design

- `timeout_result/1` → `{:error, :release_timeout}`. Grep every caller of the
  release function and keep their behaviour for `:ok`; make each handle the new
  error by treating the lease as still held (the safe reading).
- When the guardian enters `:reaping` for the nil/remote-no-request cases, emit
  `Aiur.Alerts` `workspace_lease_retained` once per lease (identifier, provider,
  since). Store `since` on the lease entry it already keeps.
- `WaitingReason.for_running/1` returns `:workspace_retained` when the lease is
  in that latch (vs `:workspace_ownership_waiting` for a normal wait). Owner:
  `Aiur.Workspace.Ownership`; recovery text names the existing command the
  operator uses today (find it in `website/docs-app/guide/`; do not invent one).

## Implementation steps

1. Callers of release: `rg` and adjust; change `timeout_result`.
2. Alert on latch entry; `since` on the entry.
3. Reason + `describe/2` row (U2-T04).
4. Tests: keep the latch assertions; add the new ones.
5. Docs: add the reason to the page that lists waiting reasons (if one exists;
   else the `agents` sample in `reference/cli.md`).

## Non-happy paths

- **Release succeeds late after timeout:** next guardian pass sees it released
  and clears the reason; alert is not repeated.
- **Many leases latch at once (reboot):** one alert per lease, rate-limited by
  `Aiur.Alerts`' existing dedupe (check the key used).

## Compatibility and rollout

Behaviour change only for the timeout return; callers adjusted in the same PR.
Rollback: revert.
