## 1. Identity and outcome

- Bucket 2, feature MP-E8 (continuous build history home page), chunk C13
  (history classification backfill, E8-D10), ticket T02.
- **User value.** After the backfill agent (C13-T04) has classified past
  tickets locally and a person has confirmed them, the Executor can, if they
  want, make those classifications visible on GitHub as `feature:<slug>` labels
  (and, with a flag, the epic's matcher label such as `bug`). The writes run
  slowly in the daemon under an explicit hourly ceiling well below the agent
  core budget, stop on a GitHub budget hold, survive a restart, and can be
  paused and resumed. The number of writes is shown before anything is written.
- **Deliverable.**
  1. PROPOSED `src/lib/aiur/build_order/history/label_backfill.ex`
     (`Aiur.BuildOrder.History.LabelBackfill`): one GenServer, idle unless its
     checkpoint says `running`. It selects eligible items (§4.3), writes one
     label per token from an hourly bucket (§4.4), records every outcome in a
     checkpoint file (§4.5), and reports `plan/1` and `status/0`.
  2. PROPOSED `src/lib/aiur/build_order/history/label_backfill/rules.ex`: pure
     functions for eligibility (§4.3 table) and the write-result table (§4.4),
     so the rules are unit-tested without a process.
  3. PROPOSED `Aiur.AgentControlCLI.history_label_writes/1` (in
     `src/lib/aiur/agent_control_cli.ex`, inside `guarded/2`) and the
     `label-writes` action of the `aiur history` engine command (C13-T01 adds
     `cmd_history` for `export`).
  4. One supervised child line in `src/lib/aiur.ex`.
  5. Docs: `website/docs-app/reference/cli.md` (the command) and one short
     paragraph in `website/docs-app/apis/github.md` "API budgets" (`:314`).
- **Non-goals.**
  - Classification itself (C13-T04) and the confirm action (C13-T03).
  - Label projection for normal joins and leaves (C6-T02). This ticket writes
    only for memberships C6-T02 holds as `:held_backfill` (C6-T02 §4.2:
    `backfill-agent` joins; only this ticket releases them), and only once
    they are confirmed. Imported (`import:*`) members stay `:exempt` for ever
    (C6-T02 §4.2, options §2.8).
  - Removing labels. A later leave of a member this ticket labelled is a normal
    C6-T02 leave (`:labelled` → `:pending_unlabel`). Epic labels are never

### 4.2 Items

One item is one label on one ticket:

```elixir
%{ticket: pos_integer(), kind: :feature | :epic, label: String.t(),
  slug_or_epic: String.t()}
```

Feature items: label `"feature:" <> slug`. Epic items (only with
`--epic-labels`): label = the first entry of the epic's `labels` list. An epic
with no matcher (a feature epic, `unsorted`, or a configured epic with an empty
list) yields no item; the plan counts it under `skipped.no_matcher`.

### 4.3 Eligibility (pure, `Rules.eligible/3`)

Input: the candidate, its History row (or `:unknown`), and the run's settings.
Checked in this order; the first match wins.

| # | Condition | Result |
| --- | --- | --- |
| E0 | `snapshot/1`, `label_states/1` or `EpicOverrides.all/1` returned `{:error, _}` for this candidate's source | `defer :registry_unknown` (never "not an item"; `plan` shows that count as `unknown`) |
| E1 | Feature candidate whose `label_states/1` state is not `:held_backfill` | not an item (C6-T02 owns it; imports are `:exempt` and never items) |
| E2 | `confirmed == false` | `skip :unconfirmed` |
| E3 | History row missing, `rows/2` returned `{:error, _}`, or `health.state != :healthy` | `defer :history_unknown` (never "absent"). Gate on `state`, not `ProviderHealth.usable?/1` (`lifecycle.ex:47-51`), which also needs `complete?` and would block until the whole History backfill ends (C6-T02 review log item 4) |
| E4 | `row.lifecycle.state == :unknown` | `defer :state_unknown` |
| E5 | `row.lifecycle.state == :open` | `skip :open` |
| E6 | `row.labels == :unknown` | `defer :labels_unknown` |
| E7 | label already in `row.labels` (case-insensitive) | `done :already_present` (feature: also `mark_labelled(slug, n, %{written_at: nil, seen_at: row.observed_at})`) |
| E8 | otherwise (also when `row.labels_complete == false`: the label may be past the first 100, and the repeated `POST` is idempotent) | `write` |

`defer` items are re-evaluated on every tick; `skip` items are counted and left
alone; `done` and written items are final in the checkpoint.

### 4.4 Pacing and the write loop

- **Ceiling.** `--per-hour N`, default **60** (C13-T00 reports hours at 60
  and 125). Maximum: half the effective
  `agent_core_limit_per_hour` from `Budget.guard_settings/1`, or 125 when that
  limit is 0 (disabled). A value above the maximum or below 1 is refused
  (exit 64 in shell for non-integers, exit 1 from the RPC for out-of-range).
  60/h plus C6-T02's own 200/h bucket (C6-T02 §4.4) stays under GitHub's
  secondary limit of 500 content-creating requests per hour (MP-E1 F11).
- **Bucket.** The checkpoint keeps the timestamps of the writes made in the last
  rolling hour. A write is allowed when fewer than `N` timestamps are younger
  than one hour. The timestamp is **reserved and saved before** the request, so
  a crash between the request and the save can never exceed the ceiling (the
  repeat write is idempotent). `ensure_labels` calls count against the same
  bucket.
- **Tick.** Every 60 s while `running`, and on start or resume: if
  `now < hold_until`, do nothing; else take eligible items oldest ticket first,
  write while the bucket allows, saving the checkpoint after each outcome.
- **Just before each write**, re-read `owner/2` (feature) or the override
  (epic). If the ticket left the feature, moved to another one, became
  unconfirmed, or its epic changed, the item becomes `skip :changed` and no
  write is made (EC-13).

Write-result table (pure, `Rules.on_result/2`):

| Result | Effect |
| --- | --- |
| `:ok` | item `written` with `at`; feature: `mark_labelled(slug, n, %{written_at: at, seen_at: at})`. `{:error, :not_held}` (C6-T02 already moved it) is accepted; `{:error, {:not_member, _}}` (it left between write and mark) is recorded as `written`, `projection: :left`; any other mark error (`:projection_state_unavailable`) records `written_unmarked`, and the mark (not the write) is retried each tick until one of these answers |
| `{:error, {:github, :local_hold, %{hold: %{reset_at: %DateTime{} = t}}}}`, or the wrapped `{:github, :transport, %{reason: {:aiur, :locally_held, %{reset_at: %DateTime{} = t}}}}` | `hold_until = t`; `status.writes = :held`; item unchanged; attempts unchanged |
| `{:error, {:github, :rate_limited, d}}` | `hold_until = now + d.retry_after` s when it is an integer, else `DateTime.from_iso8601(d.reset_at)` when it parses, else the 15 min fallback below; `:held` |
| a local hold with no `reset_at` (`reason: :github_budget_broker_timeout`); from `ensure_labels`: `{:github_api_status, s, _}` with `s` 429, or `{:github_api_request, {:aiur, :locally_held, _}}` (C6-T02 §4.4) | `hold_until = now + 15 min`; `:held` |
| `{:error, {:github, :auth, _}}` (401), `{:error, {:github, :http, %{status: 403}}}` (a 403 that is not a rate limit, `errors.ex:112`), or from `ensure_labels` `{:github_api_status, s, _}` with `s` 401 or 403 | run state `:stopped` with `stop_reason: :auth` or `:forbidden`; nothing more is written until `resume` |
| `{:error, {:github, :http, %{status: s}}}` with `s in [404, 410]` | item `failed :gone`, not retried |
| `{:error, :unsupported}` (tracker has no labels) | run `:stopped`, `stop_reason: :unsupported` |
| any other error | attempts + 1, retried on later ticks; at 5 → `failed` with `last_error` |

Every attempt, successful or not, used a bucket token, so the ceiling bounds
**requests**, not successes.

### 4.5 Checkpoint

A JSON file at PROPOSED `<state dir>/build-order/history-label-writes.json`,
written with the `progress_retention.ex` pattern (temp file, fsync, rename;
symlink and size checks; a corrupt file is quarantined).

```json
{"v": 1, "repository": "owner/repo",
 "run": {"state": "running", "per_hour": 60, "epic_labels": false,
         "started_by": "cli:kevin", "started_at": "2026-10-20T09:00:00Z",
         "expect": 812, "hold_until": null, "stop_reason": null},
 "window": ["2026-10-20T09:01:00Z", "..."],
 "items": {"1234/feature:history": {"status": "written", "at": "...", "attempts": 1},
           "1240/bug": {"status": "failed", "reason": "gone", "attempts": 1}}}
```

`run.state` is one of `idle`, `running`, `paused`, `stopped`, `finished`.
With no file the state is `idle`. A corrupt file, an unknown `v`, or a
different `repository` makes the job **unavailable**: it writes nothing and
`status` says why; it never starts fresh on its own, because a fresh start
would forget the window and could exceed the ceiling.

### 4.6 Commands

```text
aiur history label-writes plan   [--epic-labels] [--json]
aiur history label-writes start  --expect <n> [--per-hour <n>] [--epic-labels] [--json]
aiur history label-writes pause  [--json]
aiur history label-writes resume [--json]
aiur history label-writes status [--json]
```

- **plan** writes nothing. It prints, from the same `Rules` the job uses:
  `writes` (feature and epic separately), `ensure` calls, `skipped` and
  `deferred` by reason, hours at the chosen ceiling (`writes / per_hour`,
  rounded up), and the C13-T00 cost line ("measured 1 core request per write,
  census 2026-10-xx"). Any source that cannot be read (History, registry,
  overrides) makes the matching count `unknown` and the line names the source;
  the total is then `unknown`, never a partial sum shown as the total.
- **start** refuses unless the planned `writes` is known and `≤ --expect`.
  `--expect` is the number the operator read in `plan`. This is the "measured
  cost stated before it runs" (E8-D10). It refuses when a run is already
  `running`, `paused` or `stopped` (use `resume`), and in an agent workspace.
- **pause** sets `paused` (saved before the reply). An in-flight write finishes
  and is recorded; no new write starts.
- **resume** sets `running` from `paused` or `stopped`. It clears
  `stop_reason` but not `hold_until`. Refused in an agent workspace.
- **status** prints run state, ceiling, writes in the last hour, `hold_until`
  with its remaining time, counts by item status, `last_write_at` **with its
  age** ("12m ago"), and the History `observed_at` with its age. `--json` emits
  the same with `observed_at`, `age_ms` and `freshness` (AGENTS.md: a computed
  age is rendered). An unavailable job prints `unavailable (<reason>)`, never
  `idle` or `0 written`.

Exit codes follow the engine: 0 ok, 1 refused or failed, 64 bad usage, 124
RPC timeout (outcome unknown).

## 6. Non-happy paths

- **Budget hold (EC-32).** A local hold or a GitHub rate limit stops writes
  until its reset time, persisted, so a restart does not retry early. No
  steady-state polling is added: the job reads only local stores, and while
  `idle`, `paused`, `stopped` or `finished` it makes no request at all.
- **Concurrent writers (EC-13).**
  - C6-T02 projection: its writer never picks `:held_backfill` and its
    reconcile never changes an existing entry. After this job writes, `mark_labelled/3` makes
    the entry `:labelled`; the echo then matches R5 and the member is treated
    as any other labelled member. A crash between the write and the mark
    leaves the entry `:held_backfill` with the label on GitHub; the next tick finds
    the label (E7) and makes the mark with `written_at: nil`.
  - A person adds the label on GitHub first: E7, no write.
  - A person removes a label this job wrote: C6-T02 R8 turns it into a leave
    after its settle window, the same as any labelled member. This job never
    writes that label again (the item is final).
  - The ticket leaves or moves feature, or its epic changes, between plan and
    write: the pre-write re-read gives `skip :changed`.
  - Two `start` calls: the GenServer serializes them; the second is refused.
- **Crash or restart (EC-31).** The window timestamp is saved before each
  request and the outcome after it. On boot the job resumes in its saved state;
  a write repeated after a crash is idempotent and was already counted.
- **Stale or unknown data.** Unknown History, lifecycle or labels defer the
  item (E3, E4, E6); they never become "absent" or "closed". `plan` and
  `status` show `unknown`, never 0.
- **Untrusted text (EC-30).** Slugs and epic keys come from validated stores
  (C6-T01 slug rule; C5-T01 `epic:` matchers refused). Labels are sent as JSON
  values, never interpolated into a URL. The CLI passes no free text to the RPC
  (only whitelisted words and digits).
- **Permissions.** A 401 (`:auth`) or a non-rate-limit 403 (`:http` 403)
  stops the run with the reason; nothing is retried until a person resumes.
- **Tracker without labels** (Linear, `linear/tracker.ex:139`):
  `:unsupported`, run stops, plan says the tracker cannot take labels. The
  memory tracker accepts the call (`memory/tracker.ex:109-112`), which is what
  the tests' fake tracker replaces.
- **Disk full.** A failed checkpoint save before a write cancels the write
  (no token is spent without a record); the run becomes `stopped` with
  `stop_reason: :checkpoint_write_failed`.

## 7. Compatibility and rollout

- **Opt-in.** Nothing writes until a person runs `start`. Default state
  `idle`. No config key, no migration.
- **Rollback.** `pause`, or remove the child line. Labels already written stay;
  a person removes `feature:` labels through `aiur feature remove`, which
  C6-T02 projects as unlabels.
- **Docs in this PR** (AGENTS.md "Docs ship with the change"):

## 10. Decisions made without the owner

1. **Own small writer, not C6-T02's.** C6-T02 paces 20 per minute and 200 per
   hour (C6-T02 §4.4); 200 is not "well below" the 250 agent core default, it
   has no epic labels, no pause and resume, no count shown before it starts,
   and no hold that survives a restart. This job keeps no projection state of
   its own: it hands each written member to C6-T02 through `mark_labelled/3`
   (CR-1) and uses the same error taxonomy.
2. **Ceiling is a flag, default 60/hour, maximum half the agent core limit
   (125 at the default 250).** No config key: the job is a one-off and a key
   would need docs and templates for a value used once. 60/hour is a quarter of
   the agent core default and 2 % of the daemon's.
3. **`--expect` makes the measured cost a precondition.** `start` cannot run
   more writes than the operator read in `plan`.
4. **Closed tickets only.** `required_ticket_labels` may hold any non-lifecycle
   label (C6-T02 §3), so a label on an open ticket can change dispatch. Open
   tickets that a person joins with the CLI are labelled by C6-T02. A
   `backfill-agent` join of an open ticket stays `:held_backfill` after a
   confirm, so it gets no label from either ticket; a person who wants one runs
   `aiur feature remove` then `aiur feature add`, which C6-T02 projects.
5. **Epic labels write the epic's first matcher** and only with
   `--epic-labels`. Epics with no matcher are skipped.
6. **Epic labels are never removed** by this job. A later override change is
   not projected; the page is unaffected because an override wins over a
   matcher (C5-T02).
7. **Any confirmed override counts,** not only backfill-origin ones, because a
   human `aiur epic set` is also a confirmed classification. Feature items are
   limited to confirmed `:held_backfill` entries, because C6-T02 already
   labels every other join and keeps imports `:exempt` on purpose. The source
   is not required to be `backfill-agent`: a confirm rewrites it to
   `cli:<who>` (C13-T03 §4.4); the `:held_backfill` state, not the source,
   marks a backfill join.
8. **A hold with no reset time waits 15 minutes.** `LocalHold.run/2` waits at
   most 60 s in-line; a background job can wait longer without holding a
   caller.
9. **No daemon-wide budget read before each write.** `Budget.usage/1`
   returns `%{actors: []}` when the broker is absent, which cannot be told from
   "no usage"; the ceiling plus the hold pause is the honest bound.
10. **Refused in agent workspaces** (start and resume) with exit 1, following
    `test_reset.ex:84-90`. This is an Executor action that writes to GitHub.
    `pause` and `status` stay allowed: they only stop or read.
11. **One label per request.** Reuse `Aiur.Tracker.add_label/2` rather than add
    a multi-label call to the tracker seam. With `--epic-labels` a ticket
    costs up to 2 requests; `plan` counts requests, not tickets (CR-2).
12. **A 403 that is not a rate limit stops the run.** REST answers it as
    `{:github, :http, %{status: 403}}`, not `:permission` (`errors.ex:112`,
    `:138`). Retrying it 5 times per item would spend the ceiling on a
    credential that cannot write.

Uncertainty to settle in implementation: whether `POST /issues/:n/labels` with
a downcased matcher (`bug`) applies an existing label named `Bug` or creates a
second one. GitHub label names are documented as case-insensitive for lookup;
verify with one sandbox write and record the result in the PR. If it creates a
new label, use the casing seen in History's label observations instead.
