# U3-T01 - Ordered replay of the stalled buffer

> This is the "U3-event-subscription-delivery (events-webhooks-executor-01)"
> pseudo-predecessor of MP-R2-C2-T01, and the first of the "U3 ordered-replay
> and claim tickets" that MP-R1 step S3 follows.

## Identity and outcome

- Bucket 1, prior unit U3. Acceptance example AE2.
- **User value:** a subscriber that stalls on one event and then recovers
  receives every buffered event, in order; none is silently dropped behind a
  newer one.
- **Deliverable:** `resolve_stall/2` delivers the buffered events inline, in
  id order, before returning to the mailbox; a regression test with a newer
  event already queued.
- **Non-goals:** no change to dead-letter policy, cursor format or the
  `Aiur.Events.Delivery` seam (MP-R2-C2-T01 builds that on top).

## Dependencies and blockers

- U0-T01. Concurrent with U3-T02.
- MP-R2-C1-T02 (out-of-order id witness) may run first; its result is an
  input finding here, not a predecessor.

## Verified starting point (`58854d4c8`)

- `src/lib/aiur/events/subscription_store.ex` (748 lines):
  `handle_info({:event, _})` (:385-413) drops an event with id ≤ cursor
  (:398-400) **without a log**; while stalled it buffers (:402-408,
  `buffer_event/3` :475-477).
- Retry `handle_info({:retry_stalled})` (:417-440) → on success or dead-letter
  `resolve_stall/2` (:484-492) advances the cursor via `advance_cursor_inline`,
  then `send(self(), {:event, buffered})` per buffered event (:487-489). A newer
  event already in the mailbox is handled first, moves the cursor past the
  buffered ids, and they are dropped at :398.
- Stall set up in `process_new_event/4` (:444-473). Last logic change
  `8e546810b` (#1409); #2967 only shifted lines.
- Tests `test/aiur/events/subscription_store_test.exs:365`, `:401` never queue
  a newer event ahead of the self-send.

## Chosen design

- In `resolve_stall/2`, replace the self-send loop with an inline loop over the
  buffer in id order, calling the same `process_new_event/4` used for live
  events. If a buffered event stalls again, stop the loop and keep the rest of
  the buffer (still stalled) - same state as today's first stall.
- At :398-400, log at debug with subscriber and id when an event at or below
  the cursor is dropped (cheap evidence; no alert).

## Implementation steps

1. Inline ordered drain in `resolve_stall/2`; remove the self-send.
2. Debug log on drop.
3. Test below; keep existing tests green.

## Non-happy paths

- **Re-stall during drain:** remaining buffer stays; retry timer re-armed as in
  the first stall.
- **Dead-letter during drain:** same path as live (cursor advances past it, one
  dead-letter record).
- **Very large buffer:** the existing buffer bound applies unchanged; the drain
  is bounded by it.

## Compatibility and rollout

No config. Rollback: revert.
