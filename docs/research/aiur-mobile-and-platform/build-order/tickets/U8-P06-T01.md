# U8-P06-T01 — Make one canonical publication script tree and split its modules

## Identity and outcome

- Bucket 1, unit U8 (file-size debt), package `BO_PUBLISH`, chunk `U8-P06`.
- **User value:** one publisher instead of two drifting copies, so a fix to Build Order
  publication lands once. Removes about 10,800 lines of debt, about 2,700 of them pure
  duplicates.
- **Deliverable:** `.claude/skills/aiur-build/scripts/publication/` is the only source of the
  `publication_*` modules. The `docs/build-order/scripts/publication_*` files become thin
  import wrappers (as `docs/build-order/scripts/publication_operator.py` already is, 21 lines)
  or are deleted. `Publisher` (in `publication_operator.py`) and `publication_rendering.py`
  split by stage. The three execution-amendment and progress scripts split by stage. The two
  oversized test files split by concern. The publication test suites run in CI.

  publication budgets or `build-order.json` (that is `U8-P06-T02`).

## Chosen design

| PROPOSED path (skill tree `.claude/skills/aiur-build/scripts/publication/`) | Takes | Est. lines |
| --- | --- | ---: |
| `publication_client.py` | `PublicationError`, `Client`, `Budget`, `GhClient` | 120 |
| `publication_materialize.py` | atomic bundle write, staged replace, transaction recovery, `_fsync_directory`, `_atomic_write_json`, materialized and discovery writes | 330 |
| `publication_mappings.py` | canonical and persisted mappings, ownership validation | 300 |
| `publication_relationships.py` | relationship ensure, ids, live issue identity and authority | 280 |
| `publication_operator.py` | `IssueSpec`, `Context`, `Publisher` (dry run, apply, finalize, receipt and authority checks, comments) calling the modules above, `build_context`, `main` | 480 |
| `publication_rendering.py` split into `publication_rendering.py` (body assembly) and `publication_rendering_sections.py` (section renderers) | by its top-level functions | ≤ 450 each |

`Publisher` keeps its public methods; moved private methods become module functions that
take the `Publisher` fields they read as arguments (no mixin inheritance).

`docs/build-order/scripts/publication_{rendering,live_graph,receipt_authority}.py` become
wrappers like the existing operator wrapper (`sys.path.insert` of the skill tree, then
`from publication_x import *`), or are deleted if `git grep` finds no direct runner.
`execution_amendment.py` → `execution_amendment.py` (schema and validation) and
`execution_amendment_render.py` (render and parse). `execution_amendment_live.py` →
`execution_amendment_capture.py` and `execution_amendment_compare.py`.
`capture_progress_estimates.py` → move parsing helpers to `progress_estimate_parse.py`.
Tests split along the same modules.

CI: add a step to the required job that already runs skill script tests (`ci.yml:185-189`):
`python3 -m unittest discover -s docs/build-order/scripts/tests` and the skill
`scripts/tests` suite.

## Non-happy paths

- Atomic write and transaction recovery protect the published bundle from torn writes.
  Keep `_recover_materialization_transaction` and `_fsync_directory` together with the
  writers in one module, and keep the order of fsync calls.
- `sys.path` wrappers resolve from `__file__`; keep `parents[3]` correct after any move.
- The new CI step could fail on first run because the suite has not run in CI before.
  Run it locally first; if a test needs network or `gh`, mark the reason and skip it
  through the existing test pattern, do not delete it.
- Rendered body bytes are receipt inputs (`body_sha256` in `build-order.json`). A changed
  byte breaks receipts. The rendering split must keep output identical (see Verification).
