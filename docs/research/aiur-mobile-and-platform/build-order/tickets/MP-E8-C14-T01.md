## Identity and outcome

- Bucket 2, feature MP-E8 (continuous build history), chunk C14 (later-wave
  upgrades).
- **User value.**
  - A ticket keeps its conversation after the ticket closes and after its
    workspace is cleaned. Today "Conversation not retained" (S-6) appears for every
    past ticket whose workspace is gone. After this ticket it appears for tickets
    that closed before the journal existed (README row: "retained from then on";
    see Interface note 1 for the cost).
  - Event rows (`.cv-ev`) sit where the event happened in the conversation, from
    MP-E4 anchors, not from a time merge. A minimap tick (`.mm-e`) jumps to that
    place.
  - Successful commands and file diffs show in the log, as the design shows them.
    The wave-0b log had neither (C11-T03 Interface note 7).
- **Deliverable.**

     behaviour (C11-T03) over `Aiur.Conversation.History` (MP-E4-C2-T01).

     turns one History page (entries, sessions, anchors) into the design items
     (`say op sys tool diff ev`), in display order, with stable ids.
  3. BuildLive: the live tail moves from the 1 s file poll to the History PubSub
     topic. The poll timer and the generation-handle resubscribe are deleted.
  4. Payload (C3-T02's module): one new message kind, `conversation-insert`;
     two new fields, `alt` on `op` entries and `unplaced` on `conversation`;
     the `diff` entry shape `{id, k: "diff", at, file, add, del, lines}` (C11-T03
     accepted it only from the fixture); the `note` enum becomes
     `null | "imported"` and `evicted` is removed.
  5. Client: small additions in C11-T03's `conversation.js`: `insertEntries`,
     the `alt` replace rule in `appendEntries`, the duplicate skip in
     `prependEntries`, and one `conversationApplied` case in C11-T05's `live.js`.
     The `legacy_log`, `remote_window` and `live_window` note branches are deleted.
  6. Deletions: `ConversationSource.Wave0b`, `Aiur.AgentLog.PageReader`,
     `AgentLog.structured_entry/1` (all three are C11-T03 PROPOSED; delete when

## Chosen design

### The source

```elixir
defmodule AiurWeb.Build.ConversationSource.Journal do   # PROPOSED src/lib/aiur_web/build/conversation_source/journal.ex
  @behaviour AiurWeb.Build.ConversationSource
  alias Aiur.Conversation.{History, Ref}
  alias AiurWeb.Build.ConversationSource.JournalMapper

  @limit 100
  @shown_kinds ~w(message command tool_result diff operator_message system gap)a   # no :reasoning (Decision 4)
  @max_reads 3                                                                     # per request, empty-page guard
  # tail(ref, nil, opts)    -> newest page
  # tail(ref, cursor, opts) -> entries after the cursor (used only after a reset or a bottom trim)
  # page(ref, cursor, opts) -> page before the cursor
  # subscribe(ref, opts)    -> History.subscribe/1
  # unsubscribe(ref, opts)  -> Phoenix.PubSub.unsubscribe(Aiur.PubSub, "conversation:" <> id)
end
```

`opts[:principal]` is required and comes from BuildLive (Decision 7). Every History
call goes through a local copy of the `call_conversation/3` shape
(`dashboard_live.ex:2327-2335`), so a raise or exit becomes
`{:error, :unavailable}`. The `:other_repository` reason of Wave0b is not
produced: the conversation id comes from `TrackerIdentity.github_key/1`, which
includes owner and repository, so no read can reach another repository's data.

### State rules

| Ticket | History result | `state` | `live?` |
| --- | --- | --- | --- |
| identity `nil` or `Ref.worker/1` → `{:error, :unjoinable}` | not called | `:unavailable`, `reason: :unjoinable` | false |
| not running | `{:error, :not_found}` | `:not_retained` (S-6) | false |
| running | `{:error, :not_found}` | `:known_empty` (no entry written yet) | true |
| running | page | `:live`; `:restart_unknown` when the newest session has `end_reason: "daemon_restart_unknown"` and no later session | true for `:live` |
| not running | page | `:ended` | false |
| any | `{:error, :unavailable}` on the first read of this modal | `:unavailable`, `entries: []` | false |
| any | `{:error, :unavailable}` after an earlier success in this modal | `:stale`, `observed_at` = the last successful read | false |

"Running" is the same server-side lookup C11-T03 uses (C8-T04's
`running_entry(identity)`). Only its presence is read now.

**Progress percent.** MP-E4 anchors carry no percent (Interface note 5). The
mapper uses `subject_ref.percent` when an integer 0..100 is there; else the
percent that C11-T04 row 1 joins by `event_id` from the ticket history snapshot
(reuse C11-T04's join function, input `event.event_id`); else `pct: nil`. Without
this fallback every progress row would lose the percent that wave 0b shows, which
breaks "the UI does not change".

| 12 `agent.state == "command"` with no decision | kept, condition becomes "no `command_requested` anchor without a later `command_resolved` for the ticket" | current-fact rows |
| 13, 14 paused, parked; 15, 16 error, retries | kept | current-fact rows |
| 17 live "Resumed" | kept | live append only, as C11-T04 §4.5 |

C11-T04's §4.5 debounced re-read stays for the kept rows. No event shows twice.

**Times.** `at` = `occurred_at` when present. Otherwise `observed_at`, except in an
`import` session, where `observed_at` is the import time and `at` is `nil` (C11-T03
renders "Time unknown").

**Display order.** For each entry in `pos` order: its session row (if the session
starts here), the entry, then the anchors at this `pos` (both `at` and `after`),
sorted by `event.observed_at`, then `event_id`. Unanchored anchors (`pos: nil`)
are not rows. Their count is sent as `unplaced`.

**Ids** (stable, and every id is a valid page cursor):

| Row | `id` | Cursor value for `before` |
| --- | --- | --- |
| entry | `"p:<pos>"` | `pos` |
| session row | `"s:<first_pos>:<session_seq>"` | `first_pos` |
| anchor row | `"a:<pos>:<event_id>:<kind>"` | `pos + 1` |
| C11-T04 row (table above) | `"e:<pos>:<C11-T04 id>"` (`pos` 0 for dependency rows) | `pos + 1` |
| reasoning placeholder (empty-page guard) | `"r:<cursor>"` | `cursor` |

The parser reads only the prefix and the second field (an `event_id` or C11-T04
id may itself contain `:`), and accepts the value only when `1 ≤ value ≤
head_pos + 1`. Any other value is `invalid_params` (C3-T02 error reply).

A `pos + 1` cursor re-reads entry `pos` and its anchors. That happens when a top
trim leaves an anchor row first while its entry was trimmed. The client skips
rows of the earlier page whose `data-eid` is already in the log (Client
changes), so the entry comes back once and the anchors do not double.

### Paging

- First view: `list_entries(ref, tail: true, limit: 100, kinds: @shown_kinds,
  principal: p)`, `list_sessions(ref)`, `list_anchors(ref, pos_range: {first,
  last})`.
- Older: the same with `before: cursor`.
- `more?` = `prev_cursor != nil`. `before` = the id of the first row.
- **Empty-page guard.** A `kinds` read scans at most 5,000 entries
  (MP-E4-C2-T01), so a page can have zero rows while `prev_cursor` is set. Only
  `reasoning` is filtered out, so such a page is all reasoning. C11-T03's loader
  asks again only on a scroll event, and an empty prepend makes none, so the log
  would stop. The source reads up to `@max_reads` pages until it has at least one
  row. If it still has none and `prev_cursor` is set, it returns one `sys` row
  `"Reasoning not shown"` with id `"r:<prev_cursor>"` and `more?: true`, so the
  next scroll continues from there. No request scans more than 15,000 entries.
- `gap` on `conversation-append` is always `false` (no projection window).
- `note: "imported"` when `complete_from_start` is false and `more?` is false. The
  client then shows, as the first child of `#cv-log`, the `.cv-end` row
  "Earlier history was imported and may be incomplete" (no `data-k`).
- `unplaced > 0` with `more?` false → the `.cv-end` row "N events could not be
  placed in the conversation" (no `data-k`), above the imported row.

### Live updates (BuildLive)

1. On open: `subscribe(ref)` **first**, then the first `tail` read; keep
   `conversation_head` = the highest `pos` sent and `conversation_events` = the
   set of `event_id`s sent.
2. `{:entries_appended, cid, entries}` for the open conversation: the raw list
   stays bound (C14-T02 reads it in this handler); mask a copy with
   `History.mask_for(entries, principal)`, drop `pos <= conversation_head`, map,
   push `kind: "conversation-append"`, then flush any held anchors (item 3) whose
   `pos` is now `<= conversation_head`.
3. `{:anchor_added, cid, anchor}`: skip a not-shown kind and an `event_id` already
   sent. Then:
   - `pos == conversation_head` → `conversation-append`;
   - first loaded `pos ≤ pos < conversation_head` → `conversation-insert` with
     `after` = the id of the last row at that `pos` (`"p:<pos>"` or the last anchor
     row already there);
   - `pos > conversation_head` (the anchor broadcast beat its entry) → hold it in
     `conversation_held` (at most 50; beyond that, drop the oldest, which the next
     full read restores) until item 2 reaches that `pos`;
   - `pos` older than the loaded range, or `nil` → nothing (it arrives with that
     page, or as `unplaced`).
4. `{:session_changed, cid, session}`: a new session → append its `sys` row; then
   re-derive the state and push `conversation-state` when it changed.
5. The 1,000 ms poll, its timer assign, and the handle-change resubscribe from
   C11-T03 are deleted. The conversation id is per ticket, so a new generation of
   the agent writes to the same conversation.
6. `conversation-close` and a first view for a different id call
   `unsubscribe(ref, opts)`. No `terminate/2` is needed: the subscription dies with
   the LiveView process (as C11-T03's timer did).

### Messages (v1 envelope; changes to `Payload.validate/1`)

```json
{ "v": 1, "kind": "conversation-insert", "id": "123", "after": "p:41",
  "entries": [{ "id": "a:41:98812:pr_opened", "k": "ev", "ev": "pr", "at": 1791431544512,
                "label": "Opened PR #51" }] }
```

- `op` entries may carry `alt` (string).
- `diff` entries: `file` string, `add`/`del` non-negative integers, `lines` a list
  of ≤ 42 `[sign, text]` pairs with `sign ∈ {"+", "-", " "}`. The validator rejects
  any other shape, because the design inserts `add`/`del` without `esc` (J:1349).
- `conversation` gains `unplaced` (non-negative integer). `note` is
  `null | "imported"`; `evicted` is removed.
- `conversation-append` keeps `gap` (always `false`).

## Non-happy paths

- **Absent, empty or huge transcript (EC-16).** Absent for a closed ticket →
  `:not_retained`, never an empty chat. Absent for a running ticket →
  `:known_empty`. Huge → History pages by `pos` (≤ 100 entries per page, ≤ 3 reads
  per request); the DOM keeps ≤ 500 rows (C11-T03).
- **Journal unreadable** (corrupt segment, permission) → `:unavailable`, no
  entries, never a partial page that looks complete (MP-E4-C2-T01 rule). After an
  earlier good read → `:stale` with the age of that read (AGENTS.md: a computed age
  is rendered; C11-T03's footer renders it).
- **Untrusted text (EC-30).** `meta.tool`, bodies, diff text and file titles are
  agent data. All reach the DOM through the C11-T03 port's `esc`, including
  `name`, which the design itself does not escape (J:1348). `add`/`del` are
  integers checked by `Payload.validate/1`.
- **Anchor before its entry.** A held anchor (Live updates item 3) is shown when
  its entry arrives; it is never placed at a guessed position.
- **Unknown values never look known.** Unknown percent → "Progress updated" and
  `.mute` (C11-T04 §4.3), never "0%". Unknown exit code → empty `res`, never "✓". Unknown PR number →
  "Opened PR", never "#nil" or "#0". Unknown time → `at: nil`, never the import
  time or `now()`.
- **Privacy.** History masks by principal (contract §7). The modal sends a subset
  of what MP-E4's full view shows to the same principal: no command or tool
  `output`, no `provider_input` body, no reasoning, no `locator_hash`, no paths, no
  `conversation_id` (it stays server side). `reveal` is never passed.
- **Operator provenance (security M6).** Only `operator_message` with role
  `operator` becomes `op` ("You"). A `provider_input` record becomes "Provider
  input", never "You".
- **Cursor tampering.** Only the four id shapes; out-of-range values are
  `invalid_params`; a cursor never selects another conversation (the conversation
  comes from the open modal's ticket).
- **Race between subscribe and first read.** Subscribe first; drop live entries
  with `pos <= conversation_head` (the contract §7 reconnect rule). A live entry
  older than the head cannot appear twice.
- **Precision upgrade.** An `exact` anchor that follows an `observed` one for the
  same event is not pushed live (its `event_id` was sent). The next full read uses
  the strongest anchor (Decision 8).
- **Disconnect and reconnect.** C11-T01 re-opens the ticket; this ticket sends a
  fresh `conversation` message; the client drops messages for another modal id.
- **PubSub down.** `Aiur.PubSub` restarts take subscribers with them
  (`lib/aiur.ex:87-102` comment); BuildLive restarts and re-opens, as for any
  LiveView subscription.
- **Two tabs.** Each LiveView has its own head and event set. Reads are
  idempotent.
- **Remote workers.** Covered: MP-E4 tees daemon-side, so the `remote_window` note
  is gone.

## Decisions made without the owner

1. **The journal is the only source.** No fallback to workspace files for
   tickets that closed before the journal shipped; they show S-6. A fallback
   would keep Wave0b, PageReader and the 1 s poll alive, which the README row
   deletes. The importer (MP-E4-C8-T01) covers tickets that run again.
2. **The modal shows a subset of what MP-E4's full view shows to the same
   principal.** This replaces C11-T03's "less than the drawer" rule. Successful
   commands and diffs are now shown (the design has them); command and tool
   output, reasoning and provider-input bodies are not.
3. **DESIGN-E4's default visibility is not applied in the modal.** The E8 design
   shows its event kinds always, and the modal has no event filter.
4. **Reasoning is not shown** in the modal: the design has no reasoning item.
   The full page (C14-T03) shows it per DESIGN-E4 decision 3.
5. **Unknown percent reuses C11-T04's rendering** (`pct: null`: "Progress
   updated", class `mute`, no `--eh`). An earlier draft added a `mute` field and
   `--eh: 0`; that would change C11-T04's look, which "the UI does not change"
   forbids.
6. **No row for `ci.passed`, `command_resolved`, `executor_progress`, or a
   `phase` topic other than `agent.progress.phase` and the review start/end.**
   The design has no event row for them. `attention` uses the `fail` row, except
   `agent.blocked`, which keeps C11-T04's `dep` "Blocked" row.
7. **Principal and reveal.** BuildLive passes the dashboard principal that MP-E4's
   view uses (`{:operator, :loopback | :basic_auth}` from the session) and never
   `reveal`. The design has no "show raw" control or masked badge; masked text
   shows its `[REDACTED:…]` marker inline.
8. **Anchor upgrades are not moved live.** A row keeps its first position until
   the next full read.
9. **Labels use the design's wording where the fact is known** ("Opened PR #N",
   "Asked a blocking question") and plain facts where it is not ("Pushed
   <sha>", "Merged PR #N" without "into main", no `sub`).
10. **Diff rows show at most 40 lines** with an "… N more lines" line. The full diff
    is on the full page.
11. **Unanchored events are a count row, not rows**, so they are not lost and not
    placed at a guessed position.
12. **An all-reasoning stretch shows one "Reasoning not shown" row** after three
    reads (≤ 15,000 entries scanned), so paging never stops and a request stays
    bounded.
13. **An anchor that arrives before its entry is held** (≤ 50 per modal) and shown
    when the entry arrives.
