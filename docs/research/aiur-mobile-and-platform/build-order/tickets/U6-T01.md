# U6-T01 - Decision journal outcome matrix

> Answers the `U6-decision-journal` / "U6 journal outcome matrix (prior unit)"
> pseudo-predecessors of MP-R1-C5-T01 and MP-R1-C8-T02, and the S1/S10 rows of
> MP-R1 migration-plan §3.

## Identity and outcome

- Bucket 1, prior unit U6 (KTD5, KTD10).
- **User value:** a decision (an Executor answer, a blocking question) is
  never silently lost and never recorded twice when the disk misbehaves; the
  Executor sees an attention when a write fails.
- **Deliverable:** an injectable append seam in `DecisionLog`; a classifier
  that maps each append result to `:accepted | :failed | :ambiguous`; the store
  reconciles an ambiguous append by event ID before retry; a failed
  follow-up append is retried and alerted instead of only logged.
- **Non-goals:** no projection change (U6-T02); no fsync or file-format change;
  no rename (MP-R1-C5-T01 renames after this).

## Chosen design

- `DecisionLog.append/2` takes an optional `file_ops` (module with `write/2`,
  `sync/1`; default `:file`). Results:
  - write error before any byte → `:failed` (known);
  - write ok, sync error or timeout → `:ambiguous` (bytes may be on disk);
  - write ok, sync ok → `:accepted`.
- `DecisionLog.reconcile_ambiguous(log, event_id)` next to `append/2` (no new
  module; DecisionLog owns replay): replay the tail and look for the event ID →
  `:accepted` if present, else `:failed`. The store calls it before any retry,
  so a known-accepted append is never appended again (no duplicate decision).
- `fatal_lifecycle_append_failed/3` callers (`:4068`, `:4089`) are
  `follow_up_required`/`follow_up_handled` appends. Do **not** route them to
  `recover_background_append`: its handler (`maybe_reconcile_lifecycle_append`,
  :3816) re-runs dispatch and never re-appends. Give follow-up appends their own
  retry that rebuilds and re-appends the follow-up event (through
  `reconcile_ambiguous` first), with the same alert as `lifecycle_append_failed/5`;
  keep `writable?: false` until it succeeds.

## Implementation steps

1. `file_ops` option and result classification in `decision_log.ex`.
2. `reconcile_ambiguous/2`; call sites in `decision_store.ex` (the three
   persist paths) use it before retry.
3. Follow-up append retry + alert.
4. Tests with an injected `file_ops`.

## Non-happy paths

- **Reconcile replay itself fails:** treat as `:ambiguous` still; store becomes
  read-only for that transition and alerts (KTD10: hold the transition).
- **Torn tail after crash:** existing replay contract (unchanged).
- **Unrelated work:** proceeds only while journal health is proven (existing
  `writable?` flag).
