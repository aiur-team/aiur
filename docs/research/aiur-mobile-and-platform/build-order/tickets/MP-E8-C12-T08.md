## Chosen design

**Three phases, one register, fail closed.**

### Phase 1 — package (agent)

`signoff:mp-e8` (PROPOSED `src/browser/scripts/design-signoff.mjs`, about
150 lines) does, in order:

1. **Refuse a dirty or wrong tree.** `git status --porcelain` must be empty
   (nothing uncommitted anywhere, not only under `src/`), and
   `git merge-base --is-ancestor origin/main HEAD` must succeed. The diff
   `git diff --name-only origin/main...HEAD -- src website` may name only this
   ticket's own files (`src/browser/scripts/design-signoff.mjs`,
   `src/browser/tests/design-signoff.spec.mjs`, `src/browser/package.json`,
   `src/browser/scripts/artifact-sanitizer.mjs`,
   `src/browser/tests/harness-failures.spec.mjs`) and, in Phase 3, the
   allowlist file, where only `approval` blocks may differ (checked by
   parsing both versions). Any other path stops the run with the list.
   Reason: the package claims "this is the build Kevin saw" (AGENTS.md #2362
   wrong-checkout signature), but the ticket branch itself necessarily carries
   the script and, later, the approval flips; a rule of "no change under
   `src/`" could never pass.
2. **Record versions** (`versions.txt`): `HEAD` and `origin/main` commits,
   Chromium and Playwright versions, design etag and the three
   `design_sha256` values from C1-T01's `manifest.json`, the parity floor
   from `design-parity.mjs`, the date.
3. **Run each suite** by calling `runBrowserTests(args, env)`
   (`run-browser-tests.mjs:45`; one port and one sanitised artifact root each)
   with the same spec and `--config` arguments as the suite's npm script, plus
   `--reporter=list,json`, and with `env` = `process.env` plus
   `AIUR_BROWSER_KEEP_ARTIFACTS=1`, `PLAYWRIGHT_JSON_OUTPUT_FILE=<work>/<suite>.json`
   and, for the motion suite, `AIUR_PARITY_FULL=1`. Suites:
   `test:design-parity`, `parity:matrix`, `test:build-home-motion`,
   `test:home-css`, `test:build-home-phone`, `test:build-home-a11y`,
   `test:build-home-performance` and `perf:build-home`. Calling the runner
   directly (not `npm run`) skips the repeated `fixture:preflight`; the
   script runs `npm run fixture:preflight` once first.
   - **Forward the two names.** Add `'AIUR_PARITY_FULL'` and
     `'PLAYWRIGHT_JSON_OUTPUT_FILE'` to `inheritedRuntimeNames`
     (`artifact-sanitizer.mjs:15-34`), each with a one-line comment as at
     `:17-18`. Neither is a credential. Without this the child never sees them
     (Verified starting point), the motion spec runs its narrowed matrix and
     passes, and the package would claim a full run it did not do.
   - After each suite, run `sanitizeArtifactRoot(<work>)` on the JSON report
     directory too, since it sits outside the runner's artifact root.
4. **Collect** each JSON report into `cells.json`: one row per test with
   suite, title, cell (dataset, viewport, theme, palette, motion), status
   (`passed | failed | timedOut | skipped | fixme | expected-failure`; a
   `fixme` is a skipped test with a `fixme` annotation, an
   `expected-failure` is a test whose `expectedStatus` is `failed`), the
   annotations, diff pixel count, and the allowlist ids applied (from the
   run's annotations, which C1-T02 already writes for pending entries).
5. **Copy evidence** into `docs/research/evidence/mp-e8-signoff/<run-id>/`:
   - for each allowlist entry, the design / product / diff PNG of one cell it
     covers (the largest diff);
   - for each register item, the product-only screenshots named in its
     `evidence` list (these are already checked-in snapshots from C9–C11; the
     register points at them, nothing is captured twice);
   - C1-T03's 0/50/100 % frames for `snap.settle-near-top`, `modal.open`,
     `columns.enter-leave`, `feature.compact` and `tree.overlay`;
   - C12-T04/T05/T06 outputs: the phone screenshots, the focus and
     forced-colours screenshots, the axe summary (rule id, count per fixture),
     `build-home-perf.json` and `.md` (an `unavailable` metric stays
     `unavailable` in the summary, never `0` or pass);
   - `allowlist.json`, a copy of the allowlist at this commit.
   Total committed size is capped at 15 MB; over the cap the script fails and
   names the largest files.
6. **Archive the sanitized artifact roots and JSON reports** (out of git) as
   one `<run-id>.tar.gz` with `tar -czf` (present in the Playwright noble
   image and on the hosts; Node's `zlib` writes gzip streams, not archives),
   and write its sha256 (`node:crypto`) into `summary.md`.
7. **Write `summary.md`**: totals per suite, every non-passing test with its
   reason, every expected failure with its register item, every allowlist
   entry grouped by register item, every `unavailable` performance metric,
   and the list of unanswered items. This is what Kevin reads first.

**Package exit status.** The package run fails if any test failed, timed out
or was skipped, if any `fixme` remains, or if a check that does not need
Kevin's answers fails (G1–G4, G7–G9, G12, G14). `pending-sign-off` entries and
`answer: null` do **not** fail Phase 1. They are the questions. A red package
is not delivered. Each failure goes back to the ticket that owns the element
(C1-T03's `OWNER` map; C1-T02's region owner).

### Phase 2 — Kevin (Executor delivers)

The Executor gives Kevin `summary.md`, the evidence directory and the report
archive (for example as a private artifact). From the Executor repo root, the
Executor also adds a real-data look: `scripts/aiurdev --test`, open `/` in a
browser at 1440 and 390 px, open one running agent's modal, and save the
screenshots into the run directory as `real-*.png` (agents are blocked from
`--test`, AGENTS.md "Manual testing"). Kevin answers each register item in
writing, as a comment on the ticket (G6 needs a GitHub issue-comment URL as
`ref`; an answer written only in DESIGN-E8.md has no such URL, so the Executor
asks Kevin to post it as a comment; until then the item stays unanswered).

### Phase 3 — record and gate (agent, rework turn)

The agent copies each written answer into the register and flips the matching
allowlist entries, and **commits** both (the tree check refuses uncommitted
edits). Then `signoff:mp-e8 -- --gate --against <delivered-run-id>` re-runs
Phase 1 and adds the gate checks below. A missing `--against`, or a run id with
no committed `versions.txt` and `allowlist.json`, fails G13. The gate passes
only on a green re-run plus a complete register.

### Register schema (`items.json`, PROPOSED)

```json
{ "schema": 1,
  "items": [
    { "id": "S-9",
      "kind": "s-item",                    // s-item | oq | plan-decision
      "title": "Queue unavailable / history unavailable copy",
      "default": "Same .bd-mk.empty marker with 'unavailable' copy and the age",
      "source": ["MP-E8-C9-T13"],
      "proposed_as": null,                 // the writer's old label, e.g. "S-18 (C7-T03)" for S-29
      "allowlist": ["queue-unavailable-copy", "history-unavailable-copy"],
      "expected_failures": [],             // test.fail() titles this item explains (G14)
      "evidence": ["src/browser/tests/<spec>-snapshots/<name>.png"],
      "answer": null } ] }
```

`answer` is `null` until Kevin answers, then:

```json
{ "decision": "accept-default",          // or "replace"
  "text": "Kevin's words, verbatim",
  "by": "Kevin",
  "date": "2026-11-02",
  "ref": "https://github.com/<owner>/<repo>/issues/<n>#issuecomment-<id>",
  "follow_up": null }                    // ticket id, required for "replace"
```

### Gate checks (all fail closed)

| # | Check | Fails when |
| --- | --- | --- |
| G1 | Every suite produced a JSON report | a report file is missing or unparsable, or has zero tests |
| G2 | The matrices ran in full | `parity:matrix` did not run 61 tests; or a `test:build-home-motion` sequence ran fewer than 24 matrix cells (the sign that `AIUR_PARITY_FULL` did not reach the child) |
| G3 | Every test passed | any `failed`, `timedOut`, `skipped` (other than `fixme`, which is G4) |
| G4 | No `fixme` | any `fixme`, listed with its owner |
| G5 | No pending allowlist entry | any `pending-sign-off`, listed with its item |
| G6 | Approved entries are complete and unchanged | `by` is not `"Kevin"`, `date` is not ISO, `ref` is not a GitHub issue-comment URL, or the entry (except its `approval` block) differs from the delivered run's `allowlist.json` |
| G7 | Each allowlist entry belongs to exactly one item | an orphan, or an entry in two items |
| G8 | Each item's allowlist ids exist | a stale id |
| G9 | Item ids are unique | two items share an id |
| G10 | Every item has an answer | `answer: null`; never read as "accept default" |
| G11 | A `replace` answer is done | `follow_up` is empty, or its allowlist entries are still present |
| G12 | Evidence paths exist | a listed file is missing |
| G13 | Design source unchanged since the package | no `--against` run, or C1-T01's `design_sha256` values differ from that run's `versions.txt` |
| G14 | Every expected failure belongs to an item | a `test.fail()` test (C12-T04 design gaps) is not listed in exactly one item's `expected_failures` |

G1–G4, G7–G9, G12 and G14 also run in Phase 1. G5, G6, G10, G11 and G13 run
only with `--gate`.

**Invariant.** Nothing in the gate reads "no data" as "pass". Missing,
unparsable, skipped, unanswered and unknown all fail with their own message.
This is the AGENTS.md unknown rule applied to the gate itself.

**Security and privacy.** Every run uses the synthetic fixture server and
`syntheticFixtureEnvironment`. All evidence passes through
`sanitizeArtifactRoot` (`run-browser-tests.mjs:72`, and the package's own call
on its JSON work directory) before it is copied or archived. The two names
added to `inheritedRuntimeNames` carry a flag and a file path, never a
credential; N19 keeps the secret-drop assertion beside them. The
Phase 2 `real-*.png` screenshots are from the `--test` sandbox; the Executor
checks them for tokens, hostnames and Tailscale addresses before commit
(AGENTS.md "Do not commit"). **Approval authenticity:** an agent can type
`by: "Kevin"`. G6 requires a GitHub comment URL, and the reviewer opens each
URL and checks the author is Kevin's account before merge (Decisions 4).

**Idempotency.** Re-running Phase 1 creates a new run directory. It never
overwrites a delivered one, because `ref`s and the archive hash point at it.

**Stale state.** A visual PR that merges after delivery changes pixels that
Kevin did not see. The gate re-run catches it only if it adds a diff; a PR that
changes a pending entry's region silently changes what Kevin approved. So G5
plus G13 are not enough on their own: G6 also fails if `allowlist.json` in
the delivered run differs from the current allowlist for any entry Kevin
approved, except for the `approval` block itself (test `approved entry changed
after delivery`). A visual PR that changes pixels inside an approved mask
without changing the entry is not caught by any check; the reviewer compares
the gate run's triples with the delivered ones for each approved entry
(Completion).
