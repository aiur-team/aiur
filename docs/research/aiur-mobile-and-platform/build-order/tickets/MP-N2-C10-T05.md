# MP-N2-C10-T05 — Transport device validation

## Identity and outcome

- **Bucket / feature / chunk:** 3 / MP-N2 / MP-N2-C10.
- **User value:** RQ-TRANSPORT is closed with device evidence, not simulator behaviour or vendor
  claims. The readiness report can say "the phone loads the dashboard over the chosen transport on
  these devices" with a table.
- **Deliverable:** a results table appended to this ticket's PR (rows TR-1..TR-8 below, per device
  slot), plus filed tickets for any failing required row. No production code.
- **Non-goals:** push, watch and Command flows (MP-N1 DV-P, MP-N7 DV-W rows).

## Dependencies and blockers

- The owner's transport choice and its server ticket (T03 for T-A, T04 for T-B), T01, T02.
- A debug build of the phone app with the WebView host (MP-N1-C4-T02) and the device-session
  bootstrap (MP-N2-C6-T02).
- OQ-N1-4: which physical devices exist. A missing slot is reported as "not validated on <slot>".
- Can run alongside MP-N1 device-validation tickets on the same session.

- Today the dashboard is HTTP only (`src/lib/aiur/http_server.ex:64,147`); `/live` and `/voice`
  are WebSocket-only (`src/lib/aiur_web/endpoint.ex:14-29`).
- Device matrix and procedure rules: `bucket-3-mobile-watch/MP-N1/device-validation.md` §1, §4.

## Chosen design — device slots

| Slot | Exact target (pending OQ-N1-4) | Why |
|---|---|---|
| iPhone-min | iPhone on **iOS 17.x** (minimum per D-N1-3) | ATS IP-literal rule starts at iOS 17 |
| iPhone-cur | iPhone on the **current iOS 26.x** release | current WebKit WebSocket behaviour |
| Android-cur | Pixel-class phone, **Android 13+** with Google Play services | cleartext default, WebView from Play |
| Android-min | Android 10 (API 29) device, if available | minimum per D-N1-3 |
| Host | one aiur machine, two instances, reachable over the tailnet **and** a LAN | both network paths |

## Implementation steps (procedure)

For every slot, record device model, OS build, app build + git SHA, aiur version, network path,
timestamp (MP-N1 device-validation.md §4).

| Row | Steps | Pass condition | Required |
|---|---|---|---|
| TR-1 HTTPS load (T-A) | `aiur mobile tls tailscale --apply`; restart both instances; pair; tap instance 1 | Dashboard renders; Safari Web Inspector / `chrome://inspect` shows the `/live` WebSocket `101` and no mixed content | Yes (T-A) |
| TR-2 LiveView live updates | With TR-1 open, trigger a state change (`aiurdev set max-agents 1`) | The page updates within 5 s without reload | Yes |
| TR-3 WebView mic secure context | Open a worker chat, press Dictate | The OS mic prompt appears; a transcript returns (needs MP-E5) or the control shows its server-side reason — never "insecure" | Yes |
| TR-4 Pinned self-signed load (T-B) | `aiur mobile tls selfsigned`; pair (QR carries `t=`) | Page renders; `/live` falls back to long-poll on iOS (inspector shows `/live-lp` requests); Android WebView validates the pin before `proceed()` | Yes (T-B) |
| TR-5 Pin mismatch (T-B) | Rotate the key without the grace window; open the app | `tls_pin_mismatch` diagnostics screen; no page content loaded | Yes (T-B) |
| TR-6 Cleartext blocked | Set no TLS and `allow_cleartext_overlay: false`; run `aiur mobile qr` | QR refused with reasons; no pairing possible | Yes |
| TR-7 HTTP-degraded (only if the owner kept it) | `allow_cleartext_overlay: true`; pair over the tailnet IP | Page loads with the persistent warning; WebView mic `unavailable` (`insecure_context`); on iPhone-min confirm whether the ATS exception covers the 100.x address | If kept |
| TR-8 Renewal without restart | Replace the cert files with a new pair; wait 60 s; reload | The new certificate serial is presented; the app reconnects without re-pairing | Yes |

Latency figures (TR-2) are reported as median and count, per AGENTS.md "A claimed saving must be measured".
