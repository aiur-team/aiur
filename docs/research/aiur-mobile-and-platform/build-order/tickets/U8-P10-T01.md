# U8-P10-T01 — Stop tracking oversized vendored Compound Engineering files

## Identity and outcome

- Bucket 1, unit U8 (file-size debt), package `CE`, chunk `U8-P10`.
- **User value:** none visible. It removes 16,429 lines of vendored debt without forking
  the pinned Compound Engineering (CE) skills that every agent workspace receives.
- **Deliverable:** the 19 oversized CE paths leave the size debt by the route the owner
  picks in OWNER-U8-CE, with `AgentSkills` still installing byte-identical skills into
  workspaces and the release build still offline.
- **Non-goals:** no local edit of CE skill content that diverges from the pinned upstream
  except through the reviewed overlay; no change to the installed skill set, the version
  pin (3.19.0) or `/ce-setup`.

## Dependencies and blockers

- **U0 review gate (U0-T01), refreshed ledger (U0-T02) and transitional gate
  (U0-T03).** U0 reviews this package's owner rows, adopts the new rows, freezes the
  grandfathered ceilings and installs the gate. No U8 work starts before them.
- **Start contract:** U0 provenance overlay decision. The owning U-unit contract must be merged on `main`
  before this ticket edits a component-owned code file. Test-only, doc-only and
  generated-file rows may start after U0 alone.
- **Predecessors:** U0-T01, U0-T02, U0-T03, OWNER-U8-CE.
- **Enables:** none outside U8.
- **Single writer:** no other U8 ticket in package `CE`; do not run at the same time.
- **Shared-file conflicts (serialize, no order implied):** none known.
- **OWNER-U8-CE** chooses one route (U0 provenance overlay decision feeds it):
  1. **Upstream the splits (recommended).** Open PRs on the upstream CE repository that
     split each oversized file by responsibility and remove the three duplicated helpers;
     after a release, re-vendor with `scripts/update-compound-engineering-skills <version> <checkout>`.
     Keeps provenance and offline builds. Depends on upstream review time.
  2. **Fetch at build.** Stop tracking the CE tree; fetch the pinned release tarball by
     SHA-256 during `aiurdev build` and CI. Breaks offline release builds unless a cache is
     added; changes the release dependency surface.
  3. **Local overlay split.** Split the files in this repository as part of the overlay.
     Creates a permanent fork; every re-vendor must re-apply it.
  The plan forbids a permanent size exemption, so "keep as is" is not offered.
- This ticket is written for route 1. Routes 2 and 3 change steps 2–4; the owner's choice
  goes in the PR body.

## Chosen design

Route 1:
- Per upstream skill, split scripts by function group into sibling modules the entry
  script imports (Python) or sources (shell), and split `SKILL.md` into the skill body plus
  `references/*.md` that the body links, which is the skill format's own progressive
  disclosure.
- Duplicated helpers: upstream decides whether skills may share a file. If they may not
  (each skill must be self-contained when installed alone), each copy is split the same way
  and stays a copy; the duplication is upstream's design, not U8 debt to remove here.
- In this repository: re-vendor at the upstream release that contains the splits. The
  vendoring script needs no change unless upstream adds symlinks (it refuses them).
- Rationale: CE is upstream-owned; a local fork is the highest long-term cost, and route 1
  keeps `AgentSkills` and offline builds unchanged.

## Implementation steps

1. Record OWNER-U8-CE in the ticket.
2. Route 1: file the upstream PRs (one per skill family); link them here.
3. After the upstream release: run the vendoring script with the new version and checkout.
4. Recount; any CE path still above 500 gets a follow-up upstream PR, not a local edit.

## Non-happy paths

- Upstream rejects or delays: the ticket stays open and blocks `U8-P00-T02`; record the
  status and the remaining paths. Do not fall back to route 3 without the owner.
- A re-vendor can change skill behavior beyond the split (other upstream changes). Review
  the full diff; run the skill-content contract tests.
- `AgentSkills` compiles the whole tree; new files appear in workspaces automatically.
  Confirm the installed file list in a fresh workspace.

## Compatibility and rollout

Route 1: version bump in `compound-engineering.version`; no config change. Rollback:
re-vendor the previous version with the same script.
