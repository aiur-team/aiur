# MP-R1-C10-T04 — Docs-sync rules and CI wiring for the component directory

## Identity and outcome

- **Bucket / feature / chunk:** Bucket 1, MP-R1, C10 (MP-REQ4).
- **User value:** the public page can never link a deleted docs page, name a config
  section that has no reference entry, list an env var that does not exist, or drop out
  of the sidebar after publish — and a manifest-only PR rebuilds the docs.
- **Deliverable:**
  1. a `--docs` rule set in `scripts/check-components.py` (component-directory.md §5
     checks 3, 4, 5, 6, plus env-name and anchor checks);
  2. the `--docs` mode run in the **`workflow security`** job of `ci.yml` (it is
     required and runs even on docs-only PRs), in addition to the full check in `lint`;
  3. `components.json` (or `components/**`) added to `website.yml` `on.*.paths`;
  4. failing fixtures for each rule in `scripts/test-check-components.sh`, which already
     runs in `workflow security` (C1-T01).
- **Non-goals:** module-reference/dependency rules (C1-T02..T06), page rendering
  (C10-T02/T03), sidebar entry (C10-T05).

## Verified starting point (base `45a290e3`)

- **Docs-only PRs skip `lint`.** `ci.yml` `changes` job classifies a PR as docs-only
  when every changed path matches `^website/\|^packages/aiur-style/` (`ci.yml:128`), and
  every `lint` step has `if: needs.changes.outputs.docs_only != 'true'`
  (`ci.yml:241-289`). `check-config-docs.py` runs there (`:259-262`).
- **`workflow security` always runs** (no `docs_only` condition, `ci.yml:144-189`) and
  already runs docs-guard self-tests (`bash scripts/test-check-config-docs.sh`,
  `:176-177`). Ubuntu runners have `python3` on PATH (the `lint` steps call `python3`
  with only the Elixir setup action, `:247-262`).
- **Required checks** (from `scripts/verify-human-only-merge-ruleset.sh` at
  `45a290e3`): `browser harness, build, coverage, coverage (1/4..4/4), dialyzer, layout
  release smoke, lint, streamdeck, test, workflow security`. The `website` workflow's
  `guards` job is **not** required. So a docs-only PR that deletes a page the manifest
  links is caught only if a required job runs the docs rules → `workflow security`.
- `website.yml` triggers only on `website/**` and its own path (`website.yml:4-16`);
  its `guards` job builds the docs (`:49-54`).
- `check-config-docs.py` pattern: `REPO_ROOT` from `__file__` (`:29`), reference path
  `website/docs-app/reference/configuration.md` (`:32`), `EXEMPT` dict with reasons
  (`:38`), exit code 2 for setup errors via `die()` (`:74-76`). Its self-test scaffolds
  a mini repo in `mktemp -d` and asserts failures (`scripts/test-check-config-docs.sh`).
- Config reference headings are `## <section>` per section
  (`configuration.md:75 ## tracker`, `:118 ## polling`, `:713 ## build_order`, ...).
- VitePress heading anchors use `slugify` in installed VitePress 1.6.4
  (`dist/node/chunk-D3CUZ4fa.js:17688-17690`): NFKD-normalize, special characters
  including `_` and whitespace → `-`, collapse, trim, lowercase. So `## build_order` →
  `#build-order`, `## pr_health` → `#pr-health`.
- Env var canonical list: `scripts/check-env-example.py` checks `.env.example` against
  the env-var schema (`ci.yml:263-271`). The checker reads names from `.env.example`
  (repo root) rather than re-parsing the schema.
- Sidebar: `website/docs-app/.vitepress/config.ts:126-170`, link strings like
  `'/reference/configuration'`.

## Chosen design

### Rules in `--docs` mode (all pure file reads; no Elixir, no network)

| ID | Rule | Failure message shape |
|---|---|---|
| D1 | Manifest validates against `components.schema.json` (reuse C1's validator) | `components.json: <json-pointer>: <reason>` |
| D2 | Every `docs` path exists under `website/docs-app/` | `<id>: docs path not found: <path>` |
| D3 | Every `config` section has a `## <section>` heading in `reference/configuration.md` (exact heading text match; anchor = VitePress slugify of the heading) | `<id>: config section <s> has no heading in reference/configuration.md` |
| D4 | Every `env` name (or `PREFIX_*` pattern) matches at least one name in `.env.example` or the AGENTS.md § Auth list — **decide at implementation by reading `check-env-example.py`'s source of truth; use exactly that list** | `<id>: env var <NAME> unknown` |
| D5 | Every `capabilities` ID is in the `aiur-contracts` capability enum (C3-T06). Template entries (`harness.<id>.native_question`) match by pattern: `<id>` is one lowercase segment `[a-z0-9_]+` (X-46) | `<id>: capability <c> not in aiur-contracts` |
| D6 | When `directory_published` is true, `config.ts` contains the literal `'/reference/components'` | `sidebar link /reference/components missing from .vitepress/config.ts` |
| D7 | Every `features[].extends/adds` and component `requires/optional` ID resolves | `<id>: unknown component <x>` |

- **Python slugify port:** D3 compares headings, not anchors, so no slug port is needed
  for the check. The projection (C10-T02) generates anchors with the same algorithm in
  JS; C10-T03's test asserts `build_order` → `build-order`.
- **Exit codes:** 0 pass, 1 rule failure, 2 setup error (manifest missing), as in
  `check-config-docs.py`.
- **No EXEMPT for D2–D7.** A broken docs link is fixed, not exempted.

### CI wiring

```yaml
# ci.yml, workflow-security job, after "Test config documentation guard" (:176-177)
      - name: Component manifest docs links
        run: python3 scripts/check-components.py --docs
```

```yaml
# website.yml on.pull_request.paths and on.push.paths (:5-7, :14-16)
      - "components.json"          # or "components/**" per C1-T01 layout
```

Rationale for `workflow security` rather than a new job: a new job is not
merge-blocking until the ruleset is re-applied (`ci.yml:256-258` comment); the
`website / guards` job is not required.

## Non-happy paths

- **Docs-only PR deletes a linked page:** D2 fails in `workflow security` (required).
- **Manifest-only PR:** `website.yml` now rebuilds the docs; `lint` runs the full
  checker (not docs-only, since `components.json` is outside `website/`).
- **Heading renamed in configuration.md:** D3 fails; fix the manifest or the heading.
- **C3-T06 not merged:** D5 disabled with a skipped fixture (see Dependencies).
- **Checker crash:** exit 2 with a message; never exit 0 on an exception (wrap `main`).

## Compatibility and rollout

- CI-only change. Rollback: revert the PR (manifest flag, step and paths go together).
- No runtime, config or CLI change; no docs page required (AGENTS.md: CI-only).
  `CONTRIBUTING.md` § Documentation (line 144) and § Enforcement (line 257) gain one
  line each naming the new gate.
