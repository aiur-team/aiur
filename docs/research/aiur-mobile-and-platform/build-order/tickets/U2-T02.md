# U2-T02 - Guarded terminal-verification wrapper

## Identity and outcome

- Bucket 1, prior unit U2. Acceptance example AE1 family (stuck ticket with one cause).
- **User value:** a terminal ticket whose run-membership identity cannot be
  joined no longer degrades membership health and is no longer retained for
  ever; the Executor sees one alert with the ticket and cause.
- **Deliverable:** one `set_terminal_verification_pending` wrapper in
  `Aiur.CurrentRunMembership` with the joinable guard; four callers use it; an
  attempt bound plus alert for ids retained by `record_disappearing_idle_terminals`.
- **Non-goals:** no change to what "terminal" means; no new store fields.

## Dependencies and blockers

- U0-T01. MP-E1-C1-T02 edits `issue_sync.ex` heal/strand code first (RC-19).
- Independent of U2-T01 (different lines); whichever lands second rebases.

## Verified starting point (`58854d4c8`)

- `orchestrator/issue_sync.ex:993` `safely_set_terminal_verification_pending/3`
  calls the store for every identity. The store accepts only `TrackerIdentity`
  structs (`current_run_membership/store.ex:73-74`); a nil identity raises and
  is rescued to `:error`. An unjoinable struct goes to `store/runtime.ex:67` →
  `terminal_verification_marker_failed` (:247-259), which degrades membership health.
- The latch: `record_and_clear_refreshed_terminal` (:950) →
  `clear_refreshed_terminal_verification` (:971-979) → `{:error, _}` → kept by
  `record_disappearing_idle_terminals` (:831) → `mark_reconciled(:unavailable)`
  (:984-990). A ticket the refresh never returns is retained with **no age or
  attempt bound** (:868, :887-888).
- The three other wrappers already guard: `reconciler.ex:663-664`,
  `retry_engine.ex:1444-1445`, `comment_wake.ex:539-544`.
- Facade: `src/lib/aiur/current_run_membership.ex` (87 lines).
- Tests: `test/aiur/orchestrator/issue_sync_test.exs` has no nil/unjoinable case.

## Chosen design

- Copy the existing guard (the `reconciler.ex:663-664` form) into one public
  function in `current_run_membership.ex`; delete the four private copies.
  Unjoinable identity → `:skipped` (no store call, no health change).
- Bound: keep a per-id attempt counter in the existing retained-ids structure
  in `IssueSync` state. After 5 consecutive ticks where the refresh does not
  return the id, drop it from retention and emit one `Aiur.Alerts` alert
  `terminal_verification_abandoned` with identifier and reason. 5 matches the
  existing scale of tick-based bounds; record the number in a module attribute.

## Implementation steps

1. Add `CurrentRunMembership.set_terminal_verification_pending/3` with the guard.
2. Replace the four call sites; remove the private wrappers.
3. Add the counter and drop+alert in `record_disappearing_idle_terminals`.
4. Tests below.

## Non-happy paths

- **Store process down:** keep today's rescue → `:error`; counts as an attempt.
- **Id comes back after drop:** normal sync handles it as a fresh ticket.
- **Restart:** counter is in memory; a restart resets it (bounded anyway).

## Compatibility and rollout

No config. One new alert kind. Rollback: revert.
