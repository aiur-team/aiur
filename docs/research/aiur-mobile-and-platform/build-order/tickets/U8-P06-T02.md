## Chosen design

- PROPOSED `.claude/skills/aiur-build/scripts/pack_format.py` (about 60 lines):
  `format_pack(data) -> str` writes the top-level object with one key per line; a scalar
  or small object value inline; a list value as `[` then one compact element per line
  (`json.dumps(el, ensure_ascii=False, sort_keys=False, separators=(", ", ": "))`) then `]`.
  Key order is preserved (no sorting), so diffs stay readable. `main` formats files in place
  or `--check`s them.
- The publisher's existing writer for `build-order.json` (`_atomic_write_json` in the
  materialize module after `U8-P06-T01`) calls `format_pack` for pack manifests, so new
  publications keep the layout.
- Expected sizes: `build-order.json` about 170 lines, croptracker about 140, permanent
  pack about 80. Any single ticket line may be long; that is acceptable for a generated
  machine manifest and is the only layout that keeps one record per line.
- Rationale: smallest change that keeps every reader unchanged (all read parsed JSON),
  keeps one ticket per line for review, and needs no schema version bump.
