## 4. Chosen design

Events are built on the **server**, in one pure module. The hook only renders
them. Reasons: the sources are server-only; ExUnit can test every mapping; and
C14-T01 swaps one module.


### 4.1 Entry shape (C11-T03's `ev` entry)

The event rows travel as C11-T03 entries in the same `entries` list as the
transcript entries, with C11-T03's `ev` shape
`{id, k: "ev", at, ev, label, sub?, go?, pct?}`:

```json
{ "id": "ev:log:1791276296964057", "k": "ev",
  "ev": "prog|dep|review|you|merge|pr|fail|cmd|commit",
  "label": "Progress · 50%", "sub": "Core change done",
  "go": "123", "at": 1791407600000, "pct": 50 }
```

- `id` is the stable key (C11-T03: "Entry `id` is the stable key C11-T05 calls
  `key`"; it becomes `data-eid`). It is `ev:log:<event id>`, `ev:dep:<dep id>`,
  `ev:merge:<pr num>`, `ev:pr:<pr num>`, `ev:fail:pr:<pr num>`,
  `ev:cmd:<decision id>`, `ev:state:<agent.state>` or
  `ev:resume:<at>`. The `ev:` prefix keeps it apart from C11-T03's entry ids and
  cursors. An `id` is never a `before` cursor.
- `sub`, `go` and `pct` are left out when they have no value (C11-T03 marks them
  optional). The server never sends `"sub": ""`.
- `at` is daemon time in epoch ms: a log `ts`, a store time (`merged_at`,
  `created_at`), the ticket row's `end`, or for row 17 the daemon `now` of the
  C3-T02 change that carried the transition. `null` means "time unknown". It is
  never the ticket start, never the browser clock and never the time the page
  was read.
- `pct` is set only for `ev: "prog"` with a known percent.
- Strings are raw text (C3-T02 rule 1), passed through
  `AgentEventFeed.scrub/1`, then `SecretRedactor.redact/1`.
- The validator (C11-T03 step 6) must accept all ten `EVK` kinds, because the
  fixture source sends the design's `comment` and real-commit `commit` rows
  (§7). The server module emits only the nine kinds above.

### 4.4 Interleaving with C11-T03's pages

C11-T03 pages are slices of entries with a `before` cursor and `more`. Event
rows are assigned to pages by time, with **contiguous** windows so that no event
falls between two pages:

- `lo(page)` = the smallest known `at` among the page's entries (entries with
  `at: nil` are ignored). BuildLive keeps `events_upper`: the `lo` of the last
  page it sent for the open ticket (`+∞` before the first view).
- **First view** (`kind: "conversation"`): log events with `at ≥ lo`, and every
  event when the page has no timed entry. Then the current-fact rows in this
  order: rows 7–10 (PR or merge), rows 11–16 (state). Set `events_upper = lo`.
- **Older page** (`kind: "conversation-earlier"`, `more: true`): log events with
  `lo ≤ at < events_upper`. Set `events_upper = lo`. A page with no timed entry
  gets no events and leaves `events_upper` unchanged.
- **Oldest page** (`more: false`, on either reply): every remaining log event
  with `at < events_upper`, and the dependency rows (row 6) first, before every
  other entry (J:1312).
- Inside a page, events are merged by `at`, then by log id. On a tie with an
  entry, the event goes after the entry. Entries with `at: nil` keep their
  C11-T03 position.
- **Known-empty transcript** (C11-T03 `:known_empty`): one page of events only.
  **Not retained** (S-6) and **unavailable**: no events; C11-T03's state stands.
- A page reply always carries every event of its window, even when an earlier
  reply carried it too: C11-T03/C11-T05 trim the DOM at 500 entries and re-ask
  with `before: null`, and the client replaces a repeated `data-eid` in place.
  A first view (`before: null`) resets `events_upper` and the sent set (§4.5).

### 4.5 Live updates

This ticket adds no polling timer of its own. While a modal is open, BuildLive
re-reads the events at most once per second (a trailing debounce, one
`Process.send_after/3` per ticket) after one of these triggers:

1. a C11-T03 `conversation-append` push for that ticket;
2. `{:ticket_history_updated, _}` for the identity (subscribed with
   `Phoenix.PubSub.subscribe(Aiur.PubSub, TicketHistoryProvider.topic(identity))`
   when the conversation is pinned, as `dashboard_live.ex:2032–2039` does, and
   unsubscribed when it closes or another ticket is pinned);
3. a C3-T02 `{:build_changes, %{upsert: rows}}` that upserts the open ticket's
   row (state, PR, deps).

The re-read reads the newest 500 log rows (no `since_id`: lines can land out of
id order, §3) and drops every `id` in the per-ticket sent set. New entries go
out as one `conversation-append` push, so C11-T05 appends them with `cvIn`. A
current fact whose `id` changes (for example `ev:state:command` →
`ev:state:paused`) adds only the new row. Rows already shown are never edited
or removed: the log is history. Row 17 is the only live-only row.

### 4.6 Client rendering

`build-home/modal/conversation-events.js` exports `EVK`, `evHue(o)` and
`eventEl(o)`. `eventEl` reproduces J:1344 and J:1351–1352 exactly (same element
order, classes and inline `--eh`), and sets `data-eid` from `id` as C11-T03's
`itemEl` does. It renders all ten `EVK` kinds, so the fixture's `comment` rows
draw. `label`, `sub` and `go` go through `esc` (J:9) or `textContent`; the design
inserts `go` into `data-goto` unescaped, and the port escapes it too. It adds
only invisible attributes:

- `aria-hidden="true"` on the icon `svg`;
- `datetime` (ISO) on `<time>` when `at` is known;
- `aria-label="Open #N <title>"` on `.cv-go` (the visible text stays "Open").

`fmtT` and `fmtD` use the browser time zone (EC-20). A merge row with `sub: null`
and a known `at` renders `fmtD(at) + " " + fmtT(at)` (J:1333).

## 6. Non-happy paths

- **Untrusted text (EC-30):** summaries are agent-written. Titles are
  GitHub-authored. Both are raw strings in the payload and are inserted with
  `esc` (`textContent` where the port allows). The test uses C3-T02's
  `hostile.json` strings. Secrets: `SecretRedactor.redact/1` runs on every
  `label` and `sub`. The log summaries are already shown on the Stream Deck
  (`agent_event_feed.ex:107–114`). The dashboard is behind the same auth as the
  drawer, which shows full transcripts. This is no new exposure class.
- **Read only:** this ticket only reads. A read-only dashboard shows the same
  rows (EC-12 is not affected).
- **Daemon restart (EC-31):** the event log is per run. After a restart, rows 1–5
  hold only the events since boot. The history provider restarts empty, so the
  progress rows before the first new reading use row 2. The rows are not lost:
  they come back unchanged in C14-T01 from the MP-E4 journal. Rows 6–16 come
  from durable or current sources and are not affected.
- **Large logs:** `event_history` reads the whole file (`issue_log.ex:183–196`)
  and keeps the newest `limit` rows (`Enum.take(-limit)`). The largest file on
  this host is a few hundred lines. `limit: 500` matches the 500-entry DOM cap
  (C11-T03). When 500 rows come back, the oldest page shows one `sys` entry
  (`id: "ev:sys:truncated"`) "Earlier ticket events not shown" at the boundary,
  in place of a silent cut.
- **Concurrency:** two tabs each hold their own `conversation_event_ids`. The
  events are reads, with no shared write. The debounce keeps one read in flight
  per ticket per LiveView. Lines that land out of id order are still found,
  because the re-read does not use `since_id` (§4.5).
- **Navigation race:** a refresh message for a ticket that is no longer pinned
  is dropped (the message carries the ticket id).
- **Disconnect (EC-06):** no reads while the socket is down. On rejoin, C11-T03
  sends a first view, and the sent set and `events_upper` reset with it.
- **Reset broadcast:** `TicketHistoryProvider.reset_topic/0` means the provider
  restarted. BuildLive (which already subscribes to it for the drawer,
  `dashboard_live.ex:2026`) schedules one refresh for the open ticket; the
  progress rows sent before stay as they are.
- **Clock skew:** `at` is daemon time. The browser only formats it. Ordering
  uses `at` and then the log id, never the browser clock.

## 12. Decisions made without the owner

1. **Server-built events, client-rendered.** One pure module is easy to test and
   easy for C14-T01 to replace.
2. **A kind appears only with a real source.** `comment` and the real-commit
   `commit` are not shown in wave 0b. The CI "fail" row is not shown because no
   CI check state is in this ticket's inputs.
3. **"Resumed" uses the design's `commit` kind** (hue 255, commit icon), as the
   design's own pause handler does (J:1450). It never says "by you" (C11-T07
   sends `by_you_at` for pauses only).
4. **"Paused by you" means `:operator_pause`.** That is any operator action
   (dashboard, TUI or CLI). The design's word "you" is kept for that cause only.
5. **Current facts have no invented time.** Dependency state, open PR, paused,
   parked, error and retries rows show "—" in the time slot, unless a real time
   exists (merge time, decision `created_at`, `by_you_at`).
6. **Placement follows the design:** dependency rows first, the state row last
   (J:1312, J:1332–1338). With paging, the dependency rows are on the oldest
   page, and the page windows are contiguous so no event is lost between pages.
7. **The agent's review phase maps to the `review` kind** ("Review started" /
   "Review complete", not the design's "Code review · N suggestions": no source
   counts suggestions), and `agent.blocked`/`unblocked` map to `dep`. They are
   the closest design kinds for real events. Other `agent.*` topics (work and
   plan phases, ad hoc alerts) are not shown.
8. **`agent.pause.request` maps to `you`** ("Agent asked to pause"), with the
   agent's own text as the sub.
9. **Event text is shown as written, after secret redaction.** This is the
   same text the Stream Deck shows today.
10. **Refresh on triggers, not a polling timer,** with a 1 s debounce. An event
    with no trigger appears on the next trigger or when the modal is opened
    again. C11-T03's 1 s file-stat poll on running tickets is trigger 1, so a
    running agent's events still arrive within about 2 s.
11. **The log limit is 500,** to match the DOM cap. A truncated log shows one
    line, not a silent cut.
12. **Error and retry rows have no attempt count.** The Units row carries none,
    and adding fields to the shared Units projection is outside this ticket.
13. **Merge label is "Merged PR #N", not "… into main"** (J:1333). `RecentMerge`
    has no base branch, so "into main" would be a guess. The open PR row keeps
    the design's "Opened PR #N" (J:1324).
14. **The re-read does not use `since_id`.** Log writes are async casts from many
    publishers, so a lower id can land after a higher one. Reading the newest 500
    rows and dropping sent ids costs one small `File.read` per debounced trigger.
