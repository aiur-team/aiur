# U8-P25-T01 — Archive historical plans as path-preserving short indexes (HIST_CE and HIST_PRODUCT)

## Identity and outcome

- Bucket 1, unit U8 (file-size debt), package `HIST_CE + HIST_PRODUCT`, chunk `U8-P25`.
- **User value:** existing links to old plans keep working and still reach the full
  text, while the tracked tree loses 20,008 lines of historical prose.
- **Deliverable:** each of the 28 paths stays at its path as a short historical
  index (at most 500 lines) that (a) keeps the original frontmatter and title,
  (b) repeats every original heading at the same level and in the same order, so
  every existing `#fragment` still resolves, and (c) under each heading links to the
  same section in the immutable GitHub blob at the pinned commit. One small
  generator script with a test produces the indexes.
- **Non-goals:** no rewriting, summarizing or correcting of history; no deletion of
  any path; no edit of the plans' meaning. Package `HIST_PRODUCT` has no ticket of
  its own: its six rows are here because the policy and tool are the same.

## Chosen design

| PROPOSED path | Role | Est. lines |
| --- | --- | ---: |
| `scripts/archive-historical-doc.py` | reads a file at a SHA (`git show`), writes the index | 150 |
| `scripts/test-archive-historical-doc.sh` | fixture-based test | 80 |
| each of the 28 paths | index | 30–150 each |

Index layout (generated):

```markdown
---
<original frontmatter, unchanged>
archived: <sha> (U8-P25-T01)
---
# <original title>

> Historical record. Full text: https://github.com/aiur-team/aiur/blob/<sha>/<path>

## <original H2 text>
[Section text at <short-sha>](https://github.com/aiur-team/aiur/blob/<sha>/<path>#<slug>)
### <original H3 text>
...
```

- `<sha>` is the merged-main commit before this PR (the last commit with full text).
- Slugs follow GitHub's rule (lowercase, drop punctuation, spaces to `-`, duplicate
  headings get `-1`, `-2`). Because the index repeats each heading, an inbound
  `path#slug` link resolves in the index with the same slug.
- Headings inside fenced code blocks are not headings; the tool skips fences.
- Inbound `elixir/docs/...` references are rewritten to `src/docs/...` in the readers
  (they are historical docs too; this is a path fix, not a content edit).

## Implementation steps

1. Write the tool and its test (fixture with duplicate headings, a fenced `#` line,
   frontmatter, and a heading with punctuation).
2. Run it for the 28 paths at the pre-PR SHA. Commit the indexes.
3. Fix inbound `elixir/docs/` references; run a link check (below).
4. Recount: all 28 paths at most 500 lines.

## Non-happy paths

- **Lost fragment:** if the tool's slug differs from GitHub's, a deep link breaks.
  The test covers duplicates and punctuation; the link check below covers real
  inbound fragments.
- **Wrong SHA:** a SHA after this PR points at the index, not the text. The tool
  refuses a SHA where the file is already an index (it checks for `archived:`).
- **Live rule hidden in history:** handled by the active-contract check in
  Dependencies.
- **Private content:** the text is already public in Git history; no new exposure.

## Compatibility and rollout

Docs only. Rollback = revert (the full text returns). No config or packaging change.
