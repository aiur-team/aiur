## 4. Chosen design

### 4.1 Keyboard on the timeline and Gantt views (roving tab stop)

The house pattern (`interaction.js:256-322`) is reused as the semantics.
Arrow keys move in **reading order**: the layout's sections in board order
(history `L.secs.hist`, then the now band `L.band`, then `L.secs.plan`, then
`L.secs.nq`), and inside each section by `it.y`, then by `it.x`. Right/Down =
next, Left/Up = previous, Home = first (the **oldest loaded** history card, at
the top), End = last (the bottom of the plan or not-queued section). This is
linear, as in `moveFocus`.

- **State.** `ctx.a11y = { roving: null, focusId: null }`, reset with
  `onReset` (C9-T01). `roving` is the id that holds `tabindex="0"`; `focusId`
  is the id of the card that has DOM focus (set on `focusin`, cleared on a
  `focusout` whose `relatedTarget` is not a `.bd-card`).
- **One tab stop.** Every rendered card gets `tabindex="-1"`, except the card
  whose id is `ctx.a11y.roving`, which gets `tabindex="0"`. When no card has
  focus, `update()` moves `roving` to the first card in reading order whose
  absolute top is at or below `vp.scrollTop`, so Tab from the toolbar lands on
  what the user sees. A board with 1,300 cards is one tab stop, not 1,300.
- **`#bd-vp` gets `tabindex="-1"`** (no visible change at rest). C9-T03 sends
  focus to `#bd-vp` when the focused ticket leaves the board, and `focus()` on a
  `div` without `tabindex` does nothing. The explicit `-1` also keeps Chromium
  from making the scroller its own Tab stop (keyboard-focusable scrollers),
  because the cards are the Tab stop.
- **Moving to a card that is not rendered.** The target comes from the layout
  (`L.secs[*].items`, `L.band.items`), not from the DOM. If it has no element,
  set `vp.scrollTop` so that its top is one third down the viewport, call
  `update()` once (synchronous, C9-T03), then `focus({ preventScroll: true })`
  the element `R` now holds. The scroll is instant (no smooth behaviour), so it
  is the same with or without reduced motion.
- **The focused card stays rendered.** C9-T03's window test gets one extra
  condition: an item is rendered when it overlaps `[A, B]` **or** its id is
  `ctx.a11y.focusId`. The card is far off screen, so no pixel changes. Without
  this, a PageDown or a wheel scroll removes the focused element and focus falls
  to `<body>` (EC-19).
- **Enter** on a card calls `fx.openModal(ctx.D.byId[id])` (the same call as the
  click path, J:634). While a chain is locked, Enter opens only a chain member,
  as the click does (J:633).
- **Space** always calls `preventDefault()` (otherwise the scroller scrolls).
  Without `?trees=1` it does what Enter does: a `role="button"` element is
  activated by Space in the ARIA button pattern, and a screen-reader user is
  told "button". With `S.trees` on (`?trees=1`, S-3): if `ctx.lockId` is set,
  `fx.unlock()`; else `fx.lockTree(id)` (C9-T11; it finds the element in `R` or
  the band and locks). This closes C9-T11 decision 11.
- **Focus is hover for chains.** `focusin` on a card calls `fx.onHover(e)`, the
  pointer path itself (J:941-948), so the same guards apply: nothing without
  `S.trees`, while scrolling or while locked, and nothing for a card in
  `.bd-now` (J:946). A `focusout` whose `relatedTarget` is not inside a
  `.bd-card` calls `fx.onLeave()` (J:619: clear after 200 ms unless locked).
- **View switch** (Timeline/Gantt/List): before the switch, keep the focused id;
  after the new view renders, focus `[data-id="<id>"]` (a card or a `.lr` row).
  If it is not in the new view, focus `#bd-vp`.
- **The listener** is one `keydown` and one `focusin`/`focusout` pair on `#bd-vp`,
  registered with `ctx.life.on` (C9-T01), so a reset removes them.

### 4.2 Per-card accessible name

`cardLabel(t, D, cls)` in PROPOSED `build-home/a11y.js` returns one string.
`makeCard` sets `role="button"`, `tabindex` and `aria-label` once; `decorate`
re-sets `aria-label` after it toggles `dim`, `also` and `feat-on`, because those
change the text. The strings are only built for rendered cards.

Parts, joined with ". " and ended with ".":

| Part | Known | Unknown or absent |
| --- | --- | --- |
| Reference + title | `refTitle(t) + " " + t.title` → `"#123 Flaky …"` | pack row (`num: null`, `src.kind: "pack"`) → `refTitle(t) + ". " + t.title` = `"Not filed yet. …"` (C7-T02 `refTitle`; not `refText`, whose `"—"` is read as "dash") |
| State, now row | `agentText(t, D)` → `"Agent Claude: Running"`, with `", as of HH:MM"` when the board is stale (C9-T06 §4.2) | `"Agent Claude: state unknown"`, `"…, state age unknown"` |
| State, other rows | `stText(t)` (C9-T12) → `Merged`, `Failed`, `Not planned`, `Held`, `Blocked`, `Waiting on #N`, `Queued`, `Not queued`; then `agentText` when the row has an agent (`"Agent Claude"`) | `"State unknown"` (C9-T12 U3) |
| Progress, now rows only | `"45% done"` | `pct: null` → `"progress unknown"` |
| Complexity | `"Complexity 3 of 5"` | `cx: null` → `"complexity unknown"` |
| Dependencies | `"2 dependencies, unblocks 1"` (J:1159 counts, J:1169 words) | `0` is a real count here: `deps` is always a list (C3-T02) |
| CSS-only text | `ghost` → `"outside feature"`; `also` → `"also affects"` (C:270, C:273) | — |
| Filter | `dim` → `"dimmed by filter"` | — |

Example: `"#123 Flaky websocket reconnect. Agent Claude: Running. 45% done. Complexity 3 of 5. 2 dependencies, unblocks 1."`

- The name is plain text set with `setAttribute`, so a title with `<` or quotes
  is safe (EC-30). No HTML is built.
- `role="button"` makes the card's children presentational, so C9-T06's
  `.sr-only` span is not read twice. The span stays (it is cheap and correct if a
  later change removes the role).
- The visible `title` tooltips stay as in the design.
- `#bd-vp` gets `role="region"`, `aria-label="Build timeline"` and
  `tabindex="-1"` (§4.1) unless C9-T01 already set a role (the row note in C10-T01 decision 4 says the role is
  C9-T01's). No `aria-controls` link from the view tabs (C10-T01 decision 4 is
  kept: axe does not require it, and the panel is the same element in all views).
- Dependency count limit: `D.children` holds only loaded rows, as in the list
  view, so "unblocks M" can be lower for an old history card before older days
  load. The card and the list agree. Marked with a `ponytail:` comment.

### 4.3 Live region for agent state changes

One persistent node, appended by `shell()` (C9-T01) as the last child of
`ctx.root` **after** the shell's own `innerHTML` assignment (J:550), and outside
every later `innerHTML` target:
`<p class="sr-only" id="bd-state-live" aria-live="polite" aria-atomic="true"></p>`.
It exists before the first diff, so the first change is announced. The pattern
is C9-T10's `#bd-range-live` and `interaction.js:390-399`.

- **Source.** In the hook's `receive` (C9-T01 `hook.js`), on a diff: keep
  `prev = ctx.D`, call `applyDiff(msg)`, and only if it succeeded (no throw, no
  resync) call `announceState(noteDiff(prev, ctx.D, msg))`. `noteDiff` is pure
  and returns a message or `null`. It looks only at the ids in `msg.upsert`,
  and only at rows that are `now` before or after (`prev.byId[id]` against
  `ctx.D.byId[id]`):
  - a now row whose `agent.state` changes → `"#123: Error"` (the `AST` label);
  - a row that enters now → `"#123: Running"`;
  - a row that leaves now for hist → `"#123: Merged"` / `"Failed"` /
    `"Not planned"` (`stText`);
  - an unknown or `null` state → `"#123: state unknown"`, never `Running`.
  - Ids in `msg.remove` are not announced (decision 11).
- **Several changes in one diff:** up to three are joined with `"; "`. More than
  three: the first three and `"and N more"`.
- **Coalescing:** 160 ms, as `interaction.js:390-399`. A second diff inside the
  window merges into the pending list by ticket id (the newest state of a
  ticket replaces its older entry), then the cap is applied again.
- **Same text twice.** If the text to write equals the region's current text,
  the region is first set to `""` and the text is written on the next
  animation frame, so a screen reader hears it again.
- **No announcement** for a `snapshot` (first paint, reconnect, generation gap,
  EC-11). The offline banner (`role="status"`, C8-T03) announces the
  reconnection, and a snapshot would read every agent at once.
- **Other regions stay where their owners put them:** `.bd-offline`
  `role="status"` (C8-T03), `#bd-range-live` (C9-T10), the composer state line
  (C11-T06), the tree overlay (C9-T11). This ticket adds no second region for any
  of them. The daemon chip stays without a region (C10-T01 decision 5).

`dashed` and `stroke-dasharray` there (C2-T04 §3).

```css
@media (forced-colors: active) {
  /* !important only inside this block: the design's theme, palette and
     reduced-motion rules out-rank a plain selector (C:471, C:977, C:457,
     C:968, C:1011, C:1053), and a fallback must win in every theme. */
  /* dimming by opacity is invisible here (dashboard.css:1857-1858) */
  .bd-card.dim, .bd-card.hdim { opacity: 1 !important; filter: none !important; }
  .bd-card.dim .bd-in, .bd-card.hdim .bd-in { outline: 2px dashed GrayText; outline-offset: -4px; color: GrayText; }
  /* agent state by border style and width (glows are shadow and gradient) */
  .bd-card.ag-active .bd-in { border: 2px solid CanvasText; }
  .bd-card.ag-stuck .bd-in  { border: 3px double CanvasText; }
  .bd-card.ag-idle .bd-in   { border: 1px dotted CanvasText; }
  /* after the agent rules, colour only, so an agent card keeps its style */
  .bd-card.hl .bd-in, .bd-card.sel .bd-in, .bd-card.feat-on .bd-in { border-color: Highlight; }
  /* meter pattern (dashboard.css:7458-7468) */
  .bd-bar { forced-color-adjust: none; background: Canvas; border: 1px solid CanvasText; }
  .bd-bar i { forced-color-adjust: none; background: CanvasText !important; }
  .bd-e, .bd-e.ok, .bd-e.bl, .bd-e.bad { stroke: CanvasText; }
  .bd-e.hl { stroke: Highlight; }
  .bd-e.fade, .bd-ea.fade { opacity: .4; }
  .bd-ea, .bd-ea.ok, .bd-ea.bl, .bd-ea.bad { fill: CanvasText; }
}
```

- The dim outline is inset (`-4px`) on `.bd-in`, so it never meets the focus
  ring, which is outside on `.bd-card`.
- Plan cards already have a dashed **border** (C:265). The dim cue is an
  **outline** in `GrayText` with grey text, so the two stay distinct.
- The three agent states differ by **border style and width**, not colour, so
  state is not shown by colour alone (E8-D12). The state is also in the name
  (§4.2) and in the full tier's status text. `.bd-card.ag-*` (0,3,0) is used,
  not `.ag-*` (0,2,0), so it beats `.bd-card.hdim .bd-in { border-style: solid }`
  (C:408) and `.bd-card.bar .bd-in { border: 0 }` (C:935). C:704's
  `!important` is on `border-color` only, which forced colours replaces anyway.
- Edges: the gap (`2 4`) and blocked (`5 4`) kinds stay distinct from solid
  ones. Plain against `ok`, and `bl` against `bad`, differ in the design only by
  colour and width, so under forced colours they differ only by width (1.5 /
  1.8). The cause is also in the card text (`Blocked`, `Waiting on #N`, C9-T12
  `stText`), so no new dash pattern is invented (decision 12).
- Outside forced colours, none of these rules match. The C1-T02 matrix and the
  C2-T04 computed-style snapshot are unchanged.

### 4.5 Focus rings (S-12 default)

The global ring (`dashboard.css:186-192`) is the default. It already covers
buttons, links, textareas and every `[tabindex]` element, which includes the
shell controls C2-T02 sent here (`.ax-cog`, `.ax-mi`, `#ax-drag`, `.snav`), the
usage lines `.ax-ln` (C10-T04), the list rows (C9-T12) and `#cv-log` (C11-T05).
Only geometry rules are added, under `:focus-visible` so the rest state does not
change:

```css
/* S-12 default: keyboard focus geometry (not in design) */
.bd-card:focus-visible { border-radius: var(--r); }   /* ring follows the rounded card */
/* opacity and filter on .bd-card also fade and blur its outline (C:274, C:467) */
.bd-card.dim:focus-visible, .bd-card.hdim:focus-visible { opacity: 1 !important; filter: none !important; }
```

- `.bd-card` has no radius (only `.bd-in` has one, C:232), so without the first
  rule the ring has square corners around a rounded card. `--r` is set on
  `.bd-card` for every tier (C:227, C:308, C:440).
- The second rule shows a dimmed card at full strength **only while it has
  keyboard focus**. Without it the ring is drawn at 26 % opacity (and blurred for
  `hdim`), which fails the visible-focus requirement. `!important` is needed for
  the same specificity reason as §4.4 (C:471, C:977). It is an S-12 default and
  is in the C12-T08 package.
- No hover-lift override: the ring is on `.bd-card` and the lift moves only
  `.bd-in` (C:233), so the two do not interact and the hover pixels stay.
- No `outline: none` anywhere. `.cv-in textarea { outline: 0 }` (C:558) stays,
  because `.cv-in:focus-within` (C:557) is the design's visible focus for the
  composer; the C1-T02 check covers it.
- The audit (§8, K-6) lists every focusable element on the page and fails if one
  has a computed `outline-style: none` and no `:focus-within` parent rule while
  focused by keyboard.

### 4.6 axe and design contrast

axe runs with every rule on, including `color-contrast`. When the design's own
colours fail contrast (likely for `.bd-card.dim` at opacity `.26`, C:274), the
colour is **not** changed here. The failure becomes an allowlist entry in
C1-T02's `browser/support/design-parity-allowlist.json` with a new kind `axe`:

```json
{ "id": "axe-dim-card-contrast", "kind": "axe", "rule": "color-contrast",
  "selector": ".bd-card.dim .bd-title", "cells": {}, "measured": "2.1:1 dark",
  "reason": "Design dims filtered-out cards to opacity .26 (C:274)",
  "approval": { "status": "pending-sign-off", "by": null, "date": null,
                "ref": "MP-E8-C12-T05 §4.6" } }
```

(`pending-sign-off` is the spelling C1-T02's loader accepts; its
`allowlist validation` test rejects `pending-signoff`, C12-T08 note at its
line 27.)

- `loadAllowlist()` (C1-T02) accepts `kind: "axe"` and requires `rule`
  (`property` and `css` stay `null`).
- **How an entry is applied.** axe's `.exclude(selector)` is **not** used: it
  removes the element from every rule, so a missing name on an excluded card
  would pass. `.disableRules` is not used either: it turns the rule off for the
  whole page. Instead, PROPOSED `auditWithAllowlist(page, results, entries)` in
  the a11y spec runs the full scan, then removes from `results.violations` and
  from `results.incomplete` only the nodes whose rule id equals `entry.rule` and
  whose element matches `entry.selector` (checked with
  `element.matches(selector)` in the page, from the node's `target`). A
  violation left with no nodes is dropped. The filtered result goes to the
  unchanged `expectAuditClean` (`browser-helpers.mjs:68-77`).
- **Stale entry.** An `axe` entry that removes no node in a cell it covers fails
  that cell as "stale allowlist entry <id>" (the C1-T02 N11 rule, applied to
  matches instead of selectors).
- These contrast entries are sign-off item S-46.
- A `pending-sign-off` entry passes in CI; the C12-T08 `--gate` run fails while
  any entry is `pending-sign-off` (its G5), so a contrast
  failure cannot ship without Kevin's decision. That keeps "never cut
  accessibility" and "never restyle the design" both true.

## 6. Non-happy paths

- **Focused card removed by a diff** (merged, closed or filtered out): C9-T03's
  rule moves focus to the new element with the same id, else to `#bd-vp`, which
  can take focus only because of its new `tabindex="-1"`. This ticket keeps that
  rule and tests it with the roving stop (K-4).
- **Focused card scrolled out of the window:** stays rendered (§4.1). Test K-2.
- **Arrow to a card in a day that is not loaded yet:** the layout has no item, so
  Home stops at the oldest loaded card (the top of the history section). It does
  not call `loadEarlier`; scrolling to the top does, as in the design. Test K-1
  asserts Home and End on `dense` focus the first and last items of
  `readingOrder(L)`.
- **Focused card that is dimmed** (`dim` by a filter, `hdim` by a chain hover):
  shown at full strength while focused (§4.5), so the ring is visible. Test K-8.
- **Space on a card:** never scrolls the viewport (`preventDefault`); opens the
  modal without `?trees=1`; locks or unlocks with it. A now-band card gets no
  hover from focus (J:946), but Space still locks it through `fx.lockTree`,
  which finds band elements. Test K-3.
- **Modal open while the opener card leaves the board:** C11-T01 returns focus by
  id; if the id is gone, focus goes to `#bd-vp`. Verified in K-5.
- **Stale board** (daemon offline, EC-06/EC-07): card names carry the stale
  suffix from `agentText`; no live announcement is made, because no diff arrives.
  Test L-3 checks the `offline` dataset label.
- **Reconnect with a generation gap:** a snapshot, so no announcement (L-2).
- **A diff that fails to apply** (`applyDiff` throws and the hook resyncs): no
  announcement, because the board did not change. `noteDiff` runs only after a
  successful apply (L-5).
- **Read-only dashboard** (EC-12): disabled controls keep their reason in
  `title`; axe runs in `read_only` and `writable` modes. Keyboard behaviour on
  cards is the same in both, because opening a ticket is not a write.
- **Escape layering:** one Escape closes one layer, in this order: popover
  (C10-T02), modal (C11-T01), tree overlay, chain lock (C9-T11 decision 9).
  K-3 opens a popover over a locked chain and presses Escape three times.
- **Untrusted text** (EC-30): names are set with `setAttribute` and announcements
  with `textContent`; a title `"<img src=x onerror=alert(1)>"` stays text (A-6).
- **Huge board:** strings are built for rendered cards only; `readingOrder` is
  one sort per `relayout`. C12-T06 measures it at 10,000 tickets.
- **Uncertainty (platform):** which properties Chromium's forced-colours
  emulation overrides (box-shadow, gradients, SVG stroke). The tests do not depend
  on it: they assert the computed values set by this ticket's `@media` block,
  which apply whenever the media query matches
  (`page.emulateMedia({ forcedColors: 'active' })`, Playwright 1.61.1). A manual
  check in Windows high-contrast mode is in §8.

## Decisions made without the owner

1. **Roving tab stop with linear arrows**, not one tab stop per card. 1,300 cards
   as tab stops would make the board unusable by keyboard. Linear order copies
   `interaction.js:313-322`.
2. **The focused card is exempt from window recycling.** One condition in
   C9-T03; it is off screen, so no pixel changes.
3. **Space locks a chain only with `?trees=1`; otherwise Space opens the card,**
   like Enter. A `role="button"` is activated by Space in the ARIA button
   pattern, so a Space that does nothing would contradict the role. With
   `?trees=1` the house pattern (`interaction.js:278-283`, Space toggles a pinned
   selection) wins. No new shortcut; the feature stays hidden as S-3 says.
4. **`role="button"` with an `aria-label` summary.** The card opens a dialog and
   holds no interactive child. The summary includes the CSS-only text the
   design shows (`outside feature`, `also affects`).
5. **"dimmed by filter" is said for `dim`, not for `hdim`.** `hdim` is a
   transient hover state.
6. **Live announcements only for diffs, capped at three items.** Snapshots are
   silent; the banner covers reconnection.
7. **Design contrast failures go to Kevin as `pending-sign-off` allowlist
   entries,** not recoloured and not silently excluded. C12-T08 cannot pass while
   one is open.
8. **The forced-colours fallback differs by border style and width,** using only
   system colours (`Highlight`, `CanvasText`, `GrayText`).
9. **No reduced-motion additions.** The global product rule already covers the
   cases C9-T10 and C1-T03 sent here.
10. **Complexity 3,** as the row sizes it: one small module, small edits in five
    ported modules, CSS, five diff fixtures, and one spec file with a matrix.
11. **Removed now rows are not announced.** A `remove` of a now row has no
    state to name ("Merged" and "Failed" arrive as an upsert to `hist`), and a
    generic "left the board" would be a guess about the cause. The card name
    and the List view still show the board.
12. **No new dash pattern for edges under forced colours.** Plain/`ok` and
    `bl`/`bad` differ there only by width; inventing patterns would be a design
    decision. The card text carries the blocked state. Listed for C12-T08.
13. **A focused dimmed card is shown at full strength** (S-12 default, §4.5).
    The design's opacity would otherwise fade the ring to 26 %.
14. **`!important` inside the forced-colours block and the dim focus rule
    only.** The design's theme and palette selectors out-rank any plain
    selector; matching each of them would copy their specificity into this
    block and break the next time a theme rule is added.
