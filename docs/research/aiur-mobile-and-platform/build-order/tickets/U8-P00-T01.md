## Chosen design

Options for the owner, with the recommendation first:

| Option | Effect | Risk |
| --- | --- | --- |
| **A (recommended).** Keep the four files tracked and unchanged. U0's gate treats files named `package-lock.json` and `bun.lock` as a generated class: they are exempt from the 500 ceiling, and the gate instead requires that the file is the exact output of its tool (`npm install --package-lock-only --ignore-scripts` / `bun install --lockfile-only` gives no diff). | Exact transitive pins and integrity hashes stay. The exemption is narrow, checked and named. | It is an exclusion. The plan's U8 exit must say "no exclusions except tool-verified lockfiles". |
| B. Stop tracking lockfiles; CI resolves from `package.json`. | Size debt goes to zero. | Transitive versions float. That weakens supply-chain control and makes builds unrepeatable. Not acceptable without a replacement pin. |
| C. Cut dependencies until each lock is under 500 lines. | No exclusion. | Not possible for the Stream Deck package (196 entries) without dropping features. |

If the owner picks A, the gate rule is: path basename in {`package-lock.json`,
`bun.lock`}, and the regeneration check passes. Any other generated file stays
under the normal rule.

## Implementation steps

4. Option B or C: open a separate decision ticket; do not apply here.

## Non-happy paths

- **Hand-edited lockfile:** the regeneration check fails, so a manual edit
  cannot hide under the exemption.
- **Tool version drift:** a different npm version can rewrite the file. Pin the
  tool version the check uses to the one in CI (`actions/setup-node` version).
- **Offline CI:** regeneration needs the registry. If the check cannot reach it,
  the gate reports "unverified" and fails; it never passes silently.
- **A new lockfile appears** (for example under `src/browser/`): the same class rule
  covers it; no ledger edit needed.

## Compatibility and rollout

No runtime or config change. The gate change ships in the required job, so a
rollback is a revert of the gate PR. Builds and `npm ci` steps are unchanged.
