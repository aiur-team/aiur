## 4. Chosen design

### 4.1 Payload: `agent.units` on `now` rows only

```json
"agent": { "model": "claude", "name": "Claude",
           "state": "active", "effort": "high",
           "units": { "version": "OPUS 5.1",
                      "turns": 12,
                      "context": { "used": 82000, "window": 200000, "label": "41% 82k/200k" },
                      "priority": "HIGH",
                      "ci": { "decision": "pass", "pr": 12 },
                      "resume": null } }
```

| Key | Type | Producer rule (NowRows) | `null` means |
| --- | --- | --- | --- |
| `version` | str (≤ 32 chars) \| null | `UnitsPresentation.model_version(row).label` (`units_presentation.ex:145-154`) | no source names the model |
| `turns` | int ≥ 0 \| null | `row.turn_count` | not observed |
| `context` | `{used: int ≥ 0, window: int > 0 \| null, label: str}` \| null | `row.context_usage`: `used = used_tokens`, `window = window_tokens` (a non-positive or non-integer window → `null`); `label = AgentContextPresentation.compact/1` (`agent_context_presentation.ex:15-26`, which reads the same two keys) | not observed |
| `priority` | `"HIGH"\|"MED"\|"LOW"` \| null | `nil` when `complexity` and `effort` are both `nil`; else `elem(UnitsPresentation.priority(row), 0)` | unknown |
| `ci` | `{decision: "pass"\|"fail"\|"pending"\|"unknown", pr: int > 0 \| null}` \| null | `row.ci` (§4.3) | no CI result cached |
| `resume` | str \| null | `UnitsPresentation.latest_text(row)` when `row.reasons.resume` is a map, else `nil` | no declined or dropped resume |

- **Runtime is not in the payload.** It is `nowMs() − t.start`, computed on the
  client (§4.2 R1). This is the Units rule (`runtime_seconds` is
  `now − started_at`, `status_report.ex:520`), but without the `0` for an
  unknown start, and it ticks without a diff per second.
- `units` is present only on `sec: "now"` rows. A `hist`, `plan` or `nq` row
  never has it. **Absent means "not a live agent", `null` inside means
  "unknown".** The client renders them differently (§4.2).
- `units` is optional inside `agent` so the C3-T02 fixtures that do not set it
  stay valid. The validator rejects `units` on a non-`now` row and any value of
  the wrong type (`Payload.validate/1`, C3-T02 implementation step 1).
- The block holds no URL and no token. A guard test proves that (V7).
- **Size.** About 150 B per now row; 25 agents add about 4 KB, inside C3-T02's
  64 KB fixture budget. A change in `turns`, `context` or `ci` upserts that
  row once, as other agent changes do.

### 4.2 Rendering rules (client, `modal/units.js`)

`renderUnits(t, metaEl, agentEl)` is called by `renderHead(t)` after it builds
the header. It does nothing when `t.sec !== "now"` or `t.agent?.units` is
absent.

| # | Field | Known | Unknown (`null`, or not a valid value) |
| --- | --- | --- | --- |
| R1 | Runtime | `Runtime ` + `fmtRun(floor((nowMs() − t.start)/1000))`; `fmtRun(s)` = port of `format_duration/1` (`"1h 4m"`, `"7m"`); negative differences clamp to `0` as `running_seconds/2` does | `t.start` null or `nowMs()` null → `Runtime unknown`, `data-unknown="runtime"`. Never `0m` |
| R2 | Turns | `Turns 12` (a real `0` renders `Turns 0`) | `Turns unknown`, `data-unknown="turns"` |
| R3 | Context | `Context ` + `context.label` | `Context unknown`, `data-unknown="context"`. Never `—` and never `0%` |
| R4 | Priority | `Priority HIGH` | `Priority unknown`, `data-unknown="priority"`. Never `LOW` |
| R5 | CI | `pass`/`fail`/`pending` → `CI pass`, `CI fail`, `CI pending`; with `pr` → ` · PR #12` | `ci.decision: "unknown"` → `CI unknown`, `data-unknown="ci"`; `ci: null` → `CI not observed`, `data-unknown="ci"` |
| R6 | Resume | a line `<span class="bm-u bm-u-resume">` with the text | `null` → no element (no resume event is a fact, not an unknown) |
| R7 | Model version | `.bm-agent` `title = name + " " + units.version + (effort ? " · " + effort + " effort" : "")` (the design's `m.full + " · " + effort + " effort"`, J:1390, with real values) | `version` null → C11-T01's title unchanged (`name`, plus effort) |

- Each R1–R5 value is one `<span class="bm-u" data-u="<key>">` appended to
  `.bm-meta` after the `pts` span, in the order R1, R2, R3, R4, R5. Text goes
  through `esc`. Numbers are checked with `Number.isInteger` before use.
- **Agents source stale or unavailable** (`ctx.snap.sources.agents.state`,
  C8-T01):
  - `"stale"`: every `.bm-u` gets the class `stale`, and one more span
    `<span class="bm-u stale" data-u="age">stale · 3m</span>` shows the age
    from `observed_at` (AGENTS.md "If a surface computes an age, it renders
    the age"). `observed_at: null` → `stale · age unknown`.
  - `"unavailable"`: R1–R5 render their unknown text; R6 renders nothing. A
    row can still be open from an earlier snapshot when the band empties, so
    this branch is reachable.
- **Screen readers.** Each span has its full text, so no `aria-label` is
  needed. The model version is in `title` only, as the design does; it is also
  in the span text of C11-T01's `.bm-agent` name, so no fact is title-only
  except the effort, which the design already puts there.
- **Runtime tick.** While the modal is open on a `now` row,
  `ctx.life.later("bm-units", 30_000, tick)` re-renders R1 only. `tick`
  returns early when `MS.t` changed or is null; it re-arms itself.
  `onModalClose` sets a flag so no tick runs after close. The label changes at
  most once a minute, so 30 s is enough (C10-T04 decision 8 uses the same
  period).
- Live values: C11-T01's `modalSync` re-runs `renderHead` when the open row is
  upserted, and `renderHead` calls `renderUnits`. No extra subscription.
- **Tick lifetime.** `renderUnits` re-arms the `"bm-units"` timer on every
  open, so a reopen within 30 s replaces the old timer (`later` clears the
  same key, C9-T01 `life.js`).

### 4.3 `ci` on `UnitsRow` (server)

PROPOSED edit to `units_row/projection.ex` `row/5`: add
`ci: Fields.ci(status_row)`. PROPOSED `units_row/fields.ex`:

```elixir
@ci_decisions %{pass: "pass", passed: "pass", fail: "fail", failed: "fail",
                pending: "pending", unknown: "unknown"}

@spec ci(map() | term()) :: %{decision: String.t(), pr: pos_integer() | nil} | nil
def ci(status_row) do
  case Value.get(status_row, :ci_result) do
    %{} = result ->
      %{decision: Map.get(@ci_decisions, Value.get(result, :decision), "unknown"),
        pr: positive(Value.get(result, :pr_number))}
    _none -> nil
  end
end
```

- The allow-list is the `build_order_presenter.ex:32` set. It is copied, not
  called: `safe_ci_result/1` is private in a presenter of another page, and a
  call from `operator_control_center/` into `build_order_presenter.ex` would be
  a new dependency in the wrong direction.
- A decision outside the list maps to `"unknown"`, never to a specific
  decision (AGENTS.md "A collapsed cause names the collapse at the source").
- `head_sha` and `draft?` are not carried: the modal does not show them.
- The Units page ignores the new key (it reads named keys only), so its output
  does not change.

## 6. Non-happy paths

- **Unknown start** (retrying and latched rows, C8-T01 `start: nil`): R1 shows
  `Runtime unknown`. This is the case where Units shows `0m` today.
- **Data clock not set** (`nowMs()` null before the first snapshot; a fetched
  row opened before it): `Runtime unknown`, then the first tick fixes it.
- **Turn count reported as 0 but not observed:** the producer sends `null`
  (`projection.ex:107-111` already returns `nil`), so the modal shows
  `Turns unknown`, not `Turns 0`.
- **Context map with a negative or non-integer `used`:** the projection
  returns `nil` (`:113-117`); `Context unknown`.
- **Priority with no complexity and no effort:** `null` → `Priority unknown`.
  The Units page shows `LOW` here; the modal does not copy that.
- **CI decision outside the allow-list** (a new atom, a string): `"unknown"`
  → `CI unknown`. `ci_result` missing: `CI not observed`.
- **Hostile text** in `resume` (it embeds pause reasons and rejection detail):
  `esc` on the client; the server sends text, not HTML (C3-T02 rule 1).
- **Stale agents source:** values dimmed with the age shown. **Unavailable:**
  all unknown. Neither is drawn as current.
- **Row leaves the band while open** (merged, cancelled): the upsert moves it
  to `hist` without `units`; `renderUnits` draws nothing, which is right for a
  history row. The tick stops itself because `t.sec !== "now"`.
- **Read-only dashboard:** the fields are reads; they show for every session,
  as the Units table does. No control is added, so EC-12 adds no gate here
  beyond §4.6.
- **Reconnect / generation gap:** handled by C3-T02's full snapshot; the modal
  re-renders through `modalSync`. Nothing new here.
- **Concurrency, idempotency, retries:** not applicable; the ticket adds no
  write.

1. **Placement is the `.bm-meta` line** (§4.4). It needs no new box, uses the

   index broadcast), only when `dashboard_writable?/0` is true at read time,
   re-check on every open, and never log it.

   avoids `running_seconds/2`'s `0` for an unknown start and avoids a diff
   every second. It matches Units: `status_report.ex:520` uses
   `running_seconds(started_at, now)`, not `effective_runtime_seconds`, so the

   forward by the paused span (`state.ex:808-813`
   `apply_pause_runtime_clock/4`), and C8-T01's `start` is that same
   status-row `started_at`, so both surfaces drop the paused span at the same
   moment.
6. **Priority is unknown when effort and complexity are both unknown.** Units
   shows `LOW` there (`units_presentation.ex:171`). Otherwise the modal uses
   Units' rule unchanged. "Priority" here is Units' derived HIGH/MED/LOW, not
   the tracker priority the status row also carries

7. **"CI state" is the cached CI poll result,** the only CI fact the status
   row has. The work-order row says Units shows CI state; it does not, only the
   dead `FleetTable` did.
8. **`CI not observed` differs from `CI unknown`:** the first means no result
   is cached, the second means a result exists with an unknown decision.
9. **Tokens means context occupancy,** as on Units. Cumulative token totals
   are not shown.
10. **Stale looks reuse C10-T04's 55 % opacity** and show the age in a visible
    span.
11. **The CI allow-list is copied** from `build_order_presenter.ex:32`, not
    shared (§4.3).
12. **Complexity 3, not 2.** The fields need one server field, one mapper
    function, one validator block, one fixture-map change, one client module
    and one CSS block across five neighbours' files.
