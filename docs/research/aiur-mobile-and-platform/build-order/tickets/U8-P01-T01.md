Rationale: these are the three responsibilities that prior boundary §20 names (registry,
routing, model grammar). The facade keeps the `Aiur.CodingAgent.*` API, so MP-R7-C4-T03
moves four cohesive files, not one oversized file. Invariants: function names, arities,
return shapes, `@spec`s and doc text stay; `fetch_backend!/1` still raises on an
unknown backend.

Tests: `coding_agent_test.exs` splits into `coding_agent/routing_test.exs` (select,
override, alias, backend_for, effort, complexity: about 420), `coding_agent/model_grammar_test.exs`
(resolve and alias groups: about 200) and `coding_agent_test.exs` (descriptors, registry
dispatch, send_operator_message, codex command and error groups, Backend wiring,
runtime_report: about 420). `open_ai_compat/coding_agent_test.exs` splits by concern
into `open_ai_compat/coding_agent_tool_loop_test.exs`, `.../coding_agent_openrouter_test.exs`
(:394-:569) and `.../coding_agent_checkpoint_test.exs` (:570-:784), with a shared
`setup` helper in `src/test/support/` only if two files need it.

## Implementation steps

1. Create `ModelGrammar` and move the label attributes and model functions. Facade
   delegates. Run focused tests.
2. Create `Routing`; move selection functions. `Routing` calls `ModelGrammar` and
   `Registry` directly, not the facade, to avoid a cycle.
3. Create `ProvidersView`; move descriptor functions.
4. Split both test files by `describe` group as above. Keep `async: true` and every
   existing `setup`.
5. One PR (about 3,200 moved lines, all moves).
