## Identity and outcome

- Bucket 2, feature MP-E8 (continuous build history), chunk C11 (ticket modal and
  agent chat, read and write).
- **User value.** In the ticket modal the operator presses the microphone, speaks,
  presses it again, reviews the text in the composer and presses Send. This is the
  same dictation the Units drawer has today, in the design's look. When dictation
  cannot work (no ElevenLabs key, insecure origin, browser without Web Audio,
  permission denied) the button says why. It never pretends to be ready.
- **Deliverable.**
  1. `#cv-mic` in `form#cv-in` (built by C11-T06) drives the existing
     `ConversationVoiceController` in dictation mode. The button shows the design's
     `.cv-mic` idle look and `.cv-mic.rec` + `cvRec` pulse while recording.
  2. A server reply `voice-availability` tells the modal, before the button is
     enabled, whether speech-to-text is configured (S-11).
  3. Four small additive edits to `priv/static/conversation-voice-controller.js`
     (keep the mic's own title, toggle `.rec` and sync the unavailable reason into
     `title`, a failure flag on the status element, pass that flag from the failure
     paths). The Units drawer keeps its behaviour.
  4. A status line for failures and a screen-reader live region, both in one
     element.
- **Non-goals.**
  - No spoken conversation mode, no reply audio, no waveform canvas, no device
    picker. The design has one microphone button and none of these. They stay in
    the drawer, which "Open in Conversations" (C11-T07) still reaches.
  - No change to the send path, delivery states or drafts (C11-T06).
  - No change to `AiurWeb.VoiceSocket`, `AiurWeb.VoiceChannel` audio handling,
    session limits or the ElevenLabs session.
  - No general focus ring or forced-colours pass for the page (C12-T05, S-12).
    This ticket adds only the forced-colours rule its own recording state needs.
  - Not a cutover blocker (chunks.md C12: "C11-T09 is not a cutover blocker").

## Chosen design

### Where it lives

- PROPOSED `priv/static/build-home/modal/mic.js`, one ES module (C9-T01 module
  rules: no `document`/`window` listeners, no timers; the scan S2 stays green
  because all listeners are on elements inside the classic controller file).
- It exports `mountMic(root, ctx)` → `{ rebind(), destroy() }`. `root` is the
  `.cv-main` element that holds the status line and `form#cv-in`.
- C11-T06's composer module calls `mountMic` after it renders `form#cv-in`, calls
  `rebind()` if it ever re-renders inner composer nodes, and calls `destroy()`
  before it removes the form. C11-T01's `cleanupModal` path (J:1368) and the hook's
  `destroyed` (`ctx.life.dispose()`) reach the same `destroy()`.

### Availability first, then the controller (S-11)

The button starts **disabled** with the title "Checking whether dictation is
available…". It is never rendered enabled before the server answers.

```js
// build-home/modal/mic.js (PROPOSED)
const UNKNOWN = "Dictation availability is not known. Reconnect to the dashboard, then try again.";
export function mountMic(root, ctx) {
  const mic = root.querySelector("#cv-mic");
  if (!mic) return { rebind() {}, destroy() {} };   // composer hidden (read-only, past ticket)
  let voice = null, dead = false;
  off(mic, "Checking whether dictation is available…");
  ctx.push("voice-availability", {}).then((reply) => {   // C9-T01 ctx.push → LiveView reply Promise
    if (dead || !root.isConnected) return;
    const Ctl = window.AiurConversationVoiceController;
    if (reply?.state !== "available" || !Ctl) return off(mic, reply?.reason || UNKNOWN);
    mic.disabled = false; mic.title = "Dictate"; mic.removeAttribute("aria-disabled");   // C11-T06 default
    voice = new Ctl({ el: root }); voice.mount();   // binds [data-voice-mic]; may still disable (insecure origin, no Web Audio)
  }, () => { if (!dead && root.isConnected) off(mic, UNKNOWN); });   // rejected push (socket down)
  return { rebind: () => voice?.bindElements(), destroy() { dead = true; voice?.destroy(); voice = null; } };
}
function off(mic, reason) { mic.disabled = true; mic.title = reason; mic.setAttribute("aria-label", "Dictate (unavailable)"); }
```

- `#cv-mic` must carry `data-voice-mic` (added in step 6). Without it the
  controller binds no button (`:28`, `:135`) and the click does nothing.

- **States of the button.**

  | State | Source | `disabled` | `title` | Class |
  | --- | --- | --- | --- | --- |
  | checking / unknown | no reply yet, no reply ever, rejected push (LiveView down), reply without `state` | yes | "Checking…" then stays, or the UNKNOWN copy | — |
  | unconfigured | reply `unconfigured` | yes | `voice_channel.ex:254` copy, verbatim | — |
  | read-only | reply `read_only` (defensive; the form is normally hidden) | yes | "Read-only dashboard — dictation is off." | — |
  | browser cannot | controller `mount` (`:18-21`) | yes | the controller's reason (new title sync) | — |
  | idle | reply `available`, mount passed | no | "Dictate" (design) | `cv-mic` |
  | starting | permission prompt open | yes (controller `:141`) | "Dictate" | — |
  | recording | controller `recording` | no | "Dictate" | `cv-mic rec` |
  | finishing | waiting for the final transcript | yes | "Dictate" | — |
  | failed | permission, no device, transport, 5 s timeout | no | "Dictate" | — (+ visible status line) |

- An unknown availability is never shown as ready (AGENTS.md "unknown is never
  zero"): the default in `mic.js` is disabled, and every branch except an explicit
  `"available"` keeps it disabled.

### Server: `voice-availability`

- PROPOSED `AiurWeb.VoiceChannel.availability/0` → `:available | {:unconfigured,
  reason}`. It mirrors `start_stt/1` exactly so the check and the join cannot
  disagree:
  1. `Endpoint.config(:voice_stt_start_fun)` is a 1-arity function → `:available`
     (the injected seam owns the answer, as in the browser fixture).
  2. `Aiur.ElevenLabs.Realtime.configured?()` → `:available`.
  3. else `{:unconfigured, @unconfigured_reason}`.
  The `:254` string moves into `@unconfigured_reason`, used by both
  `start_realtime/0` and `availability/0` (one copy).
- `Aiur.ElevenLabs.Realtime.configured?/1` becomes public with a default:
  `def configured?(api_key_fun \\ &Config.elevenlabs_api_key/0)` and a `@doc`. The
  body is unchanged (rescue/catch → false). `boot/2` keeps calling it.
- PROPOSED `AiurWeb.BuildLive.handle_event("voice-availability", _params, socket)`
  → `{:reply, reply, socket}`:
  - `dashboard_writable?()` false → `%{state: "read_only", reason: "Read-only
    dashboard — dictation is off."}`;
  - `:available` → `%{state: "available", reason: nil}`;
  - `{:unconfigured, r}` → `%{state: "unconfigured", reason: r}`.
  The reply carries a boolean answer and fixed copy. It never carries the key
  (the same rule as `streamdeck_projection.ex:42-45`).
- The check runs on every composer mount, so a key added while the page is open is
  seen on the next modal open. No subscription.

### Composer lock and Enter

- `#cv-mic` gets `data-voice-mic` and `.cv-send` gets `data-voice-send` (two
  attributes on C11-T06's markup; the textarea already has `data-voice-input`).
  The controller then binds the button and locks the textarea and Send during
  capture (`:94-99`), as in the drawer. No pixel change: `.cv-send` sets its own
  `background` and `color` (C:564), so the disabled state does not repaint it.
- C11-T06's **submit** listener (not only the Enter listener) gets one guard at its
  top: `if (ta.readOnly || form.getAttribute("aria-busy") === "true") return;`.
  - `readOnly`: Enter during recording calls `form.requestSubmit()` (J:1489 port),
    which submits even when the submit button is disabled, and would send a partial
    transcript.
  - `aria-busy`: the controller's `syncElements` writes `send.disabled =
    composerLocked` (`:99`). If the operator dictates while a `send` is still in
    flight, the end of dictation sets `send.disabled = false` and a second click
    would push a duplicate `send`. C11-T06's own busy flag stops that. If C11-T06
    already returns early on `aria-busy`, keep its check and add only `readOnly`.

## Interface notes (mismatches with neighbour rows)

1. **C9-T01 `ctx.push` (no mismatch).** C9-T01 defines `ctx.push = (e, p) =>
   this.pushEvent(e, p)`. In LiveView 1.1.33 that returns a Promise of the reply
   (`phoenix_live_view.js:4099-4101`), so this ticket uses `.then` and needs no
   third argument and no C9-T01 change. If C9-T01 ever wraps `ctx.push` (its B5
   counter), the wrapper must return the inner Promise.
2. **C11-T06 must not replace `form#cv-in` on a diff.** The design re-runs
   `openModal(t)` after pause (J:1447–1449), which rebuilds the composer. In the
   product a ticket diff or a pause/resume (C11-T07) must patch the placeholder and
   state in place; otherwise any diff stops a recording. If C11-T06/T07 must
   re-render, they call `mic.destroy()` first and accept that recording stops.
3. **C11-T06 markup.** C11-T06 already gives `data-voice-composer` /
   `data-voice-input` and renders `#cv-mic` with `aria-disabled="true"`,
   `title="Dictate"`, no handler. This ticket adds `data-voice-mic` to `#cv-mic`,
   `data-voice-send` to `.cv-send` and the `.cv-voice-note` element before the
   form, and removes `aria-disabled` only on an `available` reply (C11-T06
   interface note 4). C11-T06 needs no change before this ticket.
4. **S-7 line.** C11-T06's `#cv-in-st` (S-7) is after the form; this ticket's
   `.cv-voice-note` is before it. They are two elements in two slots and cannot
   overlap. Both are `role="status"`; only one normally speaks at a time
   (dictation progress vs send result).
5. **C11-T06 submit guard.** This ticket adds `readOnly` (and `aria-busy`, if
   C11-T06 does not already return on it) to the top of C11-T06's submit listener.
   C11-T06's own Enter handler keeps its IME check.
6. **C2-T04** must port C:560–565 and the `.cv-mic.rec` part of C:610 verbatim;
   this ticket adds rules after them and does not edit them.

## Decisions made without the owner

1. **Dictation only.** The modal gets no spoken-conversation button, waveform or
   device picker, because the design has one microphone and nothing else. Those stay
   in the drawer reached by "Open in Conversations". The modal uses the browser's
   default microphone, not the drawer's saved device (`localStorage`
   `aiur-dashboard-microphone-device`), to avoid an `exact` device that may be
   unplugged.
2. **Availability is asked, not pushed.** A hook reply per composer mount instead of
   a new field in the C3-T02 payload schema, so the schema and its validation are
   untouched.
3. **Unknown is disabled.** Before or without a reply the button is disabled with a
   reason. S-11 names only "not configured"; the same look is used for unknown,
   read-only and browser-unsupported.
4. **Disabled look.** `opacity: .45`, default cursor, no hover. The design has no
   disabled state; this is the smallest visible difference. Kevin can change it at
   DESIGN-E8.
5. **Failure text placement.** A visible line in the `.cv-typing` slot and type,
   in `--block-ink`, only while a failure is active; otherwise visually hidden but
   announced. A `title` alone is not visible on touch screens, so permission
   denial needs visible text.
6. **Accessible name.** The controller's "Dictate message" / "Stop dictation"
   replaces the design's `aria-label="Dictate"`; the visible `title` stays
   "Dictate". No pixel change.
7. **Forced colours.** A `Highlight` outline for the recording state, because the
   design shows recording only by colour and `box-shadow`, both lost in forced
   colours.
8. **Touch target.** 34 px stays (pixel parity). C12-T05 decides whether phones get
   a larger hit area.
9. **Reply control in browser tests.** B5/B6/B6b rewrite or drop the
   `voice-availability` reply on the LiveView WebSocket with Playwright
   `routeWebSocket`, instead of adding a per-spec switch to the shared fixture
   server. It keeps the fixture unchanged for every other spec.
10. **Guard on submit, not on keydown.** The `readOnly` / `aria-busy` guard sits in
    the submit listener, so Enter, a click and any `requestSubmit()` are covered by
    one check.
