# U3-T03 - Wake inbox journal recovery and visible failures

## Identity and outcome

- Bucket 1, prior unit U3 ("wake receipt/replay" follow-up).
- **User value:** one bad line in the Executor's wake journal no longer stops
  the inbox process (and with it every Executor wake); flush and trim failures
  raise an attention instead of retrying silently.
- **Deliverable:** corrupt journal → quarantine the bad tail and start;
  repeated flush failure → one alert; trim error → logged and alerted once;
  `acknowledge/2` (no ownership check) routes through `acknowledge_as/3`.
- **Non-goals (decision):** no new durable "action receipt" record. The
  plan's "receipts distinct from observation" is met by naming what exists:
  cursor ack = "seen", `Claims.record_acknowledgement` = "owner took it". A
  proof-of-work receipt would be a new feature; deferred to MP-E2/E3 if they
  need it (recorded in README decisions).

## Dependencies and blockers

- U0-T01; U3-T02 (ack path uses the fixed owner selection).
- MP-R2-C3-T01 must **not** migrate this module's `DecisionLog` calls (its own
  ticket says so); no conflict if it lands either side.

## Verified starting point (`58854d4c8`)

- `src/lib/aiur/executor_wake_inbox.ex` (619 lines): journal via
  `DecisionLog.prepare` / `replay` (:113, :333-339, :362-367, :429-445). On
  corruption `init/1` returns `{:stop, reason}` (:130). `flush_pending/1`
  re-arms its timer on error **without logging** (:286-288). `trim_consumed/1`
  ignores errors (:558-563).
- Cursor: `advance_cursor/2` writes `last_seen_wake_id` (:469-473);
  `current_cursor` = max(memory, file) (:465).
- `acknowledge_as/3` (doc :42-62) → `acknowledge_records_as/4` (:537-545):
  `Claims.record_acknowledgement` then cursor. Bare `acknowledge/2` (:40) skips
  the ownership check.
- `DecisionLog.replay` already has a torn-tail contract (KTD10: "a torn
  unacknowledged tail follows the existing replay contract") - reuse it.
- Tests `test/aiur/executor_wake_inbox_test.exs:342, :352` cover a corrupt
  pending store, not a corrupt journal line.

## Chosen design

- `init/1`: on a replay error that `DecisionLog` classifies as a torn/corrupt
  tail, rename the journal to `<name>.corrupt-<unix>` (keep evidence), start
  with the good prefix, emit `Aiur.Alerts` `executor_wake_journal_quarantined`.
  Any other error keeps `{:stop, reason}` (do not hide real failure).
- `flush_pending/1`: count consecutive failures; log each at warning; alert
  once at 3 (`executor_wake_flush_failing`); reset on success.
- `trim_consumed/1`: log the error; alert once per process lifetime.
- `acknowledge/2`: call `acknowledge_as/3` with the default principal, or
  remove it if `rg` shows no callers outside tests.

## Implementation steps

1. Quarantine path in `init/1` using `DecisionLog`'s existing error shape.
2. Flush counter + alert; trim log + alert.
3. `acknowledge/2` change after caller check.
4. Tests.

## Non-happy paths

- **Quarantine rename fails** (read-only dir): return `{:stop, reason}` as
  today and alert with the reason - never start on an unreadable journal.
- **Wakes lost in the quarantined tail:** they were unacknowledged; the alert
  says so with the count of bad bytes; the Executor runs `aiur alerts`.
- **Restart loop:** the supervisor no longer loops on a corrupt tail.

## Compatibility and rollout

File format unchanged. Rollback: revert (quarantined file stays as evidence).
