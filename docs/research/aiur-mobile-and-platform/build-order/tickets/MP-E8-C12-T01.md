  retirement, mobile, accessibility, performance, docs, sign-off).

  page at `/`, with the live band in view. The nav has one "Build" item with the
  active-agent count, as in the design. Old links still work: Units filter links
  open the home page with the matching filter, and `/chat/...` links open the

### Route registry

```elixir
@routes [
  %{id: :build, label: "Build", icon: "", description: "", path: "/", type: :live,
    owner: :build, availability: :available, active_actions: [:build]},
  # :commands, :analytics, :streamdeck unchanged
]
# Not in the nav. They resolve only as the current route of their own page.
@hidden_routes [
  %{id: :units, label: "Units", icon: "◫", description: "", path: "/units", type: :live,
    owner: :dashboard, availability: :available, active_actions: [:index]},
  %{id: :build_order, ...unchanged map...}
]
def current_route(action), do: Enum.find(@routes ++ @hidden_routes, &active?(&1, action)) || hd(@routes)
```

`routes/1` and `route/2` read `@routes` only. So `route(:units, _)` is
`:error`, and the nav cannot render a hidden entry. On `/units` and
`/build-orders`, no nav item is active, and the page keeps its own title. The
fallback for an unknown action is Build.

### `/chat/...` redirect (EC-26)

PROPOSED `lib/aiur_web/controllers/chat_redirect_controller.ex`, routed in the
`:136–137` group (same auth, outside the live session):

| Input | Response |
| --- | --- |
| identifier passes `github_issue_identifier/1` and has at most 10 digits, owner/repo pass `github_repository_components/2`, and `same_repository?(%{owner: o, repository: r}, %{owner: co, repository: cr})` with `{:ok, {co, cr}} = configured_repo()` | `302` to `/?ticket=<identifier>`, with the request's other query keys dropped |
| owner or repo is not the configured repository, or is invalid; identifier is not canonical (`007`, `+7`, `AIUR-7`) or has more than 10 digits | `404`, `text/html`: "Chat is unavailable for this ticket." plus a link to `/` |
| `configured_repo()` returns `{:error, _}` | `503`, the same body plus "The configured repository cannot be read." |

- **302, not 301.** The rollback may move `/chat` back, and a browser keeps a
  301 in its cache.
- **Ticket id format.** Only the canonical form redirects, because
  `github_issue_identifier/1` rejects a leading zero (`bounded.ex:235`). Every
  producer writes the canonical form (`context_runtime.ex:244`,
  `bounded.ex:156–167`), so nothing real is lost. The 10-digit cap matches
  C3-T03's `ticket` rule. A longer id would redirect to a URL that C3-T03 drops,
  which is a silent dead link, so it is a 404. C11-T01 then opens the modal or
  shows its not-found state (S-10).
- **`chat: null` until C14-T03.** The C11-T01 `open-ticket` reply carries
  C11-T07's `chat` field. BuildLive sends `chat: null` for every ticket until
  C14-T03 lands: a `/chat/...` link would redirect to `/?ticket=N` and reopen
  the same modal (U25).
- **Why check the repository.** A foreign-repo link must not open the issue
  with the same number in this repo. That would show the wrong ticket.
- **Test seam.** The controller reads the repository through
  `conn.private[:aiur_configured_repo]` (a zero-arity function), with the
  default `&Aiur.GitHub.Config.configured_repo/0`. This is the
  `ticket_detail_repository.ex:12` seam moved to where a controller can see it.
  A test sets it with `Plug.Conn.put_private/3` before `get/2`. No production
  code sets it.

### Nav count (`:build`)

The design shows `fleet.length` (H:4967, `#tabcount-fleet`). The row says
"active agents". The count has one definition, the now rows whose
`agent.state` is `"active"` (C8-T01 row 6, the state the board shows as
"Running"), and it is shown only where that source exists: the home page.

- **BuildLive.** PROPOSED `lib/aiur_web/build/nav_count.ex`,
  `AiurWeb.Build.NavCount`, is pure:
  - `from_snapshot(payload) :: state` where `state` is
    `%{ids: MapSet.t(), known?: boolean()}`. `ids` holds the `now` rows with
    `agent.state == "active"`. `known?` is true when `sources.agents.state` is
    `"ok"` or `"stale"` (the C8-T01 table), and false when it is
    `"unavailable"` or missing.
  - `apply(state, changes)`:
    - An `upsert` of a row with `sec == "now"` and `agent.state == "active"`
      adds its id.
    - Any other upsert of that id removes it.
    - A `remove` of the id removes it.
    - `set.sources` recomputes `known?`.
    - A `resync: true` gives `known?: false` until the next snapshot.
  - `count(state) :: non_neg_integer() | nil`: `nil` when not known.
  BuildLive calls `from_snapshot/1` at **every** place it stores a snapshot:
  the C3-T01 mount read (`handle_async(:build_snapshot, …)`) and the C3-T02
  `build-resync` handler when it reads again. It calls `apply/2` on each
  `{:build_changes, …}` that C3-T02 accepts. A change dropped as stale (its
  `index_generation` ≤ `:build_index_generation`) is not applied. Rows and
  blocks are read with the key type that C3-T02's `Payload.row/1` emits; the
  NavCount tests build their input with `Payload.row/1`, not hand-written
  maps, so a key-type mismatch fails a test. `nav_counts` becomes
  `Map.merge(AwaitingCommands.nav_counts(…), build_count(state))`, and the
  `:build` key is present only when `count/1` is an integer.
- **The dead render and the loading state** have no `:build` key, so the shell
  shows no badge. It does not show `0`.
- **DashboardLive** (Commands and `/units`): `nav_counts/2` drops the `:units`
  key and emits no `:build` key. It keeps `:commands` with `> 0`. Renaming the
  Units count to `:build` would show a second number with another meaning
  (it depends on the URL filter, and it uses the `UnitsPolicy` rule, see
  Verified starting point), so the badge would change when the operator
  moves between `/` and `/commands`.
- **Analytics, Streamdeck and Build Order pages** keep
  `AwaitingCommands.nav_counts/1` only, so the Build item has no badge there.

### Global pause

PROPOSED `lib/aiur_web/operator_control_center/global_pause_control.ex`,
`AiurWeb.OperatorControlCenter.GlobalPauseControl` (the name from C2-T02
interface note 3):

- `server() :: GenServer.server()` is `capacity_orchestrator/0` moved
  verbatim (`dashboard_live.ex:845`), and `writable?() :: boolean()` is
  `dashboard_writable?/0` moved verbatim (`:1153`). DashboardLive calls them.
  So BuildLive never names `AiurWeb.Endpoint` or `Aiur.Orchestrator`, and the
  seam allow-list grows by two modules only.
- `from_payload(payload) :: true | false | nil` is C2-T02's
  `global_pause_state/1` moved here (C2-T02 interface note 3: "a move, not a
  rewrite").
- `state(server) :: true | false | nil` wraps `GlobalPause.globally_paused?/1`.
  `{:error, _}` becomes `nil` (unknown), never `false`.
- `toggle(current, server) :: :ok | {:error, message}`:
  - With `current` `true` or `false`, it calls
    `GlobalPause.set_global_pause(server, not current, "dashboard")`.
  - With `current` `nil`, it returns `{:error, "Global pause state is unknown; refresh and retry."}`
    and does not call. Inverting an unknown state would be a guess.
  - The two error strings are moved verbatim from `dashboard_live.ex:740–748`.
- **DashboardLive** passes `GlobalPauseControl.from_payload(socket.assigns.payload)`
  as `current`, not `global_paused?/1`. Today `global_paused?/1` turns an
  unknown state into `false`, so a click would pause the fleet on a guess.
  `global_paused?/1` and `global_pause_state/1` are then deleted: an unused
  private function is a compile warning, and the build uses
  `--warnings-as-errors`. On `:ok` DashboardLive keeps
  `reload_after_action/1` (`:738`).
- **BuildLive:**
  - It assigns `:writable` (`GlobalPauseControl.writable?/0`),
    `:global_pause_error` (`nil`) and `:globally_paused` (`nil`) in `mount/3`.
    The dead render therefore shows "Pause state unknown".
  - When connected, it reads the state with
    `start_async(:global_pause_state, fn -> GlobalPauseControl.state(GlobalPauseControl.server()) end)`.
    It does not call in `mount/3` itself, because the call can block for 5 s
    (`global_pause.ex:26`) and would hold the board's first render.
  - It subscribes to `ObservabilityPubSub` and handles **both**
    `:observability_updated` and `{:observability_updated, _event_id}` (the
    broadcaster sends the tuple, `observability_pubsub.ex:21`). Each one
    starts the same async read if none is running. If one is running, it sets
    `:global_pause_dirty` instead. When a result arrives, it sets
    `:globally_paused` (an `{:exit, _}` result sets `nil`), and if the dirty
    flag is set it clears it and starts one more read. So a burst of updates
    costs at most two calls, and an update that lands during a read is never
    lost. The board data has its own feed, so nothing else is re-read.
  - It handles `"toggle-global-pause"` behind the same writable re-check
    (`writable?/0` false → assign `:writable` false, no call). On `:ok` it
    clears `:global_pause_error` and starts the async read, so the item shows
    the new state even if the broadcast is missed (the `dashboard_live.ex:734–735`
    comment). On `{:error, message}` it assigns the message.
  - It renders the same `global-pause-error` banner markup
    (`dashboard_live.ex:925–928`) in the shell's `:banner` slot.
- The seam scan allow-list (C3-T01 rule 1) gains
  `AiurWeb.OperatorControlCenter.GlobalPauseControl` and
  `AiurWeb.ObservabilityPubSub`. C3-T01 does not list `AiurWeb.Endpoint`, and
  this ticket does not add it.

## Non-happy paths

- **Board unavailable on `/`.** C3-T01's state machine shows the unavailable
  state. The nav, the pause and Commands still work. The Build badge is absent.
  Rollback for the operator: `/units`.
- **Orchestrator down.** `GlobalPauseControl.state/1` → `nil`, and the shell
  shows "Pause state unknown" (C2-T02). A click returns the unknown-state error
  and does not call the orchestrator.
- **Slow orchestrator or a burst of updates.** The pause read runs in
  `start_async`, so the board keeps rendering while it waits (up to 5 s). Only
  one read runs at a time per tab; an update that arrives meanwhile marks the
  state dirty and causes exactly one more read. After a toggle, the new state
  appears when the next read returns; until then the item shows the last known
  value.
- **Read-only dashboard.** The pause button is disabled with the C2-T02 reason.
  A forged `toggle-global-pause` event is rejected by the server re-check and
  sets `:writable` false. This is unchanged from DashboardLive. `/chat`
  redirects work read-only, because a redirect is not a write.
- **Auth.** `/chat` stays in the `:dashboard_auth` scope. An unauthenticated
  request gets 401 before any redirect, so the redirect does not reveal whether
  a ticket exists. `/units` keeps `FinancialDataAccess`.
- **Foreign-repo or malformed `/chat` link.** 404 with fixed copy. The page
  never shows another repo's issue under the same number. A traversal-shaped
  component (`..`, `%2F`, which Phoenix decodes to `/` in the path param)
  fails `valid_path_part?/1` (`bounded.ex:234`) → 404. A non-canonical or
  over-long identifier is 404 (see the table).
- **Config unreadable.** 503. It never falls back to "assume it is ours".
- **Legacy Units URL on `/`** (`/?v=1&scope=unfinished&conditions=active`).
  C3-T03 patches it to `/?astate=active` with `replace: true`. An invalid
  legacy value is dropped by C3-T03's rules. It never crashes.
- **Back and forward across the cutover.** Going `/units` → nav "Build" → `/`
  → Back returns to `/units` with its filter query intact. This is a
  `navigate` across owners, so each page mounts fresh, and the URL is the
  state.
- **Stale or out-of-order changes.** `NavCount.apply/2` only sees changes that
  BuildLive accepts (generation rules from C3-T02 and C8-T04). After a resync
  the badge hides until the new snapshot arrives. It never shows a stale
  number as current.
- **Concurrency.** Each tab has its own `NavCount` state. Nothing is shared or
  persisted.
- **Old bookmarks of `/` with Units sort** (`/?sort=fleet:…`). C3-T03 drops
  unknown keys, so the page loads with the defaults.

## Decisions made without the owner

1. **Complexity is 4, not the row's 3.** The pause extraction (C2-T02 note 3,
   not done in C3-T01), the nav-count fold and the `/chat` controller are real
   work beyond the route swap.
2. **`/build` stays a live alias, not a redirect.** The browser fixture server
   shadows `/` with a harness page (`fixture_server.exs:2275`), so every
   browser and parity test of the home page has to use `/build`. U4 ties the
   two paths together. C12-T03 may remove the alias if it moves the harness
   route.
3. **`/chat/...` redirects (302) instead of a drawer-only action.** The modal
   (C11) is the design's conversation view, and a second drawer UI on a blank
   page is not in the design. The repository check keeps a foreign link from
   opening the wrong issue. A 404 with the existing copy replaces the old
   in-page notice, because the layout has no flash.
4. **Build count source, and only on the home page.** Count the `now` rows in
   state `active` from the payload BuildLive already receives. This avoids a
   new call on C8-T04's Index. The earlier draft also renamed DashboardLive's
   Units count to `:build` and claimed the two numbers are equal. They are
   not: the Units count follows the URL filter (scope `none` gives `0`) and
   uses the `UnitsPolicy` rule, which counts working rows with a Command and
   leaves out `:starting` rows. So Commands and `/units` show no Build badge.
   Today the Units badge is visible on Commands; that is the one visible loss,
   and it is listed for the C12-T08 sign-off. If Kevin wants it back, the fix is
   to compute C8-T01's count from DashboardLive's catalog, not to rename the
   Units count.
5. **No Build badge on Analytics, Streamdeck and Build Order.** Those pages
   have no fleet source, and an absent badge is honest. Adding a source there
   would be new scope.
5a. **The pause read is async and coalesced.** `globally_paused?/1` is a 5 s
   `GenServer.call`, and observability updates arrive often. A synchronous call
   per update per tab would stall the board and load the orchestrator.
6. **Hidden routes stay in the registry** so that `/units` and `/build-orders`
   keep their own titles and highlight nothing, instead of falling back to
   Build.
7. **An unknown pause state blocks the toggle.** Inverting an unknown value
   would be a guess about a fleet-wide write.
8. **This PR corrects the docs it falsifies.** AGENTS.md requires that, even
   though C12-T07 owns the full rewrite.
