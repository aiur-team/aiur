# GH-3033 — `aiur listen --ticket`: follow one ticket's events

**Tracker:** aiur-team/aiur#3033 (already exists; the issue is authoritative)
**Complexity:** 2
**Phase hint:** 0 (independent of the program waves)
**Depends on:** none

## Outcome

`aiur listen --ticket N` streams one JSON line per event for ticket N (push,
PR opened, CI, attention, pause, merge). The Executor no longer tails
`<repo>.executor.wakes.ndjson` with jq or falls back to a `gh` sleep loop.

## Context and evidence

Today `aiur executor-listen --topic 'ticket.3028.#'` fails with
`{:error, :binding_not_allowlisted}`. On 2026-10-07 the Executor nearly missed
#3028 pausing for an operator question for hours.

## Scope

- Rename to `aiur listen`; keep `executor-listen` as a deprecated alias for one
  release.
- Accept narrowing patterns inside the reviewed Executor bindings; refuse
  widening patterns and name the allowed bindings.
- `--ticket <id>` is shorthand for `--topic ticket.<id>.#`.
- Output includes `wake_id`, `topic`, `ticket`, `pr_number`; reconnect after a
  daemon restart or exit with a clear message.
- Docs: `cli.md` and the aiur-run wake-monitor section.

## Non-goals

- Listener modes for agents (MP-E7). This member is in the "listener" epic
  because it shares the listener vocabulary.

## Acceptance and verification

A narrowing pattern is accepted; a widening pattern is refused; the alias
works. Each test fails with its change reverted.
