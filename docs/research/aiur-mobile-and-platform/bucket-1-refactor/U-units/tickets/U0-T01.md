> This is the gate that RC-19 and MP-R1 migration-plan §2 call "U0 review
> before code work". Before this ticket existed the gate was text only. Every
> MP-R1..R7 root ticket and every U1..U7 ticket now carries `U0-T01` in

## Identity and outcome

- Bucket 1, prior unit U0 (plan `docs/plans/2026-09-29-001-refactor-production-readiness-plan.md` § U0).
- **User value:** refactor work starts from checked facts at a pinned commit,
  not from a census that is 300+ commits old. Workers do not repeat a repair
  that already merged, and do not chase a finding that no longer exists.
- **Deliverable:** one review record,
  `docs/research/refactor-2026-09-26/synthesis/u0-review-<sha>.md`, plus a
  refreshed disposition overlay `u0-review-<sha>-dispositions.json`. The record
  names the implementation SHA, the release identity, the result of each check
  below, and the explicit sign-off line "U0 review complete at `<sha>`".
- **Non-goals:** no product code; no new findings research; no change to the
  provisional fix/defer decisions except where the code at the implementation
  SHA proves them wrong; no size gate (U0-T03); no owner-ledger rows (U0-T02).

## Chosen design

- Pin one implementation SHA: the `origin/main` commit on the day the review
  runs. Never the local `main` of a research worktree.
- Reuse the existing per-finding records. For each P0/P1 finding, record
  `present | repaired | changed | stale` with one file:line at the pinned SHA.
  For P2/P3, recheck only findings whose cited path changed since `465aca643`
  (use `git diff --stat 465aca643 <sha>` to list changed paths); the others keep
  their disposition with the note "path unchanged".
- Preserve all 1,033 source-ID mappings. A count check proves it.
- Privacy: run the same contextual review on every new evidence file this
  ticket and the U-unit tickets publish (aggregate counts and source IDs only).
- Release identity: record the latest published release tag, its commit,
  and the pinned SHA (package names per `packaging/npm/`).

## Implementation steps

1. Pick the SHA; record it and the release identity.
2. List changed paths since `465aca643`; join them to finding citations.
3. Recheck P0/P1 (97) and changed-path P2/P3. Write the overlay JSON
   (`{id, status, anchor, note}`), one row per canonical finding.
4. Count check: 986 canonical rows, 1,033 source IDs mapped, zero orphans.
5. Read U0-T02's output; confirm every oversized path has an owner and next action.
6. Privacy review of new public files; record result.
7. Write the record with the sign-off line. Update `synthesis/STATUS.md`
   with one line pointing to it.

## Non-happy paths

- **A finding is repaired at the SHA:** mark `repaired` with the commit; the U
  ticket that owns it must then shrink to a guard test or close. Name that
  ticket in the record.
- **A finding moved files:** record the new anchor; do not re-open its
  disposition.
- **A privacy issue is found:** remove the text before commit; record only that
  a redaction happened (no content).
- **main moves during the review:** keep the pinned SHA. Later tickets recheck
  their own paths at their start (MP-R1-C11-T02 runbook).
