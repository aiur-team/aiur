# U5-T03 - Monotonic resource writes

## Identity and outcome

- Bucket 1, prior unit U5 (KTD11: "a failed reader cannot … roll back a newer
  resource observation").
- **User value:** a slow GitHub read that finishes after a webhook update can
  no longer replace the newer state, so tickets do not flip back to stale labels
  or blocked-by edges.
- **Deliverable:** one store primitive `deposit_unless_older/3` built on the
  existing atomic `update_resource/3`; every non-webhook writer uses it;
  `put_resource/3` loses its unconditional path.
- **Non-goals:** no change to the webhook deposit (already checks inside the
  swap); no checkpoint frequency change (crash-loss limit stays documented).

## Dependencies and blockers

- U0-T01. MP-E1-C1-T01 edits `github/issues.ex` first (RC-19).
- U5-T04 depends on this (same file).

## Verified starting point (`58854d4c8`)

- `github/resource_store.ex:712-719` `put_resource/3` = unconditional
  `update_resource`, returns `:ok` even for a nil key.
- Only the webhook path checks inside the swap: `events/github_webhook/deposit.ex:880, 950`.
- `github/issues.ex:297-323` checks then writes in two steps (the store forbids that).
- `put_resource` has four more callers that deposit **undated** poll results:
  `github_comments_poller.ex:280, 286`, `command_scan.ex:206, 212` (ten callers in all).
- Webhook comparator `regression?/2` in `deposit.ex`: refuses strictly older,
  writes on equal versions and when the marker is missing; it compares a
  transition `updated_at` marker, not the entry version.
- No check at all: `github/resource_fetch.ex:206-227` (reports `outcome: :fetched`
  regardless), `github/write_through.ex:176, 233`,
  `build_order/github_graph/reconciliation.ex:131, 156`,
  `github/dependencies_api.ex:160`.
- `MembershipAccess` (`membership_access.ex`, 25 lines) already serializes
  `:sub_issue` through the owner (keep as is).

## Chosen design

- `deposit_unless_older(key, new_resource, opts)` runs inside
  `update_resource/3`'s atomic function with the webhook's rule, moved into the
  store and shared: strictly older → `{:ok, :superseded}`; equal or missing
  marker → write.
- `nil` key → `{:error, :invalid_key}`.
- Migrate the six dated writers above. The four undated pollers keep
  `put_resource/3` (unconditional) - they have no marker to compare. `ResourceFetch` maps `:superseded` to its
  existing `outcome: :superseded` (atom already exists, :74).
- `put_resource/3` stays for undated writers; add the nil-key guard to it too.

## Implementation steps

1. Store primitive + comparator reuse; nil-key error.
2. Migrate writers; `issues.ex` two-step becomes one call.
3. Tests.

## Non-happy paths

- **Resources without a marker:** written (same as the webhook rule); poll
  writers stay unconditional so polled comment bodies keep updating.
- **Store owner down / timeout:** existing call error is returned; a timeout is
  an unknown outcome (may still apply later) - callers must not assume either.
- **Equal markers:** write (same as `regression?/2`).

## Compatibility and rollout

No config. Rollback: revert.
