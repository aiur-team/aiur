# U2-T03 - Rate-limit fallback safety and starvation

## Identity and outcome

- Bucket 1, prior unit U2.
- **User value:** (1) tearing down a parked fallback entry no longer crashes the
  orchestrator path with a KeyError; (2) one ticket whose label write keeps
  failing no longer blocks fallback for every other ticket.
- **Deliverable:** safety entries carry `:started_at` and
  `:completion_totals_recorded`; `token_accounting.ex` reads defensively;
  a failed transition no longer counts against the per-tick cap; failing
  tickets get a per-ticket backoff and one alert.
- **Non-goals:** no change to the fallback policy, the cap value, or models.

## Dependencies and blockers

- U0-T01. U2-T01 (the label writes at `:441`, `:446` move to `TicketTransition` first).

## Verified starting point (`58854d4c8`)

- orch-b-02: `orchestrator/rate_limit_fallback.ex:564-582`
  `redispatch_safety_entry/2` builds the entry with
  `Map.take([:identifier, :worker_host, :retry_attempt, :prior_work])` - no
  `:started_at`, no `:completion_totals_recorded`. `retain_redispatch_safety`
  (:589-597) parks it. `token_accounting.ex:217` reads `running_entry.started_at`
  (strict) → KeyError. Callers that reach it: `agent_teardown.ex:48`, `:119`,
  `retry_engine.ex:66`. New path from #3038: `handoff/6` (:400-428) builds the
  same entry at :408.
- orch-b-08: `reconcile/2` (:45-65) sorts by issue_id and stops at
  `@max_transitions_per_tick 1` (:37; halt :243-250). `engage_after_preflight`
  (:452-489) and `revert_after_preflight` (:491-530) return `{state, true}` on
  failure (:475, :487, :516, :528), so a failure uses the tick's only slot. The
  failure is only `Logger.error` (:532-537).
- Tests: `token_accounting_test.exs:117` always sets `started_at`;
  `rate_limit_fallback_test.exs:455, :489` cover single-ticket failure/rollback.

## Chosen design

- Entry: add `started_at: original[:started_at] || DateTime.utc_now()` and
  `completion_totals_recorded: false` in `redispatch_safety_entry/2` (both
  builders use it). `token_accounting.ex:217`: `Map.get(entry, :started_at)`
  with the existing nil handling of that function (check; if none, skip the
  duration total for nil).
- Starvation: failure branches return `{state, false}` and set
  `fallback_backoff[issue_id] = {attempts, next_at_ms}` - a new field on
  `Orchestrator.State` (RateLimitFallback works on that struct; there is no
  separate fallback state) (doubling from one tick,
  capped at 10 minutes). `reconcile/2` skips ids whose `next_at_ms` is in the
  future. After the 3rd consecutive failure, one `Aiur.Alerts` alert
  `rate_limit_fallback_write_failed` (identifier, reason). Success clears it.

## Implementation steps

1. Entry fields; defensive read.
2. Failure no longer consumes the cap; backoff map in fallback state; alert.
3. Tests.

## Non-happy paths

- **Backoff state across restart:** in memory; restart retries at once (safe:
  the label is re-read first, KTD6).
- **Ticket leaves fallback while backed off:** clear its key when removed.
- **Unknown outcome from `TicketTransition`:** treat as failure for backoff
  (never as applied).

## Compatibility and rollout

No config. One alert kind. Rollback: revert.
