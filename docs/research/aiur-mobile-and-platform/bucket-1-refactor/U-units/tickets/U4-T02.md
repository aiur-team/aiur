# U4-T02 - Condition-driven continuation (measure first)

## Identity and outcome

- Bucket 1, prior unit U4 (R4, KTD8).
- **User value:** a blocked agent stops spending turns (and quota) on
  continuation prompts that cannot make progress, and resumes when the thing it
  waits for changes - without fewer accepted tickets.
- **Deliverable, in two steps:**
  1. A measurement (no code): count no-op continuation turns per ticket on the
     live fleet since #2807 (the no-op bound), with baseline and units.
  2. Only if step 1 shows ≥ 5% of turns are no-op continuations (see Decision):
     after the **first** no-op turn, park the worker in the existing
     wait-for-operator-message state with a wake on that ticket's events,
     instead of continuing up to `max_consecutive_noop_turns` (3).
- **Non-goals:** no new config key; no change to the active-label rule; no
  claimed quota saving without the step-1 number (AGENTS.md "A claimed saving
  must be measured").

## Dependencies and blockers

- U0-T01. U2-T01 (the continuation check reads lifecycle state). U3-T01 (the
  wake relies on ordered per-ticket event delivery).
- **Decision (without owner):** threshold 5% of total turns. Below it, close
  step 2 as "not worth the change"; the #2807 bound stays. Record the number.

## Verified starting point (`58854d4c8`)

- `agent_runner/turn_loop.ex`: `finalize_turn_completion` (:340-372) →
  `continue_with_issue?` (:568-595): continue if the state label is active and
  the ticket is not `agent:paused`. Then `continue_unless_noop_bound`
  (:378-410, #2807) counts consecutive no-op turns, stops at
  `max_consecutive_noop_turns` (default 3, `config/schema/agent.ex:191`) and
  backs off (`apply_noop_backoff`, :438). Resume path :507-545.
- So a blocked turn gets up to 3 continuation turns; nothing waits for the
  blocking condition to change.
- Wait primitive: `queue_drain.ex` `wait_for_operator_message` (:130) - already
  a receive loop the worker can sit in.
- Tests: `turn_loop_noop_bound_test.exs`, `turn_progress_test.exs`.
- Evidence: frozen census 12,768 short continuation turns ≈ 20 turn-hours,
  concentrated in few threads (pre-#2807; "revised" verdicts).

## Chosen design

- Step 1: read `logs/agent.ndjson` across workspaces for the last 7 days; per
  ticket count turns, no-op turns (as `turn_progress` defines them), and
  accepted outcomes. Output a table with date range and population.
- Step 2 (conditional): in `continue_unless_noop_bound`, when the no-op count
  reaches 1, call the existing wait path with a wake filter
  `ticket.<id>.*` (comment, label, CI, decision answered - the topics the
  orchestrator already subscribes to in `orchestrator/lifecycle.ex`). Any event
  for the ticket, or an operator message, ends the wait and starts a normal turn.
  Keep `max_consecutive_noop_turns` as the outer safety bound.

## Implementation steps

1. Measurement script run (one-off, results in the PR or a synthesis note).
2. If over threshold: implement the wait; tests; foreground check.
3. Re-measure 7 days after deploy; record before/after turns and accepted tickets.

## Non-happy paths

- **No event ever arrives:** the wait has the existing idle/stall handling;
  the orchestrator's stall detection still sees the worker. Add no new timer.
- **Event arrives during the no-op turn:** checked before entering the wait
  (re-read the mailbox) to avoid a lost wake.
- **Ticket becomes non-active while waiting:** the next event/turn exits as today.

## Compatibility and rollout

No config. If step 2 ships, rollback is revert.
