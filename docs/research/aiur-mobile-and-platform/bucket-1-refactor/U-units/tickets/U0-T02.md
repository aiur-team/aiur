# U0-T02 - Refresh the oversized-path owner ledger

## Identity and outcome

- Bucket 1, prior unit U0. Feeds U8 (another agent's tickets) and RC-23.
- **User value:** every file over 500 lines has one reviewed write owner and a
  next action before parallel workers touch it, so two workers do not split the
  same file and no file is orphaned.
- **Deliverable:** `docs/research/refactor-2026-09-26/synthesis/u0-owner-ledger-<sha>.csv`
  (columns of `u8-release-007/assignments.csv` plus `current_lines`,
  `delta_since_release`, `callers_checked`, `behavior_test`, `next_action`) and a
  short `.md` summary with the counts.
- **Non-goals:** no file splits (U8); no new package taxonomy (keep the 37
  owners); no gate code (U0-T03).

## Dependencies and blockers

- No predecessors. Runs in parallel with U0-T03.
- Shared input with U8 tickets: U8 reads this ledger. If the U8 agent has
  already refreshed the ledger at a later SHA, this ticket only adds the
  caller/behavior-test review columns.

## Chosen design

- Reuse `build.py`: point it at the pinned SHA and add the new columns. Do not
  write a second generator.
- Assign each new path to one of the existing 37 owners by directory, the same
  rule `build.py` uses. Where the rule gives two owners, pick the owner of the
  file's main module and record the other as "consulted".
- `callers_checked`: for code files, the `rg` count of external references to
  the file's modules. `behavior_test`: the test file that would catch a broken
  split. Leave blank with a reason for generated or vendored text.
- Lockfiles and immutable prototypes stay in scope (KTD1, no permanent
  exemption). Their `next_action` is `regenerate` or `remove`, with the
  reproduction command.

## Implementation steps

1. Run the census at the pinned SHA with the counting rule of U0-T03 (LF bytes
   + 1 for a nonempty unterminated last line; NUL or invalid UTF-8 = binary;
   symlinks not followed).
2. Join with `assignments.csv`; mark new, retired, grown, shrunk.
3. Fill owner, callers, behavior test, next action for the 16 new paths and for
   any old path whose owner no longer fits. Record the four pre-refactor
   deletions (#2840/#2841 GitHub cache paths) and the two earlier new tests
   separately, as the plan's U0 approach requires.
4. Write the CSV and summary; link it from `u8-release-007/proposal.md`.

## Non-happy paths

- **Path renamed since release:** follow `git log --follow`; keep the old
  owner and record the rename.
- **A path is binary now:** record it; U0-T03 treats unapproved text-to-binary
  as a failure, so the next action is "approve reclassification" or "restore text".
- **Owner disagreement with U8 tickets:** the U8 ticket wins for paths it
  already claimed; record the conflict in the summary.
