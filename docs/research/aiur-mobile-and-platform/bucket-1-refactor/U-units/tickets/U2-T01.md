# U2-T01 - One ticket-transition owner

> Answers **RQ-U2-TRANSITION** (`synthesis/open-questions.md:9`: "Name the
> owner, durable replay/idempotency rule and failure behavior before U2") and
> the `U2-lifecycle-owner` pseudo-predecessor used by MP-R1-C7-T07/T08 and
> MP-R1-C9-T06/T09. Those tickets now block on this ticket ID.

## Identity and outcome

- Bucket 1, prior unit U2 ("Give lifecycle one owner"), R3.
- **User value:** when a ticket's label changes, there is one place that did it,
  one record of who asked (writer), and one failure rule. Stuck-ticket debugging
  stops being a search across 20 modules.
- **Deliverable:** new module `Aiur.Orchestrator.TicketTransition`
  (`src/lib/aiur/orchestrator/ticket_transition.ex`, target < 150 lines) with
  `write_state/3` and `write_marker/4`; all call sites below migrated; an
  xref-based guard test that fails when another module writes lifecycle labels.
- **Non-goals:** no change to *when* any module decides to transition (each
  caller keeps its decision); no effect-return refactor (MP-R1-C9-T09 does that
  on top of this owner); no new process; no change to `github/issue_state.ex`.

## Chosen design

**Owner:** `Aiur.Orchestrator.TicketTransition`. It is a plain module (no
process); it runs in the caller's process, exactly where the call runs today.

```text
write_state(issue_id, to_state, opts)    # opts: writer: atom (required),
                                         #       expected_state: (passthrough), identifier:
write_marker(issue_id, :add | :remove, label, opts)
  -> :ok | {:error, reason}
```

- Both call `Aiur.Tracker` (never the GitHub module), then record
  `%{issue_id, to, expected, writer, outcome}` as one structured `Logger.info`
  line (`ticket_transition …`, written to the daemon log on disk) and
  `:telemetry.execute([:aiur, :ticket_transition], %{}, meta)` for later
  consumers. Per-ticket IssueLog rows are deferred: they need a
  `TicketObservation` the callers do not have (ponytail: the daemon log is the
  durable record; IssueLog can subscribe to the telemetry event later).
- **Why a new module and not `writer:` on `Aiur.Tracker`:** `Aiur.Tracker` is
  the adapter facade that MP-R1-C7-T01 splits into IssueTracker/CodeHost ports;
  the transition owner belongs to orchestration (MP-R1-C9-T09 adds
  `apply_effects/2` to it). Putting the owner in the facade would mix the two.
- **Replay / idempotency rule:** the tracker label is the authority. The owner
  adds no dedupe: a repeated write has the adapter's existing effect (check and
  record it in the PR; `swap_labels/4` reads before it writes). The owner never retries; a caller that gets `{:error, _}` must re-read labels
  on its next tick before deciding again (KTD6, reconcile before retry).
- **Failure rule:** `{:error, reason}` is returned unchanged and recorded with
  `outcome: {:error, reason}`. A deadline or transport error (the request may
  have applied) is recorded as `outcome: :unknown` - never as applied. No new alert here (U2-T03 adds the
  per-ticket backoff and alert for the fallback path).
- `writer` is required so the record names who asked. The atom set is the
  module names of today's callers plus `:build_queue`, `:cli_todo`, `:agent_tool`.
- `test_reset.ex` stays as is (dev-only, `mix aiur.test.reset`); it is
  allowlisted in the guard with that reason.

## Non-happy paths

- **Memory/Linear trackers:** they go through the same facade; `expected_state`
  unsupported returns `{:error, :expected_state_unsupported}` as today.
- **CLI process** (`--todo` runs where the CLI command runs): the log line goes
  to that process's logger. Acceptable: the label is truth, the line is evidence.
- **Agent-driven writes** (`ticket_state.ex`, `tool_executor.ex`): keep their
  existing validation of allowed target states before calling the owner.
- **Concurrent writers:** unchanged - the same calls in the same processes.

## Compatibility and rollout

No config, no migration, no user change. Rollback: revert.
