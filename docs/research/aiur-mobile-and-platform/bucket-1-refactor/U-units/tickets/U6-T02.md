# U6-T02 - Projection health and withheld side-effect replay

## Identity and outcome

- Bucket 1, prior unit U6 (KTD10).
- **User value:** if `decisions.json` cannot be rewritten, decisions already in
  the journal still count, the Executor sees "projection stale since …", and
  the wake/notification that was held back is sent exactly once after repair.
- **Deliverable:** on projection failure the store stays writable for the
  journal with `health: {:projection_stale, since}`; all three persist paths
  apply one notification rule; withheld notifications are replayed by event ID
  after rebuild or restart.
- **Non-goals:** no change to the journal (U6-T01); no new store file beyond a
  small withheld-ID list if the journal cannot derive it (see design).

## Dependencies and blockers

- U6-T01 (outcome classifier).
- Consumers: Executor wake (U3-T03) only reads the notifications.

## Verified starting point (`58854d4c8`)

- `decision_store.ex:754-764` `write_projection/1` (`JsonStore.write!` + chmod).
- `repair_projection/1` (:733-751) emits `decision_store.repair_failed`, sets
  `writable?: false`, `health: {:repair, reason}` until restart.
- Request path `persist_and_notify` (:2426-2462) still calls `notify/3`
  unconditionally (:2458) and returns `:accepted`; enrichment (:2153) and
  lifecycle (:2509-2527) withhold when not writable; **no replay of withheld
  notifications by event ID**.
- Existing corrupt-record and torn-tail tests are characterization only.

## Chosen design

- Separate journal health from projection health: `writable?` stays true while
  the journal is healthy; `projection: {:stale, since, reason}` when the JSON
  write fails. Reads that need the projection return it with `stale: true`.
- One notification rule for all three paths: notify only when the event's
  side effect does not depend on the fresh projection; otherwise record the
  event ID as withheld. Withheld IDs are derived from the journal on restart:
  events after the projection's `last_event_id` that carry a notify flag.
  The projection has no last-applied marker today (review grep found none), so
  add `last_event_id` (one field). Check it against the replay rules in
  `synthesis/decision-restart-contract.json` before coding.
- After a successful rebuild, notify each withheld ID once in journal order.

## Implementation steps

1. Health split; stale flag on reads; alert once on entering stale.
2. One notify rule across the three paths.
3. Withheld derivation and replay after rebuild/restart.
4. Tests.

## Non-happy paths

- **Rebuild keeps failing:** stay stale; retry on the existing repair timer;
  alert once, not per retry.
- **Crash between notify and projection write:** on restart the event is after
  `last_event_id` → notified again. Consumers must be idempotent by event ID -
  check the wake inbox dedupes (it keys by wake id); record result.
- **Corrupt complete record:** store read-only until repair (unchanged).

## Compatibility and rollout

Projection may gain `last_event_id` (additive). Rollback: revert; old code
ignores the field.
