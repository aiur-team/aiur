# U1-T03 - Packaged Ctrl+C with a queued TUI message

## Identity and outcome

- Bucket 1, prior unit U1. The third open witness in
  `synthesis/merged-main-e196-u1-focused-witnesses.md`.
- **User value:** pressing Ctrl+C in an agent chat pane interrupts the turn
  without losing a message the Executor queued, and the message is delivered
  exactly once afterwards.
- **Deliverable:** a recorded foreground run (AGENTS.md "Manual testing")
  with `capture-pane` output before and after; a repair PR only if the run
  shows loss or duplicate delivery.
- **Non-goals:** no new automated end-to-end harness; no change to the binding.

## Dependencies and blockers

- Blocked by U0-T01. Must run from the Executor repo root, never from an agent
  workspace (`--test` guard in AGENTS.md).

## Verified starting point (`58854d4c8`)

- Binding: `share/aiur.tmux.conf:75-77` → `libexec/aiur-pane-ctrlc`; option set
  at `aiur-engine.sh:1086-1092`. Helper POSTs `/api/v1/pane/interrupt`
  (`aiur-pane-ctrlc:84-91`); `send_interrupt` → Esc (:115-120);
  `interrupted|pause_requested|paused` keep the pane (:125-130); other replies
  hide it (:135).
- Server: `observability_api_controller.ex:95` → `AgentChat.pane_interrupt`
  (`agent_chat.ex:88`) → `Interrupts.pane_interrupt_reply` (`interrupts.ex:92`),
  decisions `pane_interrupt_action` (:176), `pane_interrupt_action_no_pane` (:197).
  Launcher SIGINT trap: `aiur-engine.sh:2155`.
- Coverage: `scripts/verify-ctrlc-binding.sh` checks binding and pane survival
  only, and runs only in `release-npm.yml:314`. `interrupts_test.exs` and
  `orchestrator_interrupt_test.exs` unit-test the mapping. **Nothing checks
  that queued text is delivered exactly once after the interrupt.**

## Chosen design

Drive the packaged path (the npm-installed `aiur`, or `aiurdev` with the
release built from the same SHA) with the wrapper-tmux recipe:

1. Launch foreground `--test`; wait for a running agent row; Enter → `0.1`.
2. While the agent is mid-turn, type message M1 and Enter → expect `QUEUED`.
3. Ctrl+C in `0.1` (`send-keys C-c`) → expect the interrupt reply and the pane
   to stay.
4. Observe: M1 delivered once after the interrupt (one user row, one response);
   capture `0.1` with `-S -200`.
5. Repeat with Ctrl+C while no turn runs (no-pane / idle branch).

## Implementation steps

1. Build and confirm the release stamp matches the SHA.
2. Run the recipe; save both captures (redact paths/hostnames).
3. Write the result into the U1 evidence note.
4. If M1 is lost or duplicated: file the defect with the capture, and fix it
   in this ticket in `agent_chat.ex` / `interrupts.ex` with a unit test that
   fails on the bad ordering.

## Non-happy paths

- **Agent not yet running:** Enter is a no-op while rows show warm-up text;
  wait (AGENTS.md precondition).
- **QUEUED shown:** success, not a hang.
- **Helper missing in the packaged layout:** that is a packaging defect; record it.

## Compatibility and rollout

Evidence only unless a defect is found.

## Verification

Observable success: in the capture, M1 appears once as delivered and the agent
answers it once; the pane survives Ctrl+C. Failure: M1 missing, shown twice, or
the pane closes with M1 still queued.
