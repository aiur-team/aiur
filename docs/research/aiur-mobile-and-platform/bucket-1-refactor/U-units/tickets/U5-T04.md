# U5-T04 - Typed outcomes in Transport and Client

> Answers the `U5-typed-outcomes` pseudo-predecessor of MP-R1-C7-T04, C7-T06,
> C7-T08 and the "U5 Build Order membership" one of MP-R1-C8-T08 (X-60).

## Identity and outcome

- Bucket 1, prior unit U5 (KTD11 first seam, in-process).
- **User value:** callers can tell "GitHub said this, completely" from "we
  held the call for budget" from "we do not know what happened", so no path
  turns a truncation, hold or dead child into success.
- **Deliverable:** documented outcome contract on the existing entry points:
  `{:ok, value}` (complete), `{:error, {:aiur, :locally_held, hold}}` (held -
  existing shape), `{:error, {:aiur, :unknown, reason}}` (new: deadline,
  owner exit, timeout after send). One function `Aiur.GitHub.Errors.outcome/1`
  classifies any result into `:complete | :held | :unknown | :failed`.
  Membership-contract witnesses at the pinned SHA. Review-thread replies
  reconcile an `:unknown` post before retrying (github-b-03, folded in during review:
  same owner, same doc page).
- **Owns the Verification Contract gate "First seam startup"** for U5: crash a
  cache/quota/resource child mid-call and compare outcomes and startup order.
- **Non-goals:** no new service, facade or package (KTD11); no caller migration
  beyond the entry points that today return success-shaped values on unknown.

## Verified starting point (`58854d4c8`)

- No complete/held/unknown type. `Transport` returns
  `{:error, {:aiur, :locally_held, hold}}` (`transport.ex:176-177, 204-205`) or
  `:fetch_deadline_exceeded`; `Quota` `:ok | {:hold, hold}` (`quota.ex:136, 143`);
  `ResourceFetch.outcome` `:store | :revalidated | :superseded | :fetched` (:74).
- `membership_access.ex` (25 lines) routes `:sub_issue` through the owner with a
  15 s call and turns an exit into `{:membership_unavailable, _}`; store side
  `membership_snapshot/2` (`resource_store.ex:1113`), `replace_membership/4` (:1121);
  test `membership_access_test.exs`. Build Order reconciliation refuses
  incomplete nested membership and retries on a timer (plan § U5, `ed742aec`).
- Error helpers: `github/errors.ex`.
- github-b-03: `github/review_threads/reply.ex:80` retries whenever
  `retryable_github_error?` is true, **deadlines included**; no test covers an
  applied mutation whose response was lost (`reply_test.exs`).

## Chosen design

- Keep the held shape. Map `:fetch_deadline_exceeded` and call-exit/timeouts
  at the Transport/Client boundary to `{:aiur, :unknown, reason}` (one place).
- `Errors.outcome/1` is the classifier every caller can use; no wrapper types.
- `ResourceFetch` never reports `:fetched` for an unknown result (map to error).
- Reply: on an `:unknown` outcome only, read the thread's comments (existing
  reader) and match `author == self && body == sent_body && created_at >=
  attempt_started_at`; found → `:ok`; not found → retry once as today. A
  failed reconcile read returns the unknown error (never post blindly).
  Definite failures keep today's retry.
- `MembershipAccess`: an owner timeout returns
  `{:membership_unavailable, {:aiur, :unknown, :timeout}}` (the call may still
  run later - document in moduledoc).

## Implementation steps

## Non-happy paths

- **Mutation that timed out:** `:unknown`; reconcile before retry (replies: the branch above).
- **Child restarts mid-call:** exit → `:unknown`; Application restarts children
  in order (unchanged `rest_for_one`).

## Compatibility and rollout

Callers matching `:fetch_deadline_exceeded` must change in the same PR (grep).
Rollback: revert.
