# U9-T03 - npm launcher tests in CI

## Identity and outcome

- Bucket 1, prior unit U9 (the plan's "package layout checks" gate).
- **User value:** a change that breaks the npm-installed `aiur` launcher or
  its postinstall fails CI before release, not after.
- **Deliverable:** one CI step that runs `bun test` in `packaging/npm/aiur-cli`.
- **Non-goals:** no new tests; no change to the release workflow.

## Dependencies and blockers

- None. It is CI hygiene, not refactor code, so the U0 review gate does not
  apply. U9-T02's acceptance relies on it being green.

## Verified starting point (`58854d4c8`)

- `packaging/npm/aiur-cli`: `bun test` runs `test/launcher.test.mjs` and
  `test/postinstall.test.mjs`.
- No step in `ci.yml` or `release-npm.yml` runs it (confirm with
  `rg -n 'bun test|setup-bun' .github`).
- The packaged layout check runs at `ci.yml:770` (`check-packaged-layout-worker.mjs
  --release`) in the `layout release smoke` job.

## Chosen design

Add the step to the `layout release smoke` job (it already prepares the
packaged layout). If that job has no Bun, add `oven-sh/setup-bun` pinned by
commit SHA like the repo's other actions (check `workflow security` rules for
action pinning).

## Implementation steps

1. Add the setup (if needed) and `bun test` step with `working-directory: packaging/npm/aiur-cli`.
2. Run the job on a PR; confirm both test files execute.

## Non-happy paths

- **Tests are already broken on main:** fix them in this ticket or mark the
  step non-required with a linked issue - never merge a red required job.
- **Action pinning check fails:** pin by SHA as the security job requires.

## Compatibility and rollout

CI only. The job is already required (`layout release smoke` in the ruleset),
so a failure blocks merges. Rollback: revert the step.

## Verification

- The job log shows both test files run and pass.
- Break a launcher assertion locally in a throwaway branch: the job fails.

## Completion and handoff

- [ ] Step merged; job green on main.
- Dependents: U9-T02.
