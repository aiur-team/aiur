- Bucket 1, prior unit U9 (R12, D2, D5, D6).

  TUI, for both operating modes, and the program reports what it really removed.

## Chosen design

- Acceptance run (Executor repo root, not an agent workspace):
  1. `aiurdev build`; read the stamp; it must equal `origin/main` and `dirty: false`.
  2. Foreground `aiurdev --test3` in wrapper tmux; wait for ≥ 2 running agents.
  3. Open a Codex and a Claude chat pane; type an Executor message in each;
     capture `0.1` showing delivery and response.
  4. Pause/resume one agent with a queued message (U4-T01 path); Ctrl+C in a
     pane (U1-T03 path); capture.
  5. `aiur status` / `aiur agents` show waiting reasons with owner and age
     (U2-T04, U6-T04); dashboard shows the same values (browser screenshot).
  The run is driven through the TUI by the Executor; record whether a human or
  an Executor agent drove it (both modes use the same CLI/TUI surface; one run
  is enough).
- Census: `scripts/check-file-size.py --census <U0-T01 sha> <main>`; paste into the record.

## Implementation steps

1. Run the acceptance; write `synthesis/u9-acceptance-<sha>.md` with captures
   (redacted) and the census table.
2. Remove abandoned experimental code found during the run (D8) or file it.

## Non-happy paths

- **A step fails:** file the defect against the owning U ticket's area, fix,
  and rerun the full sequence on the new main.
- **Stamp mismatch:** rebuild; never accept a run on a stale release
  (memory: merged code is inert until rebuilt).
