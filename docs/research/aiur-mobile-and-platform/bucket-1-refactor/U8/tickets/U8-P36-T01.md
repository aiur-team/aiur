## Chosen design

Keep the LiveView callbacks in `AiurWeb.DashboardLive`. Each callback clause becomes
a one-line call into a panel module that takes and returns the socket. Panel modules
use `Phoenix.Component.assign/3` and do not `use Phoenix.LiveView`.

| PROPOSED path (module) | Takes | Est. lines |
| --- | --- | ---: |
| `live/dashboard_live.ex` (`AiurWeb.DashboardLive`) | `mount`, `handle_params`, `handle_info` and `handle_event` dispatch, `handle_async`, aliases | 450 |
| `live/dashboard_live/page.ex` (`DashboardLive.Page`) | the `render/1` HEEx body as a function component; `render/1` calls `Page.page(assigns)` | 220 |
| `live/dashboard_live/controls.ex` (`DashboardLive.Controls`) | global pause, capacity, unit controls, pause/resume agent | 330 |
| `live/dashboard_live/units_panel.ex` (`DashboardLive.UnitsPanel`) | units view and URL, tickets panel, add-agent modal | 260 |
| `live/dashboard_live/summaries.ex` (`DashboardLive.Summaries`) | run summary and current-run outcomes stash/flush/apply | 200 |
| `live/dashboard_live/usage.ex` (`DashboardLive.Usage`) | usage summary, drill-down, provider meters | 400 |
| `live/dashboard_live/ticket_context.ex` (`DashboardLive.TicketContext`) | ticket context subscriptions and refresh | 260 |
| `live/dashboard_live/conversation.ex` (`DashboardLive.Conversation`) | drawer, agent log, chat send | 260 |
| `live/dashboard_live/commands.ex` (`DashboardLive.Commands`) | payload reload, selected decision, history, decision page | 420 |

- Rationale: the private groups above are already cohesive; the split moves them
  as they are. The callback module stays the single place that lists every event and
  message, so a reader still sees the full surface.
- Invariant: each `handle_event` name and `handle_info` pattern is unchanged and
  routes to the same body. The rendered HTML is identical for the same assigns.
- No `.heex` template file exists under `src/lib/aiur_web/` today, so the template
  moves into a function component (`~H` in `DashboardLive.Page`), the house pattern.

## Non-happy paths

- **Socket ownership:** panel modules must not call `push_event`, `start_async` or
  subscribe on their own unless the moved body did; moved bodies keep their exact
  calls, including `Phoenix.PubSub` subscribe and unsubscribe pairs
  (`subscribe_ticket_context` / `unsubscribe_ticket_context`).
- **Read-only mode:** `handle_writable_event :2682` and `dashboard_writable? :1153`
  gate every write. Keep the gate in the callback path, before the panel call, so no
  panel can be reached for a write in read-only mode (tests `:673`, `:2789`, `:4818`,
  `:5219`).
- **Unknown and stale states:** unavailable usage/provider/outcome snapshots
  (`unavailable_usage_snapshot :1678`, `unavailable_detail :2083`) move unchanged.
- **Timers:** flush and tick timers (`schedule_*`) stay keyed to the same messages;
  coalescing tests (`:1227`, `assert_bounded_reload_burst`) guard them.
- **Async tests:** the base file is not `async: true`; keep each new test file the
  same.
