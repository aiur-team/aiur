## Chosen design

| PROPOSED module | Takes | Est. lines |
| --- | --- | ---: |
| `Aiur.Linear.Client` (unchanged path) | public API, pagination, request/response, test hooks | 370 |
| `Aiur.Linear.Queries` (`linear/queries.ex`) | the three GraphQL documents as functions `candidates/0`, `by_ids/0`, `viewer/0` | 100 |
| `Aiur.Linear.IssueNormalizer` (`linear/issue_normalizer.ex`) | `:461-599` normalization and assignee-filter helpers | 150 |

Rationale: the query text and the payload-to-`%Aiur.Issue{}` mapping are data and pure
functions with no process or HTTP state. The client keeps the transport and the
pagination. Test hooks stay on `Client` and delegate, so tests do not change.

## Non-happy paths

- **Auth and errors:** `graphql/3` reads the token through `Aiur.Config`; the error
  summarizer truncates the body (`truncate_error_body`, `:388`) so tokens or large
  payloads do not reach logs. These stay in `Client` unchanged.
- **Assignee routing:** `resolve_viewer_assignee_filter` (`:526`) calls the viewer
  query. It needs `graphql/3`; pass the client function as an argument or keep that
  one function in `Client`. Do not create a cycle (`IssueNormalizer` must not call
  `Client`).
- **Coverage:** `Aiur.Linear.Client` is coverage-ignored; `Queries` and
  `IssueNormalizer` are not, and the plan forbids new ignore entries. The moved
  normalization code is exercised by the `*_for_test` tests; run `mix test --cover`
  and confirm the 85% total holds.
