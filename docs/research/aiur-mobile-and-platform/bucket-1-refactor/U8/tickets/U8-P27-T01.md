# U8-P27-T01 — Build the ELK worker from a pinned package and split the layout worker spec

## Identity and outcome

- Bucket 1, unit U8 (file-size debt), package `LAYOUT`, chunk `U8-P27`.
- **User value:** none visible. The Build Order graph layout keeps working offline,
  while the repository stops tracking a 6,312-line third-party minified file and a
  duplicate copy of the authored worker.
- **Deliverable:** `elk-worker.min.js` and the vendored `aiur-layout-worker.js` copy
  become build outputs of the existing `npm run vendor:elk` step; the authored
  worker source is split into parts of at most 500 lines that the same step joins;
  `layout-worker.browser.spec.mjs` is split into files of at most 500 lines.
- **Non-goals:** no ELK upgrade, no change to the worker protocol, size limits,
  content-addressed URLs scheme, CSP, or `StaticAssets` hash verification.

## Chosen design

- Tracked: authored sources, `manifest.json` (the pin), `LICENSE.md`,
  `PROVENANCE.md`, `SOURCE.md`. Generated and gitignored: `elk-worker.min.js`,
  `aiur-layout-worker.js`, `aiur-layout-client.js` under `priv/static/vendor/elk/0.11.1/`.
- `vendor:elk` gains a `--check` mode (or `check:elk` changes) so CI fails when the
  regenerated outputs do not match the tracked `manifest.json` hashes. The manifest
  stays the source of truth (docs/vendor page already says so).
- Authored worker split (joined by `vendor:elk` in a fixed order, no runtime import,
  so CSP and the single worker URL stay):

| PROPOSED path | Takes | Est. lines |
| --- | --- | ---: |
| `src/browser/layout/worker/00-limits-and-messages.js` | 1–56 | 60 |
| `src/browser/layout/worker/10-validate.js` | 57–244 | 190 |
| `src/browser/layout/worker/20-engine.js` | 244–346 | 105 |
| `src/browser/layout/worker/30-elk-graph.js` | 346–507 | 165 |

  The joined output must equal today's worker bytes in the first PR, so its hash and
  URL do not change.
- Spec split: PROPOSED `src/browser/tests/layout-worker/{protocol,validation,engine-loading,geometry}.browser.spec.mjs`;
  `package.json` `test:layout` lists the new files.
- Build integration: the release build (CI job before `mix release`) and
  `scripts/aiurdev build` run `npm ci --ignore-scripts && npm run vendor:elk` in
  `src/browser` when the outputs are missing or older than their sources.

## Implementation steps

1. Read what the Build Order page does when `StaticAssets` layout lookup returns
   `:error`. If it degrades silently, make `aiurdev build` fail loudly when the
   generated outputs are missing.
2. Split the worker into parts; `vendor:elk` joins them; assert byte equality.
3. Gitignore the three outputs; remove them from the index; wire the build steps.
4. Update `docs/vendor/elkjs-0.11.1.md` and `PROVENANCE.md` ("generated at build").
5. Split the spec; update `test:layout`.

## Non-happy paths

- **Offline machine:** with no npm cache the build cannot fetch `elkjs`. The failure
  message must name the command to run; it must not produce a release without the
  engine (release checks already fail on a missing asset).
- **Tampered output:** `StaticAssets.verify_layout_assets` still rejects wrong bytes
  at runtime; generation does not weaken it.
- **Lockfile drift:** `vendor-elk.mjs` already refuses a package that does not match
  the lockfile integrity.
- **Agent workspaces:** a workspace `mix test` does not need the outputs unless a test
  reads them; check `git grep -n "vendor/elk" src/test` at the base and give such
  tests a fixture or the vendor step.
