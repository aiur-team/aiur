- **Process rule:** `Guardian.Provider` and `Guardian.Reaper` contain plain functions
  that run inside the guardian process when the loop calls them. They do not spawn,
  register or `receive`. All `receive` blocks stay in `Guardian`.
- `Provisioner.maybe_install_agent_support/…` and `repair_agent_github_guard/…` stay
  public on `Provisioner` as delegates (callers `workspace.ex`,
  `agent_github_guard.ex`).

## Implementation steps

1. PR 1: Guardian — move provider and reap groups; the loop calls them with the same
   state map and gets the same return shapes.
2. PR 2: Provisioner — move agent support and bootstrap groups; keep delegates.
3. PR 3: split the two test files. `ownership_test.exs` keeps `async: true`;
   lifecycle tests keep `use Aiur.TestSupport`.

## Non-happy paths

- **Reap safety:** "does not reap a root process after its identity changes"
  (`:1078`), "unknown root identity keeps release blocked" (`:625`) and the restored
  malformed provider (`:545`) guard against killing the wrong process. The identity
  comparison moves as one unit with its callers; no default is added.
- **Restore timeout:** `restore/3` keeps its 5 s `receive` and kills the spawned
  guardian on timeout.
- **Persisted state:** `persist_state`/`persist_update` write through `Store`; keep
  the write before any reply, so a crash after reply never loses a lease update.
- **Remote workspaces:** the remote prepare and readiness scripts are shell strings;
  move them byte for byte (tests `:621` in the WIP suite and the lifecycle suite
  exercise them).
