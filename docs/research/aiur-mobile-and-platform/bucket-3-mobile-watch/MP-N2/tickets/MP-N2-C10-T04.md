# MP-N2-C10-T04 — T-B: self-signed certificate with a pinned key

## Identity and outcome

- **Bucket / feature / chunk:** 3 / MP-N2 / MP-N2-C10.
- **User value:** HTTPS for the phone without publishing the machine name to Certificate
  Transparency and without any third-party CA, for operators who refuse T-A.
- **Deliverable (server side only):**
  1. `aiur mobile tls selfsigned [--rotate]`: generates an ECDSA P-256 key and a self-signed
     certificate (validity 825 days) with SANs = `advertise_host` plus every host in
     `gateway.endpoints`; writes them under `~/.config/aiur/machine/tls/` (0700/0600); sets
     `transport.tls.*` in `~/.aiur/machine`.
  2. QR parameter `t=<base64url sha256(SubjectPublicKeyInfo DER)>` (contract §3), signed with the
     rest of the QR. `GET /v1/machine` also returns `tls_spki_sha256` so a re-link can learn a
     rotated pin **only** through a response signed by the pinned `machine_key`.
  3. LiveView long-poll fallback enabled on `/live` **only when T-B is active**, because WKWebView's
     server-trust override does not apply to WebSockets (evidence below).
- **Non-goals:** the client-side pinning and WebView trust delegate (MP-N1-C5, T-B client ticket);
  `/voice` over a pinned origin (no fallback exists for a binary audio WebSocket — documented as a
  T-B limitation: the WebView microphone stays `unavailable` under T-B on iOS until MP-N1-C9-T01
  proves otherwise).

- Evidence (accessed 2026-10-06):
  - Apple DTS on the developer forums: neither UIWebView nor WKWebView lets an app override the
    TLS server trust evaluation of their WebSocket implementation (bug r. 25491679);
    `webView(_:didReceive:completionHandler:)` covers HTTPS loads only —
    <https://developer.apple.com/forums/thread/104376>. The thread is older than iOS 17; current
    behaviour is **UNVERIFIED** and is a required check in MP-N1-C9-T01.
  - Google Play: an `onReceivedSslError` handler that does not validate the certificate is a
    security vulnerability that can lead to removal — <https://support.google.com/faqs/answer/7071387>.
    The Android client must call `proceed()` only after its own pin check (MP-N1-C5 T-B ticket).
  - Phoenix LiveView supports a long-poll fallback when the socket is mounted with `longpoll:`
    and the client is given `longPollFallbackMs` (Phoenix LiveView JS client option; verify the
    exact option name against the 1.1.33 docs at <https://hexdocs.pm/phoenix_live_view/1.1.33/>
    when implementing — **UNVERIFIED name**, required check).

## Chosen design

- **Key and cert generation** with `:public_key.generate_key({:namedCurve, :secp256r1})` and
  `:public_key.pkix_sign/2` over a TBSCertificate built with `:public_key` records; no new
  dependency. Serial: 16 random bytes. `basicConstraints CA:false`, `keyUsage digitalSignature`
  (iPadOS 18.4 reports describe trust failures without `digitalSignature`,
  <https://developer.apple.com/forums/thread/782850>, accessed 2026-10-06), `extKeyUsage serverAuth`.
- **Pin:** SPKI SHA-256 (survives re-issuing a cert with the same key). `--rotate` makes a new key;
  devices learn the new pin from the next signed `/v1/machine` response **while the old cert is still
  served**: rotation writes the new pair as `next.*`, publishes `tls_spki_sha256_next`, and swaps
  after `pairing.pin_rotation_grace_seconds` (default 7 days). A device that missed the window re-scans.
- **Long-poll:** `endpoint.ex` mounts `/live` with `longpoll: [connect_info: [session: @session_options]]`
  only when `Aiur.Machine.Transport.mode() == :self_signed` (compile-time `socket/3` options cannot
  depend on runtime config, so the implementation mounts a second socket path `/live-lp` always
  and the layout's JS selects it via a `data-` attribute when T-B is active). The browser path is
  unchanged.

## Implementation steps

1. `src/lib/aiur/machine/self_signed.ex` (PROPOSED): `generate/1`, `spki_sha256/1`.
2. CLI verb `aiur mobile tls selfsigned [--rotate]` (engine dispatch + `tls_cli.ex`).
3. QR builder: add `t=` when mode is self-signed. `/v1/machine`: add `tls_spki_sha256`
   (and `_next` during rotation).
4. `endpoint.ex`: the `/live-lp` long-poll socket; layout attribute; JS selects the socket path.
5. Status: `transport.mode: "self_signed"` plus pin and rotation state.

About 300 production lines.

## Non-happy paths

| Case | Behaviour |
|---|---|
| A phone sees a different SPKI than its pin | Hard error `tls_pin_mismatch` (client); never a silent re-pin. |
| Rotation window missed | The device fails with `tls_pin_mismatch`; the app offers "scan the QR again" (relink, contract §4.3). |
| `/voice` from a WebView under T-B | Unavailable on iOS (`reason: tls_websocket_untrusted`) unless the prototype disproves the DTS statement. Native mic paths (MP-E5 device voice path) are unaffected because the native core pins its own `URLSession`. |
| Operator also has a CA cert | T-A wins: `TlsHealth` reports mode `public`, `t=` is omitted. |

## Compatibility and rollout

Gated on the owner choice; the long-poll socket exists only on T-B installs. Rollback: delete the
generated files and settings; devices must re-pair with a T-A QR.
