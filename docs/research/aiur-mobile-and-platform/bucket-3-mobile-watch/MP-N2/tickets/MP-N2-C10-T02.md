# MP-N2-C10-T02 — Gateway transport and endpoint advertisement

## Identity and outcome

- **Bucket / feature / chunk:** 3 / MP-N2 / MP-N2-C10 (RQ-TRANSPORT, RC-15).
- **User value:** the pairing QR and the instance registry only ever advertise endpoints a phone
  can actually use, and the operator learns about a bad certificate from `aiur mobile status`
  instead of from a phone that silently fails.
- **Deliverable:**
  1. The gateway (MP-N2-C4-T01 lean boot) serves HTTPS on `gateway.host`/`gateway.port`
     when the transport is configured, reusing `Aiur.Machine.Transport.tls_listener/1` and the
     certificate watcher from MP-N2-C10-T01.
  2. Endpoint selection for the QR `e=` list and for `GET /v1/machine` (contract §3, §4.3):
     `https://<advertise_host>:<gateway.port>` first; `gateway.endpoints` entries kept only if
     they are `https://`, or `http://` while `transport.allow_cleartext_overlay` is true.
  3. Registry `InstanceEntry.dashboard.url` = the instance advert's device URL; `reachable_for_devices:
     false` with `reason` from the closed list below when no usable URL exists.
  4. `Aiur.Machine.TlsHealth.check/1` (PROPOSED) reporting cert names, expiry and key match;
     surfaced in `aiur mobile status [--json]` (MP-N2-C3-T03).
- **Non-goals:** obtaining certificates (T03/T04), the instance listener (T01), the QR encoder (C5-T01).

## Chosen design

**Endpoint selection** — a pure function, so the QR, `/v1/machine` and status agree:

```elixir
# PROPOSED Aiur.Machine.Endpoints.select(settings, tls_health) ::
#   {:ok, [uri]} | {:error, :no_device_endpoint, [rejected: {uri, reason}]}
reasons: :loopback | :cleartext_not_allowed | :ip_literal_cleartext | :tls_name_mismatch | :tls_expired | :tls_unavailable | :unknown
```

Order: (1) `https://advertise_host:gateway.port` when TLS health is `:ok`; (2) each
`gateway.endpoints` entry in configured order after filtering; loopback hosts are always
rejected; `http://` only with `allow_cleartext_overlay: true` **and** a DNS-name host (an `http://` IP literal is rejected `:ip_literal_cleartext`, because iOS ATS refuses it and the app's build-time exceptions only name domains; contract §8.1 rule 2). An unclassified failure is
`:unknown` (AGENTS.md "a collapsed cause names the collapse at the source").

**Registry dashboard reachability reasons** (closed list, contract §6.3):
`loopback_only | not_bound | device_auth_off | tls_unavailable | cleartext_not_allowed | unknown`.

**TLS health** (`TlsHealth.check/1`): parses the leaf with `:public_key.pkix_decode_cert/2`,
returns `%{status: :ok | :name_mismatch | :expired | :expiring | :key_mismatch | :unreadable,
not_after, days_left, names, observed_at}`; `:expiring` when `days_left < 14`. Status renders
`days_left` and `observed_at` (AGENTS.md "if a surface computes an age, it renders the age").

**Gateway listener** uses the same rule as T01: no TLS settings → HTTP on `gateway.host` (loopback
by default); a non-loopback `gateway.host` without TLS starts only if
`allow_cleartext_overlay: true`, else the gateway refuses to bind non-loopback and logs the
setting to change (contract §6.2: "refuses a non-loopback bind while mobile is disabled" is kept).

**QR refusal.** `aiur mobile qr` (C5-T01) calls `Endpoints.select/2`; on `{:error, :no_device_endpoint, rejected}`
it prints each rejected endpoint with its reason and exits non-zero. It never prints a QR that a
phone cannot use.

## Implementation steps

1. `src/lib/aiur/machine/endpoints.ex` (PROPOSED): `select/2`.
2. `src/lib/aiur/machine/tls_health.ex` (PROPOSED): `check/1`.
3. Gateway endpoint config (in the MP-N2-C4-T01 boot module): add the `https:` listener exactly as T01.
4. Registry (MP-N2-C4-T04): set `dashboard.url` from the advert device URL and the reason list.
5. Expose `select/2` for its consumers: the QR builder (MP-N2-C5-T01) and `GET /v1/machine` (MP-N2-C5-T04) call it; those tickets depend on this one (not the reverse).
6. Status: add a `transport` block to `aiur mobile status --json`:
   `{mode: "https"|"http_overlay"|"none", tls: TlsHealth, endpoints: [...], rejected: [...]}`.

About 220 production lines.

## Non-happy paths

| Case | Behaviour |
|---|---|
| No TLS, no cleartext overlay, gateway on loopback | Status `mode: none`; QR refused with "configure transport.tls (see docs) or allow_cleartext_overlay". Pairing impossible by design. |
| Cert expiring in < 14 days | QR still shown; status warns with `days_left`. |
| Cert expired / names do not cover `advertise_host` | That endpoint rejected; if none remain, QR refused. |
| Operator lists `http://192.168.x.x` without overlay flag | Rejected `cleartext_not_allowed` (never advertised). |
| Overlay flag true on a non-overlay LAN | Allowed (owner choice); status shows `mode: http_overlay` with a warning line: bearer tokens travel in cleartext (contract §6.2). |
| Endpoint list changes after pairing | Devices refresh on the next `/v1/machine` (contract §4.3). |
