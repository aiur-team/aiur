# MP-N2-C9-T01 — Pairing documentation

## Identity and outcome

- **Bucket / feature / chunk:** 3 / MP-N2 / MP-N2-C9 "Docs and physical-device validation".
- **User value:** an operator can enable mobile, choose a transport, pair, re-link, revoke and
  unpair from the docs alone, and understands that network reachability is not authorization.
- **Deliverable:** a consolidation pass. Individual tickets already add their own reference entries
  (AGENTS.md "Docs ship with the change"); this ticket adds the **guide page** and verifies the rest
  are coherent:
  - New `website/docs-app/guide/mobile-pairing.md`: enable → transport (T-A recipe with the CT
    disclosure, or T-B and its WebView-mic limit, per the owner's choice) → show QR (terminal,
    `--open` page, dashboard settings if approved) → scan → devices → revoke → lost phone /
    unpair-all → troubleshooting by error code (C5-T02, C5-T03, C6-T01 codes).
  - Sidebar entry in `website/docs-app/.vitepress/config.ts` next to "Stream Deck" (`config.ts:137-140`).
  - `reference/cli.md`: every `aiur mobile …` verb present with exit codes.
  - `reference/configuration.md`: a "Machine settings (`~/.aiur/machine`)" section with every key
    (`mobile.enabled`, `gateway.*`, `pairing.*`, `transport.*`) and defaults, checked by the
    MP-N2-C3-T05 checker.
  - `reference/optional-optimizations.md` § Tailscale: one paragraph linking the guide (coordinate
    with MP-R3-C2-T01).
  - AGENTS.md `Auth` section: one sentence that device tokens are a separate credential and that no
    new environment variable is required (none is added by MP-N2).
- **Non-goals:** a concepts page (the contract is internal); screenshots before DESIGN-N2 approval.
