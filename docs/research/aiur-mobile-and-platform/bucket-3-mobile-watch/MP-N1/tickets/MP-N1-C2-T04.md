# MP-N1-C2-T04 — Native wire models and the cross-language fixture check

## Identity and outcome

- **Bucket / feature / chunk:** 3 / MP-N1 / MP-N1-C2.
- **User value:** the phone, the NSE/FCM service and the watch apps read the daemon's JSON
  identically, so a field rename breaks CI instead of silently showing wrong numbers.
- **Deliverable:**
  - `packages/aiur-mobile/scripts/gen-models.mjs` (PROPOSED) running a pinned `quicktype`
    over the JSON Schemas in `packages/aiur-contracts/schema/` to produce
    `native/apple-core/Sources/AiurClientKit/Generated/*.swift` (Codable) and
    `native/android-core/src/main/kotlin/dev/aiur/client/core/generated/*.kt`
    (kotlinx.serialization). Generated files are committed.
  - `npm run check:models`: regenerates into a temp dir and fails on any diff.
  - Fixture decode tests in TS (Jest), Swift (XCTest) and Kotlin (JUnit) over
    `packages/aiur-mobile/fixtures/contract/**/*.json`.
  - Initial schema set: capability report v1 (MP-R1), `InstanceEntry` + `InstanceSummary`
    v1 (MP-N2/MP-N3), Command read and answer result (MP-E2). Others are added by the tickets
    that need them.
- **N1-RQ2 resolution:** generator = `quicktype` (pinned exact version), not hand-written
  models. Reason: three languages from one source; hand-written models would need the same
  fixtures anyway and drift silently between them.
- **Non-goals:** TS types (owned by MP-R1-C3-T6, which picks the TS generator), crypto vectors
  (MP-N2-C5-T05, MP-N4-C1-T04 own them).

## Verified starting point (base 45a290e3)

- `packages/aiur-contracts` does not exist yet (MP-R1 plan §9, MP-R1-C3 "T6 `aiur-contracts`
  package and schema test").
- External (accessed 2026-10-06): quicktype accepts JSON Schema input and targets Swift,
  Kotlin and TypeScript; README example `quicktype -s schema schema.json -o
  src/ios/models.swift` (<https://github.com/glideapps/quicktype>, no release number on the page;
  pin the npm version current at implementation and record it). The Kotlin
  `--framework kotlinx` option and Swift `Codable` output are quicktype renderer options;
  **UNVERIFIED** flag names are confirmed with `npx quicktype --help` at implementation and
  written into `gen-models.mjs`.

## Chosen design

- Schema files are the source of truth; generated files carry a header
  `// GENERATED by scripts/gen-models.mjs from aiur-contracts@<commit>; do not edit`.
- Unknown fields: decoders must **ignore** unknown keys (client capability model §1 rule
  "unknown IDs are ignored"). For Kotlin, `Json { ignoreUnknownKeys = true }`; Swift
  `Codable` ignores unknown keys by default.
- Enums with server-extensible values (`state`, `reason`) are generated as **strings**, not
  closed enums, then mapped by the resolver (MP-N1-C3), so a new server reason becomes
  `unknown` instead of a decode failure. Implemented with quicktype's option to not infer enums
  (or a post-processing step if the flag is absent).
- Fixture layout: `fixtures/contract/<schema>/<case>.json` plus `<case>.expect.json` holding
  a small projection (selected fields) every language must extract identically.

## Implementation steps

1. Add `quicktype` as an exact-pinned devDependency.
2. Write `scripts/gen-models.mjs` (inputs: schema glob; outputs: two directories; options per
   above).
3. Run it; commit generated sources.
4. `scripts/check-models.mjs` (temp-dir regeneration + diff); add to the `js` CI job.
5. Fixtures: copy the example payloads from `contracts/identity-and-capabilities.md` §2.2 and
   `pairing-and-instance-registry.md` §6.3/§7 into JSON files; add edge cases: unknown
   capability id, unknown reason, Fact with `status: unavailable` and no `value`.
6. Tests in the three languages that iterate the fixture directory (Swift: resources copied
   into the test bundle; Kotlin: `src/test/resources` symlink-free copy step in Gradle).

## Non-happy paths

- **Schema adds a required field older servers omit:** decode of an older fixture fails in CI,
  forcing the schema to mark it optional; the capability model shows `needs_update` instead.
- **Generator output changes on a quicktype upgrade:** `check:models` diff in the upgrade PR;
  reviewed like any code.
- n/a security: models contain no secrets.

## Compatibility and rollout

- Generated code only. Rollback: revert the generated files and script.

## Verification

- `npm --prefix packages/aiur-mobile run check:models` — no diff. Mutation: hand-edit one
  generated Swift property name → check fails.
- `npm --prefix packages/aiur-mobile test -- fixtures` (Jest, against the TS types from
  aiur-contracts): `every fixture decodes and projects to its expect file`.
- `xcodebuild test -scheme AiurClientKit … -only-testing:AiurClientKitTests/FixtureDecodeTests`
  and `./gradlew :aiur-client-core:testDebugUnitTest --tests '*FixtureDecodeTest*'`: same.
- Cross-language mutation: change one `expect.json` value → all three suites fail.
- `unknown_reason_decodes_as_string`: fixture with `reason: "brand_new"` decodes in all three.
  Mutation: generate closed enums → Swift/Kotlin decode fails.
