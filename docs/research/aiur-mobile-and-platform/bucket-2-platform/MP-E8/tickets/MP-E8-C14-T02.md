## Identity and outcome

- Bucket 2, feature MP-E8 (continuous build history), chunk C14 (later-wave
  upgrades). Ticket 2 of 4.
- **User value.** After a send from the home-page ticket modal, the one-line
  state under the input tells the operator what became of the message:
  accepted, held for the agent, handed to the agent, in context, failed, or
  unknown. "In context" is claimed only when the conversation journal holds the
  message. A daemon restart or an unreadable receipt shows "unknown", never
  "failed" and never a quiet success.
- **Deliverable.** Replace the wave-0b delivery poll that C11-T06 added to
  `BuildLive` (queue status through `AgentChat.delivery_status/2`, about 60 s,
  states `queued | delivered | failed | superseded | unconfirmed`) with:
  1. `AiurWeb.Conversation.DeliveryOverlay` (MP-E4-C6-T01, pure module) as the
     per-ticket delivery state in `BuildLive`;
  2. `Aiur.Listener.receipt/2` and `Aiur.Listener.receipt_for_send_result/1`
     (MP-E7-C3-T04) as its inputs;
  3. the raw MP-E4 journal entries that MP-E8-C14-T01's
     `{:entries_appended, cid, entries}` handler already receives in `BuildLive`,
     so the overlay clears a message when its `operator_message` entry (with
     `refs.delivery_id`) appears;
  4. a new `send-status` vocabulary and the matching S-7 line copy in
     `modal/composer.js`.
- **Unchanged.** The send call. `OperatorSend.send/3` (C11-T06) still calls
  `AgentChat.send/3`, which MP-E7-C3-T03 makes delegate to
  `Aiur.Listener.send/3` (RC-36). The #2717 rule (one `message_id` per user
  action; keep the draft and id on `outcome_unknown`) stays in `OperatorSend`.
  The composer's pixels do not change.
- **Non-goals.**
  - No listener-mode chip or selector. The design has none (row scope;
    MP-E7-C7 owns the selector, DESIGN-E7).
  - No `read` receipt (MP-E7-C5) and no async unread count.
  - No change to the Units drawer in `DashboardLive` (it retired at C12-T01).
  - No new HTTP route and no CLI change (MP-E7-C7).
  - No receipt history per message bubble. Only the latest send per ticket has
    a line, as in C11-T06.

## Chosen design

### One state source: the overlay

`BuildLive` keeps `:delivery_overlay`, a map `ticket_id => overlay` where each
`overlay` is a `DeliveryOverlay` value holding only the latest send of that
ticket. It replaces `:send_tracking`. The overlay owns every transition; this
ticket owns no transition logic of its own. That keeps one rule set for the
full conversation page (MP-E4), the Executor view (MP-E3-C5) and this modal.

| Input | Source | Overlay call (by role; use the names MP-E4-C6-T01 merged) |
| --- | --- | --- |
| `{:ok, request_id}` from `OperatorSend.send/3` | `send` event | add item `request_id` in state `accepted` |
| `{:error, {:outcome_unknown, _}}` | `send` event | `Aiur.Listener.receipt_for_send_result/1` → `outcome_unknown`; no item is added (there is no request id); the reply already carries the #2717 copy |
| `{:ok, %{receipt: r}}` from `Aiur.Listener.receipt/2` | poll | apply receipt `r` |
| `{:ok, %{receipt: :in_context}}` or `{:ok, %{receipt: :read}}` (not produced in wave 3) | poll | apply as `harness_queued` (`queued`); never remove the item. Only the journal entry removes it (Invariants) |
| `{:error, _}` from the receipt read, or an `{:exit, _}` async result | poll | apply "receipt unreadable" (the overlay makes a non-terminal item `unknown`, MP-E4-C6-T01 "Pending messages do not survive a daemon restart") |
| journal entry `operator_message` with `refs.delivery_id == request_id` | C14-T01 `{:entries_appended, …}` handler, raw entries | remove the item ("in context"), **also when the item is already `unknown`** (Decision 10) |
| 10 min since `accepted` with no entry | overlay clock | `unknown` |

### The `send-status` push (replaces C11-T06's vocabulary)

`push_event(socket, "send-status", %{id: ticket_id, request_id: id, status: s})`
after every overlay change that changes the state of the tracked item, and only
then (no repeated push for the same state). `s` is a fixed string:

| Overlay state | `s` | S-7 line (default copy; DESIGN-E4/E7 own the words) | Tone | Polling |
| --- | --- | --- | --- | --- |
| `accepted` | `accepted` | "Queued · waiting for the agent" | muted | continue (2 s) |
| `held_async` | `held` | "Held · the agent reads it when it chooses" | muted | continue; no 10-min timeout (MP-E4-C6-T01) |
| `queued` (receipt `harness_queued`) | `queued` | "Handed to the agent · not in context yet" | muted | continue |
| removed by a journal entry | `in_context` | line hidden | — | stop |
| `failed`, reason `:superseded` | `failed` + `reason: "superseded"` | "Not delivered (superseded)"; the text is **not** put back (C11-T06 rule: a newer queue item replaced it, so restoring invites a duplicate) | bad | stop |
| `failed`, other reason | `failed` + `reason` tag + `message` | "Not delivered · {message}"; the text is put back into an empty textarea (C11-T06 rule) | bad | stop |
| `unknown` (not found, unreadable, or 10 min) | `unknown` + `cause` | "Delivery unknown · check the log before you send again" (10 min: "Not in the log after 10 minutes · check the agent") | muted | stop |

`reason`, `cause` and `message` are fixed strings: `cause ∈ {"not_found",
"unreadable", "timeout"}`; `reason` is a tag from C11-T06's fixed set plus
`"superseded"` and `"listener_mode_unavailable"`, else `"error"`. `message` is
built on the server by the same tag-to-copy function C11-T06's `send` reply
uses (`AgentLogModal.format_error/1` for a known tag, the fixed "Send failed.
Check the log before you send again." for `"error"`). The client cannot call
`format_error/1`, so the copy must travel in the push. No raw term and no sent
text reaches the client (EC-30).

`in_context` carries only `id`, `request_id` and `status`. The op row is not
touched by this push: C14-T01's `alt` rule already replaces the local op row
(its `data-eid` is `OperatorSend.transcript_id(request_id)`) with the journal
row when the entry is appended, and C14-T01 tests that ("echo replaces local
row"). So the order of the `send-status` push and the append push does not
matter, and this ticket adds no row logic.

### Polling

On acceptance: `Process.send_after(self(), {:receipt_poll, id, request_id},
2_000)`. On the message, if the tracked item for `id` is still `request_id` and
non-terminal: `start_async({:receipt, id, request_id}, fn ->
OperatorSend.receipt(request_id, 1_000) end)`. `handle_async` feeds the overlay,
pushes on a state change, and schedules the next poll while non-terminal. The
2 s interval and 10 min limit are the overlay's values (MP-E4-C6-T01); if it
exposes them as functions or attributes, use those; do not copy the numbers.
Test override: `Application.get_env(:aiur, :build_receipt_poll_ms)`.

`OperatorSend.delivery_status/2` and the `:agent_chat_delivery_status_fun`
seam are replaced by `OperatorSend.receipt/2`: `Endpoint.config(:listener_receipt_fun)`
when it is a 2-arity function, else `Aiur.Listener.receipt/2`. Same seam
pattern as `:agent_chat_send_fun` (`dashboard_live.ex:2746–2751`).

### Send errors that are new under MP-E7

- `{:error, :listener_mode_unavailable}` (MP-E7-C3-T03 non-happy path): add
  `format_error(:listener_mode_unavailable)` → "This agent's delivery mode is
  not known yet, so the message was not sent. Try again." before the catch-all
  (`agent_log_modal.ex:145`), and the tag `"listener_mode_unavailable"`. Draft
  kept; bad tone; nothing added to the overlay.
- `format_error(:superseded)` → "superseded" is used inside the
  "Not delivered (…)" line only; no new clause is needed if the client builds
  that string from the tag (it does, as C11-T06).

### Client changes in `modal/composer.js`

- Replace the `send-status` switch with the table above. Remove the
  `delivered`, `superseded` and `unconfirmed` branches.
- `in_context`: hide `#cv-in-st`. Nothing else (the row is C14-T01's `alt`
  rule).
- `failed`: keep C11-T06's rule. Put the sent text back into an empty textarea
  for every reason except `"superseded"`. The line text is "Not delivered
  (superseded)" for that tag and `"Not delivered · " + message` otherwise.
- The status is applied only for the open ticket and the last `request_id`
  (C11-T06 rule kept).

### Invariants

- "In context" and the hidden line come only from a journal entry with a
  matching `delivery_id`. A receipt, a timeout, an error or a missing item never
  hides the line.
- `unknown` is never shown as `failed`, and `failed` never as `unknown`.
- One operator row per sent message in this tab (C14-T01's `alt` rule).
- The overlay item is added inside the same `handle_event("send", …)` call
  that received `{:ok, request_id}`, before the callback returns. A History
  broadcast for that message can only be handled after the callback returns
  (one LiveView process, one mailbox), so the entry can never arrive before the
  item exists.
- Send still goes through `AgentChat.send/3`; this ticket adds no call to
  `Aiur.Listener.send/3`.
- Every write path still re-checks `dashboard_writable?()` (C11-T06, unchanged).

## Non-happy paths

Each row is an edge case of EC-14 (or the receipt side of it) with its proof.

| Input | Expected behaviour | Proved by |
| --- | --- | --- |
| Send returns `{:error, {:outcome_unknown, _}}` | Draft and message id kept (C11-T06, unchanged); muted #2717 copy; no overlay item, no poll; never "in context" | E1 |
| Receipt `accepted` forever, no journal entry | "Queued · waiting for the agent", then at 10 min "Not in the log after 10 minutes · check the agent"; never hidden | E2 (clock override) |
| Receipt `harness_queued`, then journal entry with `delivery_id` | "Handed to the agent · not in context yet", then line hidden; one op row (C14-T01 `alt`) | E3, B2 |
| Receipt `in_context` or `read` (future MP-E7 values) with no journal entry | Treated as `queued`; the line stays | E13 (mutation) |
| 10-min timeout to `unknown` during a long agent turn, then the journal entry arrives | Line hidden ("in context"); the journal is the record | E14 (mutation) |
| Receipt `harness_queued`, journal entry with a **different** `delivery_id` (another tab's or the TUI's message) | No change for this item | E4 |
| Journal entry with no `delivery_id` | Ignored by the overlay | E4 |
| Receipt `unknown` (item not in `AgentQueueStore`; defensive, see Verified starting point) | Muted "Delivery unknown …"; polling stops; never "failed", never hidden | E5 (mutation) |
| Daemon restart while a send is tracked | The LiveView restarts with the HTTP server (`aiur.ex:66`, `:461`, `:488`); the modal reopens with an empty overlay, so no line and never "failed"; the row appears when the journal has it | manual test |
| Receipt read `{:error, :timeout}` or the async task exits | `unknown` with `cause: "unreadable"` (overlay rule), never `failed` | E6 (mutation) |
| Receipt `failed` with `:superseded` | Bad "Not delivered (superseded)"; textarea stays empty (C11-T06 rule) | E7, B3 |
| Receipt `failed` with `:no_running_agent` (agent ended after acceptance) | Bad "Not delivered · Agent is no longer running."; text put back into an empty textarea | E7, B3b |
| Receipt `held_async` for 15 min | "Held · …" stays; no timeout to `unknown` | E8 |
| Send `{:error, :listener_mode_unavailable}` | Bad line with the new copy; draft kept; no overlay item | E9 |
| Two sends on one ticket | Only the second is tracked; a late receipt or journal entry for the first changes nothing in the line (its op row is still replaced by C14-T01's `alt` rule, so the log has no duplicate) | E10 |
| Two tabs (EC-13) | Each tab tracks its own send; the journal entry reaches both; the tab that did not send just appends the entry | E11 |
| Modal closed while polling | Overlay entry dropped; the next poll message is ignored; no push | E12 |

## Decisions made without the owner

1. **C14-T01 is a predecessor**, because "in context" needs the journal entry in
   `BuildLive` (Interface note 1).
2. **The overlay is the only state source.** No E8-specific transition logic;
   the C11-T06 poll and its 60 s "unconfirmed" end are removed in favour of the
   overlay's 2 s / 10 min rule.
3. **An unreadable receipt becomes `unknown`** (overlay rule), where C11-T06
   kept waiting. Following the shared module beats a second rule.
4. **Copy defaults**: "Queued · waiting for the agent" (kept), "Held · the agent
   reads it when it chooses", "Handed to the agent · not in context yet",
   "Not delivered · …", "Delivery unknown · check the log before you send again",
   "Not in the log after 10 minutes · check the agent". DESIGN-E4/E7 may change
   the words only.
5. **"In context" hides the line** rather than showing a label, so the happy
   path stays pixel-equal to the design.
6. **No age is rendered and none is sent.** `observed_at` from the receipt is
   not pushed to the client; the line always shows the latest poll (at most one
   interval old), and a read failure turns it to `unknown`. Sending an age
   without rendering it is what AGENTS.md forbids.
7. **No mode chip** (row scope; the design has none). `listener_mode` from the
   receipt is not used.
8. **No row logic here.** The operator row on "in context" is replaced by
   C14-T01's `alt` rule. An earlier draft re-keyed the row from this push; that
   duplicated C14-T01 and needed a push-order rule, so it was removed.
9. **A readable copy for `:listener_mode_unavailable`** is added to the shared
   formatter instead of the inspected atom.
10. **A late journal entry wins over a timeout.** An `unknown` line is cleared
    when the matching entry arrives, because the journal is the record
    (Interface note 6).
11. **No draft restore on `:superseded`**, as C11-T06; a newer queue item
    replaced it, so a restored draft invites a duplicate send.
12. **Receipts `in_context` and `read` do not clear the line.** Only the
    journal entry does; they are shown as "Handed to the agent".
