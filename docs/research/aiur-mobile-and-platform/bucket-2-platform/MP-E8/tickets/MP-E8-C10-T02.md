Every call into another module goes through `fx`: `fx.relayout`,
`fx.decorateAll` (C9-T05), `fx.renderList` (C9-T12 default), `fx.applyCols`,

### State and URL

- Selection state is the design's: `S.f.epic`, `S.f.model`, `S.f.tstate`,
  `S.f.astate` (arrays, order kept) and `S.feature`. `S.pop` is the open group
  or `null`.
- **The default is the absence of `tstate`** (C3-T03 note 3). The bare URL
  hides not-planned rows. `?tstate=not+planned` shows them (and, by the design's
  OR rule, dims every other ticket state). To see everything, the operator
  selects every Ticket option. The default needs no written token, so the
  canonical URL stays the design's.
- A filter change calls `writeURL()` (no `extra`). The server parses it, patches
  with `replace: true` and pushes the parsed state back only when it dropped or
  rewrote a value (C3-T03 bridge). `onServerURL` then calls `renderChrome()`,
  which calls `renderFilters()`, so the popover shows the server's truth.
- Back, forward, a stored link and a legacy Units preset reach the hook only
  through `onServerURL` (C9-T01); `renderFilters` and `syncAst` must therefore
  read only `S`, never `location`.

### Invariants

1. With every group empty, `match(t)` is `true` and `rowOk(S, t)` differs from
   the design's `epicOk` only for `not planned` rows. On the design datasets
   (no `not_planned` rows) the board is identical.
2. A ticket whose state, model or status is unknown matches **no** option of
   that group. It is never counted as Merged, Running or No agent.
3. Not-planned rows never take layout space unless `tstate` holds `not planned`.
   Edges to them are not drawn (C9-T07 draws only rendered cards, J:888-892).
4. `renderFilters` is idempotent: two calls with the same `S` and `D` give the
   same `innerHTML`.
5. Every string in the filter DOM goes through `esc`. Hues are finite numbers.

## Decisions made without the owner

1. **"Collapsed" means removed from the layout,** like the Epic filter, not
   dimmed. DESIGN-E8 line 83 says "hide `not_planned` closures". Dimming
   hundreds of cards would fill the history with noise.
2. **The default is the absence of `tstate`,** as C3-T03 decided; showing them
   is `tstate=not planned`. Under the design's OR rule this also dims the other
   ticket states. To see all, the operator selects every Ticket option. A
   separate "show not planned" key was rejected: it adds a URL key and a control
   the design does not have.
3. **The "Not planned" option appears only when a loaded history row is not
   planned (or the filter already holds it).** On the design datasets the
   popover is then identical to the design, and the option appears exactly when
   it would do something. Older not-planned rows appear in it once their day is
   loaded.
4. **Unknown history status stays visible** and matches no Ticket option. Hiding
   it would assume "not planned"; showing it as Merged is the plausible default
   AGENTS.md forbids.
5. **The Model filter lists `LOGOS` keys, then other models on loaded rows** as
   letter options (S-13 look). Plan §10 item 25 says "every model with a logo";
   an operator must still be able to filter a running `muse` agent.
6. **Feature options use `stats.total > 0` and sort by `from`,** not loaded rows
   and insertion order, because history is paged and server maps are unordered.
   The selected feature is listed even when it is older than the last six, so it
   can be cleared from the popover.
7. **An unknown feature percent is `—`** with the lower bound in `title`, as
   C6-T05 decision 6 proposes for C10-T03, so both surfaces agree. Sign-off
   item S-39.
8. **Escape closes the popover, ARIA attributes are added, and focus is kept
   after a re-render.** The design has none of these. They change no pixel and
   the accessibility rule forbids cutting them. The full pass is C12-T05.
9. **`setFeature` is ported here,** not in C10-T03 (interface note 2).
10. **C9-T06 is added to `blocked_by`,** because the Model group imports
    `modelInfo` from `agents.js`.
11. **A diff does not refresh an open popover.** Options are rebuilt on every
    render of the bar; a diff that only adds rows does not render it. Marked with
    a `ponytail:` comment; upgrade if operators report stale lists.
12. **Complexity 4,** as the summary table sizes it: one module port, edits to
    `match.js`, one-line edits in `layout.js`, `render.js`, `shell.js`,
    `list.js` and `band.js`, one CSS rule, one
    fixture row and a 16-test spec, with parity cells across five popovers.
13. **A model key outside the known list is listed and selectable** (for
    example `zz-new` on a real row); C3-T03 keeps any key of the model shape
    (interface note 4).
14. **`closed` (duplicate or unknown close reason) is visible and has no
    option,** like an unknown status. C3-T03 has no `closed` token, and adding
    one is outside this row (interface note 8). Sign-off item S-39.
15. **A now row with `agent: null` has Agent value `null`, not `none`.** The row
    is running, so "No agent" would be a plausible default. This overrides
    C9-T05's guard (interface note 5).
16. **Escape is one line in C9-T01's existing handler,** not a second document
    listener, so the order against the tree and lock is fixed: the popover
    closes first, alone.
