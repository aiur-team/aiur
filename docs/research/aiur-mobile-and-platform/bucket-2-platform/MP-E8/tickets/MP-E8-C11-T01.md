## Identity and outcome

- Bucket 2, feature MP-E8 (Continuous build history), chunk C11 (ticket modal
  and agent chat).
- **User value.** Clicking any ticket on the home page, or opening a shared
  link `/?ticket=2748`, shows that ticket's modal with its real number, state,
  epic, feature, points, GitHub issue and pull request. The link works for a
  ticket that is not in the loaded window. A link to a ticket that does not
  exist says so. It never shows another ticket or an empty frame.
- **Deliverable.**
  1. The client modal module (PROPOSED `src/priv/static/build-home/modal/frame.js`)
     that ports `openModal`'s frame and header (J:1370–1402, 1441–1456),
     `closeModal` (J:1542), `cleanupModal` (J:1368) and the deep-link boot
     (J:1567–1570), with the mock parts removed.
  2. The server events `open-ticket {id}` and `close-ticket {}` in `BuildLive`
     (the open id is kept in the `:open_ticket` assign, which C11-T02, C11-T03
     and C11-T07 hook into), and a by-id read `ticket/2` on the
     `AiurWeb.Build.DataSource` behaviour, with the fixture implementation.
  3. The S-10 not-found state and a cause-neutral "unavailable" state.
  4. Focus trap, focus return, Escape, backdrop and close button.
  5. A body seam: two `fx` entries, `fx.renderDocBody(t, bodyEl, opts)` and
     `fx.renderConversation(t, bodyEl, opts)` (no-op defaults), that C11-T02 (issue
     view, wrapping its `renderDoc`) and C11-T03 (conversation, which already
     names `fx.renderConversation`) fill. This ticket renders an empty
     `#tk-body`.
- **Non-goals.**
  - The issue view body (`.bm-doc`): C11-T02. The conversation body (`.cv`):
    C11-T03..T06, T08, T09.
  - The real `.bm-agent` group (`agentGroupHTML`, its control state and the
    16 px `.ax-mono` rule): C11-T07 (its interface notes 2 and 7). This ticket
    renders a static placeholder with the same DOM so the header has parity
    now; C11-T07 replaces the builder.
  - The pause, resume and "Open in Conversations" behaviour: C11-T07. This
    ticket renders the two `.bm-ib` buttons in the design markup, disabled,
    so the header has parity now (Decision 4).
  - The Units-only fields (runtime, turns, tokens, priority, resume reason, CI
    state, Remote Control link): OQ-E8-5 default is "add none". C11-T10 adds
    them only if Kevin says yes.
  - Pack-row (`pack:<pack>/<item>` id) source text, the `was` follow and the

  - Focus-ring styles and the forced-colours fallback (S-12): C12-T05.

## Chosen design

### Client module (PROPOSED `src/priv/static/build-home/modal/frame.js`)

Registered with one line in `hook.js` (`import "./modal/frame.js"`, C9-T01
rule 2). It exports and registers into `fx`:

| Export | Purpose |
| --- | --- |
| `openModal(t, { origin })` | Open or replace the modal with row `t` (the design's `openModal`) |
| `openById(id, { origin })` | `D.byId[id]` if loaded, else `open-ticket` fetch |
| `openFromURL()` | Boot path: `openById(S.ticket)` when `S.ticket` is set |
| `closeModal()` | All close paths |
| `syncTicket(id)` | Server URL push changed `ticket` (back/forward, `live_patch`) |
| `modalSync(msg)` | After each applied diff: refresh or retire the open row |
| `renderHead(t)` | Header only; re-run on diffs and by C11-T07 (C11-T07 adds its `applyControl` call after each `renderHead` in its PR, R-G4) |
| `onModalClose(fn)` | Successors stop timers and streams (the design's `stopLive`) |
| `MS` | `{ t, req, origin, state }`, where `state` is `"row" | "not_found" | "unavailable"` |

`fx` gains `openModal`, `closeModal`, `syncTicket`, `modalSync` (registered by
this module) and `renderDocBody`, `renderConversation` (filled by C11-T02 and
C11-T03). All six get no-op defaults in `state.js`, added by this ticket next to
the existing `openFromURL` (C9-T01 rule 1: a call into a module that may land
later goes through `fx`).

**Body choice** keeps the design rule (J:1377): `bodyKind(t) = t.agent &&
t.start != null ? "conversation" : "doc"`; the frame then calls
`fx.renderConversation(t, bodyEl, opts)` or `fx.renderDocBody(t, bodyEl, opts)`.
`opts` is a plain object the body may forward (C11-T03 passes `opts.note` to the
doc body for the S-6 hand-off). With the no-op defaults, `#tk-body` is left
empty.

### Open, replace, close

- **Open from a card** (C9-T05 calls `fx.openModal(D.byId[id], { origin: card })`):
  `cleanup()` (run `onModalClose` callbacks), set `MS.t`, add `.bdm` to
  `#tk-modal`, `renderHead`, render the body, add `.show` to `#tk-backdrop`,
  `document.body.style.overflow = "hidden"`, focus the heading, set `S.ticket`
  and call `writeURL({ ticket: t.id })`. For a pack row, set `S.ticket = null`
  and call `writeURL({ ticket: "" })` until C7-T02 widens the C3-T03 `ticket`
  rule and makes the `writeURL` change for pack ids in its PR.
- **Tell the server.** Every modal open, loaded or not, sends
  `ctx.push("open-ticket", { id })` when `ctx.socket === "up"`, so the
  successors' open hooks always fire (C11-T03's conversation read, C11-T07's `control` and `chat`, C11-T08). For a loaded row
  the push adds `loaded: true` (an additive optional field, R-G1); the reply
  then carries no `row`, and the modal does not wait for it. The reply carries
  the row only when it was not loaded. Every close
  sends `ctx.push("close-ticket", {})` (C11-T02 `TicketDoc.close/1`). Replies
  that arrive after another open or a close are dropped by the `MS.req`
  check.
- **Replace** (`[data-goto]`, a server URL push, a diff): the same steps
  without touching `.show`, so `tkin` does not replay (the design keeps `.show`
  and removes and re-adds `.bdm` in the same task, J:1371–1375). The focus
  origin stays the first one.

### Deep link and fetch by id (EC-17)

```
openById(id):
  row = D.byId[id]
  if row: return openModal(row)                    // openModal sends open-ticket {id, loaded: true}, does not wait
  if ctx.socket !== "up": return openUnavailable(id, "disconnected")
  req = ++MS.req
  try reply = await Promise.race([ctx.push("open-ticket", { id }), timeout(10_000)])
  catch e: reply = { kind: "error", reason: e === TIMEOUT ? "client_timeout" : "disconnected" }
  if req !== MS.req: return                       // a newer open or a close happened
  row = D.byId[id] || (reply.kind === "ticket" ? reply.row : null)   // a diff may have loaded it meanwhile
  if row: return openModal(row, { sent: true })   // no second open-ticket push
  reply.kind === "error" && reply.reason === "not_found" ? openNotFound(id)
                                                        : openUnavailable(id, reply.reason)
```

The 10 s client timeout is longer than the server's 5 s `safe_read` bound, so a
slow source normally answers `unavailable` first; the client timeout covers a
lost reply (a push sent as the socket drops waits up to 30 s, C9-T01).

- A fetched row is shown but not merged into `D`. Only history rows can be
  outside the window (C3-T02: the window holds the queue, the band and the
  first history days; diffs never carry older rows), and closed rows do not
  change, so the header does not need diffs.
- Nothing is shown while the fetch runs. The design opens the modal only when
  the row is known (J:1569). The answer is one GenServer call, so the wait is
  short.
- **Not found (S-10):** the frame with `.bm-h` › `.bm-tt h3` =
  `<span class="bm-num">#N</span>Ticket not found`, `.bm-act` with only the
  close button, empty body. `?ticket=N` stays in the URL until the user closes.
- **Unavailable:** the same layout with `Ticket unavailable` and a `.bm-meta`
  line naming the cause. The server sends only the C3-T02 reasons, and it
  already collapses every source error to `unavailable`. Client words:
  `unavailable` → "source unavailable", `invalid_params` → "invalid ticket id",
  `client_timeout` → "timed out", `disconnected` → "connection lost", anything
  else → "unknown cause" (AGENTS.md: a collapsed cause is cause-neutral). It
  never says "not found". The frame does not retry by itself: closing it and
  following the link again, or a reload, retries (Decision 13).
- **Malformed ids** never reach this code: C3-T03 drops them before `S.ticket`
  is set, so `?ticket=AIUR-12` opens nothing and is removed from the URL.

### Server (`BuildLive`, PROPOSED `src/lib/aiur_web/live/build_live.ex`)

```elixir
def handle_event("open-ticket", %{"id" => raw} = params, socket) when is_binary(raw) do
  case ticket_id(raw) do
    {:error, :invalid} ->
      {:reply, Payload.error(:invalid_params), socket}

    {:ok, id} when params["loaded"] == true ->
      socket = assign(socket, :open_ticket, id)    # successors (C11-T02/T03/T07/T08) pipe their open work here
      {:reply, Payload.ticket(nil, socket.assigns.build_epoch, socket.assigns.build_generation), socket}

    {:ok, id} ->
      socket = assign(socket, :open_ticket, id)    # same successor pipe
      source = socket.assigns.build_source

      case safe_read(fn -> DataSource.call(source, :ticket, [id, source_opts(socket)]) end) do
        {:ok, row} -> {:reply, ticket_reply(row, socket), socket}
        {:error, :not_found} -> {:reply, Payload.error(:not_found), socket}
        {:error, _other} -> {:reply, Payload.error(:unavailable), socket}
      end
  end
end

def handle_event("open-ticket", _params, socket), do: {:reply, Payload.error(:invalid_params), socket}

def handle_event("close-ticket", _params, socket),
  do: {:noreply, assign(socket, :open_ticket, nil)}  # successors pipe their close work here

defp ticket_reply(row, socket) do
  case Payload.row(row) do
    {:ok, row} -> Payload.ticket(row, socket.assigns.build_epoch, socket.assigns.build_generation)
    {:error, _} -> Payload.error(:unavailable)
  end
end
```

`:open_ticket` is assigned `nil` in the connected mount. The arguments
`[id, source_opts(socket)]` follow C3-T02's call style for `snapshot` (see
Interface note 1 for the `call/3` arity question).

- `ticket_id/1` accepts `^[0-9]{1,10}$` with value > 0 and returns the
  canonical `Integer.to_string/1` (the C3-T03 rule). C7-T02 extends it for
  `pack:` ids.
- The source call goes through C3-T02's `safe_read/1` (5 s bound; a timeout,
  exit or raise becomes `{:error, :timeout | :crashed}`), so a slow or dead
  source never blocks or crashes the LiveView.
- `Payload.ticket/3` (new, next to `Payload.snapshot/3`) returns `{v: 1, kind:
  "ticket", epoch, generation, row}`, with `row` omitted when it is `nil` (a
  loaded open); C11-T07 adds `control` and `chat` in its PR. Its validator clause goes into
  `Payload.validate/1` in the same PR (C3-T02 extension rule). A row that fails
  `Payload.row/1` becomes `unavailable`, not a crash.
- Not gated by `dashboard_writable?/0`: it is a read and works on a read-only
  dashboard. It never calls GitHub (EC-32): "not found" means "not in the
  index".

## Non-happy paths

- **Unknown id** (`?ticket=99999`): S-10 not-found frame; URL keeps it; close
  clears it.
- **Source down or slow:** `unavailable` with its cause; the 10 s client
  timeout gives "timed out". The page itself stays usable.
- **Disconnect during a fetch:** the push either rejects ("connection lost")
  or stays pending, and the 10 s client timeout gives "timed out". A fetch
  started while `ctx.socket === "down"` shows "connection lost" at once and
  sends nothing. `reconnected` runs `resync()`/`repaint()`, not
  `openFromURL`, so there is no automatic retry; the user closes and reopens
  the link (Decision 13). A loaded row opens from `D` while the socket is
  down; only the `open-ticket` notice is skipped.
- **Late reply:** a reply for an older request (`req !== MS.req`) is dropped,
  so a slow deep-link fetch never replaces the ticket the user clicked next.
- **Row removed while open:** not-found state in place, no crash.
- **Row changes section while open** (plan → now → hist): one upsert;
  `renderHead` shows the new state, tone and progress.
- **Pack row:** no URL write, no GitHub link, `—` for the number.
- **Hostile text** (EC-30): title, epic and feature labels escaped; numbers
  checked before raw use; the `hostile.json` fixture proves it.
- **Read-only dashboard** (EC-12): `open-ticket` works; write buttons in the
  header stay disabled (C11-T07 adds the writable rule).
- **Repository not configured** (EC-29): no GitHub link and no PR chip; never
  the design's `aiur-labs/aiur`.
- **Escape inside a later textarea** (C11-T06): closes the modal, as the design
  does. Draft handling is C11-T06's.
- **Navigation away while open:** `onReset` restores body scroll.
- **Unknown, stale, unavailable values:** `?%`, `? pts`, `Q?`, "State
  unknown", "Ticket unavailable". None renders as `0`, `Merged`, `Running` or
  a plausible default; each has a mutation test below.

## Decisions made without the owner

1. **Unknown ids show a frame; unknown causes never claim "not found".** The
   design does nothing for an id it cannot find (J:1569). S-10's default needs
   a frame, and a source failure is a different fact, so it gets its own
   cause-neutral "Ticket unavailable" frame.
2. **No visible loading state for a fetch by id.** The design opens only when
   the row is known. The fetch is one in-memory read; a 10 s timeout covers a
   stuck source.
3. **A fetched out-of-window row is not merged into `D`.** It is a closed
   history row; merging it would draw a card outside C9-T03's window.
4. **The header renders the pause and chat buttons now, disabled.** This gives
   header parity in this ticket. Author `color` on `.bm-ib` overrides the UA
   disabled colour, so the pixels match; C1-T02 checks it. C11-T07 enables them.
   `BuildLive` is at `/build` (not in the nav) until cutover, which needs C11-T07.
5. **Copy link reports failure.** The design shows "Copied" even when the copy
   fails (J:1446). That is a false success, so `.ok` is added only on success.
   The success pixels are the same.
6. **`aria-labelledby` the heading, `tabindex="-1"`, and no focus outline on
   the heading.** Accessibility is never cut; none of it changes the resting
   pixels.
7. **One Escape closes only the modal.** The handler calls `preventDefault()`
   (reconciled 2026-10-08 with C9-T11); the design's double effect (H:5106 and
   J:566) is dropped, and a second Escape reaches the tree.
8. **No MutationObserver** (J:1557). All close paths go through `closeModal`,
   so it clears `?ticket=` directly (ponytail: fewer moving parts).
9. **The focus helpers are copied, not shared,** from
   `ticket-context-dialog-hook.js`. The source is a hook object for
   LiveView-owned nodes; making it shareable would change a file that the
   Units drawer and Stream Deck pages load.
10. **`closed`, `not_planned` and unknown hist states use the grey dot.** Green
    `done` for them would be a plausible wrong default.
11. **OQ-E8-5 default:** no Units fields in the header. C11-T10 is the sized
    alternative.
12. **The fixture mapping emits the design's mock PR rule** so parity data
    equals design data. The rule is in fixture code only.
13. **No automatic retry of a failed fetch.** C9-T01's `reconnected` does not
    rerun `openFromURL`. Adding a retry loop would need a new hook point for
    one rare case; closing and reopening the link (or a reload) retries.
14. **Every open and close notifies the server** (`open-ticket`,
    `close-ticket`), even for a loaded row (with `loaded: true`, no row in the
    reply). C11-T02, C11-T03 and C11-T07 all
    need the server to know the open ticket; the loaded-row open still paints
    from `D` without waiting, so the design's timing is kept.
15. **Neutral tone class `idle`** for plan, nq, unknown and non-merged closed
    states, as the design writes `idle` (J:1380, J:90). There is no CSS rule
    for it, so it is the grey dot, and the DOM matches the design string.
