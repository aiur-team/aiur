## Chosen design

### Server: one DASH-005 path for both LiveViews

Move the DASH-005 block out of `DashboardLive` into PROPOSED
`src/lib/aiur_web/operator_control_center/unit_controls.ex`. The functions work
on a plain `controls` map (key → control state) and return values; each
LiveView keeps its own assigns and applies them. The logic, order and error
handling do not change.

```elixir
defmodule AiurWeb.OperatorControlCenter.UnitControls do
  @type controls :: %{optional(String.t()) => UnitsControlPolicy.control_state()}

  # settled? → identifier → capabilities → recheck → owner call. Returns the new
  # map and the identifier to subscribe to (nil when nothing was dispatched).
  @spec request(controls, key :: String.t(), row :: map() | nil, :pause | :resume) ::
          {controls, String.t() | nil}
  @spec apply_lifecycle(controls, payload :: map()) :: {controls, key :: String.t() | nil}
  @spec reconcile(controls, (String.t() -> map() | nil)) :: controls
  @spec in_flight_identifiers(controls) :: MapSet.t(String.t())
  @spec pause(TrackerIdentity.t() | String.t()) :: {:ok, term()} | {:error, term()}   # :agent_chat_pause_fun seam
  @spec resume(String.t()) :: {:ok, term()} | {:error, term()}                        # :agent_chat_resume_fun seam
  @spec capabilities(String.t()) :: {:ok, map()} | {:error, term()}                   # :agent_chat_capabilities_fun seam
end
```

- `request/4` with `row == nil` keeps the "not found" behaviour of
  `resolve_unit_control_row/3`: the map is unchanged and nothing is called.
- `apply_lifecycle/2` is `apply_control_lifecycle/2` +
  `find_control_token/2` on the map: it finds the entry by
  `payload.tracker_identity.identifier` and calls
  `UnitsControlPolicy.apply_lifecycle/2` (request-id correlation unchanged).
- Subscribing stays in each LiveView (it needs `connected?/1` and the
  LiveView's own subscription set), as `ensure_control_subscription/2` and
  `sync_unit_control_subscriptions/2` do today.
- `DashboardLive` keeps its Units token as the key; BuildLive uses the
  ticket id (`TrackerIdentity.identifier`). `DashboardLive.pause_agent/1`
  becomes a call to `UnitControls.pause/1`, so the drawer keeps its seam.

### Server: BuildLive events

```elixir
def handle_event("request-unit-control", %{"id" => id, "action" => action}, socket)
    when is_binary(id) and action in ["pause", "resume"]
#   1. not (socket.assigns.writable and dashboard_writable?())
#                    → assign writable false; {:reply, %{v: 1, kind: "error", reason: "read_only"}, socket}
#   2. id fails C3-T02's row-id rule or starts with "pack:"
#                    → {:reply, %{v: 1, kind: "error", reason: "invalid_params"}, socket}
#   3. row = DataSource.call(source, :unit_row, [id])        # unit_row(id, opts)
#      {:error, _}   → {:reply, %{v: 1, kind: "error", reason: "unavailable"}, socket}
#   4. {controls, sub} = UnitControls.request(controls, id, row, String.to_existing_atom(action))
#      subscribe when sub; assign; reply TicketControl.encode(...)
def handle_event("request-unit-control", _params, socket)
#   → {:reply, %{v: 1, kind: "error", reason: "invalid_params"}, socket}   (C3-T02 fallback rule)

def handle_event("open-conversation", %{"id" => id}, socket) when is_binary(id)
#   valid id + unit_row {:ok, row} + chat_path(row) = path → {:noreply, push_navigate(socket, to: path)}
#   anything else → {:reply, %{v: 1, kind: "error", reason: "unavailable"}, socket}
def handle_event("open-conversation", _params, socket)
#   → {:reply, %{v: 1, kind: "error", reason: "invalid_params"}, socket}

def handle_info({:control_lifecycle, payload}, socket) when is_map(payload)
#   {controls, key} = UnitControls.apply_lifecycle(...)
#   push "build-ticket-control" when key == the open ticket id; unsubscribe when the entry settled

# When :url_state.ticket changes to an id (C3-T03 handle_params or "build:url"),
# and on each index change for the open id or an in-flight key:
#   controls = UnitControls.reconcile(controls, &unit_row_or_nil/1); push for the open id
```

- **Writable gate.** C3-T02's rule for every write on BuildLive:
  `socket.assigns.writable and dashboard_writable?()` inside the event, before
  any read. On failure the socket's `writable` becomes false, as
  `handle_writable_event/2` does (`:2682–2688`).
- **Id check.** The id must pass C3-T02's row-id rule and must not start with
  `pack:` (an unfiled item has no agent).
- **`open-conversation` is a read.** It works on a read-only dashboard, as the
  `/chat/...` route does today.
- **`chat_path/1`:** `"/chat/#{owner}/#{repository}/#{identifier}"` from the
  row's `%TrackerIdentity{}` when all three are binaries, else `nil`. The path
  is built only on the server from the row (the same shape as
  `context_runtime.ex:244`). A path from the browser is never used.
- **First control body.** A row in the loaded window opens with no server
  call (C11-T01 B3), so BuildLive pushes `build-ticket-control` itself when
  `:url_state.ticket` becomes an id (the modal writes `?ticket=` on open,
  C3-T03 bridge). It also pushes after a connected mount with `?ticket=` set.
  The `open-ticket` reply carries the same body for rows outside the window.
- **Subscriptions.** BuildLive subscribes to an agent topic only while it has
  an in-flight control for that identifier (`in_flight_identifiers/1`), as
  `ensure_control_subscription/2` does (`dashboard_live.ex:2833–2842`), and
  unsubscribes when the entry settles. A lifecycle for an untracked identifier
  changes nothing (`UnitsControlPolicy.apply_lifecycle(nil, _)` is `nil`), so
  the open ticket alone is no reason to subscribe. Transcript and turn messages
  on that topic fall through to BuildLive's catch-all clause.

### Data-source read: `unit_row/2`

`DataSource.call/3` appends, as for C11-T01's `ticket/2`):

```elixir
@callback unit_row(id :: String.t(), opts :: keyword()) ::
            {:ok, map()} | {:error, :not_found | :index_not_running | term()}
```

- `IndexSource` (C8-T04): `GenServer.call(Index, {:unit_row, id})`. The Index

- Default body: `{:error, :not_wired}`. Fixture source: rows built from the

### Server → client: `build-ticket-control`

```json
{ "v": 1, "kind": "control", "id": "123",
  "control": { "action": "pause" | "resume" | null,
               "state": "enabled" | "pending" | "disabled",
               "title": "Pause agent",
               "status": { "label": "Pause requested…", "tone": "pending" | "applied" | "warning" | "error", "retry": false } | null } | null,
  "by_you_at": 1759900000000 | null,
  "chat": "/chat/aiur-labs/aiur/123" | null }
```

`by_you_at` (epoch ms) is set only when this LiveView's own `pause` request
for the id settled `applied` through a correlated `:control_lifecycle`; it is
the lifecycle's time. It is `null` for a pause made elsewhere (TUI, another
tab), for every resume, and once the row is no longer `paused`. C11-T04 reads it
for row 13. The `control` push kind and its fields are new, so their
`Payload.validate/1` clause and C3-T02 fixture mapping land in this PR (R-G1).

It is the `request-unit-control` reply body, the push body, and a field
C11-T01 adds to its `open-ticket` reply (Interface note 2). Encoder: PROPOSED
`AiurWeb.Build.TicketControl.encode(row_or_error, control, writable?)`.
`affordance = UnitsControlPolicy.affordance(row, control)`.

| Server input | `control` |
| --- | --- |
| `unit_row` error (not found, Index down) | `null` |
| `writable? == false` | `state: "disabled"`, `title: "Dashboard is read-only"`, `action` from affordance |
| affordance `:enabled` | `state: "enabled"`, `action`, `title` "Pause agent" / "Resume agent" (J:1391) |
| affordance `:pending` | `state: "pending"`, `action: pending_action`, `title` = `presentation(control).label` |
| affordance `:disabled` | `state: "disabled"`, `title` = `disabled_reason(reason)` |

`status` is `presentation(control)` (label, tone, `retry?`) whenever a control
state is tracked for the id, whatever its tone, as `units_table.ex:205–211`
announces every tracked state; it is `null` when nothing is tracked. When
`state` is `enabled` and `status.tone` is `error`, `warning` or `pending`
(`already_pending`), `title` = `status.label`. With tone `applied` the title
stays the affordance title (for example "Resume agent" after a pause applied).

### Client: button behaviour (PROPOSED `src/priv/static/build-home/modal/agent-control.js`)

C11-T01's `renderHead(t)` keeps building `.bm-agent` and both buttons. This
module only changes attributes on them. It does not build markup.

```js
export function applyControl(head, t, ctl)   // set state on [data-a=pause] and [data-a=chat]; ctl may be undefined
export function wireAgentControl(head, t)    // click → ctx.push; no state change in the browser
```

- **Re-apply after every render.** The hook keeps the last body per id
  (`MS.control`, reset on close and in `onReset`). After every `renderHead(t)`
  (open and each diff) it calls `applyControl(head, t, MS.control[t.id])`, so a
  diff never puts back C11-T01's plain `disabled` buttons.
- **Visible when.** Pause button: C11-T01's rule (J:1382, `now` and state
  `active|paused`), unchanged. Expand button: `hidden` unless `ctl && ctl.chat`
  (decision 2); it is hidden while no body has arrived, so it never shows and
  then vanishes on a ticket that has no chat.
- **Button state from `ctl.control`** (remove C11-T01's `disabled` attribute
  in every case; use `aria-disabled` instead, decision 3):
  - no body yet: `aria-disabled="true"`, `title` "Checking agent control…";
    icon from `t.agent.state`;
  - `control === null`: `aria-disabled="true"`, `title` "Agent control
    unavailable"; icon from `t.agent.state`;
  - `enabled`: no `aria-disabled`; icon `MI.play` for `resume`, `MI.pause` for
    `pause`;
  - `pending`: `aria-disabled="true"`, `aria-busy="true"`, icon from
    `action`;
  - `disabled`: `aria-disabled="true"`, icon from `t.agent.state`;
  - `status.tone` `error` → class `bad`; `warning` → class `warn`.
  - `title` = `ctl.control.title`; `aria-label` = `title`. An `sr-only`
    `role="status" aria-live="polite" aria-atomic="true"` span, last child of
    `.bm-agent`, gets `status.label` (empty when `status` is `null`), as
    `units_table.ex:205–211`.
- **Click.** The hook ignores a click on an `aria-disabled` button. Otherwise
  it sends `ctx.push("request-unit-control", {id: t.id, action})`, where
  `action` is `ctl.control.action`, not the browser's view of `t.agent.state`.
  The reply goes through `applyControl`. The ticket state and the card change
  only from `build-diff` (C8-T04), never here. An `error` reply sets the
  button title to the reason copy (`read_only` → "Dashboard is read-only",
  `unavailable` → "Agent control unavailable", `invalid_params` → "Control
  unavailable") with class `bad`.
- **Expand.** `ctx.push("open-conversation", {id: t.id})`. The server
  navigates in the same live session, so the page changes without a reload and
  the browser Back button returns to `?ticket=<id>`. The hook does not call
  `closeModal()` first (that would clear `?ticket=` and lose the Back target);
  its `destroyed` callback must not write the URL. An error reply sets the
  expand title to "Chat is unavailable for this ticket." (the drawer route's
  copy) and keeps the modal open.
- `data-control="ready"` on `.bm-agent` once a body has been applied. It
  paints nothing; parity and browser tests wait for it.

## Decisions made without the owner

1. **Pending, disabled and failed looks** reuse the design's own disabled rule
   (C:153, opacity .4) and its `-ink` tokens for error (`--block-ink`) and
   warning (`--attn-ink`). The full copy is shown as the button's `title` and
   `aria-label`, and announced through an `sr-only` live region. The design
   has no other slot in the header.
2. **The expand button shows only when the drawer route can open the ticket**
   (a Units row with a GitHub identity). On past tickets it is hidden until
   C14-T03, because `/chat/...` would only say "Chat is unavailable". This is
   the one pixel difference from the design, sign-off item S-41.
3. **`aria-disabled` instead of `disabled`** on the buttons, so keyboard and
   screen-reader users can still reach the button and hear the reason. The
   Units table swaps a disabled control for a `<span>` (`units_table.ex:197–203`);
   the modal keeps the design's `<button>` so the DOM matches J:1391–1392.
4. **The pause button keeps the design's visibility rule** (`active` or
   `paused` only). Parked, command, error and retry states get no button even
   when the orchestrator could resume them; the composer still resumes a parked
   agent (OQ-E8-10 default).
5. **Navigate on the server** (`push_navigate`) instead of building the URL in
   the browser, so the path cannot be forged and the session does not reload.
   `?ticket=` stays in history so Back returns to the modal.
6. **Extract the DASH-005 block** instead of a second copy in BuildLive
   (ponytail: reuse; one copy of the request and lifecycle rules). This is why
   complexity is 3, not the row's 2.
7. **Patch C11-T01's buttons instead of a second `.bm-agent` builder.** One
   header builder; this ticket owns only state and clicks. The logo, name,
   title and unknown-model letter follow C11-T01's rules.
8. **`blocked_by` adds C8-T04**, because without it only the fixture source
   can answer `unit_row/2`. C12-T01 already waits on both, so the critical
   path does not change.
9. **`by_you_at` only for this operator's own applied pause.** C11-T04 derives
