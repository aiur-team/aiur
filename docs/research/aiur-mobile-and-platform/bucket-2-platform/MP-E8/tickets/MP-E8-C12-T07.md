## 4. Chosen design

### 4.1 Page layout of the docs

- **Concept page.** One new page, `concepts/build-history.md`, title "Build
  history". It replaces `concepts/units.md` and keeps `concepts/build-orders.md`.
  Reason: `build-orders.md` is mostly about planning packs, the state node and
  Executor handoff (`:5-21`, `:61-85`). That content is still true, because the
  data layer and `aiur build-orders` stay (C12-T02 non-goals). `units.md` is
  almost entirely about the retired page. Merging both into one page would
  move true pack content for no gain (ponytail: smallest correct change).
- **Sections of `build-history.md`** (each one short, tables over prose, so the
  dense-prose rule at `gui-docs.spec.ts:254-262` passes):
  1. What the page is: `/`, one continuous board from history through Live to
     Planned and Not queued. The screenshot `build-dark.png`, alt text with the
     word "synthetic".
  2. Epics: exactly one per ticket; resolution order feature → override →
     first matching general epic → Unsorted (C5-T02). The four defaults, by
     link to `/reference/configuration#general-epics` (the `### General epics`
     subsection C5-T01 step 4 writes; C5-T01 handoff 6 asks for this link),
     not restated. `aiur epic` by link to its `cli.md` anchor.
  3. Features: owning feature and "also affects" (E8-D11); `feature:` labels
     (C6-T02); Build Order roots as `bo-<number>` (the C6-T03 paragraph, moved
     here); Focus and Compact (C10-T03); the "weighted" completion figure
     (E8-R1). `aiur feature` by link.
  4. The time axis: history by real time, Planned in build-queue order with
     dependency waves (MP-E1 queue; link to MP-E1's `aiur queue` section on
     `cli.md`), Not queued newest first. "Planned · not filed" rows and the
     "Planning packs unavailable" marker (C7-T02 handoff).
  5. Views and controls: Timeline, Gantt, List; Day/Week/Month and −/+ (C9-T10
     sentence); the Live band and `live=min` (C9-T08); List is the keyboard and
     screen-reader view (C9-T12 handoff).
  6. Filters: the C10-T02 sentence verbatim, plus "Not planned" (S-17).
  7. Estimates: default hours by complexity, overrides with a reason, the ETA
     divided by `agent.max_concurrent_agents` (C7-T03); "—" for unknown
     complexity. `aiur ticket estimate` by link.
  8. Agent indicators: logo, glow, stuck, idle; reduced motion has a static
     equivalent; state is never colour alone (E8-D12, C9-T06, S-4).
  9. The ticket modal: `?ticket=` (C11-T01/C3-T03 sentence), the issue view,
     the conversation and minimap, the composer with the S-7 copy (C11-T06),
     pause/resume and "Open in Conversations" (C11-T07), the Command answer
     card (C11-T08), dictation (C11-T09 line, only if merged), "Ticket not
     found" (S-10), "Conversation not retained" (S-6).
  10. Usage strip: APIs (GitHub core and GraphQL; ElevenLabs when configured)
      and Models. The API-meter rows and failure wording move here from
      `units.md:22-37`. "not observed" for a provider with no limits.
  11. Unknown and stale states, one table: what each unknown renders and what
      it never renders (never `0`, never "ready", never a plausible default).
      Rows: unknown runtime/tokens (EC-08), unknown estimate "—", queue or
      history "unavailable" with its age (S-9), daemon offline/cached and
      Reconnect (S-16, C8-T03), not-observed meter, start unknown in Gantt
      (S-5).
  12. What moved and where: a table mapping every `units.md` section to its
      new home (see §4.3).

## 10. Decisions made without the owner

1. **A new `concepts/build-history.md` page, and `concepts/build-orders.md`
   kept.** The row allows "replaces or merges". `build-orders.md` is mostly
   about planning packs and the state node, which stay true. Merging it would
   move true text and risk losing it. Only `units.md` is replaced.
2. **The docs screenshot uses C3-T01's `FixtureSource` with the C1 `live`
   dataset.** It is one synthetic dataset for parity and for docs, and it
   reads no live store. The alternative, a second docs-only dataset with
   `EX-` tickets, would need its own exporter and could drift from the design.
3. **The `example` text check becomes a per-surface `markers` list.** The
   three existing surfaces keep `example` plus their old marker, so nothing
   gets weaker for them. The Build surface uses two design-only labels. The
   forbidden-pattern and foreign-identifier checks are unchanged on every
   surface. The guard is never relaxed to make a capture pass.
4. **A usage-strip meter guard that checks values, not presence.** The
   existing `.rs-model` guard would see zero rows on the new page. Setting
   `required: false` would silently drop the check. The new checker compares
   non-zero widths from the committed `usage-sets.json`, and leaves out the
   Codex zeros, because 0 is what a defaulted meter shows.
5. **Complexity 3, not the row's 2.** The row lists five docs files. The
   research found three more pieces of work the row did not name: the capture
   pipeline cannot capture the new page without the source and guard changes
   (§4.4); C2-T01 hands this ticket the recapture of the images; and nine
   other pages name the Units page, meter or view (§1 item 5, `tui.md:21`
   included).
6. **Fleet capacity and the routing preview are documented as "`/units` only,
   for one release".** The design's home page has neither control (J:1391,
   J:1438), and no MP-E8 ticket adds them. The docs say so and point to `aiur
   set max-agents`. The gap is sign-off item S-48 / OQ-E8-11, not fixed
   here.
7. **The Build row's CLI counterpart is a list of commands, not one mirror.**
   No command mirrors the whole board. Inventing "`aiur build`" in the docs
   would be false.
8. **"Usage and cost" moves to `build-orders.md`.** It renders in the Build
   Order Usage pane (`usage_runtime.ex:269`), not on the Units page. When
   OQ-E8-9 retires that pane, C12-T02 removes or moves the section
   (interface note 4). The allowance-meter part of the same `units.md` section
   (`:65-75`) is Units-strip code (`run_summary_strip.ex:240, :254`) and goes
   to the home page usage strip instead.
9. **Anchors of the deleted page are not kept as stubs.** External links to
   `/concepts/units#…` reach the new page through the 301 and open at the top.
   A stub page would be a second copy that goes stale.
10. **Only merged behaviour is documented.** A handoff from a ticket that has not
    merged (for example C11-T09) is left out of the text, not written as a
    plan.
11. **V-6 checks fragments against the built HTML ids, not a copied slug
    rule.** CI already builds the docs before `test:brand`, and a hand-written
    slug function would drift from VitePress's (backticks, dots and dashes in
    CLI headings). The cost is that V-6 needs a docs build first; it fails
    loudly, never skips, when the build is missing.

    server rendered and visible before the board; waiting only for the shell
    would run the synthetic guards on an empty page.
