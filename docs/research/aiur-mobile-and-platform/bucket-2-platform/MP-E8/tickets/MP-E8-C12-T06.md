# MP-E8-C12-T06 — Performance budget and measurement

> **Wave 0b, after cutover.** Product paths are cited at `58854d4c8` (runtime
> worktree `aiur-worktrees/runtime/src`). Paths marked PROPOSED do not exist yet;
> most of them are created by predecessor tickets and are cited by the name those
> ticket docs fix. `J` = `design-source/assets/build.js`, `C` =

> no saving** (AGENTS.md "A claimed saving must be measured", last paragraph).

## Identity and outcome

- Bucket 2, feature MP-E8 (continuous build history), chunk C12 (cutover,
  retirement, mobile, accessibility, performance, docs, sign-off), ticket T06.
- **User value.** The home page stays fast with 10,000 tickets on a desktop and on
  a phone WebView, and a later change that makes it slow fails a test instead of
  reaching Kevin's phone. The numbers the predecessor tickets deferred ("C12-T06
  measures it") are measured once, on one harness, and recorded.
- **Deliverables.**
  1. A deterministic **10,000-ticket synthetic dataset** and a **5,000-entry
     transcript**, generated in memory from the design's `dense` dataset (no new
     committed fixture file).
  2. A **gated client timing module** (PROPOSED `src/priv/static/build-home/perf.js`)
     that wraps ten synchronous hot functions in `performance.measure` (§7 lists
     them). It is off unless the tab sets `sessionStorage["bd-perf"] = "1"`.
  3. **Server measurements** in ExUnit: payload bytes (a CI gate) and assembly time
     and memory (`:perf_regression`, the repo's existing opt-in tag).
  4. **Client measurements** in Playwright on Chromium, desktop and phone emulation:
     an enforced CI subset and a full report mode (`npm run perf:build-home`).
     They include the measurements that predecessors deferred to this ticket by
     name: Gantt view (C9-T09), chain hover (C9-T11), column changes (C9-T04),
     feature-focus paging (C10-T03) and the Gruvbox fixed body wash on a phone
     (C2-T01).
  5. A **report writer** that writes the numbers, the budget and a verdict per
     metric to JSON and Markdown. An unmeasured metric is `unavailable` with a
     reason, never `0` or `pass`.
  6. A **device run** on the MP-N1 phone slots (iPhone A, Android phone A), and a
     **real-repository run** on the dogfood daemon, both recorded in the PR body.
  7. The **websocket compression decision** for `/live`, made by a written rule
     from the measured numbers.
  8. The **budget table** below, with the measured value next to each proposed
     budget in the PR body.
- **Non-goals.**
  - No optimisation in this PR. Each predecessor already names its upgrade behind a
    `ponytail:` comment (see "Upgrade register"). A budget that fails gets a
    follow-up ticket with the measured number. That follow-up claims the saving
    and meets the five AGENTS.md saving rules.
  - Websocket compression is not turned on in this PR, even when the rule says
    "turn it on" (that would be a saving claim; see Decision 3).
  - No visual change, no new user-facing surface, no config key, CLI flag or
    environment variable.
  - No accessibility work (C12-T05), no phone layout work (C12-T04).

### 4. Synthetic data (one generator, in memory)

PROPOSED `src/test/support/build_home/scale.ex`, module
`Aiur.TestSupport.BuildHome.Scale`. It is loaded with `Code.require_file` in
`test/test_helper.exs` and in `test/browser/fixture_server.exs`, in both files
**before** C3-T01's fixture source line (no `elixirc_paths` exist, see "Test
harness"), so it never ships in a release. Pure functions, no RNG, no clock:

```elixir
@offset 100_000   # > every base id; dataset/2 raises ArgumentError otherwise

@spec dataset(map(), pos_integer()) :: map()
# base = the v1 `dense` fixture map (payload form). Keeps now, plan and nq rows.
# Copy k (k = 1, 2, …) of every history row: start/end/created moved back by
# k * shift_days local calendar days in America/Los_Angeles, keeping the local
# wall time. shift_days = 7 * ceil(span_days / 7), span_days = first to last
# history day + 1 (83 for dense, so shift_days = 84): whole weeks keep the
# weekday, so the design's idle weekends stay idle.
# id = Integer.to_string(String.to_integer(id) + k * @offset) (numeric, so it
# passes Payload.validate/1); a dep is remapped the same way when it is a history
# row of the base, otherwise kept. Stops at exactly n rows in total.
@spec with_nq(map(), pos_integer()) :: map()
# replaces nq with m rows copied from the base nq rows the same way (id offset
# per copy, no time shift); every other section unchanged.
@spec with_active(map(), pos_integer()) :: map()
# sets agent.state "active" on the first m now rows; when now has fewer than m
# rows, appends copies of now rows (id offset 9 * @offset + i) until it has m.
@spec perf_ticket_id(map()) :: String.t()
# the id of the first row of the base `now` section (visible on first paint).
@spec conversation(map(), pos_integer()) :: [map()]
# base = the design conversation items of one dense ticket (C11-T03 export);
# repeats them with ids "s:<n>" and `at` shifted back 1 minute per repeat, to n items.
```

Shifting by whole local days (not by a fixed number of milliseconds) keeps every
row on the same local hour across a DST change. The design rows lie between
09:00 and 22:30 (J:142, 148, 169), so no row has an ambiguous or skipped local time.
The test is G3.

- `FixtureSource` (C3-T01) accepts four new dataset names in `datasets/0`:
  `scale10k` = `Scale.dataset(dense, 10_000)`; `nq300` = `Scale.with_nq(dense, 300)`;

### 7. Client timing module

PROPOSED `src/priv/static/build-home/perf.js` (about 20 lines):

```js
let on = false;
try { on = sessionStorage.getItem("bd-perf") === "1"; } catch { on = false; } // blocked storage → off
export const perfOn = () => on;
const mark = (n, t) => { try { performance.measure("bd:" + n, { start: t }); } catch { on = false; } }; // never breaks the wrapped call
export function timed(name, fn) {           // returns fn itself when off: zero cost, no buffer growth
  if (!on) return fn;
  return function (...a) { const t = performance.now(); try { return fn.apply(this, a); } finally { mark(name, t); } };
}
export function markFirstBoard() { if (on && !performance.getEntriesByName("bd:first-board").length) mark("first-board", 0); }
```

`timed` wraps **synchronous** functions only; an async function would be measured
only up to its first `await`. All ten below are synchronous in their owner tickets.

Wraps go on **the binding the callers use**, one line each:
- an `fx` entry is wrapped where it is registered, for example in `render.js`
  `Object.assign(fx, { viewport, relayout: timed("relayout", relayout), update:
  timed("update", update), … })`. This covers `relayout`, `update` (C9-T03),
  `drawEdges` (C9-T07), `applyCols` (C9-T04), `renderList` (C9-T12) and
  `chainOf` (C9-T11, already a closure in its `Object.assign`);
- a function that is imported directly or called inside its own module is
  wrapped once at its definition: `function applyDiffImpl(msg) {…}` and
  `export const applyDiff = timed("applyDiff", applyDiffImpl)`. This covers
  `applyDiff` and `mergeEarlier` (`store.js`, imported by `hook.js`), `buildMap`
  (`modal/live.js`, module-internal) and `prependEntries` (`modal/conversation.js`,
  measured as `bd:convPage`). The `const` line sits directly under the
  `import` lines, and no module calls these at top level (C9-T01 module rules), so
  there is no use before definition;
- `hook.js`: `markFirstBoard()` after the first `fx.relayout()` that follows an
  accepted snapshot (C9-T01's `renderAll()` on first intake).

A wrap that misses the live binding records nothing, and P2/P4 fail on the
missing name.

Why it is gated: User Timing entries have no buffer limit, so an always-on measure in
a tab that stays open for days grows memory without bound. Why `sessionStorage`: it
survives the reload a device inspector needs, and it stays in one tab. A URL
parameter would not: C3-T03's `writeURL` keeps unknown keys (J:316-328), so the
flag would spread into every shared link.

### 8. Report writer

PROPOSED `src/browser/scripts/build-home-perf-report.mjs` exports
`record(id, { value, unit } | { unavailable: reason })` and `write(dir)`. Output:
`build-home-perf.json` and `build-home-perf.md` in `process.env.AIUR_BROWSER_ARTIFACT_DIR`
(the runner passes it to the spec, `run-browser-tests.mjs:51`), or in `--out` for
the target script. It writes through `writeSanitizedDiagnostic`
(`artifact-sanitizer.mjs:104`) and prints the two paths. Each row
is `id, context (D|P|device slot|real), value, unit, budget, verdict`.

- `verdict` ∈ `pass | fail | unmeasured`.
- An unavailable metric is shown as `unavailable (<reason>)` with verdict
  `unmeasured`. Examples: no CDP outside Chromium, a device slot that is missing,
  and `perf.js` not loaded.
- A missing value is never written as `0`, as `—` or as the last run's value.
- Every row carries `observed_at` (ISO time) and `commit` (fixture runs:
  `git rev-parse HEAD` of the checkout; target run: `--commit` or `"unknown"`), so
  a report reused later shows its age.

## Decisions made without the owner

1. **Budgets are proposed by this writer** from the 2026-10-08 measurement and the
   predecessors' caps (§2). Kevin can tighten them at C12-T08. A measured miss is
   filed, never edited to pass.
2. **Only byte, count and ratio budgets gate CI.** Absolute times gate the report
   mode only. Reason: CI runners are shared and noisy, and the house performance
   spec already uses CI-variance headroom.
3. **Compression is decided, not shipped, here.** Turning it on reduces wire bytes
   for every LiveView page, which is a saving claim, and the row says this ticket
   claims none. The rule (§5) decides, and a "yes" goes to a follow-up that measures
   on the wire.
4. **The synthetic 10,000 set is the design's `dense` history replicated back in
   time,** not random data. It keeps the real per-day density (median 22, max 31),
   the edge shapes and the epics, and it needs no RNG or committed file.
5. **No committed 10,000-row fixture.** About 3.3 MB of JSON in git is not needed,
   because generation is pure and fast. `:persistent_term` keeps the generation out
   of the measured requests.
6. **Phone emulation is a CI proxy only.** EC-27 needs the device run. Missing
   devices or a missing app WebView are recorded and keep EC-27 open. They are not
   reported as passes.
7. **Instrumentation ships, gated by `sessionStorage`.** A device inspector can turn
   it on with one reload. It is off for every normal visitor, and when off it adds
   zero work, because `timed` returns the original function.
8. **The 594 KB icon is recorded, not changed.** It is a first-visit cost cached for
   a year (`static_assets.ex:28`). Changing a shared asset is outside this ticket.
   Metric C11 records it, and a follow-up is filed if the phone C1 budget fails on
   first visit.
9. **Static `gzip: false` stays.** C11 measures uncompressed bytes. Pre-compressed
   static files are in the register as an upgrade, not done here.
10. **The real-repository run is read-only and manual.** No test reads live state
    (AGENTS.md "Reading real state"). The run sends no write event, and B6 proves
    that against the fixture server. It is a separate Node script because the
    shared runner drops credentials and starts the fixture server (see "Test
    harness"); widening the runner's environment allowlist for credentials was
    rejected as a security change outside this ticket.
11. **Predecessor-deferred measurements are in scope.** C9-T04, C9-T09, C9-T11,
    C10-T03 and C2-T01 each say "C12-T06 measures"; the README row lists the core
    metrics only. Leaving them out would drop them silently, so C13-C17 record
    them, report-only, with no CI gate beyond B7.
12. **Synthetic history shifts by whole weeks (84 days for `dense`)** so weekdays
    and idle weekends are kept, and ids are offset by `k * 100_000` so they stay
    numeric.
