  agent chat).

  operator messages, pick-up lines, failed tool calls, and the session footer. A

## Chosen design

### The seam

```elixir
defmodule AiurWeb.Build.ConversationSource do   # PROPOSED src/lib/aiur_web/build/conversation_source.ex
  @type ref :: %{id: String.t(), identity: Aiur.TrackerIdentity.t() | nil,
                 running: map() | nil, closed?: boolean()}
  @type entry :: %{required(:id) => String.t(), required(:k) => String.t(),
                   required(:at) => integer() | nil, optional(atom()) => term()}
  @type view :: %{state: state(), entries: [entry()], before: String.t() | nil,
                  more?: boolean(), live?: boolean(), observed_at: DateTime.t() | nil,
                  reason: atom() | nil}
  @type state :: :live | :ended | :known_empty | :stale | :unavailable |
                 :restart_unknown | :not_retained

  @callback tail(ref(), after_cursor :: String.t() | nil, keyword()) :: {:ok, view()} | {:error, term()}
  @callback page(ref(), before_cursor :: String.t(), keyword()) :: {:ok, view()} | {:error, term()}
  @callback subscribe(ref(), keyword()) :: :ok | {:error, term()}
  @callback unsubscribe(ref(), keyword()) :: :ok

  def source, do: Application.get_env(:aiur, :build_conversation_source, AiurWeb.Build.ConversationSource.Wave0b)
  # call/3 exactly as AiurWeb.Build.DataSource.call/3 (C3-T01): it appends the
  # source opts as the LAST argument, so callers pass [ref, cursor] or [ref].
end
```

`tail(ref, nil, opts)` is the first view (the newest page). `tail(ref, cursor, opts)`
returns the entries written after `cursor` (live append). `page(ref, cursor, opts)`
returns the page before `cursor`. Page size `Keyword.get(opts, :limit, 100)`
entries; `opts` are the source opts from the config tuple, so tests set the
limit there. `ref` is built by BuildLive from the C11-T01 `ticket/2` row
(`id`, `identity`, `closed?` = the row's section is `hist`) and, inside the
adapter, the running entry (`running`) read from the snapshot.

### Where entries come from (wave 0b)

| Ticket | Transcript | State |
| --- | --- | --- |
| Running, local worker, `agent.ndjson` present | PageReader over the file | the projection state of the row's handle (`resolve/2`) |
| Running, local worker, file missing, projection has no messages | none | the projection state; `:known_empty` stays `:known_empty` (live agent only) |
| Running, local worker, file missing, projection has messages (the writer swallows write errors, `agent_event_log.ex:38-47`) | the projection's ≤ 80 messages, `more?: false`, `note: "live_window"` (top row "Only the latest messages are shown") | the projection state |
| Running, remote worker (`worker_host` set) | the projection's ≤ 80 messages, `more?: false` | the projection state; `truncated?`/`evicted_count` → top row "N earlier messages are not kept for remote workers" |
| Not running (includes `retrying` and `idle` entries), workspace dir exists, file present | PageReader | `:ended` |
| Not running, dir missing, or dir present and file missing | none | `:not_retained` |
| Not running, only legacy `agent.md` | `AgentLog.read_workspace/1` as one page, `more?: false` | `:ended`, top row "Older entries are in a legacy log and are not shown" |
| Handle unresolvable, or any source raises/exits | none from the projection | `:unavailable` (pattern of `call_conversation/3`); a present file is still read |
| `ref.identity` names a repository other than the configured one (the private `Layout.repo_segment/0` would point at the wrong folder) | none, nothing is read | `:unavailable`, reason `:other_repository` (never `:not_retained`: the transcript may exist elsewhere) |
| Snapshot read fails (`:snapshot_unpublished`, `:orchestrator_unavailable`, exit) | the file of the computed issue workspace, if present | `:unavailable`, reason `:running_unknown`, `live?: false` |

The running entry comes from `Orchestrator.dashboard_snapshot/2` through an
injectable Endpoint key `:build_conversation_snapshot_fun` (default
`&Aiur.Orchestrator.dashboard_snapshot/2` with a 2,000 ms timeout), wrapped
like `call_conversation/3`. It is the one
entry in `snapshot.running` whose `identifier` equals the ticket number,
refused when two match (the `issue_payload/3` rule). It is read on the first
view and on each `live_conversation_changed`/`restarted` message, not on the
1 s poll.

The file is the transcript of record: a superset of the projection for local
workers, holding every generation. So, unlike the drawer, a **new generation is
not "superseded"**: the adapter resubscribes and entries continue from the file.

### Entry mapping (design kinds; same data as the drawer or less)

The reader runs the existing parser per line (a public `@doc false`
`AgentLog.structured_entry/1` that wraps today's private `parse_structured_line/1`;
no behaviour change for `read_workspace/1`), then groups merge runs itself so
each entry knows its first line's byte offset.

| AgentLog message | Design item | Fields |
| --- | --- | --- |
| `role "assistant"` | `say` | `text` = body |
| `role "user"`, title `"Executor"` | `op` | `text` = body; rendered "You · HH:MM" |
| `role "user"`, title `"Issue prompt"` | `sys` | `text` = "Picked up by {model name} · {effort} effort" for the last prompt of the **first view** (a reader that pages cannot know a later page's prompts) when the row's model and effort are known; every other prompt "Picked up". The prompt body is **not** sent |
| `role "system"`, title `"Coordination event"` (`agent_log.ex:425-426`) | `sys` | `text` = "Coordination event" |
| `role "tool"`, title `"Command failed"` | `tool` | `name` "bash", `arg` = the text after `"$ "` up to the `"\nexit <n>"` line; a multi-line command keeps its first line plus " …"; `res` = "✗ exit N", `bad: true`; output not sent |
| `role "tool"`, title `"Command output"` (exit 0 with auth-failure output) | `tool` | as above, `res` = "✗ auth failure", `bad: true` |
| `role "alert"` | `sys` | `text` = "Alert · {name}" |
| `role "system"`, title `"Warning"` | `sys` | `text` = "Warning · {first line, ≤ 120 chars}" |
| other `role "system"` | `sys` | `text` = the title only; the raw-JSON body is **not** sent |
| projection `"agent"` / `"operator"` / `"tool"` (projection-window rows only) | `say` / `op` / `tool` | `at` = `occurred_at` in ms; `tool`: `name` = title, `arg` = first body line, `res` "" |
| — | `diff` | **no wave-0b source** (the parser drops file changes; the drawer shows none). Not rendered |

- `at` = `timestamp` parsed as ISO 8601 → Unix ms; anything else → `nil`.
- `id` = `"#{gen}:#{offset}"`: `gen` = `:erlang.phash2({major_device, inode,
  first_bytes})` as hex, where `first_bytes` = the file's first 256 bytes (one
  `pread`). The first bytes are needed because a reclone can reuse the inode;
  the first line (the first event) never changes for the life of a file. An
  empty file that gets its first line changes `gen` once; the client then
  re-renders from a `reset`, which loses nothing because nothing was shown.
  `offset` = byte offset of the entry's first line. Projection entries use the
  projection message `id`. A logged operator answer whose line carries the
  decision action id gets the id `answer:<action_id>` (C11-T08's client row id),
  so `appendEntries` replaces C11-T08's row in place.
- **Placeholders inside merge groups.** When the reader joins a merge group, a
  part whose body is exactly `"No content."` (the `blank_to_placeholder/1`
  value for an empty delta) counts as empty. A standalone entry keeps its body
  as the drawer shows it.
- Text fields are scrubbed to valid UTF-8 and capped at 8,000 characters with
  "…" (EC-30, payload size). They are data, never HTML (C3-T02 rule 1).

### PageReader (PROPOSED `src/lib/aiur/agent_log/page_reader.ex`)

```elixir
@spec tail(Path.t(), keyword()) :: {:ok, page} | {:error, :enoent | :reset | :invalid_cursor | term()}
@spec before(Path.t(), cursor, keyword()) :: {:ok, page} | {:error, …}
@spec since(Path.t(), cursor, keyword()) :: {:ok, page} | {:error, …}
# page :: %{entries: [map()], first: cursor | nil, last: cursor | nil, more?: boolean(), gen: String.t()}
```

- Opens the file `[:read, :binary, :raw]` and reads backwards in 64 KiB `pread`
  chunks (through `opts[:pread]`, default `&:file.pread/3`, so a test can count
  bytes) until it has `limit` entries or reaches byte 0. Budget per call: it
  starts no new line after 1 MiB has been read and returns what it has with
  `more?: true`. The line it is inside is always finished, so the hard bound
  is 1 MiB + one line.
- **Lines over 4 MiB.** While scanning for a line start, the reader keeps at
  most 4 MiB of the line. A longer line is not decoded: its bytes are dropped as
  they are scanned, and it becomes one `sys` entry "Entry too large to show".
  Memory stays ≤ 4 MiB + one chunk. Malformed lines are skipped
  (`Jsonl.decode_line/1`).
- **A page never starts inside a merge group.** If the earliest parsed message
  has a `merge_key`, it keeps reading earlier lines until the key changes, up to
  4 MiB more. A longer group is split at that point; its two parts get two ids
  (accepted: an agent message is far smaller in practice).
- `since/3` reads forward from the cursor to EOF (≤ 1 MiB per call; the caller
  calls again if `more?`). If the last entry is an open merge group, `last` points
  at its first line, so the next call resends it under the same `id` and the
  client replaces it in place.
- **Cursor validation**, in this order: a cursor that does not parse as
  `<hex>:<non-negative integer>` → `{:error, :invalid_cursor}`; `gen` differs
  from the file's current `gen`, or `offset > size` → `{:error, :reset}`
  (workspace recloned or truncated); `offset > 0` and the byte before `offset`
  is not `"\n"` → `{:error, :invalid_cursor}`. A cursor never selects a file:
  the path always comes from `ref`.
- The reader produces no placeholder text of its own (it never calls
  `AgentLog.read/1`). An empty file is `{:ok, %{entries: []}}`.

### Server flow in BuildLive

1. **First view.** The client's conversation body (registered with C11-T01's
   `registerBody("conversation")`, so it runs only when `t.agent && t.start !=
   null`, J:1377) sends `conversation-page {id, before: null}` with a reply
   callback. BuildLive reads the row through the DataSource `ticket/2`
   (C11-T01): `{:error, :not_found}` → `invalid_params`; a row with no `agent`
   or no `start` → `invalid_params` and **no source call** (doc view). If
   another conversation is pinned, it is closed first (unsubscribe, cancel the
   timer). Then `tail(ref, nil)`, `subscribe(ref)`, pin `conversation_ref`, and
   reply `kind: "conversation"`.
2. `handle_event("conversation-page", %{"id" => id} = p)`: `before` is
   `p["before"]`; absent and `nil` mean the same (C11-T05 sends no `before`).
   `before` must be a string or `nil`, else `invalid_params`. `before == nil`
   is the step-1 first view (also used by C11-T05 after a bottom trim). A
   string `before` requires `id == conversation_ref.id` (else
   `invalid_params`) and calls `page`. Reply `kind: "conversation-earlier"`.
   Errors: `:invalid_cursor` → `invalid_params`; `:reset` → a fresh
   `kind: "conversation"` reply with `reset: true`; any other source error →
   `unavailable`. A fallback clause replies `invalid_params` (C3-T02 rule).
   `handle_event("conversation-close", %{"id" => id})` with the pinned id →
   unsubscribe, cancel the timer, clear the assigns, reply `{v: 1, kind:
   "ok"}`; another id is ignored with the same reply (idempotent).
3. `{:live_conversation_changed, snapshot}` for the pinned handle and
   `{:live_conversation_restarted, _epoch, _now}` (3-tuple,
   `dashboard_live.ex:349`) → re-read the state and push
   `kind: "conversation-state"`. For a remote worker the changed snapshot's
   new messages go out as `kind: "conversation-append"`. A row whose handle
   changed → `unsubscribe` old, then `subscribe` new (this order, see
   `unsubscribe_handle/1` above), keep entries.
4. A 1,000 ms timer (`Process.send_after`) runs while a conversation is
   pinned on a local ticket whose file exists (running or not): `File.stat`; if
   `size` grew, `tail(ref, last)` and push `kind: "conversation-append"`; if
   `size` shrank below the last cursor offset or `gen` changed, push a fresh
   `kind: "conversation"` with `reset: true`. Cancelled on
   `conversation-close` and on a first view for another id; it dies with the
   LiveView process (no `terminate/2`), so a lost close is harmless. The poll
   exists because not every logged line changes the projection (failed
   commands, alerts); one stat per second is cheap.
5. Reading is allowed on a read-only dashboard (the drawer's read is not gated
   either, `dashboard_live.ex:568`). No write happens here.
6. **Composer for C11-T06.** On the first view of a running ticket, assign
   `conversation_composer = AgentLogModal.composer(entry, payload)` (or `nil`
   when not running). `composer/2` is `build/2` without `path` and `messages`;
   `build/2` becomes `composer/2` merged with `read_agent_log/1`'s result, so
   the drawer does not change and the modal never reads the whole log.
   `payload` is the real fleet payload from the same snapshot read (`%{fleet:
   snapshot}`, as the drawer passes it), never `nil`. Cleared with the other
   assigns on close. C11-T08 reads the pinned ticket id as `conversation_ref.id`.

### Messages (v1 envelope; added to `Payload.validate/1`)

```json
{ "v": 1, "kind": "conversation", "id": "123", "reset": false,
  "state": "live|ended|known_empty|stale|unavailable|restart_unknown|not_retained",
  "reason": null, "live": true, "observed_at": 1791431544512,
  "entries": [entry], "before": "3fa2c1:0", "more": false, "note": null }
{ "v": 1, "kind": "conversation-earlier", "id": "123", "entries": [entry], "before": "…", "more": true }
{ "v": 1, "kind": "conversation-append",  "id": "123", "entries": [entry], "gap": false }
{ "v": 1, "kind": "conversation-state",   "id": "123", "state": "stale", "live": false, "observed_at": 1791431600000 }
```

`entry` = `{id, k, at, text?, name?, arg?, res?, bad?}` for `say op sys tool`
and `{id, k: "ev", at, ev, label, sub?, go?, pct?}` (C11-T04; the fixture uses it
now). `k`, `ev` are enums; `at`, `pct` are integer or null; `bad` boolean. `note`
is one of `null | "legacy_log" | "remote_window" | "live_window"` with an integer `evicted`.
`gap: true` on an append means the projection window evicted entries between
two pushes (`evicted_count` grew); C11-T05 reads it. Entry `id` is the stable
key C11-T05 calls `key`, and the `data-eid` C11-T06 and C14-T01 use. The
`conversation` and `conversation-earlier` kinds are **replies** to
`conversation-page`; `conversation-append` and `conversation-state` are
`push_event(socket, "build-conversation", msg)`.
`live` = the projection is `:live` or `:known_empty` and the ticket is running;
C11-T05 shows typing only when `live` and the agent state is active and the
socket is connected.

## Non-happy paths

- **Absent, empty, huge (EC-16).** Absent for a past ticket → `:not_retained`
  (never an empty chat). Absent for a live agent → `:known_empty`. Empty file →
  zero entries with the state's footer. A 50 MB file → the first view reads
  ≤ 1 MiB + one line (≤ 4 MiB kept in memory).
- **Placeholders are not entries.** The reader never calls `read/1`; the legacy
  `agent.md` branch drops entries whose body is a placeholder string.
- **Untrusted text (EC-30).** Every string goes through `esc` (C9-T01 `dom.js`,
  with C3-T02's `'` addition). The sent data is a subset of the drawer's: no
  prompt bodies, raw system JSON, command output, paths or generation handle.
- **Path safety.** Non-numeric ids are rejected before any path is built; a
  workspace that escapes the root through a symlink is `:unavailable` with
  reason `:workspace_symlink_escape` (outside the root: `:workspace_outside_root`;
  the root itself: `:workspace_equals_root`), and nothing is read.
- **Wrong repository.** The workspace layout uses the configured repo, so a
  ticket of another repository is `:unavailable` / `:other_repository`, never
  "not retained" (which would claim the transcript is gone).
- **Cursor tampering / stale cursor.** Validated per request; never trusted to
  pick another file. A wrong-gen cursor after a reclone → `reset`.
- **Concurrency.** A backward read uses the size seen at open; later bytes come
  through `since/3`. No log lock is taken (whole lines only; a partial last line
  waits for the next poll).
- **Disconnect / reconnect.** The new LiveView has no pinned conversation. On
  C9-T01's `onReset` the module re-sends the first view for the open `MS.t` and
  re-renders from the reply (as a `reset`). Pushes or replies for another id or
  an old request counter are dropped. A string `before` that reaches an
  unpinned process gets `invalid_params`; the client re-sends the first view.
- **Snapshot unavailable.** If the snapshot read fails, the ticket is not known
  to be running: the file is still read if present, the state is
  `:unavailable` / `:running_unknown`, and no typing is shown (`live: false`).
- **Retrying or idle tickets** count as not running: file → `:ended`, no file →
  `:not_retained`. The 1 s poll still appends a re-dispatch's lines; the footer
  and typing switch to the new run only on reopen (wave-0b limitation).
- **Projection crash/restart.** `:restart_unknown` until the next snapshot; file
  entries still render.
- **Remote workers.** Only the projection window; the footer note says so.
- **Two tabs.** Each LiveView has its own cursor and timer; reads are idempotent.

## Decisions made without the owner

1. **The workspace file is the transcript of record;** the live projection gives
   only state and change signals (it is a bounded subset of the same events).
2. **A new generation of the same ticket continues the conversation** instead
   of the drawer's "superseded" state, because the modal is per ticket and the
   file holds every generation.
3. **Less data than the drawer, never more:** no prompt bodies, raw system JSON,
   command output or paths. Successful commands and file diffs are not shown in
   wave 0b.
4. **"You" for every Executor message** (the design's label), although an
   Executor agent may have sent it; the Executor is the operator of the run.
5. **Pick-up lines** name the model and effort only for the last pick-up in the
   first view, and only when the row knows them; all others say "Picked up".
6. **Only the issue workspace is searched** for past tickets (not `pr-<n>`
   workspaces); anything else is "not retained".
7. **Page size 100, read cap 1 MiB per call, line cap 4 MiB, text cap 8,000
   characters, poll 1 s.** Chosen to keep a page well under the C3-T02 budget;
   C12-T06 may tune them.
8. **The S-15 row and every new state row reuse `.cv-end` unchanged,** as
   DESIGN-E8 says "`.cv-end`-style". No new CSS.
9. **Unknown times are omitted with a "Time unknown" title** on `sys` and `op`,
   not replaced by `nowMs()`, so the AGENTS.md mutation (replace with a plausible
   value) fails the test. `ev` rows follow C11-T04 (`"—"`).
10. **Reading is allowed on read-only dashboards,** as the drawer allows it today.
11. **The conversation body asks for its own data** (`conversation-page` with
    `before: null`) and says when it closes (`conversation-close`), so paging,
    reset and reconnect use one path (C11-T01's `open-ticket` carries no
    conversation).
12. **The adapter reads the running entry from the published snapshot**
    instead of waiting for a C8 lookup that no C8 ticket provides.
13. **A ticket of another repository is "unavailable", not "not retained".**
    The workspace layout only knows the configured repository.
14. **Retrying and idle tickets count as not running;** the state footer moves
    to a new run only on reopen (wave-0b limitation).
15. **The S-6 cue goes through C11-T02's `opts.note`,** with a one-line fallback
    until C11-T02 lands, instead of C11-T02 calling a helper from this ticket.
16. **A placeholder "No content." part inside a merge group counts as empty;**
    a standalone "No content." body stays, as the drawer shows it.
