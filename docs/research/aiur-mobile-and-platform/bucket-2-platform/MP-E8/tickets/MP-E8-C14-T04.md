## Identity and outcome

- Bucket 2, feature MP-E8 (continuous build history), chunk C14 (later-wave
  upgrades). Plan §6 row "Command authority and supersede — MP-E2 — consumed in
  C14-T04".
- **User value.** The Command card in the ticket modal follows the same answer
  rules as every other human surface (contract
  [command-request-and-resolution.md](../../../contracts/command-request-and-resolution.md)
  §6, D11):

    `actor_source: :dashboard_session`, so it outranks any Executor, supervisor or

    from the card, with a confirmation.

    operator is sent to the composer for a follow-up message.

    `ConflictSummary`, not a guess.

     (MP-E2-C3-T02), not from the error text of today's `command_error/1`.

     (MP-E2-C3-T01).
  3. Two new card states, `replaceable` and `confirm`, plus a `too_late`
     settled kind. A `replace-decision` event calls
     `DecisionCommands.replace/4` (MP-E2-C3-T03) → `Answering.supersede/3`.
  4. A multi-question Command (MP-E2-C1-T01 `questions`) shows the existing
     "answer on the Commands page" fallback card, never a one-click answer.
- **Scope rule from the row: the card's look stays.** The open card is the same
  DOM, classes and pixels as in C11-T08. The new states use only the design's
  classes (`.cv-cmd`, `.row`, `.btn.sm`, `.btn.secondary.sm`, `.rec`) and
  C11-T08's S-42 state line.

  - No routing chip, requester line or escalation timeline on the card
    (DESIGN-E2 §4.1, §4.3). The design card has none, and "the card's look stays".
    `/commands` shows them (MP-E2-C7).
  - No custom response, rationale, defer, dismiss or "Send correction" (revise) on
    the card. `/commands` keeps them (C11-T08 non-goal 1; contract §6 rule 7).
  - No change to the store, the facade or the precedence guard. Those are
    MP-E2-C3-T01/T02.
  - No delivery receipts for the composer (C14-T02). No "Open in Conversations"

## Chosen design

### 1. The answer goes through the facade (reuse C3-T03)

After C3-T03, the card's existing `answer-decision` → `record_answer/4` path
already calls `Answering.answer/3`. This ticket adds no second path. It checks two
things in `DecisionCommands` and fixes them only if C3-T03 left them out:

- `actor_source: :dashboard_session` is passed on the answer and the supersede
  call (contract §6 table). The card shares `/commands`'s entry point, so it
  shares its source.
- The outcome map is kept: `update_state(socket, id, &Map.put(&1, :outcome, outcome))`
  next to `put_notice` / `put_error`, and `put_form/4` also deletes `:outcome`
  (no stale outcome from an earlier submit). This is one line each. `/commands`
  ignores the new key.

### 2. Read: the winner comes from the Decision, not the row

PROPOSED `DecisionCommands.answer_context/1`:

```elixir
@spec answer_context(String.t()) ::
        {:ok, %{winner: ConflictSummary.t() | nil, question_count: non_neg_integer()}}
        | {:unavailable, :not_found | :store_unavailable}
def answer_context(decision_id) do
  case DecisionStore.get(decision_id, decision_store()) do
    {:ok, decision} ->
      winner = if Decision.active_answer(decision), do: ConflictSummary.for(decision, actor())
      {:ok, %{winner: winner, question_count: length(Map.get(decision, :questions) || [])}}
    {:error, :not_found} -> {:unavailable, :not_found}
  end
catch
  :exit, _ -> {:unavailable, :store_unavailable}
end
```

- It lives in `DecisionCommands` because MP-E8-C3-T01's seam scan lets
  `lib/aiur_web/build/**` call `DecisionCommands` but not `DecisionStore`
  (C11-T08 "Seam").
- `actor()` is the caller, so `replaceable` uses the operator's rank (3) — never
  a "caller is human" boolean (contract §6 rule 1).
- `CommandCard.load/2` calls it at most once per load: for the `{:open, row}`
  row (for `question_count`), for the replaceable candidate below, or for the
  race-view row from `command_detail/1`. One extra GenServer call per modal load
  and per refresh tick while a modal is open. No new subscription or timer.

**Replaceable read.** `ticket_command/1` (C11-T08) reads only open rows, so a
decided Command never reaches the card on a fresh open. This ticket adds one
branch to `ticket_command/1`, taken **only when the open read is a complete,
empty page** (C11-T08's `:none` case; a partial or unreadable open read stays
`{:unavailable, _}` and no second read runs):

```elixir
# after the open read returned a complete empty page
params = %{"ticket" => identifier, "lifecycle" => "decided", "limit" => 100}

case DecisionProvider.list(params, decision_store: decision_store()) do
  {:ok, %{decisions: rows}} ->
    case pick_replaceable(rows) do
      nil -> :none
      row -> {:replaceable, row}
    end
  _ -> :none   # never Replace from an unknown state; C11-T08's :none rules apply
end
```

- PROPOSED `pick_replaceable/1`: rows whose `answer.actor.kind in [:executor,
  :supervisor]`, newest `answer.accepted_at` first; the first one. This is only
  a pre-filter on the presenter row. `CommandCard.load/2` then calls
  `answer_context/1` on that one row, and shows `replaceable` only when the
  `ConflictSummary` says `replaceable: true` and `actor_kind in [:executor,
  :supervisor]`; otherwise it shows **no card** (C11-T08: a fresh open never shows
  a settled card).
- `{:replaceable, row}` is shown **even on a fresh modal open**. A replaceable
  answer must be visible on open, or the D11 window cannot be used from this
  page.
- Ordering: open rows first (C11-T08's rule), then the newest replaceable row,
  then C11-T08's race-view settled rule (`command_detail/1`; a race-view row
  with a replaceable machine winner is shown as `replaceable` too).
- A decided row past the 100-row page is not looked for (`ponytail:` the cap is
  `params.ex:8`; more than 100 decided Commands on one ticket is out of scope,
  and `/commands` still offers Replace).

### 3. Card payload (additive to C11-T08)

```text
{ state: "open", …C11-T08 fields…,
  multi: false }                                   # true when question_count > 1
| { state: "replaceable",
    decision_id, version,
    question, options: [{ id, label, title, recommended }],
    winner_option_id: id | null,                   # null for a custom answer
    text: <who/when/what line>,                    # server-built, at_ms separate
    at_ms: int | null,
    writable, disabled_reason }
| { state: "settled", decision_id,
    kind: "answered" | "too_late" | "expired" | "dismissed" | "moot",
    option_id, text, at_ms }
| { state: "unavailable", … }                      # C11-T08, unchanged
```

**Who-line builder** (server, `CommandCard`, from `ConflictSummary`). Drafts
until DESIGN-E2 §4.4 is final:

| `actor_kind` / `actor_source` | Who |
| --- | --- |
| `:executor` | "the Executor" |
| `:supervisor` | "the supervisor" |
| `:operator_relayed` | "the Executor, relaying you" |
| `:operator` + `:dashboard_session` or `:basic_auth` | "you" |
| `:operator` + `:streamdeck` | "you on the Stream Deck" |
| `:operator` + `:device` | "you on another device" |
| `:operator` + `:rpc`, no source, or any other source | "operator (unverified: no surface)" (contract §6) |
| any other kind | "another responder" (never "you") |

Line: `Answered by <who> at <HH:MM>: '<summary>'`. With `accepted_at` nil the
` at <HH:MM>` part is left out; with `summary` nil the `: '<summary>'` part is
left out. The server sends `at_ms`; the client formats local `HH:MM`, as
C11-T08 does. `summary` is untrusted text (C3-T01 caps a custom answer at 120
chars) and is escaped on the client.

### 4. Outcome → reply mapping (`CommandCard.reply/2`)

`reply/2` reads `decision_actions[id].outcome` (§1). The text comes from C3-T03's
`outcome_notice/1` where one exists, so the card and `/commands` say the same
thing.

| Outcome | Reply | Card after the reply |
| --- | --- | --- |
| `:accepted`, `:duplicate` | `accepted`, `text: "Answered: <label>"`, `at_ms`, `action_id` | card removed; `cv-op` row appended (C11-T08) |
| `:already_answered`, `winner.replaceable` and machine winner | `replaceable` + the payload | buttons enabled, winner badge `answered`, who-line |
| `:already_answered`, otherwise | `settled`, `kind: "answered"` | buttons disabled, who-line |
| `:too_late` | `settled`, `kind: "too_late"` | buttons disabled; text "Already delivered. Send a follow-up message instead." (`:answer_delivered`) or "It is being delivered now and can no longer be replaced." (`:answer_in_flight`); focus to `#cv-in textarea` if present |
| `:withdrawn` | `settled`; `:expired` → `expired`, `:dismissed` → `dismissed`, `:moot` → `moot`; `:resolved` → `answered`, built from the reloaded row (C11-T08 builds `decided \| acknowledged \| resolved` as answered) | C11-T08 texts; buttons disabled |
| `:stale` | `error`, "This Command changed. Refresh to see the latest." | reload re-renders at `current_version`; key dropped by `put_error/3` (`decision_commands.ex:296-302`), so the next submit gets a fresh key |
| `:not_allowed` (any reason) | `error`, "This answer is not allowed from this page. Answer it on the Commands page." (placeholder until DESIGN-E2) | buttons disabled; card stays. Not reachable for a direct operator today (C3-T02: `:human_answer` / `:direct_operator_answer` are kept only for a future relay caller); the row exists so the shape is never mapped to `accepted` |
| `:error`, missing outcome, or any unknown shape | `error`, "The answer was not confirmed. The card was refreshed." | buttons re-enabled after reload |

The last row is the AGENTS.md unknown-path rule: an outcome the card does not know
is never `accepted`, and it never removes the card.

### 5. Replace (D11) on the card

- **Shown only when** `state == "replaceable"`: the winner is `:executor` or
  `:supervisor`, not delivered, not in flight, and `replaceable` is true. Never for
  an operator or relayed winner (C3-T03 shows Replace for executor only; this
  card also covers `:supervisor`, rank 1, because the row says "supervisor or
  human authority" — see Interface notes, item 3). Never when `writable` is false.
- **Arm.** A click on a non-winning option sets the card to a client-only
  `confirm` view: the clicked button gets `aria-pressed="true"`; the other option
  buttons are disabled; the state line shows the DESIGN-E2 copy
  "Replace the Executor's answer? It has not reached #<ticket> yet." (or "the
  supervisor's"); a second `.row` holds
  `<button class="btn sm" type="button" data-act="replace">Replace</button>` and
  `<button class="btn secondary sm" type="button" data-act="cancel">Cancel</button>`.
  Focus moves to Replace. Escape or Cancel returns to `replaceable`; Escape is
  caught by a `keydown` listener on `#bd-cmd` that calls `stopPropagation()`
  **only while the confirm view is showing**, so it does not reach C11-T01's
  `document` Escape listener (C11-T01 "Close triggers": it does not stop
  propagation itself). Outside the confirm view Escape closes the modal as
  before.
  A click on the winning option does nothing (it is already the answer).
- **Confirm.** Replace sets `disabled` on every button and `aria-busy="true"`,
  then `pushEvent("replace-decision", {decision_id, answer: {choice: "option:" + id}}, onReply)`.
- **Server.** PROPOSED BuildLive clause, beside C11-T08's `answer-decision` ones:

  ```elixir
  def handle_event("replace-decision", %{"decision_id" => id, "answer" => %{"choice" => "option:" <> _} = form}, socket) do
    if socket.assigns.writable and dashboard_writable?() do
      socket = DecisionCommands.replace(socket, id, form, &CommandCard.reload/1)
      {:reply, CommandCard.reply(socket, id), socket}
    else
      {:reply, %{status: "error", message: "This dashboard is read-only."}, assign(socket, :writable, false)}
    end
  end

  def handle_event("replace-decision", _params, socket),
    do: {:reply, %{status: "error", message: "The submitted answer was incomplete. Try again."}, socket}
  ```

  `CommandCard.load/2` assigns the `{:replaceable, row}` row as
  `selected_decision`, so `DecisionCommands.replace/4` finds it (Interface notes,
  item 2). The idempotency key, `expected_version` and the outcome mapping are
  `replace/4`'s.
- **Success** (`:accepted`) is the same as an answer: card removed, `cv-op` row
  "Answered: <label>" appended. The orchestrator delivers only the newest answer
  (`decision_store.ex:271-274`).

### 6. Multi-question Commands

`question_count > 1` → the card shows the question and C11-T08's zero-option
fallback (`<a class="btn secondary sm" href="/commands">Open Commands</a>`) with
the state line "This Command has several questions. Answer it on the Commands
page." One button cannot answer every question, and a partial answer is not
delivered (DESIGN-E2 §4.2; MP-E2-C3-T02 `{:question_answers, :incomplete}`).
`question_count` 0 or 1 keeps the one-click card.

**Server guard (trust boundary).** MP-E2-C3-T02 validates a `question_answers`
payload, but it does not say that a v1 `choice` answer against a Decision with
several `questions` is refused. So the card does not rely on it: the
`answer-decision` and `replace-decision` clauses check the `command_card` assign
first, and when its `decision_id` is the submitted id and `multi: true`, they
reply `%{status: "error", message: "Answer this Command on the Commands page."}`
and write nothing. Interface notes, item 7, asks C3-T02 to refuse it in the facade
too.

### Invariants

- The client sends only a decision id, an option id and the event name. The actor,
  `actor_source`, version and key are set on the server.
- Replace is never offered from an unknown state: `answer_context` unavailable,
  `winner` nil, or `replaceable` false → no Replace.
- An unknown actor is never shown as "you"; an unknown time is never shown as now.
- The open card's DOM and classes are byte-identical to C11-T08's.

## Decisions made without the owner

1. **Reuse C3-T03's rewiring** of `record_answer/4` and its `replace/4` instead of
   calling `Answering` from `CommandCard`. One answer path for `/commands` and the
   card.
2. **Replace is offered only for a machine winner** (`:executor`, `:supervisor`),
   never for an operator or relayed answer, even where the rank rule would allow
   it. Replacing another human's answer belongs on `/commands`, where the full
   history is visible.
3. **A replaceable answer shows a card on a fresh modal open,** not only while a
   card is already open. Without it the D11 window is unreachable from this page.
4. **Confirmation is an in-card Replace/Cancel row** using the design's `.btn sm`
   and `.btn secondary sm`, not a browser `confirm()` dialog (WebView and
   accessibility) and not a second click on the same button (a double click would
   confirm by accident).
5. **Too late sends the operator to the composer** (focus to `#cv-in textarea`).
   No link to the conversation page; C14-T03 owns that button.
6. **Delivered time is not shown** in the too-late text: `ConflictSummary` has a
   `delivered?` flag, not a time. "at 10:20" from DESIGN-E2's draft is left out
   rather than invented.
7. **Multi-question Commands go to `/commands`.** One click cannot answer several
   questions, and a partial answer is never delivered.
8. **No routing chip or requester line on the card.** The row says the card's
   look stays; `/commands` shows routing.
9. **Who-line copy is a placeholder** mapped from `actor_kind` and
   `actor_source`; DESIGN-E2 §4.4's approved strings replace it. An `:operator`
   answer with any source outside `:dashboard_session | :basic_auth |
   :streamdeck | :device` is shown as unverified, never as "you".
10. **The multi-question refusal lives on the card's server clauses** as well as
    being requested from the facade, because the card is a trust boundary and the
    facade's behaviour for that case is not specified.
11. **Replaceable read is pre-filtered on the presenter row, confirmed by
    `ConflictSummary`.** One list read plus one `get` per load, instead of one
    `get` per decided row; the pre-filter alone never shows Replace.
