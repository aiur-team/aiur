## 4. Chosen design

### 4.1 Port `renderTools` and split it in two

`tools.js` ports J:1128–1150 with three changes and no change to the markup
except the pixel-neutral attributes in 4.4.

1. **The demo parts are removed.** `off` (J:1129) and the select (J:1142,
   J:1149) are gone. The chip comes from `daemonView()`.
2. **Two render units.** `renderTools()` = `renderControls()` + `renderStatus()`.
   - `renderControls()` writes `#bd-tools-l` and `#bd-tools` only when its key
     `S.view + "|" + S.span + "|" + spanKey` changed since the last write
     (`spanKey` = `fx.spanToolsHTML()`'s output, so C9-T10's disabled ends
     still update). Reason: `renderChrome()` calls `fx.renderTools()` on every
     diff with a `set` key. The design rewrites `innerHTML` each time, which in
     the product would destroy the focused button every few seconds and drop
     keyboard focus (EC-19). The same markup is written, so pixels do not
     change.
   - `renderStatus()` always rewrites `#bd-status`. It has no focusable element.
3. **Listeners are delegated and bound once per mount.** In the design, the
   handlers are added again after each `innerHTML` write (J:1143–1149). Here
   `tools.js` binds one `click` and one `keydown` listener on the stable host
   `#bd-tools-l` through `ctx.life.on` (C9-T01 rule 4). C9-T01's `resetState`
   runs the `onReset` callbacks **before** `shell()` (C9-T01 `mounted`), so the
   binding is done by the first `renderTools()` after a reset, guarded by a
   `bound` flag that `onReset` clears. The handler finds the button with
   `e.target.closest("[data-v]")`. `tools.js` binds nothing on `#bd-tools`:
   the Live click is C9-T08's delegated listener and the span clicks are
   C9-T10's `wireSpanTools`.

```js
// tools.js (PROPOSED), sketch
import { S, ctx, fx, onReset } from "./state.js"
import { $, esc } from "./dom.js"
import { writeURL } from "./url.js"
import { I } from "./icons.js"

const VIEWS = [["graph", "graph", "Timeline"], ["gantt", "gantt", "Gantt"], ["list", "list", "List"]]
let lastKey = null, bound = false
onReset(() => { lastKey = null; bound = false })

function viewButton([v, ic, l]) {
  const on = S.view === v
  return '<button type="button" data-v="' + v + '" class="' + (on ? "on" : "") + '" title="' + l + '"' +
    ' role="tab" aria-selected="' + on + '" aria-label="' + l + '" tabindex="' + (on ? "0" : "-1") + '">' +
    I[ic] + "<span>" + l + "</span></button>"
}

function renderControls() {
  const span = S.view === "list" ? "" : fx.spanToolsHTML()
  const key = S.view + "|" + S.span + "|" + span
  if (key === lastKey) return
  const fv = document.activeElement?.closest?.("#bd-tools-l [data-v]")?.dataset.v   // the focused tab, if any
  lastKey = key
  $("#bd-tools-l").innerHTML = '<div class="bd-seg vw" role="tablist" aria-label="View">' + VIEWS.map(viewButton).join("") + "</div>"
  $("#bd-tools").innerHTML = '<button class="bd-live" type="button" id="bd-nowbtn" title="Jump to live"><i></i>Live</button>' + span
  if (span) fx.wireSpanTools($("#bd-tools"))
  if (fv) $('#bd-tools-l [data-v="' + fv + '"]').focus()   // same tab, not always the selected one
}

export function renderStatus() {
  const d = fx.daemonView()
  const key = S.view === "list" ? "" :
    '<span class="bd-key"><span class="bd-leg"><span class="bd-leg-l"></span>Cleared</span>' +
    '<span class="bd-leg"><span class="bd-leg-l d"></span>Pending</span>' +
    (S.view === "gantt" ? '<span class="bd-leg"><span class="bd-leg-h"></span>Planned estimate</span>' : "") + "</span>"
  $("#bd-status").innerHTML = '<span class="bd-daemon' + (d.dotOff ? " off" : "") + '"><i></i>' + esc(d.dotText) + "</span>" + key
}

export function renderTools() { bindOnce(); renderControls(); renderStatus() }

export function setView(v) {
  if (S.view === v) return            // J:1143 guard
  S.view = v; writeURL(); renderTools()
  if (S.loading) return               // as C9-T10 setSpan (its 4.3): keep the skeleton or the "unavailable" text
  fx.viewport(); fx.relayout(); fx.jumpNow(true)
}

Object.assign(fx, { renderTools, renderStatus, setView })
```

`bindOnce()` binds the two delegated listeners on `#bd-tools-l` described above
when `bound` is false, then sets it. The click on `[data-v]` calls
`setView(btn.dataset.v)`. The `keydown` handler is in 4.4.

**During loading** (`S.loading`, before the first snapshot) `setView` stops
after the toolbar, the key and the URL. The design's order
(`viewport(); relayout()`) would run `renderLoading()` (J:639, J:1249–1253) and
put the spinner back over C9-T01/C9-T13's "Build timeline unavailable · …"
text. This is the same rule C9-T10 uses for `setSpan` (its 4.3). The first
snapshot's `firstPaint()` → `renderAll` → `viewport()` reads the new `S.view`,
so the board still opens in the chosen view.

### 4.2 The daemon chip

The chip is `fx.daemonView().dotText` and `.dotOff`, nothing else. C8-T03
defines five rows (first match wins); this ticket renders whatever comes back:

| `daemonView()` (C8-T03 table) | Chip |
| --- | --- |
| `linkDown` (socket down for more than 500 ms) | "Daemon unreachable", `.off` |
| `daemon.state === "offline"` | "Daemon offline", `.off` (the design's only off string) |
| `daemon.state === "stale"` | "Daemon stale", `.off` |
| `daemon.state === "live"` | "Daemon live" (the design's only on string) |
| `"unknown"`, any other value, or no daemon block (before the first snapshot) | "Daemon status unknown", `.off` |

Two rules make the chip honest:

1. **No default "live".** The `state.js` default for `fx.daemonView` is
   `() => ({ dotOff: true, dotText: "Daemon status unknown" })` (step 2), never
   the design's `"Daemon live"`. `tools.js` has no second fallback of its own.
2. **The chip follows the link, not only server messages.** A socket drop sends
   no message, so `renderChrome()` does not run. C8-T03's `offline.js` already
   calls `fx.renderStatus()` when `linkDown` changes (C8-T03 "Re-render", B15).
   This ticket's part is to register a real `fx.renderStatus`. Without it, the
   `fx` default is a no-op and the banner says "Daemon unreachable" while the
   chip still says "Daemon live".

The chip has no live region. C8-T03 gives the banner `role="status"`, and one
announcement per change is enough (Decision 5).

### 4.3 Span and zoom: an interface, not a port

J:1136–1137 renders the Day/Week/Month and zoom groups inside `#bd-tools`.
They belong to C9-T10 (`span.js`: `setSpan`, `calNear`, `CALI`). C9-T10 lists
this ticket in its `blocked_by`, so it merges after this ticket, and until then
`#bd-tools` holds only the Live button. The contract (C9-T10 4.4 uses the same
names):

- `fx.spanToolsHTML()` returns the J:1136–1137 markup for the current `S`
  (`""` before C9-T10 lands).
- `fx.wireSpanTools(host)` binds the `[data-z]` and `[data-span]` clicks
  (J:1146–1147) through `ctx.life` (no-op before C9-T10 lands).
- `setSpan` (J:1229–1232) calls `fx.renderTools()`, as the design calls
  `renderTools()`.

Both entries get a no-op default in C9-T01's `fx` table (`state.js`):
`spanToolsHTML: () => ""`, `wireSpanTools() {}`. This ticket adds them (it
merges first). Because the markup string is part of `renderControls()`'s key,
a change of span re-renders the host.

`wireSpanTools` is called after each host write. C9-T10 agreed to one delegated
listener on the stable `#bd-tools`, idempotent per host (C9-T10 4.4), so
rewrites do not stack listeners in `ctx.life`.

### 4.4 Accessibility without a pixel change

The design marks the segment `role="tablist"` but its children are plain
buttons. axe reports this as `aria-required-children` (a tablist must own
`tab` elements), and C12-T05 runs axe on every fixture. The text label is
`display: none` (C:713), so the accessible name is only the `title`.

This ticket completes the tabs pattern with attributes only:

- each button: `role="tab"`, `aria-selected="true|false"`, `aria-label="<l>"`,
  roving `tabindex` (`0` on the selected tab, `-1` on the others);
- `keydown` on `#bd-tools-l`: `ArrowRight`/`ArrowLeft` move focus to the
  next/previous tab (wrapping), `Home`/`End` to the first/last. Focus moves
  only; **Enter or Space activates** (manual activation, native button click).
  Reason: a view switch rebuilds the viewport, so automatic activation on every
  arrow press would rebuild it two or three times on the way to List.
- when the host is rewritten while a tab has focus (after an activation by
  keyboard, or a span change), focus is put back on the tab with the same
  `data-v` (`fv` in 4.1). After Enter that is the new selected tab; after an
  arrow move it is the tab the user moved to, not the selected one.

There is no `aria-controls`/`tabpanel` pairing: `#bd-vp` is C9-T01's element and
its role is not changed here (Decision 4). None of these attributes is matched
by a selector in C, so computed style is unchanged. C2-T04's computed-style
snapshot proves it.

The Live button has visible text "Live", so it needs no label. Its `<i>` is
empty and gets no attribute.

### 4.5 Back and forward (interface fix in `url.js`)

C9-T01's `onServerURL({ state })` applies the server state, then calls
`renderChrome(); fx.relayout(); fx.update()` and `fx.jumpNow(true)` when `span`
changed. A change of `view` also needs `fx.viewport()` (the lane label switches
between "Order" and "Time", J:607) and `fx.jumpNow(true)` (J:1143). Without them,
Back from `?view=gantt` to `/build` keeps the "Time" label and the Gantt
`content`.

This ticket changes `onServerURL` in place, with no call into `tools.js`:

```js
// url.js onServerURL (C9-T01), edited
const prevView = S.view, prevSpan = S.span
fromServer(state)
renderChrome()                                         // redraws the tabs and the key
if (S.view !== prevView && !S.loading) fx.viewport()   // new: lane label and content (J:604–607)
fx.relayout(); fx.update()
if (S.span !== prevSpan || S.view !== prevView) fx.jumpNow(true)   // view part is new (J:1143)
```

It never calls `writeURL()` (no echo, C3-T03). It does not depend on
`tools.js`, so a rollback of `tools.js` does not break Back and Forward. The
`!S.loading` guard keeps the skeleton (4.1). This is a small edit to C9-T01's
file; it is listed in 9 so C9-T01's owner knows.
