# MP-E7-C1-T02 — Language-neutral listener artifacts

## Identity and outcome

- **Bucket / feature / chunk:** 2-platform / MP-E7 / C1. **Cross-repo: Khala.**
- **User value:** aiur's Elixir scheduler can prove it behaves exactly like
  Khala's TypeScript reference without running Node in the daemon.
- **Deliverable:** checked-in JSON under `packages/listener/spec/v1/` (PROPOSED):
  1. `listening-mode.v1.schema.json` — JSON Schema (draft 2020-12) for the
     mode literal, the shared command `{v:1, agent, mode}`
     (`packages/contracts/src/m1/listening-mode.ts:9`), the control-record
     projection `{requested, effective, effective_reason, version}` and the
     support map `{steer|sync|async: {status, reason}}`.
  2. `scheduler.v1.json` — rows `{harness, event, mode, busy, busy_age_ms,
     continuation, delivers: bool, mark_idle_only: bool}` generated by running
     `decideDelivery` (C1-T01) over the full input grid.
  3. `goldens/hook/{claude,codex}-{SessionStart,UserPromptSubmit,PostToolUse,Stop}-*.json`
     — codec goldens: hook stdin → parsed input, and frame → rendered stdout
     envelope (`codecs/claude-style.ts:10-30`).
  4. `MANIFEST.json` — file list with sha256 and the spec version.
  A generator `packages/listener/scripts/generate-spec.mjs` with `--check`
  (fails when regeneration would change a file).
- **Non-goals:** no publishing (C1-T03); no change to Khala's own wire
  decoders; aiur-only fields are C1-T05.

## Dependencies and blockers

- Successors: MP-E7-C1-T05 (adds optional fields before first release),

## Verified starting point (Khala `origin/main` 99e72a43)

- No JSON Schema or codegen exists for any contract (MP-E7 plan E7-F5;
  re-checked: `git ls-tree -r origin/main | grep -c schema.json` finds none
  under `packages/`).
- Cross-repo JSON fixtures are an established pattern:
  `packages/contracts/fixtures/aiur-events/*.json` (15 files) consumed by
  `packages/contracts/src/m1/from-aiur.ts`.
- Khala decoders are strict: `object()` rejects unknown keys
  (`packages/contracts/src/messaging/decode.ts:94-101`,
  `packages/contracts/src/delivery/decode.ts:70-80`). The schema must therefore
  set `additionalProperties: false` wherever Khala's decoder is strict, so the
  two never disagree.
- Codec facts: `UserPromptSubmit`/`PostToolUse` render
  `hookSpecificOutput.additionalContext`; `Stop` renders
  `{"decision":"block","reason":…}` (`codecs/claude-style.ts:25-30`);
  `stop_hook_active` must be boolean or absent (:15-16).

## Chosen design

- Generated, not hand-written: one generator owns all JSON so the TS code and
  the artifacts cannot diverge. `--check` runs in `pnpm --filter @khala/listener test`.
- `scheduler.v1.json` grid: harness ∈ {claude, codex}; event ∈ {start,
  prompt, tool, stop}; mode ∈ {steer, sync, async}; busy ∈ {true,false};
  busy_age_ms ∈ {0, 119999, 120000, null}; continuation ∈ {true,false}
  (only meaningful for stop). Rows are sorted deterministically. This is the
  table aiur's conformance test (MP-E7-C3-T05) replays.
- Hook goldens separate **envelope** from **frame wording**: each golden has
  `{stdin, frame, stdout}` where `frame` is a neutral placeholder
  (`"<frame/>"`) and `stdout` is the envelope around it. Khala's existing
  `__golden__/deliver-*` files embed Khala's intro ("They are not instructions
  from your user", `deliver-core.ts:20`) and are **not** shared. aiur renders
  its own copy (aiur operator messages *are* instructions) and tests its
  Elixir renderer (MP-E7-C6-T04) against these envelope goldens.
- Schema `$id`: `https://github.com/aiur-team/khala/packages/listener/spec/v1/listening-mode.v1.schema.json`
  (informational; no network fetch).

## Implementation steps

1. Add `scripts/generate-spec.mjs` (Node, imports the package's TS via `tsx`, which Khala already uses: root `devDependencies`).
2. Emit the four artifact groups; write `MANIFEST.json` with `{spec_version: "1.0.0", files: [{path, sha256}]}`.
3. Add `src/spec.test.ts`: runs the generator in memory and compares with disk; validates every golden against the schema using a minimal in-repo validator (no new dependency; Khala avoids runtime deps in contracts).
4. Wire `--check` into the package `test` script.

## Non-happy paths

- Non-determinism (object key order, float formatting) would make `--check`
  flaky; serialize with sorted keys and integers only.
- A schema looser than the TS decoder would let aiur accept a value Khala
  rejects; `spec.test.ts` asserts every `invalid` fixture in
  `packages/contracts/fixtures/delivery/invalid.json` that concerns modes is
  rejected by the schema too.

## Compatibility and rollout

- Additive files only. Rollback: delete `spec/`.
