# MP-E6-C13-T09 — /talk docs and end-to-end verification

Plan: [../plan.md](../plan.md) §19.9. Requirements: all; acceptance examples AE1–AE4 (AE5 is aiur-side and closes in C14-T06).

## Identity and outcome

- **User value:** a new user can install and use `/talk` from one page; the team has proof that AE1–AE4 work on real agents.
- **Deliverable:**
  - Package guide `packages/elixir/voice_converse/guides/talk.md` and a website page `website/docs-app/guide/talk.md` (linked from the guide sidebar) with: install per agent, the option table (what each needs, price hint, privacy row per provider), `.env` instructions, SSH port-forward note (`ssh -N -L localhost:PORT:localhost:PORT`, research §4), troubleshooting (mic blocked, wrong port, Firefox has browser speech recognition off by default → text mode with OS dictation, research §2), and a privacy row for browser speech-to-text (audio can go to the browser vendor).
  - An e2e script `scripts/talk-e2e.sh` (fake provider, no keys) that runs `talk install-skill` into a temp HOME, `talk doctor --json`, `talk serve`, a headless Chromium session in text mode, one propose and one confirm, `talk inbox wait`, `talk inbox reply <id> --applied`, a check that the page shows "applied", and `talk stop`. It reads the binary path from `TALK_BIN`.
  - A manual verification record in the PR for AE1–AE4 with real keys (operator run; cost under USD 2).
- **Non-goals:** aiur dashboard docs (C9-T01).

## Acceptance criteria

- [ ] `scripts/talk-e2e.sh` passes in CI with the fake provider.
- [ ] The docs list every option id from C14-T01 (doc test compares lists).
- [ ] The docs show a privacy row for every option id (same doc test).
- [ ] `talk-e2e.sh` checks that no `inbox wait` record exists before the confirm (V5, end to end).
- [ ] AE1–AE4 recorded as passed, with time to first audio for each live voice option tried (time to first text for `text_only`), total spend under USD 2.

## Verification

```bash
bash scripts/talk-e2e.sh
python3 scripts/check-talk-docs.py   # option ids in docs == registry
```

**Mutation check.** Remove one option from the docs table: the doc test fails.

## Plan pass (2026-10-10)

**Key decisions**

- The doc test takes the option ids from `talk doctor --json` with an empty environment, not from Elixir source. Reason: doctor lists every option, also unsupported ones (SD6), and it calls the C14-T01 registry. So the list has one source and the script does not parse Elixir.
- `scripts/talk-e2e.sh` uses `TALK_BIN`. CI points it at the release that the C13-T03 job builds. Reason: the npm path needs a published package, and CI must not depend on a publish.
- The CI browser step runs in text mode with the FakeProvider and reuses the Playwright Chromium install in `src/browser`. Reason: text mode needs no microphone. The voice path in the browser is already covered by the C13-T04 browser tests.
- The website page goes in `website/docs-app/guide/talk.md`, next to `quick-start.md`. Reason: that is the existing guide section. The package guide is the source text, and the website page is a copy with site links.
- AE5 is not in this ticket. Reason: AE5 is aiur config behaviour, and C14-T06 already tests the AE5 shape.

**Risks**

- The docs drift from the registry when an adapter adds an option → the doc test fails on any difference in ids or a missing privacy cell. It runs in CI.
- The e2e script hangs on a stuck `inbox wait` or a server that does not stop → every step has a timeout, and a `trap` runs `talk stop` and kills child processes on exit.
- The manual run spends more than USD 2 → set the session cap of plan §17.6 to USD 0.75 per live run, and keep each run under 3 minutes.
- The Claude Code socket line format is undocumented (C13-T06) → the AE3 record says which path delivered the draft: socket push or file inbox.
- Model ids in the docs go stale → the docs name the option id and say "adapter default", and show model ids only with a date.

**Test strategy**

- Unit with fakes: none new. C13-T01..T08 and C14 own the unit tests.
- Doc test: `python3 scripts/check-talk-docs.py` compares the option ids and privacy rows in both docs with `talk doctor --json`. Mutation guard: remove one option row from the docs table, and the test fails. Also add a fake id to the docs, and the test fails.
- Integration: `bash scripts/talk-e2e.sh` in CI, FakeProvider, no keys, no network. Regression guard: the script checks that `inbox wait --timeout 0` exits 2 before the confirm. If delivery happens on propose, the script fails.
- Manual with real keys (operator, cap USD 2 total): AE1 with `ANTHROPIC_API_KEY` only (cascade, Claude Code); AE2 with `OPENAI_API_KEY` (openai_live, Codex, native `thread/fork`); AE3 on Claude Code (socket push) and on Codex (`codex queue`); AE4 text mode with OS dictation, and a check that the browser asks for no mic permission. Record the time to first audio or text, the cost estimate from the page, and the agent and option versions in the PR.
