# MP-E6-C13-T01 — talk host CLI and secure local launch

Plan: [../plan.md](../plan.md) §19.2, §19.5. Requirements: [../talk/requirements.md](../talk/requirements.md) R8, R23. Research: [../talk/research.md](../talk/research.md) §4.

## Identity and outcome

- **User value:** the agent starts the voice page with one command and gives the user one link that only this user's browser on this machine can open.
- **Deliverable:** the standalone host of C11-T03 becomes an executable `talk` with verbs:
  - `talk serve [--port P] [--project DIR] [--open]` binds `127.0.0.1` only (never `0.0.0.0`; `--host` is not offered). Preferred fixed port 47821 (mic permission is stored per origin, port included, so a stable port avoids a new mic prompt each launch); next free port if taken. Prints one line of JSON `{url, port, pid, state_dir}` and the URL.
  - Link `http://127.0.0.1:<port>/?code=<one-time 128-bit code>`. The first GET exchanges the code for an `HttpOnly; SameSite=Strict; Path=/` cookie and redirects to `/` without the code. The code is single-use and expires after 10 minutes.
  - Every HTTP request and the WebSocket upgrade check: `Host` in `{127.0.0.1:<port>, localhost:<port>}`; `Origin` equal to the page origin on the upgrade and on state-changing requests; valid cookie. No CORS headers. `Referrer-Policy: no-referrer`, a strict CSP, `X-Frame-Options: DENY`.
  - `talk status [--json]`, `talk stop` via a state file in `<project>/.talk/` (pid, port, started_at; mode 0600). One host per project directory.
  - `talk url` prints a fresh one-time link for the running host (the agent can resend it).
- **Non-goals:** remote access, TLS, LAN binding (users forward with `ssh -L` at their own choice; the README says how).

## Acceptance criteria

- [ ] The listening socket is bound to 127.0.0.1 only (test reads the bound address).
- [ ] A request with `Host: evil.example` gets 403 (DNS-rebinding guard).
- [ ] A WebSocket upgrade with a foreign `Origin` gets 403.
- [ ] A reused or expired code gets 401 and no cookie.
- [ ] `talk stop` ends the host and removes the state file; a stale state file (dead pid) is replaced on `serve`.
- [ ] The secret code never appears in the host's own logs.
- [ ] Every response carries `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` and the CSP, and no `Access-Control-*` header. A state-changing POST with a foreign `Origin` gets 403.
- [ ] The WebSocket upgrade authenticates with the cookie only. The `?token=` query path of the C11-T02 transport is off in the talk host.
- [ ] When port 47821 is in use, `serve` takes the next free port and prints it. The state file has mode 0600.
- [ ] `talk url` gives a new code that works once; the earlier codes stay single-use.

## Plan pass (2026-10-10)

**Key decisions**

- The talk host modules go in `lib/voice_converse/talk/` of the core package. They compile only when `bandit` is present, as the WebSock transport does (plan §17.2). Reason: the test path `test/voice_converse/talk` and the `mix release talk` of C13-T03 are in the core project, and consumers that do not load Bandit must not get it. The example host of C11-T03 becomes a thin wrapper over these modules, so its tests and the C13-T04 browser tests continue to run.
- The cookie is the only credential after the first GET. The talk host turns off the `?token=` query path of the C11-T02 transport. Reason: a token in the query string leaks to history, logs and the Referer header (research §4.1).
- The cookie name includes the port (`talk_<port>`), and the value is a new 128-bit random value, not the code. Reason: browsers scope cookies by host, not by port, so two talk hosts on 127.0.0.1 would overwrite each other's cookie.
- The CLI verbs `status`, `url` and `stop` reach the running host through a Unix domain socket `<project>/.talk/control.sock` (mode 0600). Reason: a browser cannot reach a Unix socket, and the new code for `talk url` exists only in host memory. ThousandIsland accepts a `{:local, path}` address.
- `serve` treats a state file as stale when the pid is dead or the control socket does not answer. Reason: a live pid can be a reused pid that belongs to a different process.
- `Origin` and `Host` accept both `127.0.0.1:<port>` and `localhost:<port>`, but the `Origin` host must agree with the `Host` header. The printed link always uses `127.0.0.1`. Reason: `localhost` can resolve to `::1` first, and the host binds IPv4 only.

**Risks**

- The code leaks through a crash report or a Bandit error log that prints the full conn or the query string → the log test captures all levels, including a forced handler crash, and the host's redactor removes `code=` values. Plug.Logger logs `request_path` only, which helps.
- `ssh -L` with a different local port changes the `Host` header, and the host returns 403 → the README tells users to use the same port on both ends (`-L 47821:127.0.0.1:47821`).
- A CSP that is too strict blocks the C13-T04 page (inline script, `blob:` audio, `ws:` connect) → the CSP is one constant in the host, and the C13-T04 browser test loads the page with this CSP.
- The Unix control socket does not work on Windows → v1 targets macOS and Linux (requirements scope). A Windows build, if added, needs a loopback control endpoint with a secret from the state file.
- Tests that bind port 47821 conflict with each other or with a real `talk` on the host → tests pass `--port 0` or a free test port, and one test takes 47821 first to prove the fallback.

**Test strategy**

- Unit tests with fakes (FakeProvider, file-backed ports): code issue, exchange, expiry (injected clock), single use; Host, Origin and cookie checks as a Plug pipeline; header set; state file write, mode, stale detection; CLI argument parsing and the JSON line.
- Integration tests on a real Bandit listener on a test port: bound address `{127,0,0,1}`; raw HTTP with `Host: evil.example` gets 403; WebSocket upgrade with a foreign `Origin` gets 403; upgrade with `?token=` and no cookie gets 401; `serve`, `url`, `status`, `stop` through the control socket; log capture has no code.
- Browser check: none in this ticket. C13-T04 covers the page under this CSP.
- Manual: none with real keys. This ticket starts no provider. One manual run of `talk serve --open` on the developer machine confirms one mic prompt across two launches on the stable port (cost USD 0).
- Regression guard: the rebinding test (`Host: evil.example` gets 403). Mutation checks: remove the Host allowlist and the rebinding test fails; accept the query token on the upgrade and the "query token refused" test fails.

**Open points**
