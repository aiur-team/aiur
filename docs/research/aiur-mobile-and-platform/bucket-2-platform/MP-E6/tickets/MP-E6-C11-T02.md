# MP-E6-C11-T02 — Session API, wire codec, WebSock transport

Plan: [../plan.md](../plan.md) §17.5; contract voice-session §3.3 (converse frames).

## Identity and outcome

- **User value:** any host can connect a browser or a device to a voice session without
  Phoenix or aiur. aiur's `/voice` channel and the standalone socket use the same frames.
- **Deliverable:**
  - `VoiceConverse.Wire.encode/1`, `decode/1` for the voice-session §3.3 converse frames
    (client → server: start, audio, text, confirm_draft, discard_draft, end; server → client:
    state, transcript, agent_text, agent_audio, interrupted, draft, delivery, context_gap,
    error, ended). Golden-frame fixtures in `test/fixtures/wire/`.
  - `VoiceConverse.Transport.WebSock` (compiled only when `websock_adapter` is present):
    binds `127.0.0.1` by default, requires `Authorization: Bearer <Config.transport_token>`
    (or a `?token=` query parameter for the browser, compared in constant time). It sends
    `confirm_draft` with `origin: :client`. Frame cap: 400,000 bytes, as `/voice`
    (voice-session §3.6).
  - `priv/static/voice_converse_client.js` (no build step, ES module): mic capture with
    `echoCancellation: true`, 16 kHz PCM, playback queue that stops on `interrupted`, draft
    cards with Confirm/Discard. `getUserMedia` runs only after a click.
- **Non-goals:** aiur's channel (C7-T01, which adopts the codec); a CLI audio client (E6-OQ17).

## Non-happy paths

- Bad or missing token → close 4401, no session started.
- A frame over the cap → `error{frame_too_large}`; the session stays open.
- Client disconnect → the session ends with `transport_lost` after a 10 s grace (same as voice-session §6).
