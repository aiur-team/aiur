# MP-E6-C12-T04 — Executor skill and docs

Plan: [../plan.md](../plan.md) §18.3, §18.4.

## Identity and outcome

- **User value:** the Executor knows what to do with a voice proposal, and the operator knows
  how to start a voice conversation with the Executor.
- **Deliverable:**
  - `.claude/skills/aiur-run/references/executor.md`: a wake record `executor.voice.proposal`
    is an operator request that has been confirmed but is not yet authorized for privileged
    actions. Apply it with the Executor's normal rules (review, merge policy) or decline with
    a reason, and always answer with `aiur executor-voice-reply`. `executor.voice.ask`:
    answer with `--answer`.
  - Operator docs (with C9-T01): Converse on the Executor panel; what the fork can and cannot
    do; that proposals land at the next wake.
- **Non-goals:** code changes beyond the skill and docs.

## Acceptance criteria

- [ ] The skill names both record types, the reply verb and the rule "the fork never acts;
      the live Executor applies or declines".
- [ ] Manual: an Executor session receives a proposal from a real voice session, applies it
      and replies; the operator hears the receipt. Evidence in the PR.

## Verification

Docs check (`scripts/check-docs-links.py` or the repo docs lint) and the manual run above.
