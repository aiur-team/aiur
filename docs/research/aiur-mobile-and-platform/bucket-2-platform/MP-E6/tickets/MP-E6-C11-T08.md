# MP-E6-C11-T08 — Core `Briefing.render/2`, `diff/2`, staleness

Plan: [../plan.md](../plan.md) §17.4 ("Generic Briefing"), §19.10 (dependency re-cut).

## Identity and outcome

- **User value:** the assistant answers from a compact, current briefing in both aiur and `/talk`. Moving the generic part here lets `/talk` ship without the aiur status-card work (C10-T01/T02, which wait on MP-R2).
- **Deliverable:** the `%VoiceConverse.Briefing{}` struct and its `field` shape exactly as plan §17.4 gives them, then `VoiceConverse.Briefing.render/2` (≤ 1,500 tokens; drop order extra → links → `next_steps` beyond 3; never drops `current_task`, `waiting_on`, `questions`), `diff/2` (changed lines only, for one non-interrupting context update), staleness rendering ("(as of 12 min ago)" past `max_age_s`), and `from_markdown/1,2` (the fixed headings that `talk brief` uses, C13-T06; the optional second argument gives `observed_at`). Tests in the package.
- **Non-goals:** aiur fields (C10-T02 keeps them).

## Acceptance criteria

- [ ] A briefing over budget drops fields in the stated order and keeps the three protected fields.
- [ ] `diff/2` of equal briefings is empty; a changed `waiting_on` yields one line.
- [ ] A field past `max_age_s` renders with its age.
- [ ] `from_markdown/1` maps the five headings; a missing heading becomes a `gaps` entry.
- [ ] When the protected fields alone exceed the budget, `render/2` keeps them whole and reports `over_budget: true`. It never cuts them silently.
- [ ] `diff/2` of two briefings that differ only in `observed_at` or `version` is empty.
- [ ] A field with `max_age_s: nil` never renders an age.

## Plan pass (2026-10-10)

**Key decisions**

- `render/2` takes `opts` with `budget` (default 1,500, from `Config.limits.briefing_token_budget`) and `now`. It returns `{text, %{tokens, dropped, over_budget}}`. Reason: an injected clock makes the staleness tests deterministic, and the metadata lets C4-T03 log what was dropped.
- The token estimate is `div(byte_size(text), 4)`, the same rule as C4-T03. Reason: no tokenizer dependency, and the two budgets stay comparable.
- Drop order is extra, then links, then `next_steps` items 4 and later. `summary` and the three protected fields are never dropped. If the result is still over budget, `render/2` keeps the text whole and sets `over_budget: true`. Reason: a silent cut of `questions` hides an operator question, which is worse than a large block. ContextBuilder (C4-T03) owns the total budget.
- `diff/2` compares rendered field values, not structs. It ignores `version` and `observed_at`. It gives one line per changed field, and "<Field>: none now" for a field that became empty. Reason: a periodic refresh with the same content must not send a `contextual_update`.
- `from_markdown/1,2` matches the five headings (Summary, Doing now, Next, Waiting on, Questions for you) without case and at any heading level. List items become `next_steps` and `questions` entries. An unknown heading goes to `extra`, so it is dropped first. A missing heading adds a `gaps` entry and is not an error. Reason: C13-T06 and C11-T03 call this one parser and must not reject a partial briefing.
- `render/2` does not redact. Reason: ContextBuilder applies the redactor hook once, before the provider and the store (plan §17.3).

**Risks**

- A fixed character-based estimate under-counts dense text (code, URLs). Mitigation: the 1,500 budget is a target. C4-T03 keeps a margin in the 4,000 start budget.
- An age string in each render changes the text every minute and can look like a change. Mitigation: `diff/2` ignores age text; only `render/2` shows it.
- Agents write headings with small variations ("Waiting for", "Questions"). Mitigation: keep an explicit alias table in one place, with a test per alias. Do not use fuzzy matching.
- C10-T02 and C11-T03 could add their own parsers or renderers. Mitigation: both tickets already name C11-T08 as the only owner; review rejects a second copy.

**Test strategy**

- Unit tests only, in `test/voice_converse/briefing_test.exs`, with plain struct fixtures and a fixed `now`. No fakes, no network, no provider, no keys, cost zero.
- Property test (StreamData if the core already has it, else a generated table of 200 cases): for random field sizes, the three protected fields are always present in the output, and `over_budget` is true exactly when the estimate exceeds the budget.
- Example tests: drop order step by step; equal briefings give `[]`; one changed `waiting_on` gives one line; `observed_at`-only change gives `[]`; a 15-minute-old field with `max_age_s: 120` shows "as of 15 min ago"; `max_age_s: nil` shows no age; `from_markdown` with all five headings, with one missing (one gap), and with an unknown heading (goes to `extra`).
- No integration or browser test here. C11-T03 and C13-T06 cover the file path end to end.
- Regression and mutation guards: (1) drop `questions` first, and the protected-field property fails; (2) make `diff/2` compare `observed_at`, and the refresh test fails; (3) the package CI grep `\bAiur(Web)?\.` on `lib/` must stay empty.

**Open points**

- None that block. The heading alias list is the implementer's choice; C13-T08 (skill text) must use the five canonical headings.
