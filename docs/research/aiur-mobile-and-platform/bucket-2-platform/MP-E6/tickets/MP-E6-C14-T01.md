# MP-E6-C14-T01 — Provider registry and preference resolution

Plan: [../plan.md](../plan.md) §19.3, §20. Requirements: [../talk/requirements.md](../talk/requirements.md) R3, R4, R6, R7, R20, R21.

Kevin, 2026-10-10 (verbatim): "just to flag, i originally said i only wanted air convo to support eleven, this means full support for native model convo wrappers to use model APIs in aiur too and .config settings to choose preferences".

## Identity and outcome

- **User value:** one place decides which conversation option a session uses. The same code tells `/talk` what to show the user and tells aiur why Converse picked a provider.
- **Deliverable (core, no aiur reference):**
  - `VoiceConverse.Providers` registry. Each adapter module declares `descriptor/0`: `%{id, family: :speech_to_speech | :hosted_agent | :cascade | :agent_native, label, modes: [:voice | :text], needs: [credential ids], parts: %{stt, llm, tts} (cascade only), client_parts: [:browser_stt, :browser_tts, :text_in], privacy: %{audio_stored_by_provider: …, deletable?: …}, price_hint}`. For `cascade` and `text_only`, `needs` is computed from `Config.providers.cascade` (the `llm` vendor plus any server `stt`/`tts` part), not fixed in the descriptor.
  - Option ids (v1): `openai_live`, `openai_realtime`, `gemini_live`, `elevenlabs_agents`, `cascade` (with parts), `text_only` (cascade with `stt: :text_in`, `tts: :none` or `:browser_tts`), and the experimental agent-native family `codex_realtime` (C14-T07; status `unsupported` unless the Codex CLI reports the feature).
  - Family `:agent_native` is added for options where the agent CLI itself runs the voice conversation (research §6).
  - `Config.providers`: `preference: [option_id]`, `mode: :voice | :text`, `cascade: %{stt: [..], llm: "<vendor>:<model>", tts: [..]}`, `on_missing_credential: :next | :text_only | :refuse` (default `:next`).
  - `VoiceConverse.options(config) :: [%{id, status: :ready | :needs_credential | :unsupported, missing: [..], reason}]` using `Credentials.fetch(provider, :probe)` (presence only, no network). This ticket adds the purpose `:probe` to `VoiceConverse.Ports.Credentials` (plan §17.4 lists only `:connect | :provision | :delete`): a `:probe` call returns `{:ok, :present} | {:error, :missing}` and never the secret. `Testing.StaticCredentials` implements it.
  - Default `preference` when the host gives none: `[elevenlabs_agents, openai_live, gemini_live, cascade]` (plan §20.2). `codex_realtime` is never in the default.
  - `VoiceConverse.resolve(config) :: {:ok, option, skipped: [{id, reason}]} | {:error, :no_usable_option, [..]}`.
- **Non-goals:** any adapter; any network key check (that is `talk doctor --check`, C13-T02).

## Acceptance criteria

- [ ] With preference `[openai_live, elevenlabs_agents, cascade]` and only an ElevenLabs key, `resolve/1` returns `elevenlabs_agents` and lists `openai_live` as skipped with `missing_credential: openai`.
- [ ] `on_missing_credential: :refuse` returns `{:error, :no_usable_option, …}` when the first option lacks its key.
- [ ] `mode: :text` resolves to a text-capable option and never to `openai_live`/`gemini_live` unless they declare text mode.
- [ ] `options/1` lists every registered option, including unsupported ones, with a reason.
- [ ] No secret value appears in any returned term (test inspects the terms).
- [ ] `on_missing_credential: :text_only` with no usable option in the preference resolves to `text_only` when its model key is present, and returns `{:error, :no_usable_option, …}` when it is not.
- [ ] An unknown option id in `preference` is skipped with reason `:unknown_option`. It does not raise.
- [ ] `cascade` with `llm: "anthropic:…"` needs `:anthropic`; with `tts: [:elevenlabs_tts]` it also needs the `:elevenlabs` credential (part ids are `elevenlabs_tts`, `elevenlabs_stt`, `openai_tts`, `openai_stt`, `browser_stt`, `browser_tts`, `text_in`, `none`, as in C14-T05/T06; credential ids stay vendor names). With only browser parts it needs only the model key.
- [ ] `codex_realtime` and any id whose adapter module is not loaded show `status: :unsupported` with a reason. `resolve/1` skips them.
- [ ] `options/1` and `resolve/1` never call `Credentials.fetch/2` with a purpose other than `:probe` (fake port records the calls).

## Plan pass (2026-10-10)

**Key decisions**

- The registry is a fixed list of `{option_id, module, fallback descriptor}` in `VoiceConverse.Providers`. Reason: no adapter exists when this ticket lands (non-goal), but `options/1` must list every v1 option. If the module is not loaded, the option is `unsupported` with reason `:adapter_missing`. When the adapter lands, its `descriptor/0` replaces the fallback.
- `options/1` and `resolve/1` are pure functions of `Config` and the `Credentials` port. Reason: `talk doctor`, `talk serve`, `aiur voice setup` and the aiur capability reason (C13-T02, C3-T02, C14-T06) must agree. They agree only if they call one function with the same inputs.
- Credential presence uses a new `:probe` purpose that returns `{:ok, :present}`, not the secret. Reason: plan §17.4 says a secret is fetched only at the moment of use. A probe that returned the value would put keys into option terms and logs.
- Credential ids are atoms (`:openai`, `:gemini`, `:elevenlabs`, `:anthropic`). `Providers.credential_env/1` maps each one to its usual variable name (`OPENAI_API_KEY`, …). Reason: R5 and C13-T02 must name the exact variable. The host can override the map, because aiur reads keys from MP-R5, not the environment.
- `codex_realtime` availability comes from a host-supplied feature fact in `Config` (set by C14-T07 from `codex features list`). Reason: the core runs no process and makes no network call in `options/1`. Without the fact, the option is `unsupported`.
- `mode: :text` filters by the descriptor `modes` field, not by family. Reason: the AC says speech-to-speech options are excluded "unless they declare text mode". Only a declared field can carry that.

**Risks**

- Two sources of option facts (fallback descriptor and adapter `descriptor/0`) drift apart → a test asserts that, for each loaded adapter, `id`, `family` and `needs` match the fallback entry.
- Cascade `needs` depends on config, so a bad `llm` string (`"foo"`) gives a wrong status → validate `"<vendor>:<model>"` in `Config` and fail with the field name (the C11-T01 rule).
- A secret leaks through a `reason` string or a skipped tuple → reasons carry only atoms and variable names. The "never a secret" test plants a sentinel value in `StaticCredentials` and searches `inspect/1` of every returned term.
- The default preference in the core and in aiur (C14-T06) drift → C14-T06 reads the core default (`Providers.default_preference/0`). It does not copy the list.

**Test strategy**

- Unit tests only, in `packages/elixir/voice_converse/test/voice_converse/providers_test.exs`. They use `Testing.StaticCredentials` (with call recording) and small fake adapter modules declared in the test, so no real adapter is needed. There is no network, no browser and no real key. Cost: zero.
- Table test over key sets: none, Anthropic only (AE1), OpenAI only (AE2), ElevenLabs only (AE5 shape), all keys. For each, check `options/1` status per option and the `resolve/1` result for each `on_missing_credential` policy and each `mode`.
- Integration happens downstream: C13-T02 (`doctor --json`) and C14-T06 (aiur capability reason) call these functions. No manual run with real keys is needed for this ticket.
- Regression and mutation guards: (1) make `resolve/1` ignore `:needs_credential` → "falls through to the next option on a missing key" fails. (2) Make `options/1` call `fetch(_, :connect)` → "probe is the only credential purpose" fails. (3) Remove the `modes` filter → "text mode excludes speech-only providers" fails.

**Open points**

- The `price_hint` text for each option (a static string such as "about USD 0.05/min") goes stale when providers change prices. The implementer takes the values from research §1 with the date. Kevin decides later if a price table needs a refresh process.

Changed in plan pass: (1) added `:agent_native` to the family type and a `modes` field to the descriptor, because the deliverable named `:agent_native` and the text-mode AC needs a declared text mode; (2) defined the `:probe` purpose, because plan §17.4 has no such purpose and `fetch` returns the secret; (3) cascade `needs` now come from config; (4) set the default preference from plan §20.2; (5) added five acceptance criteria and five verification rows (`:text_only` policy, unknown id, cascade needs, unloaded adapter, probe-only fetch). `blocked_by: [MP-E6-C2-T01]` is correct: C2-T01 adds `descriptor/0` to the behaviour, and C11-T01 (Config, Credentials port) comes before C2-T01.
