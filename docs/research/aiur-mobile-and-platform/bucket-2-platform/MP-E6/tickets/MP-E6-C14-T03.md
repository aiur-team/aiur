# MP-E6-C14-T03 — Gemini Live adapter

Plan: [../plan.md](../plan.md) §20. Research: [../talk/research.md](../talk/research.md) §1, [../realtime-convo-research.md](../realtime-convo-research.md) §3.4.

## Identity and outcome

- **User value:** a user with only a Gemini API key gets a native speech-to-speech conversation.
- **Deliverable:** `VoiceConverse.Provider.GeminiLive` (option id `gemini_live`): server-side WebSocket to the Live API with the key from `Credentials.fetch(:gemini, :connect)`; model from config (default `gemini-3.8-live`, research §1.2); input and output transcription on; function tools with `NON_BLOCKING` behaviour; a late tool result goes back as a function response with `scheduling: WHEN_IDLE`; an `announce/3` with no pending call id is queued until the server reports the turn complete and is then sent as a client text turn; session resumption and context-window compression so a 20-minute session survives the documented connection limit; event mapping incl. `AgentTextTiming` from output transcription; `descriptor/0`.
- **Non-goals:** Vertex AI auth (API key only in v1; Vertex is a later option).

## Acceptance criteria

- [ ] Passes `ProviderConformance` with documented-frame fixtures.
- [ ] A forced server `goAway` / connection end resumes with the stored resumption handle and no lost transcript record.
- [ ] A late tool result is spoken at the next pause, not as an interruption (fixture).
- [ ] Key never logged or kept in state.
- [ ] The setup frame turns on `contextWindowCompression` and `sessionResumption` (fixture inspects the frame).
- [ ] `AgentAudio` events declare the 24 kHz output rate; no adapter-side resampling.
- [ ] `descriptor/0` states `deletable?: false` (no delete API for Live sessions) and the provider data-use note; the adapter enables no provider-side storage.
- [ ] Manual (operator, at review, cost under USD 1): one 2-minute live session; record time to first audio.

## Plan pass (2026-10-10)

**Key decisions**

- Split the adapter in two parts: a pure frame codec (`GeminiLive.Frames`: encode setup, audio, text, function responses; decode server messages to `VoiceConverse.Events`) and a connection process with an injectable transport. Reason: most tests then run on plain data with no socket.
- Send the key in the `x-goog-api-key` header, not in the `?key=` query. Call `Credentials.fetch(:gemini, :connect)` again for each reconnect and drop the value after the upgrade. Reason: URLs appear in logs and crash reports; the key must not stay in state.
- Use two paths for late speech. A tool result for a pending call id goes as a function response with `scheduling: WHEN_IDLE`. An `announce/3` with no pending call id waits for `turnComplete` and goes as a client text turn. Reason: a function response needs a call id; the C2-T01 amendment mapping covers only the tool-result case.
- On `goAway`, reconnect at once with the last handle that the server marked `resumable: true`. Do not wait for the socket to close. Buffer microphone audio during the reconnect (cap 2 s, then drop and emit one `Error` event of kind `:degraded`). Reason: the handle is not resumable during generation or a pending call, so only the last resumable handle is safe.
- Declare `text_only?: false` in v1. Reason: the native-audio Live model answers in audio; text-mode users resolve to `cascade` with a Gemini text model (C14-T01 rule).
- Map `send_context/2` to `clientContent` with `turnComplete: false`. Reason: it adds context and does not start a model turn.

**Risks**

- Gemini output is 24 kHz PCM; the C2-T01 `audio_out` type lists only `:pcm_16000 | :pcm_44100`. → Add `:pcm_24000` to the type (see Open points); the page reads the rate from the event (C13-T04).
- A pending NON_BLOCKING call can be lost across a resume. → If the resumed session rejects the call id, send the result as a client text turn and record that in the transcript.
- Output transcription may arrive in large chunks or late (research §1.2: incremental streaming UNVERIFIED). → `AgentTextTiming` uses `from_text_deltas/2` with `estimated: true`; the page reveals at arrival when no audio duration is known.
- Forum reports give 9 to 26 s first audio on an older Live model (realtime-convo-research §3.4). → The manual run records time to first audio. If the median is over 3 s, the descriptor `price_hint` gets a latency note and the default preference (C14-T06) keeps `gemini_live` after `openai_live`.
- Free-tier Gemini API content can be used by Google to improve its products (Gemini API terms; check the text at build time). → The descriptor carries this note, and `talk doctor` (C13-T02) shows it next to the option.

**Test strategy**

- Unit, with fakes: codec round trips on documented-frame fixtures (setup, `serverContent` with `interrupted`, `inputTranscription`, `outputTranscription`, `toolCall`, `toolCallCancellation`, `goAway`, `sessionResumptionUpdate`, `generationComplete`, `turnComplete`); `ProviderConformance` (speech-to-speech family) through the fake transport; resume after `goAway`; WHEN_IDLE scheduling; queued announce; key absence (inspect state, capture logs with a sentinel key value).
- Integration: one test against a loopback WebSocket server in the test process (scripted server frames, forced close after `goAway`). It checks the real upgrade headers and that the key is in the header, not the URL.
- Manual (operator, at review): one 2-minute session on `gemini-3.8-live` with a real key. Cost cap USD 1, expected about USD 0.10 (audio in USD 0.005/min, out USD 0.018/min, plus context rebilling). Hard stop at 3 minutes. Record time to first audio and save redacted frames as fixture updates.
- Regression guards (mutation checks): drop the resumption handle on reconnect → the resume test fails. Remove the `scheduling` field → the WHEN_IDLE test fails. Put the key in the URL → the integration header test fails.

**Open points**

- C2-T01 must widen `audio_out` to include `:pcm_24000` (C14-T02 needs it too for OpenAI). Decides: the C2-T01 implementer; the Executor adds it to CONTRACT-REQUESTS.md.

Changed in plan pass: the deliverable now maps `announce/3` without a pending call id to a queued client text turn (a function response needs a call id); added acceptance criteria for compression and resumption in the setup frame, the 24 kHz output rate, and the privacy descriptor (plan §17.11, §20.1). `blocked_by` is correct and unchanged.
