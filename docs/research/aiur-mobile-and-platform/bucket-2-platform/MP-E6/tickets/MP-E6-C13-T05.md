# MP-E6-C13-T05 — Assistant text timing

Plan: [../plan.md](../plan.md) §19.5. Requirement R11. Research: [../talk/research.md](../talk/research.md) §1.6.

## Identity and outcome

- **User value:** the assistant's words appear in step with its voice, whatever provider speaks.
- **Deliverable:**
  - `VoiceConverse.Events.AgentTextTiming{turn_id, text, chars: [{offset_ms, length}] | nil, audio_offset_ms, estimated}`: chunk text plus optional per-character (or per-word) start offsets relative to the turn's first audio sample. `length` counts Unicode grapheme clusters (Elixir `String.graphemes/1`, browser `Intl.Segmenter`). `estimated` is a boolean (`false` for provider timing).
  - Helpers that adapters call: `from_char_alignment/3` (ElevenLabs-style character arrays), `from_word_timestamps/2`, `from_text_deltas/2` (no timing: offsets estimated from audio duration of the matching chunk, flagged `estimated: true`).
  - Server → client wire frame `agent_text_timing{turn_id, text, chars?, audio_offset_ms, estimated}` in `VoiceConverse.Wire` and in `contracts/voice-session.md` §3.4 (daemon → client), plus the normalized event `agent_text_timing` in §4.1. The transcript store records only the final text (timings are not stored).
  - Client → server: the existing §3.3 `playback_state` frame gains optional `turn_id` and `played_until_ms` (`{state: "stopped", turn_id, played_until_ms}`). No new client frame.
  - Truncation rule on `Interruption`: the session waits for `playback_state{stopped}` for that turn (grace 2 s), then writes the §9 record `assistant_turn{turn_id, text: <heard prefix>, interrupted?: true}`. The heard prefix is the graphemes whose start offset is below `played_until_ms`. Without timings, or when the frame does not arrive in the grace, the session writes all text received so far with `interrupted?: true` (OpenAI truncation semantics generalized).
  - Optional provider callback `truncate(ref, turn_id, played_until_ms)` in `VoiceConverse.Provider`. The session calls it after the interruption when the adapter declares `manual_truncation: true` (C14-T02 maps it to OpenAI Realtime `conversation.item.truncate`).
- **Non-goals:** the page rendering (C13-T04).

## Acceptance criteria

- [ ] Each helper produces monotonic offsets and a total length equal to the text length (property test).
- [ ] `played_until_ms` truncation records the heard prefix in the transcript.
- [ ] The wire codec round-trips the frame (encode → decode equality).
- [ ] The wire codec round-trips `playback_state` with and without `played_until_ms` (old frames still decode).
- [ ] No transcript record contains `chars` or `offset_ms` (timings are not stored).
- [ ] Without a `playback_state` frame in the 2 s grace, the session writes all received text with `interrupted?: true`.
- [ ] `played_until_ms` past the last offset records the full text; `played_until_ms: 0` records an empty text.

## Plan pass (2026-10-10)

**Key decisions**

- One event for all providers: `AgentTextTiming` with `estimated` as a field. Reason: the page (C13-T04) uses one code path and only changes trust in the offsets.
- The unit of `length` is the grapheme cluster on both sides. Reason: code points split emoji and accents, and JS string length counts UTF-16 units; the page must cut text at the same point as the transcript.
- `from_char_alignment/3` uses ElevenLabs `alignment`, not `normalizedAlignment`. Reason: normalized text can differ from the displayed text (numbers spelled out), so its counts do not match the text (research §1.4b).
- `from_text_deltas/2` spreads the delta evenly over the audio duration that arrived for the turn since the previous timing event. Duration comes from the `AgentAudio` format (PCM bytes / (rate x 2); G.711 bytes / 8 per ms). With no audio yet, `chars` is `nil` and the page reveals at arrival. Reason: research §1.6 has no provider timing for OpenAI or Gemini; this is the documented fallback.
- `played_until_ms` rides on the existing `playback_state` frame. Reason: the contract already has the frame "to log interruptions" (§3.3); a second frame would let the two disagree.
- The heard prefix goes into the existing §9 `assistant_turn{interrupted?}` record. Reason: no transcript schema change, so C6-T01 is not reopened.

**Risks**

- The client report never arrives (tab closed at barge-in) → the 2 s grace writes the full received text with `interrupted?: true`; persist-before-notify still holds for later events of the session.
- Estimated offsets differ from real speech, so the heard prefix is approximate for OpenAI and Gemini → mark the turn as estimated only in memory; the transcript keeps `interrupted?: true`, which tells a reader the cut is not exact. For OpenAI Realtime over WebSocket, `truncate/3` also tells the provider, so its own context matches.
- ElevenLabs alignment chunks restart at 0 per chunk (times relative to the chunk, research §1.4b) → the helper adds the running turn audio offset; a property test covers multi-chunk input.
- Alignment character count does not match the text (whitespace, normalization) → the helper falls back to `from_text_deltas/2` with `estimated: true` and emits a `:telemetry` event, never a crash.
- Text-only mode has no audio clock → no timing events; on a user message mid-reply the session records the text sent so far.

**Test strategy**

- Unit (ExUnit with StreamData, no keys): property tests for all three helpers (monotonic offsets, sum of lengths = grapheme count of `text`, multi-chunk ElevenLabs input, mismatched alignment falls back). Wire golden fixtures for `agent_text_timing` and both `playback_state` shapes.
- Session tests with `FakeProvider` and the real `TranscriptStore` in a tmp `transcript_root`: heard prefix, grace timeout, bounds (0 and past the end), no timings in the ndjson, `truncate/3` called once only when `manual_truncation: true`.
- Integration and browser: none here. C13-T04 Playwright tests drive these frames against a scripted server.
- Manual with real keys: none in this ticket. Provider fixtures come from C14-T02/T03/T05 operator runs (under USD 1 each, plan §19.11) and the C2-T03 spike.
- Regression and mutation guard: store the full text on interruption → the heard-prefix test fails. Second guard: count bytes instead of graphemes → the property test fails on a multi-byte input.

**Open points**

- C13-T04 says the client sends `played_until_ms` and `playback_state{stopped}`. With this plan they are one frame. The C13-T04 implementer follows this ticket; no decision is needed.
