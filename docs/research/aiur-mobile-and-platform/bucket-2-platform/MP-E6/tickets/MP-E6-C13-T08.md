# MP-E6-C13-T08 — The `/talk` skill

Plan: [../plan.md](../plan.md) §19.1, §19.4, §19.7. Requirements: R1–R8, R15–R18, SD5, SD6. Research: [../talk/research.md](../talk/research.md) §3.

Kevin, 2026-10-10 (verbatim): "i invoke /talk, tells agent how to set up and run locally."

## Identity and outcome

- **User value:** the user types `/talk` in their agent; the agent sets everything up, shows the options, starts the page, sends the link, and keeps working while it listens for confirmed instructions.
- **Deliverable:**
  - `skills/talk/SKILL.md` in the open Agent Skills format (agentskills.io; spec-safe keys only: `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`) plus `references/` per agent (`claude-code.md`, `codex.md`, `gemini-cli.md`, `other.md`) and one launcher `scripts/talk-launch` that detects the host agent (`CLAUDE_CODE_SESSION_ID` → Claude Code; `CODEX_THREAD_ID` → Codex), resolves the `talk` binary once (pinned version), and runs `talk <verb> --agent <self> …` as a child of the agent's shell tool, so `talk serve` inherits the session id and the messaging socket (C13-T01, C13-T06, C13-T07 read them from the environment; no handle flag exists). Canonical source: `packages/elixir/voice_converse/priv/skills/talk/`, so the release carries it for `install-skill` (see Plan pass). Invocation: `/talk` in Claude Code and Cursor, `$talk` in Codex, model-activated in Gemini CLI (the README says so). The skill holds steps, not logic:
    1. Ensure the host: `npx -y <talk package> --version` (C13-T03); on failure explain the one prerequisite (Node 20+).
    2. `talk doctor --json --agent <self>`; present **all** options in a short table with status, cost hint and the recommended one; never skip this, even with one ready option (SD6).
    3. For a chosen option that needs a key: tell the user the variable name and the file (`.env` in the project or `~/.config/talk/.env`), ask them to add it themselves, wait, re-run doctor. Never ask for the key in chat; never print it.
    4. `talk prefer <choice>`; `talk serve --project .` through the launcher, from the agent's own shell tool (not a detached terminal), so the host inherits the session id and the messaging socket; send the printed link. To resend, use `talk url`.
    5. Write the first briefing with `talk brief`, then continue the user's work; refresh the briefing at each checkpoint.
    6. Inbox: confirmed drafts arrive by push where the harness allows it (Claude Code messaging socket, Codex `codex queue`; C13-T06). Others run `talk inbox wait --timeout 0` between steps. Claude Code may also keep a background `talk inbox wait` and start it again when it exits 2 (timeout, no record). Before applying, check the record `id`: if a reply for it exists, skip it (push and `wait` can deliver the same record). Apply a confirmed instruction only if it fits the user's current request; reply `--applied` or `--declined --reason`. Answer `ask` records with `--answer`.
    7. `/talk stop` → `talk stop`.
  - `talk install-skill [--project] [--agent claude|agents|all]` (default `all`) writes the skill once to `~/.agents/skills/talk/` (read by Codex, Gemini CLI, Cursor, Copilot, OpenCode) and symlinks `~/.claude/skills/talk` to it (Claude Code reads only its own directory), then prints both paths. `--project` does the same under `<project>/.agents/skills/` and `<project>/.claude/skills/`. Re-runs replace the old copy (idempotent). It prints a duplicate-listing note when `~/.cursor` or `~/.config/opencode` exists, because Cursor and OpenCode read both trees (research §3.1.2, gap 6).
  - The skill text states the safety rules: no instruction is applied without the user's Confirm on the page; the fork is read-only.
  - Wire the talk host: its `AgentChannel.fork_query/3` calls `VoiceConverse.AgentFork` (C13-T07) with the handle that C13-T07 discovery reads from the environment `talk serve` inherits; no handle → `fork: :none`, stated on the page. (Added by the coordinator after the C13-T07 plan pass: no other ticket owned this wiring.)
- **Non-goals:** any aiur dependency (SD5). In an aiur Executor session the same skill works; the aiur adapter (C12-T03) is an alternative path, not required.

## Plan pass (2026-10-10)

**Key decisions**

- Keep the canonical skill in `packages/elixir/voice_converse/priv/skills/talk/`. Reason: `talk install-skill` runs from the release binary, and `priv/` ships in the release. A repo-root `skills/talk/` (requirements AS4) is outside the package and cannot ship without coupling the build to the aiur tree.
- `scripts/talk-launch` resolves the binary once: `talk` on `PATH`, else `npx -y @aiur-team/talk@<pinned version>`. Every step calls the launcher. Reason: one pinned version prevents skew between skill text and CLI flags.
- The launcher passes no session handle. It runs `talk` as a child of the agent's shell tool. Reason: C13-T01 has no handle flag; C13-T06 and C13-T07 read `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_MESSAGING_*` and `CODEX_THREAD_ID` from the inherited environment.
- `SKILL.md` frontmatter uses only spec-safe keys. No `disable-model-invocation`. For Codex, add `agents/openai.yaml` with `policy.allow_implicit_invocation: false`. Reason: Claude-only keys can break the claude.ai upload path (research §3.1.3). Gemini CLI has only model activation, so implicit use must stay possible there.
- The skill shows the `doctor --json` table as it is and names no option id. Reason: the option registry (C14-T01) can change without a skill change, and KD1 says a skill update must not change behaviour.
- Lint and content checks are ExUnit tests in the package. Reason: the repo has no skill lint, and an external validator adds a Python dependency to CI.

**Risks**

- The agent forgets to re-arm `inbox wait` or applies a record twice → explicit steps in `SKILL.md`, guarded by the content test; C13-T06 also refuses a second reply.
- Version skew between an old installed skill and a new binary → the launcher pins the version; `install-skill` replaces the old copy.
- The agent starts `talk serve` in a detached terminal and loses the inherited socket and session id → step 4 says "from your own shell tool". The file inbox is always the record of truth (C13-T06), so the skill also tells every agent to run `talk inbox wait --timeout 0` at each checkpoint as a backstop.
- Duplicate listing in Cursor and OpenCode (research §3.6 gap 6, UNVERIFIED) → `install-skill` prints a note; `--agent agents` installs only the shared tree.
- Codex `CODEX_THREAD_ID` is source-verified only → detection lives in the launcher and in C13-T07, each in one place; the manual Codex run confirms it.

**Test strategy**

- Unit (ExUnit, no network, temp HOME): `install_skill_test.exs` covers every target directory, the `--project` tree, the symlink, idempotent re-run, and the duplicate note with fake `~/.cursor`. The frontmatter lint, the 500-line limit, the required-steps content test and the secret-print scan run in the same file.
- Launcher: a shell test with a stub `talk` on `PATH` checks agent detection (`CLAUDE_CODE_SESSION_ID`, `CODEX_THREAD_ID`, neither) and the forwarded `--agent` value.
- Integration: C13-T09's `scripts/talk-e2e.sh` runs `install-skill` through the fake provider. No browser test in this ticket.
- Manual (operator, real agents): Claude Code and Codex each run `/talk`, show all options, start the page, and apply one confirmed draft. Use `text_only` or `cascade` with a cheap text model. Cost cap USD 1 for both runs. Record versions and the push mode seen.
- Regression and mutation guard: delete the "present all options" step → content test fails; add `printenv` to the launcher → scan fails.
