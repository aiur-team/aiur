# MP-E6-C12-T03 — Executor `AgentChannel`

Plan: [../plan.md](../plan.md) §18.3, §18.4, §18.5.

## Identity and outcome

- **User value:** the operator talks to the Executor by voice. Questions are answered from
  the Executor's fork; confirmed instructions reach the live Executor as proposals that it
  applies on its next wake. Only the live Executor acts.
- **Deliverable (aiur adapter only, `src/lib/aiur/voice_converse/host/agent_channel.ex`):**
  - `capabilities(%{kind: :executor})` → `fork: :native | :none` from the C12-T01 handle.
  - `fork_query` → `Aiur.Executor.Fork.query/2` → `{:fork_answer, ref, text}`.
  - `ask` / `instruct` → wake records `executor.voice.ask` / `executor.voice.proposal`
    (`conversation_id`, `draft_id` or `ask_ref`, redacted text, operator principal) through
    `ExecutorWakeInbox`; idempotent per `draft_id`.
  - `aiur executor-voice-reply <ref> --applied | --declined [--reason] | --answer <text>`
    → receipt or `{:agent_reply, ref, text}` to the voice session.
  - Executor session unknown → `ask`/`instruct` refused `executor_unavailable`; the session
    stays discussion-only.
- **Non-goals:** core changes (none allowed, §18.5); merge/approve/label/restart tools
  (none exist, §6); typing into the Executor terminal or session file.

## Acceptance criteria

- [ ] A confirmed draft creates exactly one `executor.voice.proposal` wake record, and
      `executor-wait` returns it.
- [ ] No path from a tool or provider event creates a proposal without a client confirm (V5
      test with the core `FakeProvider`).
- [ ] `executor-voice-reply --applied` reaches the voice session as a `:delivered` receipt.
- [ ] The standalone CI grep finds no `Aiur` reference in the package (unchanged).
