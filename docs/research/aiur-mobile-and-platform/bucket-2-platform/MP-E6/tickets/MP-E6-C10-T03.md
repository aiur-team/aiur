# MP-E6-C10-T03 — Side-query spike (fork, do not interrupt)

Research: [../realtime-convo-research.md](../realtime-convo-research.md) §5.3 path C.

## Identity and outcome

- **Bucket / feature / chunk:** 2-platform / MP-E6 / C10.
- **User value:** some questions need the coding agent's own memory ("why did you drop the
  retry?"), not the status card. Today the only way to ask is to send a message into the
  agent's turn, which waits for a high-effort turn (minutes) or interrupts its work. A forked
  side session could answer from the same context in seconds while the real agent keeps
  working.
- **Deliverable:** a findings note `bucket-2-platform/MP-E6/side-query-findings.md` with
  measured numbers, a pass/fail verdict per criterion, and a recommended design for
  MP-E6-C10-T05.
- **Non-goals:** production code; any change to a live agent session (the spike forks a
  copy of a finished or test session only).

## Dependencies and blockers

- **Predecessors:** none. Uses the operator's existing harness subscriptions, not a new paid
  vendor; it still spends model quota, so keep to the budget below.
- **Budget:** at most 40 forked queries in total; one working day.

## Verified starting point (base `0972f0297`)

- aiur already knows each Claude session id and resumes it with `--resume`
  (`src/lib/aiur/claude/repl/command.ex:50-60`); Codex has its own resume path (same file
  comment, #378/#613).
- No fork usage exists in `src/lib` (`grep -rn fork-session` finds nothing).

## Questions to answer

| ID | Question | How |
| --- | --- | --- |
| SQ-1 | Does `claude -p --resume <id> --fork-session` (or the current equivalent) answer from the parent's context without writing to the parent's transcript? | fork a test session; diff the parent jsonl before/after |
| SQ-2 | Time to first token and to a full 3-sentence answer for a 50k / 150k-token parent context, at low effort, with and without a warm prompt cache | 5 runs each; record the parent's last-activity age |
| SQ-3 | Can the fork be restricted to read-only tools (no edits, no git, no network)? | `--allowedTools` / permission mode; try a write; expect refusal |
| SQ-4 | Codex: does the app-server / CLI offer a thread fork or an ephemeral read-only turn on a copy? Same numbers as SQ-2 | Codex docs and a run |
| SQ-5 | Cost per query (tokens in/out, cache reads) | harness usage output |
| SQ-6 | Is the fork safe while the parent is mid-turn (file lock, partial jsonl line)? | fork during a running test turn; check both survive |

## Pass / fail criteria

| Criterion | Pass | Fail → consequence |
| --- | --- | --- |
| Isolation (SQ-1, SQ-3, SQ-6) | parent transcript unchanged; writes refused; parent unharmed | path C is not built; `ask_agent` uses the queued consult only (C5-T04) |
| Speed (SQ-2) | median full answer ≤ 15 s at 150k context with a warm cache | > 30 s → path C offered only for "deep" questions, with a spoken "this takes about half a minute" |
| Cost (SQ-5) | ≤ USD 0.25 per query at list price, or inside subscription limits | higher → owner decides (E6-OQ15) |
