# MP-E6-C13-T07 — Native fork from a session handle

Plan: [../plan.md](../plan.md) §19.7, §17.7, §18.2. Requirement R17, R24. Research: [../talk/research.md](../talk/research.md) §3.

Kevin, 2026-10-10: "same forking functionality applies to let agent continue working during convo."

## Identity and outcome

- **User value:** in `/talk`, a "why" question is answered from a copy of the live agent's own session, and the live agent is not stopped or changed.
- **Deliverable:** `VoiceConverse.AgentFork` (core; drives agent CLIs as external programs, no aiur code):
  - Handle: `%{harness: :claude_code | :codex | :opencode | :other, session_id, cwd, config_dir}`. Discovery: Claude Code `CLAUDE_CODE_SESSION_ID` (documented in Bash tool subprocesses) and `CLAUDE_CONFIG_DIR`; Codex `CODEX_THREAD_ID` (injected into tool shells, source-verified, not in user docs; keep the name in one module with a fixture). `talk serve` is started from the agent's shell tool, so it inherits them.
  - `claude_code`: `claude -p --resume <id> --fork-session --no-session-persistence --permission-mode plan --tools "Read,Grep,Glob" --disallowedTools "mcp__*" --strict-mcp-config --permission-prompts none --max-turns N --input-format stream-json --output-format stream-json --include-partial-messages --verbose`, env without GitHub tokens, cwd = handle cwd. Plan mode is passed explicitly (a fork does not restore it).
  - `codex`: `thread/fork` on the shared app-server daemon (or an own `codex app-server` when no daemon) with `ephemeral: true`, `sandbox: read-only`, `approvalPolicy: never`, `experimentalPredictionMode` when available (prompt-cache reuse), then one turn. CLI fallback `codex exec fork <id> --ephemeral --json -c sandbox_mode="read-only"`.
  - `opencode`: `POST /session/:id/fork` on the TUI server when its port is known; else replay.
  - Warm fork: a fork answer takes seconds (research §3.5), so the assistant says "let me check" and keeps talking. For Claude Code, keep one stream-json fork process per voice session and reuse it while the parent has not advanced more than N entries; else re-fork. Measure first-token time and record it.
  - `replay` fallback for other harnesses: one model call with the briefing, the question and the read-only note (needs a model credential; else `:none`).
  - One fork at a time per session; 60 s timeout kills the process tree; result `{:fork_answer, ref, text, mode, usage}`.
  - The standalone `AgentChannel.fork_query/3` (C11-T03 host) calls it. This ticket does not edit the host: C11-T03 does not wait for this ticket and lands with `fork: :none`. The call site is wired by the later of the two (see Plan pass, Open points).
- **Shared with aiur:** C12-T02 (Executor fork) calls this module with the aiur-recorded handle instead of building its own argv. Worker forks keep using MP-R7 `fork_session/2` (C11-T05), which may also delegate the CLI cases here.
- **Non-goals:** Gemini CLI native fork (replay until research shows a fork, plan §17.7). OpenCode native fork is in scope, but only behind the read-only gate in the Plan pass; otherwise OpenCode uses replay.

## Acceptance criteria

- [ ] Claude argv and env exactly as above (stub CLI records them). The env has no `GITHUB_TOKEN`/`GH_TOKEN` and no key that `talk` loaded from `.env`.
- [ ] Codex `thread/fork` params are `ephemeral: true`, `sandbox: "read-only"`, `approvalPolicy: "never"`, and the turn also passes a read-only `sandboxPolicy`. `lastTurnId` is never an in-progress turn (fake app-server records the JSON-RPC).
- [ ] Parent untouched: parent session file hash and `git status --porcelain` equal before and after (stub CLI, plus one manual real run each for Claude Code and Codex recorded in the PR).
- [ ] No new session file in the profile's project directory after a Claude fork.
- [ ] Second concurrent fork → `{:error, :fork_busy}`; timeout leaves no OS process.
- [ ] A replay answer carries `mode: :replay` so the assistant can say it came from a summary. With no replay model, the result is `{:error, :none}` and no process starts.
- [ ] First-token time of one real Claude Code fork and one real Codex fork on the dev host is recorded in the PR.

## Plan pass (2026-10-10)

**Key decisions**

- One module per harness behind one `AgentFork` API (`claude_code`, `codex`, `opencode`, `replay`). Each harness has its own flags and its own risks (plan §17.7, SD2).
- The environment-variable names (`CLAUDE_CODE_SESSION_ID`, `CLAUDE_CONFIG_DIR`, `CODEX_THREAD_ID`) live in one discovery function with a fixture. `CODEX_THREAD_ID` is source-verified only (research §3.2.2), so a rename must break one test, not the feature.
- Callers pass options, not argv: `lock_key` (default the voice session id; C12-T02 passes `{:executor, consumer_id}`), `env_drop` (extra names to remove), `max_turns` (default 6), `timeout_ms` (default 60 000). C12-T02 then adds its Executor limits without its own argv builder (C12-T02 line 79).
- The child env removes GitHub tokens and every key that `talk` loaded from `.env`. Reason: if `ANTHROPIC_API_KEY` leaks into the child, `claude` bills the API key instead of the user's own login (research §3.4). Keys that were already in the agent's shell env stay.
- The fork runs in its own OS process group (`setsid`); timeout and cancel kill the group. The core must not call aiur code, so it copies the pattern of `Aiur.Claude.Repl.Reaper`, not the module.
- Replay uses a model function that the host injects (`replay_model`). The talk host passes the cascade text model when C14-T04 has merged. Without it, replay is `:none`. Reason: this keeps the ticket off the C14 chain.
- Codex uses the shared daemon when its control socket answers and the thread is loaded there (needed for `experimentalPredictionMode`). Else it starts an own `codex app-server`. The `codex exec fork` CLI fallback is used only if the manual run shows that `-c sandbox_mode="read-only"` applies to `exec fork` (research §3.2.2, UNVERIFIED); else replay.
- OpenCode native fork is used only when the prompt can run with a read-only agent (for example `plan`) and the manual check shows no write. Until then `opencode` is `:replay`. Reason: research §3.2.4 did not verify read-only.

**Risks**

- Mid-turn parent (research §3.6 gap 2, SQ-6): the fork sees a cut-off tool call or an interruption marker. → Never pass an in-progress `lastTurnId`; take C10-T03's result as the expected behaviour; add a stub-transcript test with an open `tool_use` as the last record.
- Warm fork goes stale: the reused stream-json process does not see new parent entries. → Count parent transcript lines (Claude) or turns (Codex) at fork time; re-fork when the parent advanced more than N (default 20) or the fork is older than 10 min.
- Cost: the fork reads the whole parent context (up to 1M tokens). → Record `usage` in every result; `max_turns` small; one fork at a time per lock key.
- Claude CLI flag drift (`--permission-prompts`, `--tools`, `--no-session-persistence` are recent). → Probe `claude --help` once per process; if a required read-only flag is missing, refuse with `{:error, :unsafe_cli}`, never run with fewer limits.
- Process leak on timeout. → Group kill plus a test with a stub that starts a grandchild.

**Test strategy**

- Unit, with fakes (CI, no keys): a stub `claude` script records argv, env and cwd, writes a session file under a temp `CLAUDE_CONFIG_DIR/projects/...` unless `--no-session-persistence` is present, and starts a sleeping grandchild for the timeout test. A fake Codex app-server (stdio JSON-RPC) records `thread/fork` and `turn/start` params. A fake OpenCode HTTP server records the fork request. A fake `replay_model` covers `mode: :replay` and the `:none` path. Parent-unchanged test: hash of the parent session file and `git status --porcelain` of a temp repo before and after.
- Regression and mutation guards: drop `--no-session-persistence` → the project-directory test fails. Drop `ephemeral: true` or `sandbox` → the Codex params test fails. Remove the env filter → the env test fails.
- Integration: none in CI (no real agent binaries on runners).
- Manual, real keys and logins, recorded in the PR: one Claude Code fork and one Codex fork against a live parent that is mid-edit. Record the parent hash and git status before and after, first-token time, and `usage`. Cost cap: USD 2 in total; stop at the cap.
