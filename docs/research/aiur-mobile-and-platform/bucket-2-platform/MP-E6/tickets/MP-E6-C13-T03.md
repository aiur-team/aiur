# MP-E6-C13-T03 — Self-contained distribution

Plan: [../plan.md](../plan.md) §19.6. Research: [../talk/research.md](../talk/research.md) §5. Requirement R2.

## Identity and outcome

- **User value:** a Claude Code or Codex user runs `npx -y <talk package> serve` (or the skill does it) with no Elixir, Erlang or compiler on the machine.
- **Deliverable:**
  - A `mix release` of the talk host with ERTS included, built in CI for `linux-x64` (glibc), `linux-arm64` (glibc) and `darwin-arm64`. The release does not need a system OpenSSL (OTP built with a static OpenSSL, or an equal proof). Erlang distribution is off (`RELEASE_DISTRIBUTION=none`), so the release starts no epmd and opens no port other than the C13-T01 loopback port and control socket.
  - Not built in v1, and the launcher prints the documented "not supported yet" message and exits non-zero: `darwin-x64` (no CI runner can build it; same rule as `packaging/scripts/platforms.mjs` for aiur-cli), Linux musl (Alpine), and Windows (the C13-T01 control socket is Unix-only; the message says "use WSL").
  - npm packaging in the esbuild pattern under `packaging/npm/talk/` (next to `packaging/npm/aiur-cli`): one launcher package with a small JS bin and per-platform packages as `optionalDependencies` (`os`/`cpu`, and `libc: ["glibc"]` on Linux), each holding one release tarball. Reuse what `packaging/npm/aiur-cli` already does where it fits; do not couple the talk packages to aiur's version.
  - SHA-256 of each tarball in the launcher package; the launcher verifies before first run.
  - Release CI job, manual dispatch only, dry-run by default. A real `npm publish` needs E6-OQ18 (the package name) and Kevin's go; E6-OQ16 is already answered for npm (plan §19.8). A dry-run `npm pack` runs on every PR that touches the package.
  - Name: placeholder `@aiur-team/talk` until E6-OQ18 settles the package name.
- **Non-goals:** Hex publish (E6-OQ16, after the 2-release clean check); Homebrew.

## Acceptance criteria

- [ ] On a clean `node:20-slim` container (no Erlang, no OpenSSL package added), after `npm install` of the launcher and platform tarballs from local files, `talk --version` exits 0, and `talk serve --port 0` reaches "listening", `talk status --json` exits 0 and `talk stop` ends it. (`doctor --json` is C13-T02; C13-T08 adds it to this smoke.)
- [ ] The release opens no listening socket except the loopback HTTP port and the control socket (no epmd, no distribution port).
- [ ] With `--omit=optional` (platform package missing), the launcher prints a clear reinstall message and exits non-zero.
- [ ] Cold start of `talk serve` to "listening" under 2 s on linux-x64 (record the number).
- [ ] A tampered tarball fails the checksum and does not run.
- [ ] Unsupported platform prints the documented message and exits non-zero.

## Plan pass (2026-10-10)

**Key decisions**

- The release is `releases: [talk: ...]` in the core `packages/elixir/voice_converse/mix.exs`, with `include_erts: true` and steps `[:assemble, :tar]`. Reason: C13-T01 puts the talk host modules in the core project, and the `:tar` step gives the one tarball that the checksum covers.
- Each platform package holds `talk-<target>.tar.gz`. The launcher package holds `checksums.json` (SHA-256 per target), stamped at release time. On first run of a version, the launcher verifies the tarball, then extracts it to `$XDG_CACHE_HOME/talk/<version>-<target>/` (macOS: `~/Library/Caches/talk/...`) through a temp directory and one atomic rename. Reason: `node_modules` can be read-only, and an extracted cache keeps later starts fast.
- Later runs check a marker file in the cache that records the verified hash. They do not hash the tarball again. Reason: the 2 s cold-start budget. A cache with no marker, or a marker with a different hash, causes a new verify and extract.
- The launcher passes the CLI arguments to the release through an overlay script (`rel/overlays/bin/talk-cli`) that sets `TALK_ARGV` and runs `bin/talk eval` for short verbs and `bin/talk start` for `serve`. It also sets `RELEASE_TMP` to the cache directory and `RELEASE_DISTRIBUTION=none`. Reason: no shell quoting of user arguments, and no epmd on `0.0.0.0:4369`, which would break the loopback-only rule of plan §19.5.
- OTP for the talk release links OpenSSL statically (kerl `--disable-dynamic-ssl-lib` against a pinned static OpenSSL, cached in CI). Reason: `mix release` links OpenSSL dynamically (research §5). On macOS the mise OTP links Homebrew's OpenSSL, which a clean Mac does not have. The providers need `:ssl`.
- The platform list has its own single source (`packaging/npm/talk/platforms.mjs`), with a drift check like `check-platform-drift.mjs`. The talk version comes from the core `mix.exs`, not from aiur's. Reason: the aiur-cli #2110 defect (a pinned platform that is not published installs silently into a runtime with no binary), and no version coupling to aiur.

**Risks**

- The static OpenSSL build of OTP fails or takes too long on one runner → cache the OTP build per target and OpenSSL version. If static linking fails on one target, ship that target with a launcher pre-check that prints the exact package to install (`libssl3`). Record the choice in the PR.
- macOS arm64 needs a valid code signature on every Mach-O file, and stripping or changing a file after the build breaks the ad-hoc signature → do not strip on macOS. The smoke runs the extracted release on `macos-14` with no Homebrew OpenSSL on the path. Notarization is out of scope: npm downloads get no quarantine flag.
- `npm install --omit=optional` or a shared lockfile skips the platform package without a sign → the launcher error names the cause and the fix, the same as aiur-cli (research §5).
- Two `npx` runs extract at the same time → extract into a unique temp directory and `rename` it into place. The loser removes its copy and uses the winner's.
- The tarball (ERTS plus Bandit, Mint and the core) is larger than expected → record the size per target in the PR. The requirement assumes tens of MB (AS2).

**Test strategy**

- Unit (Node, no network, fake platform package in a temp directory): `packaging/npm/talk/test/launcher.test.mjs` covers platform mapping (darwin x64, win32, linux musl stubs give the documented message and a non-zero exit), the missing-package message, checksum pass, checksum fail (one changed byte: non-zero exit, nothing extracted, nothing run), the cache marker, and the concurrent-extract rename.
- Packaging: `npm pack --dry-run --json` on every PR that touches `packaging/npm/talk/**` or the release config, compared with a checked-in file allowlist. The platform drift check runs in the same job.
- Integration (CI, manual dispatch and dry-run on release-config PRs): build matrix linux-x64, linux-arm64, darwin-arm64. The smoke installs the launcher and the platform tarball from local files in `node:20-slim` (Linux) and on a clean `macos-14` runner, then runs `--version`, `serve --port 0`, `status --json` and `stop`. It lists the listening sockets and records the cold-start time (warm cache) and the first-run extract time. `ldd`/`otool -L` on `crypto.so` must show no `libssl`/`libcrypto`.
- Manual: none with real keys. No provider is called, so the cost is zero.
- Regression and mutation guard: skip the checksum compare in the launcher, and the tamper test fails. Remove `RELEASE_DISTRIBUTION=none`, and the "no extra listeners" smoke fails.
