# MP-E6-C13-T02 — `talk doctor`, `.env` and preferences

Plan: [../plan.md](../plan.md) §19.4. Requirements: R3–R7, SD6 ("agent presents user options regardless").

## Identity and outcome

- **User value:** the agent can show the user every option with a clear status and the exact next step, and remember the choice.
- **Deliverable:**
  - `talk doctor [--json] [--check]` prints every option from `VoiceConverse.options/1` (C14-T01): id, label, status (`ready`, `needs_credential`, `unsupported`), the missing variable names, a one-line price hint, a privacy note, and one `recommended` option. Recommendation rule: the user's own model provider's native option if ready (agent detected from `--agent claude|codex|gemini|other` or from the environment), else ElevenLabs if ready, else cascade with the agent's provider model if ready, else text-only.
  - `--check` makes one cheap authenticated request per present key (list-models style, no audio, no cost) and reports `invalid_key` without printing the key.
  - Credentials load order: process env, `<project>/.env`, `$XDG_CONFIG_HOME/talk/.env` (`~/.config/talk/.env`). Variables: `OPENAI_API_KEY`, `GEMINI_API_KEY` (also `GOOGLE_API_KEY`), `ANTHROPIC_API_KEY`, `ELEVENLABS_API_KEY`. The `.env` parser accepts `KEY=value`, quotes and comments; it never echoes values. `doctor` warns when `<project>/.env` is not in `.gitignore`.
  - `talk prefer <option_id> [--mode voice|text]` writes `~/.config/talk/config.json` (preference list, mode, cascade parts). `serve` reads it.
- **Non-goals:** writing keys for the user (the user edits `.env`; requirement R5).

## Acceptance criteria

- [ ] With only `ANTHROPIC_API_KEY` set and `--agent claude`, `doctor --json` lists all options, marks cascade and text_only ready, and recommends cascade.
- [ ] With `OPENAI_API_KEY` and `--agent codex`, it recommends `openai_live`.
- [ ] `doctor` output never contains a key value (test with planted keys).
- [ ] A project `.env` not covered by `.gitignore` produces a warning line.
- [ ] `--check` with a bad key reports `invalid_key` (fake HTTP).
- [ ] With no key at all, `doctor --json` marks `text_only` and `cascade` as `needs_credential`, sets `recommended: null`, and names the variables that would make each option ready. It does not crash.
- [ ] `codex_realtime` is never `recommended`, also when it is `ready` (experimental, opt-in only, plan §19.3).
- [ ] Precedence: a key in the process environment wins over the project `.env`, and the project `.env` wins over the user-level `.env`. The `.env` values are not written into the process environment (`System.get_env/1` is unchanged after loading).
- [ ] `talk prefer` refuses an unknown option id with a non-zero exit. After `talk prefer`, `doctor --json` shows the saved preference and whether it still resolves (R7). The config file honours `$XDG_CONFIG_HOME`.
- [ ] `--check` reports `unchecked` (not `invalid_key`) on a network error or a timeout. The key travels in a header, never in a URL.

## Plan pass (2026-10-10)

**Key decisions**

- The `.env` loader and the file-backed `Credentials` port live in the talk host modules (`lib/voice_converse/talk/`), not in the core. Reason: the core reads no files except roles and transcripts (plan §17.6). The host passes the port into `VoiceConverse.Config`, and `VoiceConverse.options/1` (C14-T01) stays presence-only.
- Loaded keys stay in a host-private map. The host never calls `System.put_env/2` with them. Reason: the fork of C13-T07 runs the user's own agent binary. An exported `ANTHROPIC_API_KEY` can make `claude` bill the API key instead of the user's login (research §3.4). It can also leak the key to child processes.
- First found wins: process env, then `<project>/.env`, then `$XDG_CONFIG_HOME/talk/.env`. For Gemini, `GOOGLE_API_KEY` wins over `GEMINI_API_KEY`, the same as the google-genai SDK, and doctor notes when both are set. Reason: the user must get the same key that their other tools use.
- Agent detection: `--agent` wins. Else `CLAUDECODE` or `CLAUDE_CODE_SESSION_ID` gives `claude`, and `CODEX_THREAD_ID` gives `codex` (research §3.1.4, §3.2). Else `other`. Gemini CLI has no documented marker, so it uses `--agent gemini`. Reason: only these markers are verified.
- Recommendation: the native option of the agent's provider (`openai_live` before `openai_realtime`; `gemini_live`), then `elevenlabs_agents`, then `cascade` with the agent's model, then `text_only`. `codex_realtime` is never recommended. If no option is ready, `recommended` is `null`. Reason: plan §19.3 marks `codex_realtime` opt-in, and with no key even `text_only` has no model (it needs the model key).
- `--check` sends one GET per present key to a model-list endpoint (Anthropic, OpenAI, Gemini `models`; ElevenLabs `models` or `user`) with the key in a header (`x-api-key`, `Authorization`, `x-goog-api-key`, `xi-api-key`). 401 or 403 gives `invalid_key`. A network error or a 5-second timeout gives `unchecked`. Reason: a key in a URL goes into logs, and an outage is not a bad key.
- `.gitignore` warning: in a git work tree, `git check-ignore -q .env` decides. Outside a git work tree, no warning. Reason: git itself is the oracle for nested and global ignore rules.

**Risks**

- A crash report or `inspect/1` of the credential map prints a key → the map is a struct with a redacting `Inspect` implementation. The "no secret in output" test plants keys and checks stdout, stderr, the JSON and the captured log of a forced crash.
- The `.env` parser differs from what users expect (`export KEY=`, quotes, `#` inside quotes, CRLF) → table tests for each form. Variable expansion (`${OTHER}`) is not supported, and doctor says so in a warning for a value that contains `${`.
- The user-level `.env` is readable by other users → doctor warns when `~/.config/talk/.env` is group- or world-readable. `prefer` writes `config.json` with mode 0600.
- Provider list endpoints change or start to cost money → each probe is one module with a fixture. `--check` is opt-in, and the default `doctor` makes no network call.
- `serve` and `doctor` disagree on the chosen option → both call the same resolve function with the same loaded credentials and the saved preference.

**Test strategy**

- Unit tests with fakes: the `.env` parser (table tests), load precedence and no-export, agent detection from a fake env map, the recommendation rule for each agent and key mix (AE1, AE2, no key, `codex_realtime` ready), the `prefer` round trip in a temporary `XDG_CONFIG_HOME`, and the JSON shape. `--check` uses a fake HTTP client (Req test adapter) for 200, 401, timeout and a connection error.
- Integration: `doctor --json` and `prefer` through the CLI entry point against a temporary project directory with a real `git init` and `.gitignore`. No browser test.
- Manual with real keys: one `talk doctor --check` run with the four real keys and one revoked key. Cost USD 0 (list endpoints are free). Cap USD 0.10.
- Regression guard: the "no secret in output" test with planted keys. Mutation checks: print the raw env map in `--json` and the test fails; call `System.put_env/2` in the loader and the "env precedence and no export" test fails.

**Open points**

- Agent detection for Gemini CLI and other agents without a marker. The skill passes `--agent` (C13-T08), so this does not block. C13-T08 owner decides if the skill must always pass it.
