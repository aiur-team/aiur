# MP-E6-C10-T04 — Briefing on demand (Kevin's "halt and dump", made optional)

Research: [../realtime-convo-research.md](../realtime-convo-research.md) §4 (evaluation of
the 5-step flow) and §6.

## Identity and outcome

- **Bucket / feature / chunk:** 2-platform / MP-E6 / C10.
- **User value:** the operator can still get Kevin's proposed full briefing from the agent
  itself when the card is not enough, but the conversation does not wait for it and the agent
  does not stop unless the operator chooses that.
- **Deliverable:** two session actions and one assistant tool.
  1. **Refresh (default, non-halting).** On Converse start (if the note is older than 5
     minutes) and when the operator asks ("get me a fresh update"), send the agent a
     `status.refresh` request through the listener-mode send (MP-E7) with checkpoint
     delivery: "Update your status note now (progress.status, updated_reason: refresh), then
     continue your work." The assistant keeps talking from the card. When the new note
     arrives, C10-T02 pushes the delta and the assistant says "The agent just updated: …"
     at the next pause.
  2. **Pause and brief me (opt-in halt).** A button and a spoken request that maps to a
     confirm-required draft: pause the agent through the existing pause path
     (`Aiur.Orchestrator.PauseResume`), then ask for a full briefing (note + open questions
     + what it would do next). Resume is a separate confirm. This is Kevin's step 2, kept for
     the cases where he wants the agent to stop (for example, it is going the wrong way).
  3. Tool `request_briefing(mode: "refresh" | "pause")` — `pause` only creates the draft; it
     never pauses without the on-screen Confirm (V5, E6-OQ1).
- **Non-goals:** making a halt the default; any summary generated by aiur itself.

## Dependencies and blockers

- **Owner:** E6-OQ12 (is "Pause and brief me" offered at all; is refresh-on-start automatic).
- **Predecessors:** C10-T01, C10-T02, C5-T03 (confirm path), MP-E7 send.

## Verified starting point (base `0972f0297`)

- Delivery policies `:checkpoint`, `:interrupt`, `:immediate`
  (`orchestrator/operator_messages/delivery_policy.ex:9-46`); `AgentChat.send/3` defaults to
  `:interrupt` (`agent_chat.ex:27`). The refresh request must pass `:checkpoint` explicitly
  so it never cuts a turn.
- A paused worker is not woken by queued messages
  (`delivery_policy.ex`, `deliver_now?/3` with `status: :paused`).

## Non-happy paths

- The agent does not refresh within 5 minutes (long tool run): the assistant says the note is
  from <age> and offers the queued consult (C5-T04) or "Pause and brief me".
- The agent is paused already: refresh is queued and delivered on resume; the assistant says
  so.
- Async listener mode: the request waits for a pull; the assistant says so (contract §11).
