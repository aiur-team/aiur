# MP-E6-C14-T06 — aiur provider preferences in `.aiur/config`

Plan: [../plan.md](../plan.md) §20.2. Kevin, 2026-10-10 (verbatim): "… full support for native model convo wrappers to use model APIs in aiur too and .config settings to choose preferences".

## Identity and outcome

- **User value:** the operator chooses, in `.aiur/config`, which conversation provider aiur prefers, the cascade parts, voice or text mode, and what happens when a key is missing. The dashboard says which option Converse used and why.
- **Deliverable:**
  - `Aiur.Config.Schema.VoiceConversationProviders` embedded at `voice.conversation.providers`:

    ```yaml
    voice:
      conversation:
        providers:
          preference: [openai_live, elevenlabs_agents, gemini_live, cascade]
          mode: voice                 # voice | text
          on_missing_credential: next # next | text_only | refuse
          openai:   { live_model: gpt-live-1, realtime_model: gpt-realtime-2.1 }
          gemini:   { live_model: gemini-3.8-live }
          cascade:  { stt: [elevenlabs_stt, browser_stt], llm: "anthropic:claude-haiku-5-5", tts: [elevenlabs_tts, browser_tts] }
    ```

  - Credentials: `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY` read through the MP-R5 credential facade or environment, never stored in config (contract §12 rule). `elevenlabs.api_key` unchanged.
  - `Aiur.VoiceConverse.Host.Config.build/1` maps the keys into `%VoiceConverse.Config{providers: …}`.
  - `Aiur.VoiceConverse.Host.Credentials` (C11-T04) gains `:openai`, `:gemini` and `:anthropic` (read from the environment at the moment of use) and the `:probe` purpose (C14-T01: `{:ok, :present} | {:error, :missing}`, never the secret). It passes the aiur credential-name map to the core, so a reason names `elevenlabs.api_key` / `ELEVENLABS_API_KEY` for ElevenLabs and the variable name for the others. (C11-T04 pointed the OpenAI key at superseded C11-T06; this ticket owns it now.)
  - `openai`, `gemini` and `cascade` are `embeds_one` schemas, not `:map` fields, so `scripts/check-config-docs.py` sees every leaf. Model fields default to `nil`, which means "the adapter's default model".
  - Capability `voice.conversation` reason text from `VoiceConverse.resolve/1` skipped list ("OpenAI Live skipped: OPENAI_API_KEY missing").
  - `config.example` block, `configuration.md` entries, `scripts/check-config-docs.py` green; `website/docs-app/apis/` page per new provider (`openai.md`, `gemini.md`, `anthropic.md`) with its privacy row (contract §10), and a sidebar entry for each in `website/docs-app/.vitepress/config.ts`.
- **Non-goals:** limits keys (C3-T01); the ElevenLabs agent provisioning (C3-T02).

## Acceptance criteria

- [ ] Every key reaches the core struct (mapping test per key).
- [ ] An unknown option id in `preference` fails config load with the field name.
- [ ] A config without `providers` loads with the default preference `[elevenlabs_agents, openai_live, gemini_live, cascade]` (ElevenLabs stays the default third-party provider, SD4).
- [ ] The capability reason names the skipped option and the missing variable, never the value.
- [ ] Config-docs gate green.
- [ ] The default preference equals `VoiceConverse.Providers.default_preference/0`; aiur does not keep its own copy of the list.
- [ ] An unknown cascade part id (`cascade.stt`, `cascade.tts`) or a malformed `cascade.llm` fails config load with the aiur field path.
- [ ] The credentials adapter answers `:probe` without the secret, and with `:connect` reads the key at call time (no key in process state or in `%VoiceConverse.Config{}`).

## Plan pass (2026-10-10)

**Key decisions**

- The aiur changeset checks `preference` ids against the core registry (`VoiceConverse.Providers`, C14-T01). It does not keep its own id list. Reason: one source of ids. The core skips unknown ids (C14-T01), but aiur fails at load, because an operator typo must not silently change the provider.
- Cascade parts and the `llm` string are checked by the core `VoiceConverse.Config` validation. The aiur changeset calls it and maps the error back to the aiur field path. Reason: the part ids belong to C14-T04/T05. A copy in aiur would drift.
- The default preference comes from `Providers.default_preference/0`. Reason: the C14-T01 plan pass names this as the drift guard.
- Model fields default to `nil`, which means the adapter default. Reason: model ids change often (research §1: `gpt-realtime-2.1`, `gpt-live-1`, `gemini-3.8-live`). One default in the adapter is easier to keep current than two. The reference page and `config.example` show the current ids with the date.
- No `api_key` field under `providers`. Keys come from the environment at the moment of use, and ElevenLabs keeps `elevenlabs.api_key` (contract §12, RC-13). Reason: secrets stay out of config. The daemon already scrubs `*_API_KEY` from agent environments (`config/schema/eleven_labs.ex` comment), so the new keys do not reach workers.
- `openai`, `gemini` and `cascade` are embedded schemas. Reason: `scripts/check-config-docs.py` walks only `embeds_one`. A `:map` field would need a `KNOWN_MAP_SUBKEYS` row and could hide a missing reference entry.

**Risks**

- `voice.conversation.llm` (C3-T01, the ElevenLabs agent LLM) and `providers.cascade.llm` look alike → the reference page says that `voice.conversation.llm` applies only to `elevenlabs_agents` and `cascade.llm` only to `cascade`/`text_only`. The example shows both with one comment line each.
- A reason string leaks a key → reasons carry only option ids and credential names. The sentinel test checks `inspect/1` of the config struct and of the capability reason.
- The adapters (C14-T02..T05) list C14-T06 as a dependent, but this ticket does not block on them → the registry fallback descriptors (C14-T01) cover every v1 id, so validation works before the adapters land. An option whose adapter is not loaded shows `unsupported` with a reason. That is the correct state, not a bug.
- `on_missing_credential: refuse` with the default preference refuses Converse for an operator who has no ElevenLabs key → the reference page says this. The capability reason names the first missing credential.

**Test strategy**

- Unit tests with fakes, no network, no real key, cost zero:
  - `test/aiur/config/schema/voice_conversation_providers_test.exs`: defaults, enum values, unknown id, unknown cascade part, malformed `llm`.
  - `test/aiur/voice_converse/host/config_test.exs`: table test, one row per key, from YAML to `%VoiceConverse.Config{}`.
  - `test/aiur/voice_converse/host/credentials_test.exs`: `:probe` and `:connect` with the environment set and unset (use a test-local variable override, not the real environment). Include the sentinel leak check.
  - Capability reason: AE5 shape (preference `[openai_live, elevenlabs_agents, cascade]`, only an ElevenLabs key) gives `elevenlabs_agents` and "OpenAI Live skipped: OPENAI_API_KEY missing".
- Docs: `python3 scripts/check-config-docs.py` and `bash scripts/test-check-config-docs.sh`. The `website/tests/gui-docs.spec.ts` sidebar check runs in CI only, not on this host.
- Manual: none with paid keys. One optional check: boot a dev daemon with a sample config and no voice keys, and read the `voice.conversation` capability reason. No provider call is made, so the cost is zero.
- Mutation guards: (1) drop one key from `Host.Config.build/1` → the table test fails. (2) Remove one reference entry → the docs gate fails. (3) Make `:probe` return the secret → the sentinel test fails. (4) Hard-code a default list that differs from the core → the default test fails.
