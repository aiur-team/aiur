# MP-E6-C10-T02 — Status card

Research: [../realtime-convo-research.md](../realtime-convo-research.md) §5–§6.

## Identity and outcome

- **Bucket / feature / chunk:** 2-platform / MP-E6 / C10.
- **User value:** the voice assistant starts every conversation with a short, current briefing
  (about 1,500 tokens) instead of a raw 8,000-token dump. It answers most questions at once.
  The briefing stays current while the operator talks, so the coding agent never has to stop.
- **Deliverable:** `Aiur.VoiceConversation.StatusCard.build(target, ports) -> %{version,
  observed_at, text, fields, stale: [field]}` (PROPOSED) and `diff(old, new) -> [line]`.
  - Worker target fields: ticket id/title; phase and percent (bare `progress`); the agent
    status note (C10-T01) with its age; PR number, CI state, review state; open Commands
    (question + options); last 5 milestones; the last operator message and whether the agent
    has consumed it (`AgentChat.delivery_status/2`); listener mode (MP-E7).
  - Executor target: active agents with one line each (their notes' `doing`), blockers, open
    Commands count + top 3, build-order progress.
  - `ContextBuilder` (C4-T03) puts the card first, then the existing blocks in the remaining
    budget (raw message tail becomes a tool result, `get_details`, not start context).
  - `LiveContext` (C4-T05) recomputes the card on each relevant event, and sends only the
    changed lines as one `contextual_update` ("Card v7: CI is now green; next: open the PR").
    It keeps the 5 s coalescing rule.
- **Non-goals:** any LLM call to summarise. The card is deterministic text built from data
  aiur already holds (no new data processor; works when the agent is mid-turn).

## Dependencies and blockers

- **Predecessors:** C10-T01 (note), C4-T03 (builder), C4-T05 (live updates).

## Verified starting point (base `0972f0297`)

- Status and progress data: `Aiur.Orchestrator.StatusReport` (`orchestrator/status_report.ex`).
- Delivery receipts: `Aiur.AgentChat.delivery_status/2` (`agent_chat.ex:63-80`): `:pending`,
  `:delivered`, `:consumed`.
- Bus: `Aiur.Events.Exchange.subscribe/2` (`events/exchange.ex`).

## Chosen design

- Size target 1,500 tokens (`div(byte_size, 4)`); drop milestones first, then Command options,
  never the note, the PR/CI line or `asks`.
- Each field carries `observed_at`; a field older than its freshness limit (note 10 min, CI
  2 min) is listed in `stale` and the text says "(as of 12 min ago)". The assistant prompt
  (C4-T04 role) says: state the age when you answer from a stale field.
- The card text is written to the transcript as a `context` record before the provider sees it
  (contract §9), like every other block.

## Amendment 2026-10-09 — independent package

Source: [../plan.md](../plan.md) §17. Kevin, 2026-10-09: build the voice assistant as "its own
independent package that can be used separately from [aiur]". The core is the Mix project
`packages/elixir/voice_converse/` (OTP app `:voice_converse`, namespace `VoiceConverse.*`).
It has no `Aiur.*` reference, and aiur is one host behind ports (§17.4). Module moves:
plan §17.9. Core tests run with `env -C packages/elixir/voice_converse mise exec -- mix test`
and do not boot aiur.

- **Split.** Generic code moves to the core as `VoiceConverse.Briefing`: the struct, `render/2`
  (1,500-token target, drop order), `diff/2` (changed lines only), and staleness ("as of …").
  Its tests ("only the changed line", "15-minute-old field marked stale", size) become core tests.
- aiur keeps `Aiur.VoiceConverse.Host.BriefingSource`, which fills the struct. Worker
  targets use the status note (C10-T01), phase/percent, PR/CI/review, open Commands, the
  last 5 milestones, the delivery status of the last operator message, and the listener
  mode. Executor targets use active agents, blockers, Commands and build-order progress.
  The test "no note yields the fallback line" stays here and puts "no note from the agent
  yet" in `Briefing.gaps`.
