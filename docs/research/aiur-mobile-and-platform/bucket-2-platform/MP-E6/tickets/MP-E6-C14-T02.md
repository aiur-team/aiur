# MP-E6-C14-T02 — OpenAI native voice adapter

Plan: [../plan.md](../plan.md) §20. Research: [../talk/research.md](../talk/research.md) §1, [../realtime-convo-research.md](../realtime-convo-research.md) §3.1–§3.2.

## Identity and outcome

- **User value:** a user (aiur or `/talk`) with only an OpenAI API key gets a native speech-to-speech conversation with no other vendor.
- **Deliverable:** two adapter modules over one shared helper (changed in plan pass: `descriptor/0` and `capabilities/0` take no arguments, so one module cannot declare two option ids with different capabilities):
  - `VoiceConverse.Provider.OpenAI.Common`: WebSocket client, `Credentials.fetch(:openai, :connect)` at connect (key never in state), error mapping to `Events.Error` codes, the storage guard, and 16 kHz ↔ 24 kHz PCM resampling (OpenAI accepts only 24 kHz PCM or G.711; C2-T01 `session_spec` uses `audio_in: :pcm_16000`).
  - `VoiceConverse.Provider.OpenAILive` (`openai_live`): GPT-Live 1 on `v1/live/sessions` over a server-side WebSocket. **Responses delegation** (changed in plan pass, was "client delegation"): the session tool specs go in `delegation.responses.tools`; function calls arrive as `response.output_item.done` inside the `response.event` envelope and become `ToolCall`; `tool_result/3` sends `response.item.create` (`function_call_output`) then `response.create`. `announce/3` sends `session.commentary.append` (≤ 500 tokens; longer text is cut at a sentence end); `send_context/2` sends `session.thinking.append`. GPT-Live owns turn-taking (no manual truncation or turn-detection setting, research §1.1b), so `capabilities/0` declares `manual_truncation: false`. GPT-Live has no end-of-response frame, so the adapter ends a turn (final `AgentText`) after a configurable audio silence (default 700 ms).
  - `VoiceConverse.Provider.OpenAIRealtime` (`openai_realtime`): `gpt-realtime-*` (default `gpt-realtime-2.1`) over the Realtime WebSocket, GA shapes (no `OpenAI-Beta` header); `conversation.item.create` + `response.create` for `announce/3`; `semantic_vad`; barge-in: `input_audio_buffer.speech_started` emits `Interruption`, and `truncate/3` (C13-T05, `manual_truncation: true`) sends `conversation.item.truncate` with `audio_end_ms = played_until_ms`.
  - Event mapping to the C2-T01 structs, including `AgentTextTiming` (C13-T05, `from_text_deltas/2`, `estimated: true`) from output transcript deltas.
  - Privacy: provider storage off. `store: false` is sent where the protocol documents the field (GPT-Live session). A config that turns storage on is refused (plan §17.11). Where no storage field exists, the descriptor states the provider retention terms instead of sending an unknown field.
  - `descriptor/0` for C14-T01 in each module; `price_hint` for `openai_live` says the backend model is billed on top of USD 0.05/min.
- **Non-goals:** browser-direct WebRTC with ephemeral keys (rejected: plan §3 daemon relay; research §1 notes it as a later latency option); OpenAI cascade parts (C14-T05).

## Plan pass (2026-10-10)

**Key decisions**

- Two modules (`OpenAILive`, `OpenAIRealtime`) over `OpenAI.Common`. Reason: `descriptor/0` and `capabilities/0` have arity 0 and C14-T01 expects one `id` per descriptor; the two protocols also differ in turn-taking and truncation (research §1.1).
- GPT-Live uses Responses delegation with our function tools. Reason: in client delegation, `session.delegation.created` has no task text (live-delegation guide, checked 2026-10-10), so the core would need its own model to choose tools. Responses delegation gives `call_id`/`name`/`arguments`, which map straight to `ToolCall`. Client delegation (for example a Claude backend) is a later option.
- `announce/3` on GPT-Live is `session.commentary.append`; `send_context/2` is `session.thinking.append`. Reason: commentary is spoken and thinking is silent context, which match the two callbacks; both are capped at 500 tokens, so the adapter cuts at a sentence end.
- Resampling lives in the adapter (`OpenAI.Common`), linear, 16-bit mono. Reason: OpenAI takes only 24 kHz PCM or G.711, and the C2-T01 contract fixes `audio_in: :pcm_16000`. C14-T03 (Gemini, 24 kHz out) can reuse the helper.
- GPT-Live turn end comes from a silence timer (default 700 ms after the last audio delta). Reason: GPT-Live sends no end-of-response frame (research §1.1b), and the session and C13-T05 need a final `AgentText`.
- Storage: send `store: false` only where the protocol documents it; refuse `store: true` in config. Reason: plan §17.11 and R22 ("off where the provider allows it"); an unknown field can make the provider reject the session.

**Risks**

- GPT-Live has no documented interruption frame (live-delegation guide names none) → the AC accepts a declared missing `Interruption`; the client then stops playback on its own speech detection (C13-T04). The manual run records whether a frame exists, and the fixture follows the capture.
- Backend Responses calls may store data by default (the guide names no store setting for the backend) → the manual run checks the dashboard logs for stored responses; if they are stored, the descriptor `privacy` says so and the doctor output (C13-T02) shows it. Executor records the result in the PR.
- Delegated work continues after an interruption ("Live speech and delegated work continue independently") → the adapter tags each `ToolCall` with the turn and the core de-duplicates by `call_id`; a result for a cancelled turn goes through `send_context/2`, not `announce/3`.
- Session limits (Realtime 60 min; GPT-Live max not published) → on a provider close the adapter emits `Closed{reason: :provider_session_limit}`; the session shows it and the user starts again. No silent reconnect in v1.
- Fixtures drawn from docs can differ from live frames → the manual run saves a redacted capture, and the fixtures are updated from it before merge.

**Test strategy**

- Unit, fakes only: frame encode/decode and event mapping per module against documented-frame fixtures through `ProviderConformance`; a fake WebSocket transport (the `Realtime.Transport` seam pattern) records sent frames; `Testing.StaticCredentials` with a sentinel key. Cases: tool round trip, announce, context, interruption and truncate (Realtime), silence turn end (Live), `store: true` refusal, missing key → `provider_auth`, resampler length and round trip (property test).
- Secret guard: `ExUnit.CaptureLog` over a full fixture session, `:sys.get_state/1` of the adapter process, and `inspect/1` of every emitted event must not contain the sentinel.
- No browser test in this ticket; the page path is covered by C13-T09 end to end with this adapter.
- Manual (operator, at review): one 2-minute session per option id with a real `OPENAI_API_KEY`; cap USD 1 total (about USD 0.10 GPT-Live minutes plus backend tokens, plus `gpt-realtime-2.1` audio tokens). Record time to first audio, whether an interruption frame appeared, and the redacted capture.
- Mutation guards: (1) map `input_audio_buffer.speech_started` to nothing → "interruption stops playback" fails for `openai_realtime`; (2) drop the silence timer → the Live turn-end case fails; (3) let `store: true` through → "store true is refused" fails.

**Open points**

- C2-T01 `audio_out` allows `:pcm_16000 | :pcm_44100` only; OpenAI and Gemini produce 24 kHz. Adding `:pcm_24000` would remove output resampling. Decided by the C2-T01 implementer; until then this adapter resamples to the requested format.
- Default GPT-Live backend model (cost and latency trade-off, billed on top of USD 0.05/min). The implementer picks the fastest documented Responses model and puts it in config; Kevin may change the default.
