# MP-E6-C12-T01 — Executor session registration

Plan: [../plan.md](../plan.md) §18.1. Kevin, 2026-10-10 (verbatim): "ensure the voice convo
mode code is also accessible for the executor agent to use and fork itself so that the user
can chat with the executor".

## Identity and outcome

- **User value:** aiur knows which harness session is the live Executor, so a voice session
  (and later handoff, the roster and side questions) can fork it. Useful alone: the roster
  shows which session owns the wake stream.
- **Deliverable:**
  - One function `Aiur.Executor.HarnessSession.detect(env)` that reads
    `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CONFIG_DIR`, `CLAUDE_PID` and
    `CLAUDE_CODE_CHILD_SESSION` (observed on Claude Code 2.1.296; not documented, so keep the
    names in this one module with a fixture test). It returns `nil` for a child session.
  - `aiurdev executor-wait --session-id <uuid> [--harness codex]` for Codex and as an
    override.
  - The owner's claim entry (`Aiur.Executor.Claims`) gains an optional `session` object:
    `harness, session_id, config_dir, cwd, harness_pid, recorded_at`. Observers never write
    it. Renew keeps it; a new session id replaces it.
  - `aiur executor-session [--json]` and an RPC read. A handle with a dead `harness_pid` or
    an expired lease reads as `unknown`.
- **Non-goals:** forking (C12-T02); any voice code.

## Acceptance criteria

- [ ] An owner `executor-wait` from a Claude Code session records the session object.
- [ ] A subagent (`CLAUDE_CODE_CHILD_SESSION` set) or an observer never writes it.
- [ ] `--session-id` records a Codex session; an invalid UUID is refused.
- [ ] `aiur executor-session --json` prints the handle, or `{"state":"unknown","reason":…}`.
- [ ] The claim file stays readable by the current build (additive field).

## Verification
