# MP-E6-C14-T04 — Cascade adapter

Plan: [../plan.md](../plan.md) §19.3, §20. Requirements: R4, R13, R20.

## Identity and outcome

- **User value:** a user whose model provider has no native voice API (Anthropic Claude today, research §1.3) talks with that provider's own model. Text-only mode needs no speech vendor at all.
- **Deliverable:** `VoiceConverse.Provider.Cascade` (option ids `cascade`, `text_only`):
  - Turn engine: final user text in → streamed model reply → sentence-chunked text out (and to TTS when a TTS part is set). Barge-in cancels the model stream and the TTS stream.
  - Model backends behind `VoiceConverse.Cascade.LLM`: `anthropic` (Messages API streaming with tool use), `openai` (Responses streaming), `gemini` (generateContent streaming). The tool set and the briefing are the same as for speech-to-speech providers.
  - Client-side parts: `:browser_stt` and `:text_in` (the page sends final user text; partial text is display-only), `:browser_tts` (the page speaks the text; the host sends text with sentence boundaries), `:none`.
  - `AgentTextTiming` (C13-T05): for `:browser_tts` the host sends one sentence per frame with `chars: nil, estimated: true`; the page speaks each sentence and reveals it locally from `SpeechSynthesisUtterance` boundary events. No new client frame: on barge-in the page sends `playback_state{stopped, turn_id}` (C13-T05), and the session records all text sent so far with `interrupted?: true`. For `:none` text streams at arrival.
  - Barge-in path: the adapter declares `manual_truncation: true`. `truncate/3` (C13-T05) and a new `send_user_text/2` during a reply both cancel the model stream (and TTS), emit `Interruption{turn_id}`, and keep only the sent text of the cut reply in the in-memory history.
  - Privacy (R22, plan §17.11): OpenAI Responses requests set `store: false` and send the full history each turn (no `previous_response_id`). History lives in process memory only. The descriptor privacy facts state, per backend, whether the provider keeps request data, and that `:browser_stt` may send audio to the browser vendor (research §2.1).
  - Usage: each model response emits `:telemetry` `[:voice_converse, :cascade, :usage]` with input and output tokens and the model id, so the host can show a running cost (R23).
  - `descriptor/0` lists parts and which credentials each needs.
- **Non-goals:** server STT/TTS vendors (C14-T05); local Whisper (out of v1 scope, requirements).

## Acceptance criteria

- [ ] Passes `ProviderConformance` (text cases; audio cases skipped when no audio part is set, and the skip is declared in `capabilities/0`).
- [ ] With `anthropic` and `:text_in`, a scripted turn streams text deltas and executes one tool round trip (fake HTTP).
- [ ] A user message during a streaming reply cancels the stream (no further deltas after `Interruption`).
- [ ] `text_only` needs no credential beyond the model's.
- [ ] An OpenAI Responses request body contains `store: false` and no `previous_response_id`.
- [ ] One user turn makes at most `max_tool_rounds` model calls (default 4); the next call is refused with a spoken or written "I could not finish that" text, not a loop.
- [ ] Each completed model response emits one usage telemetry event with token counts.
- [ ] Partial (non-final) user text never starts a model call.
- [ ] Manual (operator, at review, cost cap USD 0.50): one text-only session with an Anthropic key (`claude-haiku-5-5`); record first-token time.

## Plan pass (2026-10-10)

**Key decisions**

- The HTTP streaming goes through a small seam, `VoiceConverse.Cascade.HTTP` (behaviour), with a Mint implementation and a scripted fake. Reason: the core may use only `mint`, `mint_web_socket`, `jason` and `telemetry` (plan §17.2), and the "fake HTTP" criterion needs a seam that tests can drive without a network.
- One shared SSE parser and three small backend modules that map vendor events (Anthropic `content_block_delta`/`input_json_delta`, OpenAI `response.output_text.delta`/function call items, Gemini `streamGenerateContent?alt=sse` parts) to one internal stream: `{:text, delta} | {:tool_call, id, name, args} | {:usage, map} | :done`. Reason: the turn engine, barge-in and tool loop are written once; a vendor change touches one mapper.
- Barge-in uses the C13-T05 `truncate/3` callback (`manual_truncation: true`) plus "new user text cancels". Reason: no new wire frame and no new behaviour callback; the cascade owns turn-taking, so it must cancel itself.
- `:browser_tts` gets no server-side timing. Reason: C13-T05 adds no client frame for boundary events, and the page already has them locally. The cost is a coarse heard prefix on barge-in (all sent text), which C13-T05 already accepts as the fallback.
- Default model per vendor comes from `Config.providers.cascade.llm` (`"<vendor>:<model>"`, C14-T01); the default for a Claude user is `claude-haiku-5-5` (E6-OQ7, plan §19.8). Do not send `temperature` to Haiku 5.5, and use the lowest effort setting the API accepts for it (research §1.3). Reason: first-token time is the latency budget (plan §17.11, 0.8 s median).
- A per-turn tool round cap (`max_tool_rounds`, default 4). Reason: a model that keeps calling tools would loop and spend money without a user action.

**Risks**

- Vendor SSE shapes change or the documented examples differ from live output → fixtures come from the vendors' documented examples, the parser ignores unknown event types, and the Anthropic manual run captures one real stream (redacted) as a new fixture.
- Cancel does not stop billing at once (the provider keeps generating until the socket closes) → close the Mint connection, not only drop events; the usage event for a cut reply reports what the provider returned, or `:unknown`.
- Text sent to the page after `Interruption` (a late delta in the mailbox) → tag each stream with a turn ref and drop deltas whose ref is not current; the barge-in test checks the owner mailbox after the cancel.
- A slow tool (fork query, seconds) blocks the turn → the tool result arrives through `tool_result/3` like the other families; the model stream for that turn stays open-ended only to `turn_timeout_seconds` (plan §17.6), then the turn ends with a short text.
- Keys leak into logs through an error body or a request struct → fetch with `Credentials.fetch(:anthropic, :connect)` at request time, put the key only in the header list, and reduce HTTP errors to `Events.Error` codes (C2-T01 rule).

**Test strategy**

- Unit tests with fakes, no network, no key, cost zero: `test/voice_converse/provider/cascade_test.exs` and `test/voice_converse/cascade/llm/*_test.exs`. They use the fake `Cascade.HTTP` that replays SSE fixtures, split at random byte points (StreamData), plus `Testing.StaticCredentials` and `Testing.FakeProvider`-style owner capture. They cover: text deltas, one tool round trip per backend, barge-in by `truncate/3` and by new user text, tool round cap, `store: false`, usage telemetry, partial text ignored, sentence chunking for `:browser_tts`, and `ProviderConformance` text cases with audio cases skipped through `capabilities/0`.
- Integration: one session test with the real session and the cascade on the fake HTTP, so `Interruption` → `playback_state{stopped}` → transcript `interrupted?: true` works end to end. Browser behaviour (speech synthesis, Web Speech) is tested in C13-T04 with Playwright against a scripted server, not here.
- Manual with a real key: the operator runs one text-only session with `ANTHROPIC_API_KEY` and `claude-haiku-5-5`, about 10 turns and one tool call, cost cap USD 0.50 (expected under USD 0.05 at USD 0.10/0.50 per MTok). Record first-token time per turn in the PR. OpenAI and Gemini backends are fixture-only in this ticket.
- Mutation and regression guards: (1) ignore the cancel on interruption → "barge-in cancels the model stream" fails. (2) Remove `store: false` → "openai responses does not store" fails. (3) Start a model call on partial text → "partial text does not start a turn" fails.
