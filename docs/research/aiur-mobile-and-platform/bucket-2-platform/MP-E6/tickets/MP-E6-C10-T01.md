# MP-E6-C10-T01 — Agent status note

Research: [../realtime-convo-research.md](../realtime-convo-research.md) §5–§6 (the
"status card" flow that replaces "halt and dump").

## Identity and outcome

- **Bucket / feature / chunk:** 2-platform / MP-E6 / C10 fast path over a slow agent.
- **User value:** when the operator opens Converse, the voice assistant can answer "what are
  you doing and why" in about one second from a note the coding agent already wrote. Nothing
  has to stop the coding agent or ask it to summarise itself while the operator waits.
- **Deliverable:**
  1. A status-note protocol on the existing `emit_event` tool, so no new tool is needed:
     `emit_event(name: "progress.status", message: <one line>, payload: %{doing, why, next,
     waiting_on, asks, risks, pr, updated_reason})`. Each field is a short string; the whole
     payload is at most 1,200 bytes. The published topic is
     `ticket.<id>.agent.progress.status` (`codex/dynamic_tool/emit_event.ex:12-25` already
     allows `progress.<slug>`).
  2. A validator that rejects an oversized or malformed note with a tool error naming the
     limit, and redacts it with `Aiur.SecretRedactor` before it is published.
  3. A durable "latest note" per ticket session (PROPOSED: kept by the same store that keeps
     the bare `progress` sample, with `version` (monotonic) and `observed_at`). A read
     function `Aiur.AgentStatusNote.latest(ticket_ref) -> {:ok, note} | :none`.
  4. Prompt text in `src/prompts/shared-agent-instructions.md` (beside "Progress emits"):
     write or update the note (a) at each phase boundary, paired with the existing progress
     emit; (b) before a step you expect to take more than about 3 minutes (long test run, big
     refactor); (c) when you open a Command; (d) at the end of each turn; (e) when Aiur asks
     for a refresh (`status.refresh` request, MP-E6-C10-T04). Keep it true, short, and in
     plain words; never paste logs.
- **Non-goals:** the voice assistant itself; the status card (C10-T02); changing the bare
  `progress` 2-per-turn cap (the note has its own cap: 6 per turn, the 7th is rejected).

## Dependencies and blockers

- **Predecessors:** MP-R2-C5-T01 (topic catalog registers `ticket.<id>.agent.progress.status`).
- **Concurrency:** independent of every other E6 ticket; it can land first. It also helps the
  Executor and the phone home view, which can show the note.

## Verified starting point (base `0972f0297`)

- `emit_event` vocabulary includes `progress.<slug>` and publishes
  `ticket.<issue>.agent.<name>` (`src/lib/aiur/codex/dynamic_tool/emit_event.ex:12-40`).
- Progress cadence and the 2-per-turn cap are agent instructions
  (`src/prompts/shared-agent-instructions.md:106-135`).
- Agents already keep one `## Agent Workpad` comment (`.claude/skills/aiur-agent/SKILL.md:35`);
  the note is the short, machine-readable head of that workpad, not a replacement.

## Chosen design

| Field | Meaning | Max |
| --- | --- | --- |
| `doing` | what the agent is doing right now | 200 B |
| `why` | the reason or the plan step it serves | 200 B |
| `next` | the next 1–3 steps | 200 B |
| `waiting_on` | CI, review, a Command, nothing | 120 B |
| `asks` | what the agent wants from the operator, or empty | 200 B |
| `risks` | what may go wrong or what it is unsure of | 160 B |
| `pr` | PR number or empty | 16 B |
| `updated_reason` | `phase`, `long_step`, `command`, `turn_end`, `refresh` | enum |

## Non-happy paths

- An agent never writes a note (old prompt, other harness): the status card (C10-T02) falls
  back to daemon-derived fields and says "no note from the agent yet".
- A note older than the agent's last 3 tool calls or 10 minutes is marked `stale` by the
  card, not hidden.
