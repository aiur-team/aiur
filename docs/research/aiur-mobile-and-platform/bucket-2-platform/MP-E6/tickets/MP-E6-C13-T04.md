# MP-E6-C13-T04 — Conversation page v1

Plan: [../plan.md](../plan.md) §19.5. Requirements: R9–R14. Research: [../talk/research.md](../talk/research.md) §2, §4.

## Identity and outcome

- **User value:** the user clicks the link and sees a page like ChatGPT voice mode: speak and see your words live, hear the assistant and watch its words appear letter by letter, interrupt by talking, or switch to typing.
- **Deliverable:** one page (`priv/static/talk.html` + CSS) and an extension of the package JS client that C11-T02 created (`priv/static/voice_converse_client.js`, plain JS ES module, no build step). The talk host serves the page; aiur's panel (C7-T02) reuses the client:
  - States: connecting, listening, thinking, speaking, consulting, reconnecting, ended, error (voice-session §6), one large indicator, mute, end.
  - Voice mode: `getUserMedia` only after the user presses Start (no prompt on page load); echo cancellation, noise suppression and auto gain on; AudioWorklet capture to 16 kHz PCM; assistant audio played through an `<audio>`-backed path (research §2.4: Chromium echo cancellation does not cover Web Audio output).
  - Live user text from provider partials, or from the browser Web Speech API when the option uses `:browser_stt` (prefer `processLocally` where available; say on the page when audio goes to the browser vendor's cloud).
  - Letter-by-letter reveal driven by `AgentTextTiming` (C13-T05) against the audio playback clock; without timings, reveal at arrival.
  - Barge-in: an `interrupted` frame, or `speechstart` from browser speech recognition (`:browser_stt` only), stops playback within 150 ms and truncates the revealed text at the stop point. The client then sends `played_until_ms` (C13-T05) and `playback_state{stopped}`.
  - Text-only mode: no microphone; a focused textarea that keeps focus (works with OS dictation tools); Enter sends; replies stream as text; optional "speak replies" toggle (browser speech synthesis or a TTS part).
  - Draft cards with Confirm, Edit, Discard; Confirm sends `confirm_draft` with `origin: client`. Edit is local to the card; Confirm after Edit sends `confirm_draft{draft_id, edited_text}` (voice-session §5.3).
  - Status line: provider option, cost estimate, cap remaining, "answer from a summary" note when the fork is a replay. Data comes from a new server-to-client frame `session_info{option_id, label, cost_estimate_usd?, session_seconds_left?, minutes_left_today?, fork_mode?: "native" | "replay"}`. This ticket adds the frame to `VoiceConverse.Wire`, to voice-session §3.4/§13, and to the session (sent at start, at each turn end and after each fork answer). The page hides a field that is absent.
  - Works at 360 px width; keyboard reachable; colour tokens for light and dark.
- **Non-goals:** aiur dashboard panel (C7-T02 reuses the client); transcript history views (C8 for aiur; the talk host lists files only).

## Acceptance criteria

- [ ] Confirm sends exactly one `confirm_draft` per draft (double click test).

- [ ] Edit then Confirm sends `confirm_draft` with `edited_text`; Discard sends `discard_draft`.
- [ ] `session_info` round-trips through `VoiceConverse.Wire` (golden fixture); the page hides absent fields.

## Plan pass (2026-10-10)

**Key decisions**

- Extend the C11-T02 client. Do not write a second client. Reason: C11-T02 already owns capture, the playback queue and draft cards, and C7-T02 must reuse one file.
- Play assistant audio through an `AudioContext` scheduler whose output goes to a `MediaStreamAudioDestinationNode`, then to an `<audio>` element (`srcObject`). Reason: the scheduler gives gapless PCM and one playback clock (`AudioContext.currentTime`); the media element is the path that Chromium echo cancellation covers (research §2.4). Fallback: WAV-wrapped chunks on a plain `<audio>` element if the manual echo check fails.
- Read the output sample rate from the provider metadata. Do not hard-code it. Reason: ElevenLabs, OpenAI and Gemini send different rates (voice-session §3.4 `audio` row).
- Barge-in triggers are the `interrupted` frame and, for `:browser_stt` only, `SpeechRecognition` `speechstart`. There is no client energy VAD in v1. Reason: an energy gate hears leaked assistant audio and interrupts itself.
- Reveal text from the `agent_text_timing` offsets against the playback clock. When `estimated: true` or no timing exists, use the C13-T05 estimate or reveal at arrival. Reason: only ElevenLabs gives character timing (research §1.6).
- Browser tests run in the core package (`test/browser/`, Playwright + `@axe-core/playwright`) against a test-only Bandit host in `test/support/`. That host serves `priv/static` and either a scripted frame server or `VoiceConverse.Transport.WebSock` with `FakeProvider`. Reason: the page must not depend on aiur's `src/browser` harness (§17.2 independence), and C11-T03 is not an ancestor of this ticket.

**Risks**

- The `MediaStreamDestination` to `<audio>` route may not get echo cancellation in some Chromium version → manual check with speakers (not headphones) on Chromium and Safari; if the assistant interrupts itself, switch to the WAV-chunk fallback and record the result in the PR.
- Timing tests flake on a busy CI runner → measure against `AudioContext.currentTime` read inside the page, not wall time; assert on the 100 ms and 150 ms budgets with three samples and take the median.
- Headless Chromium has no microphone → launch with `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`; install a `getUserMedia` spy with `addInitScript` before page scripts run.
- Live updates steal focus from the textarea and break OS dictation (research §2.3) → write streamed text only to non-focusable nodes; use `aria-live="polite"` on one region; never set `value` on the textarea from code after the user types.
- The `session_info` frame touches the core codec and the session → keep all fields except `option_id` and `label` optional; the session fills only values it already holds (limits, `TranscriptIndex.minutes_today`, fork `mode`). The cost estimate is present only when the provider descriptor has a `price_hint` (C14-T01).

**Test strategy**

- Unit (ExUnit, fakes): `session_info` Wire golden fixture; the session emits `session_info` at start, at turn end and after a `FakeAgentChannel` fork answer with `mode: :replay`.
- Browser (Playwright, scripted frame server, no keys): no mic before Start; text mode has no mic; letters follow the audio clock (≤ 100 ms); barge-in stops audio (≤ 150 ms) and sends one `played_until_ms`; double confirm sends one frame; Edit then Confirm sends `edited_text`; textarea focus kept; axe at 360 px and 1280 px in light and dark; no horizontal scroll at 360 px.
- Browser smoke (Playwright, real `WebSock` + `FakeProvider`): one full turn and `ended{user_end}`.
- Manual (operator, at review, real keys): one voice session with ElevenLabs or OpenAI on Chromium with speakers (echo check, barge-in feel), one `:browser_stt` cascade session, one text-only session with OS dictation. Cost cap USD 1 in total; record results in the PR.
- Regression and mutation guards: reveal all text at once → the letter timing test fails. Remove the `played_until_ms` send → the barge-in report test fails. Remove the confirm-button disable → the double-confirm test fails.

**Open points**

- The CI job for the package (C11-T01) must gain a Node + Playwright step for `test/browser/`. The C11-T01 owner or the Executor decides if it is a separate job.
- Who computes the cost estimate when no `price_hint` exists (session or host)? C14-T01 owner decides; until then the page hides the field.
