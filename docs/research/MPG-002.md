# MPG-002 — Add projects, capacity and coordination sections to the machine config: research

Deep dive for MPG-002 (#7604), research ticket MPG-002R (#7582). Plan:
`docs/plans/2026-11-06-multi-project-gateways.md` (PR #7579), state schema S3 in
`docs/plans/2026-11-06-multi-project-gateways/state-schemas.md`, contract in `tickets-m0-m1.md`.
Code references are to `origin/main` at `26ec6e00d`.

## Outcome

`~/.aiur/machine` accepts three new top-level sections, `projects:` (a list), `capacity:` and `coordination:`.
`Aiur.Machine.Settings.load/0` and `get/0` return them as typed structs with defaults. Unknown keys inside them,
bad repo names, relative config paths, `capacity.max_agents: 0` and similar return
`{:error, {:invalid, [{path, message}]}}` naming the key and never the value. Nothing reads the sections yet. The
existing `mobile`, `gateway`, `pairing`, `transport` sections behave exactly as before.

## Design

### Final key names and defaults

```yaml
projects:                       # default []
  - repo: owner/name            # required
    config: /abs/or/~/path/.aiur/config   # required; see "Privacy"
    max_agents: 8               # optional, integer >= 1, default null (no project ceiling)
    priority: 1                 # optional, integer >= 0, default null (unranked)
capacity:
  max_agents: 12                # optional, integer >= 1, default null (no machine ceiling)
coordination:
  database_url_env: AIUR_LEASE_DATABASE_URL   # default shown; the NAME of an env var, never a URL
  offline_after_seconds: 180                  # integer, 30..86400, default 180
```

Names are the S3 names unchanged. Reasons for each choice:

| Key | Decision | Reason |
|---|---|---|
| `projects[].repo` | `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$`, required | The contract rejects "no slash"; the regex also rejects empty halves, spaces and a third segment. GitHub names are case-insensitive, so uniqueness is checked case-insensitively. |
| `projects[].config` | required, absolute, `~/` expanded | See Privacy. A project with no config path has nothing to load (MPG-301). |
| `projects[].max_agents` | `>= 1`, null by default | Plan L1 rule: caps L3 `agent.max_concurrent_agents`. Null means "no extra cap", not 0. `0` is rejected like `capacity.max_agents: 0`; to stop a project, remove it. |
| `projects[].priority` | integer `>= 0`, null by default; **lower number is served first** | Matches the S3 example (`priority: 1`) and "rank" reading; MPG-402 compares it only when shared intent was never reached, and null sorts last. Allocation never rises with priority (MPG-401 rule). |
| `capacity.max_agents` | `>= 1`, **null by default** | Null = no machine ceiling, so a machine file without the key leaves today's `agent.max_concurrent_agents` behaviour unchanged. A non-null default would silently cap existing users. `--max-agents` (MPG-306) overrides at launch (plan L6). |
| `coordination.database_url_env` | env var **name**, default `AIUR_LEASE_DATABASE_URL`, must match `^[A-Z_][A-Z0-9_]*$` | The existing store reads that variable (`lease_store.ex:494`). Storing the name keeps the credential out of a file. The regex rejects a pasted `postgres://user:pw@...`, and the error message does not echo the value. |
| `coordination.offline_after_seconds` | integer `30..86400`, default 180 | Default is fixed by MPG-408. The lease TTL is 30 s (`lease_store.ex:12-15`), so a threshold below 30 would alert on a single missed renewal; one day is an upper sanity bound. |

Cross-field rule: a project `max_agents` above `capacity.max_agents` is **accepted**. The ceiling is a clamp the
capacity broker applies (MPG-307: "each project stays within `projects[].max_agents`" and the total within capacity);
rejecting it would make a valid machine file depend on a sibling key. `Validation` is per section today.

Rule that is checked across entries: duplicate `repo` (case-insensitive) and duplicate `config` after expansion are
errors on key `projects`, because two entries would double-dispatch one checkout.

### Privacy of `config:` paths

The file is `~/.aiur/machine`, mode 0600 in a 0700 directory, written by `Settings.write/1` via
`Aiur.Fs.atomic_write(..., mode: 0o600)` and outside every Git tree. A checkout path is machine-local and mildly
sensitive (it names user and project layout); it is not a credential. The design keeps it from spreading:

1. **Never in a value-bearing error.** Messages are static strings (`"must be an absolute path"`); the path in
   `Validation.errors/1` output is the key (`projects[0].config`), not the value. A test asserts the error list does
   not contain the fixture path.
2. **Never in `inspect`.** `Schema.Project` is declared `@derive {Inspect, except: [:config]}`, so `inspect(settings)`,
   a `last_error` log, a crash report or an `IO.inspect` shows `config` omitted. (`Settings` is also cached in
   `:persistent_term`; that is process-local, not exported.)
3. **Never in a summary or a shared record.** The gateway summary (S6) lists `repo` only; S4 shared intent keys on
   repo, never path; peers never see the path. This is a constraint on MPG-304/MPG-403/MPG-404, recorded here so those
   tickets' reviewers can check it.
4. **No credential in the file.** `database_url_env` stores a name. A test pins that a URL-shaped value is rejected.
5. **Mode is not newly enforced on read.** `load/0` reads a 0644 file today (`settings_test.exs:140-148` asserts it
   loads). Rejecting it would change the existing contract. Permissions are set on write; see open question 3.

Known limit: agents run as the same user and can read `~/.aiur/machine`. The paths are not secrets, so this is
accepted; it is the same exposure class as the reminder about the agent token file and is not widened by this ticket.

### Home of the code

The existing pattern: each section is an Ecto embedded schema under `schema/`, embedded from `schema.ex` with
`embeds_one(..., defaults_to_struct: true, on_replace: :update)`, cast by `Validation.cast/3`, unknown keys found by
`Validation.unknown_keys/3`. `scripts/check-config-docs.py` walks `embeds_one` **and** `embeds_many`
(`EMBEDS_RE`, line 97) in `schema/*.ex`, producing `machine:projects.repo` style keys with no `[]`.

Three findings the contract does not state, each needed for the acceptance to hold:

1. **`Validation.unknown_keys/3` ignores lists.** `nested_errors/5` recurses only `when is_map(value)`
   (`validation.ex:43`). A `projects:` list entry with a typo key would be silently dropped by `Map.take` in
   `cast`, violating "rejects unknown keys in them". Add a clause that, for an `embeds_many` field with a list value,
   recurses into each map element with prefix `projects[<i>].`.
2. **`Validation.errors/1` breaks on `embeds_many` errors.** `traverse_errors/2` returns, for a list embed, a list of
   maps (one per entry, `%{}` for valid entries). `flatten/2` (`validation.ex:63`) calls `Enum.map(value, &{path, &1})`
   on it, producing `{"projects", %{repo: [...]}}` tuples whose message is a map. Fix: when the list holds maps,
   flatten each with prefix `projects[<i>].` and skip empty maps. Without it `projects[].repo` without a slash would
   not "name the key" and `Enum.sort/1` or a caller doing string work would crash.
3. **File names.** The contract lists `projects.ex`; the checker resolves `embeds_many(:projects, Project)` to module
   `Aiur.Machine.Settings.Schema.Project` and the repo convention is one singular module per file (`gateway.ex`,
   `pairing.ex`). Use `project.ex` / `Schema.Project`, plus `capacity.ex` / `Capacity` and `coordination.ex` /
   `Coordination`. Also, the docs page is `reference/configuration.md` (the machine table is at lines 160-177),
   not `configuration-daemon.md`; the checker reads `configuration.md` and all `configuration-*.md`, so either would
   pass, but the table lives where the other `machine:` rows are.

Alternatives considered:

- *One `projects.ex` holding a nested module.* The checker slices a file per `defmodule`, so it would work, but it
  breaks the one-module-per-file convention. Rejected.
- *A map keyed by repo (`projects: {"o/r": {...}}`).* Gives uniqueness for free but departs from the plan's S3 shape
  and the contract's `projects[].repo` wording. Rejected.
- *Reading the sections from `Aiur.Config` workflow schema.* The machine file is the home by plan layer L1 and by the
  regression guard at `settings_test.exs:196` (`workflow.ex`/`config.ex` never mention `Aiur.Machine.Settings`).
  Rejected.

## Risks

- **Silent drop of list typos** (finding 1) and **crash or garbage in error formatting** (finding 2) are the two ways a
  naive copy of the `Gateway` pattern fails the acceptance. The "Unknown keys" and "Repo without slash" scenarios
  catch both; detect early by running them before writing docs.
- **`validate_required` on embed fields** with `Validation.cast(..., empty_values: [])`: an empty string `repo: ""`
  is not "empty" under that option, so the format regex, not required-ness, must reject it. Test `repo: ""` and
  `config: ""`.
- **`write/1` replaces lists wholesale** (`merge/2` merges only maps). A partial `write(%{projects: [one]})`
  drops the other projects. No caller exists yet; MPG-301's enrollment commands must read-modify-write the list.
  Documented in the doc row, not changed here.
- **Cache:** `get/0` caches by mtime/size/inode; the new sections ride the same cache, no change.
- **Config doc drift:** the docs checker passes on any inline-code mention, so a row with the wrong default would
  pass lint. Review the table against the schema defaults by hand.

## Open questions

| Question | Recommended default | What changes if answered differently |
|---|---|---|
| Does lower `priority` mean served first? | Yes; null sorts last | If higher-first, only the doc row and MPG-402's comparator flip; the schema is identical. |
| Should `capacity.max_agents` default to a number (for example the detected CPU envelope)? | No, null; the existing `agent.max_concurrent_agents` derivation stays the fallback | A numeric default would change behaviour for every machine file written by other features; MPG-307 would need to special-case it. |
| Warn or refuse when `~/.aiur/machine` is group/world-readable? | No in this ticket; set 0600 on write only (current behaviour) | A refusal breaks the existing loads-at-0644 test and users with a shared dotfile manager; a warning would belong to MPG-301 with a place to surface it. |
| Should `config:` also accept a repo root (checkout dir) and append `.aiur/config`? | No; require the full file path as in the contract | Accepting both adds an ambiguity (a directory named `config`); a later `aiur project add` command can accept a root and write the file path. |
| Reject duplicate `config` paths, not only duplicate `repo`? | Yes (cheap, prevents a double-dispatch) | If allowed, MPG-301 must dedupe on load instead. |
| Reject `projects[].max_agents` above `capacity.max_agents`? | No, accept and clamp in the broker | Rejecting couples two sections and makes `--max-agents` (launch flag) able to invalidate a valid file. |
| Add `projects[].enabled: false` for a temporarily parked project? | No (not in S3; omit a project by deleting its entry) | If wanted, one boolean field plus a doc row; MPG-301 would have to filter on it. |
| Keep `docs-app/reference/configuration.md` as the home of the rows, not `configuration-daemon.md`? | Yes | Either page satisfies the checker; moving only changes which topic page grows (daemon is 394 lines, near the 400 cap, so adding rows there would trip the size rule). |
