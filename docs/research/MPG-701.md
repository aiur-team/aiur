## Design

### Principles

1. **Evidence is a recording, not a claim.** Each test row has the command, output, and a numeric comparison to
   the expected value in this document. "Looked fine" is a fail.
2. **Cause every outage reversibly, with a dead-man timer**, so an agent that dies mid-test cannot leave a
   gateway cut off.
3. **Count duplicates from three independent sources** (ownership refs, per-gateway run records, GitHub PRs). One
   source can be blind to the failure it would show.
4. **Non-destructive tests first, destructive last, long soaks overlapped** with short tests that cannot disturb
   them.
5. **Probe tickets for outages; the real backlog for soaks.** Outage tests need deterministic work, so seed
   tiny probe tickets. A1 and A4 need the real backlog.

### Fault injection (safe, reversible)

All five faults go through one pattern: **arm a dead-man timer first, then cause the fault, then verify the fault,
then run the test, then undo and verify the undo.** Record the timer, fault and undo commands in the evidence file.

| Fault | Cause | Verify it took | Undo | Dead-man timer |
|---|---|---|---|---|
| F1 PC daemon down | on PC: `env -C <runtime checkout> scripts/aiurdev stop` after pausing and waiting for idle (`aiurdev pause`, `aiurdev agents` empty), or accept losing only probe-ticket agents | `aiurdev status` reports not running; from Nook `aiur gateway list` shows PC `offline` | `aiurdev --bg` on PC | `systemd-run --user --on-active=20m aiurdev --bg` (PC) |
| F2 Nook daemon down | same on Nook | from PC `aiur gateway list` shows Nook `offline` after `coordination.offline_after_seconds` (default 180) | `aiurdev --bg` on Nook | same, on Nook |
| F3 store down | **Default:** drop outbound traffic to the store host and port on the gateway under test: `sudo nft add table inet mpg701 && sudo nft add chain inet mpg701 out '{ type filter hook output priority 0; }' && sudo nft add rule inet mpg701 out ip daddr <store-ip> tcp dport <store-port> drop`. **If the store is self-hosted on a machine we own:** `sudo systemctl stop postgresql`. Never stop a managed or shared production database. For "Postgres down" in A5, cut both gateways. | `psql "$AIUR_LEASE_DATABASE_URL" -c 'select 1'` fails or hangs on each cut gateway; alert `system.instance.ownership_unknown` appears (code-confirmed name, `lease_store.ex:462`) | `sudo nft delete table inet mpg701`, or `sudo systemctl start postgresql` | `sudo systemd-run --on-active=15m nft delete table inet mpg701` |
| F5 store restart | Agents running on both gateways (2 probes each, long enough to span the test). Record `T_fault`, then restart the store: **self-hosted:** `sudo systemctl restart postgresql` (or `stop`, wait 60 s, `start`; run both variants, record each); **otherwise:** the F3 nft cut on *both* gateways for 60 s, then `sudo nft delete table inet mpg701` (drops connections without restarting the service). Never restart a managed or shared production database. | before undo: `psql "$AIUR_LEASE_DATABASE_URL" -c 'select 1'` fails on both gateways; after: succeeds on both within 60 s. `aiurdev agents` on each gateway lists the same agent pids as before `T_fault` | the restart is its own undo; if `select 1` still fails 15 min after `T_fault`, run the F3 undo and stop | `sudo systemd-run --on-active=15m nft delete table inet mpg701` (and `systemctl start postgresql` if self-hosted) |
| F4 peer port blocked | on the *calling* gateway: same nft table, rule `ip daddr <peer-ip> tcp dport <peer-aiur-port> drop` (use `reject with tcp reset` for the "fails promptly" variant and `drop` for the "times out" variant; record both) | `curl -m 3 https://<peer>/api/v1/gateway/hello` fails | `sudo nft delete table inet mpg701` | same 15 min timer |

Rules:
- Window arithmetic: `T_fault` hold times (A5 10 min, A6 10 min, F5 60 s) are inside the 15 min store/peer timers
  and the 20 min daemon timers, so no dead-man timer fires during a test. A hold longer than 12 min needs its timer
  re-armed first.
- Cut only the direction under test. Never cut GitHub (`api.github.com`) in MPG-701; the plan's "GitHub
  unreachable" row is out of the acceptance list.
- Before each fault, record `date -u +%FT%TZ` as `T_fault`; before each undo, `T_undo`. All "within N minutes"
  expectations count from these.
- Verify the undo: `nft list tables` has no `mpg701`; `psql ... 'select 1'` succeeds; `aiur gateway list` shows
  `online` on both sides.
- Do not run two faults at once.
- A fault that cannot be undone in 15 minutes is a stop condition: revert, record, and escalate to the Executor.

### How to count duplicates (A1, A5, A6, A9 and every fault)

A **duplicate** is a ticket on which two different gateways each ran an agent with overlapping lifetimes, or on which
two PRs from different gateways were opened for the same ticket inside the window. Expected count in every test:
**0**. Run all three counts; any non-zero is a fail, and a disagreement between them is a finding.

| Source | What it sees | Command sketch (window `[T0,T1]`) |
|---|---|---|
| S-ref: ownership refs (plan-defined, KTD-2) | two claims of one ticket at the same epoch, or an epoch that skipped without a recorded transfer | `git ls-remote origin 'refs/aiur/owners/*'`; per ref, `git log --format=%H <sha> -- owner.json` then `git show <commit>:owner.json \| jq -c '{ticket,epoch,previous_epoch,gateway_id,reason}'`. Duplicate if two commits share `epoch` with different `gateway_id`, or if `previous_epoch+1 != epoch` |
| S-run: per-gateway run records (code-confirmed files) | each gateway's own agent starts and ends | on each machine, from every workspace `logs/agent.ndjson` in the window and the analytics `ticket-record` attempts (`analytics/schema/ticket-record.v1.json`: field `attempts`); build `(ticket, gateway, start, end)` rows; duplicate if two rows with different gateways overlap in time. Reuse the query MPG-109R ships; add the cross-gateway join by copying both machines' rows to one directory |
| S-pr: GitHub | two PRs, or two push authors, for one ticket | `gh pr list --state all --search 'created:T0..T1' --json number,headRefName,body,createdAt`; group by `Closes #N`; duplicate if a ticket has more than one PR whose head branch was created by different gateways, or two `gateway:<label>` labels were ever applied (`gh issue view N --json labels` plus the issue events API) |

A ticket legitimately re-run on the **same** gateway (rework) is not a duplicate. A transfer (`reason: transfer`)
followed by a run on the new owner is not a duplicate if the old owner's run ended before the transfer's `at` or was
stopped by the fence (alert `ownership fence` raised, MPG-105).

The pass line for A1 is therefore: S-ref duplicates 0, S-run overlaps 0, S-pr duplicates 0, **and** at least 6
tickets dispatched in the window across both gateways (a soak with no dispatch proves nothing; see Risks).

### Restart cost: before and after

Definition. `gap_dispatch` = time from the restart command's start to the first agent start on the restarted
daemon, in minutes. Also record `T_stop_done`, `T_ready` (first `aiur status` success), `agents_before`,
`agents_after_adopted`, `agents_lost`.

*Before* (step 1, R0). On PC, with the pre-multi-project deployment mode and about 10 running agents:
1. `aiurdev agents --json > before.json`; `date -u` as `T_cmd`.
2. `aiurdev restart` **without** `--keep-agents` (today's default; the briefing's "20+ minutes" is this path across
   about 130 tickets).
3. Poll `aiurdev agents --json` every 15 s until the count is back to the pre-restart count or 30 minutes pass.
   `gap_dispatch` = first new agent start minus `T_cmd`; `time_to_full` = count restored minus `T_cmd`.
4. `agents_lost` = tickets in `before.json` not running at the end *and* not re-dispatched (expected: they are
   re-dispatched; so also record "restarted from scratch" = a new run id for a ticket that had one).

*After* (step 8, A8). With projects mode on and ~10 running agents across both projects:
1. `aiurdev agents --json > a8-before.json`.
2. `aiurdev restart --keep-agents`.
3. `aiurdev status --handoff --json > a8-handoff.json`; every ticket in `a8-before.json` appears in `adopted[]` with
   the same provider pid and session id, or in `fallback[]` with a reason (documented, `cli-operations.md` line 128).
4. `gap_dispatch` = first new agent start after `T_cmd` (not counting adopted agents).

Expected: `agents_lost == 0` (adopted + fallback with documented reason == before); `gap_dispatch` for A8 under
5 minutes (proposed bound; the code allows up to 120 s for the node name plus 100 s prepare, per
`cli-operations.md`). State both numbers next to "20+ minutes". If R0 does not reproduce 20 minutes, say so plainly
in the evidence; the briefing's figure was an estimate (`code-evidence.md` §1 row 15).

A8 is also run a second way: change project B's `workspace.root`, restart with `--keep-agents`, and check B's agents
fall back while A's are adopted (MPG-308's per-project fingerprint).

| Risk | Detect early | Fallback |
|---|---|---|
