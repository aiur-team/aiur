# MPG-405 — Reconcile shared intent deterministically: research

Plan: `docs/plans/2026-11-06-multi-project-gateways.md` ("Reconciliation"); contract: MPG-405 in
`docs/plans/2026-11-06-multi-project-gateways/tickets-m4-m7.md`; schema S4 in `state-schemas.md`; rules and worked rows
from `docs/research/MPG-403.md` (amendments A1-A3) and its executable oracle
`docs/research/MPG-403/reconcile_model.py`. Q4 (decided by Kevin): an Executor overrides a human change only with
`force: true`, a `reason`, and `supersedes` naming the human change that is current at that point in the fold.

## Outcome

`Aiur.Intent.Reconciler` folds any set of shared-intent changes into the same registers on every gateway, whatever the
arrival order or duplication. Every MPG-403 row gives its stated winner. Applying a remote change stores it and
recomputes registers but never touches the outbox. A remote change more than 60 s ahead of local time is held, raises
`system.intent.clock_skew` once, does not advance the local HLC, and applies once the clock passes it. No config key,
CLI command or user-facing surface changes.

## Design

**One pure module, two functions.** `Reconciler.fold(changes)` is the contract's `fold/1`: it holds nothing and equals
`fold(changes, [])`. `Reconciler.fold(changes, opts)` takes exactly two options: `now_ms` (integer; when absent nothing
is held) and `own_gateway` (binary; when absent no change is exempt from the hold). It does no I/O and reads no clock.
`fold/2` first drops held changes, then folds the rest.
`Reconciler.held(changes, now_ms, own_gateway)` returns the held subset so `Sync` can alert; it shares one predicate with
`fold/2`, so the two cannot disagree.

**Algorithm (a port of the model, not a redesign).**
1. Dedupe by `change_id` (first wins; the id is immutable, so copies are equal).
2. Drop invalid changes: `slot == "default"` and `field == "pause"` (A2). The writer API (MPG-404/406) also rejects
   these; the fold ignoring them is the defence for a store row written by a buggy peer.
3. Sort by `{hlc_wall_ms, hlc_counter, pause_rank, origin_gateway, change_id}` where `pause_rank` is 1 iff
   `field == "pause"` and `value_json == true` (A1). Plain tuple comparison; no clock, no `seq`.
4. Group by `{entity_kind, entity_key, field}`, each group a map of slots `%{human: nil, executor: nil, default: nil}`.
   Walk the sorted changes:
   - human `pause` with `false`: reset all three slots to `nil`, then store the change in `human` (rule 5);
   - executor with `force == true`, non-blank `reason`, and `supersedes` equal to the current human slot's `change_id`:
     set `human` to `nil` (rule 3). Any other executor change leaves `human` alone;
   - then `slots[slot] = change` (later replaces earlier within a slot, rule 2).
5. Effective value: for `pause`, `true` if any slot's value is `true`, else `false` (`nil` slots ignored); for every other
   field, the first non-nil of human, executor, default.
6. Output: `%{{kind, key, field} => %{effective: value, winning_change_id: id, slot: :human | :executor | :default,
   takeover: change_id | nil, slots: slots}}`. `winning_change_id` is, for `pause`, the paused change with the greatest sort
   key (else the highest-ranked non-nil slot); otherwise the effective slot's change. `takeover` is the executor change
   id when the winning executor change was a honoured forced takeover (so the dashboard can say "takeover"). This is a
   superset of the `aiur_intent_registers` columns, which stay a derived cache.

**Hold (rule 6, A3).** `held?(change, now_ms, own_gateway)` is true iff `change.hlc_wall_ms > now_ms + 60_000` and
`change.origin_gateway != own_gateway`. Strictly greater: 60 s ahead applies, 61 s is held (row 15, ticket acceptance).
Locally authored changes are never held: MPG-404's HLC is persisted and never moves backwards, so after a wall clock set
back 5 minutes our own new changes are legitimately ahead of `now`, and holding them would hide the operator's own
edits from themselves. A held change stays in `changes.ndjson` (the log is the complete set; held-ness is computed, not
stored) and is excluded from the fold only. It is not dropped and not clamped.

**Sync integration (`intent/sync.ex`).** One private `ingest(changes)` runs the four steps below; both entry points call
it, so they cannot drift. The pull path passes each pulled batch. `Sync.apply_remote/1` (MPG-406R's direct delivery of a
fleet pause to a reachable peer) passes one validated change, never touches the outbox, and returns
`{:ok, :applied | :duplicate | :held}`: `:duplicate` when `change_id` was already stored (step 1 is idempotent), `:held`
when the change is stored but held by step 2, else `:applied`. MPG-406 prints its `held (clock skew)` label from `:held`.
Steps for each ingest, in this order:
1. Store each pulled change with `Store.put_change/1` (idempotent by `change_id`); advance the `seq` cursor over all of
   them, held or not.
2. `held = Reconciler.held(all_changes, now, own)`; alert for each `change_id` not already in the in-memory
   `alerted` set; add it.
3. Call `Hlc.observe/1` (MPG-404) only for changes that are not held (A3).
4. Recompute `Reconciler.fold(all_changes, now_ms: now, own_gateway: own)` and `Store.write_registers/1`. Compare each
   register's effective value with the previous registers (read before the write); for each register whose effective
   value changed, broadcast `{:intent_register_changed, {kind, key, field}, effective}` on PubSub topic
   `"intent:registers"` (the app's existing PubSub; the implementer confirms its name). An unchanged refold broadcasts
   nothing. MPG-406 subscribes and maps `{"fleet", "fleet", "pause"}` to its `{:fleet_pause_changed, boolean}`; MPG-406R
   must say so (MPG-404R's "MPG-405 adds the notify" is satisfied here).
Recompute also runs on every sync tick, which is what applies a held change once the clock passes it; no extra timer.
Remote apply has no call into `Store.append_outbox/1`; only the writer that authors a local change does (rule 7).
The sync path is therefore the only new caller of the reconciler, and the outbox call count is asserted zero in a test.

**Alert.** `system.intent.clock_skew`, `needs_attention: true`, `severity: "warning"`, emitted through an injected
`emit_fun` exactly as `Aiur.GitHub.AppTokenRefresher.safe_emit/4` does
(`src/lib/aiur/github/app_token_refresher.ex:357`). Message names `origin_gateway`, `change_id`, and seconds ahead. One
alert per `change_id` per process; a restart while still held re-alerts once. A resolved event is not emitted
(the change applies silently when the skew passes). It needs a catalog entry in
`src/lib/aiur/events/catalog/system_entries.ex` beside the other `system.*` alerts.

**Alternatives rejected.**
- *Fold in `seq` (arrival) order*: differs per gateway; breaks convergence.
- *Clamp a far-future wall to `now + 60 s`*: the clamped change gets a different position on each gateway and every
  gateway's clamp changes with time; not deterministic. Hold is.
- *Persist held-ness / alerted set in a new file*: a fourth file for one dedupe flag; not worth it (open question 3).
- *Make `fold/1` take the clock*: breaks purity and the property test; the clock stays in `fold/2` as an explicit input.
- *Reducer inside the Postgres store*: then local-only mode could not fold; the log is the truth, SQL is transport.

exemption must fail "Own origin"; calling `observe/1` before the hold check must fail "HLC"; making `apply_remote/1` skip the hold check must fail

## Data and assets

Change ids in tests are fixed binaries (`"h1"`, `"e"`), not UUIDs; the fold treats `change_id` as an opaque binary
and compares it bytewise. `value_json` is an Elixir term after decode (a boolean for `pause`, a string for
`order_key`). Dates are injected via `now_ms` (no real clock, per the AGENTS.md time-bomb rule). Known gap: HLC wall
values are integers in milliseconds; the oracle uses small integers, tests do the same plus `n`-relative values for hold.

## Risks

- *Divergence between the Python oracle and Elixir*: both are small; the 15-row table is the shared check. A second
  guard is cheap: dump 20 random sets from the oracle as JSON fixtures and assert equal winners. Not in scope by default.
- *Own-origin exemption hides a real skew bug in our own clock*: a gateway whose clock jumps ahead authors changes that
  sort late everywhere. Peers hold them, which is the desired containment. Detect via the peer's skew alert.
- *Fold cost*: refolding the full log each tick is O(n log n). Fine at 2-10 gateways and human-rate edits; if the log
  reaches ~10^5 rows, add snapshot compaction (a later ticket).
- *`registers.json` written while a reader polls it*: `Store.write_registers/1` must write temp-then-rename (MPG-404).
- *Held change at the head of the log blocks nothing*: only its own register is affected.

## Open questions

| Question | Recommended default | What changes if answered differently |
|---|---|---|
| 1. Rate limit on forced Executor takeovers (MPG-403 open (a)) | Out of MPG-405. Enforce at write time in the writer (`intent/registers.ex`, MPG-406) as one per item per hour, audited | The fold and these tests are unchanged either way; only the writer gains a rejection |
| 2. "Takeover superseded" / "concurrent edit lost" note (MPG-403 (b)) | Expose only `takeover` in the register map now; the dashboard derives other notes later | A fold-time `cleared_human` list would be added to the output; no change to winners |
| 3. Persist the alerted set across restarts | In memory only; a restart while a change is still held re-alerts once | A durable set needs one more file under `intent/`; touches MPG-404's layout |
| 4. Exempt locally authored changes from the hold | Yes (own `origin_gateway`) | Without it, a clock set back 5 minutes hides the operator's own new edits until the clock catches up |
| 5. Change representation: plain atom-keyed maps or an `Aiur.Intent.Change` struct | Plain maps; MPG-404's `Store` decodes rows into them. Use the struct if MPG-404 already ships one | Only the pattern matches in `reconciler.ex` |
| 6. Owner component name in the catalog entry | Reuse whatever component MPG-404 registers for the intent lane; else `orchestration` | A catalog test fails on an unknown component; fix the string |
