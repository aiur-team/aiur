# MPG-210 — Prove registered gateways and remote control between PC and Nook: research

Deep dive MPG-210R (ticket #7593). Source contract: MPG-210 in
`docs/plans/2026-11-06-multi-project-gateways/tickets-m2.md` (plan PR #7579, branch `plan/multi-project-gateways`).
No code is changed by this ticket; MPG-210 itself adds only evidence.

## Outcome

MPG-210 ships no production code. When it is done, `docs/research/multi-gateway/evidence/MPG-210-live-run.md` holds
one block per acceptance test G1-G10 (plan "Acceptance tests"), each with the exact command, its output with secrets
and addresses redacted, and PASS or FAIL. Two extra blocks cover the bypass POST (message-only token, grant-changing
expression sent straight to `/api/v1/control`) and the G10 double denial. A reader can replay the run from the
runbook below without asking anyone.

## Design

The run is a manual live test under `docs/manual-testing.md`, executed from the Executor repo root on PC against Nook.
Agent issue workspaces cannot run it (`scripts/aiurdev --test` is blocked there); the MPG-210 worker records the
runbook as a script-free checklist and the Executor runs it, or the worker is dispatched from the Executor checkout.

**Roles.** PC = caller "A" (`pc`). Nook = receiver "B" (`nook`). A third registered gateway "C" is needed for G10; use
a loopback second daemon on PC (`AIUR_INSTANCE_KEY=mpg210c`, own port, own `HOME`), registered on Nook as `third`.
Run C under an isolated `HOME` so it never touches the real `~/.aiur`.

**Why every check goes through the receiver's own files.** Grants live in the receiver's
`~/.aiur/remote-instances.yaml` (`allows`, S2) and its audit is `control-audit.ndjson`. So each block ends with a
read of the receiver's file (`sha256sum` before and after for refusals), not just an exit code. An exit code proves
what the CLI printed; the file hash and audit line prove what the receiver did.

**Redaction rule.** Replace every token with `aiur_<redacted>`, every tailnet name or IP with `<nook-host>` /
`<pc-host>`, and gateway ids with their first 6 characters. Do this with one `sed` filter applied to the capture,
never by hand-editing output.

**Alternatives rejected.** (a) Driving only the stub server used by launcher tests: those tests already cover the
parser and are the MPG-20x tickets' own proof; MPG-210 exists to see the real receiver enforce. (b) One script that
prints PASS/FAIL: hides the evidence the ticket must record.

## Runbook

Placeholders: `$NOOK_URL` (HTTPS origin), `$PC_ID`, `$NOOK_ID` (26-char gateway ids from `aiur gateway status`).
Run every `aiur` command from the Executor checkout with `scripts/aiurdev` if testing a dev build. Set a scratch
capture dir `export EV=$(mktemp -d)`; every command is `cmd 2>&1 | tee -a $EV/<id>.txt`.

### Preflight

| Step | Command (on) | Expected |
|---|---|---|
| P1 | `aiur --version` (PC, Nook) | same build `commit` on both, containing MPG-202..209 |
| P2 | `aiur status` (Nook); `aiur status` (PC) | both daemons running, `dashboard_writable` true on Nook |
| P3 | `stat -c %a ~/.aiur/remote-instances.yaml ~/.aiur/peers/*` (both) | `600` each |
| P4 | `sha256sum ~/.aiur/remote-instances.yaml` (Nook) → record as `NOOK_REG_0` | hash recorded |
| P5 | `wc -l ~/.aiur/log/control-audit.ndjson` if present, else the path from `aiur status` (Nook) → `NOOK_AUDIT_0` | line count recorded |

### G1 registered vs reachable, accurate last seen

1. On Nook: `aiur gateway invite --grant read,message --ttl 10m` → prints one `aiur-invite:…` code.
2. On PC: `aiur gateway join <code> --name nook` → exit 0; `~/.aiur/remote-instances.yaml` gains `nook` with `gateway_id`; token file mode 600.
3. On PC: `aiur gateway list` → row `nook`: registered, `online`, `last seen` under 1 minute, gateway id equals `$NOOK_ID`.
4. Stop Nook's daemon (`aiur stop` on Nook), wait 60 s, on PC: `aiur gateway list` → `nook` shows `offline`, last-seen age about 60 s and growing (not zero, not blank). Restart Nook.

PASS when step 3 shows `online` and step 4 shows `offline` with an age, and both are still *registered*.

### G2 discovery and manual registration

1. On PC: `aiur gateway discover` → Nook listed `discovered (not enrolled)` before G1 join, `enrolled` after. Run it before G1 step 2 and after; record both.
2. Manual path with no Tailscale: on PC `PATH=$(echo "$PATH" | tr ':' '\n' | grep -v tailscale | paste -sd:)` then `aiur gateway discover` → registry entries only, stderr/stdout says Tailscale was not found.
3. `aiur gateway register nook2 --url $NOOK_URL --token-file ~/.aiur/peers/nook.token` → entry created; `aiur --gateway nook2 status` works. Then `aiur gateway remove nook2`.
4. `sha256sum` Nook's registry before and after `discover` → unchanged (discovery never grants).

### G3 read command reaches the intended gateway, identity pin checked

1. `aiur --gateway nook status` → output carries Nook's `instance_id`, not PC's.
2. `aiur --gateway Nook status` (case-insensitive label) → same.
3. Edit PC's `nook` entry `gateway_id` to 26 `a` characters (copy the file first, restore after). `aiur --gateway nook status` → exit 77, stderr `gateway identity mismatch for 'nook'`. Restore.

### G4 authorised remote write is enforced and audited by the receiver

1. On Nook: `aiur gateway grant pc agents`; answer the human-required Decision from a signed-in Nook dashboard session (Google or passkey). `aiur gateway permissions pc` → `agents` listed.
2. On PC: `aiur --gateway nook pause` → exit 0. Then `aiur --gateway nook resume`.
3. On Nook: the last audit lines show `outcome` ok, `category` agents, `peer` = PC's id, `origin_gateway` = PC's id, a `request_id`, and `actor`. Record the two lines (redacted).

### G5 unauthorised writes refused, including an Executor granting itself more

1. Revoke first: on Nook `aiur gateway revoke pc agents`. On PC: `aiur --gateway nook pause` → exit 77, message names `category_not_granted: agents`.
2. As an Executor on PC with its own token (`aiur token create exec-pc --scope write --peer $PC_ID --categories read,message` on Nook), run `aiur --gateway nook gateway grant pc agents` → exit 64 `grant changes are local to the receiving gateway` (CLI gate).
3. Same attempt but POSTed directly (see Bypass POST) → 403 `grants_are_local`.
4. Nook registry hash still equals `NOOK_REG_0`-after-G4 cleanup state (record the hash at start of G5 and at end).

### G6 remote agents and ticket owners shown; offline gateway not shown idle

1. With an agent running on Nook: `aiur gateway status nook` on PC → lists running agents and owned tickets with ages.
2. `aiur stop` on Nook; PC `aiur gateway status nook` → agents shown with `(<age> ago)`, connectivity `offline`, workload not `idle`.
3. `aiur gateway list --json` → each row has `gateway, connectivity, workload, last_seen_at, age_ms, freshness`.

### G7 unreachable gateway fails promptly, nothing queued

1. With Nook stopped: `time aiur --gateway nook pause` → exit 69 within the configured timeout (record seconds; expected under 10), stderr `could not reach remote instance 'nook'`.
2. Start Nook; `aiur status` (Nook) → not paused; the audit log has no `pause` line from this attempt. Nothing replays.

### G8 delegated tickets stay owned on GitHub while remote commands to the owner fail

Needs MPG-501/502 for full proof. Until then record: take a ticket on Nook (`aiur take <id>`), stop Nook, confirm the ticket's
GitHub ownership ref/label still names Nook (`gh issue view <id> -R <repo> --json labels`), and `aiur --gateway nook message <id> hi` from PC exits 69. Mark G8 `PARTIAL (needs MPG-502)` if ownership refs are not shipped; do not mark PASS.

### G9 existing `--instance` scripts and local CLI unchanged

1. `aiur --instance nook status` → same output as `--gateway nook status`.
2. `aiur --instance nook --gateway nook status` → exit 64 `use one of --gateway or --instance`.
3. `aiur status`, `aiur agents`, `aiur pause`/`resume` locally on PC → unchanged from the pre-run capture taken in P2.
4. A `remote-instances.yaml` written by the old launcher (no `gateway_id`) works and prints the id once with the pin command.

### Bypass POST (message-only token, grant-changing expression)

On Nook create a message-only token for PC: `aiur token create msg-pc --scope write --peer $PC_ID --categories message`.
Then, from PC (bypassing the CLI gate):

```bash
curl -sS -o $EV/bypass.json -w '%{http_code}\n' -X POST "$NOOK_URL/api/v1/control" \
  -H "Authorization: Bearer $(cat ~/.aiur/peers/msg-pc.token)" -H 'Content-Type: application/json' \
  -d '{"contract":"aiur.control.call","contract_version":2,"request_id":"<uuidv7>","max_scope":"write",
       "command":"gateway grant","expression":"Aiur.Gateway.CLI.run([\"grant\",\"pc\",\"agents\"])","timeout_ms":5000}'
```

Expected: HTTP `403`, body error `grants_are_local`; Nook `sha256sum ~/.aiur/remote-instances.yaml` unchanged; one new
audit line with `outcome` denied, `category` trust-or-grant, `peer` PC. The exact module and function in `expression`
come from MPG-206 as merged; copy them from `src/lib/aiur/gateway/cli.ex`.

### G10 fully trusted peers cannot grant over the network

1. On Nook: `aiur gateway trust pc --full` (confirm Decision in Nook dashboard). On PC: `aiur gateway trust nook --full` (confirm in PC dashboard). Record `aiur gateway permissions` on both: `read, message, executor, agents, tickets, config`, never `trust`.
2. Register `third` on Nook (`gateway invite` on Nook, `join` from C), leaving `third` at `[read]`.
3. Record `NOOK_REG_1=$(sha256sum ~/.aiur/remote-instances.yaml)` and `NOOK_AUDIT_1` line count.
4. From PC, POST (using PC's full-trust token, direct as in Bypass) two grant-changing expressions: grant `agents` to `pc`, then to `third`.
5. Expected: both HTTP 403 `grants_are_local`; Nook registry hash equals `NOOK_REG_1` byte for byte; Nook audit gained exactly two denial lines, one naming `pc`, one naming `third` as the target.

## Test scenarios

| Scenario | Input | Expected |
|---|---|---|

| Unreachable | Nook stopped, `--gateway nook pause` | exit 69 in under 10 s, nothing queued |

## Risks

- **Bypass returns 422 `unknown_on_build`, not 403.** The control allowlist rejects unknown functions before any grant
  check. If MPG-206 does not recognise the grant functions and refuse them as `grants_are_local`, the acceptance text
  (403 plus audit) fails even though the call is blocked. Detect: run the bypass POST on the MPG-206 PR head. Fallback:
  record 422 as FAIL against MPG-206.
- **Audit gaps.** Denials must be audited; a failed audit write returns 503. If the two G10 denials do not both appear,
  FAIL and file against MPG-204/206.
- **Wrong checkout or stale build.** Different `commit` on PC and Nook invalidates the run; P1 guards it.
- **Secrets in captured output.** Apply the redaction filter before pasting; grep the evidence file for `aiur_` and
  for the Tailscale domain before opening the PR.
- **Real `~/.aiur` mutated by the third gateway.** Always run it under an isolated `HOME`.
