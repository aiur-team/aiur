# MPG-305 — Register the remaining per-project singletons: research

Plan: [multi-project gateways](../plans/2026-11-06-multi-project-gateways.md). Contract: `tickets-m3.md` MPG-305.
Reads: [MPG-301](MPG-301.md) (the ADR; its §1, §2, §5 and §11 are the classification this ticket implements).
Code references are to `src/` at `7d5cc6199`. `Aiur.Project`, `Aiur.Project.Context` and `Aiur.Project.Table` do not exist yet
(they arrive with MPG-302/303/304), so every name below that starts with `Aiur.Project` is a **consumed contract**, not
current code.

## Binding decisions this doc follows

From the Executor's review of this PR (MPG M3, applies to 302/304/305/306):

- A **project id is the repository `owner/name` downcased** (`String.downcase(repo)`). The original-case repo is for display and API calls only.
- `Aiur.Project.Context.current/0` returns a `%Aiur.Project{}`; its `.id` is that downcased string. `scope_key/1`, `topic/1`, `ProcessReaper` metadata and every registry key below use `.id`, never the original-case repo and never the struct.
- Each project's state leaf is built from its own id. The daemon's own repo resolves to exactly today's `decision_state_dir` leaf. Two entries that resolve to one leaf are a boot error (MPG-306).
- `Paths.decision_state_dir/0` **stays machine-level**. MPG-304R adds a context-aware `Paths.project_state_dir/0`, which only per-project paths use.

## Outcome

Every singleton the ADR marks per-project for MPG-305 (9 modules plus 3 helpers) starts once per project tree and finds
its own server by `Aiur.Project.whereis(__MODULE__)`. Five machine-level modules keep one process but gain a project id
in a key or a field. A new test, `src/test/aiur/project/singleton_inventory_test.exs`, fails when any module that
registers a process under its own module name is not classified, and when its classification differs from the ADR
table. With no project context nothing changes: `whereis/1` returns the module name, tables are the named tables of
today, and keys are bare identifiers.

## Design

### D1. The mechanism is the ADR's, not a new one

- **Process names.** `name: __MODULE__` becomes `name: Aiur.Project.via(__MODULE__)`. `via/1` returns `__MODULE__`
  with no context and `{:via, Registry, {Aiur.ProjectRegistry, {project_id, Module}}}` with one. Public functions
  call `GenServer.call(Aiur.Project.whereis(__MODULE__), ...)`, so callers stay untouched.
  *Why not a name argument on every function:* 42 lib files call `RepoBase` and 25 call `Listeners`; the ADR (Decision 1)
  already fixed that callers are not edited.
- **ETS.** A table named `__MODULE__` becomes an unnamed table whose tid is published with
  `Aiur.Project.Table` (MPG-304's `{Aiur.Project.Table, project_id, name}` `persistent_term` lookup). Readers resolve the
  tid with the caller's context. With no context they use the named table. Same-VM tests that use no context keep passing.
- **Project id in keys.** One helper, `Aiur.Project.scope_key(identifier)`: returns `identifier` unchanged when
  `Context.current/0` is `nil`, else `{project.id, identifier}` (the downcased id, never the original-case repo). *Why a helper that can return a bare string:* the 21
  `ActiveTurns` test files and the guards `is_binary(identifier)` in `ActiveTurns`, `TokenRegistry`, `SessionWriter` pass a
  string today. Returning the bare string with no project keeps them green; the guards widen to `is_binary or is_tuple`.

### D3. Inner named children are singletons the grep cannot see

`Listeners` starts `Firehose`, `Comments` and `CommandScan` as `{Mod, name: Mod}` (`github/listeners.ex:14`). The
`name: __MODULE__` grep does not match those, so MPG-301's count (27 + the §2 forms) omits them. They live inside a
per-project supervisor, so they become per-project **without a change**, provided their names are not looked up by atom
from outside the project: MPG-305 greps `Listeners.Firehose|Listeners.Comments|Listeners.CommandScan` outside
`github/listeners/` and migrates any hit to `whereis`. The inventory test (D7) matches three forms: `name: __MODULE__`,
`Keyword.get(opts, :name, __MODULE__)` and `{Mod, name: Mod}` in a `Supervisor.init` list; the third form is only
reported (never fails) because the ADR table has no row for children of a per-project supervisor.

### D5. PubSub topics: MPG-305 scopes two, not "about 4"

A census of the topic literals in `lib` (`PubSub.subscribe|broadcast` with a string topic, plus `@topic` attributes)
gives 11 literals and about 25 `@topic` attributes. Only topics whose **broadcaster is a module MPG-305 migrates** are in
scope: `"tracker:open_issues"` (broadcast in `github/open_issue_snapshot.ex:99`, subscribed in `build_order/index.ex:121`).
`"build_queue:changed"` belongs to MPG-304. The `fleet_refresh` module has no PubSub topic of its own. The rest
(`"conversation:" <> id` carries a unique conversation id, and the dashboard and `@topic` ones are machine fan-out) stay.

Add `Aiur.Project.topic(base)`: returns `base` with no context, else `"project:" <> project.id <> ":" <> base` (the downcased id). Use it in
the two files above. That cuts the ADR's "about 4 files" to **2**, and the batch total to 22 (D8).

### D6. Registry-keyed state

`Aiur.Events.SubscriptionStoreRegistry` (`application/children.ex:243`) is keyed by issue id
(`events/subscription_store.ex:35,56`, `events/subscription_store/persistence.ex:12`,
`github/listeners/comments/owned_poll.ex:95`, `events.ex:63`). Recommended: keep **one** registry and prefix the key
with `scope_key/1`, rather than start one registry per project (a registry name must be an atom, and creating atoms from
project ids is unbounded). Same for `SessionWriterRegistry`.

**The persisted file is shared too.** `events/subscription_store/persistence.ex:23-31` writes
`<Paths.repo_name()>.<identifier>.subscriptions.json` under `Paths.runtime_state_dir()`, which falls back to
`decision_state_dir()` (machine-level). `repo_name/0` keeps only the last path segment, so projects `o/a` and `p/a` both
write `a.12.subscriptions.json`. Recommended: when no `:runtime_state_dir` override is set, `path_for/1` uses
`Paths.project_state_dir()`, which already separates the owner. With no context the file name is today's, so the
daemon's own repo keeps its file. With the override set, the override wins as today and the file name gains the project
id (`<owner>__<name>.<identifier>.subscriptions.json`), so two projects cannot share a name there either.
`owned_poll.ex` needs no path change.

### D7. The inventory test

`src/test/aiur/project/singleton_inventory_test.exs`:

1. Scans `lib/**/*.ex` for the two registering forms from D3 (not the third).
2. Parses the ADR table in `docs/research/MPG-301.md` (§1 and §2 rows: module, owner) as the expected classification.
3. Asserts the scanned set equals the ADR set row for row (fails on an unclassified module, on a stale ADR row, and on a
   module whose owner differs from `@classification` in the test).
4. For every `per-project` row, asserts the file contains `Aiur.Project.via(` or `Aiur.Project.whereis(`, so a per-project
   module cannot pass as machine-level by omission. This is the `[fails without]` assertion.

*Why parse the ADR rather than copy it:* a copied list is the "assertion against an inlined copy" the repo rules forbid.
`TaskSupervisor`, `PubSub`, `ProcessReaper` and the other §2 machine rows are in the ADR table, so the parse covers them.

## Risks

- **`RetainedCache` line 134 starts a second instance** with a bare `GenServer.start(__MODULE__, nil, name: __MODULE__)`.
  If it keeps the bare name in projects mode it collides across projects. Detect: the registration test starts two projects
  and expects two pids.
- **`ActiveTurns`/`TokenRegistry` guards.** Widening `is_binary` can let a mistyped key through. The tuple form is the only
  other accepted shape.
- **`OptimisticLedger` latch** keyed on `Process.whereis(Aiur.Supervisor)` would suppress the second project's alert if
  it kept that key. Covered by adding `project_id` to the key.
- **ADR drift.** The inventory test parses `MPG-301.md`; reformatting that table breaks it. The test fails with the
  parse error rather than passing silently (an empty parse is a failure).
