# MPG-103 — Require durable ownership before every dispatch: research

Plan id MPG-103R (issue #7606). Blocks MPG-103 (#7639). Plan: `docs/plans/2026-11-06-multi-project-gateways.md`
(KTD-2, S1, "Ownership protocol"). Contract: MPG-103 in `docs/plans/2026-11-06-multi-project-gateways/tickets-m0-m1.md`.
Code read at the branch base (`a39605edc`). Line numbers refer to that commit. `S/` = `src/lib/aiur/`.

## Outcome

With `instance.ownership: github`, no agent starts for a ticket unless this gateway (same `gateway_id` **and**
`daemon_key`) already owns its ownership ref or wins the claim. That holds for every path that can start an agent:
the poll, manual resume, recycle, backend or account redispatch, Remote Control demotion, reactivation, override
recovery, and PR-anchored units. A refusal, a lost race and an unknown outcome all leave the ticket unstarted and
retryable. With `instance.ownership: off` (default) behaviour is byte-for-byte what it is today.

## Design

### Finding 1: there is one seam, so the gate goes in one place

All 12 call sites in 11 files (the "11" in the ticket is files; `code-evidence.md` §2 does not list them, so this
table is the list) reach `Launch.do_dispatch_issue/5` (`S/orchestrator/dispatcher/launch.ex:93`), which calls
`SharedLeaseDispatch.dispatch/6` (`launch.ex:96-103`). The three `dispatch_prevalidated_issue` callers go through
`do_dispatch_issue(state, issue, nil, nil)` (`launch.ex:56-57`). `SharedLeaseDispatch.ready_dispatch/8`
(`shared_lease_dispatch.ex:61-92`) runs after `prepare_for_dispatch` (handoff hold, optimistic prepare, hosted-mode
check, toolchain selection) and `ownership_eligibility` (`instance.owns`/`pool`), and is the only place that
chooses between "dispatch with the shared lease" and "bypass for `pr_head_ref`". No caller needs its own check.

"Mode" is how the gate treats an absent or released record: **claim** (callers 1-5) wins it; **held** (6-12)
should find the record already ours. The decision for 6-12 is to run the *same* `ensure_owned/2` rather than skip the
check: a ticket whose agent was started before `ownership: github` was switched on has no record, and claiming it at
the next recycle is the migration path the plan's `reason: "migration"` value exists for. A record owned by another
gateway at recycle time means a transfer happened while the agent ran; refusing is the correct fence (MPG-105 stops
the old agent; MPG-103 must not restart it).

No caller needs a code change. Each already handles "dispatch returned without starting" because
`:shared_lease_held`, `:instance_not_owner` and `:instance_ownership_unavailable` declines already exist at this
seam. MPG-103 adds one more decline reason set, and the test list below proves each caller's refusal path.

### Finding 2: PR-anchored units need an explicit ownership key and a lease-key check

`build_pr_anchored_issue/3` (`pr_anchored.ex:106-117`) builds an `%Issue{id: "pr-<N>", identifier: "<N>",
tracker_identity: nil, pr_head_ref: head}`. Ownership key must be `pr-<N>` (S1), not the issue's `identifier`.
`LeaseStore.TicketKey.ticket_key/1` resolves `%{identifier: "<N>"}` to `owner/repo#<N>` using `GitHubConfig.repo()`
(`ticket_key.ex:25-26,43-48`), so removing the `pr_head_ref` bypass does not break the lease: it keys the PR by its
GitHub number, which cannot collide with an issue because GitHub numbers PRs and issues from one sequence.
The repository for the ownership ref is `GitHubConfig.repo()` for these units, since they carry no `tracker_identity`.

### Finding 3: the second bypass is in the agent, and it must move with the first

`AgentRunner.run/3` (`S/agent_runner.ex:27-30`) skips `LeaseStore.watch` for `pr_head_ref` issues
(`lease = if is_binary(issue.pr_head_ref), do: :disabled, else: lease_watch.(issue)`). Removing only the
dispatcher branch would leave the lease acquired at dispatch and never renewed for PR units, so it would expire in
30 s (`lease_store.ex:12-15`) while the agent runs. Both lines go in the same change. `agent_runner.ex` is 498 lines
and must not grow: the edit replaces four lines with `lease = lease_watch.(issue)`.

### Gate shape

New facade `Aiur.Ownership` (`S/ownership.ex`), built on MPG-102's `Aiur.Ownership.GitHubRef`:

```elixir
@spec ensure_owned(Issue.t(), keyword()) ::
        {:ok, Record.t()} | :disabled | {:declined, :not_owner | :unknown, term()}
```

- `:disabled` when `instance.ownership` is `off`.
- Key: `"pr-" <> identifier` when `is_binary(issue.pr_head_ref)`, else the issue number. Repo from
  `issue.tracker_identity` when joinable, else `GitHubConfig.repo()`.
- Read uncached (`GitHubRef.read/2`, bypasses `ReadCache`, MPG-102 acceptance). Then:
  - owned by self (`gateway_id` and `daemon_key` both equal) → `{:ok, record}`; **no write**.
  - absent or `state: "released"` → `GitHubRef.claim/3` with `reason: "dispatch"` (`"migration"` when the caller
    mode is `held`); `{:won, r}` → `{:ok, r}`; `{:lost, current}` → `{:declined, :not_owner, current}`;
    `{:unknown, why}` → `{:declined, :unknown, why}`.
  - owned by another gateway or another daemon key → `{:declined, :not_owner, record}`.
  - read `{:unknown, why}` → `{:declined, :unknown, why}`.
- Never infers a result from error text (constraints 3-4 under Prior art: a lost create is indistinguishable from a
  server error; the adapter re-reads and classifies).

Hook in `SharedLeaseDispatch.ready_dispatch/8`, replacing the `if is_binary(issue.pr_head_ref)` block:

```elixir
:eligible ->
  case Aiur.Ownership.ensure_owned(selected_issue, opts) do
    result when result == :disabled or match?({:ok, _}, result) ->
      dispatch_with_shared_lease(state, issue, selected_issue, dispatch, opts)

    {:declined, :not_owner, _} ->
      Candidates.emit_dispatch_attempt_decline(state, issue, :ownership_not_owner, false)

    {:declined, :unknown, why} ->
      Logger.warning("Ownership unknown (#{inspect(why)}) for #{State.issue_context(issue)}; holding dispatch")
      Candidates.emit_dispatch_attempt_decline(state, issue, :ownership_unknown, true)
  end
```

Order matters and is deliberate: `prepare_for_dispatch` (cheap, local) → `instance.owns` roster check (local /
Postgres) → ownership (one GitHub read, a write only on first claim) → shared lease (Postgres). A ticket that fails
a cheap local check never costs a GitHub read. The lease stays after ownership because KTD-3 makes it a "no two runs
of an owned ticket" optimisation that never grants ownership.

`release_if_unstarted/3` (`shared_lease_dispatch.ex:128-136`) already releases the lease when the dispatch fn did not
claim. The ownership record is **not** released in that case: a gateway that won the claim and then failed to spawn
(no slot, backend limit) still owns the ticket, and the next poll re-reads `owned by self` and proceeds without a
write. Releasing would make two gateways race again every poll. MPG-108 owns release-on-close.

### Alert and decline reasons

- `:ownership_unknown` declines with `hold? = true` (the same flag `:instance_ownership_unavailable` uses), and
  raises one attention per ticket per hour (reuse the dedupe pattern in `lease_store.ex:460-481` rather than a new
  mechanism). Retried every poll; no state is stored.
- `:ownership_not_owner` is `hold? = false`, like `:instance_not_owner`: a quiet decline, no alert. MPG-104 owns the
  ambiguity alert.
- `dispatch_prevalidated_issue` maps any non-started result to `{:error, :dispatch_not_started}` (`launch.ex:80`).
  Operators resuming a ticket owned elsewhere would see that opaque reason. Carrying the real cause back would
  need a new `state.dispatch_recovery` field and two `cond` arms, which is more invasive than it is worth.
  **Recommended default**: leave the result as
  `:dispatch_not_started`, rely on the decline event (visible on the dashboard) for the cause. See open question 2.

### Config

`instance.ownership`: string, `off | github`, default `off`, in `S/config/schema/instance.ex` beside `pool`/`role`
(the file is 113 lines; add after `pool`). Annotate with `@config-reference config-configuration-00 instance.ownership`
and `@config-detail` per the existing pattern (`instance.ex:55-66`). Validate with `validate_inclusion`; anything
else is a config error naming the allowed values. **Read once at daemon start, not hot-reloadable** (recommended; a
live flip would make running agents ownerless). Read through a single `Aiur.Ownership.enabled?/0`.

## Prior art

None needed beyond the settled MPG-101 result (`docs/research/MPG-101.md`, run 2026-11-06, verdict GO) and
`docs/research/multi-gateway/github-claim-protocols.md`. The constraints this design depends on, pinned here so the
doc stands alone:

1. **Claims and advances use only GraphQL `updateRefs` with `beforeOid`.** Create-if-absent is `beforeOid` = 40 zeros;
   an advance passes the current oid. REST `PATCH force=false` is not a compare-and-set (it accepted an unrelated
   commit) and is never used for ownership.
2. **Namespace is `refs/aiur/owners/<ticket>`.**
3. **A losing create has no distinguishable signature.** It returns an `errors` entry with no `type` and no
   "already exists" text, identical to a server error. The adapter never infers a loss from error text.
4. **On any error, re-read the ref.** Pointing at my commit: I won (the call may have succeeded before the error).
   Pointing elsewhere: I lost. Absent: retry with backoff. Anything else: ownership not established, so `:unknown`
   and the dispatch is declined.
5. A stale `beforeOid` on an advance is rejected (`UNPROCESSABLE`); a conditional read with `If-None-Match` returns 304.

This ticket's questions are internal: which callers, where the seam is, and how refusal flows back.

## Risks

- **GitHub read cost per dispatch attempt.** Every attempt that clears the local checks does one uncached ref read.
  A ticket `agent:todo` but owned by another gateway is re-read each poll. Count the population before shipping:
  `gh api repos/<repo>/git/matching-refs/aiur/owners` lists owned tickets; compare to the todo/rework count. Mitigation:
  MPG-102's read should use `If-None-Match` (a 304 is free, MPG-101 step 6). Fallback: a per-poll cache of
  `{:declined, :not_owner}` keyed by ticket with TTL = poll interval (only negative results, never positive).
- **Claim then failed spawn leaves ownership held.** Intended (see above); detect via MPG-104's projection and MPG-108.
- **Recycle on unknown ownership stalls an agent between turns.** Held-mode callers retry via existing retry paths;
  a GitHub outage therefore pauses recycles, not running agents (the plan's "running agents continue"). Verify with
  the "hold after refusal does not loop" test.
- **Turning the flag on mid-flight.** Running agents have no record; the first recycle claims it as `migration`.
  A different gateway that polls first and claims a ticket whose agent is running here would win and block our
  recycle. Mitigation: documented in the config row: enable on a drained or quiet gateway; MPG-109 acceptance
  includes the order.
- **`dispatch_prevalidated_issue` reason is opaque** (Design). Low severity; see open question 2.
