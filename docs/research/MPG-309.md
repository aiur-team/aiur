# MPG-309 — Key the daemon by gateway and migrate per-repository state: research

Research ticket MPG-309R (#7622). Contract: `docs/plans/2026-11-06-multi-project-gateways/tickets-m3.md` (MPG-309).
Reads: `code-evidence.md` §3.1/§5, `state-schemas.md` S3, `docs/research/MPG-301.md` (ADR). No external question arose, so no
deep-research run. Brainstorm questions are recorded under "Open questions" with a recommended default; none blocked.

## Outcome

With `projects:` set in `~/.aiur/machine`, every `aiur`/`aiurdev` command resolves the same instance key
`gw-<first 10 hex of sha256(gateway_id)>` from **any directory**, so `aiur status` from `/tmp` reaches the gateway daemon.
`aiur gateway migrate-state` lists (dry run) and `--apply` performs a one-time move of
`<state root>/<old key>/<repo leaf>/` to `<state root>/<gateway key>/<repo leaf>/`, leaving a symlink behind so a
rollback to single-project mode still finds its state. Without `projects:`, the key is today's cwd-derived key, byte for byte.

## Design

### D1. What "gateway mode" is
`aiur_gateway_mode` is true when **all** hold: `${AIUR_GATEWAY_MODE:-1}` is not `0`; the file `$HOME/.aiur/machine`
(same path as `Aiur.Machine.Settings.path/0`, which reads `$HOME`) has a non-empty top-level `projects:` list; and
`AIUR_INSTANCE_KEY` is not already set (the existing `${AIUR_INSTANCE_KEY+x}` explicit override keeps winning).
`AIUR_GATEWAY_MODE=0` is an escape hatch for `aiurdev --test`, which must stay on a cwd key so it never touches the
live gateway. It is read only by the launcher; **not** documented as an operator variable (test/dev seam; see Q6).
Detection is a shell `awk` over the file: a line `^projects:[[:space:]]*$` followed by a line matching `^[[:space:]]+-`,
or `^projects:[[:space:]]*\[[^]]` for the inline form. Anything else (missing file, `projects: []`, `projects:` empty,
unreadable file) is **not** gateway mode. A file that is present but invalid YAML is also not gateway mode here; the daemon
reports the real error at boot (`Aiur.Machine.Settings.get/0` returns `{:error, {:invalid, _}}`). Rejected alternative:
call the BEAM to parse YAML. Control commands must work while the daemon is down (`status` must say "not running"), and
booting a node costs seconds.

### D2. The key
`aiur_gateway_instance_key` = `printf '%s' "$gateway_id" | sha256sum | cut -c1-10`, prefixed `gw-` (13 chars). It matches
`Aiur.Config.InstanceKey` (`[A-Za-z0-9_-]{1,64}`), the node-name charset and `Paths.sanitize/1`, so
`Aiur.Config.Paths.resolve_decision_state_dir/0` needs **no logic change**: it already builds
`<root>/<AIUR_INSTANCE_KEY>/<leaf>`. `gateway_id` is the 26-char `machine_id` in `<AIUR_BG_STATE_DIR>/machine/identity.json`
(KTD-1; `Aiur.Identity.Store.dir/0` default is `$AIUR_BG_STATE_DIR/machine`, `AIUR_BG_STATE_DIR` defaulting to
`~/.config/aiur`). The shell extracts it with `sed -n 's/.*"machine_id"[[:space:]]*:[[:space:]]*"\([a-z2-7]\{26\}\)".*/\1/p'`.

### D3. Chicken and egg: identity before first boot
The node name needs the key before the BEAM exists, but `identity.json` is first written at boot
(`Aiur.Identity.Store.create/2`). Decision: the launcher creates it when absent, in gateway mode only, with
`aiur_ensure_machine_identity` in `identity.sh`: 16 random bytes → base32 lowercase unpadded (26 chars, alphabet `a-z2-7`),
JSON `{"schema_version":1,"machine_id":…,"machine_label":<hostname -s>,"created_at":<UTC ISO8601>}`, mode 0600 in a 0700
dir, published with `ln` of a temp file (never replaces, the same race rule as `Store.create/2`). A cross-language test
proves `Aiur.Identity.Store.read/1` accepts the shell-written file (Q1 has the alternative).

### D4. Project root, source and records in gateway mode
`aiur_project_root_source` gains the value `gateway`. `aiur_project_root` returns `$HOME/.aiur` (the machine file's
directory) because several consumers need a non-empty root: `load_aiur_instance_record` requires a non-empty
`AIUR_RECORD_PROJECT_ROOT`, `write_aiur_instance_record` canonicalizes it, `AIUR_PROJECT_ROOT` is exported to the daemon.
`resolve_control_identity_from_records` (control.sh:96-150) only runs for source `cwd`; `gateway` skips it, which is
right: the key is already directory-independent, so no record scan is needed. `print_global_config_control_hint` is also
`cwd`-only and stays silent. `AIUR_REPO_ROOT` (dev shim) loses to gateway mode unless `AIUR_GATEWAY_MODE=0`.

### D5. Everything else keyed by the key follows automatically
Node `aiur-$USER-gw-xxxxxxxxxx@127.0.0.1`, tmux socket/session `aiur-$USER-gw-…`, the `*.instance` record, launch lock,
`.last-crash` and `.last-restart` markers are all derived from `AIUR_RELEASE_NODE`/`AIUR_INSTANCE_KEY` (`aiur_state_slug`).
They are ephemeral runtime markers; **not migrated**. The old single-project daemon and the gateway daemon have different
nodes, so they can run side by side until the operator stops the old one (migration refuses while the old one is live, D7).

### D7. `aiur gateway migrate-state [--apply]`
New module `Aiur.Gateway.StateMigration` (pure planner + applier) and `Aiur.Gateway.StateMigrationCli` (argv, output, exit
code). Dispatch is a control-class call through the launcher (`engine/commands.sh` gets a `gateway` case routing
`migrate-state` to a **distribution-free** oneshot like `run_ask` legacy history, since the daemon must be stopped).

Plan algorithm (`plan/1`, pure, takes `projects`, `state_root`, `home`, `gateway_key`):
1. For each `projects[]` entry `{repo, config}` in order:
   - `old_key = sha256(realpath(dirname(dirname(config))))[0:10]` (project root is the directory holding `.aiur/`;
     exactly `aiur_instance_key`: realpath, then sha256 hex 10). If `config` is `~/.aiur/config` (global config), root is
     `dirname(dirname(config))` too, but the legacy key was cwd-derived and is **unknowable**: the plan lists it as
     `skipped: legacy key not derivable` and takes an optional `--from-key <hex10>` for that project (Q4).
   - `src_leaf`: today's leaf, **case preserved**. `decision_project_leaf/0` used `sanitize/1` of that project's own
     config `tracker.repo`, which can differ in case from `projects[].repo`. Read `tracker.repo` from the project's
     config; if unreadable, take the single case-insensitive match of the downcased name segment among the entries of
     `<old_key>/`. Two matches is a `conflict` naming both.
   - `dst_leaf` is `Paths.project_leaf(String.downcase(repo))` (MPG-306R), reused, never a second derivation. For
     `O/MyRepo`: `src_leaf = MyRepo`, `dst_leaf = myrepo`.
   - `src = <state_root>/<old_key>/<src_leaf>`, `dst = <state_root>/<gateway_key>/<dst_leaf>`. The symlink left behind
     (D9) is at `src`, so rollback keeps finding today's case.
2. Classify each: `move` (src is a real dir, dst absent); `already_migrated` (src is a symlink resolving to dst, or src
   absent and dst present); `nothing` (src absent, dst absent); `conflict` (src real dir **and** dst exists, or two
   projects share `dst`: **compared on `dst_leaf`, i.e. downcased**, so `o1/app`, `o2/app` and `o3/App` all collide). Conflicts block `--apply` entirely (exit 1).
3. Auxiliary files under `~/.aiur/instances/<old_key>/` (D8).

Apply: refuse with exit 75 and `aiur: stop the daemon first (node <name> is up)` when **either** the old node or the
gateway node answers (`probe_named_node_liveness`; the launcher passes both node names in). For each `move`:
`mkdir -p <state_root>/<gateway_key>` (0700), `File.rename(src, dst)` (same filesystem, atomic; on `:exdev` fall back to
**refuse** with the path, never copy+delete), then `File.ln_s(dst, src)`. Idempotent: the second run reports
`already_migrated` for every row and exits 0. Dry run prints one line per row,
`move <src> -> <dst>` / `skip …` / `conflict …`, and changes nothing (test asserts a tree hash before and after). Exit codes:
0 ok or nothing to do, 1 conflict, 64 usage, 75 daemon running.

### D9. Why a symlink and not just a move
Rollback: delete `projects:` and the old single-project daemon computes the old key, opens `<old_key>/<leaf>`, which
is the symlink. `Aiur.PathSafety.contained?/2` canonicalizes the candidate; the target is still under the state root, so
`contain_within_root/2` accepts it. Alternatives: copy (doubles disk, forks truth), bare move (breaks rollback silently),
hard link (directories cannot).

### D8. Auxiliary per-key files in `~/.aiur/instances/<old_key>/`
| File | Policy | Reason |
|---|---|---|
| `streamdeck-settings.json` | copy to `<gateway_key>/` from the first project (config order) that has one, only if dst is absent | per-daemon preference; harmless |
| `secret_key_base` | **not migrated**; dashboard mints a new one; operators who care set `AIUR_SECRET_KEY_BASE` | copying a secret between keys widens its blast radius; the cost is one re-login |
| `config-overrides.json` | **not migrated**, listed in the dry run as `not migrated: run-time overrides, re-apply with aiur set` | they were per-project; one gateway file would apply project A's overrides to B (L5 ownership is MPG-310/311) |

  two projects resolving to one leaf are a boot error there. This ticket matches it: `dst_leaf` is downcased (D7) and

  That error message must name `aiur gateway migrate-state`. It must say: run `aiur gateway migrate-state --apply` (daemon stopped); it renames `<old_key>/MyRepo`
  to `<gateway_key>/myrepo`. MPG-306R owns the wording; this ticket's `--apply` is the fix and is the only code that moves state.

## Risks
- **Half-moved state if the process dies between rename and symlink.** Detect: rerun reports `src absent, dst present` =
  `already_migrated` but no symlink; the planner repairs the symlink when the old key dir exists. Cheap and covered by M3 variant.
- **Shell YAML sniffing disagrees with the Elixir parser** (D1): gateway mode on in shell, off in daemon, or the reverse.
  Mitigation: the daemon logs `gateway_key_mismatch` at boot when `projects` is non-empty and its key does not start `gw-`
  (one `Logger.warning`, in MPG-306 boot, not here); L7 pins the shell side.
- **Identity created by shell diverges from the Elixir schema.** L6 round-trips through `Store.read/1`.
- **Secret and session reset** on first gateway boot (D8): documented in `cli-launch.md`.
- **Rename across filesystems** (`~/.config/aiur` on another mount than the leaf): refuse, never copy.
