# MPG-406 — Deliver gateway pause and pause-all durably: research

Plan: `docs/plans/2026-11-06-multi-project-gateways.md` (rows 11 and 23, acceptance A11 and A12, "Reconciliation" rules
4, 5, 7). Contract: MPG-406 in `docs/plans/2026-11-06-multi-project-gateways/tickets-m4-m7.md`. Rules come from
[MPG-403](MPG-403.md), including its amendments A1 to A3. MPG-406 builds on MPG-404 (store, outbox, sync) and MPG-405
(`Reconciler.fold/1`). Where this note names a function those tickets own, the name is the interface MPG-406 needs; it
is confirmed in MPG-404R and MPG-405R (open question 1).

## Outcome

`aiur pause --all-gateways` records one `fleet.pause` change in shared intent, tries to reach every other gateway
directly, and prints one line per gateway: `paused now`, `will pause on reconnect`, or `unknown`. A gateway that was
offline pauses itself the moment it syncs, before its next dispatch, and reports `paused (fleet)`. `aiur resume
--all-gateways` is the human unpause that clears it. Pausing one gateway (`aiur pause`) is unchanged. Already-running
agents are never stopped, as today.

## Design

### D1. Two switches, one effective value

Keep the existing local switch exactly as is (`State.globally_paused`, persisted in `global-pause.json`). Add a second,
derived input: `State.fleet_paused`, the folded value of register `(fleet, "fleet", pause)`. Dispatch is stopped when
`globally_paused or fleet_paused`. The fleet value is **never written into `global-pause.json`**: that file is the
local operator's decision, and writing the fleet value into it would make a later fleet unpause either clear a local
pause the operator set separately or leave a pause nobody can explain.

Alternatives rejected:
- Reuse `globally_paused` for both. Fleet unpause could not tell its own pause from a local one, and
  `global_pause_test.exs` already pins the file's meaning.
- Make the fleet pause a direct `pause_global` call on each peer. It is lost for an unreachable peer, which is the case
  the ticket exists for, and a local pause is not undone by the fleet unpause.

### D2. The register and who may write it

- Register key: `entity_kind: "fleet"`, `entity_key: "fleet"`, `field: "pause"`, `value_json: true | false` (S4 in
  `state-schemas.md`; the plan's "`fleet.pause`" is this triple).
- Slot is chosen by the caller, as MPG-403 rule 4: `aiur pause --all-gateways` is `human` without `--as` and
  `executor` with `--as <id>`. **A daemon never writes `pause`** (A2); there is no code path where the scheduler,
  rate-limit fallback, or a boot step calls the writer.
- Effective value comes only from `Reconciler.fold/1` (any paused slot pauses; human unpause clears every slot; pause
  wins an exact HLC tie, A1). MPG-406 does not re-implement any of it.
- `resume --all-gateways` writes `false` in the caller's slot. From an Executor it clears only the executor slot, so a
  human pause remains. The output says so (`still paused: a human pause is set`).

### D3. Delivery has two paths and the register is the one that cannot be lost

`aiur pause --all-gateways`, in order:

1. **Author.** The local daemon authors the change (new HLC, new `change_id`), writes it to `changes.ndjson`, then to
   the outbox, and applies it locally at once. Nothing else is needed for the local gateway to stop dispatching.
2. **Push.** Try to push the outbox to the store (existing `Intent.Sync`, MPG-404). Result: `stored` or `outbox_only`.
3. **Direct calls.** In parallel, for every peer in `~/.aiur/remote-instances.yaml` that has a `url`, send one control
   call that applies the **same change** (same `change_id`, HLC, slot, `reason`) on the peer. The peer treats it as a
   remote apply (MPG-403 rule 7): idempotent by `change_id`, never copied to its outbox. Timeout 10 s per peer, calls
   run concurrently, so the command takes at most about 10 s plus the push.
4. **Report.** Per gateway:

| Direct call | Change in store | Label |
|---|---|---|
| acknowledged | any | `paused now` |
| failed, refused, or no `url` | `stored` | `will pause on reconnect` (suffix the reason, for example `direct call refused: category_not_granted: agents`) |
| failed or no `url` | `outbox_only` | `unknown` (this machine is the only carrier; the line says `retry when the store is reachable`) |

Gateways listed come from the registry plus the store roster (`Instance.Roster`). A roster-only peer (in the store but
not in the registry) cannot be called, so it is `will pause on reconnect` when the change is `stored`, else `unknown`.
The local gateway is printed first as `paused now`. Exit code 0 unless any line is `unknown`, then 69 (the existing
"unreachable" code, `remote.sh`); a refused direct call alone does not fail the command because the store delivers it.

Why not make the direct call the only path: an offline peer never hears it. Why not make the store the only path: the
store may be down, and "store down, gateway reachable: the direct call still pauses it" is an acceptance line. Both
carry the same change, so applying twice is a no-op and a later human unpause (higher HLC) wins over a stale direct
delivery. That last property is why the direct call carries the full change and not a boolean: a boolean applied
directly could outlive the unpause that followed it.

### D4. What the direct call is

One new control-call function, allowlisted as category `agents` (the category `pause_global` already has, MPG-205):

`apply_fleet_pause_change(change :: map)` → `{:ok, :applied | :duplicate | :held}`. It accepts only
`entity_kind == "fleet"`, `field == "pause"`, a boolean `value_json`, and a slot of `human` or `executor`; anything else
is refused. It calls the MPG-404 remote-apply path and then folds. It is deliberately not a general "apply any change"
endpoint: a general one lets any `agents` peer write ticket order and project priority, which MPG-501 has not decided.
A token's `category_not_granted: agents` refusal therefore blocks only the direct path; the store path still delivers.
That is intended: the store is already a shared trust boundary, and the pause is one the receiving human can undo. It
is also why the output reason is shown.

`apply_fleet_pause_change` must not accept a change whose slot claims `human` from a remote caller that has no signed-in
proof. Open question 3.

### D5. Boot and reconnect: sync before dispatch

The failure to prevent: gateway restarts or reconnects, the store has `fleet.pause = true`, and the first dispatch
tick runs before the pull.

- **Boot.** In `Lifecycle` init, after `GlobalPauseStore.load()` and before `schedule_initial_tick`, call
  `Intent.Sync.pull(timeout_ms: 5_000)` when the store is configured (`LeaseStore.configured?/0`). On success fold and
  set `fleet_paused`. On failure or timeout, use the cached `registers.json`. The wait is bounded, so a down store
  delays boot by at most 5 s and never blocks it.
- **Cache is fail-safe in one direction.** A cached `true` stays paused with the store down: the gateway keeps
  honouring the last pause it knew, as `global-pause.json` does for an unreadable file. A cache that was never written
  (the gateway has never synced) means `fleet_paused = false`: we cannot invent a pause we never heard of, and stopping
  every unsynced gateway would make a store outage halt the fleet. This is the residual window (D6).
- **Reconnect.** `Intent.Sync` keeps a flag `needs_pull` set whenever a pull or push failed and cleared by a successful
  pull. The dispatch cycle's first step (`Dispatcher.start_candidate_poll/…`) calls `Intent.Sync.ensure_fresh(5_000)`
  only while `needs_pull` is set, folds, and then evaluates `effective_paused?`. In steady state the flag is clear, so
  there is no added cost and no per-tick store read. A pull that fails again leaves the cached value in force.
- **Change while running.** A pull that changes the folded value sends `{:fleet_pause_changed, boolean}` to the
  orchestrator, which updates `fleet_paused`, publishes the snapshot, and requests an immediate refresh on unpause
  (the same `maybe_refresh_after_global_pause_change` treatment as a local resume).

### D6. Known limit, stated

A gateway that is offline when pause-all is set, **and** whose store was unreachable from the issuing machine, **and**
that has never cached the register, cannot know. It is `unknown` in the output and pauses only when the store and the
change meet. The `unknown` label exists so the operator is not told otherwise. A held change (more than 60 s ahead,
A3) is not applied until the clock passes it; for a pause this means a skewed issuer can delay a pause by up to the
skew. The output reports `held (clock skew)` for a `:held` reply instead of `paused now`.

### D7. Reporting and local resume

- `GlobalPause.global_pause_status/1` gains `fleet_paused` and `pause_scope` (`:none | :local | :fleet | :both`). Text
  status prints `paused (fleet)`, `paused (local)`, or `paused (local + fleet)`. JSON consumers keep
  `globally_paused` as the **effective** value, so Stream Deck, dashboard, and `InstanceSummary` need no change to stay
  correct; the local-only value is the existing `source`/`paused_at` pair.
- `Instance.heartbeat_metadata/0` reads `:instance_globally_paused`; MPG-406 sets that env to the effective value so the
  heartbeat says `dispatching: false` while fleet-paused. One writer: `GlobalPause.put_effective_env/1`.
- `aiur resume` (no flag) while only the fleet pause holds refuses with exit 1:
  `paused by fleet pause (set <age> ago by <actor>); run aiur resume --all-gateways`. It does not silently flip a switch
  that was not on. Per-ticket `resume N` during a pause is already refused (existing behaviour); the message for the
  fleet case names the fleet pause.
- `aiur pause --all-gateways` is the only accepted combination. With ticket ids, `--all`, `--instance` or `--gateway`
  the engine exits 64 (`--all-gateways is its own command`). `--all` already means "every active ticket"; the long name
  avoids the collision.

### D8. Audit

The authoring daemon writes one `control-audit.ndjson` line for the change (existing fields plus S5 `origin_gateway`,
`actor`, `category: "agents"`) and each peer writes its own for the direct call, so the operator can reconstruct who
paused the fleet and which gateway heard it by which path.

## Interfaces

- Consumes from MPG-404: `Aiur.Intent.Store` local files and outbox; `Aiur.Intent.Sync.pull/1`, a push call, and a
  remote-apply function (named `Sync.apply_remote/1` here), idempotent by `change_id`, never touching the outbox.
- Consumes from MPG-405: `Aiur.Intent.Reconciler.fold/1` returning registers, and the writer that stamps the HLC and
  rejects a `default`-slot `pause` (A2).
- Consumes from MPG-205: allowlist categories (`agents`). From MPG-201/202: `--gateway`/`--instance` refusal rules.
- Provides `Aiur.Intent.Registers.fleet_pause/0 :: {:paused, change_id, set_at, actor} | :clear | :never_synced` and
  `Registers.write_fleet_pause/2`, `GlobalPause.effective_paused?/1`, the `fleet_paused` State field, and the control
  call `apply_fleet_pause_change/1`. MPG-602/603 (dashboard) read `pause_scope` from the gateway summary.

## Test scenarios

Fixtures: a fake store (in-memory, with a `down?` switch), two peer daemons as orchestrator test servers, a fake HTTP
control endpoint per peer with `up?` and a granted-category switch, a controllable clock. Never touch `~/.aiur`; set
`:global_pause_store_path` and the intent state root to temp dirs.

| Scenario | Input | Expected |
|---|---|---|
| Offline at pause, reconnect (acceptance 1) | Peer B down; A runs `pause_all`; store up. B boots, store reachable | A prints B `will pause on reconnect`; B after boot: `effective_paused? == true`, status `paused (fleet)`, dispatch call count 0 over one tick |
| Same, reverted production hunk | Boot gate removed | B dispatches one ticket; test fails |
| Per-gateway labels (acceptance 2) | B reachable, C down, D no `url`; store up | B `paused now`, C `will pause on reconnect`, D `will pause on reconnect` |
| Unknown | Store down, C down | C `unknown`, exit 69; B reachable still `paused now` |
| Store down, gateway reachable (acceptance 3) | Store down; B reachable | B `paused now`, B paused; A's outbox holds the change exactly once |
| Direct refused, store up | B token lacks `agents` | B `will pause on reconnect (direct call refused: category_not_granted: agents)`; exit 0; B pauses at its next pull |
| Reconnect mid-run | B running with store down; A pauses; store returns | `needs_pull` true, first tick after return pulls and does not dispatch; ticks after: no store read (assert pull count 1) |
| Local and fleet are independent | B local pause on; fleet pause on, then fleet resume | B still paused (local); `pause_scope :local`; `global-pause.json` unchanged by either fleet step |
| Fleet value never persisted | Fleet pause, restart B with store down and a cached `true` | `paused (fleet)`; with cache absent: not paused |
| Local resume while fleet paused | `aiur resume` on B | exit 1, message names the fleet pause; `fleet_paused` still true |
| Human pause, executor resume | Human `pause_all`, then `--as exec` `resume_all` | still paused; output `still paused: a human pause is set` |
| Executor pause, human resume | reverse | not paused (human unpause clears every slot) |
| Late unpause beats stale direct delivery | Pause (HLC 10) applied direct to B after the human unpause (HLC 20) already synced | B stays unpaused (fold by HLC); `:duplicate` or ignored |
| Daemon cannot pause | Call the writer with slot `default`, field `pause` | rejected; register unchanged |
| Clock skew hold | Peer applies a change 61 s ahead | `held (clock skew)`, not `paused now`; applies when the clock advances 1 s |
| Idempotent delivery | Same change by direct call and by sync | `fleet_paused` true once, one audit line each, outbox of B empty |
| Mixed flags | `pause 12 --all-gateways`; `pause --all --all-gateways`; `--gateway b pause --all-gateways` | each exits 64 |
| Running agents untouched | Pause with 2 running agents | both still running; slots available 0 |
| Heartbeat | Fleet pause | `heartbeat_metadata` `dispatching == false` |
| Boot bound | Store hangs | boot proceeds after 5 s ±1 s with the cached value |

Each **[fails without]** row is checked by reverting its production hunk (AGENTS.md "Tests must fail without the
production change"). The unknown rows must fail if the `unknown` label is replaced with `will pause on reconnect`.

## Risks

- **Guard-site drift.** A missed `globally_paused` match dispatches during a fleet pause. Detect: the test enumerates
  guard sites by grepping `src/lib` for `globally_paused: true` and fails if a new one appears that is not on its list.
  Fallback: the sites are few and local.
- **Near-limit files** (`dispatcher.ex` 494, `rate_limit_fallback.ex` 496, `state.ex` 479). Keep edits line-neutral or
  extract; the file-size gate is a hard fail.
- **Store down at issue time plus a never-synced gateway** (D6): reported as `unknown`, not hidden.
- **Dependence on unwritten interfaces** from MPG-404/405 (names above). If they differ, only units 1, 4 and 5 change.
- **Hot-file conflicts** with the other intent-sync tickets in `global_pause.ex`/`lifecycle.ex`; MPG-405 should land
  first, as the dependency says.
