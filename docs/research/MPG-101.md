## Decision (KTD-2)

**GO.** GraphQL `updateRefs` with `beforeOid` = 40 zeros is an atomic create-if-absent,
and a stale `beforeOid` rejects an advance.

- Chosen namespace: **`refs/aiur/owners/<ticket>`** (accepted, creates and lists like
  `refs/heads/aiur-owner/`, without appearing as branches).
- Loser signature: **there is none.** Every losing create, sequential or concurrent,
  returned `{"errors":[{"message":"Something went wrong while executing your query on <ts>. Please include `<id>` ..."}]}`
  with no `type` and no "already exists". It is indistinguishable from a real server
  error, so the adapter must never infer a loss from the error text.
- Re-read rule: on **any** error, re-read the ref. Pointing at my commit: I won (the
  call may have succeeded before the error). Pointing elsewhere: I lost. Absent: retry
  with backoff. Anything else is "ownership not established".
- Use only GraphQL `updateRefs` for claims and advances; REST `PATCH` is not a CAS.
