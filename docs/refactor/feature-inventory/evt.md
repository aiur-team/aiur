## Event bus, agent events & alerts (FI-EVT)
The in-BEAM eventing surface: the Exchange/Publisher/SubscriptionStore/IdGenerator core, the ls-remote branch-push detector, the locked agent event vocabulary and emit tools, cross-ticket auto-subscriptions, the alert pipeline (`.aiur/alerts`, sounds, feeds, CLI), and the internal Phoenix.PubSub topic contracts.

- **FI-EVT-001 · Wildcard topic-pattern routing** [api] — Exchange.subscribe/1 binds the calling pid to an AMQP-style pattern; publish/2 walks the ETS bindings table and delivers {:event, event} to every pid whose pattern matches via Topic.matches?/2 ('*' = one segment, '#' = zero-or-more), returning subscriber count (src/lib/aiur/events/exchange.ex:71,93-106; src/lib/aiur/events/topic.ex:32). Tests: src/test/aiur/events/exchange_test.exs, src/test/aiur/events/topic_test.exs. Risk: medium.
- **FI-EVT-002 · Non-blocking fire-and-forget publish** [api] — publish/2 reads the public ETS table directly (never the GenServer mailbox) and uses raw send/2, so a slow/sleeping subscriber cannot block a publisher; no backpressure, at-least-once with cursor dedup downstream (src/lib/aiur/events/exchange.ex:33-39,93-106). Routing publish through GenServer.call/cast would serialize the bus behind the slowest subscriber. Tests: src/test/aiur/events/exchange_test.exs (publish <100ms with sleeping subscriber). Risk: high.
- **FI-EVT-003 · Subscriber-death binding reap** [lifecycle] — Exchange monitors every subscriber at subscribe time; on :DOWN it match_deletes ALL bindings for that pid and drops monitor bookkeeping, so crashed subscribers never leave stale ETS rows (src/lib/aiur/events/exchange.ex:141,162-174). Tests: src/test/aiur/events/exchange_test.exs ("DOWN reaps binding within 100ms"). Risk: high.
- **FI-EVT-004 · Subscribe pattern validation raises** [api] — subscribe/1 raises ArgumentError in the caller (before the GenServer) for empty pattern, leading/trailing dot, or '..' (src/lib/aiur/events/exchange.ex:71-74,185-203); SubscriptionStore relies on this raising to rescue per-entry on bad persisted topics. Tests: src/test/aiur/events/exchange_test.exs. Risk: low.
- **FI-EVT-005 · unsubscribe removes one binding, no-op if absent** [api] — unsubscribe/1 removes the (pattern, caller) binding, demonitors with :flush, returns :ok; unknown pattern is a silent no-op. ETS is duplicate_bag: double-subscribe = double delivery, guarded by SubscriptionStore idempotency (src/lib/aiur/events/exchange.ex:81-83,146-159). Tests: src/test/aiur/events/exchange_test.exs. Risk: low.
- **FI-EVT-006 · bindings_for/1 and matches?/2 helpers** [api] — bindings_for(pid) lists patterns bound to a pid; Exchange.matches?/2 delegates to Topic.matches?/2 (src/lib/aiur/events/exchange.ex:113-117,124). Tests: src/test/aiur/events/exchange_test.exs. Risk: low.
- **FI-EVT-007 · Publisher event-ID + topic stamping** [api] — every accepted Publisher.publish/3 gets a fresh monotonic id from IdGenerator and %{id:, topic:} merged into the payload before Exchange fan-out; returns {:ok, id, subscriber_count} (src/lib/aiur/events/publisher.ex:102-109). The integer :id is load-bearing for cursor dedup. Tests: src/test/aiur/events/publisher_test.exs. Risk: medium.
- **FI-EVT-008 · Bot self-loop filter (case-insensitive)** [event] — publish/3 returns :filtered when opts[:actor] case-insensitively equals the workflow tracker bot_account, so Aiur never reacts to its own GitHub writes; nil actor passes; applies even with bypass_contamination: true (src/lib/aiur/events/publisher.ex:91-93,180-187). Tests: src/test/aiur/events/publisher_test.exs. Risk: medium.
- **FI-EVT-009 · Contamination filter via injected tracked_fn** [event] — publish/3 returns :filtered when opts[:issue_number] fails the tracked_fn stored in :persistent_term (orchestrator installs issue_tracked?/1 at src/lib/aiur/orchestrator.ex:262); nil issue_number bypasses; no fn installed = accept-all (src/lib/aiur/events/publisher.ex:95-97,149-152,189-196). Hot path deliberately avoids GenServer calls. Tests: src/test/aiur/events/publisher_test.exs. Risk: medium.
- **FI-EVT-010 · bypass_contamination publish option** [config-option] — bypass_contamination: true skips ONLY the tracked-issue filter (self-loop and dedup still apply), so inbound human comments on :deactivated tickets can reach the orchestrator for reactivation (src/lib/aiur/events/publisher.ex:76-84,95-97). Tests: src/test/aiur/events/publisher_test.exs. Risk: medium.
- **FI-EVT-011 · Replay dedup window on dedup_key** [event] — a second publish with the same {repo, kind, id} binary triple inside the TTL (default 1h, Publisher :ttl_ms start opt) returns :deduped; keys recorded in public ETS with monotonic timestamps (src/lib/aiur/events/publisher.ex:44-52,198-226). The 1h window is deliberate — GitHub's Events API re-emits for hours; shrinking it reintroduces duplicate pr.opened/issue.commented storms. Tests: src/test/aiur/events/publisher_test.exs. Risk: medium.
- **FI-EVT-012 · Malformed dedup_key never blocks publishing** [event] — a dedup_key that is not a 3-tuple of binaries is silently ignored and the event publishes normally (src/lib/aiur/events/publisher.ex:209-211). Tests: src/test/aiur/events/publisher_test.exs. Risk: low.
- **FI-EVT-013 · Dedup-table TTL sweep** [lifecycle] — the Publisher GenServer select_deletes dedup entries older than TTL every 60s, keeping the table bounded; unexpected process messages are ignored without crashing (src/lib/aiur/events/publisher.ex:52,171-178). Tests: src/test/aiur/events/publisher_test.exs (unexpected messages; sweep timing untested). Risk: low.
- **FI-EVT-014 · Publisher.set_tracked_fn hot-path injection** [api] — set_tracked_fn/1 stores an arity-1 fn in :persistent_term (also settable via :tracked_fn start opt); orchestrator re-installs at boot so the filter sees live running/queued sets (src/lib/aiur/events/publisher.ex:149-152,162-165). Tests: src/test/aiur/events/publisher_test.exs. Risk: low.
- **FI-EVT-015 · Per-issue SubscriptionStore attach (idempotent, error-swallowing)** [lifecycle] — attach/1 idempotently starts a per-identifier GenServer under a DynamicSupervisor via Registry; :already_started returns :ok and any other start error logs a warning and STILL returns :ok; child restart :transient (src/lib/aiur/events/subscription_store.ex:74-81,93-106). Callers rely on attach never raising. Tests: src/test/aiur/events/subscription_store_test.exs. Risk: medium.
- **FI-EVT-016 · Subscription persistence to <repo>.<id>.subscriptions.json** [artifact] — every mutation persists synchronously via JsonStore atomic-rename to <log_root>/<repo>.<sanitized-id>.subscriptions.json with keys subscribed_to / last_seen_event_id / open_attentions; persist failures are logged and swallowed (src/lib/aiur/events/subscription_store.ex:378-381,422-433). On-disk contract read back on restart. Tests: src/test/aiur/events/subscription_store_test.exs. Risk: medium.
- **FI-EVT-017 · Synchronous binding re-registration on init (no attach race)** [lifecycle] — init loads the persisted file and re-subscribes every topic with the Exchange BEFORE attach/1 returns, so a publish right after attach cannot drop; one bad persisted topic is rescued per-entry; corrupt files warn and start empty (src/lib/aiur/events/subscription_store.ex:203-210,383-420). Moving the load to handle_continue reintroduces the silent-drop race. Tests: src/test/aiur/events/subscription_store_test.exs (no-race + reload tests). Risk: high.
- **FI-EVT-018 · add_subscription with per-binding event-ID floor** [api] — add_subscription/3 records {topic, reason, subscription_created_at_event_id} where the floor is IdGenerator.peek/0 (an event-ID, not wall clock, so bootstrap replay is NTP-immune), persists, then registers with the Exchange (src/lib/aiur/events/subscription_store.ex:25-37,214-228). Tests: src/test/aiur/events/subscription_store_test.exs. Risk: medium.
- **FI-EVT-019 · First-write-wins subscription idempotency** [api] — re-adding a subscribed topic is a full no-op: ORIGINAL reason and floor are kept, so an auto-subscribe pass (blocker:auto) can't clobber a manual:agent claim and let reason-scoped removal drop it as collateral (src/lib/aiur/events/subscription_store.ex:230-238). Tests: src/test/aiur/events/subscription_store_test.exs (first-write-wins test). Risk: high.
- **FI-EVT-020 · Reason-scoped subscription removal** [api] — remove_subscription/3 removes a topic only if its recorded reason equals expected_reason (dependency teardown removes blocker:auto/blockee:auto without touching manual subs, src/lib/aiur/orchestrator.ex:7516-7519); remove_subscription/2 is unconditional; both unsubscribe from the Exchange and no-op on unknown topics (src/lib/aiur/events/subscription_store.ex:139-150,241-267). Tests: src/test/aiur/events/subscription_store_test.exs (/2 covered; /3 reason-scoping has no direct test). Risk: medium.
- **FI-EVT-021 · Monotonic last_seen_event_id cursor** [api] — advance_cursor/2 sets the cursor to max(current, new) — never rewinds — and persists; the same monotonic advance happens inline after each consumed event (src/lib/aiur/events/subscription_store.ex:269-279,332-339). Tests: src/test/aiur/events/subscription_store_test.exs. Risk: medium.
- **FI-EVT-022 · Cursor redelivery defense on event receive** [event] — on {:event, event}, an integer id <= the persisted cursor is silently dropped (restart redelivery); newer events are enqueued to the orchestrator, IssueLog-recorded as :consumed, DebugLog-broadcast as :receive, and the cursor advances+persists inline; events without an integer id skip the check and advance (src/lib/aiur/events/subscription_store.ex:306-328). The at-least-once → effectively-once layer. Tests: src/test/aiur/events/subscription_store_test.exs, src/test/aiur/events/event_delivery_test.exs. Risk: high.
- **FI-EVT-023 · Event enqueue routing to orchestrator (with test injection)** [integration] — consumed events go to the fn set via set_enqueue_fn/1 if present (exceptions swallowed), else GenServer.call(Aiur.Orchestrator, {:enqueue_event_digest, id, event}, 1_000); missing process or timeout is swallowed — a busy orchestrator drops the handoff rather than cascading, and the event is still marked consumed (src/lib/aiur/events/subscription_store.ex:341-364; src/lib/aiur/orchestrator.ex:5238-5239). Tests: src/test/aiur/events/event_delivery_test.exs, src/test/aiur/events/subscription_store_test.exs. Risk: high.
- **FI-EVT-024 · Open-attentions set (add/resolve, idempotent)** [api] — add_attention/2 appends a slug only if absent (order-preserving); resolve_attention/2 removes it, no-op on unknown; both persist; snapshot/1 exposes open_attentions + subscriptions + cursor, :not_found when no store runs — consumed by orchestrator, AgentRunner and the TUI (src/lib/aiur/events/subscription_store.ex:162-180,281-299). Tests: src/test/aiur/events/subscription_store_test.exs. Risk: low.
- **FI-EVT-025 · SubscriptionStore terminate: unbind + final flush** [lifecycle] — terminate/2 unsubscribes every persisted topic from the Exchange (all failures rescued) and does a final persist; stop/1 stops via Registry, no-op when absent (src/lib/aiur/events/subscription_store.ex:112-118,366-374). Note: no lib code calls stop/1 today — stores live until BEAM shutdown despite the moduledoc. Tests: src/test/aiur/events/subscription_store_test.exs. Risk: medium.
- **FI-EVT-026 · Restart-safe monotonic event IDs (reserve-before-return)** [api] — IdGenerator.next_id/0 returns strictly-increasing unique ids across BEAM restarts by persisting {last_id, reserved_through} to <log_root>/<repo>.event_id BEFORE issuing from a batch (batch_size opt, default 50); kill -9 can lose unused IDs (gap) but never re-issues (src/lib/aiur/events/id_generator.ex:100-111,128-137,169-180). Cursor dedup is meaningless if IDs rewind — do not swap back to :erlang.unique_integer. Tests: src/test/aiur/events/id_generator_test.exs (incl. kill simulation). Risk: high.
- **FI-EVT-027 · IdGenerator cold-boot fallback** [lifecycle] — missing/corrupt counter file logs a warning and seeds at max(scan of *.log IssueLog '[event:*] ... id=N' markers, system time µs) + 1_000_000 margin, so new IDs exceed anything previously issued (src/lib/aiur/events/id_generator.ex:139-167,208-250). The scan regex couples to the IssueLog marker line format. Tests: src/test/aiur/events/id_generator_test.exs. Risk: medium.
- **FI-EVT-028 · IdGenerator.peek/0 non-advancing read** [api] — peek/0 returns the current counter without advancing; next next_id/0 is peek+1; used as the subscription floor at binding creation (src/lib/aiur/events/id_generator.ex:69-77,113-115). - **FI-EVT-029 · IdGenerator survives unwritable counter path** [lifecycle] — a failed reservation persist logs exactly ONE deduplicated warning, stays alive, keeps issuing increasing in-memory IDs (restart-safety degraded, never crashes); terminate/2 does a best-effort final flush (src/lib/aiur/events/id_generator.ex:117-126,169-201). - **FI-EVT-030 · ls-remote polling: sole ticket-branch push detector** [integration] — LsRemoteTicker polls `git ls-remote --heads <remote> refs/heads/aiur/*` every interval (default 30s; opts: interval_ms, remote, ref_pattern, repo, start_paused?, ls_remote_fun, publisher) and publishes ticket.<id>.branch.push when a known ref's SHA changes or a new ref appears post-bootstrap; the GitHub firehose no longer publishes ticket branch pushes (src/lib/aiur/events/ls_remote_ticker.ex:19-25,185-243). - **FI-EVT-031 · Ticker bootstrap suppresses phantom pushes** [lifecycle] — the first SUCCESSFUL tick records all SHAs without publishing (logs `aiur_perf ls_remote_ticker phase=bootstrap_done refs=N`); error ticks keep bootstrapped? false so the first success is baseline, never a phantom-push storm auto-resuming every paused blockee (src/lib/aiur/events/ls_remote_ticker.ex:100-110,185-199). Documented past regression; trade-off: a push between error and next success is lost. Tests: src/test/aiur/events/ls_remote_ticker_test.exs. Risk: high.
