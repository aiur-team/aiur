## Runtime artifacts & persistence contracts (FI-ART)
Every file aiur reads or writes outside its own source tree — config sidecars, session logs, per-issue state, workspaces, caches, and foreign-tool files — with each artifact's path, format, readers/writers, and retention as the contract; runtime behavior of the owning subsystems is inventoried in their own sections.

- **FI-ART-001 · Config file discovery precedence** [artifact] — YAML config resolved by fixed precedence: `./.aiur/config` → legacy `./.aiurconfig` → `~/.aiur/config` → legacy `~/.aiurconfig`, with the repo-local path returned when none exist so errors point at the current layout (src/lib/aiur/workflow.ex:41-59). The engine shell independently walks up from `$PWD` (stopping at `$HOME`) to key the instance (packaging/npm/aiur-cli/libexec/aiur-engine.sh:47-66); config is re-read uncached so edits apply at the next poll tick. Discovery logic is duplicated in two languages and must stay in agreement (#443). Tests: src/test/aiur/workflow_test.exs, src/test/aiur/workspace_and_config_test.exs, packaging/npm/aiur-cli/test/launcher.test.mjs. Risk: medium.
- **FI-ART-002 · `.aiur/hooks` sidecar (hooks_file)** [artifact] — Optional `hooks_file:` key points at a sibling YAML file (resolved relative to the config dir) merged into config as `"hooks"`; a missing or invalid file is a load error (`{:missing_hooks_file, ...}` / `{:invalid_hooks_file, ...}`), never a silent skip (src/lib/aiur/workflow.ex:127-160). `aiur init` scaffolds it from `.aiur/examples/hooks.example` (src/lib/aiur/init.ex:78-85). Tests: src/test/aiur/workflow_test.exs, src/test/aiur/init_test.exs. Risk: low.
- **FI-ART-003 · `.aiur/prompt.md` Liquid prompt template (prompt_file)** [artifact] — Optional `prompt_file:` resolves a markdown Liquid template relative to the config dir; its contents replace the entire per-repo agent turn prompt, falling back to the tracker's built-in default when absent, and a configured-but-missing file is a load error (src/lib/aiur/workflow.ex:209-233). init scaffolds prompt.md with `{{REPO}}` filled at init time while preserving turn-time `{{ issue.* }}` Liquid for PromptBuilder (src/lib/aiur/init.ex:46-53). Tests: src/test/aiur/workflow_test.exs, src/test/aiur/prompt_builder_test.exs, src/test/aiur/init/prompt_test.exs. Risk: low.
- **FI-ART-004 · `.aiur/prewarm` build script (prewarm.base_build_file)** [artifact] — `prewarm.base_build_file:` points at a sibling shell script whose raw trimmed contents become `prewarm.base_build`, keeping the multi-line warm-base build command out of the main config (mirrors hooks_file); missing file is a load error (src/lib/aiur/workflow.ex:163-183). Aiur's own script runs deps.get + compile + `mix dialyzer --plt`, making PLT caches part of the warm base (.aiur/prewarm:1-7). Tests: src/test/aiur/workflow_test.exs, src/test/aiur/repo_base_test.exs, src/test/aiur/repo_prewarm_test.exs. Risk: low.
- **FI-ART-005 · `.aiur/alerts` / `alerts.yaml` topic-to-sound mapping** [artifact] — `alerts.alerts_file:` with a relative value anchors to the config dir; absolute/`~` values pass through untouched (src/lib/aiur/workflow.ex:185-207). When unset or unloadable, the default `<config-dir>/alerts.yaml` is read at runtime — a typo'd custom path falls back rather than erroring (src/lib/aiur/alerts.ex:310-359); init scaffolds a platform-specific mapping (macOS vs Linux sounds) (src/lib/aiur/init.ex:86-99). Tests: src/test/aiur/alerts_test.exs, src/test/aiur/workflow_test.exs. Risk: low.
- **FI-ART-006 · `aiur init` scaffolded `.aiur/` layout** [artifact] — init writes `.aiur/config` (or global `~/.aiur/config`) plus hooks, prompt.md, alerts, prewarm and an `examples/` folder; a legacy root `.aiurconfig` layout is migrated into the folder with example files renamed (e.g. `.aiurconfig.example` → `examples/config.example`), and repo-local init offers to append `.aiur/` to .gitignore (src/lib/aiur/init.ex:23-40,69-99). Templates are embedded at compile time via `@external_resource` so init works from a release (src/lib/aiur/init.ex:1126-1135). Tests: src/test/aiur/init_test.exs. Risk: low.
- **FI-ART-007 · `.env` secrets file (init-written, engine-loaded)** [artifact] — for GitHub trackers, init ensures `./.env` contains a `GITHUB_TOKEN` key: it creates a missing file with only `GITHUB_TOKEN=` or appends that line without rewriting existing bytes, and it never creates or modifies `.env.example` (`src/lib/aiur/init/scaffold.ex`). At launch the engine's `load_dotenv` parses `KEY=VALUE` pairs into the environment before exec'ing the release, with already-exported shell vars always winning over the file (`packaging/npm/aiur-cli/libexec/aiur-engine.sh`); init also loads cwd `.env` before its token checks (`src/lib/aiur/init/dotenv.ex`). Tests: `packaging/npm/aiur-cli/test/launcher.test.mjs`, `src/test/aiur/init/scaffold_test.exs`, `src/test/aiur/init_test.exs`. Risk: medium.
- **FI-ART-008 · Unified session log root `~/.aiur/logs/<session-id>/`** [artifact] — Every run persists under one timestamped session root, resolved in order: explicit `--logs-root` (Application `:log_file`) → `AIUR_LOGS_ROOT` env (exported by scripts/aiurdev and the engine for background runs, format `<UTCstamp>-<pid>`) → freshly minted `~/.aiur/logs/<UTCstamp>-<ospid>`; test env skips minting (src/lib/aiur/log_file.ex:35-76). `Aiur.Config.Paths.log_root_dir/0` is the single source of truth for all per-issue/per-repo sidecars (src/lib/aiur/config/paths.ex:28-35); shell and BEAM must agree on the same root, and `aiurdev --clear` (debug-gated) wipes prior sessions (scripts/aiurdev:352-357). Tests: src/test/aiur/log_file_test.exs, src/test/aiur/config_paths_test.exs. Risk: medium.
- **FI-ART-009 · Application log `<session>/log/aiur.log` (debug-gated, no rotation)** [artifact] — With AIUR_DEBUG truthy (`--debug` flag or config `debug: true` bridged into AIUR_DEBUG at boot; the flag can never be downgraded by config), an OTP `:logger_std_h` file handler writes single-line logs with filesync every 200ms so `tail -F` follows live; without debug there is NO aiur.log and the console handler is removed (src/lib/aiur/log_file.ex:113-127,158-196). No rotation by design; legacy disk_log wrap files (.idx/.siz/.N) are removed (src/lib/aiur/log_file.ex:214-226). Tests: src/test/aiur/log_file_test.exs. Risk: low.
- **FI-ART-010 · Background-run boot capture `<session>/log/boot.out.log`** [artifact] — `--bg` runs tee BEAM startup stdout/stderr into a durable `$AIUR_LOGS_ROOT/log/boot.out.log` (foreground uses a mktemp file) so boot crashes are diagnosable after the launcher exits; the dir/file is created lazily just before launch so an idempotent early-return start leaves no empty dir (packaging/npm/aiur-cli/libexec/aiur-engine.sh:445-455). Startup-grace crash surfacing depends on this capture. Tests: packaging/npm/aiur-cli/test/launcher.test.mjs. Risk: medium.
- **FI-ART-011 · BEAM crash record `<session>/log/aiur.crash` + `<state>/<slug>.last-crash`** [artifact] — A bash BEAM-death watchdog (armed for background runs, outliving the BEAM) distinguishes intentional stop from crash via a stop sentinel: on unexpected exit it appends a crash body to `<run_log_dir>/log/aiur.crash` and writes a per-instance `.last-crash` marker that `aiur status` surfaces; a fresh run deletes stale crash/stop state first so status never reports a previous instance's crash (packaging/npm/aiur-cli/libexec/aiur-engine.sh:980-1023,568-580,1146-1185). Timing-sensitive bash (watchdog poll, consume-vs-crash race, `seen` latch) with no ExUnit coverage. Tests: packaging/npm/aiur-cli/test/launcher.test.mjs. Risk: high.
- **FI-ART-012 · Log-history retention sweep of `~/.aiur/logs`** [lifecycle] — `Aiur.Logs.Retention` periodically (default 5 min) bounds total log size to `max_log_history_mb` (default 1000 MB), deleting oldest session dirs by mtime until under cap and never deleting the ACTIVE session resolved from `Paths.log_root_dir` (src/lib/aiur/logs/retention.ex:88-134,165-183; src/lib/aiur/config/schema.ex:556). A custom `--logs-root` outside the retention root makes everything under `~/.aiur/logs` a candidate; the current-session guard is the invariant. Tests: src/test/aiur/logs/retention_test.exs. Risk: medium.
- **FI-ART-013 · JsonStore crash-safe write pattern (tmp + fsync + rename)** [artifact] — All small JSON sidecars (event-ID counter, subscription state, session handles) go through `Aiur.JsonStore.write!`: write `path.tmp.<unique>`, fsync, rename into place — atomic to concurrent readers, last-writer-wins; reads return the default on missing file and `{:error, reason}` on corruption so callers choose fallback vs refuse (src/lib/aiur/json_store.ex:1-51). Replacing this with plain `File.write` would reintroduce torn-file corruption after crashes. Tests: src/test/aiur/json_store_test.exs. Risk: medium.
- **FI-ART-014 · Per-issue transcript log `<logs-root>/<repo>.<id>.log` (IssueLog)** [artifact] — One GenServer per active issue subscribes to the agent's PubSub topic and appends every transcript/alert event via `File.open([:append, :utf8])`; `attach/1` is idempotent and the writer lives until BEAM exit, with the last 100 events kept in memory for `history/2` backfill (src/lib/aiur/issue_log.ex:215-234; src/lib/aiur/agent_runner.ex:1963-1966). Filename pattern and event-line format are load-bearing beyond display — IdGenerator's cold-boot scan reads them (see FI-ART-015). Tests: src/test/aiur/issue_log_event_history_test.exs. Risk: low.
- **FI-ART-015 · Persistent monotonic event-ID counter `<logs-root>/<repo>.event_id`** [artifact] — `Events.IdGenerator` reserves ID blocks via JsonStore; on boot it resumes past the reserved block, a missing/corrupt file triggers a cold-boot scan of IssueLog files for the max emitted ID (provable monotonicity after damage), fresh installs seed at base, and persistence failure degrades loudly to in-memory IDs rather than halting event flow (src/lib/aiur/events/id_generator.ex:15-25,129-150,183-205). Monotonicity across crash/restart is the contract; subscription snapshots depend on it. Tests: src/test/aiur/events/id_generator_test.exs. Risk: medium.
- **FI-ART-016 · Per-issue subscription state `<logs-root>/<repo>.<id>.subscriptions.json`** [artifact] — Each issue's SubscriptionStore persists subscriptions through crash-safe JsonStore on every mutation and reads them back on `init/1` so they survive restarts; a corrupt file logs a warning naming the path and the store falls back per policy instead of crashing the tree (src/lib/aiur/events/subscription_store.ex:378-398,423). Known seed-dependent test flakes from subs files persisting across mix-test runs — persistence path is concurrency/isolation sensitive. Tests: src/test/aiur/events/subscription_store_test.exs, src/test/aiur/events/event_delivery_test.exs. Risk: high.
- **FI-ART-017 · Durable per-issue SessionHandle `<logs-root>/<repo>.<id>.session.json`** [artifact] — AgentRunner persists `{backend, thread_id, hostname, updated_at, schema_version}` after each turn so a restarted aiur resumes the agent's prior thread (#378); `load/3` returns the handle only for same backend AND same host — missing/corrupt/forward-versioned/mismatched handles return `:none` and the runner cold-starts (src/lib/aiur/session_handle.ex:1-31,95-100; src/lib/aiur/agent_runner.ex:926-935). Terminal-state cleanup clears handles; todo-state cleanup deliberately does not (src/lib/aiur/orchestrator.ex:4176); lives in the shared state dir so it survives a workspace reclone. Tests: src/test/aiur/session_handle_test.exs, src/test/aiur/agent_runner_test.exs, src/test/aiur/orchestrator_status_test.exs. Risk: medium.
- **FI-ART-018 · Central alerts feed `<logs-root>/alerts.ndjson`** [artifact] — Alerts without a local workspace (or from a worker host) are appended one JSON line each, best-effort (failures only debug-log) (src/lib/aiur/alerts.ex:209-237). `Aiur.AlertFeed` merges this central file with per-workspace agent.ndjson alert lines — scanning both the configured workspace root and legacy `~/.aiur/workspaces` — dedupes, optionally filters needs_attention, sorts by timestamp (src/lib/aiur/alert_feed.ex:10-52). Tests: src/test/aiur/alerts_test.exs, src/test/aiur/alert_feed_test.exs. Risk: low.
- **FI-ART-019 · Workspace agent transcript sinks `logs/agent.md` + `logs/agent.ndjson`** [artifact] — AgentEventLog appends EVERY agent event to both per-workspace sinks: agent.md (chat-style markdown, `## <ts> <event>` + fenced body) and agent.ndjson (one JSON object per line); the ndjson stream must never be event-type-filtered — it is the only structured per-event record and crash reasons like `{:port_exit, N}` must persist for post-mortem (#708) (src/lib/aiur/agent_event_log.ex:1-45). Readers: `Aiur.AgentLog` regex-parses agent.md for the log pane (writer and parser must move together, src/lib/aiur/agent_log.ex:18-57); AlertFeed reads agent.ndjson alert lines. Writes are best-effort; remote worker_host events are skipped. Tests: src/test/aiur/agent_event_log_test.exs (regression for #708), src/test/aiur/agent_log_test.exs, src/test/aiur/alert_feed_test.exs. Risk: medium.
- **FI-ART-020 · Operator message wait metrics `<logs-root>/metrics/operator_message_wait.ndjson`** [artifact] — OperatorWaitLog appends one NDJSON line per delivered operator message (`{at, identifier, request_id, wait_ms, text_bytes}`) measuring submit-to-delivery latency, deliberately placed in `metrics/` so it survives `aiur --clear` (which only deletes top-level aiur*.log) and `--test` resets, accumulating cross-run samples on wall-clock time (src/lib/aiur/operator_wait_log.ex:1-27,86-100).
