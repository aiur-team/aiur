## Orchestrator & agent lifecycle (FI-ORC)
Dispatch, concurrency, retry, pause/resume, reconciliation, event routing, and the AgentRunner turn loop that together drive agents from ticket claim to teardown.

- **FI-ORC-001 · Poll tick loop with tokenized timers** [lifecycle] — Ticks are scheduled via Process.send_after with a unique tick_token; stale `{:tick, token}` messages are dropped (bare `:tick` still accepted). A tick sets poll_check_in_progress, notifies the dashboard, then defers the poll cycle by 20ms (@poll_transition_render_delay_ms) so the agent-list renders the "0s" label first; the next tick re-arms at max(GitHub backoff delays, poll_interval_ms) (src/lib/aiur/orchestrator.ex:310-353, src/lib/aiur/orchestrator.ex:6840-6859, src/lib/aiur/orchestrator.ex:1497-1508). Tests: src/test/aiur/orchestrator_status_test.exs, src/test/aiur/orchestrator_broadcast_test.exs, src/test/aiur/core_test.exs. Risk: medium.
- **FI-ORC-002 · Runtime config refresh per tick** [config-option] — poll_interval_ms and max_concurrent_agents are re-read from Config.settings! on every tick and on `:snapshot`, so `.aiur/config` edits apply without restart; the session cap override is never clobbered by this refresh (src/lib/aiur/orchestrator.ex:6890-6898, src/lib/aiur/orchestrator.ex:5289). Tests: src/test/aiur/orchestrator_max_agents_test.exs. Risk: low.
- **FI-ORC-003 · Startup terminal-workspace cleanup** [lifecycle] — At init, all issues in terminal states get their workspaces removed AND persisted SessionHandles cleared; missing Linear credentials skip quietly (debug log), other preflight failures warn and skip, and GitHub cleanup is independent of Linear auth (src/lib/aiur/orchestrator.ex:186, src/lib/aiur/orchestrator.ex:4227-4291). Tests: src/test/aiur/orchestrator_status_test.exs. Risk: low.
- **FI-ORC-004 · Startup todo-workspace cleanup** [lifecycle] — After terminal cleanup, workspaces of issues currently in a 'todo' state are removed so fresh dispatch starts from a clean clone; session handles are NOT cleared. Uses configured active states with slug 'todo', falling back to ["todo"] (src/lib/aiur/orchestrator.ex:187, src/lib/aiur/orchestrator.ex:4179-4225). Tests: src/test/aiur/orchestrator_status_test.exs. Risk: low.
- **FI-ORC-005 · Shutdown reaping in terminate/2** [lifecycle] — The orchestrator traps exits; terminate calls ProcessReaper.reap([:agent], drain: false) then kill_repl_session for every running entry, so headless claude/node grandchildren reparented to init cannot survive shutdown and keep pushing. drain: false is load-bearing: terminate also runs on supervised crash-restart and must not latch the reaper into draining (src/lib/aiur/orchestrator.ex:165, src/lib/aiur/orchestrator.ex:206-215, src/lib/aiur/orchestrator.ex:6699-6714). Tests: src/test/aiur/orchestrator_deactivate_test.exs. Risk: high.
- **FI-ORC-006 · TrackedSet ETS contamination gate** [integration] — The event Publisher consults Orchestrator.issue_tracked?/1 via ETS (never a GenServer call, avoiding deadlock during :run_poll_cycle); the set rebuilds after every poll and on deactivation, with :deactivated entries EXCLUDED so late events from killed tasks drop. TrackedSet.member? fails open (true) when the table is missing, and the table is owned by a supervised process surviving orchestrator restarts (src/lib/aiur/orchestrator.ex:260-307, src/lib/aiur/orchestrator/tracked_set.ex:36-46). Tests: src/test/aiur/orchestrator_tracked_set_test.exs. Risk: high.

- **FI-ORC-009 · Dispatch candidate gates** [lifecycle] — An issue dispatches only when ALL hold: id/identifier/title/state binaries present; routable to this worker; state active and not terminal; a 'todo' issue not blocked by any non-terminal blocker (unknown blocker state counts as blocking); not claimed or running; per-state slot room; worker host slot available. - **FI-ORC-010 · Per-state concurrency caps** [config-option] — effective_state_limit honors agent.max_concurrent_agents_by_state[state] first, then falls back to the SESSION-aware global limit (session override > state > config) so runtime cap bumps affect per-state eligibility; only active (non-paused, non-deactivated) entries count against the per-state total (src/lib/aiur/orchestrator.ex:3594-3628, src/lib/aiur/orchestrator.ex:4743-4754).
