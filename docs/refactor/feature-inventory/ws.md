## Workspaces, init & test modes (FI-WS)
Per-issue workspace lifecycle (creation, layout, hooks, warm-base materialize, removal, remote SSH prep), the `aiur init` wizard, and the `--test`/`--test3` sandbox reset machinery.

- **FI-WS-001 · Per-issue workspace creation** [lifecycle] — `Workspace.create_for_issue/2` builds an isolated dir per issue under `workspace.root`: sanitize identifier (non `[a-zA-Z0-9._-]` → `_`), canonicalize, validate under root, ensure dir, run `after_create` hook (fresh creates only), install agent skills — in that with-chain order (src/lib/aiur/workspace.ex:16-35, src/lib/aiur/workspace.ex:875-877). Rescues ArgumentError/ErlangError/File.Error into `{:error, error}` with a logged context line. Tests: src/test/aiur/workspace_and_config_test.exs. Risk: medium.
- **FI-WS-002 · Repo-namespaced layout `<root>/<owner>/<repo>/<issue>`** [artifact] — Workspace paths are namespaced by the full owner/name repo segment (nested dirs; Linear uses `project_slug`; memory tracker falls back to flat `<root>/<issue>`). The append is idempotent when the root already ends with the repo segment (init bakes owner/name into the default root), and each segment component is sanitized with `.`/`..`/empty parts dropped so it can never escape the root (src/lib/aiur/workspace.ex:827-873). Tests: src/test/aiur/workspace_and_config_test.exs. Risk: high.
- **FI-WS-003 · `workspace_path_under/2` shared-layout API** [api] — Public helper returning the per-issue path under an already-expanded root with the exact same repo-namespace + identifier sanitization as `create_for_issue/1`, used by per-workspace alert logging and the opencode session writer to locate workspaces without re-deriving layout (src/lib/aiur/workspace.ex:798-809); drift silently relocates `<workspace>/logs/agent.md` artifacts (#708). Tests: none directly (exercised via callers). Risk: medium.
- **FI-WS-004 · Workspace path safety guard (root containment)** [lifecycle] — Local paths are `Path.expand`-ed and symlink-canonicalized; create/remove refuse with distinct errors `{:workspace_equals_root,..}`, `{:workspace_symlink_escape,..}`, `{:workspace_outside_root,..}` (src/lib/aiur/workspace.ex:1079-1119). Remote (SSH) paths only get empty/newline/NUL checks. Tests: src/test/aiur/workspace_and_config_test.exs. Risk: medium.
- **FI-WS-005 · Workspace reuse without deletion** [lifecycle] — An existing workspace dir is reused as-is (`created?=false`, no `after_create` hook, local changes preserved) — the contract underpinning agent resume; a non-directory file at the path is `rm_rf`'d and the workspace recreated fresh (src/lib/aiur/workspace.ex:71-83, src/lib/aiur/workspace.ex:879-899). Tests: src/test/aiur/workspace_and_config_test.exs. Risk: medium.
- **FI-WS-006 · Warm-base materialize (copy-on-write workspace)** [lifecycle] — With prewarm enabled and `RepoBase.status()` `{:ready, base}`, new workspaces copy the warm base (`cp -Rc` macOS / `cp -a --reflink=auto` Linux, degrading to full copy) carrying gitignored `_build`/`deps`, then branch `aiur/<id>` off the LIVE `origin/<base>` tip (fetch first; copied-HEAD fallback offline, #567), falling through to the cold path on any failure (src/lib/aiur/workspace.ex:129-217, src/lib/aiur/workspace.ex:273-300). `created?` is `:materialized`, which suppresses the `after_create` hook (src/lib/aiur/workspace.ex:893-895) — losing that suppression would double-clone. Tests: src/test/aiur/workspace_materialize_test.exs. Risk: high.
- **FI-WS-007 · PR-anchored workspaces (`pr-<pr#>` leaf, human PR head branch)** [lifecycle] — An issue with non-empty `pr_head_ref` gets a `pr-`-prefixed workspace leaf (identifier/resume key stays the bare PR number) so a watched human PR never collides with a same-numbered ticket; materialize fetches the PR head ref and checks it out via `git checkout -B <ref> FETCH_HEAD` (deliberately not `--track`; never creating `aiur/<id>` — regressing would open duplicate PRs), with a local-branch fallback when no usable remote (src/lib/aiur/workspace.ex:50-69, src/lib/aiur/workspace.ex:186-270). Remote worker_hosts ignore `pr_head_ref` and keep the legacy path byte-for-byte (src/lib/aiur/workspace.ex:1180-1230). Tests: src/test/aiur/workspace_materialize_test.exs; src/test/aiur/workspace_and_config_test.exs. Risk: high.
- **FI-WS-008 · `after_create` hook (cold-clone bootstrap)** [config-option] — `hooks.after_create` runs inside the workspace only when `created?==true` — never on reuse (`false`) or warm-base materialize (`:materialized`) — and its failure or timeout fails workspace creation (src/lib/aiur/workspace.ex:879-900). Tests: src/test/aiur/workspace_and_config_test.exs. Risk: medium.
- **FI-WS-009 · `before_run` hook + exit-65 dirty-refresh contract** [lifecycle] — `run_before_run_hook` runs `hooks.before_run`, verifies git metadata writable, then optionally seeds from a bootstrap image. Exit 65 = "refuses to refresh a dirty tree": for a todo dispatch the stale workspace is recreated clean and before_run re-run (#577); for an in-flight/resumed agent the refusal is non-fatal — refresh skipped, WIP preserved, `:ok` returned (#653); any other error is fatal (src/lib/aiur/workspace.ex:381-456, src/lib/aiur/workspace.ex:559-574). The exit-65 magic number is shared with the operator's checked-in hooks file; the todo-vs-in-flight branch decides whether agent WIP survives. Tests: src/test/aiur/workspace_and_config_test.exs. Risk: high.
- **FI-WS-010 · `.git`-writable bootstrap (stale lock repair)** [lifecycle] — Before each run, `ensure_git_metadata_writable/2` resolves the git dir (must canonicalize inside the workspace, else `{:git_dir_outside_workspace,..}`), then for `index.lock`, `FETCH_HEAD.lock`, `ORIG_HEAD.lock`, and `refs/remotes/origin/aiur/<id>.lock` removes stale locks and exclusive-creates/deletes a probe file; `pr-*` workspaces additionally probe the checked-out head-ref lock; non-git workspaces pass; an SSH-script variant mirrors this remotely (exit 31 = git metadata outside workspace) (src/lib/aiur/workspace.ex:598-781). Tests: src/test/aiur/workspace_and_config_test.exs; src/test/aiur/workspace_materialize_test.exs. Risk: high.
- **FI-WS-011 · Bootstrap-image warm cache seeding** [config-option] — With `workspace.bootstrap_image` set, after before_run the workspace is seeded via `docker run` (current uid:gid, workspace bind-mounted at /workspace) copying `/opt/aiur/{src/deps,src/_build,deps,_build}`, keeping any path that already exists and exiting 66 if no cache path is found; `bootstrap_image_pull=true` adds a `docker pull` first; runs locally or over SSH bounded by `hooks.timeout_ms` (src/lib/aiur/workspace.ex:458-557, src/lib/aiur/config/schema.ex:165-173). Tests: src/test/aiur/workspace_and_config_test.exs. Risk: medium.
- **FI-WS-012 · `after_run` hook (failure-ignored)** [config-option] — `hooks.after_run` runs in the workspace after an agent run; failures and timeouts are swallowed so post-run cleanup can never fail the run (src/lib/aiur/workspace.ex:783-796, src/lib/aiur/workspace.ex:965-966). Tests: src/test/aiur/workspace_and_config_test.exs. Risk: low.
- **FI-WS-013 · `before_remove` hook + workspace removal** [lifecycle] — `Workspace.remove/2` validates the path, runs `hooks.before_remove` (failures, large output, and timeouts all ignored — removal proceeds regardless), then `File.rm_rf`; remotely the hook + `rm -rf` run via SSH wrapped in `if [ -d ... ]` (src/lib/aiur/workspace.ex:302-379). `remove_issue_workspaces/2` fans out across every `worker.ssh_hosts` entry when configured, else removes locally; non-binary identifiers are a no-op `:ok` (src/lib/aiur/workspace.ex:902-963). Tests: src/test/aiur/workspace_and_config_test.exs. Risk: medium.
- **FI-WS-014 · Hook execution environment (env scrub + THIS_REPOSITORY_URL + perf log)** [integration] — Local hooks run as `sh -lc` with cd=workspace, stderr merged, Erlang distribution env scrubbed via `AgentEnvironment.scrub_shell_command` (prevents "name already in use" node crashes inside mix hooks), and `THIS_REPOSITORY_URL` exported for github trackers; each hook is bounded by `hooks.timeout_ms` with brutal-kill shutdown, logs an always-on `aiur_perf workspace_hook ... elapsed_ms=` line, a 512-byte output tail on success, and 2048 truncated bytes on failure (src/lib/aiur/workspace.ex:968-1077). Tests: src/test/aiur/workspace_and_config_test.exs (env-scrub and perf-line not directly asserted). Risk: high.
- **FI-WS-015 · Remote (SSH) workspace prep protocol** [integration] — For a worker_host, workspace ensure runs a shell script over SSH that mkdir-p's (or replaces a non-dir) the workspace and prints the marker `__AIUR_WORKSPACE__\t<created 0|1>\t<pwd -P>`, parsed tolerating surrounding noise to yield `{:ok, workspace, created?}`; paths get tilde-expansion against remote `$HOME` and single-quote escaping; remote commands run in a Task bounded by `hooks.timeout_ms`, timing out as `{:error, {:workspace_hook_timeout, "remote_command", ms}}` (src/lib/aiur/workspace.ex:85-116, src/lib/aiur/workspace.ex:1121-1175). Tests: src/test/aiur/workspace_and_config_test.exs. Risk: high.
- **FI-WS-016 · Workspace agent-skills install (#689/#722)** [skill] — After a workspace is populated (create or reuse), the compile-time-embedded using-aiur and aiur-agent skills are written into `<workspace>/.claude/skills/` with `.codex/skills/<skill>` relative symlinks back; local worker only, idempotent, never clobbers a skill the target repo ships, best-effort (file errors logged, never fail creation), atomic per skill via temp-dir stage + rename, dangling codex symlinks detected via lstat (src/lib/aiur/workspace.ex:37-43, src/lib/aiur/agent_skills.ex:73-143). Tests: src/test/aiur/workspace_and_config_test.exs; Aiur.AiurAgentSkillTest cross-check. Risk: medium.
- **FI-WS-017 · `aiur init` wizard entry (dotenv load, req start, risk warning)** [cli-command] — `Init.run/1` loads `KEY=VALUE` pairs from `./.env` into process env (existing env always wins; values never logged), starts the `:req` HTTP client (init boots without the OTP app), and prints the fixed "Use at your own risk: aiur bypasses all agent permissions..." warning before any prompt (src/lib/aiur/init.ex:137-179, src/lib/aiur/init.ex:2203-2248). Tests: src/test/aiur/init_test.exs. Risk: low.
- **FI-WS-018 · Existing-config detection and resume (probe order, `--force`)** [cli-flag] — Without `--force`, init probes in Workflow-discovery order `./.aiur/config`, `./.aiurconfig`, `~/.aiur/config`, `~/.aiurconfig`; the first hit resumes setup — saved-selections summary, intro questions skipped, then migration offer, section backfill, prewarm verify, CODEOWNERS, and provisioning re-run. `--force` always starts fresh; an unreadable existing config errors with a "--force to recreate" hint (src/lib/aiur/init.ex:152-226). Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-WS-019 · Legacy `.aiurconfig` → `.aiur/` layout migration** [lifecycle] — On resume over a legacy layout, init offers migration: `migrate_layout/1` copies referenced hooks/prompt files and `*.example` templates into `.aiur/` FIRST, then writes the rewritten config (only pointer keys whose files actually moved, quoted values replaced whole), and only then removes legacy originals — partial failure never leaves an unloadable state (src/lib/aiur/init.ex:237-257, src/lib/aiur/init.ex:1848-1988). Tracked files move via `git rm`/`git add` (unless `ignore: true`, which appends `.aiur/` to .gitignore); pointer targets outside the repo are never copied or deleted; declining leaves the still-loadable legacy layout. Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-WS-020 · Fresh-setup scaffold wizard (question flow + template fill)** [cli-command] — Fresh setup asks in order: settings location (repo `./.aiur/` vs global `~/.aiur/`), tracker (github w/ origin-remote repo detect, or linear key/slug), agent multiselect (claude/codex only, never claude-repl; empty → first), optional per-complexity(1-5) routing encoded `backend[:model][:[:]effort]`, permission mode (interactive modes redirect to bypassPermissions w/ warning), workspace root (default `~/.aiur/workspaces/<owner>/<repo>` for github repo-local), max agents (10), max turns ('none'=uncapped), max duration minutes (60; 'none'→0 = watchdog disabled), pre-warmed opencode sessions (3), polling seconds (30), prompt_file (repo-local only), prewarm opt-in, alerts opt-in; answers fill `{{TOKEN}}` placeholders in the embedded config example (src/lib/aiur/init.ex:271-323, src/lib/aiur/init.ex:544-705, src/lib/aiur/init.ex:1021-1078). Global config intentionally omits repo, prompt_file, and prewarm. Tests: src/test/aiur/init_test.exs (extensive). Risk: medium.
- **FI-WS-021 · Init sibling-file scaffolding (prompt.md, hooks, alerts, prewarm, .env)** [artifact] — After writing the config, init scaffolds referenced files without clobbering project-owned content: prompt file (embedded `prompt.md.example`, `{{REPO}}` filled, turn-time `{{ issue.* }}` Liquid preserved), `.aiur/hooks`, `.aiur/alerts` (host-OS macOS/Linux template or reused `~/.aiur/alerts` copy), `.aiur/prewarm` (detected base-build command, opt-in only), and `.env` for GitHub trackers. A missing `.env` contains only `GITHUB_TOKEN=`; an existing file gains that line only when the key is absent. Init never creates or modifies `.env.example` (`src/lib/aiur/init/scaffold.ex`, `src/lib/aiur/init/templates.ex`). Tests: `src/test/aiur/init/scaffold_test.exs`, `src/test/aiur/init_test.exs`. Risk: medium.
- **FI-WS-022 · Gitignore opt-in for `.aiur/`** [cli-command] — Repo-local init (and migration) offers appending `.aiur/` to .gitignore: idempotent (trimmed-line check, returns `:exists`), creates .gitignore if absent, preserves a missing trailing newline; global setup never offers it; declining leaves `.aiur/` tracked for team-shared config (src/lib/aiur/init.ex:1129-1140, src/lib/aiur/init.ex:1826-1846). Tests: src/test/aiur/init_test.exs. Risk: low.
- **FI-WS-023 · CODEOWNERS trust setup (#705)** [integration] — For github trackers, on BOTH fresh setup and resume: explains CODEOWNERS decides whose PR/issue comments aiur trusts, offers to create a comment-only `.github/CODEOWNERS` scaffold, detects the operator via `gh api user`, and offers to add them — appending `@login` to the LAST existing `*` wildcard rule (before inline comments) or a new `* @login` rule; duplicate detection is case-insensitive, `@`-tolerant, comment-aware; declines respected, file errors degrade to warnings (src/lib/aiur/init.ex:1148-1368, src/lib/aiur/init.ex:2137-2149). Security/trust surface: a wrong append changes who can drive agents from comments. Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-WS-024 · Pre-warm opt-in (toolchain detect, first build, failure triage)** [config-option] — Repo-local init offers a pre-warmed main checkout: single detected build command → use/edit/skip; ambiguous or missed detection discloses candidates and hands the operator a ready-to-paste coding-agent prompt, leaving prewarm disabled. On opt-in the command is written to `.aiur/prewarm` and the warm base built once via `RepoBase.refresh`; a build failure is classified (auth/clone/build/other) with class-specific guidance plus an AI handoff prompt embedding ≤1500 chars of failure output; global configs skip prewarm; resume re-verifies an enabled prewarm config by re-running the first build (src/lib/aiur/init.ex:707-974, src/lib/aiur/init.ex:529-542). Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-WS-025 · Resume backfill of promptable config sections (#411)** [lifecycle] — On resume, init walks a registry of promptable sections (currently only `prewarm`); for any registered top-level key the saved config lacks, it reuses the fresh-setup prompt and on opt-in APPENDS the rendered YAML block to the existing config (never regenerating the file), running the section's one-time side effect only after the append succeeded; declining leaves the config untouched (src/lib/aiur/init.ex:444-527, src/lib/aiur/init.ex:1751-1757). Convention: every new init prompt for a new config section must be registered here. Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-WS-026 · GitHub label provisioning (staged, idempotent, token-gated)** [integration] — With GITHUB_TOKEN, init fetches existing labels once (REST, 100/page) then runs four gated stages: required `agent:*` lifecycle labels (Enter-gated), optional complexity labels, optional model-override labels for chosen backends, and `model:remote` (claude-only, default No); all-existing stages print a faint "created." status instead of prompting; creation failures print per-label `gh label create ... --force` fallbacks and withhold the ready screen (src/lib/aiur/init.ex:1387-1567). No token → numbered token-creation instructions; Linear gets an API-key walkthrough + limited-support warning; the final screen says label issues `agent:todo` and run `aiur --bg` (src/lib/aiur/init.ex:2023-2097). Tests: src/test/aiur/init_test.exs (15+ tests). Risk: low.
- **FI-WS-027 · Agent CLI presence checks + aiur-claude auto-install** [integration] — After the config is written (so failures never block setup), init verifies each selected CLI-backed agent's command resolves on PATH (claude-repl skipped — no CLI); a missing claude triggers automatic `npm install -g aiur-claude` before re-checking, degrading to a manual-install hint on failure; other missing CLIs warn with an install hint and offer retry/skip, proceeding either way (src/lib/aiur/init.ex:1571-1631, src/lib/aiur/init.ex:2099-2135). Tests: src/test/aiur/init_test.exs. Risk: low.
- **FI-WS-028 · `--test`/`--test3` sandbox reset with four safety guards** [cli-command] — `Aiur.TestReset.run` (via `mix aiur.test.reset`, wired to `aiur --test/--test3`) enforces in order: agent-workspace guard, pinned ticket IDs from `.aiur-test-tickets.json` (empty/invalid ids abort), clean git tree (`--force` overrides), origin remote matching `expected_remote` (`--allow-remote` overrides; nil passes), and sandbox baseline files present in HEAD (src/lib/aiur/test_reset.ex:60-129, src/lib/aiur/test_reset.ex:151-254). Without `--confirm` it is a dry-run printing the full per-ticket plan to stderr with zero side effects; `single: true` (`aiur --test`) narrows to the FIRST pinned ticket; the mix task resolves repo_root via `git rev-parse --show-toplevel` and `System.halt(1)`s on error (src/lib/mix/tasks/aiur.test.reset.ex:33-64). Tests: src/test/aiur/test_reset_test.exs. Risk: medium.
- **FI-WS-029 · Fail-closed agent-workspace guard on test reset** [lifecycle] — TestReset refuses to run when `AIUR_AGENT_WORKSPACE` is set non-empty or repo_root contains `/aiur-workspaces/`, returning `{:error, :agent_workspace_blocked}` with an explicit "agents must stop here" message — UNLESS `AIUR_AGENT_IR_SANDBOX=1` (set by scripts/aiurdev's agent-IR sandbox path only after redirecting state/logs/pidfiles/ports), which bypasses both checks; this guard runs before any other guard or file read (src/lib/aiur/test_reset.ex:64-97). Losing it lets a dogfooding agent wipe the operator's live sandbox/tickets. Tests: src/test/aiur/test_reset_test.exs. Risk: high.
- **FI-WS-030 · Per-ticket reset actions (workspace, branches, PRs, subscriptions, workpads)** [lifecycle] — For each open pinned ticket the confirmed reset: deletes `<log_root>/<repo>.<id>.subscriptions.json`; `rm -rf`'s `<workspace_root>/<sanitized-id>` (root from `Config.workspace_root()`, `~`-expanded, tmp-dir fallback; deliberately NOT via `Workspace.remove_issue_workspaces` and joined FLAT without the repo segment — consistent only because init bakes owner/repo into the root); deletes remote branches matching exactly `aiur/<id>` or `aiur/<id>-*` (pattern tightened so `aiur/99` never matches `aiur/999`); closes open PRs on those branches via `gh pr close --delete-branch=false`; and deletes issue comments whose body starts with `## Agent Workpad` (mid-body mentions never match) (src/lib/aiur/test_reset.ex:490-703). Dry-run plan claims ssh_hosts fan-out but reset_one only deletes locally. Tests: src/test/aiur/test_reset_test.exs (workpad_comment?/1 only; branch/PR/workspace deletion paths untested). Risk: high.
- **FI-WS-031 · Two-call label reset contract with retry and fail-closed abort** [integration] — Label reset issues TWO separate gh calls — remove ALL `agent:*` state labels (todo, in-progress, human-review, rework, merging, done, error, cancelled, canceled) then add `agent:todo` — never combined, because GitHub resolves a same-label remove+add PATCH with the remove winning (issue left unlabeled, never dispatched); the pair retries up to 3 attempts with 1500ms backoff, and if any ticket still lacks `agent:todo` the whole reset ABORTS with `{:error, {:labels_unset, ids}}` (src/lib/aiur/test_reset.ex:705-787, src/lib/aiur/test_reset.ex:262-288). The label list must track `Aiur.GitHub.Labels` (cross-referenced in labels.ex:24). Tests: src/test/aiur/test_reset_test.exs. Risk: high.
- **FI-WS-032 · Closed-ticket handling on reset (skip + label cleanup + abort)** [lifecycle] — Each pinned ticket's state is fetched (`gh issue view --json state,labels`); closed tickets are excluded from reset and any observed `agent:*`/`model:*` labels removed (single `--remove-label a,b` call, no `--add-label` ever); after processing, ANY closed/errored ticket aborts the run with `{:error, {:tickets_not_open, ids}}` so a run that cannot dispatch its chain never launches (src/lib/aiur/test_reset.ex:290-443). Tests: src/test/aiur/test_reset_test.exs. Risk: medium.
- **FI-WS-033 · Sandbox baseline restore + event-ID counter preservation** [lifecycle] — Every confirmed reset restores the 4 sandbox baseline files via `git checkout HEAD -- src/lib/aiur/sandbox/...` (guard pre-verified they exist in HEAD); with `--force` and uncommitted sandbox edits those files are `git stash push`-ed first so the checkout never silently loses work (src/lib/aiur/test_reset.ex:43-48, src/lib/aiur/test_reset.ex:789-826). The `<log_root>/<repo>.event_id` IdGenerator counter is NEVER deleted — wiping it would let post-reset events reuse pre-reset IDs and break the at-least-once cursor contract (src/lib/aiur/test_reset.ex:29-34); this negative requirement is enforced only by the absence of code. Tests: none directly. Risk: medium.
- **FI-WS-034 · Opencode theme ensure on test reset** [integration] — After a confirmed reset, `Aiur.OpencodeTheme.ensure_active()` installs and activates the 'aiur' opencode theme (dim command/tool blockquotes); idempotent across re-runs, preserves a user-selected custom theme with a warning, and is best-effort — failures produce a warning listing each failed step, never failing the reset (src/lib/aiur/test_reset.ex:268, src/lib/aiur/test_reset.ex:449-471). Tests: none in test_reset_test.exs. Risk: low.
- **FI-WS-035 · Reset status output vocabulary (stderr ✅/⚠️/❌)** [other] — All reset progress goes to stderr with a fixed vocabulary: plain lines, `✅ ` ok lines, `⚠️  ` warnings, and `❌ --test ABORT: <msg>` abort lines mirrored to `Logger.error`, with per-action lines naming the ticket (`#<id> workspace removed`, `#<id> labels prepared on open ticket → agent:todo`, `✅ sandbox reset complete`) — read by operators and the `aiur --test` driver (src/lib/aiur/test_reset.ex:832-839, src/lib/aiur/test_reset.ex:263).
