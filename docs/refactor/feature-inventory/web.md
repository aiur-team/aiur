## LiveView dashboard & HTTP server (FI-WEB)
The Phoenix-based observability surface: the `/` Operations Dashboard LiveView, the `/api/v1/*` JSON API, auth/writability gating, embedded static assets, and the `Aiur.HttpServer` boot gates that start the endpoint.

- **FI-WEB-001 · Dashboard LiveView page at /** [dashboard] — GET / renders the "Operations Dashboard": ITS/agent-kind badges, four metric cards (Running, Retrying, Total tokens In/Out, Runtime), a rate-limits pre panel ("n/a" when nil), Running-sessions and Retry-queue tables with empty-state text; data always via Presenter.state_payload from the configured orchestrator (src/lib/aiur_web/live/dashboard_live.ex:114-398, src/lib/aiur_web/router.ex:53-57). Tests: src/test/aiur/extensions_test.exs:685. Risk: low.
- **FI-WEB-002 · PubSub-driven live refresh** [event] — On connected mount, DashboardLive subscribes to topic "observability:dashboard" on Aiur.PubSub; the bare atom :observability_updated reloads the payload, updates :now, and refreshes any open agent-log modal; broadcasters are Orchestrator state changes and Alerts.emit (src/lib/aiur_web/observability_pubsub.ex:6-24, src/lib/aiur_web/live/dashboard_live.ex:23-46, src/lib/aiur/orchestrator.ex:4310, src/lib/aiur/alerts.ex:172). Topic string + message atom are a cross-module contract. Tests: src/test/aiur/observability_pubsub_test.exs; src/test/aiur/extensions_test.exs:685. Risk: medium.
- **FI-WEB-003 · broadcast_update is a no-op when PubSub is down** [event] — ObservabilityPubSub.broadcast_update/0 checks Process.whereis(Aiur.PubSub) and returns :ok without raising when PubSub is absent, so Orchestrator/Alerts never crash because the optional web stack isn't running (src/lib/aiur_web/observability_pubsub.ex:16-24). Tests: src/test/aiur/observability_pubsub_test.exs. Risk: medium.
- **FI-WEB-004 · 1-second server-side runtime tick** [dashboard] — Connected views recursively Process.send_after(:runtime_tick, 1000); each tick reassigns :now so the Runtime metric and per-row "Runtime / turns" advance server-side with no client JS clock (src/lib/aiur_web/live/dashboard_live.ex:10,32-35,478-480). Tests: src/test/aiur/extensions_test.exs:~749 refutes any client-side clock; tick itself untested. Risk: medium.
- **FI-WEB-005 · Metric computations and formatting** [dashboard] — Runtime = agent_totals.seconds_running (nil-safe) + per-entry elapsed from started_at (DateTime or ISO8601 string, else 0) to :now, formatted "Xm Ys" with negatives clamped to 0; "runtime / turns" only for positive integer turn_count; format_int adds comma separators, "n/a" for non-integers; state badges classed by substring (active/danger/warning/plain) (src/lib/aiur_web/live/dashboard_live.ex:418-476). Tests: rendering via src/test/aiur/extensions_test.exs:685; helpers have no unit tests. Risk: medium.
- **FI-WEB-006 · CSS-driven Live/Offline connection badges** [dashboard] — Both badges are always in the DOM; dashboard.css selectors keyed on [data-phx-main].phx-connected toggle visibility, so connection status needs no JS or server round-trip (src/lib/aiur_web/live/dashboard_live.ex:134-141, src/priv/static/dashboard.css:231-235). - **FI-WEB-016 · Optional HTTP basic auth via env vars** [config-option] — Every route (dashboard, API, static assets) passes dashboard_basic_auth: when both AIUR_DASHBOARD_USERNAME and AIUR_DASHBOARD_PASSWORD are non-blank, Plug.BasicAuth enforces them with realm "Aiur" (401 + WWW-Authenticate on mismatch); otherwise auth is fully disabled; env vars are read per-request so credentials change without restart (src/lib/aiur_web/router.ex:9-11,95-106). - **FI-WEB-017 · api_write CSRF defense: same-origin + custom header** [api] — All POST API endpoints require BOTH an Origin (or Referer fallback) prefix-matching the endpoint's own URL or http(s)://127.0.0.1|localhost AND header X-Aiur-Request: 1; failures return 403 {"error":"origin not allowed"} / {"error":"missing X-Aiur-Request header"}; deliberately not Plug.CSRFProtection so operator curl/scripts work (src/lib/aiur_web/router.ex:21-33,111-120,143-185). Machine callers (scripts/aiur-pane-ctrlc, claude hook curl from src/lib/aiur/claude/hook_settings.ex:34-37) hard-code these values — changing allowlist or header name breaks tmux Ctrl+C/Ctrl+Q and RC hooks.
