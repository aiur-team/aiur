## Tracker adapters (Linear, Memory, dispatch) (FI-TRK)
Tracker adapter dispatch/config boundary plus the Linear and Memory implementations of the Aiur.Tracker behaviour: candidate polling, reconciliation, normalization, mutations, stubs, and the linear_graphql agent tool (GitHub adapter covered in FI-GH).

- **FI-TRK-001 · Tracker adapter dispatch boundary** [adapter-dispatch] — `Aiur.Tracker.adapter/0` dispatches on `tracker.kind`: "github" -> `Aiur.GitHub.Tracker`, "memory" -> `Aiur.Memory.Tracker`, ANY other value (nil/garbage) falls through to `Aiur.Linear.Tracker` (src/lib/aiur/tracker.ex:96-103); rejection lives separately in `Config.validate_kinds_and_secrets/1` ({:error, {:unsupported_tracker_kind, kind}} / :missing_tracker_kind, src/lib/aiur/config.ex:421-447) run as dispatch preflight, and kind is inferred from section presence github: > linear: > memory: when unset (src/lib/aiur/config.ex:477-484). `project_identity/0` is `function_exported?`-guarded; `add_label/remove_label` are @optional_callbacks yet delegated unconditionally (src/lib/aiur/tracker.ex:20-23,87-94). Tests: src/test/aiur/extensions_test.exs:221-245, src/test/aiur/core_test.exs:141,155. Risk: medium.
- **FI-TRK-002 · Linear configuration resolution and validation** [config] — Schema.Linear resolves api_key/project_slug/endpoint (default https://api.linear.app/graphql)/assignee with $VAR env indirection, canonical fallbacks LINEAR_API_KEY/LINEAR_ASSIGNEE, and $VAR-resolving-to-empty treated as missing (src/lib/aiur/config/schema.ex:59-76,836-847); `Aiur.Linear.Config` re-implements the same logic but its `validate!` (behaviour Aiur.TrackerConfig) is never dispatched — Config inlines :missing_linear_api_token/:missing_linear_project_slug checks (src/lib/aiur/linear/config.ex:8-104, src/lib/aiur/config.ex:427-447); a linear: section infers kind "linear". Tests: src/test/aiur/core_test.exs:57,102,217-248,278-280 (Linear.Config's own paths untested). Risk: medium.
- **FI-TRK-003 · Linear project identity — workspace and log namespacing** [identity] — `project_identity/0` returns the trimmed project_slug (src/lib/aiur/linear/tracker.ex:41-42); it namespaces per-issue workspaces as `<root>/<project_slug>/<issue>` with component sanitization ([^a-zA-Z0-9._-] -> _, traversal parts dropped, idempotent append; src/lib/aiur/workspace.ex:821-877), prefixes per-issue log/subscription filenames via `Config.Paths.repo_name` (failure-safe -> "aiur", src/lib/aiur/config/paths.ex:41-75), and names RC tmux sessions (src/lib/aiur/agent_runner.ex:998). Tests: src/test/aiur/core_test.exs:391,1442, src/test/aiur/config_paths_test.exs. Risk: low.
- **FI-TRK-004 · Linear candidate issue polling with cursor pagination** [tracker-read] — `fetch_candidate_issues/0` guards missing api_key/project_slug (:missing_linear_api_token / :missing_linear_project_slug), then pages the AiurLinearPoll query (project slugId eq filter, state name in `tracker.active_states` default ["Todo","In Progress"], first: 50, relationFirst: 50), preserving cross-page order; hasNextPage without a usable endCursor is {:error, :linear_missing_end_cursor} (src/lib/aiur/linear/client.ex:12-55,106-146,248-285). `fetch_issues_by_states/2` is the same query minus the assignee filter for startup terminal cleanup, {:ok, []} on empty states (src/lib/aiur/linear/client.ex:453-459). Tests: src/test/aiur/workspace_and_config_test.exs:1082-1096, src/test/aiur/core_test.exs:102, src/test/aiur/orchestrator_status_test.exs (multi-page cursor loop not driven end-to-end). Risk: medium.
- **FI-TRK-005 · Linear assignee routing filter ("me" viewer resolution)** [tracker-read] — `linear.assignee` (LINEAR_ASSIGNEE, $VAR supported) gates `assigned_to_worker`: nil/blank -> every issue true; a literal matches trimmed assignee.id against a MapSet; special value "me" resolves viewer.id per poll via AiurLinearViewer (payload without id -> {:error, :missing_linear_viewer_identity}, transport errors fail the whole fetch) (src/lib/aiur/linear/client.ex:98-104,487-552). Applied to candidate polling and by-ids refresh, NOT to terminal-cleanup fetch_issues_by_states (src/lib/aiur/linear/client.ex:119-123,157-159). Tests: src/test/aiur/workspace_and_config_test.exs:1019-1081, src/test/aiur/core_test.exs:235-248 ("me" path and :missing_linear_viewer_identity untested). Risk: medium.
- **FI-TRK-006 · Linear issue normalization (labels, blockers, priority, timestamps)** [normalization] — `normalize_issue/2` maps raw GraphQL nodes to %Aiur.Issue{}: labels lowercased (nils dropped); blocked_by only from inverseRelations of type "blocks" (trimmed+downcased; relatesTo/duplicates dropped) keeping {id, identifier, state.name}; priority integer-only else nil; ISO-8601 timestamps (parse failure -> nil); non-map nodes rejected (src/lib/aiur/linear/client.ex:461-482,554-598). GraphQL "errors" bodies decode to {:linear_graphql_errors, errors}; unknown shapes to :linear_unknown_payload (src/lib/aiur/linear/client.ex:418-433). Tests: src/test/aiur/workspace_and_config_test.exs:1007-1080. Risk: low.
- **FI-TRK-007 · Linear issue-state refresh by IDs (reconciliation fetch)** [tracker-read] — `fetch_issue_states_by_ids/1` uniqs ids ({:ok, []} on empty), applies the same assignee filter, batches AiurLinearIssuesById ([ID!] variable, id in filter) in chunks of 50 with first = exact batch length, then re-sorts results into requested id order (unknown ids last); any batch error aborts the fetch, and the orchestrator treats refresh failure as non-fatal (workers keep running) (src/lib/aiur/linear/client.ex:57-96,148-161,287-337). A mid-run reassignment returns assigned_to_worker: false rather than vanishing. Tests: src/test/aiur/workspace_and_config_test.exs:1098-1140, src/test/aiur/core_test.exs:315,1432+. Risk: low.
- **FI-TRK-008 · Linear GraphQL transport, error taxonomy, and log truncation** [http-client] — `Client.graphql/3` is the single transport: Req.post to `linear.endpoint` with raw-token Authorization (no Bearer), optional trimmed operationName, connect_options: [timeout: 30_000] (connect-only — SPEC 11.2's 30s network timeout is only partial; receive timeout is Req default) (src/lib/aiur/linear/client.ex:163-194,339-416). Errors: :missing_linear_api_token pre-request, {:linear_api_status, status} with error body whitespace-collapsed and truncated to 1000 bytes in logs, {:linear_api_request, reason} on transport failure; opt :quiet_auth_errors? suppresses logging only for 401/:missing_linear_api_token (used by orchestrator startup cleanup and status polls, src/lib/aiur/orchestrator.ex:4197,4257); :request_fun injects HTTP for tests. Tests: src/test/aiur/workspace_and_config_test.exs:1142-1210, src/test/aiur/orchestrator_status_test.exs:15,213. Risk: medium.
- **FI-TRK-009 · Linear mutations: create_comment and two-step update_issue_state** [tracker-write] — `create_comment/2` runs AiurCreateComment requiring commentCreate.success == true else {:error, :comment_create_failed}; `update_issue_state/2` first resolves state name -> stateId via AiurResolveStateId (exact-name match within the issue's team, first: 1; no match -> {:error, :state_not_found}, uncached per call) then AiurUpdateIssueState requiring issueUpdate.success else {:error, :issue_update_failed} (src/lib/aiur/linear/tracker.ex:11-39,73-83,97-134). Client module swappable via Application env :aiur, :linear_client_module. Tests: src/test/aiur/extensions_test.exs:247-360. Risk: low.
- **FI-TRK-010 · Linear label ops unsupported — RC promote/demote degrades** [tracker-write] — `Linear.Tracker.add_label/2` and `remove_label/2` unconditionally return {:error, :unsupported} (deliberate gap; the model:remote toggle is a GitHub-label concept, src/lib/aiur/linear/tracker.ex:112-118), so RC promotion on a Linear run fails as {:error, {:rc_label_failed, :unsupported}} and the TUI shows the local-Claude hint instead of crashing (src/lib/aiur/agent_list/app.ex:1297). Tests: src/test/aiur/orchestrator_remote_control_test.exs:102-136, src/test/aiur/agent_list/app_test.exs:502-503. Risk: medium.
- **FI-TRK-011 · Linear PR/comment-classification stubs (rework pipeline inert)** [tracker-read] — `fetch_classified_issue_comments/1`, `fetch_classified_pr_review_comments/1`, `fetch_unaddressed_pr_review_thread_comments/1` always {:ok, []} and `fetch_open_pull_request_for_branch/1` always {:ok, nil} (src/lib/aiur/linear/tracker.ex:85-95), so AgentRunner's review-comment/PR-anchored rework context assembly (src/lib/aiur/agent_runner.ex:271-274) is silently empty on Linear — no errors, no signal. Tests: none (direct; implied by delegation coverage and GitHub-side tests). Risk: medium.
- **FI-TRK-012 · linear_graphql dynamic agent tool** [agent-tool] — Codex.DynamicTool advertises a "linear_graphql" MCP-style tool (required query string, optional variables object, additionalProperties false) backed by `Client.graphql/3` with Aiur's Linear auth; raw-string or map arguments, blank query -> missing_query, non-object variables -> :invalid_variables, legacy operationName ignored (src/lib/aiur/codex/dynamic_tool.ex:122-135,572-607). Errors are humanized per reason (:missing_linear_api_token setup hint, HTTP status, transport reason inspect); success bodies return as tool text with GraphQL-error bodies marked failures (src/lib/aiur/codex/dynamic_tool.ex:1027-1068). Tests: src/test/aiur/dynamic_tool_test.exs:6-17,102,333-544. Risk: low.
- **FI-TRK-013 · Memory tracker adapter (in-memory fixture tracker)** [test-adapter] — Full Aiur.Tracker implementation driven by Application env: fixtures from :aiur, :memory_tracker_issues (non-%Issue{} entries filtered); fetch_issues_by_states matches case/whitespace-insensitively; fetch_issue_states_by_ids filters by id set (src/lib/aiur/memory/tracker.ex:30-97). Writes are observable no-ops sending {:memory_tracker_comment|_state_update|_add_label|_remove_label, ...} tuples to :aiur, :memory_tracker_recipient (else silent :ok) — label ops SUCCEED unlike Linear, enabling RC promote/demote tests; classification/PR fetches stub like Linear; project_identity "memory" falls back to the FLAT `<root>/<issue>` workspace layout since repo_segment only maps github/linear (src/lib/aiur/memory/tracker.ex:10-28,99-121, src/lib/aiur/workspace.ex:848-862). Mutations never mutate fixtures — multi-tick transitions must swap :memory_tracker_issues manually. Tests: src/test/aiur/extensions_test.exs:221-245, src/test/aiur/orchestrator_remote_control_test.exs:153-232, src/test/aiur/core_test.exs:446-520. Risk: low.
- **FI-TRK-014 · Memory tracker config (no-op validation)** [config] — `Aiur.Memory.Config.validate!` always :ok (kind "memory" needs no secrets, so dispatch preflight passes clean); like Linear.Config it implements Aiur.TrackerConfig but is never dispatched — Config.validate_kinds_and_secrets hits its `true -> :ok` branch (src/lib/aiur/memory/config.ex:1-11, src/lib/aiur/config.ex:421-447). Undocumented in SPEC 5.3.1 (tests/local-dev extension). Tests: none direct; exercised transitively by every memory-kind orchestrator test. Risk: low.
