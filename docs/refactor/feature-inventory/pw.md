## Repo prewarm (FI-PW)
Warm-base repo pre-warming: toolchain detection, prewarm config, RepoBase clone/fetch/build lifecycle, orchestrator dispatch gating, workspace materialization from the warm base, init opt-in flow, and TUI phase display.

- **FI-PW-001 · prewarm config block** [config-option] — Config schema embeds a prewarm block: `enabled` (default false — opt-in), `base_build` (string), `base_build_file` (string), `poll_seconds` (integer default 0, validated >= 0), exposed via `Config.prewarm_enabled?/0`, `prewarm_base_build/0`, `prewarm_poll_seconds/0` (src/lib/aiur/config/schema.ex:391-414, src/lib/aiur/config.ex:208-226). Tests: src/test/aiur/workflow_test.exs, src/test/aiur/init_test.exs. Risk: low.
- **FI-PW-002 · base_build_file sibling-script resolution** [config-option] — `prewarm.base_build_file` points at a sibling script (convention `.aiur/prewarm`, resolved relative to the config dir); its trimmed shell contents replace any inline `base_build` at workflow load (src/lib/aiur/workflow.ex:168-183). A missing file fails the load with `{:error, {:missing_prewarm_file, path, reason}}`, surfaced with the friendly label "prewarm base_build_file" (src/lib/aiur/config.ex:516,535); absent file key ⇒ inline `base_build` used unchanged. Tests: src/test/aiur/workflow_test.exs:243-267. Risk: medium.
- **FI-PW-003 · Toolchain auto-detection (Detect.detect/1)** [api] — Walks the repo tree (max depth 4, skipping .git/node_modules/deps/_build/target/vendor/cover/.elixir_ls/priv/.build/Pods) for elixir/node/go/rust/python/swift/cocoapods manifests, returning `{:ok, %{language, build_root, command}}`, `{:ambiguous, candidates}`, or `:none` — never guessing a command on :none/:ambiguous (src/lib/aiur/prewarm/detect.ex:27,52,57). Called by `aiur init` via deps.detect_toolchain (src/lib/aiur/init.ex:1759). Tests: src/test/aiur/prewarm/detect_test.exs. Risk: low.
- **FI-PW-004 · Build root = manifest dir with lockfile tiebreaker** [api] — The detected build_root is the manifest's directory, NOT the repo root (aiur's own mix.exs lives in src/ behind a lockfile-less root package.json); with multiple languages, exactly one lockfile-backed candidate wins, else `{:ambiguous, candidates}` sorted by build_root; only the shallowest manifest per language counts (src/lib/aiur/prewarm/detect.ex:74-78,122-126,130-146). Breaking this silently re-detects aiur's root package.json into a useless npm base build. Tests: src/test/aiur/prewarm/detect_test.exs. Risk: medium.
- **FI-PW-005 · Node workspace-root promotion** [api] — A repo root with pnpm-workspace.yaml or a package.json `workspaces` key is promoted as a depth-0 node candidate even without its own manifest hit, so JS/TS monorepos install once at the workspace root (src/lib/aiur/prewarm/detect.ex:110-120,233-241). Tests: src/test/aiur/prewarm/detect_test.exs. Risk: medium.
- **FI-PW-006 · Per-toolchain command synthesis via mise exec** [api] — Every synthesized install/build call routes through `mise exec --`; package-manager choice is lockfile-driven (pnpm frozen-lockfile+corepack, bun, yarn immutable+corepack, npm ci, npm install fallback; poetry/uv/pdm/pipenv/pip); node build-step preference nx.json > turbo.json > workspace recursive build > package.json `build` script > none; non-root build_root gets a `cd <rel> && ` prefix (src/lib/aiur/prewarm/detect.ex:163-185,187-227,279-288). Tests: src/test/aiur/prewarm/detect_test.exs. Risk: low.
- **FI-PW-007 · Vendored tree exclusion in detection** [api] — Vendored/build trees (.build for SwiftPM, Pods, node_modules, deps, _build, target, vendor) are never descended into, so nested checkouts inside them cannot masquerade as the repo's toolchain (src/lib/aiur/prewarm/detect.ex:49-53,92). Tests: src/test/aiur/prewarm/detect_test.exs. Risk: low.
- **FI-PW-008 · aiur init pre-warm opt-in prompt** [cli-command] — Repo-local init asks "Keep a pre-warmed copy of latest main so agents skip cloning + building?" (default yes); on yes it runs detection and shows language/build-root/command with a use/edit/skip select ("edit" rewrites the command). Global (~/.aiur) configs always skip the prompt and leave prewarm disabled (src/lib/aiur/init.ex:707-748,285). Tests: src/test/aiur/init_test.exs ("pre-warm opt-in"). Risk: low.
- **FI-PW-009 · init detection-miss / ambiguity disclosure + agent fallback prompt** [cli-command] — Detection `:none` prints "Couldn't auto-detect this repo's build — pre-warm left off" plus a ready-to-paste coding-agent prompt (full base_build conventions: mise exec routing, frozen installs, idempotency, no sudo/brew, exact YAML shape, verify-twice); `{:ambiguous, candidates}` lists every `<lang> (<root>)` candidate, explains pre-warm builds ONE base, then hands over the same prompt — both leave prewarm disabled (src/lib/aiur/init.ex:750-821). Tests: src/test/aiur/init_test.exs. Risk: low.
- **FI-PW-010 · init writes .aiur/prewarm sibling script + config block** [artifact] — On opt-in, init writes the detected/edited command into `.aiur/prewarm` (command + trailing newline) only if the file doesn't already exist ({:exists} preserves operator edits), and the rendered config block always references it via `base_build_file: prewarm` rather than inlining; the prewarm: block is only rendered on opt-in (src/lib/aiur/init.ex:511-519,1043,1116-1124,1813-1822). Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-PW-011 · init one-time first warm-base build** [cli-command] — On opt-in with a github tracker repo, init immediately builds the warm base once ("Building the warm base now — one-time clone + compile; later runs reuse it.") via `RepoBase.refresh(base_path(url), url, cmd)` with url `https://github.com/<repo>.git`, printing "✅ Warm base ready." on success, so the first run dispatches without waiting on the gate (src/lib/aiur/init.ex:823-844,1761-1763). Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-PW-012 · init warm-base failure classification + guidance** [alert] — A failed first build is classified :auth (git stderr auth signatures like "authentication failed", "could not read username", "403 forbidden"), :clone, :build (base_build_failed), or :other; each prints concrete self-fix steps, a ready-to-paste agent prompt embedding the captured failure output, and "The warm base also retries automatically on the next aiur run." (src/lib/aiur/init.ex:851-931). Tests: src/test/aiur/init_test.exs ("warm-base failure report"). Risk: low.
- **FI-PW-013 · init resume: re-verify + backfill prewarm section** [cli-command] — Re-running init with prewarm enabled + non-empty base_build re-runs the one-time build (maybe_resume_prewarm); a config predating the feature (no `prewarm` key) gets the section offered via the promptable-sections registry — on opt-in the block is APPENDED to the existing file (never regenerated), the sibling script is written, and the first build runs only after the append succeeded; declining leaves the config untouched (src/lib/aiur/init.ex:217,444-542). Tests: src/test/aiur/init_test.exs. Risk: medium.
- **FI-PW-014 · Warm base location + slug** [artifact] — The warm base checkout lives at `~/.aiur/repo/<owner>/<name>`; `RepoBase.base_path/1` slugs https/ssh URLs and bare local paths to the last two path segments, stripping .git and scheme/host tokens; the base root is overridable via Application env `:aiur, :repo_base_root` (tests use this) (src/lib/aiur/repo_base.ex:38-40,399-413). Tests: src/test/aiur/repo_base_test.exs. Risk: low.
- **FI-PW-015 · RepoBase.refresh/3 clone-fetch-build core** [lifecycle] — Clones (`git clone --branch main`, hardcoded default branch) only when `<base>/.git` is absent (rm -rf of non-git leftovers first), fetches + hard-resets to origin/main only when local HEAD differs, and runs base_build only when main changed or the `.aiur-base-built` marker is missing; success writes the marker, a failed build skips it so the next refresh retries; _build/deps survive reset --hard (gitignored), keeping builds incremental; nil/empty base_build is a no-op success (src/lib/aiur/repo_base.ex:66-84,240-289,365-366). Tests: src/test/aiur/repo_base_test.exs. Risk: medium.
- **FI-PW-016 · base_build execution environment** [lifecycle] — base_build runs as `sh -lc <cmd>` with cwd = base path, stderr merged into stdout, the command scrubbed via `AgentEnvironment.scrub_shell_command/1` (strips operator Erlang distribution env), and `MISE_TRUSTED_CONFIG_PATHS=<base_path>` so the base's mise.toml is trusted without a prompt; exit != 0 becomes `{:error, {:base_build_failed, status, output}}` (src/lib/aiur/repo_base.ex:294-313, src/lib/aiur/agent_environment.ex:113-118). Tests: src/test/aiur/repo_base_test.exs. Risk: medium.
- **FI-PW-017 · Git auth via env-config extraheader (private repos)** [integration] — All RepoBase git calls run with GIT_TERMINAL_PROMPT=0 (fail fast, never block on a credential prompt); a GitHub token is injected as a basic Authorization header scoped to `http.https://github.com/.` via GIT_CONFIG_COUNT/KEY_0/VALUE_0 env — keeping it out of argv/ps and out of the cloned .git/config (src/lib/aiur/repo_base.ex:317-349). Security-sensitive: `-c key=value` or URL-embedded tokens would leak. Tests: src/test/aiur/repo_base_test.exs ("git_auth_env/1"). Risk: high.
- **FI-PW-018 · Async build worker with mid-build preemption** [lifecycle] — Builds run in a spawned+monitored worker so status/0 never blocks; while a build is in flight (or base :ready) a `git ls-remote` probe (never touching the base tree) checks whether origin/main advanced past the worker's locked-in `{:build_head, ...}` — if so the in-flight build is KILLED and restarted so workspaces never materialize off a stale base; a crashed worker surfaces `{:error, {:build_crashed, reason}}`; ready_head is recorded for future probes (src/lib/aiur/repo_base.ex:113-135,145-236). Concurrency-heavy: pid/ref message-tag matching and `Process.demonitor(:flush)` ordering are load-bearing. Tests: src/test/aiur/repo_base_test.exs ("server state machine"). Risk: high.
- **FI-PW-019 · refresh_async gating (resolve/0)** [lifecycle] — `RepoBase.refresh_async/0` (and the poll timer) is a no-op that sets phase :idle unless ALL of: prewarm.enabled true, base_build a non-empty string, and the tracker is a github repo (URL synthesized as `https://github.com/<repo>.git`); safe to call every orchestrator poll cycle (src/lib/aiur/repo_base.ex:56-57,145-158,370-383). Tests: src/test/aiur/repo_base_test.exs. Risk: medium.
- **FI-PW-020 · Background poll timer (prewarm.poll_seconds)** [config-option] — When `prewarm.poll_seconds > 0`, RepoBase schedules a `:poll` message on init and re-arms after every poll, each tick running refresh_async logic; 0 (default) disables background polling entirely — the base then refreshes only via the orchestrator dispatch gate (src/lib/aiur/repo_base.ex:89-91,105-109,385-397). Tests: none. Risk: high. Check: set `prewarm.poll_seconds: 5`, start aiur idle, push a commit to main, and confirm `~/.aiur/repo/<owner>/<name>` resets to the new head within a few ticks (prewarm phase log/events fire without any dispatch).
- **FI-PW-021 · Prewarm phase events on pubsub** [event] — RepoBase broadcasts `{:prewarm_phase, phase}` on AgentPubSub topic `"prewarm:phase"` in order :cloning → :fetching → :building → :ready, or `{:error, reason}` on failure; both the sync refresh/3 path and the async worker emit the same events; subscribers use `AgentPubSub.subscribe_prewarm/0` (src/lib/aiur/repo_base.ex:244,256,279,415, src/lib/aiur/agent_pubsub.ex:94-107). Tests: src/test/aiur/repo_base_test.exs ("emits ordered phase events"). Risk: medium.
- **FI-PW-022 · Loud prewarm failure logging** [alert] — Every base failure logs at error level `prewarm base unavailable: <tag> (exit N): <output truncated to 1500 chars>` at the source, THEN broadcasts the `{:error, reason}` phase (previously pubsub-only, so a broken base looped silently while agents cold-cloned); successful builds must not produce this line (src/lib/aiur/repo_base.ex:417-428). Tests: src/test/aiur/repo_base_test.exs. Risk: low.
- **FI-PW-023 · RepoBase is an unconditional top-level child (headless prewarm)** [lifecycle] — `Aiur.RepoBase` starts as an unconditional top-level supervision child (src/lib/aiur.ex:106), unlike the interactive-only opencode pre-warm block (src/lib/aiur.ex:78-90), so the warm base works in headless/--bg runs too. Tests: src/test/aiur/application_test.exs (child-spec gating). Risk: medium.
- **FI-PW-024 · Orchestrator eager pre-warm dispatch gate** [lifecycle] — Every dispatch tick with prewarm enabled kicks `RepoBase.refresh_async()` and reads status non-blocking, then pure `prewarm_gate/2` decides: dispatch when disabled or base :ready; dispatch via cold-clone fallback (with "prewarm base unavailable ... dispatching via cold clone" warning) when the base errored — never hangs the run; HOLD dispatch in any warming phase; this gate runs BEFORE the CPU load gate so a busy box still warms its base (src/lib/aiur/orchestrator.ex:2301-2320,2360-2381). Tests: src/test/aiur/orchestrator_prewarm_gate_test.exs. Risk: medium.
- **FI-PW-025 · Workspace materialization from warm base (CoW)** [lifecycle] — When prewarm is enabled AND `RepoBase.status()` is `{:ready, base}` AND the base dir exists, a new workspace is materialized by copying the whole base — `cp -Rc` on macOS (APFS clone), `cp -a --reflink=auto` elsewhere — carrying warm _build/deps, then branching; ANY failure falls through to the unchanged cold `create_workspace/1` path with a warning, a failed materialize rm -rf's the partial workspace, and materialize mkdir_p's the workspace's parent itself (repo-namespaced `<root>/<repo>/<issue>`) (src/lib/aiur/workspace.ex:124-138,156-178,290-298). Tests: src/test/aiur/workspace_materialize_test.exs. Risk: high.
- **FI-PW-026 · Materialized branch anchored to live origin tip (#567)** [lifecycle] — After copying the base, the fresh `aiur/<id>` branch is created off origin/<base-branch> (re-fetched first), NOT off the copied HEAD — the warm base only refetches on a timer/dispatch gate, so a workspace could otherwise silently start from stale main; with no usable remote (offline/tests/detached HEAD) it falls back to the copied HEAD so materialize still succeeds (src/lib/aiur/workspace.ex:202-216,272-288). Tests: src/test/aiur/workspace_materialize_test.exs ("#567"). Risk: high.
- **FI-PW-027 · PR-anchored materialize (existing head branch)** [lifecycle] — A dispatch carrying `pr_head_ref` copies the warm base then `fetch origin <ref>` + `checkout -B <ref> FETCH_HEAD` (deliberately not `--track` nor a plain checkout of a possibly-stale local ref) so the agent works the human's existing branch and pushes back there — never creating an `aiur/<id>` branch or PR; failed fetch ⇒ local branch off copied HEAD; prewarm-unavailable ⇒ cold create_workspace; the legacy 2-arity materialize must never leak PR-anchored behavior, and remote worker_host ignores pr_head_ref entirely (src/lib/aiur/workspace.ex:45-69,140-154,180-270). Tests: src/test/aiur/workspace_materialize_test.exs. Risk: high.
- **FI-PW-028 · after_create hook suppressed for materialized workspaces** [lifecycle] — ensure_workspace returns created? in {true, false, :materialized}; the cold-clone `hooks.after_create` hook runs ONLY when created? == true — a warm-base-materialized workspace (:materialized) skips it (aiur already populated + branched), as does a reused workspace (false) (src/lib/aiur/workspace.ex:129-138,879-900). Collapsing :materialized into true would re-run the clone hook on every warm workspace and clobber the checkout. Tests: none (workspace_and_config_test.exs covers hook plumbing, not :materialized suppression). Risk: high. Check: with a ready warm base and `hooks.after_create` set to `touch /tmp/hook-ran`, dispatch a ticket and confirm the sentinel does NOT appear for the materialized workspace.
- **FI-PW-029 · Agent-list pre-warm loading bar** [tui-behavior] — AgentList subscribes to the prewarm topic; `{:prewarm_phase, p}` for cloning/fetching/building sets prewarm_active?+phase and re-renders, :ready or {:error,_} clears both; the renderer shows the spinner line "Pre-warming base (cloning|fetching main|compiling|warming up)…" ONLY while the agent list is empty, so a missed clear can never strand it; state is seeded at App init and prewarm_active?/prewarm_phase must stay in the renderer's Map.put pipeline (src/lib/aiur/agent_list/app.ex:151,608-625, src/lib/aiur/agent_list/renderer.ex:161-162,638-653). Tests: src/test/aiur/agent_list/prewarm_render_test.exs. Risk: medium.
- **FI-PW-030 · Dogfood .aiur/prewarm script (aiur's own base build)** [artifact] — aiur's repo ships `.aiur/prewarm`: scopes HEX_HOME/MIX_HOME under the base ($PWD/.aiur-hex, $PWD/.aiur-mix) so warm caches copy into workspaces, then `cd src` + mise exec mix local.hex/local.rebar/deps.get/compile AND `mix dialyzer --plt` — the PLT build is a guarded contract (dogfood agents skip the multi-minute per-workspace PLT build) (.aiur/prewarm:1-8, .aiur/config). Tests: src/test/aiur/repo_prewarm_test.exs. Risk: low.
- **FI-PW-031 · Remote docker warm-cache bootstrap** [integration] — Remote (worker_host) workspaces can be seeded from a docker image: bootstrap copies each of src/deps, src/_build, deps, _build from `/opt/aiur/<path>` into the workspace, keeping any existing target, logging seeded/missing per path, and exiting 66 when NO cache path was found in image or workspace; workspace hooks are documented to pre-warm deps/compile with a visible output tail logged on success (src/lib/aiur/workspace.ex:10,518-557,1045-1057). Separate warm path from the local warm base — a rename-driven refactor of "warm" code must not sweep it. Tests: src/test/aiur/workspace_and_config_test.exs. Risk: medium.
