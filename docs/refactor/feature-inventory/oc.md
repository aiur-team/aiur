## Opencode chat-pane bridge (FI-OC)
The OpenAI-compatible HTTP bridge and session plumbing that renders Aiur agent transcripts inside opencode chat panes: chat-completions SSE streaming, __aiur_turn__ markers, operator-input dispatch, SessionWriter persistence into opencode's SQLite, opencode-serve lifecycle, and workspace/provider config artifacts.

- **FI-OC-001 · Bridge HTTP router** [api] — Plug router: GET /v1/health returns `{ok: true}` with NO auth; POST /v1/chat/completions dispatches to ChatCompletions.handle; everything else 404 (src/lib/aiur/opencode/bridge.ex:12-24). Tests: src/test/aiur/opencode/bridge_test.exs. Risk: low.
- **FI-OC-002 · Bridge port resolution and auto-scan** [config-option] — When the default port 4097 is occupied, scans up to 100 ports upward (warning names the occupying process via lsof); explicitly pinned ports (env/workflow/app override) never auto-select and fail with pin source + suggested AIUR_OPENCODE_BRIDGE_PORT; port 0 passes through; auto-selected port persists to app env :opencode_bridge_port_override so Config.bridge_port() agrees with the listener (src/lib/aiur/opencode/bridge_port.ex:12-51, src/lib/aiur/opencode/bridge_supervisor.ex:15-28). Tests: src/test/aiur/opencode/bridge_port_test.exs. Risk: low.
- **FI-OC-003 · Bridge Bandit server lifecycle** [lifecycle] — BridgeSupervisor starts Bandit with num_connections: 50 (bounds concurrent SSE streams; lowering starves multi-pane setups), restart: :temporary (crashed listener not restarted; boot raises on unresolvable port); host parse falls back to 127.0.0.1 (src/lib/aiur/opencode/bridge_supervisor.ex:30-55). Tests: src/test/aiur/opencode/bridge_port_test.exs. Risk: medium.
- **FI-OC-004 · Model-field identifier routing** [api] — The request's model field routes to an agent: accepts both '<prefix>/issue-<id>' and bare 'issue-<id>'; 'placeholder' (bare or prefixed) short-circuits to an empty SSE ('data: [DONE]') so the warm placeholder session never toasts an error; other shapes log invalid_model and return 400 (src/lib/aiur/opencode/chat_completions.ex:63-77, src/lib/aiur/opencode/chat_completions.ex:879-917). Tests: src/test/aiur/opencode/bridge_test.exs. Risk: medium.
- **FI-OC-005 · Bearer-token authorization (routing-independent)** [api] — Operator-text dispatch requires a TokenRegistry-valid Bearer token; failure returns 401 'auth_failed' with a close/reopen-pane hint. Token only authorizes 'live workspace' — identifier routing stays with the model field; marker/turn streams don't gate on auth at open but use the bearer to resolve the originating slot (src/lib/aiur/opencode/chat_completions.ex:1096-1114, src/lib/aiur/opencode/token_registry.ex:93-103). Tests: src/test/aiur/opencode/bridge_test.exs, src/test/aiur/opencode/token_registry_test.exs. Risk: medium.
- **FI-OC-006 · TokenRegistry generation-overlap restart window** [lifecycle] — Tokens keyed by token alone with {slot_index, generation, ts}; slot restart order put(new, gen+1) → boot serve → attach ready → delete_stale(slot, gen+1), so BOTH old and new tokens validate mid-restart (no unauthorized window); delete/1 removes one token on slot teardown; lookup_slot maps a bearer back to its slot for base_url resolution (src/lib/aiur/opencode/token_registry.ex:15-30, src/lib/aiur/opencode/token_registry.ex:47-118). Tests: src/test/aiur/opencode/token_registry_test.exs. Risk: medium.

Tests: none. Risk: low.
- **FI-OC-008 · Bridge-as-LLM turn streaming (__aiur_turn__ markers)** [integration] — A synthetic user message '__aiur_turn__:<id>' opens a chat completion; the bridge subscribes to the agent's PubSub topic BEFORE the ActiveTurns lookup (racing close broadcasts land in the mailbox) and streams every transcript event as SSE deltas until {:aiur_turn_done, ...}. Marker ids may carry a -s<N> segment suffix; ActiveTurns and turn-done matching key on the bare parent id; codex turnId is deliberately NOT filtered — the whole aiur turn renders as one growing assistant message (src/lib/aiur/opencode/chat_completions.ex:140-190, src/lib/aiur/opencode/chat_completions.ex:201-296, src/lib/aiur/opencode/turn_markers.ex:40-52). Tests: src/test/aiur/opencode/chat_completions_test.exs (pure helpers only; live loop untested). Risk: high.

- **FI-OC-014 · Segmented turn streams** [lifecycle] — The per-turn SSE closes at natural boundaries so opencode flushes its input queue (typed text otherwise sits QUEUED all turn): tool/command boundary after threshold (default 20s, app env :turn_segment_threshold_ms), idle boundary on heartbeats; before closing, continuation marker '<parent>-s<N+1>' is posted to ONLY the originating writer, then finish 'stop'. - **FI-OC-015 · 10-minute activity-aware watchdog with sleep marker** [alert] — Watchdog compares against last REAL event time (heartbeats don't count): if active it reschedules for the remaining window (never cuts an active turn); on true silence it calls Aiur.Orchestrator.mark_sleeping, streams a '**system:** ... closing stream' notice, and closes with finish 'timeout' (src/lib/aiur/opencode/chat_completions.ex:260-291, src/lib/aiur/opencode/chat_completions.ex:383-399). - **FI-OC-018 · SSE chunk-write failure tolerance** [lifecycle] — A failed Plug.Conn.chunk (opencode disconnected: pane kill/respawn or read timeout) logs at debug and returns the conn unchanged instead of crashing the handler; the loop finishes via turn-done and subsequent writes fast-fail silently — a MatchError here used to take down whole-turn rendering (src/lib/aiur/opencode/chat_completions.ex:856-874).
