## Website & terminal sim (FI-SITE)
The aiur.team marketing site under website/: hero page UI, the deterministic 90-second terminal dashboard simulation, its responsive layout machinery, and the golden-snapshot/assert/build guard tooling that protects it.

- **FI-SITE-001 · 90s ShopWave dashboard loop** [tui-behavior] — Terminal section plays a deterministic 90s loop (loopSec = elapsed ms/1000 % LOOP_SECONDS) simulating an Aiur dashboard for its-everdred/shopwave with header 'Agents: 10/15' / 'Project: its-everdred/shopwave' / 'Dashboard: http://127.0.0.1:4000/'; 10 scripted tickets, only first 6 (VISIBLE_TICKETS) render; repaint every 100ms (website/src/simData.ts:38-41, website/src/dashboard.ts:344-358,555-556,687). Tests: website/scripts/assert-sim.ts (golden frames). Risk: medium.
- **FI-SITE-002 · Sim data contract** [api] — simData.ts exports the typed sim content consumed by dashboard.ts and both scripts: TICKETS (10 TicketScripts, ascending keyframes, first at t=0), EVENTS (ascending t, array order = display order, t<=0 seed history), OPENCODE_SCRIPT (chip 'Build · issue-321', history, alert, question, 3 options, typedText, reply), plus BEAT, OC_TOTAL_ROWS, LOOP_SECONDS (website/src/simData.ts:1-291). Content edits can violate BEAT invariants or overflow columns; the assert is the only guard. Tests: website/scripts/assert-sim.ts checks 1 and 3. Risk: medium.
- **FI-SITE-003 · Take-the-wheel beat timeline** [tui-behavior] — Fixed loop-second milestones: #321 enters decide at t=2 (❗ in list); cursor descends from t=7; opencode pane open [10,25); options post one-per-second from t=11; operator types [16,19); user block posts at 19; agent reply at 21; pane closes at 25; cursor ascends until 28; #321 flips to brainstorm at t=22 and never resolves (website/src/simData.ts:54-64, website/src/dashboard.ts:508-524,555-596). Re-timing the beat is called out in assert-sim.ts as a load-bearing hazard. Tests: website/scripts/assert-sim.ts checks 3, 4, 6. Risk: high.
- **FI-SITE-004 · Two-occurrence narrative ordering** [tui-behavior] — The human-steering beat on #321 closes (t=25) strictly before the autonomous #318→#319 unblock receive fires (t=29), so the loop reads as two distinct demonstrations; the old #321 'schema migrated' publish and #324 receive must not exist in EVENTS (website/src/simData.ts:218-226, website/scripts/assert-sim.ts:67-83). Tests: website/scripts/assert-sim.ts check 3. Risk: medium.
- **FI-SITE-005 · Selection cursor walk** [tui-behavior] — The ▶ marker is a pure function of loopSec: row 0 by default, descends one row per 0.5s from t=7 to the last visible row (#321), pins while the pane is open [10,25), ascends one row per 0.5s from t=25 to t=28 (website/src/dashboard.ts:510-524,562-567).
