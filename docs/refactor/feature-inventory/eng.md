## Engine scripts, packaging, build & dev-tooling gates (FI-ENG)
The shared shell engine and its launch/teardown lifecycle, the aiurdev dev shim, npm packaging and launcher, tmux UI config and Ctrl+C bridge, and the repo's build/CI/quality-gate tooling.

- **FI-ENG-001 · Single shared engine dispatch** [cli-command] — Installed `aiur` (packaging/npm/aiur-cli/bin/aiur.js) and dev `aiurdev` both exec the ONE engine script owning every subcommand: help/-h/-help/--h/--help, --version, init, --bg, run, status, agents, alerts, watch, set, pause, resume, message, cleanup-stale, stop, plus `__identity`; bare `aiur`, a leading flag, or an existing path arg dispatch to a foreground run, and an unknown command prints usage to stderr and exits 64 (packaging/npm/aiur-cli/libexec/aiur-engine.sh:2018-2094, :268-284). `run` is accepted but undocumented in usage. Tests: src/test/aiur_engine_test.exs. Risk: medium.
- **FI-ENG-002 · AIUR_RELEASE_DIR contract** [api] — The engine dies with a clear error if AIUR_RELEASE_DIR is unset or not a directory; release version comes from releases/start_erl.data and the versioned elixir launcher must exist (packaging/npm/aiur-cli/libexec/aiur-engine.sh:216-226). aiurdev sets it to src/_build/dev/rel/aiur (scripts/aiurdev:416); bin/aiur.js sets the platform package's release/ — a preset env always wins (packaging/npm/aiur-cli/bin/aiur.js:35-74). Tests: packaging/npm/aiur-cli/test/launcher.test.mjs, src/test/scripts_aiurdev_test.exs. Risk: medium.
- **FI-ENG-003 · Per-instance keyed distribution identity** [lifecycle] — Node/session/socket names are keyed by aiur project root: AIUR_REPO_ROOT wins, else walk up from $PWD to the first dir with .aiur/config or .aiurconfig stopping at $HOME (#443), else realpath($PWD); instance key = first 10 hex chars of sha256(root), node name aiur-$USER-<key>@127.0.0.1, so two same-user instances never collide or reap each other (packaging/npm/aiur-cli/libexec/aiur-engine.sh:61-117, :119-138). Global-config runs are cwd-keyed: control commands must run from the launch dir or a subdir. Tests: src/test/aiur_engine_test.exs (keyed identity, sourced-run isolation). Risk: high.
- **FI-ENG-004 · Identity env override points** [config-option] — AIUR_BG_STATE_DIR (default ~/.config/aiur), AIUR_COOKIE_FILE, AIUR_SESSION_PREFIX, AIUR_PROFILES_FILE and AIUR_RELEASE_NODE stay overridable so tests/sandboxes redirect state; `${AIUR_INSTANCE_KEY+x}` honors an explicit empty key (packaging/npm/aiur-cli/libexec/aiur-engine.sh:124-137). Tests: src/test/aiur_engine_test.exs:46-53. Risk: low.
- **FI-ENG-005 · __identity diagnostic subcommand** [cli-command] — `aiur __identity` prints resolved release dir, state dir, session prefix, profiles file, release node, instance key, project root + source and cookie file as KEY=VALUE lines; consumed by the engine test suite and verify-install.sh Layer 2 (packaging/npm/aiur-cli/libexec/aiur-engine.sh:140-151, packaging/npm/aiur-cli/scripts/verify-install.sh:74-81). Tests: src/test/aiur_engine_test.exs (identity/1 helper). Risk: medium.
- **FI-ENG-006 · Erlang cookie auto-provisioning and validation** [artifact] — A missing cookie file is minted atomically (umask 0177, mktemp+mv, 32 random base64 chars, chmod 0400); existing cookies must be readable, owned by $USER and >=16 bytes or the command dies; RELEASE_COOKIE/AIUR_ERLANG_COOKIE are exported for every distributed command (packaging/npm/aiur-cli/libexec/aiur-engine.sh:160-208). Tests: indirect via src/test/aiur_engine_test.exs RPC tests. Risk: medium.
- **FI-ENG-007 · Loopback-pinned BEAM distribution** [lifecycle] — Every distributed launch exports RELEASE_DISTRIBUTION=name, ERL_AFLAGS pinning inet_dist to {127,0,0,1} and ERL_EPMD_ADDRESS=127.0.0.1 so the distribution listener and epmd bind only to loopback (packaging/npm/aiur-cli/libexec/aiur-engine.sh:198-207).
